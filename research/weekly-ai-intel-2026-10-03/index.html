현재 환경에 가까운 업데이트#

OpenVINO 툴킷 2026.4.1 릴리스#

자료 1 [공식 발표·로컬 미확인] 발표 상태: 발표/게시 자료이며 로컬 실행은 확인하지 않음.

GroupQueryAttention 지원 확대 및 MatMulNBits bfloat16 지원이 추가되었으며, 슬라이딩 윈도우 KV-cache 경로의 정확성 문제가 수정되었습니다. GPU에서 원격 출력 텐서 사용 시 전이 변환 오류가 해결되고, dynamic shapes 조건에서의 GRU 모델 정확성이 개선된 점이 특징입니다.

이번 릴리스는 대형 언어 모델(LLM) 서빙을 위한 GroupQueryAttention 지원 범위를 넓히고, bfloat16 지원을 통해 양자화 모델 디코딩 정확도를 높였습니다. 슬라이딩 윈도우 KV-cache 경로에서 발생하던 메모리 손상 및 드라이버 충돌 문제를 수정하여 GPU 안정성을 강화했으며, dynamic shapes 환경에서의 GRU 모델 연산 오류를 교정했습니다. CPU 분야에서는 OV_CPU_MAX_ISA 캡핑 기능이 릴리스 빌드에서도 활성화되어 JIT kernel 선택이 개선되었습니다.

해석·적용 시 주의: 원문에 나열된 개별 드라이버 번호를 연속 범위나 최소 버전으로 해석하지 않는다. 실제 적용 여부는 원문에 명시된 장비 조건과 함께 별도로 확인해야 한다.

원문에 나열된 개별 드라이버 표기 자료 1: 32.0.100.4300, 32.0.100.4509, 32.0.100.4512. 연속 범위나 지원 보장으로 확대 해석하지 않는다.

OpenVINO 2026.4.1로 업데이트하고 성능을 최적화하며 연산 범위를 확대하고 디바이스 목록을 개선했습니다. Qwen3.5 MoE 퍼포먼스 향상과 단일 시퀀스 반복 상태 최적화가 포함되었으며, 그래프 캐시 키 단순화와 GPU MoE 퓨전 기본 활성화 등이 진행되었습니다.

ggml-openvino 프로젝트가 OpenVINO 2026.4.1로 업데이트되어 Qwen3.5 MoE 추론 성능이 개선되었습니다. 단일 시퀀스 반복 상태 최적화와 그래프 캐시 키 단순화가 진행되었으며, GPU MoE 퓨전이 기본적으로 활성화되어 다양한 하드웨어에서의 효율적인 처리가 가능해졌습니다. 원격 출력 텐서 사용 기본 설정 및 캐시된 컴파일 모델 디스크 직접 가져오기 기능이 추가되었습니다.

해석·적용 시 주의: 실험적 단계의 자료이며, 특정 장비 구성에 대한 보장되지 않은 최신 기능 포함. 설치·호환 버전·실행 명령·성능 수치가 자료에 없으면 추정하지 않는다.

onnx runtime — ONNX Runtime v1.28.3 업데이트#

자료 3 [공식 발표·로컬 미확인] 발표 상태: 발표/게시 자료이며 로컬 실행은 확인하지 않음.

버전 업그레이드와 함께 메모리 안전성 및 모델 검증 수정, 플러그인 실행 수정, 패키징 인프라 업데이트가 포함된 패치 릴리스입니다. 주요 버그 수정으로 EmbedLayerNormalization shape inference, packed sub-byte buffer 오버플로우, Loop/Scan 입력 초기화 문제 등이 해결되었습니다.

ONNX Runtime v1.28.3는 v1.28.2를 기반으로 한 패치 릴리스로, 메모리 안전성 및 모델 검증 수정, 플러그인 실행 수정, 패키징 인프라 업데이트가 포함되어 있습니다. 특히 EmbedLayerNormalization shape inference 시 beta가 스칼라인 경우 발생하던 아웃오브바운드 리드 버그, packed sub-byte buffer 재사용 시 힙 버퍼 오버플로우, Loop 또는 Scan body 입력 초기화 문제 등이 해결되었습니다. 또한 적용 가능한 contrib 연산자에 대한 모양 추론이 강화되었으며, ConvTransposeWithDynamicPads 및 InferenceContextImpl::getInputData에서의 아웃오브바운드 리드 문제가 수정되었습니다.

해석·적용 시 주의: 패치 릴리스로, 기존 v1.28.2 환경에서 업그레이드 시 메모리 안전성 관련 이슈가 해결됩니다. 구체적인 하드웨어·드라이버·설정에서의 안정성은 검증되지 않았으며, 모든 contrib 연산자에 대한 강화된 모양 추론이 적용되었음을 확인해야 합니다.

ollama — v0.35.1 업데이트#

자료 4 [공식 발표·로컬 미확인] 발표 상태: 발표/게시 자료이며 로컬 실행은 확인하지 않음.

Clef 및 Clef Flash 모델 지원이 추가되어 멀티모달 요청(텍스트+이미지)이 가능해졌으며, 웹 검색 기능이 최대 10회로 확대되고 Modelfile에 CAPABILITY 선언이 지원돼 모델의 기능을 명시적으로 정의할 수 있게 되었습니다.

ollama v0.35.1에서는 Cloudflare의 오픈소스 결정 모델인 Clef(27B)와 Clef Flash(9B)가 추가되어 /v1/systemone을 통해 지원됩니다. 이 모델들은 멀티모달 기능을 갖추고 있어 요청에 이미지를 함께 포함시킬 수 있으며, 텍스트 상태와 공유되어 jointly scoring가 가능합니다. 또한 웹 검색 기능이 최대 10회까지 수행 가능하도록 확대되었으며, Modelfile에 CAPABILITY 선언이 지원돼 모델 creators가 모델의 기능을 명시적으로 선언할 수 있게 되었습니다. 기존에는 decision 모델이 일반 챗·툴·싱킹 등에 제공되었으나, 이제 capability가 decision으로만 보고되어 클라이언트에서 오퍼링되지 않습니다.

해석·적용 시 주의: Clef 및 Clef Flash 모델은 새로운 멀티모달 결정 모델로, 기존 모델과의 호환성이나 특정 하드웨어·드라이버 환경에서의 성능은 검증된 바가 없습니다. CAPABILITY 선언 기능은 모델 생성 시 preserved되지만, 모든 모델에 적용되는 표준은 아닙니다.

SGLang v0.5.21: 새로운 모델과 기능 추가#

자료 5 [공식 발표·로컬 미확인] 발표 상태: 발표/게시 자료이며 로컬 실행은 확인하지 않음.

779개의 PR이 227명의 기여자에 의해 병합되었으며, DeepSeek-V4.1, Kimi K3, GLM-5.3-Flash 등 신규 모델 지원 및 사전 캐시 최적화, PD 인스턴스 실시간 프리디코드 전환, Decisions/Score API 등 새로운 기능이 도입되었다.

SGLang v0.5.21은 대규모 기여자 기반을 통해 779개의 PR이 병합된 버전으로, DeepSeek-V4.1의 첫 토큰 처리 속도 향상(Kimi K3 프리디코드 throughput 증가 등) 및 GLM-5.3-Flash의 AMD MI355X 지원 확대가 주요 하이라이트다. 사전 캐시가 기본적으로 Rust 코어로 실행되며, Decisions API와 Score API를 통해 LLM을 분류기와 스코어링 도구로 활용할 수 있다. 또한 PD 인스턴스가 재시작 없이 프리디코드 모드를 실시간으로 전환할 수 있게 되어 serving 효율이 높아졌다.

해석·적용 시 주의: 새로운 백엔드 및 MoE 설정(FlashInfer, DeepEP, MXFP8 등)에 대한 호환성 검증이 진행 중이며, 일부 실험적 기능은 안정화가 필요할 수 있다. 구체적인 GPU·드라이버 환경에 따라 성능이 달라질 수 있으며, 원문에 명시된 조건 외의 환경에서는 적용 전 테스트가 권장된다.

transformers Release 5.18.0: 새로운 모델 및 버그 수정#

자료 6 [공식 발표·로컬 미확인] 발표 상태: 발표/게시 자료이며 로컬 실행은 확인하지 않음.

Nemotron 3 Diarization, NemotronH Omni, HyperCLOVAX Vision V2 등 다수의 신규 모델이 추가되었으며, ROCm 경로 관련 라우팅 수정, 영상 처리 속도 향상, 인덱서 리매핑 등 다양한 버그 픽스와 개선 사항이 포함되었다.

transformers 5.18.0은 스피커 diarization 모델인 Nemotron 3 Diarization을 비롯해 멀티모달 추론이 가능한 NemotronH Omni, NAVER의 HyperCLOVAX Vision V2 등 신규 모델 도입이 두드러진다. 또한 ROCm 기반 gpt-oss 라우팅 개선, Detr 이미지 처리 속도 향상, Qwen2.5-VL temporal RoPE 수정 등 안정성 및 호환성 관련 픽스가 다수 적용되었다. 이러한 변화는 멀티모달 추론 및 다양한 하드웨어 환경에서의 모델 사용을 확장한다.

해석·적용 시 주의: ROCm 경로 관련 라우팅 변경 및 특정 모델의 통합 테스트 수정 사항이 포함되어 있어, 해당 백엔드를 사용하는 사용자는 업데이트 전 호환성 확인 필요. XPU 등록 커널 등 새로운 기능은 플랫폼별 검증이 요구된다.

지원 경로와 제작 흐름#

이 부분은 새 소식을 이해하기 위한 배경 안내다. 아래 문서를 이번에 조회했다는 뜻이며, 이번 주에 새로 추가된 지원이나 로컬 실행 결과가 아니다. 문서 본문 접근·필수 주제 일치 확인은 개별 호환성 검증을 대신하지 않는다.

배경 1 LM Studio 런타임 관리#

LM Studio 앱과 실제 추론 런타임은 구분해서 본다. 공식 런타임 관리 문서에서 목록·선택·관리 방법을 확인하고, 상위 엔진의 새 변경이 설치된 런타임에도 포함됐는지는 별도로 확인한다.

배경 2 llama.cpp 백엔드 빌드 문서#

llama.cpp는 CUDA·HIP·Vulkan 등 백엔드별 빌드 경로를 따로 설명한다. 백엔드 이름이 있다는 것과 특정 GPU·모델·드라이버 조합의 동작 보장은 다르다. 사용할 엔진의 빌드 옵션과 운영체제별 조건을 먼저 대조한다.

배경 3 PyTorch Intel GPU 시작 조건#

PyTorch의 Intel GPU 경로는 모델 이름이나 GPU 제조사만으로 판단하지 않는다. 공식 안내의 장비·운영체제·드라이버·PyTorch 조건을 함께 확인한다. XPU 학습/추론 경로와 LM Studio의 실제 추론 엔진은 별개이며, 이 문서를 읽었다고 설치나 동작을 검증한 것은 아니다.

배경 4 OpenVINO 시스템 요구 조건#

OpenVINO의 CPU·GPU·운영체제 조건을 지원 문서에 대조한다. GPU 경로에는 별도 드라이버 조건이 있으므로 GPU 이름이나 다운로드 파일 존재를 동작 보장으로 해석하지 않는다. 정확한 모델·GPU 세대·버전의 조합은 실제 사용 환경에서 별도 확인해야 한다.

적용 전 확인할 것#

아래는 Intel 환경에서 원문의 적용 조건을 확인할 후보다. 직접 실행 성공이나 호환성 보장이 아니다.

자료 1 OpenVINO 툴킷 2026.4.1 릴리스#

  • 대상 버전/발표: 2026.4.1. 설치된 런타임·백엔드·의존성이 원문의 적용 대상인지 먼저 확인한다.
  • 확인 목적: GroupQueryAttention 지원 확대 및 MatMulNBits bfloat16 지원이 추가되었으며, 슬라이딩 윈도우 KV-cache 경로의 정확성 문제가 수정되었습니다. GPU에서 원격 출력 텐서 사용 시 전이 변환 오류가 해결되고, dynamic shapes 조건에서의 GRU 모델 정확성이 개선된 점이 특징입니다.
  • 성공 기준: 분리한 시험 환경에서 같은 입력으로 기본 동작을 확인하고, 기존에 정상 동작하던 작업이 유지되는지 비교한다.
  • 되돌릴 방법: 기존 검증 환경과 설정을 보관하고 분리 시험한다. 문제가 있으면 기존 환경과 설정으로 복원한다.

  • 확인 목적: 버전 업그레이드와 함께 메모리 안전성 및 모델 검증 수정, 플러그인 실행 수정, 패키징 인프라 업데이트가 포함된 패치 릴리스입니다. 주요 버그 수정으로 EmbedLayerNormalization shape inference, packed sub-byte buffer 오버플로우, Loop/Scan 입력 초기화 문제 등이 해결되었습니다.
