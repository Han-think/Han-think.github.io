1. 환경 분리#

왜 이걸 보게 됐나#

환경 분리는 프로젝트의 안정성과 효율성을 높이기 위해 필수적입니다. 로컬 환경과 클라우드 환경(예: Colab)을 명확히 구분함으로써 실험과 실제 개발 작업 간의 오류를 최소화하고, 각 환경에 최적화된 설정을 유지할 수 있습니다.

내가 헷갈린 지점#

초기에는 Colab과 로컬 환경의 역할 차이와 파일 관리 구조에 대한 이해 부족으로 혼란스러웠습니다. 특히, 학습 자료와 프로젝트 파일을 구분하는 방법이 명확하지 않았습니다.

시도한 코드 / 예시#

import os
import hashlib
import pandas as pd

def scan_and_register_files(folder_path, registry_file='source_registry.csv'):
    # 기존 registry 파일 로드
    try:
        registry = pd.read_csv(registry_file)
    except FileNotFoundError:
        registry = pd.DataFrame(columns=['filename', 'filetype', 'hash', 'policy'])

    # 폴더 내 파일 스캔
    files = os.listdir(folder_path)
    for file in files:
        file_path = os.path.join(folder_path, file)
        if os.path.isfile(file_path):
            # 파일 유형 확인
            file_type = os.path.splitext(file)[1]
            # 해시 생성
            file_hash = hashlib.md5(open(file_path, 'rb').read()).hexdigest()
            # 신규 파일 등록 로직 (예시)
            if file not in registry['filename']:
                new_entry = {'filename': file, 'filetype': file_type, 'hash': file_hash, 'policy': 'public'}
                registry = registry.append(new_entry, ignore_index=True)
                # registry 업데이트 (예시: CSV로 저장)
                registry.to_csv(registry_file, index=False)
    return registry

# 예시 사용
lectures_folder = 'lectures'
updated_registry = scan_and_register_files(lectures_folder)
print(updated_registry)

결과와 해석#

위 코드는 lectures 폴더 내의 파일들을 스캔하고, 각 파일의 해시 값을 생성하여 source_registry.csv에 신규 파일을 등록하는 예시입니다. 출력 예시:

  filename       filetype       hash policy
0  example_lecture1.pdf  .pdf  ... public
1  example_lecture2.ipynb  .ipynb  ... public

정리된 이해#

환경 분리를 통해 로컬 환경과 클라우드 환경(Colab)의 역할을 명확히 이해하고, 파일 관리 시스템을 효과적으로 구축할 수 있습니다. 이를 통해 학습 자료와 프로젝트 파일을 체계적으로 분류하고 관리할 수 있으며, 자동화된 파이프라인을 통해 효율적인 작업 흐름을 유지할 수 있습니다.

2. 가상 환경 활용#

왜 이걸 보게 됐나#

가상 환경을 활용하면 학습과 실제 프로젝트 개발을 분리하여 각 환경에 최적화된 설정을 유지할 수 있습니다. 이를 통해 버전 호환성 문제를 해결하고 실험과 실제 작업 간의 오류를 최소화할 수 있습니다.

내가 헷갈린 지점#

초기에는 Python 버전 차이와 라이브러리 호환성 문제로 인해 어떤 환경에서 어떻게 작업해야 할지 혼란스러웠습니다. 또한, Colab과 로컬 환경의 역할 구분이 명확하지 않아 프로젝트 관리에 어려움을 겪었습니다.

시도한 코드 / 예시#

# 가상 환경 생성 및 활성화 예시

결과와 해석#

로컬 환경에서 myenv라는 가상 환경이 생성되고 활성화되어 Python 3.12에서 코드가 실행됩니다. Colab에서는 Python 버전 확인 명령어를 통해 현재 환경의 버전을 확인할 수 있습니다.

정리된 이해#

가상 환경을 활용하면 Python 버전과 라이브러리 호환성 문제를 해결하고, 학습 환경과 실제 프로젝트 환경을 명확히 구분하여 효율적인 개발과 학습을 가능하게 합니다. Colab은 임시 실행 환경으로서 실시간 피드백과 협업에 유용하며, 로컬 환경은 안정적인 개발과 실험에 적합합니다.

3. Colab 역할#

왜 이걸 보게 됐나#

Colab은 주로 교육적 목적으로 실시간 협업과 코드 실행을 위한 임시 환경으로 활용되며, 로컬 환경은 안정적이고 개인화된 프로젝트 개발에 중점을 둡니다. 이를 이해함으로써 학습과 실제 작업 사이의 역할 혼동을 해소할 수 있습니다.

내가 헷갈린 지점#

Colab과 로컬 환경의 구분이 모호하여 어디에 어떤 작업을 집중해야 할지 혼란스러웠습니다. 또한, 자동화된 학습 로그 관리 시스템의 구체적인 작동 방식에 대한 이해 부족이 있었습니다.
