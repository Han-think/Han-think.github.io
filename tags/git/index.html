2026-05-28 학습 노트: Git Bash, Markdown, vi, 그리고 Hugo 활용

왜 썼나 오늘의 학습 목표는 다양한 도구와 플랫폼을 효과적으로 활용하여 개인적인 학습 내용을 체계적으로 기록하고 공유하는 방법을 익히는 것이었습니다. 특히 Git Bash를 통한 Linux CLI 기초, Markdown을 활용한 문서 작성, 텍스트 편집기인 vi의 기초, 그리고 이를 블로그 플랫폼인 Hugo에 적용하는 방법을 학습했습니다. 이러한 기술들은 정보를 효과적으로 관리하고 공유하는 데 필수적이기 때문입니다. 배운 것 Git Bash와 Linux CLI: 단순히 명령어를 외우는 것이 아니라, 터미널 내에서 문제 해결을 위한 경로 탐색 감각을 키웠습니다. 이를 통해 시스템 관리와 버전 관리에 대한 이해도가 향상되었습니다. Markdown 문서 작성: Markdown의 기본 문법을 배워 문서를 간결하고 가독성 있게 작성할 수 있게 되었습니다. 특히 #를 이용한 제목 표시와 >/>>를 이용한 파일 내용 추가 방식을 이해했습니다. vi 편집기: vi 편집기의 기본적인 사용법을 익혔습니다. 특히 파일을 열고 편집하며 내용을 추가하거나 수정하는 방법을 배웠습니다. 하지만 vi의 복잡한 모드 전환은 아직 익숙해지는 과정에 있습니다. Hugo 블로그 구축: 내가 학습한 내용을 Hugo를 통해 블로그 형태로 기록하고 공개하는 방법을 학습했습니다. LearningLog 구조를 이해하며, 개인적인 학습 일지를 효과적으로 관리하고 공유할 수 있는 플랫폼을 구축하는 데 필요한 기본적인 설정을 수행했습니다. 헷갈리던 점 >와 >>의 차이: 처음에는 >와 >>의 기능 차이를 정확히 이해하지 못했습니다. >는 첫 줄에 내용을 추가하고, >>는 기존 내용 뒤에 추가한다는 점을 깨달았습니다. Markdown 내 #의 이중 역할: Markdown에서 #은 제목을 표시하는 데 사용되지만, Git Bash에서는 주석 표시로 사용됩니다. 문맥에 따라 같은 기호가 다른 역할을 한다는 점이 혼란스러웠습니다. vi 편집기의 모드 전환: vi 편집기에서 i 모드로 들어가 편집을 시작하는 것은 이해했지만, 다시 정규 모드로 돌아가는 방법을 찾는 데 어려움을 겪었습니다. Esc 키를 사용한다는 것을 알게 되었습니다. 문자열 표기법의 차이: " "와 ' '의 차이를 이해하는 데 시간이 걸렸습니다. 특히 변수 $변수가 포함될 때 두 방식의 차이를 직접 실행해 보며 확인했습니다. 정리된 이해 Git Bash: 터미널에서의 문제 해결 능력 향상이 중요하다. Markdown: 간결하고 읽기 쉬운 문서 작성을 위한 기본 문법 숙지. vi 편집기: 기본적인 편집 기능과 모드 전환을 이해하는 것이 핵심이다. Hugo: 개인 블로그 구축을 위한 구조와 기본 설정 이해. 실습 예시 Markdown 예시: ...
