Markdown 문서 작성: Markdown의 기본 문법을 배워 문서를 간결하고 가독성 있게 작성할 수 있게 되었습니다. 특히 #를 이용한 제목 표시와 >/>>를 이용한 파일 내용 추가 방식을 이해했습니다. vi 편집기: vi 편집기의 기본적인 사용법을 익혔습니다. 특히 파일을 열고 편집하며 내용을 추가하거나 수정하는 방법을 배웠습니다. 하지만 vi의 복잡한 모드 전환은 아직 익숙해지는 과정에 있습니다. Hugo 블로그 구축: 내가 학습한 내용을 Hugo를 통해 블로그 형태로 기록하고 공개하는 방법을 학습했습니다. LearningLog 구조를 이해하며, 개인적인 학습 일지를 효과적으로 관리하고 공유할 수 있는 플랫폼을 구축하는 데 필요한 기본적인 설정을 수행했습니다. 헷갈리던 점 >와 >>의 차이: 처음에는 >와 >>의 기능 차이를 정확히 이해하지 못했습니다. >는 첫 줄에 내용을 추가하고, >>는 기존 내용 뒤에 추가한다는 점을 깨달았습니다. Markdown 내 #의 이중 역할: Markdown에서 #은 제목을 표시하는 데 사용되지만, Git Bash에서는 주석 표시로 사용됩니다. 문맥에 따라 같은 기호가 다른 역할을 한다는 점이 혼란스러웠습니다. vi 편집기의 모드 전환: vi 편집기에서 i 모드로 들어가 편집을 시작하는 것은 이해했지만, 다시 정규 모드로 돌아가는 방법을 찾는 데 어려움을 겪었습니다. Esc 키를 사용한다는 것을 알게 되었습니다. 문자열 표기법의 차이: " "와 ' '의 차이를 이해하는 데 시간이 걸렸습니다. 특히 변수 $변수가 포함될 때 두 방식의 차이를 직접 실행해 보며 확인했습니다. 정리된 이해 Git Bash: 터미널에서의 문제 해결 능력 향상이 중요하다. 웹 서버, HTTP, GitHub Pages 이해하기: 기초 개념 정리

왜 썼나? 최근 웹 개발의 기본 요소인 웹 서버, HTTP 프로토콜, 그리고 GitHub Pages를 활용한 블로그 구축에 대해 깊이 이해하고 싶어졌습니다. 특히, 로컬 환경에서의 실습과 클라우드 기반 호스팅 간의 차이점을 명확히 파악하고자 이 글을 작성하게 되었습니다. 이를 통해 웹 개발의 핵심 개념을 초보자도 쉽게 이해할 수 있도록 돕고자 합니다. 배운 것 로컬 서버 이해 로컬 서버는 주로 개발 과정에서 사용됩니다. hugo server 명령을 통해 로컬 컴퓨터에서만 접근 가능한 임시 웹사이트를 생성합니다. 예시: http://localhost:1313에서 Hugo가 생성한 사이트를 확인할 수 있습니다. 핵심 포인트: 이 서버는 사용자가 직접 끄기 전까지는 지속적으로 작동합니다. 하지만 인터넷 외부에서는 접근할 수 없습니다. GitHub Pages의 역할 GitHub Pages는 정적 웹사이트를 공개적으로 호스팅하는 플랫폼입니다. 사용자의 컴퓨터가 꺼져 있어도 웹사이트는 계속 운영됩니다. 작동 원리: HTML 파일들이 GitHub 저장소에 업로드되면 GitHub Pages가 이를 처리하여 웹사이트를 공개합니다. 역할: 개발자의 로컬 작업 환경과 무관하게 웹사이트를 지속적으로 유지하고 서비스합니다. Hugo의 기능 Hugo는 Markdown 파일을 HTML로 변환하는 정적 사이트 제너레이터입니다. 주요 역할: Markdown 파일을 읽어들여 정적 웹사이트의 HTML 파일을 생성하지만, 직접 웹 호스팅은 수행하지 않습니다. 실습 예시: # Hugo 프로젝트 초기화 hugo new site myblog # Markdown 파일 생성 및 HTML로 변환 hugo server 헷갈린 것 서버 개념의 혼동 혼동 포인트: 로컬 서버, 공개 서버, 정적 사이트, 동적 사이트, GitHub Pages, 그리고 Hugo 간의 구분이 어려웠습니다. 질문: “내 컴퓨터 서버 기반이면 내가 켜놓을 때만 되는 건가?” 해석: 로컬 서버는 개발자의 컴퓨터에서만 작동하며, GitHub Pages는 파일이 GitHub에 업로드되면 지속적으로 호스팅됩니다. 따라서 각각의 역할과 범위를 명확히 이해하는 것이 중요합니다. 정리된 이해 로컬 vs 공개 호스팅 로컬 서버: 개발 중에만 사용되며, 로컬 네트워크 내에서만 접근 가능합니다. 예시: http://localhost:1313에서 확인 가능. GitHub Pages: 파일을 GitHub 저장소에 업로드하면 공개적으로 접근 가능한 웹사이트를 제공합니다. 핵심: 로컬 작업은 “업로드 작업장"으로, GitHub Pages가 실제 호스팅을 담당합니다. Hugo의 역할 재정의 Hugo는 Markdown 파일을 HTML로 변환하는 도구일 뿐, 직접 웹 호스팅은 수행하지 않습니다. GitHub Pages가 실제 호스팅을 담당합니다. 실습 예시 로컬 환경에서 Hugo 사용하기 Hugo 프로젝트 초기화: hugo new site myblog Markdown 파일 생성: hugo new posts/my-first-post.md 로컬 서버 실행: hugo server 확인: 브라우저에서 http://localhost:1313로 접근 가능. GitHub Pages와 통합하기 GitHub 저장소 생성: username.github.io 형식의 저장소 생성. Hugo 프로젝트를 GitHub에 업로드: main 브랜치에 public 폴더 내의 HTML 파일들을 업로드. GitHub Pages 설정: 저장소 설정에서 GitHub Pages를 활성화. 초보자 키워드 왜 썼나? 블로그를 만드는 과정에서 개인적인 학습 경험을 기록하고, 이를 통해 기술적 이해를 깊게 하며, 향후 비슷한 프로젝트를 진행할 때 참고 자료로 활용하고자 합니다. 또한, 기술에 대한 내 해석을 공유함으로써 초보자들에게도 도움이 되길 바랍니다. ...
