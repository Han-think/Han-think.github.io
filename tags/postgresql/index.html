팀 프로젝트 DB 선택: SQLite에서 PostgreSQL로 넘어가야 하는 순간

왜 이 글을 프로젝트로 옮겼나 이 기록은 단순히 SQLite 문법을 배운 글이 아니라, 팀 프로젝트에서 어떤 데이터베이스를 선택해야 하는지 판단하는 설계 기록에 가깝다. 개인 실습에서는 SQLite가 편하지만, 팀 프로젝트나 웹 서비스에서는 동시성, 권한, 배포, 운영 비용까지 함께 봐야 한다. 처음 헷갈렸던 지점 SQLite를 처음 볼 때는 “가볍고 쉬우면 좋은 DB 아닌가?“라는 생각이 강했다. 하지만 프로젝트 상황을 나누어 보니 같은 DB라도 적합한 맥락이 달랐다. SQLite는 파일 기반이라 개인 실습과 로컬 테스트에 좋다. FOREIGN KEY는 PRAGMA foreign_keys = ON을 명시해야 한다. ALTER TABLE로 제약조건을 수정하거나 삭제하는 흐름이 제한적이다. ERD 도구가 SQLite 스키마를 항상 깔끔하게 반영하지 못할 수 있다. 팀 프로젝트에서는 여러 명이 동시에 접근하고 권한을 나누는 문제가 생긴다. SQLite 실습에서 배운 것 SQLite에서 참조 무결성을 쓰려면 외래 키를 켜야 한다. ...
