왜 음성 생성이 아니라 화자 고정이 문제였나#

로컬 파티 게임의 게임마스터는 한 번만 말하는 효과음이 아니다. 시작 안내, 밤 결과, 투표 결과, 다음 차례 안내를 계속 반복한다. 그래서 중요한 기준은 “이번 문장이 자연스러운가?”보다 “다음 문장도 같은 진행자로 들리는가?”였다.

처음에는 VoiceDesign 모델에 같은 시드와 스타일 지시문을 넣었다. 좋은 대사가 나왔지만 대사가 달라지면 목소리의 인상도 달라졌다. 같은 톤을 설명하는 것과 같은 화자를 재현하는 것은 다른 문제였다.

해결은 Qwen3-TTS Base 모델의 기준 음성 클로닝이었다. 승인한 짧은 WAV와 그 WAV의 정확한 대본을 기준으로 등록하고, 이후에는 gm_b라는 고정 화자로만 합성하게 만들었다. 이것으로 문장마다 화자가 바뀌는 문제를 크게 줄일 수 있었다.

실시간 합성 대신 캐시를 고른 이유#

CPU 환경에서 고품질 음성 합성은 게임의 즉각적인 흐름을 따라가기 어려웠다. 버튼을 누른 뒤 음성이 나올 때까지 기다리게 하면 진행자 역할이 오히려 게임의 박자를 끊는다.

그래서 구조를 바꿨다.

방 설정과 명단 확정
  -> 실제로 쓸 완성 문장 목록 생성
  -> WAV 선생성 및 체크포인트 저장
  -> 게임 중에는 파일을 즉시 재생

이 선택은 음성을 “서비스 호출”이 아니라 “게임 에셋”으로 바꿨다. 캐시가 있으면 게임 중 TTS 서버가 잠시 꺼져 있어도 이미 준비한 대사는 재생할 수 있다.

고정 TTS 캐시 키트의 구성#

이 작업에서 남긴 것은 특정 프로젝트 전용 WAV 모음이 아니라, 다른 로컬 게임에도 옮길 수 있는 작은 운영 키트다.

구성 요소 역할
기준 WAV + 기준 대본 클론 화자의 기준점. 공개 저장소에서는 제외한다.
TTS_VOICE=gm_b 설정 게임이 어떤 고정 화자를 쓸지 지정한다.
자동 음성 등록 TTS 서버 재시작 뒤에도 클론을 다시 등록한다.
대사 카탈로그 실제 게임에서 들릴 문장을 먼저 확정한다.
배치 생성기 3문장 생성 뒤 서버를 재시작해 긴 작업의 실패를 줄인다.
체크포인트·로그 중단 후에도 이미 생성된 WAV를 건너뛰고 이어서 만든다.
읽기 쉬운 파일명 사람이 들어보고 교체할 수 있게 한다.

대표 파일명은 다음처럼 역할이 보이게 만들었다.

mafia_doctor_saved_gm_b.wav
mafia_no_victim_gm_b.wav
mafia_night_attack_플레이어이름_gm_b.wav
mafia_execution_mafia_플레이어이름_gm_b.wav
mafia_execution_citizen_플레이어이름_gm_b.wav

이름이 해시뿐이면 생성에는 성공해도 사람이 검수하기 어렵다. 이번에는 파일명도 게임 설계의 일부로 취급했다.

마피아 게임 대사에서 배운 운영 규칙#

밤사이 공격과 낮 투표 처형을 같은 “탈락”이라는 표현으로 묶으면, 플레이어는 언제 어떤 사건이 일어났는지 헷갈린다. 그래서 이벤트를 분리했다.

  • 밤 습격 성공: “밤사이 마피아의 습격으로 ○○님이 살해 당했습니다. 의사는 막아내지 못했습니다.”
  • 의사 보호 성공: “밤사이 마피아의 습격이 있었지만, 의사가 막아냈습니다.”
  • 무피해: “밤사이 습격으로 인한 탈락자는 없습니다.”
  • 투표 처형: 낮 투표 결과로만 별도 안내한다.

반대로 경찰 조사처럼 한 사람에게만 필요한 정보는 전체 음성으로 읽지 않는다. 개인 화면 텍스트로 남겨야 게임 정보가 새지 않는다.

검증 결과와 공개 경계#

대사 라이브러리는 더미 명단 65개, 개인 명단 53개를 모두 실패 없이 만들었다. 실제 게임 캐시에서는 93개 WAV가 사람에게 읽히는 파일명으로 정리됐다. API와 게임 로직 회귀 테스트도 통과했다.

하지만 “재현 가능”이 “모든 결과물을 공개한다”는 뜻은 아니다. 공개 저장소에는 아래만 남긴다.

  • 게임 코드와 대사 카탈로그
  • 더미 명단
  • 음성 등록·배치 생성·파일명 정리 스크립트
  • 이 운영 기록

실제 음성 WAV, 기준 음성, 개인 이름 명단, 개인 명단 로그는 로컬에만 남긴다. 그래야 키트는 공유하면서도 참여자 정보와 음성은 보호할 수 있다.

다음 단계#

다음 작업은 캐시 생성이 아니라 실제 플레이 검증이다. 게임 화면에서 밤 결과와 투표 결과가 정확한 파일을 재생하는지, 그리고 새 환경에서 더미 명단만으로 키트를 다시 구성할 수 있는지를 확인한다.

이번 작업에서 얻은 결론은 단순하다. 고정 캐릭터 음성은 모델 하나를 고르는 문제가 아니라, 기준 음성·재등록·캐시·파일명·개인정보 경계를 함께 설계하는 운영 문제였다.

총평#

이번 글에서 정리한 것#

한 명의 게임마스터처럼 들리는 음성은 한 번의 프롬프트로 완성되지 않았다. 기준 음성 클로닝, 서버 재등록, 캐시 생성, 대사별 파일명, 중단 후 재개하는 체크포인트까지 연결했을 때 비로소 게임 에셋으로 사용할 수 있었다.

다음에 조심할 것#

공개 가능한 키트와 실제 플레이 데이터는 분리해야 한다. 실제 음성 파일이나 참여자 명단을 편의상 글·저장소에 넣으면 재현성은 높아 보여도 공개 경계가 무너진다.
