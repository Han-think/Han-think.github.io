1. 도구 이름 결정#

왜 이걸 보게 됐나#

프로젝트를 시작하면서 어떤 이름으로 부를지 정하는 게 생각보다 어려웠어. 이름은 프로젝트의 첫인상이기도 하고, 다른 사람들이 쉽게 이해할 수 있어야 하니까 고민하다가 결국 ‘classmap-hanthink’를 선택하게 됐지. 이 과정을 통해 프로젝트의 본질을 잘 드러내는 이름이 얼마나 중요한지, 그리고 이름 결정 과정에서 여러 요소를 고려해야 하는지 깨달았어.

내가 헷갈린 지점#

처음에는 ‘py-inherit-tree’처럼 좀 더 명확하게 상속 트리 시각화 도구임을 나타내는 이름을 원했는데, 너무 길고 복잡해서 기억하기 어려울 것 같다는 생각이 들었어. ‘classmap’은 짧고 간결해서 좋지만, 상속 관계를 나타내는 도구라는 점이 잘 드러나지 않아 고민했었지. 결국 확장성을 고려해서 ‘classmap’을 선택했지만, 처음에는 이름에 대한 확신이 없었어.

시도한 코드 / 예시#

class Animal:
    pass

class Dog(Animal):
    pass

class Puppy(Dog):
    pass

class Config:
    pass

class ExternalChild(dict):
    pass

결과와 해석#

처음에는 py-inherit-tree처럼 복잡한 이름도 고려했지만, classmap이 더 간결하고 상속 관계를 직관적으로 보여주는 이름이라고 판단했습니다. classmap . 명령어를 사용하면 현재 디렉토리의 모든 파이썬 파일을 스캔하여 클래스 상속 관계를 확인할 수 있고, --mermaid 옵션을 사용하면 시각적인 다이어그램으로 표현할 수 있습니다.

정리된 이해#

classmap이라는 이름은 짧고 기억하기 쉬우며, 상속 관계를 명확하게 보여줄 수 있어서 좋다고 생각합니다. 앞으로 이 도구가 다양한 기능을 가질 수 있도록 확장성을 고려한 이름이라고 판단했습니다. 전체적인 프로젝트의 역할을 잘 나타내면서도 간결함을 유지하기 위해 이 이름을 선택하게 되었습니다.

2. 상속 관계 이해#

왜 이걸 보게 됐나#

프로젝트를 진행하면서 클래스 간의 상속 관계를 파악하고 시각화하는 기능이 필요했는데, 처음에는 부모 자식 클래스 구분이 명확하지 않아 어려움을 겪었습니다. 상속 관계를 제대로 이해하지 못하면 코드를 분석하고 디버깅하는 데 큰 어려움이 있을 뿐만 아니라, 나중에 코드를 확장하거나 수정하기도 힘들기 때문에 학습하게 되었습니다. 상속 개념을 확실히 숙지해야 프로젝트의 핵심 기능을 구현하고 유지보수할 수 있습니다.

내가 헷갈린 지점#

처음에는 부모 클래스와 자식 클래스가 어떤 기준으로 나뉘는지 헷갈렸고, 특히 외부 베이스 클래스가 어떻게 상속 관계에 영향을 주는지 파악하는 데 어려움을 느꼈다. 독립적인 클래스와 외부 베이스 클래스의 차이점을 명확히 이해하지 못해서 전체적인 상속 구조를 시각화하는 데 시간이 오래 걸렸다.

시도한 코드 / 예시#

  class Animal:
      pass

  class Dog(Animal):
      pass

  class Puppy(Dog):
      pass

  class Config:
      pass

  class ExternalChild(dict):
      pass

결과와 해석#

examples/sample_classes.py 파일을 통해 Animal, Dog, Puppy 클래스의 상속 관계를 명확하게 확인할 수 있었고, 외부 베이스 클래스인 dict를 상속받는 ExternalChild 클래스의 존재를 이해하게 되었다. classmap 명령어를 실행하여 이들의 상속 구조를 시각적으로 표현하는 방법을 익혔고, 이 과정을 통해 클래스 간의 관계를 더욱 직관적으로 파악할 수 있었다. 특히 --show-external 옵션을 사용하면 외부 베이스 클래스가 상속 구조에 어떻게 연결되는지 쉽게 확인할 수 있었다.

정리된 이해#

상속 관계는 부모 클래스의 속성과 메서드를 자식 클래스가 물려받아 사용하는 것을 의미하며, 이를 통해 코드 재사용성을 높이고 클래스 간의 구조적인 관계를 명확하게 표현할 수 있습니다. 특히 독립적인 클래스와 외부 베이스 클래스를 구분하는 것은 상속 관계를 정확히 파악하고 활용하는데 중요합니다.

3. 부모 클래스#

왜 이걸 보게 됐나#

프로젝트에서 클래스 간의 상속 관계를 파악하고 시각화하는 기능이 필요했기 때문에 부모 클래스와 자식 클래스 개념을 배우게 됐어. 상속을 통해 코드의 재사용성을 높이고, 클래스 간의 관계를 명확하게 정의하는 것이 중요해서 그래. 이걸 제대로 이해해야 classmap-hanthink 프로젝트의 핵심 기능을 구현할 수 있어.

내가 헷갈린 지점#

처음에는 상속 관계를 그릴 때 어떤 클래스가 부모이고 어떤 클래스가 자식인지 혼란스러웠어요. 특히, 코드만 보면 어떤 클래스가 베이스 클래스인지, 그리고 독립적으로 존재하는 클래스인지 구분하기 어려웠습니다. 상속을 시각적으로 표현하고 클래스 간의 관계를 파악하는 데 시간이 오래 걸렸습니다.

시도한 코드 / 예시#

class Animal:
    pass

결과와 해석#

부모 클래스는 다른 클래스가 상속받아 기능을 확장하거나 재정의하는 기준이 되는 클래스예요. 예를 들어 Animal 클래스가 부모 클래스라면, Dog 클래스는 Animal 클래스를 상속받아 Animal의 속성과 기능을 그대로 가져오면서 자신만의 특징을 추가할 수 있죠. 코드에서는 Dog(Animal)과 같이 괄호 안에 부모 클래스 이름을 넣어 상속 관계를 표현합니다.

정리된 이해#

부모 클래스는 다른 클래스가 상속받아 기능을 물려받는, 즉 기반이 되는 클래스를 의미합니다. 자식 클래스는 부모 클래스의 속성과 메서드를 그대로 사용할 뿐만 아니라, 자신만의 기능을 추가하거나 기존 기능을 변경할 수 있습니다. 이를 통해 코드 재사용성을 높이고 클래스 간의 관계를 명확하게 정의할 수 있습니다.

4. 자식 클래스#

왜 이걸 보게 됐나#

객체 지향 프로그래밍에서 상속은 코드 재사용성을 높이고, 기존 클래스의 기능을 확장하거나 수정할 때 매우 유용한 기법이에요. 자식 클래스를 배우게 된 건, 부모 클래스의 속성과 기능을 물려받아 새로운 클래스를 만들고 싶어서, 그리고 코드 중복을 줄이면서 더 효율적인 프로그램을 만들 수 있는 방법을 익히기 위해서랍니다.

내가 헷갈린 지점#

처음에는 ‘자식 클래스’라는 단어 자체가 좀 낯설었고, 부모 클래스가 어떤 역할을 하는지 제대로 이해하지 못해서 자식 클래스가 대체 뭘 하는 건지 헷갈렸어. 특히 외부 베이스 클래스를 사용할 때, 자식 클래스가 어디에서 상속받는지 파악하는 게 어려웠어.

시도한 코드 / 예시#

class Dog(Animal):
  # 상속 관계를 보여주는 예시. Animal 클래스는 Dog 클래스의 부모 클래스 (base class)이다.
  # Dog 클래스는 Animal 클래스의 속성과 메서드를 상속받는다.
  pass

결과와 해석#

자식 클래스, 즉 ‘Puppy’ 클래스는 ‘Dog’ 클래스를 상속받아 ‘Dog’의 모든 속성을 그대로 가지면서 추가적인 기능이나 속성을 정의할 수 있다는 걸 알게 되었어. classmap 명령어를 실행했을 때, ‘Puppy’ 클래스가 ‘Dog’ 클래스 아래에 위치하는 다이어그램으로 시각화되는 것을 보면서 상속 관계를 명확하게 이해할 수 있었어. 이는 기존 코드의 재사용성을 높이고, 코드의 중복을 줄여주며, 보다 구조화된 코드를 작성하는 데 도움을 준다는 것을 알게 되었어.

정리된 이해#

자식 클래스는 기존 클래스(부모 클래스)의 기능을 상속받아 확장하거나 수정하는 새로운 클래스를 의미합니다. 즉, 부모 클래스의 속성과 메서드를 그대로 가져오면서, 필요에 따라 추가적인 기능이나 설정을 덧붙일 수 있습니다. 이를 통해 코드 재사용성을 높이고, 클래스 간의 계층적인 관계를 명확하게 표현할 수 있습니다.

총평#

오늘 전체에서 배운 것#

클래스 상속 구조를 시각화하는 도구 이름을 정하고, 부모 클래스와 자식 클래스, 외부 베이스 클래스 등의 관계를 이해하는 데 집중했어요. classmap-hanthink 프로젝트를 사용하면서 파이썬 상속 개념을 좀 더 명확하게 정리할 수 있었습니다.

다음에 조심할 것#

프로젝트 이름 짓는 건 생각보다 어려워서, 앞으로는 더 다양한 이름을 후보군에 두고 고민해야겠다. 상속 관계는 아직 헷갈리는 부분이 많으니, 다양한 예제 코드를 통해 좀 더 숙달해야 할 것 같다.

다음 복습 주제#

외부 베이스 클래스의 상속 처리 로직이 복잡해 보이고, 실제 사용 시 어떤 상황에서 유용하게 쓰일지 더 알아봐야겠다. Config 클래스 같은 독립 클래스가 상속 관계에서 어떻게 위치하는지 명확히 이해하고 싶다.
