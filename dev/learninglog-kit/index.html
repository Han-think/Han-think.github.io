[환경구성] LearningLog Kit — 학습 노트를 블로그로 자동 발행하는 파이프라인

강의자료와 개인 학습 노트, 프로젝트 시리즈를 분리해 intake, extract, preview, approve, publish 흐름으로 정리하는 학습 기록 파이프라인. v0.5.4는 LearningLog와 Projects 메뉴 분리를 포함한다.
2026년 5월 30일 · 5 min

v0.5.4 업데이트 (2026-07-06) — 런처를 LearningLog / Projects / Daily로 분리했습니다. 프로젝트 글은 04_blog_drafts/projects/에 여러 편의 시리즈 초안으로 만들고, 등록·미리보기·승인·발행도 projects 섹션만 보도록 분리했습니다. DailyLog Kit도 1.2로 갱신해 블로그 발행과 별도의 개인 회고 도구임을 명확히 했습니다.

무엇을 만드나#

매일 배운 것을 기록하고 싶지만, 원본 파일을 등록하고, LLM으로 정리하고, 블로그 글로 다듬고, 발행 여부를 확인하는 과정은 생각보다 번거롭다.

LearningLog Kit은 그 과정을 하나의 파이프라인으로 묶는다.

00_inbox
  -> 01_registry
  -> 02_extracted
  -> 03_working_notes
  -> 04_blog_drafts
  -> 05_ready_to_publish
  -> blog-source/content
  -> 06_published

핵심은 “무조건 자동 발행"이 아니라, 원본과 초안과 발행본을 분리해서 안전하게 다루는 것이다.

다운로드#

LearningLog Kit 다운로드 (ZIP · v0.5.4)

Python 패키지로 쓰려면 pip install ./learninglog-kit-v0.5.4.zip[web,gemini] 형태로 설치할 수 있습니다.
Windows 로컬 운영판은 zip 안의 local_powershell/README.md를 먼저 읽고 LearningLog.bat으로 실행합니다.

두 가지 사용 방식#

v0.5.4 킷트에는 두 흐름이 같이 들어 있다.

방식 추천 상황 시작
Python 패키지 / Web UI 가볍게 설치해서 UI로 시작하고 싶을 때 learninglog ui
Windows PowerShell 로컬 운영판 폴더 기반 전체 흐름, preview, approve, publish, unpublish까지 쓰고 싶을 때 local_powershell/LearningLog.bat

Python/Web UI는 기존 킷트의 가벼운 진입점이다. Windows 로컬 운영판은 실제 운영 흐름에 맞춰 더 촘촘하게 정리한 버전이다.

이번 버전부터 Windows 로컬 운영판은 매일 학습 글과 프로젝트 시리즈를 메뉴에서 분리한다. LearningLog는 수업/학습 합본을, Projects는 프로젝트 회고와 분석 글을, Daily는 별도 개인 회고를 맡는다.

Windows 로컬 운영판 구조#

Windows 로컬 운영판은 다음 폴더 구조를 기준으로 동작한다.

00_inbox              원본 소스 투입구
01_registry           CSV 장부와 처리 상태
02_extracted          LLM이 뽑은 사실 요약
03_working_notes      개인 학습 노트
04_blog_drafts        블로그 초안
05_ready_to_publish   발행 승인 대기
06_published          발행 완료 로컬 사본
07_archive            처리 완료 보관
08_templates          Markdown/CSV 템플릿
09_reports            실행 리포트와 미리보기
_local_core           공통 PowerShell 모듈과 로컬 자산

실행은 LearningLog.bat에서 시작한다. 메뉴는 현재 상태를 보여주고, 필요한 단계를 순서대로 실행한다.

[1] LearningLog    학습 기록/발행
[2] Projects       프로젝트 시리즈
[3] Daily          별도 회고 기록
[0] Ollama 서버 시작

v0.5.4에서 좋아진 점#

1. LearningLog와 Projects 메뉴 분리#

매일 학습 합본과 프로젝트 회고가 같은 목록에 섞이면 승인과 발행 때 불안해진다. v0.5.4에서는 첫 화면에서 LearningLog, Projects, Daily를 나누어 고르게 했다.

2. projects 섹션 전용 흐름#

프로젝트 글은 04_blog_drafts/projects/에 생성된다. 등록, 미리보기, 승인, 발행 스크립트에 -Section 필터를 추가해 Projects 메뉴에서는 projects 글만 보도록 했다. LearningLog 메뉴는 learning 글만 본다.

3. 프로젝트 시리즈 초안 생성기#

run_learninglog_project_series.ps1을 추가했다. 빈 프로젝트 시리즈 뼈대 또는 Kaggle House Prices 회고 프리셋을 선택해 개요, pipeline 문법, 분석 축, LLM 리뷰, 검증/액션 플랜으로 나누어 쓸 수 있다.

4. DailyLog Kit 1.2와 역할 정리#

DailyLog Kit은 블로그 발행 도구가 아니라 로컬 개인 회고 도구다. v1.2에서는 LearningLog의 learning/projects 발행 흐름과 DailyLog의 개인 메모 흐름을 분리하고, Google AI Studio의 Gemini API 키로 하루 메모를 정리할 수 있게 했다.

v0.5.3에서 좋아진 점#

1. preview 1개 표시 버그 수정#

v0.5.2에서는 미리보기 대상이 정확히 1개일 때 PowerShell JSON이 배열이 아니라 단일 객체로 들어가면서, 브라우저 화면에서 왼쪽 카드와 양쪽 본문 패널이 비어 보일 수 있었다.

v0.5.3에서는 preview 데이터가 0개, 1개, 여러 개일 때 모두 같은 배열 형태로 들어가도록 고쳤다. 배지 데이터도 1개만 있어도 화면이 깨지지 않게 방어했다.

2. daily 합본 원본 패널 보정#

daily 합본 글은 registry에서 04_blog_drafts/...daily.md 자체를 source로 갖기 때문에, 기존 preview에서는 왼쪽 원본 패널이 daily 초안 자기 자신을 보여줄 수 있었다.

v0.5.3에서는 daily 합본 글을 미리볼 때 해당 AM/PM 멤버 원본 노트들을 묶어서 왼쪽 패널에 보여준다.

3. preview/approve에서 부산물 제외#

LLM 처리 과정에서 생기는 중간 산출물이나 부분 초안이 미리보기와 승인 흐름에 섞이면, 실제로 올릴 글을 고르기가 어렵다.

부산물 초안을 기본 흐름에서 제외해, 공개 후보 글만 더 쉽게 볼 수 있게 했다.

4. daily 합본 글 목차 보정#

기존 daily 합본 글은 섹션 제목에 am-01-join-groupby-having-churn 같은 내부 slug가 그대로 들어갈 수 있었다.

사람이 읽는 한국어 제목을 사용하도록 보정했다. 그래서 목차와 본문 섹션 제목이 다음처럼 보인다.

JOIN, GROUP BY, HAVING으로 이탈 고객 찾기
PARTITION BY와 RANK로 그룹별 순위 이해하기
PERCENT_RANK와 NTILE로 분포 읽기

5. publish 전에 신규/갱신 카운트 확인#

발행 직전에 최종 복사 경로를 기준으로 새 글인지, 기존 글 갱신인지 나눠 보여준다.

신규 추가: 2개
기존 글 갱신: 1개

기존 글을 갱신하는 경우에는 한 번 더 확인을 받는다. 취소하면 복사, Hugo 빌드, git 작업이 시작되지 않는다.

6. unpublish 개선#

잘못 올라간 글을 내릴 때 파일명을 직접 찾아 헤매지 않아도 된다. URL, slug, 목록 선택으로 대상을 지정해 발행 글을 제거할 수 있다.

예를 들어 이런 주소를 넣어도 대상 파일을 찾는 흐름으로 이어진다.

https://example.github.io/learning/some-post/

사전 준비물#

준비물 필요한 이유 확인
PowerShell 7 Windows 로컬 운영판 실행 pwsh --version
Python 3.10+ Python 패키지/Web UI 사용 python --version
LLM API 키 또는 Ollama 노트 정리와 초안 생성 Gemini, Groq, Ollama 등
Hugo extended 블로그 빌드 hugo version
Git GitHub Pages 발행 git --version
블로그 소스 폴더 최종 발행 대상 Hugo/Jekyll 사이트

블로그 발행까지 쓰려면 Hugo와 Git, 그리고 blog-source 같은 실제 블로그 소스 폴더가 필요하다. 정리된 노트까지만 쓰고 싶다면 publish 없이 extract/blogdraft까지만 활용해도 된다.

Python/Web UI 빠른 시작#

pip install "./learninglog-kit-v0.5.4.zip[web,gemini]"
learninglog ui

브라우저가 열리면:

1. 작업 폴더 생성
2. LLM provider 선택
3. API 키 저장 및 테스트
4. 00_inbox에 원본 또는 개인 노트 넣기
5. intake -> extract -> publish 순서로 실행

API 키는 .learninglog/config.yaml에 저장될 수 있으므로 GitHub에 올리지 않도록 주의해야 한다.

Windows 로컬 운영판 빠른 시작#

zip을 푼 뒤:

cd local_powershell
.\LearningLog.bat

처음에는 local_powershell/README.md를 먼저 읽는 것을 권장한다. 이 문서에는 현재 폴더 구조, 메뉴 단계, publish 안전장치, unpublish 방식이 정리되어 있다.

이 도구가 지키는 원칙#

  • 원본 파일은 00_inbox에서 직접 수정하지 않는다.
  • 처리 상태는 registry에 남긴다.
  • 공개 가능한 글과 내부 참고용 부산물을 구분한다.
  • 발행은 05_ready_to_publish를 거친 승인본만 대상으로 한다.
  • 기존 글 갱신은 사용자 확인 후 진행한다.
  • API 키와 개인 노트는 배포 zip에 넣지 않는다.

설치와 제거#
