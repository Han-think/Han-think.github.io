Kaggle Playground S6E7 개인 도전 - 9. 외부 anchor와 단 한 행의 교정

Public 0.95112 제출을 anchor로 유지하면서 한 행 교정으로 0.95113을 확인하고, 그 성공을 일반화하기 위한 비용 민감 규칙을 검증했다.
2026년 7월 15일 · 4 min

재현 가능한 자체 모델이 0.95005에서 멈춘 뒤에는 강한 외부 제출을 새 기준점으로 삼되, 어떤 행을 왜 바꾸는지 설명 가능한 범위에서만 실험했다.

목차#

    1. Run 16~18: 고득점 제출을 anchor로 사용하다
    1. Run 19~24: 그 한 행의 성공을 일반화할 수 있을까
  • 총평

7. Run 16~18: 고득점 제출을 anchor로 사용하다#

이 시점에서 로컬 모델만으로는 0.95005를 안정적으로 넘기 어려웠다.

외부에서 Public 점수가 파일명에 기록된 제출 20개를 확보했다. 이 중 최고 파일의 Public은 0.95112였다. 이것을 새 anchor로 삼았다.

로컬 0.95005 제출과 외부 0.95112 anchor는 Test 295,753행 중 1,459행, 약 0.493%에서 달랐다.

Run 16 — 위원회와 로컬 arbiter#

외부 top-5, top-8, top-10 제출의 합의와 로컬 챔피언을 결합했다.

선택된 변경은 한 행이었다.

id=889660
at-risk -> unhealthy

Public은 0.95112로 같았다.

Run 17과 17_1 — 한 행씩 추적하면 정답을 알 수 있을까#

20개 제출의 hard-label signature가 같은 행을 block으로 묶고, 가장 강한 미검증 block을 한 번에 하나씩 바꿨다.

Run 17의 한 행도 0.95112였다.

남은 세 block을 A, B, C라고 두고 AB, AC, BC 세 제출을 만들었다. 세 점수를 알면 각 block의 효과를 역산할 수 있을 것 같았다.

하지만 세 제출이 모두 0.95112였다.

Kaggle 화면의 소수점 다섯 자리 해상도 안에서는 다음을 구분할 수 없었다.

  • 실제 변화가 정확히 0
  • 변화는 있지만 같은 반올림 구간
  • 변경 행이 Public subset에 없음
  • 두 변경의 양·음 효과가 상쇄됨

같은 점수는 정답을 알려주지 않았다.

Run 18 — 공개 노트북을 정확히 재현하다#

공개된 Student Health Signal Engine 노트북의 방식을 정확히 재현했다.

이 모델의 성격은 기존 로컬 챔피언과 달랐다.

  • 전체 train을 사용하는 Accuracy CatBoost
  • 13개 원본 특성
  • iterations=360, depth=8
  • 외부 top-5/8/10 위원회가 갈리는 20행만 검사
  • 강한 대안 확률과 margin을 만족하는 행만 수정

선택된 행은 하나였다.

id=776133
fit -> at-risk
p_alt = 0.8250
margin = +0.7569

그리고 Public이 바뀌었다.

0.95112 -> 0.95113

이 세션에서 Public 상승을 직접 확인한 유일하게 해석 가능한 단일 변경이었다.

중요한 것은 Accuracy CatBoost 전체가 더 좋은 모델이라는 뜻이 아니라는 점이다. 오히려 강한 외부 anchor를 유지하고, 모델이 매우 확신하는 희소한 한 행만 교정했기 때문에 성공했을 가능성이 높았다.

8. Run 19~24: 그 한 행의 성공을 일반화할 수 있을까#

Run 18의 성공 이유를 이해하면 같은 형태의 행을 더 찾을 수 있을 것 같았다. 여기서 다시 여러 가설을 검증했다.

Run 19 — 소수 클래스 과보정 회수#

Accuracy CatBoost가 기존 balanced 모델의 소수 클래스 과보정을 at-risk로 되돌릴 수 있다고 가정했다.

하지만 primary 규칙의 결과는 다음과 같았다.

delta = -0.001608
fold wins = 0/5
rare recall drop = 0.010082

Run 18의 한 행을 넓은 규칙으로 일반화하는 것은 실패했다.

Run 20 — 1,459행 부검#

외부 anchor와 로컬 챔피언이 다른 1,459행을 transition, 확률 gap, 외부 투표, 특성 이동으로 분해했다.

주요 transition은 다음과 같았다.

transition 행 수
unhealthy -> at-risk 626
at-risk -> unhealthy 483
fit -> at-risk 179
unhealthy -> fit 83
at-risk -> fit 73
fit -> unhealthy 15

로컬 모델 기준 55.4%가 확률 gap 0.10 이하의 경계 행이었다.

수치형 특성을 한 축으로 줄였을 때 건강축 순서는 다음처럼 보였다.

unhealthy -> at-risk -> fit

처음 기대했던 종 모양과 건강축 아이디어가 다시 등장했다.

Run 21 — 건강축 LDA#

7개 수치특성으로 shrinkage LDA를 만들고, 기존 모델의 gap이 0.10 이하인 행에만 10% log-pool했다.

각 fold의 geometry BA는 약 0.748~0.753으로 나쁘지 않았다. 총 정답 변화만 보면 더 흥미로웠다.

wrong -> correct = 887
correct -> wrong = 376
net correction = +511

그런데 최종 Balanced Accuracy는 -0.000330, 0/5 fold였다.

왜일까?

정답이 된 887행 중 다수는 상대적으로 값이 싼 at-risk였고, 손해 본 행에는 더 비싼 희소 클래스가 포함됐다. 특히 unhealthy recall이 -0.002027 하락했다.

이 결과는 Balanced Accuracy를 가장 직관적으로 보여주는 사례였다.

더 많은 행을 맞혔는데도 점수는 내려갈 수 있다.

Run 22 — 비용 민감 fit -> at-risk#

30개 전체 특성으로 fit/at-risk 이진 LightGBM을 만들고, 두 모델이 모두 at-risk라고 동의할 때만 변경했다.

selected rows = 616
wrong -> correct = 575
correct -> wrong = 40
observed precision = 93.4959%
break-even precision = 93.7057%
delta = -0.000012

거의 손익분기였지만 아주 조금 부족했다.

Run 22_1 — 0.80 tail 확인#

cutoff 0.80을 미리 고정하고 새로운 stratified 5-fold와 새 model seed로 확인했다.

selected rows = 98
wrong -> correct = 96

precision = 97.9592%

로컬 검증만 보면 매우 깨끗했다.

Run 18 제출에서 Test 두 행을 추가로 변경했다.

id Run 18 Run 22_1
765608 fit at-risk
982096 fit at-risk

Kaggle Public은 0.95113으로 같았다.

같은 점수이므로 이 두 행이 좋았거나 나빴다고 단정할 수 없다. 다만 독립 OOF 근거가 강했고 Public 최고점을 유지했으므로 Private leaderboard 분산 후보로 보존했다.

Run 23 — at-risk와 unhealthy pairwise#

양방향 변경을 한 모델에서 함께 평가했다.

방향 손익분기 정밀도 관측 정밀도
at-risk -> unhealthy 8.8767% 9.6419%
unhealthy -> at-risk 91.1233% 88.7384%

첫 방향은 근소하게 가능성이 있었지만 두 번째 방향이 손익분기에 못 미쳤다. 최종 delta는 -0.000159, 1/5 fold였다.

Run 24 — Accuracy CatBoost를 10%만 섞으면 어떨까#

Run 18에서 사용한 Accuracy CatBoost 확률을 기존 Blend에 정확히 10% 주입했다.

changed rows = 1,232
delta = -0.000199
fold wins = 1/5

다시 한 번 같은 결론이었다.

Run 18은 모델 전체의 승리가 아니라 국소적인 한 행 교정의 승리였다.

총평#

Public을 실제로 올린 변화는 거대한 모델 교체가 아니라 fit에서 at-risk로 바꾼 한 행이었다. 그러나 그 성공을 넓은 규칙으로 확대하자 대부분 실패했다. 좁은 0.80 tail만 새 5-fold에서 살아남았고, Public 표시는 같은 0.95113이었다.
