14. 실행과 재현성#

확인 가능한 최소 누적 실험량은 다음과 같다.

base/auxiliary learner fits = 319
meta model 포함 fits = 339
측정 wall time = 236.46분, 약 3시간 56분

여기에는 다음 시간이 포함되지 않는다.

  • 초기 미계측 모델 학습
  • Kaggle 제출과 score 대기
  • 오류 후 재시작
  • 외부 자료 확인

실험 운영에서 지킨 원칙은 다음과 같다.

  • 기존 OOF, 제출, my_best_submission.csv를 덮어쓰지 않았다.
  • 새 후보는 별도 실행 폴더와 execution JSON에 저장했다.
  • 긴 학습은 fold checkpoint를 남겼다.
  • OOF gate를 통과하지 못하면 제출 파일을 만들지 않았다.
  • 탐색 후에는 새 fold seed 또는 겹치지 않는 행으로 확인했다.
  • 최종 CSV는 행 수, ID 순서, 라벨, 결측, SHA256을 다시 검사했다.

15. 하지 않은 것: TabPFN-3#

TabPFN-3와 공개 starter를 검토했다.

100k GPU probe와 전체 T4x2 후보 노트북까지 준비하고 정적 검증했다. 그러나 실제 실행은 하지 않았다.

  • 로컬 CUDA GPU가 없었다.
  • Kaggle GPU quota와 약 1시간의 실행 비용이 필요했다.
  • 현재 0.95113 대비 기대 개선이 불확실했다.
  • 이미 Public과 로컬의 불일치를 여러 번 확인한 상태였다.

실행하지 않은 모델을 실패로 기록하지 않았다. 결과가 없기 때문에 그저 미실행 후보다.

17. 이번 대회에서 얻은 실전 규칙#

1. 로컬 최고점을 챔피언이라고 부르지 않는다#

새 모델이 높은 OOF를 기록해도 최종 Blend, 독립 확인, Public은 별도 문제다.

2. 탐색과 확인을 분리한다#

같은 fold에서 threshold, seed, weight, feature를 고르면 결과는 낙관적으로 보인다. 고정한 뒤 새 fold 또는 disjoint 행에서 다시 본다.

3. 최종 소비자를 평가한다#

CatBoost를 개선했더라도 최종 제출이 LGB+CatBoost Blend라면 Blend 점수로 판단한다.

4. Balanced Accuracy는 행별 비용표를 먼저 만든다#

변경 방향마다 손익분기 정밀도를 계산한다. 총 정답 수만 보면 잘못된 결론을 낼 수 있다.

5. Public 같은 점수는 정답이 아니다#

다섯 자리 반올림, Public subset 포함 여부, 상쇄 효과를 구분할 수 없다.

6. 성공한 한 행을 전역 규칙으로 확대하지 않는다#

Run 18은 성공했지만 Run 19와 Run 24의 광범위한 일반화는 실패했다.

7. 멈출 기준도 실험 설계의 일부다#

TabPFN을 준비했지만 실행하지 않은 것은 포기가 아니라, 비용 대비 기대값이 낮다는 판단이었다.

총평#

처음에는 건강 특성의 분포를 겹쳐 그리면 세 클래스가 자연스럽게 갈릴 것 같았다. 실제로는 모델보다 검증 구조가 더 어려웠다.

로컬 0.950192가 Public 0.94924가 되었고, 27개의 seed fit은 이득을 만들지 못했고, 처음 좋아 보인 OVR은 fresh 150k의 모든 fold에서 졌다. 총 정답을 511개 늘린 건강축 모델도 Balanced Accuracy는 내려갔다.

반대로 최종 Public을 올린 것은 거대한 새 모델이 아니라 강한 anchor를 거의 그대로 유지한 단 한 행의 교정이었다.

그래서 이 기록의 핵심은 0.95113이 아니다.

무엇이 좋아 보였는지, 어떤 검증에서 무너졌는지, 왜 Balanced Accuracy에서 행의 가치가 달랐는지, 그리고 어느 순간 추가 탐색을 멈춰야 했는지를 남긴 것이 더 중요하다.

Kaggle에서 점수는 결과지만, 다음 대회에 가져갈 수 있는 것은 결국 검증 가능한 실험 과정이다.
