그린존 확장 8 — 운영 기능을 화면과 로컬 데이터까지 연결하기

D 팀 제출본을 바꾸지 않고 C 개인 통합판에 운영 자료·이력·시나리오 흐름을 연결하려는 목표와 현재 남은 연결점.

C에서 더 완성하고 싶은 운영 문제와 목표#

팀 저장소 D에서는 검색, 지도, 경로안, 배출 안내, 관리자 자료 관리를 하나의 제출 가능한 흐름으로 정리했다. 하지만 관리자가 실제로 운영한다면 안내 문서만 바꾸는 것으로 충분한지, 거점 제안과 현장 의견, 작업 기록, 영상 검토까지 어떻게 이어지는지 더 고민하고 싶었다.

그래서 개인 통합판 C는 팀 제출 D를 덮어쓰는 브랜치가 아니라, 핵심 서비스 구조를 참고해 내 로컬에서 추가 기능을 연결해 보는 작업 공간으로 두었다. 두 저장소를 섞어 설명하지 않는 것이 먼저였다.

운영 기능의 구조와 현재 코드#

C에는 운영 레코드 저장, 변경 이력, 시나리오, 영상 작업을 위한 서버 코드와 화면 뼈대가 들어 있다. 관리자 관점에서 생각한 흐름은 다음과 같다.

자료 등록·검토 → 상태와 출처 관리 → 변경 이력 확인
            → 거점 시나리오 비교 → 현장 확인 항목 기록

시나리오는 팀 Louvain 분석의 결과를 다시 계산하거나 대체하는 용도가 아니다. 기존 분석 결과를 기준으로 몇 가지 조건을 바꾸었을 때 어떤 차이를 비교할지 살피는 추가 도구다. 근사 계산이나 관리자 입력값은 팀의 공식 분석 결과와 구분해야 한다.

화면 연결 구현의 현황#

현재 C에는 API와 저장 구조가 추가되었지만, 일부 화면 연결이 빠져 있다. 운영 페이지에서 호출하는 JavaScript가 없고, 주민 의견이나 거점 카드로 연결되는 일부 템플릿도 빠져 있어 API만 존재한다고 사용자 흐름이 끝난 것은 아니다. 영상과 시나리오도 화면에서 실제로 등록하고 결과를 확인하는 종단 검증 자료가 남아 있지 않다.

이 점을 확인한 뒤 “C에 운영 기능이 완성됐다”고 쓰지 않기로 했다. 지금 상태를 정확히 말하면 운영·영상·시나리오를 위한 기반 코드가 있고, 화면 연결과 실제 로컬 흐름 확인이 남아 있다.

완료 검증 순서와 다음 단계#

  1. 관리자 운영 화면에서 자료 목록·등록·수정·중지·복원과 이력을 실제 로컬 DB로 연결한다.
  2. 각 저장 동작 뒤 사용자 화면에서 어떤 값이 언제 바뀌는지 확인한다.
  3. 데이터가 없는 경우, 잘못된 값, 수정 취소, 중복 등록을 확인해 빈 상태와 오류 안내를 만든다.
  4. 시나리오 비교값에는 입력 조건·계산 기준·근사 한계를 표시하고 팀 분석 결과와 나란히 놓는다.
  5. 사용 가능한 데이터가 없는 시설은 임의로 채우지 않고 “자료 미확보”로 둔다.

이 순서가 끝나야 관리자에게 보이는 기능이라고 할 수 있다. 외부에 공개하거나 실제 기관 업무에 붙이는 일은 별도의 승인과 운영 준비가 필요하다.

이번 편의 정리#

C에서 더 많은 코드를 추가하는 것보다, 이미 있는 서버 기능을 화면과 데이터의 한 흐름으로 연결하는 것이 지금의 우선 작업이다. 다음 편에서는 영상 처리 코드도 사람의 확인과 안전한 원본 정리까지 연결해야 완성이라 부를 수 있는 이유를 살펴본다.
