1. 최종 스코어보드#

단계 로컬 검증 Public LB (실제 제출)
SGD 베이스라인 (GPT 원본) 0.884453 (80/20 홀드아웃) 0.88188
버그 수정 + LightGBM + grid 보정 0.932107 (OOF) 0.93365
Nelder-Mead 보정 확장 1~3라운드 0.9474→0.9485 (nested) 0.94523→0.94836→0.94892
LightGBM+CatBoost 블렌드 (튜닝 전) nested 0.949451 0.94937 (랭킹 약 650등)

한국시간 21:45 기준 리더보드에서 이 최종 제출의 순위는 371등이었다(리더보드는 다른 참가자들의 제출로 계속 변동하므로 시점에 따라 달라진다). 당시 관측된 Kaggle 상위권 클러스터는 0.95130.9517대로, 최종 결과와 약 0.00130.0017 차이였다.

2. 최종 채택 모델 상세#

최종 아키텍처는 LightGBM(5-Fold OOF, class_weight='balanced', n_estimators=6000)과 CatBoost(동일 fold, Optuna로 튜닝된 하이퍼파라미터, auto_class_weights='Balanced')의 선형 확률 블렌드다. 블렌드 비율은 alpha≈0.52(LightGBM 비중)로 거의 반반이었고, 클래스별 보정 가중치는 [at-risk, fit, unhealthy] ≈ [1.17, 3.0, 2.79] 근처였다(재실행 시마다 미세하게 달라질 수 있음). 피처는 원본 수치형 7개 + 원본 범주형 6개 + 엔지니어링한 stress_activity + 결측 플래그 13개 + 파생 수치 3개로 총 30개였다. 스태킹과 XGBoost는 nested 검증에서 블렌드보다 낮게 나와 최종적으로 채택하지 않았다.

3. 강의 과제였다는 반전#

여기까지 순수하게 점수만 보고 온 뒤, “이걸 정리해서 노트북 파일로 만들고, 결론은 액션플랜으로 수익구조화를 하는 것까지가 강의 프로젝트의 목적"이라는 말로 이게 사실 강의 과제였다는 게 드러났다. 별도의 rubric 문서는 없어서, 평소 쓰던 학습 블로그의 과거 글들을 근거로 요건을 파악했다 — Pipeline 문법을 강조한 글에서는 전처리와 모델을 ColumnTransformer+Pipeline으로 묶어 fold마다 전처리가 다시 fit되게 만드는 게 핵심이라는 점을, 검증 관련 글에서는 세그먼트별 오차 분석과 우선순위 액션 리스트 형식을 확인했다. 사업 컨셉은 헬스케어 앱/구독 서비스(B2C), 산출물은 실제 .ipynb 파일, SCQA 청중은 가상의 경영진/투자자로 정했다.

4. 노트북 제작 — 구조와 겪은 버그들#

노트북은 SCQA와 바바라 민토 피라미드 구조를 따랐다: 결론과 3가지 핵심 근거를 담은 피라미드 다이어그램, Executive Summary, 데이터 개요, Mutual Information과 stress×activity 히트맵 같은 핵심 발견, 그리고 모델링 여정 — 원래 GPT의 SGD 베이스라인을 정식 Pipeline으로 재현해 왜 최종 모델(트리 기반)은 Pipeline을 안 썼는지도 정직하게 설명했다. SHAP 해석에서는 unhealthy 클래스 기준으로 gain importance 1위와 다르게 bmi가 SHAP 기준 1위로 나와서, 이걸 “Premium 플랜 코칭 콘텐츠에 체중 관리도 포함해야 한다"는 제품 인사이트로 연결했다. 마지막엔 리스크 티어→상품 티어 매핑, 오분류 비용 논의, 가상 시장규모 계산까지 붙였다(실제 조사 데이터가 아님을 명시).

제작 중 겪은 버그도 몇 가지 있었다. matplotlib 기본 폰트로는 한글이 깨져서 Malgun Gothic을 지정해야 했고, SHAP 셀에서 test가 정의되지 않았다는 에러가 나서 해당 셀에서 test 데이터를 별도로 로드하도록 고쳤다. 피라미드 다이어그램은 꼭대기 폭이 좁아 텍스트가 잘려서 폭을 넓히고 텍스트를 줄여 해결했고, 별개 스크립트에서는 pandas 3.0에서 groupby().apply(sample)이 타겟 컬럼을 없애버리는 문제를 train_test_split(stratify=...)로 교체해 해결했다.
