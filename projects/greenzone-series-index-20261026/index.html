문제와 목표 — 이 연재를 읽기 전에#

그린존은 신월1동의 건물과 공공자료를 살펴 생활권·거점안을 비교하고, 그 결과를 검색 지도와 배출 안내로 연결한 팀 프로젝트다. 이 연재는 제출 결과를 다시 따라가며, 처음의 큰 아이디어가 팀 대화와 검토를 거쳐 어떻게 작아지고 구체화됐는지 기록한다.

처음에는 쓰레기 배출 문제를 넓게 다루려 했다. 도움을 받아도 놓친 질문은 계속 나왔다. 주민이 어디서 검색하는지, 지도에서 무엇이 먼저 보여야 하는지, 분석 결과를 실제 운영처럼 오해하지 않게 하려면 무엇을 밝혀야 하는지 하나씩 발견했다. 그래서 기능을 무작정 늘리기보다 이용 흐름과 화면 우선순위를 조금씩 정리했다.

앞의 7편은 팀 저장소와 제출 결과에 확인되는 내용이다. 실제 날짜별 작업일지를 그대로 재현한 것은 아니다. 뒤의 2편은 개인 통합판에서 더 살펴보고 싶은 확장 아이디어이며, 팀 제출 기능과 구분한다.

구조와 결정 — 한눈에 보는 구성#

편 주제 살펴볼 질문
1 범위와 문제 정의 큰 아이디어를 왜 신월1동의 서비스 흐름으로 줄였나?
2 공공자료 수집 자료마다 기준과 범위가 달라 무엇을 확인했나?
3 수요 해석 등록 주거단위는 무엇을 뜻하고 무엇을 뜻하지 않나?
4 생활권과 거점안 분석 결과를 어떤 관점으로 비교했나?
5 검색과 지도 사용자가 필요한 정보를 찾도록 화면을 어떻게 다듬었나?
6 사진과 배출 안내 AI 제안과 공식 근거, 사용자 확인을 어떻게 나눴나?
7 관리자와 구현 범위 시연 기능과 실제 운영의 경계는 어디인가?
8 운영 기능 확장 개인 작업에서 다음에 연결하고 싶은 것은 무엇인가?
9 영상 검토 구상 영상 분석을 다루려면 어떤 사람 확인과 보호가 필요한가?

구현과 확인 — 공개 범위와 표기 기준#

공공자료는 행정 경계, 건물·주거 현황, 도로·보호시설, 폐기물 배출 안내와 통계처럼 주제별 범주로만 설명한다. 원본 데이터 구조와 내부 가공 절차는 공개 글에서 생략했다. 결과 수치는 어떤 자료를 어떤 가정으로 해석했는지와 한계를 함께 적는다.

팀원 표기는 공개된 GitHub 계정만 사용한다: Han-think, SnNiFe, dg-logs, hihiimj. 실명이나 개인 연락처, 개인별 역할을 계정만으로 추정해 붙이지 않는다. 팀 저장소

한계와 다음 단계 — 글의 기준#

AI는 생각을 넓히고 초안을 정리하는 보조 수단으로 사용했다. 사실과 수치는 제출 자료와 공공 출처를 다시 확인하고, 디자인 결정은 팀 의견과 실제 화면을 보며 고쳤다. 도움을 받았다는 사실이 분석 결과나 현장 검증을 대신하지는 않는다.

거점과 경로는 운영 승인 전 분석 제안이다. 등록 주거단위는 실제 거주 인구가 아니며, 배출량은 실측이 아닌 참고 추정이다. 이 구분을 유지하며 프로젝트의 현재 결과와 다음 과제를 이어서 읽을 수 있게 했다.
