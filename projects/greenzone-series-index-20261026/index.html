연재의 목표와 문제 정의#

제출을 마친 그린존 팀 프로젝트를 한 번에 결과만 나열하지 않고, 문제 정의부터 자료와 분석, 지도 화면, AI 안내, 관리자 기능까지 이어지는 흐름으로 다시 정리한다. 앞의 일곱 편은 팀 저장소 D에서 확인한 결과를 기준으로 쓴다. 저장소에 남은 코드·문서·분석 결과를 따라 읽기 좋은 순서로 재구성한 기록이며, 실제 하루별 작업일지와 동일하다고 단정하지 않는다.

여덟째와 아홉째 편은 개인 통합판 C에서 더 구현하고 싶은 확장이다. C에는 운영·영상 관련 코드가 추가되어 있지만, 화면과 API의 연결 또는 종단 검증이 끝나지 않은 부분이 있다. 그 부분을 완성 성과처럼 포장하지 않고, 현재 구현된 토대와 남은 완료 조건을 함께 적는다.

9편의 진행 구조#

편 기준 제목 핵심 질문
1 D 팀 결과 쓰레기 배출 문제를 신월1동 서비스로 좁히다 누구의 어떤 불편을 다루며, 무엇을 이번 범위에서 뺐나?
2 D 팀 결과 데이터 기준일과 출처 정리 어떤 기관의 어떤 데이터를 어떤 시점 기준으로 썼나?
3 D 팀 결과 등록 주거단위로 수요를 추정하다 1,585필지와 7,193은 어떻게 만들어졌고 무엇을 뜻하지 않나?
4 D 팀 결과 Louvain으로 생활권을 나눈 이유 6개 기존 후보와 3개 대안은 어떤 비교로 만들어졌나?
5 D 팀 결과 검색·지도·수거 경로안을 연결하다 분석 데이터를 주민·관리자 화면에 어떻게 연결했나?
6 D 팀 결과 사진 후보와 공식 안내 근거를 연결하다 사진 분석·사람 확인·RAG·Opik을 어디에 썼나?
7 D 팀 결과 구현 결과와 실제 운영의 경계를 정리하다 관리자·ERD·검증 결과와 한계는 무엇인가?
8 C 개인 확장 운영 기능을 화면과 로컬 데이터까지 연결하기 관리자 작업과 시나리오를 어떻게 끝까지 이어야 하나?
9 C 개인 확장 영상 검토 흐름을 사람 확인까지 연결하기 어떤 단계가 구현되어야 영상 분석을 완성이라 부를 수 있나?

검증 범위와 공개 기준#

  • 팀 결과와 개인 확장을 분리한다. C의 새 코드를 D의 팀 제출 기능처럼 설명하지 않는다.
  • 등록 주거단위·조건부 배출량 추정·거리 시나리오를 실제 거주 인구·실측 배출량·현장 성과로 바꾸어 쓰지 않는다.
  • 모델이 제안한 후보, 사람이 확인한 값, 공식 품목·규격·수수료 조회를 구분한다.
  • 공개 저장소에 없는 키, 계정 정보, 로컬 경로, 원본 이미지, 비공개 평가 파일은 싣지 않는다.
  • 사진·지도 캡처는 출처와 재배포 권리를 확인한 뒤 별도 선별한다. 현재 초안에는 원본 이미지가 포함되지 않았다.
  • 1~7편은 확인 가능한 팀 저장소와 제출 분석자료를 기준으로 하며, 현장 운영 승인이나 미확인 로컬 작업 상태까지 뜻하지 않는다.
  • 8·9편은 C 개인 통합판의 확장 기록이다. 코드가 있다는 것과 화면·데이터·사용자 검토까지 연결된 완료 상태를 구분한다.
  • 공개 글에는 API 키, 계정 정보, 개인 비밀번호, 로컬 경로, 원본 사진과 비공개 평가 파일을 넣지 않는다.

게시 순서와 다음 행동#

1~7편을 팀 결과 연재로 먼저 읽고, 8·9편은 개인 확장 기록으로 이어 읽도록 구성했다. 게시 날짜는 독자가 따라오기 쉽도록 연속된 순서로 정하고, 캡처는 출처와 재배포 가능 범위를 확인한 것만 추가한다.

이 연재는 프로젝트 결과를 이해하기 위한 공개용 초안이다. 현장 운영 승인이나 실제 환경의 효과 검증을 의미하지 않는다.
