1. 계기: 보정 개선폭이 줄어들 때#

확률 보정 범위를 넓히는 방식은 라운드마다 개선폭이 줄고 있었다(+0.5 → +0.3 → +0.1점). 같은 모델의 확률을 계속 쥐어짜는 대신, 진짜 새로운 정보 — 즉 다른 모델 — 를 추가하는 쪽으로 방향을 틀었다.

2. CatBoost 추가#

LightGBM과는 다른 트리 분할 방식(대칭 트리, ordered boosting)과 범주형 네이티브 처리가 강점인 CatBoost를 추가했다. auto_class_weights='Balanced'로 학습 단계에서부터 불균형을 처리하게 했다. 설계에서 중요했던 원칙은 “LightGBM과 완전히 동일한 fold를 써야 블렌딩이 의미 있다"는 것이었다 — 그래서 CatBoost 학습 스크립트는 자체적으로 fold를 다시 나누지 않고, LightGBM 학습 때 캐싱해둔 fold 배열을 그대로 읽어서 재현했다.

첫 시도에서 CatBoost가 범주형 NaN을 거부하는 에러가 났다. pandas.Categorical 컬럼을 .astype(str)만 하면 NaN이 문자열 'nan'이 아니라 진짜 float NaN인 채로 object 배열에 남는데, CatBoost는 이걸 받아주지 않는다. .cat.add_categories(['__MISSING__']).fillna('__MISSING__')로 명시적으로 결측 카테고리를 만들어서 해결했다. 이 버그는 작은 샘플로 미리 돌려보는 스모크 테스트 덕분에 69만 행 전체 학습 전에 잡을 수 있었다. 결과는 CatBoost 단독 raw OOF 0.949136 — LightGBM 단독(0.9226)보다 훨씬 높았다. auto_class_weights='Balanced'가 우리가 후처리로 하던 보정의 상당 부분을 학습 단계에서 이미 대신하고 있었던 것으로 해석했다.

3. LightGBM + CatBoost 선형 블렌드#

두 모델의 OOF 확률을 alpha * lgbm + (1-alpha) * catboost 형태로 섞고, alpha와 클래스별 가중치 3개를 합쳐 총 4차원을 Nelder-Mead로 같이 탐색했다. nested 검증도 블렌드 버전으로 확장했다. 결과는 nested 0.949451, 실제 Public LB로 0.94836 → 0.94892까지 확인 — LightGBM 단독(nested 0.948521)보다 명확히 우위였다. 흥미로운 신호도 있었다: 이전까지는 가중치가 탐색 범위 경계에 계속 붙었는데, 이번엔 범위 안쪽([0.4064, 1.2345, 1.1684], 범위는 [0.15, 3.0])에서 멈췄다. 이건 진짜 내부 최적점을 찾았다는 신호로 읽었다.

4. 스태킹으로 일반화#

alpha 블렌드는 모델이 2개일 때만 깔끔하다. 모델이 3개 이상이면 다중 alpha 탐색이 비효율적이라, 로지스틱 회귀를 메타모델로 쓰는 스태킹으로 일반화했다. 각 모델의 확률을 가로로 이어붙여 특징으로 쓰고, class_weight='balanced' 로지스틱 회귀로 최종 판단을 맡기는 방식이라 모델 수가 늘어나도 코드 변경 없이 그대로 확장된다. nested 검증도 동일한 fold-rotation 방식으로 정직성을 확인했다.

5. XGBoost 추가 시도 — 실패#

세 번째 앙상블 멤버로 XGBoost도 시도했다. pandas category dtype을 enable_categorical=True로 그대로 받아줘서 CatBoost 때와 같은 문자열 변환 버그는 없었고, sample_weight로 불균형을 처리했다(XGBoost sklearn API엔 class_weight 파라미터가 없다). 하지만 결과는 raw OOF 0.923616 — LightGBM 수준이지 CatBoost(0.949)에 한참 못 미쳤다. 3모델 스태킹(nested 0.949399)이 오히려 2모델 블렌드(nested 0.949451)보다 낮게 나왔다. 결론은 명확했다 — XGBoost는 도움이 안 됐고 채택하지 않았다. 약한 모델을 앙상블에 더하면 오히려 희석될 수 있다는 것을 실측으로 확인한 유용한 negative result였다.

최종 로직은 캐시 파일 존재 여부를 자동 감지해서 있는 모델 수에 따라 lgbm_only / blend(정확히 2개일 때) / stack(N개 자동 대응) 후보를 구성하고, 이 중 nested 점수가 가장 높은 것을 채택하도록 만들었다.

총평#

이번 글에서 정리한 것#

CatBoost를 추가해 진짜 새로운 정보를 넣은 과정, 스태킹으로 N개 모델에 대응하도록 일반화한 과정, 그리고 XGBoost를 시도했다가 기각한 과정을 정리했다.

다음에 조심할 것#

모델을 더 넣는다고 항상 좋아지는 게 아니다 — 약한 모델은 앙상블을 오히려 희석시킬 수 있으므로, 반드시 nested 점수로 채택 여부를 판단해야 한다.

다음 액션#
