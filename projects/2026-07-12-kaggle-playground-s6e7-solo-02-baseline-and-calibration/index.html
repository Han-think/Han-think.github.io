1. 기존 코드 진단 — 실제로 검증된 것과 아이디어뿐인 것#

기존 GPT 패키지 두 개를 먼저 뜯어봤다. 실제로 실행되고 숫자가 나온 건 SGD 베이스라인 하나뿐이었다(80/20 홀드아웃 balanced accuracy 0.884453). LightGBM·CatBoost 후보 설정이나 클래스별 확률 곱셈 보정 템플릿은 코드로는 있었지만 한 번도 전체 데이터로 실행된 적이 없었다.

두 번째 패키지(advanced_package)는 전체의 3%에 해당하는 2만 행 서브샘플로 “방향성 벤치마크"만 해둔 상태였다. 여기서 중요한 사실 두 가지를 확인했다. 첫째, 클러스터 거리 피처를 추가하거나 클러스터별 모델을 블렌딩하는 시도는 오히려 점수를 깎아먹었다(0.855577, 0.852388 — 글로벌 모델의 0.862922보다 낮음). 둘째, 클래스별 확률에 곱셈 가중치를 주는 방식만 유일하게 개선 효과가 있었다(0.869910). 이 두 결론이 이후 하루 종일의 방향을 실질적으로 정했다 — 클러스터링 계열은 이미 실패로 확인됐으니 다시 시도하지 않고, 확률 보정 쪽을 정식화하는 데 집중한다는 원칙이었다.

2. 치명적 버그: 수치형 컬럼까지 LabelEncoder#

기존 solution.py는 모든 컬럼을 dtype=str로 읽은 뒤, 수치형이든 범주형이든 가리지 않고 전부 LabelEncoder로 인코딩하고 있었다. 문제는 sleep_duration=7.23 같은 값이 “7.23이라는 문자열"로 취급돼 알파벳 순서로 정수가 매겨진다는 점이었다 — 모델은 실제 수면시간의 크기나 순서 정보를 완전히 잃고, 그냥 “몇 번째로 등장한 고유값인가"라는 임의의 숫자만 보게 된다. 게다가 결측치는 전부 0으로 채워서, LightGBM이 결측 패턴 자체를 학습할 기회도 없었다.

수정 방향은 세 가지였다. 수치형 컬럼은 pd.to_numeric(errors='coerce').astype(np.float32)로 진짜 float를 유지하고 결측치는 NaN 그대로 둬서 LightGBM이 결측 방향을 직접 학습하게 했다. 범주형 컬럼은 train과 test를 합친 vocabulary로 pandas.Categorical 처리했다. 그리고 advanced_package의 SGD가 검증했던 class_weight='balanced'를 LightGBM에도 적용하고, 두 GPT 패키지 다 해본 적 없는 진짜 전체 데이터 5-Fold StratifiedKFold OOF 학습을 붙였다. 결과는 로컬 OOF 0.932107, Public LB 0.93365 — 원래 GPT 베이스라인(0.882) 대비 이미 +0.05 이상 개선이었다.

3. 보정 루프 분리와 nested CV#

LightGBM 5-Fold 전체 학습은 수십 분이 걸리는데, 보정 가중치만 바꿔서 여러 번 실험하고 싶을 때마다 처음부터 재학습하는 건 낭비였다. 그래서 학습 단계와 보정 단계를 분리했다 — 학습이 끝나면 OOF 확률, test 확률, fold 정보를 캐시로 저장해두고, 보정 스크립트는 이 캐시만 읽어서 몇 초~몇십 초 안에 가중치를 반복 탐색하게 만들었다.

보정 방식 자체는 predict_proba()가 뽑은 확률 행렬에 클래스별 가중치 벡터를 곱한 뒤 다시 argmax를 취하는 것이다. 소수 클래스(fit, unhealthy) 가중치를 1보다 크게, 다수 클래스(at-risk)를 1보다 작게 주면 리콜이 소수 클래스 쪽으로 더 잘 나오도록 모델을 편향시킬 수 있다. 처음엔 고정 grid 전수 탐색으로 시작했다가, 더 정밀하고 넓은 범위를 빠르게 탐색하기 위해 scipy.optimize.minimize(Nelder-Mead)를 40개 다른 시작점에서 재시작하는 방식으로 바꿨다.

그런데 탐색 범위를 넓힐 때마다 가중치가 매번 범위 경계에 딱 붙는 패턴이 나타났다. 이건 두 가지 중 하나를 의미한다 — 범위를 더 넓히면 진짜 좋아지거나, 아니면 가중치를 탐색한 데이터와 채점한 데이터가 같아서 과적합된 낙관적 점수가 나오는 것이다. 이 둘을 구분하려고 nested cross-validation 정직성 검증을 만들었다. fold를 하나씩 떼어내고, 나머지 4-fold의 OOF로 가중치를 탐색한 뒤 떼어낸 fold로 채점하는 방식이다. 이렇게 하면 가중치를 정한 데이터와 평가한 데이터가 완전히 분리된다.

실제로 벌어진 일은 흥미로웠다. 범위를 넓힐 때마다 naive OOF와 nested 평균이 ±0.001 이내로 거의 일치했고, 세 라운드 연속으로 이 nested 예측치가 실제 Public LB 점수와도 거의 맞아떨어졌다(0.94523 → 0.94836 → 0.94892). 이게 이 방법론 전체를 신뢰하게 된 결정적 증거였다. 동시에 개선폭 자체는 라운드를 거듭할수록 줄었다(+0.5 → +0.3 → +0.1점) — 전형적인 수확체감 곡선이었고, at-risk 리콜을 계속 깎아가며 fit/unhealthy 리콜을 올리는 트레이드오프가 점점 심해지고 있다는 신호이기도 했다.

4. 자잘한 사고들#

run_kaggle.bat을 Git Bash 안에서 cmd.exe /c run_kaggle.bat으로 실행하려다 실패한 적이 있다. MSYS/Git Bash가 /c 같은 단일 슬래시 인자를 자동으로 Windows 경로로 바꿔버려서 cmd.exe가 인자를 못 알아듣고 빈 세션만 열었다 닫혔다. PowerShell로 직접 실행하는 것으로 해결했다. 또 하나는 저장 방식 문제였다 — 처음엔 보정 스크립트도 제출 파일 하나에만 덮어써서, 이전 좋은 결과가 다음 실행에서 사라질 수 있는 위험이 있었다. 타임스탬프와 점수가 붙은 보관용 사본을 항상 같이 저장하도록 고쳐서 해결했다.

다음에 조심할 것#
