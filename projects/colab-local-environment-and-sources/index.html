1. Python 버전 호환성#

왜 이걸 보게 됐나#

강의 자료를 따라하다가 라이브러리 오류가 계속 발생했고, 그 원인이 Python 버전 차이 때문이라는 것을 알게 되었습니다. 로컬 환경과 Colab 환경의 버전이 달라서 호환성 문제가 생긴다는 설명을 듣고, 학습 환경을 제대로 구축하기 위해 꼭 이해해야 할 개념임을 깨달았습니다. 버전 차이로 인한 문제를 해결하고 효율적인 학습을 위해 Python 버전 호환성에 대한 이해가 필요했습니다.

내가 헷갈린 지점#

처음에는 Colab에서 제공하는 최신 Python 버전이 항상 더 좋다고 생각했습니다. 기존 로컬 환경에서 오류가 발생할 때마다 무조건 최신 버전으로 업데이트해야 한다고 생각했고, 버전 차이로 인한 문제가 발생하면 해결하기 어렵다고 여겼습니다. 결과적으로 버전 관리가 복잡하고 오히려 학습에 방해가 될 수 있다는 것을 깨달았습니다.

시도한 코드 / 예시#

import sys
print(sys.version)

결과와 해석#

강의에서는 Python 3.14를 사용해야 해서 가상 환경을 만들어 사용했는데, 로컬 환경은 3.12를 사용했기 때문에 버전 호환성 문제가 발생할 수 있다는 것을 알게 되었다. virtualenv를 통해 Python 3.12 환경을 생성하고 Colab에서는 3.14 환경을 활용하여, 각 환경에 맞는 라이브러리들을 독립적으로 관리할 수 있었다. 이 과정을 통해 학습 환경과 실제 작업 환경을 분리하는 것의 중요성을 깨달았다.

정리된 이해#

강의에서 요구하는 최신 Python 버전과 로컬 환경의 Python 버전이 다를 경우, 라이브러리 호환성 문제가 발생할 수 있다는 것을 알게 되었습니다. 이 문제를 해결하기 위해 가상 환경을 활용하여 각 프로젝트에 맞는 Python 버전과 라이브러리를 독립적으로 관리하는 것이 중요하다는 것을 깨달았습니다. 이를 통해 학습 환경과 실제 작업 환경을 분리하여 오류를 최소화할 수 있습니다.

2. 가상 환경#

왜 이걸 보게 됐나#

기존에 사용하던 파이썬 환경과 프로젝트가 늘어나면서, 각 프로젝트마다 필요한 라이브러리 버전이 충돌할 수 있다는 문제가 발생했어요. 그래서 서로 다른 프로젝트 환경을 깔끔하게 분리하고, 각 프로젝트에 맞는 라이브러리 버전을 자유롭게 사용할 수 있는 가상 환경이라는 개념을 배우게 되었죠. 이를 통해 학습 및 실제 개발 환경의 혼란을 줄이고, 보다 안정적인 개발 환경을 구축할 수 있게 되었습니다.

내가 헷갈린 지점#

처음에는 가상 환경이 단순히 여러 버전의 파이썬을 설치하는 방법인 줄 알았습니다. 그래서 프로젝트마다 다른 파이썬 버전을 쓰는 게 아니라, 그냥 여러 버전을 섞어 쓰는 줄 오해했습니다. 결국 로컬 환경이 꼬일까 봐 시도조차 못하고 Colab에만 의존했던 기억이 납니다.

시도한 코드 / 예시#

# 로컬 환경에서 Python 3.12 가상 환경 생성 및 활성화
# python3.12: 사용할 Python 버전 명시
# myenv: 가상 환경 이름 (원하는 대로 변경 가능)
# -p 옵션은 특정 Python 인터프리터를 사용하도록 지정
# virtualenv -p python3.12 myenv

# 가상 환경 활성화
# source myenv/bin/activate

결과와 해석#

가상 환경을 만들면 특정 프로젝트에 필요한 라이브러리 버전을 고정시켜 다른 프로젝트에 영향을 주지 않고 독립적으로 작업할 수 있어 버전 충돌 문제를 해결할 수 있다. 예를 들어, 로컬 환경에서는 Python 3.12로 설정하고 수업에서는 Colab의 3.14 환경을 사용하는 것처럼 각 환경을 분리하여 관리할 수 있었다. 이를 통해 학습과 실제 프로젝트 진행 모두 안정적인 환경을 유지할 수 있게 되었다.

정리된 이해#

가상 환경은 프로젝트별로 독립적인 Python 버전과 라이브러리를 관리할 수 있게 해주는 도구인데, 이를 통해 학습 환경과 실제 작업 환경의 충돌을 방지할 수 있다. 덕분에 여러 프로젝트를 동시에 진행할 때 버전 호환성 문제를 겪지 않고 각 프로젝트에 최적화된 환경을 유지할 수 있다. virtualenv나 conda와 같은 도구를 사용하면 간단하게 가상 환경을 생성하고 활성화할 수 있다.

3. Colab 역할#

왜 이걸 보게 됐나#

강의를 듣는 동안 Colab 환경에서 코드를 실행하면서 실제 프로젝트 작업을 위한 장소와 혼동되는 경우가 많았습니다. Colab은 편리하지만 일시적인 환경이라는 것을 명확히 인지하고, 안정적인 개발을 위해서는 로컬 환경을 중심으로 작업해야 한다는 것을 깨닫게 되었습니다. 이 이해는 학습 효율성을 높이고, 실제 프로젝트에 적용 가능한 능력을 키우기 위해 필요했습니다.

내가 헷갈린 지점#

처음에는 Colab을 마치 나만의 개발 환경처럼 생각해서, 실제 프로젝트를 진행할 때도 Colab을 사용하려 했습니다. Colab이 편리하고 접근성이 좋다는 이유만으로, 로컬 환경의 중요성을 간과하고 안정적인 개발 환경 구축을 미루었습니다. 또한 Colab이 지속적으로 사용 가능한 환경이라고 생각하여, 중요한 데이터를 저장하거나 장기간 사용하는 것을 당연하게 여겼습니다.

시도한 코드 / 예시#

import matplotlib.pyplot as plt
import numpy as np

x = np.linspace(0, 10, 100)
y = np.sin(x)

plt.plot(x, y)
plt.title('Sine Wave')
plt.xlabel('X axis')
plt.ylabel('Y axis')
plt.show()

결과와 해석#

Colab은 수업 내용 이해를 돕는 임시 실행 환경으로, 코드를 빠르게 테스트하고 실시간 피드백을 받을 수 있어 편리합니다. %matplotlib inline 명령어를 통해 그래프를 바로 시각화하여 데이터 분석 과정을 쉽게 따라갈 수 있었습니다. 하지만 Colab은 불안정한 환경이므로, 실제 프로젝트 개발에는 적합하지 않습니다.

정리된 이해#

Colab은 강사님과 함께 학습 내용을 실시간으로 확인하고 코드를 공유하는 임시 환경이며, 실제 프로젝트 개발을 위한 주된 공간은 아닙니다. 안정적인 개발과 데이터 처리를 위해서는 로컬 환경을 사용하는 것이 좋습니다.

4. 파일 관리 구조#

왜 이걸 보게 됐나#

강의 자료와 실습 파일을 효율적으로 정리하고, 나중에 다시 찾거나 활용할 때 시간을 낭비하지 않도록 하기 위해 파일 관리 구조에 대한 이해가 필요했습니다. 특히, 여러 버전의 파일들이 섞이거나, 자료의 출처가 불분명해지는 상황을 방지하기 위해 체계적인 구조를 갖추는 것이 중요했습니다. 파일 관리 방식은 단순히 자료를 보관하는 것을 넘어 학습 효율을 높이는 핵심 요소라는 것을 깨달았습니다.

내가 헷갈린 지점#

처음에는 Colab과 로컬 환경의 역할을 명확히 구분하지 못하고, Colab을 주 개발 환경으로 생각하여 불편함을 느꼈습니다. 또, 수업 자료와 실습 파일들이 섞여 있는 폴더 구조 때문에 어떤 파일을 어디에 저장해야 할지, 자료를 어떻게 활용해야 할지 혼란스러웠습니다.

시도한 코드 / 예시#

import os
import pandas as pd
import hashlib

def scan_lectures_folder(folder_path):

    registry = pd.DataFrame(columns=['filename', 'filetype', 'hash', 'policy'])

결과와 해석#

lectures 폴더 내 파일을 스캔하여 새로운 파일을 감지하고, 파일 이름, 확장자, 해시값, 공개 정책을 source_registry.csv에 기록하는 간단한 파이프라인을 구현했습니다. 파일을 자동으로 분류하고 source_registry.csv에 등록하는 과정을 통해 파일 관리가 효율적으로 이루어지는 것을 확인했습니다. 해시값을 활용하여 중복 파일을 방지하는 기능도 필요하다는 생각을 했습니다.

정리된 이해#

Colab은 교육 및 코드 공유를 위한 임시 환경이며, 실제 프로젝트 개발은 로컬 환경에서 진행하는 것이 안정적입니다. 자료들은 Colab에서 학습하고, 로컬 환경에서 프로젝트를 개발하며 GitHub를 통해 코드 관리를 효율적으로 하는 것이 좋습니다. LearningLog는 이러한 학습 기록을 체계적으로 정리하는 데 도움을 줍니다.

총평#

오늘 전체에서 배운 것#

Python 버전 호환성 문제 해결을 위해 로컬 환경과 Colab을 분리하여 사용하고, 프로젝트별 가상 환경을 활용하기로 결정했습니다. Colab은 임시 실행 환경으로 활용하고, 실제 개발은 로컬 환경에서 진행하며 GitHub을 통해 코드 관리를 할 예정입니다. 또한 LearningLog 파이프라인이 신규 파일을 감지하고 등록하는 과정을 이해하게 되었습니다.

다음에 조심할 것#

Colab 사용 시 환경 변수나 라이브러리 버전이 로컬 환경과 다를 수 있으니 항상 주의해야겠다. 프로젝트 규모가 커지면 가상 환경 관리가 더 중요해질 것 같아 꾸준히 학습하고 적용해야겠다. 파일 관리 구조를 명확히 이해하고, 깃허브를 적극 활용하여 코드 관리를 철저히 해야겠다.

다음 복습 주제#

conda 환경 설정과 관리에 대한 깊이 있는 학습이 필요하고, Colab 외에 로컬 환경에서 실제 프로젝트를 진행하며 디버깅하는 경험을 쌓아야겠다. nbconvert를 활용한 파일 변환 기능이 더 다양한 형식을 지원하는지 알아봐야겠다.
