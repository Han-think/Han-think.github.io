1. 버전 관리#

왜 이걸 보게 됐나#

처음에는 코드를 완성하는 게 전부라고 생각했는데, 실제로는 패키지가 발전하는 과정을 기록하고 관리하는 게 중요하다는 걸 알게 됐어. 단순히 코드를 짜는 것만으로는 다른 사람에게 공유하거나, 나중에 업데이트를 진행할 때 어려움이 발생할 수 있거든. 그래서 버전 관리를 배우게 된 거야, 패키지의 성장 과정을 체계적으로 기록하고 관리해서, 공유하고 유지 보수하기 쉽게 만드는 과정이 필요하다는 걸 깨달았어.

내가 헷갈린 지점#

버전 관리가 단순히 코드를 업데이트하고 숫자를 올리는 줄 알았는데, 각 단계별로 commit과 tag를 생성하고 기록해야 한다는 점이 처음에는 복잡하게 느껴졌다. 각 버전의 변경사항을 꼼꼼하게 기록해야 한다는 의무감 때문에 부담스럽기도 했고, 어떤 기준으로 새로운 버전을 만들어야 하는지에 대한 명확한 기준이 없어 막막했다.

시도한 코드 / 예시#

# SRC-20260604-021에서 확인된 Git 태그 생성 예시 (v0.1.0)
git tag v0.1.0
git push origin v0.1.0

결과와 해석#

버전 관리는 패키지가 어떻게 발전하고 변화하는지 기록하는 과정인데, 단순히 코드를 완성하는 것 이상으로 각 기능 추가 단계마다 Git commit과 tag를 생성하며 패키지의 성장 과정을 추적하는 것이 중요하단 걸 알게 되었어. 특히 PyPI 패키지 이름과 import 이름의 형식 차이 (하이픈 vs. 언더스코어)를 명확히 구분해야 하는 점이 헷갈렸지만, 각 단계별로 기록하고 관리하는 게 중요하다는 것을 깨달았어.

정리된 이해#

버전 관리는 코드 변경 사항을 기록하고 관리하는 체계적인 과정이라는 것을 알게 되었다. 단순히 최종 버전을 배포하는 것이 아니라, 각 기능 추가 및 수정 단계를 버전으로 관리하고 기록하는 것이 중요하고, 이를 통해 패키지의 발전 과정을 추적하고 재현할 수 있다는 것을 이해했다.

2. 패키지 배포#

왜 이걸 보게 됐나#

단순히 코드를 짜는 것만으로는 부족하다는 것을 깨달았어. 패키지 배포를 배우게 된 건, 나 혼자만 사용하는 코드를 다른 사람에게 공유하고, 버전 관리하며 지속적으로 개선해 나가는 과정을 경험하고 싶었기 때문이야. 특히 다른 개발자들이 내 코드를 사용하고 피드백을 주면서 함께 성장할 수 있도록 만드는 방법을 배우고 싶었어.

내가 헷갈린 지점#

패키지 배포를 생각하면 최종 버전을 PyPI에 올리는 것뿐이라고 생각했는데, 버전 관리, Git 태그, 테스트 실행 등 생각보다 훨씬 복잡한 과정이 필요하다는 점이 처음엔 헷갈렸다. 특히 GitHub 저장소 이름, PyPI 패키지 이름, Python import 이름이 서로 달라서 어떤 것을 따라야 할지 몰라 혼란스러웠다. 하이픈과 언더스코어의 구분도 명확하지 않아 오류의 원인이 될 수 있다는 점이 걱정되었다.

시도한 코드 / 예시#

# 예시: PyPI 패키지 업로드 (setup.py 내용)
# 실제 값: 'setup.py' 파일의 내용
# 이 코드는 예시이며, 실제 setup.py 파일에는 더 많은 설정이 포함될 수 있습니다.

from setuptools import setup, find_packages

setup(
    name="mathlib-hanthink",  # PyPI 패키지 이름
    version="0.3.0",  # 현재 버전
    packages=find_packages(),
    install_requires=[],
    author="Your Name",
    author_email="your.email@example.com",
    description="A simple math library.",
    url="https://github.com/your_username/mathlib-hanthink",
)

결과와 해석#

Python 패키지 배포 실습을 통해 단순히 코드를 만드는 것 외에 버전 관리, 테스트, PyPI 업로드, 그리고 기록 관리의 중요성을 깨달았습니다. 패키지 이름과 import 이름의 형식 차이에 주의해야 하며, 하이픈과 언더스코어의 사용법을 명확히 구분하는 것이 오류 방지에 핵심적이었습니다.

정리된 이해#

패키지 배포는 단순히 코드를 올리는 것이 아니라, 버전 관리 시스템을 이용해 기능별로 변화를 기록하고, 각 단계마다 테스트를 거쳐 안정성을 확보하는 과정이라는 것을 알게 되었다. 패키지 이름, 저장소 이름, import 이름의 규칙을 명확히 구분하고 일관성을 유지하는 것이 중요하며, 이는 배포 과정의 오류를 예방하는 데 필수적이다.

3. 이름 규칙#

왜 이걸 보게 됐나#

패키지 배포 과정에서 여러 이름이 섞여 있어서 혼란스러웠는데, 각 이름이 서로 다른 목적과 규칙을 가진다는 것을 알게 됐어. GitHub 저장소 이름은 프로젝트를 식별하고, PyPI 패키지 이름은 다운로드 가능성을 나타내며, import 이름은 코드 내에서 사용되는 방식과 연관되어 있다는 점을 이해했어. 이러한 이름 규칙을 제대로 따르지 않으면 프로젝트를 제대로 관리하고 다른 사람들과 공유하기 어려워진다는 것을 깨달았지.

내가 헷갈린 지점#

GitHub 저장소 이름과 PyPI 패키지 이름, 그리고 Python import 이름이 왜 이렇게 다를까 싶어서 처음에는 엄청 헷갈렸어. 특히 mathlib-hanthink와 mathlib_hanthink을 구분하지 못해서 계속 import 에러가 나는 바람에 당황했지. 하이픈과 언더스코어의 의미 차이를 제대로 이해하지 못하면 패키지 배포 자체가 막힐 수 있다는 걸 깨달았어.

시도한 코드 / 예시#

# GitHub 저장소 이름: mathlib-hanthink
# PyPI 패키지 이름: mathlib-hanthink
# Python import 이름: mathlib_hanthink
# Git 태그 이름: v0.1.0, v0.2.0, v0.3.0

결과와 해석#

패키지 이름, 저장소 이름, import 이름은 모두 달라야 한다는 것을 깨달았고, 하이픈과 언더스코어는 구분해서 사용해야 한다는 점이 중요했다. 이 명명 규칙들을 제대로 지키지 않으면 코드가 제대로 작동하지 않거나 배포 과정에서 문제가 생길 수 있다는 것을 알게 되었다.

정리된 이해#

각 플랫폼마다 이름 규칙이 달라서, GitHub 저장소와 PyPI 패키지 이름은 하이픈을 쓰고, Python import 시에는 언더스코어를 사용하는 것을 이해했다. 이 규칙들을 제대로 구분하지 않으면 import 오류나 배포 과정에서 예상치 못한 문제가 발생할 수 있다는 점을 명심해야겠다.

4. 빌드 및 테스트#

왜 이걸 보게 됐나#

내가 만든 패키지를 다른 사람도 사용할 수 있게 하려면 코드가 제대로 작동하는지 확인해야 하고, 여러 버전의 변화를 체계적으로 관리해야 하니까 빌드와 테스트를 배우게 됐어. 단순히 코드를 완성하는 것만으로는 부족하고, 패키지가 성장하는 과정에서 발생할 수 있는 오류를 사전에 방지하고 안정적인 배포를 보장하기 위해서였어.

내가 헷갈린 지점#

빌드하고 테스트하는 과정이 코드 작성만큼이나 중요한 부분이라는 것을 인지하지 못했다. 특히 테스트 코드를 작성하고 실행하는 것 자체에 익숙하지 않았고, 빌드 과정을 통해 패키지가 만들어지는 과정을 시각적으로 확인하는 것이 생소했다. 처음에는 테스트가 제대로 통과한다고 해서 패키지가 완벽하게 만들어진다고 생각했지만, 빌드 과정에서 발생하는 문제들을 해결하는 것이 패키지 배포의 중요한 부분임을 깨달았다.

시도한 코드 / 예시#

# 예시: setup.py 파일 내용 (빌드 설정)
# 실제 setup.py 파일에 포함될 내용
# name="mathlib-hanthink"
# version="0.1.0"
# ... (다른 설정들)

# 예시: 테스트 실행 명령어 (빌드 과정의 일부)
# 실제 터미널 명령어
# pytest -v

결과와 해석#

빌드 과정에서는 setup.py 파일의 내용을 기반으로 패키지 메타데이터를 생성하고, 이를 실행 가능한 형태로 묶어서 배포 가능한 파일을 만드는 것을 알게 되었다. 테스트는 pytest를 사용하여 각 기능에 대한 자동화된 테스트를 실행했고, 테스트 실패 시 코드 수정 및 버그 해결 과정을 거쳐야 다음 단계로 진행할 수 있었다. 이 과정을 통해 코드의 안정성과 기능의 정확성을 확보하고, 지속적인 통합 개발 환경을 구축하는 중요성을 깨달았다.

정리된 이해#

코드를 완성하는 것만큼 중요한 건 각 기능 추가 단계마다 테스트를 실행하고 빌드하는 과정이었어. 이를 통해 코드가 예상대로 동작하는지 확인하고, 패키지 개발 과정을 체계적으로 관리할 수 있다는 점을 알게 되었어. 버전 관리를 통해 코드의 변경 이력을 기록하고, 각 단계의 빌드 결과물을 저장하는 것이 중요하겠구나.

총평#

오늘 전체에서 배운 것#

Python 패키지 배포는 버전 관리와 함께 기록하는 과정이라는 것을 알게 되었고, 저장소 이름, 패키지 이름, import 이름의 규칙 차이를 명확히 구분하는 것이 중요함을 깨달았습니다. 단순히 코드를 만드는 것 외에, 배포 과정을 체계적으로 관리하는 것이 중요하다는 점을 배웠습니다.

다음에 조심할 것#

패키지 이름과 import 이름의 규칙을 정확히 구분하고, 하이픈과 언더스코어의 의미 차이를 명확히 숙지해야겠다. 다음엔 배포 과정에서 이름 관련 오류가 발생하지 않도록 각 단계별 이름 규칙을 다시 한번 확인해야겠다.

다음 복습 주제#

PyPI 패키지 이름과 Git 태그 이름을 짓는 규칙, 그리고 import 시 사용할 이름이 어떻게 달라지는지 더 자세히 알아봐야겠다. 빌드 시스템(setup.py, pyproject.toml 등)의 역할과 설정 옵션들을 좀 더 깊이 파고들어서, 좀 더 다양한 환경에서 패키지가 잘 동작하도록 만들고 싶다.
