첫 Kaggle House Prices 도전: 4개의 선형 분석과 4개의 LLM 관점

4개의 선형 분석 트랙과 4개의 LLM 관점으로 진행한 첫 Kaggle 프로젝트
2026년 7월 6일 · 4 min

프로젝트 요약#

첫 Kaggle House Prices 프로젝트는 단순히 제출 파일 하나를 만드는 작업이 아니라, 같은 문제를 여러 선형 분석 트랙으로 비교하고 로컬 LLM을 해석 보조자로 붙여 검증 흐름을 만든 실험이었다. 목표는 Ames 주택 특성 데이터를 이용해 SalePrice를 예측하고, 로컬 검증 점수와 Kaggle public score 사이의 차이를 설명할 수 있는 제출 후보를 고르는 것이었다.

최종 제출 후보는 Advanced linear v3였다. 이 모델은 고차원 one-hot feature 공간에서 RobustScaler와 LassoCV를 사용해 계수 불안정을 줄였고, local 5-fold log-RMSE를 0.110139까지 낮췄다. Kaggle public score는 0.12607로 local CV보다 나빴지만, 이후 검증 감사에서 이 차이가 단순한 전처리 누수보다는 Neighborhood 분포 차이와 저가 주택 구간 약점에 가깝다는 결론을 얻었다.

문제 정의#

House Prices 문제의 핵심은 주택의 면적, 품질, 위치, 연식, 지하실, 차고, 외부 마감 등 다양한 특성을 이용해 최종 판매가격을 예측하는 것이다. 이번 프로젝트에서는 복잡한 모델을 무작정 늘리기보다, 선형 모델 계열을 단계적으로 강화하면서 어떤 변화가 점수와 안정성에 영향을 주는지 확인했다.

처음 세운 질문은 세 가지였다.

1. 단순 선형 회귀는 어느 지점에서 불안정해지는가?
2. 정규화와 스케일링은 House Prices 예측을 얼마나 안정화하는가?
3. local CV와 Kaggle public score 차이는 어떤 검증 방식으로 설명할 수 있는가?

데이터와 경계#

데이터는 Kaggle의 House Prices - Advanced Regression Techniques 대회 데이터를 사용했다. 학습 데이터에서는 알려진 이상 패턴인 GrLivArea 대비 낮은 SalePrice의 극단값 2개만 제거했고, 테스트 데이터는 Kaggle 제출 형식을 유지해야 하므로 어떤 행도 제거하지 않았다.

영역 처리 이유
Train rows GrLivArea/SalePrice 이상치 2개 제거 oversized low-price house가 계수를 왜곡하는 것을 줄이기 위해
Test rows 제거 없음 sample_submission의 모든 Id와 순서를 유지해야 하기 때문
High-risk rows 제거하지 않고 플래그 제출 후 디버깅용
Neighborhood 제거하지 않고 세그먼트 검증 위치 분포 차이를 확인하기 위해

4개의 선형 분석 트랙#

이번 작업은 하나의 모델만 본 것이 아니라, 선형 계열을 단계별로 비교했다.

접근 모델 CV mean CV std 역할
Course DecisionTree DecisionTreeRegressor 0.177098 0.006441 수업 기준선
Simple linear LinearRegression 0.137385 0.020864 단순 선형 기준선
Pipeline LassoCV FeatureEngineer + ColumnTransformer + LassoCV 0.112370 0.006184 수업형 pipeline 구현
Advanced linear v3 LassoCV + RobustScaler 0.110139 0.007380 최종 제출 후보

비교 결과 단순 선형 회귀는 기준선으로는 의미가 있었지만, one-hot feature가 늘어난 상태에서 계수와 예측값이 불안정했다. LassoCV는 불필요한 feature 영향력을 줄였고, RobustScaler는 이상치가 있는 수치형 변수의 영향력을 완화했다. 그래서 최종 제출 후보는 Advanced linear v3로 정했다.

public score가 local CV보다 나빠졌기 때문에, 단순히 “좋은 점수"로 끝낼 수는 없었다. 대신 이 차이가 어디서 오는지 확인하기 위해 검증 감사를 추가했다.

검증 감사#

최종 감사에서는 random CV, repeated CV, price decile stratified CV, Neighborhood GroupKFold를 비교했다.

validation log_rmse_mean log_rmse_std n_folds
cv_safe_random_5fold 0.110170 0.007002 5
cv_safe_repeated_kfold_5x3 0.110440 0.005954 15
price_decile_stratified_5fold 0.109914 0.011926 5
neighborhood_group_5fold 0.121348 0.022803 5

핵심은 random CV와 CV-safe random CV가 거의 같았다는 점이다. 이는 최종 v3 성능이 단순한 fold-preprocessing optimism 때문만은 아니라는 근거가 됐다. 반대로 Neighborhood를 그룹으로 잡았을 때 점수가 크게 나빠졌고, 이 결과는 Kaggle public score와 더 가까웠다. 따라서 다음 개선 방향은 위치 분포 차이와 저가 주택 구간을 더 잘 다루는 것이다.

4개의 LLM 관점#

LLM은 모델을 학습하거나 Kaggle 점수를 만든 것이 아니다. 실험 결과가 나온 뒤 해석, 보고서 구조화, 다음 질문 정리에 사용했다.

LLM 강조점 사용처
GPT-OSS metric structure CV 표와 public gap 설명 구조화
Gemma robustness and next question local CV와 Kaggle public 차이 해석
Magistral regularization and feature selection LassoCV와 feature 선택 설명
Hermes interpretability RobustScaler와 계수 안정성 설명

이 방식은 초보 프로젝트에서 특히 유용했다. 모델링 결과를 바로 결론으로 확정하지 않고, 서로 다른 관점의 해석을 통해 “다음에 무엇을 확인해야 하는가"를 더 분명히 만들 수 있었다.

회고#

이번 프로젝트에서 가장 크게 배운 점은 Kaggle 점수 하나보다 검증 구조가 더 중요하다는 것이다. local CV가 좋아도 public score가 나빠질 수 있고, 그 차이를 설명하려면 검증 방식을 여러 각도로 바꿔봐야 한다. 특히 Neighborhood GroupKFold 결과는 실제 서비스 상황에서 지역 분포가 달라질 때 모델이 약해질 수 있음을 보여줬다.

다음 v4에서는 세 가지를 우선 확인하고 싶다.

1. 저가 주택 구간 전용 feature와 loss 관점 점검
2. Neighborhood interaction과 위치 기반 그룹 안정성 개선
3. LassoCV 유지 여부와 HGB/앙상블 재비교

첫 도전의 결론은 “완벽한 모델"이 아니라 “설명 가능한 제출 후보"를 만들었다는 데 있다. 이 정도면 첫 Kaggle 프로젝트로는 꽤 좋은 출발점이라고 볼 수 있다.
