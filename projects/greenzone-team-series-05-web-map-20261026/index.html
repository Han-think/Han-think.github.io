그린존 5 — 검색 결과가 지도에서 읽히도록 화면을 고치다

검색 위치와 분석 결과를 구분하고, 필터와 지도 표시를 다듬으며 발견한 사용 흐름.

문제와 목표 — 지도에 모두 표시하는 것이 답은 아니었다#

처음 화면에는 생활권, 거점 후보, 도로와 보호시설 등 여러 정보가 한꺼번에 보였다. 데이터가 많다는 것은 장점이었지만, 정작 사용자가 검색한 위치와 관련 정보를 빠르게 읽기 어려웠다.

화면을 보며 팀 의견과 사용성 피드백을 반영했다. 먼저 검색한 위치와 선택한 마커가 눈에 들어오게 하고, 나머지 분석 자료는 필요한 항목을 켜서 확인하도록 바꾸는 방향을 잡았다. 검색창을 접더라도 사용자가 다시 열 수 있는 버튼이 있어야 한다는 점도 함께 반영했다.

구조와 결정 — 검색과 분석 후보를 구분했다#

검색은 보유한 건물·주소 자료에서 대상을 찾아 담당 생활권을 확인하는 기능이다. 지도 서비스는 바탕 지도와 위치 표시를 맡고, 프로젝트 데이터는 검색 결과와 분석 제안의 기준이 된다. 검색되지 않는 주소가 있을 수 있어, 이를 모든 주소를 실시간으로 찾는 서비스처럼 소개하지 않는다.

후보 마커와 검색 결과도 역할이 다르다. 후보는 분석자가 비교할 조사 지점이고, 검색 위치는 주민이 확인하려는 건물이다. 필터를 통해 필요한 정보만 지도에서 보도록 만든 이유다.

구현과 확인 — Leaflet과 Folium을 함께 둔 이유#

Leaflet은 브라우저에서 필터를 바꾸고 마커를 살펴보는 탐색 화면으로 사용했다. Folium은 Python 분석 결과를 HTML 지도 보고서로 표현해 검토하는 데 활용했다. 하나는 인터랙션, 하나는 분석 결과의 지도 표현에 무게가 있다.

두 보기가 별도 데이터나 다른 분석을 뜻하지 않도록 설명을 붙였다. 화면을 둘로 나눈 목적은 기능을 늘리는 것이 아니라, 탐색과 결과 확인의 차이를 쉽게 보여주기 위해서였다.

경로안은 운행 확정이 아니다#

지도에서 거점 방문 순서를 비교하고 경로안을 확인할 수 있다. 사용자가 순서를 지정하는 방식과 가까운 순서로 계산하는 방식을 제공하지만, 실제 수거차 운행 경로로 확정된 것은 아니다. 일방통행과 차량 제원, 회전 조건, 시간대 교통, 현장 정차 가능성을 모두 확인한 내비게이션이 아니기 때문이다.

한계와 다음 단계 — 이번 편의 정리#

화면 디자인은 장식보다 정보의 순서를 정하는 일이었다. 무엇을 먼저 보여주고, 어떤 정보는 사용자가 요청할 때 나타낼지 고민하면서 지도는 분석 결과를 읽게 돕는 화면으로 다듬어졌다.
