1. GitHub 저장소#

왜 이걸 보게 됐나#

코드를 관리하고 다른 사람들과 공유하기 위해 필수적인 도구이기 때문에 GitHub 저장소를 배우게 되었습니다. 내가 작성한 코드를 안전하게 보관하고, 변경 사항을 추적하며, 다른 개발자와 협업할 때 없어서는 안 될 존재라는 것을 알게 되었습니다. 특히 패키지를 배포할 때, 코드를 GitHub에 저장하고 관리하는 것이 기본적인 절차라는 것을 인지하고 있습니다.

내가 헷갈린 지점#

처음에는 GitHub 저장소를 단순히 코드 보관 창고 정도로만 생각했는데, 버전 관리 시스템의 핵심적인 역할을 한다는 것을 몰랐다. 특히, 로컬 저장소와 원격 저장소 간의 연결, 그리고 push와 pull 동작 방식이 어떻게 코드 변경 사항을 동기화하는지 이해하는 데 어려움이 있었다. 또한, 여러 개발자가 함께 작업할 때 GitHub을 통해 어떻게 협업하는지에 대한 그림이 부족했다.

시도한 코드 / 예시#

git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/yourusername/your-repo.git
git push -u origin main

결과와 해석#

깃 저장소는 내 코드를 온라인에 안전하게 보관하고, 여러 버전으로 관리할 수 있는 공간이야. 이번 실습을 통해 로컬 저장소에서 GitHub로 코드를 업로드하는 기본적인 과정을 익혔고, 앞으로 코드 변경 이력을 관리하는 데 활용할 수 있을 것 같아.

정리된 이해#

GitHub 저장소는 내가 작성한 코드와 관련된 모든 것을 보관하는 온라인 공간이야. 버전 관리 시스템을 사용하여 코드의 변경 사항을 추적하고, 다른 사람들과 협업하는 데 필수적이라고 이해하고 있어. 마치 파일들을 안전하게 보관하고 관리하는 디지털 서랍장과 같다고 생각하고 있어.

2. PyPI 배포#

왜 이걸 보게 됐나#

내가 만들고 있는 작은 수학 라이브러리를 다른 사람들이 쉽게 사용할 수 있도록 해주고 싶어서 PyPI 배포 방법을 배우게 되었어. 단순히 코드를 공유하는 것보다, 패키지로 만들어 배포하면 설치와 관리가 훨씬 편리해지잖아. 결국 나중에 더 큰 프로젝트에 참여하거나, 내가 만든 라이브러리를 여러 곳에서 활용하고 싶을 때 필수적인 과정이라고 생각했어.

내가 헷갈린 지점#

처음에는 코드 작성 외에 패키지를 배포하는 과정이 복잡하고, 특히 PyPI와 연동하는 부분이 어떻게 작동하는지 잘 몰랐다. API 토큰과 .pypirc 파일이 왜 필요한지, 그리고 어떤 방식으로 작동하는지 이해하는 데 어려움을 느꼈다. 또한, uv와 twine 같은 도구들의 역할과 연결 고리가 명확하게 느껴지지 않아 전체적인 흐름을 파악하는 데 시간이 걸렸다.

시도한 코드 / 예시#

[build-system]
requires = ["uv"]
build-backend = "uv.core.build"

결과와 해석#

PyPI에 패키지를 배포하는 과정은 코드를 빌드하고 테스트를 통과시킨 후 twine 도구를 사용하여 PyPI 저장소에 업로드하는 방식으로 진행됩니다. .pypirc 파일에 설정된 API 토큰을 통해 안전하게 인증하며, 빌드 시스템은 pyproject.toml 파일에 정의된 설정을 기반으로 작동합니다. 이러한 과정을 통해 다른 개발자들이 쉽게 내 패키지를 사용할 수 있도록 만들 수 있습니다.

정리된 이해#

PyPI 배포는 코드 변경사항을 GitHub 저장소에 올리고, uv를 사용하여 패키지를 빌드한 후 twine을 통해 PyPI에 업로드하는 과정을 통해 다른 사람들이 나의 패키지를 사용할 수 있도록 하는 것을 의미합니다. 이 과정에서 API 토큰과 .pypirc 파일은 PyPI와의 안전한 연결을 위한 중요한 설정 요소입니다.

3. 빌드 및 업로드 도구#

왜 이걸 보게 됐나#

패키지를 만들고 다른 사람과 공유하고 싶어지니, 코드를 빌드해서 배포 가능한 형태로 만들고, 그 파일을 PyPI에 올려서 다른 사람들이 쉽게 설치할 수 있도록 만들어야 했어. 이를 위해 필요한 도구들을 배우게 된 거지. 마치 집을 짓기 전에 필요한 재료를 준비하는 것처럼, 패키지를 배포하기 위해서는 빌드 및 업로드 도구들을 익혀야 했어.

내가 헷갈린 지점#

처음에는 uv와 twine이 서로 무슨 역할을 하는지, 그리고 왜 두 도구를 모두 사용해야 하는지 이해가 안 갔어요. uv가 패키지를 빌드하고, twine이 그걸 PyPI에 올리는 과정이 마치 별개의 작업처럼 느껴져서, 이 둘 사이의 관계가 명확하지 않았습니다. 결국 uv는 패키지 빌드 과정에서 .pypirc 파일과 연동하여 필요한 설정을 가져오고, twine은 빌드된 패키지를 PyPI에 안전하게 업로드하는 역할을 한다는 것을 알게 되었죠.

시도한 코드 / 예시#

[project]
name = "your-package-name"
version = "0.1.0"
description = "Your package description"
authors = [
  { name = "Your Name", email = "your.email@example.com" }
]
dependencies = [
    # "dependency1 >= version1",
    # "dependency2"
]

[build-system]
requires = ["uv"]
build-backend = "uv.core.build"

uv --version

twine upload --repository testpypi your_package_name-0.1.0-py3-none-any.whl

결과와 해석#

uv는 pyproject.toml 파일을 기반으로 패키지를 빌드하는 도구인데, 이전 방식의 setup.py 파일을 직접 만들 필요 없이 프로젝트 설정을 읽어 빌드 과정을 자동화해 준다. twine은 빌드된 패키지를 PyPI에 안전하게 업로드할 때 사용하며, twine upload dist/* 명령어를 통해 업로드 작업을 수행했다. 이 도구들을 사용함으로써 패키지 빌드와 배포 과정을 간소화할 수 있었다.

정리된 이해#

uv는 파이썬 프로젝트의 빌드 과정을 관리하는 도구이고, twine은 빌드된 패키지를 안전하게 PyPI에 업로드하는 역할을 합니다. 이 두 도구를 사용하면 코드를 빌드하고 배포하는 과정을 자동화하여 효율적으로 패키지를 관리할 수 있습니다.

4. 프로젝트 설정 파일#

왜 이걸 보게 됐나#

프로젝트 설정 파일은 패키지를 만들고 배포하는 과정에서 필수적인 요소인데, 이 파일 하나로 패키지의 이름, 버전, 의존성, 빌드 방식 등 중요한 정보들을 정의할 수 있어 전체적인 패키지 관리의 효율성을 크게 높여줘요. 특히, 다양한 환경에서 패키지가 제대로 작동하도록 보장하고, 자동화된 빌드 및 배포 과정을 가능하게 하는 핵심 역할을 수행하기 때문에 중요하게 다루고 있습니다.

내가 헷갈린 지점#

처음에는 pyproject.toml 파일이 단순히 프로젝트에 대한 정보를 담고 있는 설정 파일이라고 생각했는데, 빌드 시스템과 패키지 빌드 과정을 정의하는 핵심 설정 파일이라는 것을 알게 되었다. 특히, 빌드 시스템의 종류와 의존성을 명시하는 부분이 패키지 배포 환경 구성에 중요한 역할을 한다는 점이 신기했다. 프로젝트 설정을 파일 하나로 관리한다는 개념이 처음에는 낯설었는데, 나중에는 코드 구조를 효율적으로 관리하는 데 도움을 준다는 것을 깨달았다.

시도한 코드 / 예시#

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

결과와 해석#

pyproject.toml 파일은 패키지의 빌드 시스템과 관련된 정보를 담고 있는데, 여기에는 사용하는 빌드 백엔드와 필요한 의존성이 명시됩니다. 이 파일을 통해 패키지 빌드 과정이 자동화되고 일관성을 유지할 수 있으며, 다른 개발 환경에서도 동일한 방식으로 빌드할 수 있게 됩니다.

정리된 이해#

프로젝트 설정 파일은 패키지의 메타데이터, 빌드 시스템, 의존성 정보 등 패키지에 대한 모든 설정을 담고 있는 중요한 파일이야. 이걸 통해 패키지가 어떻게 빌드되고, 어떤 의존성을 가지는지 명확하게 정의할 수 있고, 다른 개발자나 빌드 시스템이 패키지를 쉽게 이해하고 사용할 수 있도록 해.

총평#

오늘 전체에서 배운 것#

파이썬 패키지 배포를 위해서는 코드를 GitHub 저장소에 관리하고, pyproject.toml 파일로 패키지 정보를 설정한 뒤, uv로 빌드하고 twine으로 PyPI에 업로드해야 한다. 특히 .pypirc 파일과 API 토큰 관리가 중요하며, 테스트 코드를 통해 패키지의 안정성을 확보하는 것이 필수적이다.

다음에 조심할 것#

.pypirc 파일에 저장된 토큰은 절대로 공개되어서는 안 되고, PyPI 업로드 시 오류 발생 시 twine 사용법을 다시 확인해야겠다. 빌드 시스템과 테스트 실행 과정이 복잡하게 얽혀있어서, 이 부분들을 차근차근 분리해서 이해해야 전체적인 흐름을 파악하기 쉬울 것 같다.

다음 복습 주제#

.pypirc 파일 설정과 토큰 관리를 좀 더 자세히 알아봐야겠다. 특히 토큰이 유출될 경우 발생할 수 있는 보안 문제에 대해 더 깊이 공부해야 할 것 같다.
