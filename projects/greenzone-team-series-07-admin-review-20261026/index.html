그린존 7 — 화면에서 확인한 기능과 실제 운영을 구분하다

관리자 화면과 데이터 구조를 살펴보며 시제품의 구현 범위와 실제 운영에 필요한 조건을 나눈 기록.

문제와 목표 — 관리자는 무엇을 할 수 있어야 하나#

관리자 화면은 개발자가 코드를 고치는 곳이 아니라, 안내 자료와 후보 정보를 검토하고 필요한 변경을 남기는 운영 화면으로 구상했다. 자료를 확인·수정하고 변경 이력을 남기는 흐름을 사용자 화면과 구분했다.

다만 한 PC의 로컬 데이터에 수정 내용이 저장되는 것과 팀 전체가 함께 쓰는 운영 서비스는 다르다. 여러 사용자 계정, 권한, 공용 서버, 백업과 복구가 갖춰져야 실제 운영으로 이어질 수 있다. 시연에서 확인한 동작과 장기 운영을 같은 말로 쓰지 않았다.

구조와 결정 — ERD는 개념도와 실제 저장 구조를 나눠 읽는다#

발표용 ERD는 서비스에서 다룰 정보가 어떤 관계를 갖는지 설명하는 논리 구조다. 실제 코드는 그보다 작은 로컬 데이터 저장 구조를 사용한다. 그림에 표현된 모든 개념이 현재 데이터베이스 테이블로 구현된 것은 아니다.

이 차이를 설명하지 않으면 ERD가 완성된 운영 DB처럼 보일 수 있다. 발표와 README에는 개념 설계와 실제 구현을 분리해 적고, 구현된 범위만 확인된 사실로 남겼다.

구현과 확인 — 무엇을 확인했고 무엇은 남았나#

로컬 시연에서는 사진 후보와 사용자 선택, 안내 자료 조회, 관리자 수정 흐름을 확인했다. 이 확인은 정해진 개발 환경에서 동작을 살펴본 것이며, 실제 주민의 이용성이나 외부 기관 연계, 현장 안전을 증명한 결과는 아니다.

관리자 기능을 여러 PC에서 같이 쓰거나, 기관 자료를 자동으로 갱신하거나, 실제 예약·결제와 연결하려면 별도의 운영 기반과 허가가 필요하다. 이번 결과를 서비스 제안형 시제품으로 설명하는 이유다.

한계와 다음 단계 — 이번 편의 정리#

기능이 화면에 보이는지, 코드에 연결돼 있는지, 실제 환경에서 지속 운영되는지는 각각 다른 확인 단계다. 그 구분을 솔직하게 적는 것이 프로젝트 결과를 더 믿을 수 있게 만들었다.
