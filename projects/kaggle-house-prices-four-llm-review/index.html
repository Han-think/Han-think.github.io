Kaggle House Prices 3: 4개의 LLM은 같은 실험을 어떻게 다르게 읽었나

GPT-OSS, Gemma, Magistral, Hermes가 Kaggle 실험 해석에서 맡은 역할 비교
2026년 7월 6일 · 2 min

LLM을 모델링에 쓴 방식#

이 프로젝트에서 LLM은 학습, CV 계산, 제출 파일 생성을 직접 수행하지 않았다. 실제 학습과 제출 파일 생성은 scikit-learn 코드가 수행했다. LLM은 코드 검토, 보고서 구조화, 결과 해석, 다음 질문 정리에 사용했다.

중요한 원칙은 하나였다.

LLM의 결론을 투표로 결정하지 않고, 코드와 숫자를 고정된 증거표로 삼는다.

4개의 LLM 역할 비교#

LLM 맡긴 관점 유용했던 해석 교정한 부분
GPT-OSS metric structure CV mean/std와 public gap 설명 구조화 단순 선형도 broad pipeline을 공유함을 보완
Gemma robustness and next question local CV와 Kaggle public 차이 해석 v3를 현재 후보로 제한
Magistral regularization and feature selection LassoCV와 feature 선택 설명 미제출 모델과 public score 직접 비교 제거
Hermes interpretability RobustScaler와 계수 안정성 설명 public score 과대평가 교정

GPT-OSS: 지표 구조를 잡는 역할#

GPT-OSS는 여러 실험 결과를 표로 정리하고, local CV와 public score의 차이를 설명하는 구조를 잡는 데 유용했다. 특히 CV mean, CV std, Kaggle public score, gap을 한 흐름으로 보여주는 데 강했다.

다만 GPT-OSS는 설명을 넓게 잡는 경향이 있어서, 단순 선형과 pipeline Lasso의 경계를 다시 코드 기준으로 교정해야 했다.

Gemma: 강건성과 다음 질문#

Gemma는 local CV와 Kaggle public score가 왜 다를 수 있는지 묻는 데 유용했다. 단순히 “점수가 나빴다"가 아니라 “어떤 분포 차이가 있을 수 있는가"를 물어보게 만들었다.

이 관점 덕분에 Neighborhood GroupKFold와 가격대별 오차를 별도로 확인해야 한다는 질문이 더 분명해졌다.

Magistral: 규제와 feature 선택#

Magistral은 LassoCV가 왜 feature 선택처럼 작동하는지 설명하는 데 유용했다. one-hot feature가 많아진 상태에서 모든 feature를 똑같이 믿으면 계수가 불안정해질 수 있고, L1 규제는 일부 feature의 계수를 0에 가깝게 보내며 모델을 단순화한다.

하지만 미제출 모델의 local CV와 제출 모델의 public score를 같은 표에서 직접 경쟁시키면 오해가 생길 수 있어, 이 부분은 사람이 다시 교정했다.

Hermes: 해석 가능성과 발표 흐름#

Hermes는 RobustScaler, 계수 안정성, 발표용 문장 정리에 유용했다. “왜 선형 모델이 아직 의미가 있는가"를 초보자 관점에서 풀어주는 데 강했다.

다만 public score가 나온 뒤에는 낙관적인 표현을 줄이고, local-public gap을 약점으로 인정하는 방향으로 수정했다.

4개 LLM을 쓴 이유#

4개 LLM을 쓴 이유는 정답을 다수결로 뽑기 위해서가 아니었다. 같은 숫자를 서로 다른 관점으로 읽게 해서 내가 놓친 질문을 찾기 위해서였다.

  • 데이터 관점: 결측치는 누락인가 시설 없음인가?
  • 모델 관점: 계수 불안정인가 비선형 부족인가?
  • 검증 관점: random KFold만으로 충분한가?
  • 사용자 관점: 저가·노후·희소 지역의 큰 오차를 어떻게 표시할 것인가?

결론#

LLM은 프로젝트를 대신 완성해 주는 도구가 아니라, 실험 결과를 다시 질문하게 만드는 해석 보조자에 가까웠다. 최종 판단은 코드, OOF 예측, Kaggle score, 검증 감사 표로 고정했고, LLM의 문장은 그 증거를 설명하는 데만 사용했다.
