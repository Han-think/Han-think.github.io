사진 분류 문제와 목표#

대형폐기물 사진을 올리면 가구 이름은 짐작할 수 있어도, 사진만으로 규격·수량·수수료·공식 배출장소까지 확정하기는 어렵다. 보이는 각도와 가림 때문에 침대가 수납장으로 분류되거나, 같은 물건이 두 개로 보일 수도 있다. 그래서 사진 분석의 결과를 최종 정답이 아니라 품목 후보로 제한했다.

업로드한 사진은 서버에 영구 저장하지 않도록 구성했다. 다만 분석을 위해 EXIF를 제거하고 크기를 줄인 뒤 외부 Vision API로 전송한다. “저장하지 않는다”와 “외부로 보내지 않는다”는 같은 말이 아니다. 공개 글에는 원본 사진을 첨부하지 않고, 사용자는 제공자의 처리 정책도 확인해야 한다.

사용자 선택을 포함한 구현 흐름#

서비스의 실제 흐름은 다음과 같다.

사진 업로드 → Gemini가 공식 품목 목록에서 최대 3개 후보 제안
           → 사용자가 후보를 선택하거나 직접 검색
           → 규격·수량을 사람이 확인
           → 보유 DB의 참고 수수료와 공식 신청 경로 표시

모델이 새 품목명이나 금액을 만들어 바로 결제 단계로 넘기는 구조가 아니다. 사용자가 선택한 품목 ID가 허용 목록에 있는지 다시 확인하고, 금액은 선택한 규격과 데이터베이스를 통해 계산한다. 실제 예약·결제는 지자체 공식 사이트에서 진행한다.

초기 실험에서는 AI-Hub의 가구 이미지 일부와 물체가 없는 합성 이미지를 여러 방식으로 비교했다. 표본이 작고 촬영 환경도 제한적이어서 일반적인 정확도나 실제 민원 환경의 성공률로 말할 수 없다. YOLO 학습 모델과 DINO 비교는 이 웹 업로드 경로에 연결하지 않았다.

공식 문서 검색 구조와 근거#

사진 인식과 배출 규칙은 다른 문제다. 사진은 “무슨 품목처럼 보이는가”를 제안하고, RAG는 “어떤 규칙이 공식 자료에 적혀 있는가”를 찾아 설명한다.

배출 안내 화면에서 질문을 받으면 검수한 공식 발췌 문서를 문단으로 나누고, 임베딩 검색으로 관련 근거를 찾는다. Gemini는 검색된 근거에 기대어 답변을 구조화하고, 화면에는 출처와 확인일 또는 시행일을 보여준다. 근거가 없거나 질문에 필요한 품목·규격이 비어 있으면 답변을 보류하거나 확인을 요청한다. 현재 검색 범위는 보유 문서이지 실시간 웹 검색이 아니다.

Opik 관측과 답변 검증 결과#

Opik은 선택 설정에서 실제 서비스 호출의 상태, 근거 ID, 처리시간, 토큰 사용량 같은 관측 정보를 남긴다. 사진·키·주소·질문 원문을 저장하지 않도록 제한했다. 이 관측 로그가 답변의 정답 여부를 자동으로 판정해 주는 것은 아니다.

답변의 질문 충족 여부와 근거 일치는 별도의 고정 질문 평가 파일에서 직접 대조했다. 따라서 “Opik을 붙였으니 환각을 측정했다”라고 쓰지 않는다. 로그 추적과 답변 품질 평가는 서로 다른 작업이다.

평가 결과의 해석과 한계#

고정 개발 질문 14건의 첫 평가에서는 11건이 충족, 3건이 부분 충족이었다. 공식 안내의 누락 문단을 보완한 뒤 같은 14건을 다시 확인했을 때 13건 충족, 1건 부분 충족으로 기록되었다. 최종 세트에서 근거 없는 단정을 발견하지 못했지만, 이것은 전체 질문의 정확도나 일반 환각률 0%를 뜻하지 않는다. 같은 질문과 같은 평가 흐름이기 때문이다.

평가에서 드러난 점은 단순했다. 근거가 없어서 안전하게 보류하는 것은 좋은 출발이지만, 공식 자료에 답이 있는데 검색 자료에 빠져 있으면 사용자의 문제를 해결하지 못한다. 검색 대상 자료의 최신성·누락·상충 여부를 계속 관리해야 한다.

이번 편의 정리#

AI가 제안한 후보와 공식 자료를 확인한 결과를 분리하고, 마지막 선택은 사용자에게 남기는 방식이 이번 구현의 핵심이었다. RAG도 자료 품질과 평가 범위를 함께 관리해야 신뢰를 설명할 수 있다.
