1. 멀티모달 입력 파이프라인 기본 공식#

무엇을 배웠나#

멀티모달 모델 입력은 이미지와 텍스트가 별도 경로가 아닌 하나의 메시지 구조로 통합된다는 점이 핵심이었다. processor를 통해 시각 정보와 텍스트가 섞인 텐서 형태로 변환되는 과정을 이해하는 것이 모델 활용의 시작점이다. 특히 프롬프트 길이만큼 잘라내는 후처리 단계는 생성된 답안을 정확히 추출하는 데 필수적이다.

헷갈렸던 점#

처음 멀티모달 모델을 접했을 때, 이미지와 텍스트가 별도의 경로로 전달된다고 생각했던 것이 가장 큰 오해였습니다. 실제로는 이미지가 텍스트와 섞여 하나의 message 안에 담기며, 이를 처리하는 processor 단계가 필수적입니다. 모델에 바로 입력하면 구조를 이해하지 못해 혼란을 겪을 수 있어, 입력 전처리 과정이 얼마나 중요한지 깨닫게 되었습니다.

정리된 이해#

멀티모달 모델은 이미지와 텍스트를 별도로 처리하는 것이 아니라, 하나의 message 안에 담아 문자열처럼 전달한다는 점이다. 핵심은 processor가 이 메시지를 모델이 이해할 수 있는 텐서 형태로 변환해준다는 점이며, 입력 프롬프트 길이만큼 잘라내는 후처리 과정이 필수적임을 깨달았다.

# Qwen3-VL 멀티모달 입력 파이프라인 핵심 코드

from PIL import Image
from transformers import AutoProcessor, Qwen2VLForConditionalGeneration
import torch

# 1. 모델 및 프로세서 로드
model_id = "Qwen/Qwen3-VL-2B-Instruct" # 예시 모델 ID
processor = AutoProcessor.from_pretrained(model_id)
model = Qwen2VLForConditionalGeneration.from_pretrained(
    model_id, torch_dtype="auto", device_map="auto"
)

# 2. 이미지 준비 (PIL 라이브러리 사용)
image = Image.open("example.jpg").convert("RGB")

# 3. 메시지 구성 (role과 content 배열 구조)
messages = [
    {"role": "user", "content": [
        {"type": "image"},
        {"type": "text", "text": "이 이미지에 무엇이 나와요?"}
    ]}
]

# 4. 프로세싱: 메시지를 모델 입력 텐서로 변환 (핵심 단계)
# apply_chat_template이 image와 text를 섞어 token화합니다.
inputs = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
    tokenize=True,
    return_tensors="pt"
).to(model.device)

# 5. 추론 수행
output = model.generate(**inputs, max_new_tokens=128)

# 6. 후처리: 생성된 전체 텍스트에서 프롬프트 길이만큼 잘라내기
generated_text = processor.decode(output[0], skip_special_tokens=True)
prompt_length = len(processor.decode(inputs["input_ids"][0], skip_special_tokens=True))
answer = generated_text[prompt_length:].strip()

print(f"모델 답변: {answer}")

2. 파일 업로드와 FormData 연결 고리#

무엇을 배웠나#

FormData 사용은 JSON 전송이 불가능한 파일 업로드 시 필요한 multipart 형식이라는 점을 이해하게 되었다. HTML input name과 FastAPI 파라미터 이름이 일치해야 데이터가 올바르게 매핑된다는 연결 고리를 파악했다. 브라우저가 FormData를 통해 자동으로 경계선을 그어 데이터를 포장한다는 과정을 통해 프론트와 백엔드의 데이터 흐름을 명확히 할 수 있었다.

헷갈렸던 점#

JSON 전송 방식과 파일 업로드용 FormData 전송 방식이 다르다는 점이 가장 큰 혼란이었다. 브라우저가 FormData를 multipart 형식으로 자동 포장한다는 사실과, 프론트와 백엔드의 파라미터 이름이 일치해야 데이터가 매핑된다는 연결 고리가 부족했다.

정리된 이해#

FormData는 JSON 전송이 불가능한 파일과 텍스트 필드를 multipart 형식으로 묶어 브라우저가 자동으로 포장해 보내며, 이때 HTML input name과 FastAPI 파라미터 이름이 일치해야 데이터가 올바르게 매핑된다.

<!-- HTML Form (Frontend) -->
<form action="/upload" method="POST" enctype="multipart/form-data">
    <input type="file" name="files" multiple>
    <textarea name="query"></textarea>
    <button type="submit">Upload</button>
</form>

# FastAPI Backend (Backend)
from fastapi import FastAPI, File, Form

app = FastAPI()

@app.post("/upload")
async def upload_files(files: list[UploadFile] = File(...), query: str = Form(...)):
    # 파일과 텍스트 필드가 name 속성으로 매핑됨
    return {"filenames": [f.filename for f in files], "query": query}

3. 소스코드와 모델 파일의 분리#

무엇을 배웠나#

소스 코드와 모델 파일을 분리하여 관리하는 것이 프로젝트 용량을 줄이고 버전 관리를 효율적으로 할 수 있다는 점을 깨달았다. 특히 .venv나 캐시 파일 같은 재생성 가능한 아티팩트는 git에 올리지 않고, 핵심 로직과 모델 ID만 남기는 것이 좋다. 또한 백엔드 변경 시 환경 정합성을 위해 별도의 깨끗한 가상환경을 유지하는 것이 필수적임을 이해했다.

헷갈렸던 점#

소스 코드와 모델 파일을 같은 폴더에 두면 용량이 과도해져서 프로젝트 관리가 어려워진다는 점을 깨닫게 되었다. LLM 모델 파일은 로컬에 올리기엔 크기가 커서, 어떻게 버전 관리하고 공유해야 할지 막막함을 느꼈다. CUDA와 XPU 휠을 섞어 쓰면 안 된다는 조언이 있었으나, 왜 별도의 깨끗한 환경이 필요한지 실감하기 어려웠다.

정리된 이해#

소스 코드와 실행 artifact을 분리하여 관리해야 프로젝트 용량을 최소화하고 환경을 일관성 있게 유지할 수 있다. 모델 파일과 가상환경은 재생성이 가능한 아티팩트로 간주하며, 핵심은 source code, requirements, model ID, backend 선택 이유만 보존하는 것이다.

오늘 오후 전체에서 배운 것#

멀티모달 모델 입력은 시각 정보와 텍스트가 통합된 텐서 형태로 변환되는 것이 핵심이며, 프롬프트 길이 절단은 정확한 답안 추출을 위해 필수적이다. 파일 업로드 시 FormData를 통해 multipart 형식으로 데이터를 전송하며, HTML의 input name과 백엔드 파라미터 이름이 일치해야 데이터가 올바르게 매핑된다. 소스 코드와 모델 파일은 분리 관리하여 프로젝트 용량을 줄이고, 재생성 가능한 아티팩트는 git에 올리지 않는 것이 효율적인 버전 관리의 비결이다.

다음에 조심할 것#

  1. processor 후처리 단계에서 프롬프트 길이만큼 토큰을 잘라내지 않으면, 모델이 생성한 답안에 불필요한 입력 프롬프트가 섞여 정확한 결과 추출에 방해가 될 수 있다.
  2. FormData를 사용할 때 HTML input의 name 속성과 FastAPI 파라미터 이름이 정확히 일치하지 않으면 데이터 매핑이 실패하여 업로드된 파일이 서버에서 인식되지 않을 수 있다.
  3. 프로젝트 관리를 위해 .venv나 캐시 파일 등 재생성 가능한 아티팩트는 git에 올리지 않고, 핵심 로직과 모델 ID만 관리해야 하며, 백엔드 수정 시 환경 정합성을 위해 별도의 깨끗한 가상환경을 유지해야 한다.
