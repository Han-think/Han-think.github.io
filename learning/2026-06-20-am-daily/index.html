1. pandas DataFrame과 Series 기초 다지기#

무엇을 배웠나#

오늘 pandas DataFrame과 Series를 처음 배우면서 SQL과의 역할 차이를 명확히 이해하게 되었고, DataFrame과 Series를 혼동했던 부분도 정리할 수 있었습니다. 특히 df["컬럼"]와 df[["컬럼"]]의 차이를 이해하는 것이 중요했습니다. pandas는 이미 불러온 데이터를 Python 환경에서 유연하게 다루는 도구라는 것을 확실히 알게 되었습니다.

헷갈렸던 점#

처음에는 pandas가 SQL처럼 데이터베이스를 직접 쿼리하는 도구라고 생각했지만, 이미 불러온 데이터를 Python에서 조작하는 도구라는 점을 이해하는 데 어려움을 느꼈습니다. DataFrame과 Series의 차이점, 특히 컬럼 선택 시 반환되는 객체 유형이 헷갈려 코드를 작성하면서 계속 오류가 발생했습니다.

정리된 이해#

pandas는 SQL과 달리 이미 가져온 데이터를 Python 환경에서 유연하게 처리하는 도구이며, 데이터 추출보다는 조작 및 분석에 초점을 맞춘다. DataFrame은 테이블 형태의 데이터 구조, Series는 단일 컬럼 데이터를 나타내는 구조로, 컬럼 선택 시 df["컬럼"]와 df[["컬럼"]]의 차이를 이해하는 것이 중요하다.

2. 데이터 부재 시 문제 정의 및 분석 접근 방식#

무엇을 배웠나#

데이터 분석을 시작하기 전에 데이터의 존재 여부와 품질을 먼저 확인해야 한다는 점을 깨달았습니다. 문제 정의가 중요하지만, 데이터의 현실성을 고려하여 문제 정의를 유연하게 조정해야 분석이 가능하며, 데이터가 없을 때는 대체 데이터를 활용하거나 분석 범위를 축소하는 등의 다양한 해결책을 모색해야 한다는 것을 알게 되었습니다. 결국, 데이터의 현실성을 바탕으로 문제 정의를 재정의하는 것이 분석의 첫걸음이라는 것을 배웠습니다.

헷갈렸던 점#

처음에는 문제 정의가 명확해지면 바로 분석을 시작할 수 있을 거라고 생각했는데, 데이터의 존재 유무와 품질이 분석 전체를 좌우한다는 사실이 당황스러웠다. 특히 문제 정의와 데이터 확보의 우선순위를 어떻게 결정해야 할지 몰라 어려움을 겪었다. 결국 데이터 현실성을 고려하여 문제 정의를 유연하게 조정하는 것이 중요하다는 점을 깨달았다.

정리된 이해#

3. 데이터 시각화, 대상과 목적에 맞춘 효과적인 정보 전달#

무엇을 배웠나#

데이터 시각화는 단순히 그림을 예쁘게 그리는 것이 아니라, 정보를 전달하는 효과적인 커뮤니케이션 도구라는 점을 깨달았습니다. 특히, 대상의 배경 지식 수준을 고려하여 차트를 설계하는 것이 중요하며, 분석 결과를 의사결정에 활용할 수 있도록 정보를 전달하는 것이 핵심이라는 것을 알게 되었습니다. 비즈니스 보고서와 학술 보고서용 차트 예시를 통해 실질적인 적용 방법을 이해했습니다.

헷갈렸던 점#

처음에는 데이터 시각화가 단순히 예쁜 그래프를 그리는 기술이라고 생각했어요. 누구에게 보여주는지에 대한 고민 없이, 단순히 차트를 만드는 데 집중했죠. 결과적으로 데이터 시각화가 정보 전달이라는 커뮤니케이션의 일환이라는 점을 간과했던 것 같아요.

정리된 이해#

데이터 시각화는 데이터를 보여주는 것을 넘어, 대상에 맞춰 정보를 효과적으로 전달하는 커뮤니케이션 도구입니다. 단순히 예쁜 차트를 만드는 것이 아니라, 보는 사람의 이해도를 고려하여 분석 결과를 명확하게 전달하는 것이 중요합니다. 이를 통해 데이터 기반 의사결정을 지원할 수 있습니다.

6. Google Colab과 Drive를 활용한 pandas 데이터 로드 가이드#

무엇을 배웠나#

Google Drive에 저장된 데이터를 Colab에서 pandas를 사용하여 불러오는 방법을 익혔습니다. 특히 Colab 환경에서의 파일 경로는 로컬 환경과 다르다는 점을 이해하고, 데이터 로드 후에는 head(), info(), describe() 등의 명령어를 사용하여 데이터의 구조와 내용을 확인하는 것이 중요하다는 것을 알았습니다. 이제 Google Drive와 Colab을 활용하여 pandas 데이터 분석을 시작할 수 있을 것 같습니다.

헷갈렸던 점#

Google Drive에 있는 파일을 Colab에서 불러올 때 파일 경로가 달라서 어디에 파일이 있는지 계속 찾았었어. 그리고 불러온 파일이 바로 DataFrame이 된다는 점을 인지하지 못해서, 원본 파일과 DataFrame 변수가 무엇인지 헷갈렸던 것 같아.

정리된 이해#

Google Drive에 저장된 파일을 Colab에서 pandas로 불러올 때, 로컬 경로와 Colab 경로를 혼동하지 않도록 주의해야 합니다. 파일이 pandas로 로드되면 DataFrame이라는 데이터 구조로 변환되므로, 원본 파일과 DataFrame을 명확히 구분해야 분석을 진행하기 편리합니다.

7. 데이터 품질 문제: 개념과 실습으로 이해하기#

무엇을 배웠나#

데이터 품질 문제에 대해 “오염됐다"처럼 주관적인 표현으로만 이해했던 기존 방식을 벗어나, 편향, 오류, 결측 데이터, 오염 등의 전문 용어에 대한 정확한 정의와 의미를 파악하게 되었습니다. 또한, 생성형 모델 출력물의 품질 문제와 데이터 품질 검증의 연관성을 이해하고, 실제 검수 과정에서 발생할 수 있는 문제들을 데이터 품질 문제 유형으로 분류하는 방법을 익혔습니다. 이를 통해 데이터 품질 문제에 대한 체계적인 접근 방식을 갖추게 되었습니다.

헷갈렸던 점#

헷갈렸던 점#

정규화는 데이터 관리의 중요성을 강조하는 개념이었는데, 비정규화 분석 테이블 생성 방법과 어떻게 조화되는지 잘 이해가 되지 않았습니다. 데이터 무결성을 유지하는 정규화와 분석 편의성을 위한 비정규화가 서로 상반되는 것처럼 느껴져 혼란스러웠습니다. 결국 두 개념의 목적이 다르다는 것을 깨달았습니다.

정리된 이해#

정규화는 데이터 관리의 효율성과 정확성을 위해 데이터를 구조화하는 것이고, 비정규화는 분석 편의성을 위해 여러 테이블을 결합하여 데이터를 묶는 방식입니다. 이 둘은 목적이 다르며, 운영 데이터베이스에서는 정규화를, 분석에서는 비정규화를 주로 활용합니다. 따라서 정규화와 비정규화는 서로 충돌하는 개념이 아니라, 데이터 활용 목적에 따라 적절하게 선택해야 할 전략입니다.

SELECT
    c.customer_id,
    c.customer_name,
    o.order_id,
    o.order_date,
    p.product_name,
    oi.quantity,
    oi.price * oi.quantity AS total_price
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id;

정리된 이해#

기초 통계량은 데이터를 요약해서 보여주는 중요한 지표들인데, 특히 분산은 데이터가 얼마나 넓게 퍼져있는지를 나타내는 값이라는 점을 명확히 이해해야 한다. 각 통계량들의 의미를 정확히 파악하면 데이터를 더 효과적으로 분석하고 해석할 수 있을 것이다. 앞으로는 이러한 기초 통계량들을 활용하여 데이터의 특징을 파악하는 연습을 꾸준히 해야겠다.

import pandas as pd

data = [10, 12, 23, 23, 16, 23, 21, 16]
df = pd.DataFrame(data, columns=['Values'])

# 평균 계산
mean_value = df['Values'].mean()
print(f"평균: {mean_value}")

# 각 값과 평균의 차이 계산 (편차)
deviations = df['Values'] - mean_value
print(f"편차: {deviations}")

# 편차 제곱
squared_deviations = deviations ** 2
print(f"편차 제곱: {squared_deviations}")

# 분산 계산
variance = squared_deviations.mean()
print(f"분산: {variance}")

15. Pandas 실습으로 겪은 어려움과 핵심 개념 정리#

무엇을 배웠나#

Pandas 실습에서 변수명 혼동과 대소문자 민감성 때문에 어려움을 겪었는데, 라이브러리 이름과 DataFrame 변수명을 구분하고, DataFrame 변수명을 통해 작업해야 한다는 점을 명확히 알게 되었다. 또한, 데이터 필터링 시 컬럼 내 값의 대소문자 차이에 주의해야 한다는 것을 깨달았고, 데이터 분석 과정을 정확하게 이해하고 접근하는 것이 중요하다는 점을 배웠다. 앞으로는 변수명과 대소문자 구분에 더욱 신경 써서 코드를 작성해야겠다.

헷갈렸던 점#

강사님 코드를 따라하다가 변수명이랑 문제 설명에 나오는 이름이 달라서 어디를 건드려야 할지 몰랐고, 데이터 안의 문자 하나하나까지 영향을 준다는 점이 당황스러웠어. 라이브러리 이름이랑 DataFrame 변수명을 헷갈려서 코드가 작동하지 않는 상황이 자주 발생했어.

정리된 이해#

Seaborn 라이브러리를 사용할 때, 라이브러리 이름과 실제 데이터를 담은 DataFrame 변수명을 혼동하지 않도록 주의해야 합니다. DataFrame 변수명을 통해 데이터에 접근하고, 컬럼명과 컬럼 내의 실제 값을 구분하여 필터링 조건을 적용해야 정확한 결과를 얻을 수 있습니다. 특히 대소문자 민감성을 고려하여 데이터 값을 정확하게 입력하는 것이 중요합니다.

import seaborn as sns
tips = sns.load_dataset("tips")
print(tips.head())

16. 가설 검정: 모수 vs 비모수 방법 비교#

무엇을 배웠나#

통계 가설 검정은 시각적으로 차이가 보이는 데이터라도, 그 차이가 우연히 발생한 것인지 확인하는 중요한 과정이라는 것을 배웠습니다. 모수 검정과 비모수 검정은 데이터의 특성에 따라 적절한 방법을 선택해야 하며, 귀무가설과 대립가설을 설정하여 검정을 수행한다는 점도 이해했습니다. 이제 시각화 결과에 섣불리 판단하지 않고 가설 검정을 통해 객관적인 결론을 도출해야 할 것 같습니다.

헷갈렸던 점#

수업에서 그래프로 차이가 보이는 것을 보고 바로 “다르다"고 결론 내리는 것이 잘못이라는 점이 이해가 안 되었습니다. 시각화는 단순히 차이를 발견하는 도구일 뿐이고, 그 차이가 실제 의미 있는지 판단하는 통계적인 검증 과정이 필요하다는 점을 정확히 이해하지 못했습니다. 시각화 결과와 통계적 유의미성 사이의 관계가 명확하게 와닿지 않았습니다.

정리된 이해#

데이터 시각화만으로는 차이가 있는지 확인할 수 있지만, 그 차이가 실제로 의미 있는지는 통계 가설 검정을 통해 판단해야 합니다. 모수 검정은 데이터가 정규분포를 따를 때, 비모수 검정은 분포가 불분명하거나 이상치가 많을 때 활용하여, 귀무가설을 기각하고 대립가설을 채택함으로써 차이가 있다는 결론을 내릴 수 있습니다.

# 예시: tips 데이터셋에서 흡연자와 비흡연자의 팁 금액 차이 분석 (t-test)
import pandas as pd
from scipy import stats

# 데이터 로드 (가정)
tips = pd.read_csv("tips.csv")

# t-test 수행
result = stats.ttest_ind(tips[tips['smoker'] == 'Yes']['total_bill'], tips[tips['smoker'] == 'No']['total_bill'])

# 결과 출력
print(result)

17. 데이터 품질 관리와 출력물 라우팅 이해#

무엇을 배웠나#

데이터 품질 관리와 라우팅 과정에서 태깅의 복잡성과 LLM 판단에 대한 불확실성을 느끼며 어려움을 겪었습니다. 태그는 데이터의 특징을 설명하고 최종 목적지를 결정하는 중요한 힌트 역할을 한다는 점을 이해하게 되었고, 데이터의 출처 추적, 검토 필요 여부, 사용 금지 컨텍스트 등을 고려한 체계적인 관리 방법이 필요하다는 것을 알게 되었습니다. 이를 통해 데이터 품질 관리와 라우팅 결정이 단순히 분류 작업을 넘어 데이터 활용의 효율성을 높이는 중요한 과정임을 깨달았습니다.

헷갈렸던 점#

처음에는 데이터에 태그를 붙이는 것이 단순히 분류하는 일이라고 생각했는데, 각 출력물의 사용 맥락을 판단하는 복잡한 과정이라는 점이 헷갈렸습니다. 특히 여러 요소가 섞인 이미지의 경우, 어떤 기준으로 어디로 라우팅해야 할지 결정하기 어려웠습니다. 또한 LLM의 판단에 의존하는 라우팅 결정 과정에서 결과에 대한 확실한 보증이 없다는 점이 불안했습니다.

정리된 이해#

데이터 품질 관리와 라우팅은 단순히 태그를 붙이는 것을 넘어, 생성된 결과물이 어떤 맥락에서 사용될지 정확히 파악하고 그에 따른 적절한 경로를 결정하는 복잡한 과정이라는 것을 알게 되었습니다. 각 태그는 데이터의 특징을 설명하고, 라우팅 결정을 위한 힌트를 제공하며, 최종적으로는 데이터의 활용 범위를 제한하는 역할까지 수행합니다. 이러한 이해를 바탕으로 데이터의 출처 추적, 품질 상태 검토, 그리고 최종 목적지 설정까지 고려해야 데이터 품질을 효율적으로 관리할 수 있다는 점을 명확히 했습니다.
