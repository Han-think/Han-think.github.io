DOM 선택과 fetch 흐름, 입력을 먼저 확인하는 습관

DOM 선택과 fetch 흐름, 입력을 먼저 확인하는 습관 학습 정리
2026년 8월 24일 · 5 min

목차#

    1. getElementById
    1. querySelector
    1. JSON

1. getElementById#

왜 이걸 보게 됐나#

DOM 요소 선택에 익숙해지기 위해 getElementById를 배우게 되었습니다. ID 하나로 특정 요소를 정확히 찾아내는 기본기가 필요했기 때문입니다. 이를 통해 querySelector 등 다른 메서드와의 차이점을 명확히 구분할 수 있게 되었습니다.

내가 헷갈린 지점#

ID를 넣어야 하는지, class를 넣어야 하는지, 혹은 name을 넣어야 하는지를 구분하는 것이 가장 어려웠습니다. 특히 getElementById와 querySelector 같은 메서드 이름이 비슷해 혼동되기 쉽고, 잘못된 이름을 머릿속에 그리다가 정정해야 했습니다. 무엇보다도 어떤 데이터를 입력값으로 주어야 하는지 감이 안 서 있어 코드를 작성하기 전에 먼저 확인하는 습관이 필요했습니다.

시도한 코드 / 예시#

// DOM 요소 선택 (ID를 인자로 받음)
const element = document.getElementById("input");

주의: getElementById는 유일한 ID 문자열을 인자로 전달받습니다.

결과와 해석#

getElementById는 HTML 문서에서 id 속성 값이 정확히 일치하는 단 하나의 요소를 선택합니다. 입력값으로 특정 ID를 직접 전달하여 해당 요소에 접근하며, 선택된 요소의 .value나 .textContent 같은 프로퍼티를 통해 데이터를 가져오거나 수정할 수 있습니다. 이 메서드는 ID가 유일해야 하므로, 여러 개의 동일한 ID가 존재하면 첫 번째 요소만 반환되고 오류가 발생할 위험이 있습니다.

정리된 이해#

getElementById는 HTML 문서 내에 존재하는 유일한 ID 값을 가진 요소를 선택하는 메서드입니다. 이 메서드를 사용하면 특정 요소에 접근해 그 속성이나 내용을 쉽게 조작할 수 있습니다. 선택 시 ID 문자열을 정확하게 입력해야만 원하는 요소를 찾을 수 있습니다.

2. querySelector#

왜 이걸 보게 됐나#

DOM 요소 선택 시 getElementById는 특정 ID를 정확히 찾지만, 여러 요소를 선택하거나 복잡한 조건이 필요할 때는 querySelector가 더 유연하고 직관적이기 때문에 배우게 되었습니다. 특히 클래스명이나 태그명, 속성 조합을 기준으로 요소를 찾을 때 getElementsByClassName 같은 결과값 배열 반환 방식보다 querySelector로 단일 요소나 특정 조건에 맞는 첫 번째 요소를 바로 가져올 수 있어 실무에서 자주 활용하게 됩니다.

내가 헷갈린 지점#

querySelector와 querySelectorAll은 모두 CSS 선택자를 사용한다는 점에서 비슷해 보였지만, 반환값의 형태가 다르다는 점이 가장 큰 혼란이었습니다. getElementById나 getElementsByClassName처럼 특정 요소 하나를 바로 반환하는지, 아니면 NodeList 같은 컬렉션을 반환하는지를 미리 파악하지 못하면 코드 실행 시 예상치 못한 오류에 부딪히기 쉽습니다. 결국 ‘무엇을 선택하느냐’보다 ‘몇 개를 선택하느냐’가 메서드의 핵심 차이였습니다.

시도한 코드 / 예시#

// querySelector: 첫 번째 일치하는 요소 반환
const firstElement = document.querySelector('.my-class');
// 결과: <div class="my-class">...</div>

// querySelectorAll: 모든 일치하는 요소를 NodeList로 반환
const allElements = document.querySelectorAll('.my-class');
// 결과: [ <div class="my-class">...</div>, <span class="my-class">...</span> ]

결과와 해석#

querySelector는 CSS 선택자를 이용해 첫 번째 일치하는 요소를 반환하며, querySelectorAll은 모든 일치하는 요소들을 NodeList로 반환한다는 점이 가장 큰 차이점입니다. 실습을 통해 클래스명이나 태그명으로 요소를 정확히 타겟팅할 수 있다는 자신감이 생겼고, 여러 요소를 다룰 때는 반복문과 결합하여 활용하게 되었습니다.

정리된 이해#

querySelector는 CSS 선택자를 사용해 첫 번째 일치하는 요소를, querySelectorAll은 모든 일치하는 요소들을 NodeList로 반환한다는 점이 핵심입니다. 따라서 “하나를 찾을 때”와 “여러 개를 찾을 때” 구분하여 사용하는 것이 가장 중요합니다.

3. JSON#

왜 이걸 보게 됐나#

JSON은 웹 서버와 클라이언트 사이에서 데이터를 주고받을 때 가장 널리 사용되는 표준 형식입니다. fetch API를 통해 서버에서 받아온 원시 데이터는 텍스트 형태이지만, 실제 애플리케이션에서는 객체나 배열로 다뤄야 하므로 JSON 메서드를 사용하여 파싱해야 합니다. 이를 통해 자바스크립트 코드 내에서 데이터를 쉽게 접근하고 manipulate할 수 있게 됩니다.

내가 헷갈린 지점#

처음에는 JSON이 단순히 ‘데이터 포맷’ 정도로만 생각했었다. 하지만 실제로는 서버로부터 받아온 텍스트를 자바스크립트 객체로 변환해주는 필수적인 과정이었음을 깨달았다. 또한 fetch의 결과가 바로 사용 가능한 객체가 아니라 response 객체라는 점과, 이를 json() 메서드로 한 번 더 변환해야 한다는 점이 가장 큰 진입장애였다.

시도한 코드 / 예시#

// JSON 데이터 구조 예시 (노트 내용 기반)
{
  "id": 1,
  "name": "홍길동",
  "age": 25
}

결과와 해석#

JSON은 서버로부터 받아온 텍스트 데이터를 자바스크립트 객체 형태로 변환한 것입니다. response.json() 메서드를 사용하면 비동기적으로 데이터를 파싱하여 사용할 수 있습니다. 이를 통해 배열이나 객체의 메서드인 map, filter 등을 활용해 원하는 정보만 쉽게 추출하고 화면에 출력할 수 있습니다.

정리된 이해#

JSON은 서버로부터 전달된 데이터를 자바스크립트 객체 형태로 변환한 것입니다. 이 형태를 통해 데이터의 구조를 파악하고 필요한 정보를 추출할 수 있습니다. fetch로 받은 원시 응답을 JSON으로 변환하는 것이 데이터 활용의 핵심 단계입니다.

4. filter#

왜 이걸 보게 됐나#

데이터를 걸러내는 실무적 필요성을 느껴 배우기 시작했다. 단순히 전체 데이터를 보여주는 것보다 특정 조건에 맞는 데이터만 추출해야 하는 경우가 많았기 때문이다. filter를 통해 불필요한 데이터를 제거하고 필요한 정보만 효율적으로 처리할 수 있게 되었다.

내가 헷갈린 지점#

filter는 배열 전체를 순회하며 조건을 만족하는 요소들만 걸러내어 새로운 배열을 반환합니다. 저는 처음에는 filter가 첫 번째로 찾은 하나의 요소를 반환하는 것인 줄 알았지만, 실제로는 여러 개를 담은 배열을 만든다는 점이 달랐습니다. 따라서 조건에 맞는 항목이 없을 경우 빈 배열([])이 반환된다는 점을 꼭 기억해야 합니다.

시도한 코드 / 예시#

// notes: filter는 조건을 만족하는 요소만 걸러내어 새로운 배열을 반환합니다.
const numbers = [1, 2, 3, 4, 5];
const filteredNumbers = numbers.filter(num => num > 2);
// 결과: [3, 4, 5]

결과와 해석#

filter는 배열에서 조건에 맞는 요소만 골라내는 메서드입니다. 입력값을 비교 함수로 전달하면, true를 반환하는 요소들로 새로운 배열을 만들어 반환합니다. 이를 통해 불필요한 데이터를 걸러내고 원하는 데이터만 효율적으로 추출할 수 있습니다.

정리된 이해#

filter는 배열에서 조건에 맞는 요소만 걸러내어 새로운 배열을 반환하는 메서드입니다. 사용자가 원하는 특정 데이터가 포함된지를 확인하거나, 불필요한 데이터를 제거할 때 유용하게 활용됩니다. filter의 반환값은 항상 배열이므로, 이후 다른 메서드와 연쇄하여 사용할 수 있습니다.

총평#

오늘 전체에서 배운 것#

DOM 요소 선택 시 ID와 클래스 구분법을 명확히 하고, fetch 실습에서는 요청할 데이터의 형태(ID, index 등)를 먼저 확인하는 습관이 필요합니다.

다음에 조심할 것#

ID와 class를 혼동하지 않도록 getElementById와 querySelector의 용도를 명확히 구분해서 사용한다.

입력값이 ID, index, name 중 어떤 형태인지 먼저 확인한 뒤 해당하는 API를 선택해야 코드가 올바르게 동작한다.

다음 복습 주제#

다음에 복습하거나 더 알아볼 주제#

DOM 선택자는 id와 class의 차이를 명확히 구분하는 연습이 필요합니다. 특히 querySelectorAll은 NodeList를 반환하므로, 실제 DOM 조작을 위해서는 배열 변환(Array.from)이나 forEach 사용이 필수적입니다.

fetch 실습에서는 요청 URL과 파라미터가 어떻게 데이터에 영향을 주는지 시뮬레이션 데이터를 직접 만들어보며 검증하는 연습을 해보면 좋습니다. 특히 응답 코드(status code)별 처리 흐름과 에러 처리의 기본 패턴을 숙지하면 실제 서비스 개발 시 당황하지 않고 대처할 수 있습니다.
