1. 클래스 설계도#

왜 이걸 보게 됐나#

클래스 설계도를 통해 객체 지향 프로그래밍의 기본 개념을 이해하고자 함. 특히, 클래스와 인스턴스 간의 관계, 그리고 독립적인 객체 상태의 유지 방법을 명확히 파악하고자 함.

내가 헷갈린 지점#

클래스를 통해 생성된 인스턴스들이 서로 독립적인 데이터를 가질 수 있다는 점과 member1 is member2가 False로 출력되는 이유를 이해하는 데 어려움을 겪음. 또한, 클래스 정의와 객체 생성 과정의 구분, 속성과 메서드의 역할 특히 @property 데코레이터의 활용에 대한 명확한 이해 부족.

시도한 코드 / 예시#

class TeamMember:
    def __init__(self, name, role):
        self.name = name  # 이름 속성
        self.role = role   # 역할 속성

member1 = TeamMember('Alice', 'Developer')
member2 = TeamMember('Bob', 'Designer')

print(member1.name)  # 출력: Alice
print(member2.name)  # 출력: Bob
print(member1 is member2)  # 출력: False

결과와 해석#

위 코드는 TeamMember 클래스를 정의하고 두 개의 독립적인 인스턴스 member1과 member2를 생성합니다. 각 인스턴스는 독립적인 name과 role 속성을 가지므로, member1과 member2는 서로 다른 객체로 인식되어 member1 is member2는 False를 반환합니다.

정리된 이해#

클래스 설계도는 객체 생성을 위한 템플릿으로, 이를 통해 독립적인 객체 인스턴스를 만들 수 있습니다. 각 인스턴스는 클래스의 속성과 메소드를 가지며 독립적인 상태를 유지합니다. 이로 인해 같은 클래스에서 생성된 인스턴스라도 서로 다른 데이터를 가질 수 있으며, 객체 비교 시 is 연산자는 동일한 메모리 참조를 확인하므로 False를 반환합니다.

2. 인스턴스 생성#

왜 이걸 보게 됐나#

클래스를 통해 독립적인 객체를 생성하는 과정과 그 중요성을 이해하기 위해, 인스턴스 생성의 기본 개념부터 실제 적용 예시까지 학습하고자 함.

내가 헷갈린 지점#

인스턴스 생성 시 각 객체가 독립적인 메모리 공간을 갖는다는 점과 이를 통해 서로 다른 상태를 유지할 수 있다는 개념이 처음에는 혼란스러웠음. 특히, 같은 클래스에서 생성된 객체들이 서로 다른 데이터를 가질 수 있다는 점이 명확하게 이해되지 않았음.

시도한 코드 / 예시#

class Employee:
    def __init__(self, name, salary):
        self.name = name  # 직원 이름 속성
        self.salary = salary  # 급여 속성

# 두 개의 독립적인 인스턴스 생성
emp1 = Employee('Charlie', 50000)
emp2 = Employee('Diana', 60000)

# 인스턴스 속성 출력
print(f'Employee 1 Name: {emp1.name}, Salary: ${emp1.salary}')
print(f'Employee 2 Name: {emp2.name}, Salary: ${emp2.salary}')

결과와 해석#

출력 예시:

Employee 1 Name: Charlie, Salary: $50000
Employee 2 Name: Diana, Salary: $60000

정리된 이해#

인스턴스 생성을 통해 클래스의 설계도를 실제 데이터와 동작을 가진 독립적인 객체로 구현할 수 있음을 이해했습니다. Employee 클래스의 두 인스턴스 emp1과 emp2는 각각 다른 이름과 급여를 가질 수 있으며, 이는 클래스 정의 내에서 초기화 메서드(__init__)를 통해 달성됩니다.

3. 독립적 객체#

왜 이걸 보게 됐나#

독립적 객체의 개념을 이해하는 데 어려움을 겪으면서 클래스와 인스턴스 간의 관계와 메모리 할당에 대한 명확한 이해가 필요했습니다. 특히, 동일한 클래스에서 생성된 객체들이 서로 독립적인 상태를 유지할 수 있다는 점이 혼란스러웠습니다.

내가 헷갈린 지점#

가장 혼란스러웠던 부분은 member1과 member2가 같은 TeamMember 클래스를 사용해 생성되었음에도 불구하고 서로 독립적인 객체라는 사실을 받아들이는 것이었습니다. member1 is member2가 False로 출력되는 이유를 명확히 이해하지 못했습니다. 또한, 클래스 정의와 실제 객체 생성 사이의 연결고리가 명확하지 않았습니다.

시도한 코드 / 예시#

class TeamMember:
    def __init__(self, name, role):
        self.name = name
        self.role = role

member1 = TeamMember('Alice', 'Developer')
member2 = TeamMember('Bob', 'Designer')

print(member1.name)  # 출력: Alice
print(member2.name)  # 출력: Bob
print(member1 is member2)  # 출력: False

결과와 해석#

위 코드는 TeamMember 클래스를 정의하고 member1과 member2 두 개의 독립적인 인스턴스를 생성합니다. 각 객체는 독립적인 name과 role 속성을 가지며, member1 is member2는 False를 반환하여 두 객체가 서로 다른 독립적인 인스턴스임을 확인할 수 있습니다.

정리된 이해#

독립적 객체의 핵심은 클래스가 설계도 역할을 하며, 인스턴스는 그 설계도를 바탕으로 독립적으로 생성된 개별 객체라는 점입니다. member1과 member2는 같은 클래스를 사용하더라도 각각 고유한 상태를 유지하며, 메모리 상에서 별개로 존재하기 때문에 동일한 객체로 인식되지 않습니다.

4. 속성 접근 제어#

왜 이걸 보게 됐나#

속성 접근 제어는 객체 지향 프로그래밍에서 데이터 보호와 유연한 접근 방식을 제공하여 클래스의 내부 상태를 안전하게 관리하고 사용자 인터페이스를 개선하는 데 중요합니다. 이를 통해 속성 값을 직접 변경하는 대신 메서드를 통해 제어할 수 있어, 데이터 유효성 검사나 복잡한 로직을 적용할 수 있습니다.

내가 헷갈린 지점#

초보자들은 @property 데코레이터가 어떻게 동작하는지와 일반 메서드와의 차이점을 이해하는 데 어려움을 겪을 수 있습니다. 특히, 속성 접근이 단순히 getter와 setter 메서드를 통해 어떻게 더 직관적이고 안전하게 이루어지는지 명확히 파악하는 것이 중요합니다.

시도한 코드 / 예시#

class BankAccount:
    def __init__(self, owner, balance=0):
        self._owner = owner  # 보호된 속성
        self._balance = balance  # 보호된 속성

    @property
    def owner(self) -> str:
        """은행 계좌 소유자 정보를 읽어옵니다."""
        return self._owner

    @owner.setter
    def owner(self, new_owner: str):
        """소유자 정보를 업데이트합니다. 추가적인 검증 로직을 포함할 수 있습니다."""
        if isinstance(new_owner, str) and new_owner.strip():
            self._owner = new_owner
        else:
            raise ValueError('소유자 이름은 유효한 문자열이어야 합니다.')

    @property
    def balance(self) -> float:
        """은행 계좌 잔액을 읽어옵니다."""
        return self._balance

    def deposit(self, amount: float):
        """잔액에 입금합니다."""
        if amount > 0:
            self._balance += amount
        else:
            raise ValueError('입금 금액은 양수여야 합니다.')

    def withdraw(self, amount: float):
        """잔액에서 출금합니다."""
        if 0 < amount <= self._balance:
            self._balance -= amount
        else:
            raise ValueError('출금 금액은 유효해야 합니다.')

# 예시 사용
account = BankAccount('Alice', 1000)
print(account.owner)  # 출력: Alice
account.owner = 'Bob'  # 소유자 변경
print(account.owner)  # 출력: Bob
print(account.balance)  # 출력: 1000
account.deposit(500)
print(account.balance)  # 출력: 1500
account.withdraw(200)
print(account.balance)  # 출력: 1300

결과와 해석#

위 코드는 BankAccount 클래스를 통해 속성 접근 제어의 활용 방법을 보여줍니다. _owner와 _balance는 직접 접근이 제한된 보호된 속성으로, @property 데코레이터를 사용해 owner와 balance 속성에 대한 안전하고 제어된 접근을 제공합니다. owner 속성의 경우, 값 설정 시 유효성 검사를 포함하여 소유자 이름이 유효한 문자열인지 확인합니다. deposit과 withdraw 메서드는 잔액 조작 시 유효성 검사를 수행하여 안전한 트랜잭션을 보장합니다.

정리된 이해#

속성 접근 제어는 클래스 내부 데이터를 보호하고, 사용자 인터페이스를 개선하며, 데이터 유효성 검사를 용이하게 합니다. @property 데코레이터를 사용하면 속성에 대한 접근을 유연하게 제어할 수 있으며, 이는 코드의 가독성과 안정성을 향상시킵니다.

총평#

오늘 전체에서 배운 것#

클래스는 객체 생성을 위한 설계도이며, 인스턴스는 독립적인 데이터를 가진 개별 객체임을 이해했습니다. 속성 접근 제어와 pass 구문 사용에 대한 개념도 명확히 파악했습니다.

다음에 조심할 것#

클래스와 인스턴스의 독립성 이해가 아직 완벽하지 않아, 실제 코딩 시 혼동이 발생할 수 있으니 주의가 필요합니다. 특히, is 연산자로 객체의 동일성을 확인할 때 독립적인 객체임을 명심해야 합니다.
