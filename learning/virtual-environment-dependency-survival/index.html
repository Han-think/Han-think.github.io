1. 가상환경#

왜 이걸 보게 됐나#

여러 프로젝트를 진행하면서 패키지 버전 충돌 문제 때문에 코드가 실행되지 않거나 예상치 못한 오류가 발생하는 경험을 했습니다. 이 문제를 해결하기 위해 가상환경이라는 개념을 배우게 되었고, 이제는 독립적인 환경을 구축하여 안전하게 개발할 수 있게 되었습니다. 이를 통해 개발 과정에서 더 많은 자유와 안정감을 얻을 수 있을 것이라고 생각합니다.

내가 헷갈린 지점#

처음에는 가상환경이 왜 필요한지, 그리고 어떻게 작동하는지 감이 잘 안 잡혔다. 뭔가 복잡하고 어렵게 느껴졌고, 단순히 패키지를 설치하는 것과 뭐가 다른지 이해하는 데 시간이 걸렸다. 특히 여러 프로젝트를 관리할 때 이 가상환경을 어떻게 활용해야 하는지 막막했다.

시도한 코드 / 예시#

# 가상환경 생성
python3 -m venv my_project_env

# 가상환경 활성화
source my_project_env/bin/activate

# 패키지 설치
pip install pandas==1.5.3  # 필요한 버전 설치

# 환경 스냅샷 저장 (필요한 패키지 목록 기록)
pip freeze > requirements.txt

# 환경 비활성화
deactivate

# 가상환경 삭제 (실험 실패 시)
rm -rf my_project_env

결과와 해석#

python3 -m venv my_project_env 명령어를 통해 프로젝트별로 독립된 가상환경을 만들 수 있었고, source my_project_env/bin/activate를 실행하여 해당 환경에 진입했습니다. pip install pandas==1.5.3으로 특정 버전의 패키지를 설치하면서, 버전 충돌 걱정 없이 프로젝트에 필요한 환경을 구성할 수 있다는 점을 체감했습니다.

정리된 이해#

가상환경은 각 프로젝트마다 독립적인 Python 환경을 만들어 서로 다른 버전의 패키지를 필요로 하는 상황에서 충돌을 일으키지 않도록 해주는 공간입니다. 덕분에 새로운 패키지를 설치하거나 버전을 변경할 때 불안감 없이 안전하게 실험을 진행할 수 있고, 실패하더라도 다른 환경에 영향을 주지 않도록 격리할 수 있습니다.

2. 의존성 관리#

왜 이걸 보게 됐나#

여러 프로젝트를 진행하다가 각 프로젝트마다 필요한 패키지 버전이 달라서 전역 환경에 설치하면 충돌이 일어나는 상황을 겪으면서, 더 이상 환경 관리에 쩔쩔매지 않기 위해 의존성 관리가 필요하다는 것을 알게 되었어. 특히 프로젝트가 커지고 협업이 필요할수록 어떤 패키지가 어떤 버전에 필요하다는 것을 명확하게 관리하는 것이 중요하게 느껴졌어. 결국 나만의 깔끔한 개발 환경을 구축하기 위해 이 개념을 배우게 되었어.

내가 헷갈린 지점#

처음에는 의존성이 ‘패키지 버전’에만 영향을 받는다고 생각했어요. 그래서 프로젝트마다 필요한 패키지를 전역 환경에 설치하면 되겠다, 라고 쉽게 생각했지만, 버전 충돌 문제가 발생하는 이유를 제대로 이해하지 못했습니다. 프로젝트 간의 독립적인 환경이 왜 필요한지, 그리고 그 중요성이 무엇인지 헷갈렸습니다.

시도한 코드 / 예시#

# 환경 스냅샷 저장 (필요한 패키지 목록 기록)
pip freeze > requirements.txt

결과와 해석#

pip freeze > requirements.txt 명령어를 통해 현재 가상환경에 설치된 모든 패키지와 버전을 텍스트 파일로 저장했는데, 나중에 다른 환경에서도 동일한 프로젝트를 돌릴 때 이 파일을 활용해 필요한 패키지를 쉽게 설치할 수 있다는 점이 인상 깊었다. 즉, 프로젝트의 의존성을 명시적으로 기록하고 공유하여 재현 가능성을 높일 수 있다는 의미였다. 이 파일을 활용하면 다른 개발자들이 프로젝트를 쉽게 설정하고 실행할 수 있어 협업에 큰 도움이 될 것 같다.

정리된 이해#

의존성 관리는 여러 프로젝트가 서로 다른 패키지 버전을 필요로 할 때, 각 프로젝트를 위한 독립적인 환경을 만들어 버전 충돌을 피하는 것을 의미합니다. 이를 통해 안전하게 실험하고, 문제가 발생해도 다른 프로젝트에 영향을 주지 않도록 격리할 수 있습니다. 결국, 프로젝트별로 필요한 패키지 버전을 자유롭게 관리하며 개발하는 핵심적인 방법입니다.

3. venv#

왜 이걸 보게 됐나#

여러 프로젝트를 진행하면서 패키지 버전에 따른 충돌이 발생하는 문제를 해결하기 위해, 그리고 안전하게 실험적인 코드를 작성하고 싶어서 가상환경을 배우게 됐어. 특히 venv는 파이썬 자체에 포함되어 있어서 별도의 설치 없이 바로 사용할 수 있다는 점이 매력적이었어. 이제는 프로젝트마다 독립된 환경을 만들고 관리할 수 있게 됐지.

내가 헷갈린 지점#

처음에는 venv가 Python 자체에 포함된 별도의 프로그램이라고 생각했어요. 가상환경을 만들고 관리하기 위한 완전히 새로운 명령어나 도구가 필요할 줄 알았죠. 사실 Python 실행 파일과 함께 제공되는 모듈이라는 점이 신기했습니다.

시도한 코드 / 예시#

# 가상환경 생성
python3 -m venv my_project_env

결과와 해석#

venv는 파이썬 내장 모듈이라 별도 설치 없이 python3 -m venv my_project_env 명령으로 간단하게 가상환경을 만들 수 있어서 매우 유용했어요. 가상환경을 만들고 활성화하면, 마치 새로운 파이썬 환경이 생긴 것처럼 느껴지면서 프로젝트별로 필요한 패키지를 독립적으로 설치하고 관리할 수 있게 되었죠. 덕분에 전역 환경을 오염시키지 않고 다양한 실험을 자유롭게 진행할 수 있게 되었습니다.

정리된 이해#

venv는 Python에서 프로젝트별로 격리된 가상 환경을 만들 수 있게 해주는 도구인데, 덕분에 다양한 프로젝트를 진행할 때 패키지 버전 충돌 걱정 없이 안전하게 실험할 수 있어 정말 유용해. 각 프로젝트에 필요한 특정 버전의 패키지를 독립적으로 설치하고 관리할 수 있게 해준다고 이해하고 있어.

4. requirements.txt#

왜 이걸 보게 됐나#

프로젝트를 진행하다 보면 어떤 패키지가 정확히 어떤 버전을 사용해야 하는지, 그리고 다른 프로젝트에서는 어떤 버전을 써야 하는지 헷갈릴 때가 많았어. 그래서 나중에 다른 개발자와 협업하거나, 프로젝트를 다시 실행할 때마다 환경을 똑같이 구성하기 위해 필요한 패키지 목록을 기록하는 requirements.txt 파일을 배우게 됐어. 이렇게 하면 환경을 재현하는 과정이 훨씬 쉬워질 것 같아.

내가 헷갈린 지점#

처음에는 requirements.txt 파일이 단순히 설치된 패키지 목록을 보여주는 파일인 줄 알았는데, 실제로는 프로젝트를 다른 환경에서 재현할 때 필요한 패키지 버전 정보를 담고 있는 중요한 파일이라는 점을 몰랐다. 이 파일을 통해 프로젝트 실행에 필요한 정확한 패키지 버전을 고정시켜, 개발 환경과 운영 환경 간의 불일치 문제를 해결할 수 있다는 것을 뒤늦게 알게 되었다. 단순히 기록하는 파일이 아니라, 프로젝트의 재현성을 보장하는 핵심적인 역할을 한다는 것을 깨달았다.

시도한 코드 / 예시#

# requirements.txt 예시
# 프로젝트 A의 패키지 목록
pandas==1.5.3
numpy==1.24.0
requests==2.28.1

# 프로젝트 B의 패키지 목록
pandas==2.2.0
scikit-learn==1.2.0
matplotlib==3.7.0

결과와 해석#

requirements.txt 파일은 현재 가상환경에 설치된 패키지 이름과 버전을 텍스트 형식으로 저장하는 파일이야. pip freeze > requirements.txt 명령어로 쉽게 만들 수 있고, 다른 사람이 동일한 환경을 구축할 때 매우 유용해. 마치 레시피처럼, 필요한 재료(패키지) 목록을 알려주는 역할을 한다고 보면 이해하기 쉬울 것 같아.

정리된 이해#

requirements.txt 파일은 현재 가상환경에 설치된 패키지들의 이름과 버전을 기록하는 목록 파일이라고 이해했습니다. 이 파일을 통해 다른 환경에서도 동일한 패키지 버전을 쉽게 설치하여 환경을 재현할 수 있고, 프로젝트의 의존성을 명확하게 관리할 수 있습니다.

총평#

오늘 전체에서 배운 것#

이제 프로젝트별로 독립적인 환경을 만들어 패키지 버전을 관리할 수 있다는 것을 알게 되었다. venv를 사용해 가상환경을 만들고 requirements.txt 파일로 필요한 패키지 목록을 저장하여 환경을 쉽게 재현할 수 있게 되었다.

다음에 조심할 것#

requirements.txt 파일은 프로젝트 복제를 할 때 꼭 생성하고, 다른 환경에서 복원할 때 제대로 작동하는지 확인해야겠다. conda와 venv 중에 어떤 도구를 사용할지 프로젝트 성격에 따라 신중하게 결정하고, 가상환경 활성화 여부를 항상 체크해야 환경 충돌을 막을 수 있겠다.

다음 복습 주제#

conda를 활용한 가상환경 생성 및 관리에 대해 좀 더 자세히 알아봐야겠다. pip freeze 외에 requirements.txt를 좀 더 효과적으로 활용할 수 있는 방법도 찾아보고, 프로젝트 규모가 커질 때 유용하게 사용할 수 있는 의존성 관리 도구들을 탐색해봐야겠다.
