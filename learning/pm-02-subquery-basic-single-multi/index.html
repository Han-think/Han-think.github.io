1. 서브쿼리 작성 방식#

왜 이걸 보게 됐나#

평소 문제 해결을 단계별로 생각하는 내 사고방식과 SQL 서브쿼리 작성 방식이 충돌해서 어려움을 겪었거든. 특히 앨범 ID를 먼저 찾는 게 자연스러웠는데, SQL에서는 결과값을 기준으로 메인쿼리를 먼저 작성해야 해서 계속 헷갈렸어. 그래서 서브쿼리의 역할 분담을 명확히 이해하고, 메인쿼리와 서브쿼리를 역순으로 생각하는 방식을 익히게 됐어.

내가 헷갈린 지점#

평소 문제 해결 방식이 알던 단서부터 시작해서 점진적으로 답을 찾아가는 흐름인데, 서브쿼리는 그 반대로 최종 결과부터 생각하고 메인쿼리를 먼저 작성해야 해서 처음에는 역순으로 생각해야 한다는 점이 헷갈렸어요. 특히 앨범 이름을 기준으로 AlbumId를 찾는 문제가 직관적이지 않아서 SQL 작성 방식이 어색하게 느껴졌습니다. 이러한 사고방식의 차이 때문에 서브쿼리 작성에 어려움을 겪었습니다.

시도한 코드 / 예시#

SELECT Name
FROM tracks
WHERE AlbumId IN (SELECT AlbumId FROM albums WHERE GenreId = (SELECT GenreId FROM genres WHERE Name = 'Rock'));

결과와 해석#

SELECT Name FROM tracks WHERE AlbumId IN (SELECT AlbumId FROM albums WHERE Genre = 'Rock'); 이 코드는 ‘Rock’ 장르 앨범의 AlbumId를 먼저 찾고, 그 AlbumId에 해당하는 트랙의 이름을 메인 쿼리에서 가져옵니다. 서브쿼리를 먼저 작성하여 앨범 ID를 구하는 과정이, 문제 해결의 역순으로 사고해야 한다는 서브쿼리 작성 방식을 이해하는데 도움이 되었습니다.

정리된 이해#

서브쿼리는 메인쿼리가 필요한 기준값을 미리 계산해서 제공하는 보조 쿼리 역할을 하며, 문제를 해결할 때 최종 출력부터 생각하고 메인 쿼리를 먼저 작성하는 역순 사고방식이 필요합니다. 즉, 메인쿼리가 결과 데이터의 틀을 만들고, 서브쿼리는 그 틀에 들어갈 기준값을 제공하는 방식으로 이해해야 합니다.

2. 메인쿼리와 서브쿼리 역할#

왜 이걸 보게 됐나#

평소 문제 해결 방식을 SQL 쿼리 작성에 적용하려니, 결과가 나오지 않거나 예상치 못한 결과가 나왔어요. 특히 서브쿼리를 사용할 때, 어떤 값을 기준으로 쿼리를 작성해야 하는지 혼란스러웠고, 메인 쿼리와 서브쿼리 역할 분담을 제대로 이해하지 못하면 원하는 결과를 얻을 수 없다는 것을 깨달았습니다.

내가 헷갈린 지점#

평소 문제 해결 방식이 자연스럽게 ‘알고 있는 단서부터 찾는다’는 흐름이었는데, 서브쿼리는 이와 반대로 최종 출력부터 생각하고 메인쿼리를 먼저 작성해야 해서 처음에는 역순으로 생각해야 한다는 점이 헷갈렸습니다. 결국 메인쿼리와 서브쿼리의 역할을 명확히 분담하는 것이 중요하고, 서브쿼리는 메인쿼리가 필요로 하는 값을 미리 계산해서 제공하는 역할을 한다는 점을 깨달았습니다.

시도한 코드 / 예시#

SELECT
  t.Name
FROM
  tracks AS t
WHERE
  t.AlbumId IN (
    SELECT
      AlbumId
    FROM
      albums
    WHERE
      GenreId = (
        SELECT
          GenreId
        FROM
          genres
        WHERE
          Name = 'Rock'
      )
  );

결과와 해석#

먼저 메인 쿼리에서 tracks 테이블의 Name을 선택하고, AlbumId를 기준으로 서브쿼리를 작성하여 albums 테이블에서 장르가 “Rock"인 앨범의 AlbumId를 찾았습니다. 이 AlbumId를 메인 쿼리의 WHERE 절에 넣어, 해당 앨범에 속한 트랙 이름만 출력했습니다. 서브쿼리는 메인 쿼리가 필터링을 위해 필요한 특정 앨범 ID를 제공하는 역할을 했습니다.

정리된 이해#

서브쿼리의 핵심은 메인 쿼리가 최종 결과를 보여주는 틀을 만들고, 서브쿼리는 그 틀에 필요한 특정 기준값이나 조건을 제공하는 역할을 한다는 점입니다. 즉, 문제 해결 과정을 역으로 생각하며, 최종적으로 원하는 결과부터 시작하여 필요한 정보를 서브쿼리를 통해 구해야 합니다.

3. 기준값 제공#

왜 이걸 보게 됐나#

평소 문제 해결 과정에서 자연스럽게 생각하는 흐름과 SQL 쿼리 작성 방식이 달라서 어려움을 겪었고, 특히 기준값을 먼저 찾는 과정에서 혼란스러웠습니다. 서브쿼리를 통해 필요한 정보를 미리 계산해서 메인 쿼리에 활용함으로써 쿼리의 복잡성을 줄이고 효율적인 데이터 조회가 가능하다는 점을 깨달았습니다. 이 개념은 결국 데이터베이스에서 정보 검색의 효율성을 높이는 중요한 기술입니다.

내가 헷갈린 지점#

처음에는 서브쿼리를 이용해서 기준값을 찾는 과정이, 마치 문제의 답을 역으로 추적하는 것처럼 느껴져서 막막했습니다. 내가 생각하는 ‘알고 있는 정보’를 먼저 활용해야 한다고 생각했는데, SQL에서는 필요한 값을 얻기 위해 서브쿼리를 먼저 돌려야 한다는 점이 어색했습니다. 기준값이라는 게 무엇인지 정확히 이해하지 못하고, 단순히 ‘값을 찾아달라’는 명령으로 받아들였던 것 같습니다.

시도한 코드 / 예시#

SELECT Name
FROM tracks
WHERE AlbumId IN (SELECT AlbumId FROM albums WHERE GenreId = (SELECT GenreId FROM genres WHERE Name = 'Rock'));

결과와 해석#

albums 테이블에서 장르가 “Rock"인 앨범의 AlbumId를 서브쿼리로 먼저 가져온 후, tracks 테이블에서 해당 AlbumId를 가진 트랙들의 Name을 메인쿼리에서 가져왔습니다. 서브쿼리는 필요한 기준값을 미리 계산하여 메인쿼리에 제공함으로써, 전체 앨범 목록을 뒤져야 하는 비효율을 막아줍니다. 이처럼 메인쿼리와 서브쿼리가 역할을 분담하여 효율적인 쿼리 작성이 가능합니다.

정리된 이해#

서브쿼리는 메인 쿼리에서 필요한 특정 값을 미리 계산해주는 보조 쿼리 역할을 수행하며, 최종 결과를 담을 틀을 만드는 메인 쿼리와 정보를 제공하는 서브쿼리의 역할 분담을 이해하는 것이 중요합니다. 즉, 메인 쿼리의 WHERE 조건에 필요한 기준값을 서브쿼리를 통해 찾아 제공함으로써, 원하는 결과를 효율적으로 얻을 수 있습니다.

4. 정보 계산#

왜 이걸 보게 됐나#

서브쿼리를 배우면서 데이터 분석의 복잡한 문제를 단계적으로 해결하는 방식을 익혀야 한다는 것을 깨달았습니다. 단순히 데이터 조회뿐만 아니라, 여러 테이블과 조건들을 활용하여 원하는 정보를 효율적으로 추출하는 능력이 중요하기 때문입니다. 특히 서브쿼리는 복잡한 조건에서 필요한 기준값을 미리 계산하고 활용하도록 도와주어, SQL 쿼리의 효율성과 가독성을 높이는 데 필수적인 개념입니다.

내가 헷갈린 지점#

처음에는 트랙 이름을 먼저 찾고 앨범 ID를 조회하는 방식이 당연하다고 생각했는데, 실제 SQL 작성 시에는 앨범을 먼저 찾고 트랙을 찾는 방식으로 역으로 진행해야 한다는 점이 헷갈렸어요. 또, 서브쿼리가 단순히 기준값을 찾는 역할 이상으로 전체적인 쿼리 구조에 영향을 주는구나, 라는 인식이 부족했어요. 서브쿼리가 전체 쿼리를 짤 때 어떤 기준으로 위치해야 하는지 명확히 이해하지 못해서 어려움을 겪었습니다.

시도한 코드 / 예시#

SELECT
  Name
FROM tracks
WHERE
  AlbumId IN (
    SELECT AlbumId
    FROM albums
    WHERE GenreId IN (
      SELECT GenreId
      FROM genres
      WHERE Name = 'Rock'
    )
  );

결과와 해석#

먼저 albums 테이블에서 장르가 “Rock"인 앨범의 AlbumId를 서브쿼리로 찾아야 했습니다. 그 결과값을 메인쿼리의 WHERE절에서 AlbumId와 비교하여 해당하는 트랙 이름을 출력하는 방식으로 문제를 해결했습니다. 이를 통해 서브쿼리가 메인쿼리의 조건을 만족하는 기준값을 제공하는 역할을 한다는 것을 다시 한번 확인했습니다.

정리된 이해#

서브쿼리는 메인쿼리가 필요한 정보를 미리 계산해서 제공하는 보조 쿼리 역할을 수행하며, 메인쿼리는 최종 결과를 보여줄 틀을 만드는 역할을 합니다. 따라서 문제 해결 시 최종 결과를 먼저 생각하고, 필요한 기준값을 서브쿼리를 통해 찾아서 메인쿼리의 조건에 적용하는 방식으로 접근해야 합니다.

총평#

오늘 전체에서 배운 것#

서브쿼리를 작성할 때는 최종 출력부터 생각하고 메인 쿼리를 먼저 작성해야 한다는 점을 깨달았습니다. 서브쿼리는 메인 쿼리가 필요로 하는 기준값을 제공하는 보조적인 역할을 한다는 것을 명확히 이해하게 되었습니다.

다음에 조심할 것#

평소 사고방식과 SQL 작성 방식의 차이를 항상 염두에 둬야겠어. 서브쿼리를 사용할 때는 항상 최종 출력부터 생각하고 메인쿼리를 구성하는 연습을 꾸준히 해야겠다.

다음 복습 주제#

서브쿼리가 여러 줄로 겹쳐질 때, 각 서브쿼리 간의 의존성을 파악하고 논리적인 오류가 없는지 검토하는 연습이 필요해 보인다. 특히 복잡한 조건이 여러 단계에 걸쳐 적용될 때, 전체적인 흐름을 한눈에 파악하는 능력을 키워야겠다.
