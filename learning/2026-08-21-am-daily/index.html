1. DOM 입력값 파이프라인: 입력 → 처리 → 출력#

무엇을 배웠나#

DOM 입출력 문제를 해결하는 핵심은 ‘입력 → 처리 → 출력’이라는 3단계 파이프라인 구조를 머릿속에 그리는 것이었다. 특히 input.value가 문자열임을 인지하고 Number()나 parseInt()로 타입 변환을 반드시 수행해야 연산 오류를 막을 수 있다는 점을 명확히 했다. 이제 코드를 작성할 때 입력 요소 찾기, 이벤트 연결, 값 변환, 결과 출력의 순서를 체크리스트처럼 점검하며 접근할 수 있게 되었다.

헷갈렸던 점#

DOM 입력값을 다룰 때 가장 큰 혼란은 input.value가 문자열로 반환된다는 점을 간과하고 연산에 바로 사용해 NaN이 발생했던 점입니다. 또한, 문제 설명이 길어질 경우 HTML의 어떤 부분이 입력 요소이고 어떤 부분이 출력 요소인지 식별하는 데 어려움을 겪었습니다. 이러한 흐름을 ‘입력 → 처리 → 출력’이라는 3단계 파이프라인으로 정리하여 각 단계가 어떻게 연결되는지 명확히 이해하려 노력했습니다.

정리된 이해#

DOM 입력/출력 문제는 ‘입력 → 처리 → 출력’이라는 3단계 파이프라인으로 접근하면 해결된다. 먼저 document.getElementById로 요소를 찾은 뒤, .value를 읽을 때는 반드시 Number() 등으로 타입을 변환해야 연산 오류를 막을 수 있다. 마지막으로 계산된 결과를 textContent나 innerHTML을 통해 화면에 출력하면 된다.

// 1. 입력: ID가 "radiusInput"인 요소의 value를 읽음
const inputElement = document.getElementById("radiusInput");
let radiusStr = inputElement.value;

// 2. 처리: 문자열을 숫자로 변환 후 계산
let radius = Number(radiusStr);
let area = Math.PI * radius * radius;

// 3. 출력: ID가 "result"인 요소에 텍스트를 씀
document.getElementById("result").textContent = area.toFixed(2) + "cm²";

2. DOM 스타일·클래스·속성 구분하기#

무엇을 배웠나#

DOM 조작은 크게 스타일, 클래스, 속성 세 가지로 구분할 수 있다. 시각적 변화는 style, UI 상태 전환은 classList, 버튼 비활성화 등 고유한 속성은 property를 사용하면 된다. 무엇보다 무엇을 제어하는지 명확히 구분하는 것이 핵심이다.

헷갈렸던 점#

DOM 조작에서 style, classList, property가 같은 맥락처럼 보여 혼란스러웠습니다. 특히 시각적 변화와 상태 제어가 섞여 있어 어떤 메서드를 써야 할지 순간적으로 판단하기 어려웠습니다. 반복되는 실습을 통해 ‘무엇을 제어하는가’에 따라 구분하는 기준이 필요하다는 점을 깨닫게 되었습니다.

정리된 이해#

DOM 조작은 목적에 따라 style, classList, property를 구분하여 사용해야 한다. 시각적인 변화는 style, UI 상태 전환이나 디자인 변경은 classList, 버튼 활성화나 입력 타입 같은 고유 속성은 property를 활용하면 된다.

// 스타일 직접 변경 (색상, 정렬, 테두리)
paragraph.style.textAlign = "center";
box.style.border = "2px dashed red";

// 클래스 상태 전환 (테마 전환 등)
body.classList.add("dark-mode");
body.classList.remove("dark-mode");
body.classList.toggle("dark-mode");

// 속성 변경 (버튼 비활성화, 입력 타입 변경)
button.disabled = true;
input.type = "text";

3. 데이터 구조와 입력 값의 의미 구분하기#

무엇을 배웠나#

fetch는 단순히 데이터를 불러오는 문법을 외우는 문제가 아니라, 데이터가 들어왔을 때 어떤 연산을 수행할지 결정하는 과정입니다. 핵심은 먼저 데이터 구조를 확인하고, 입력값이 ID인지 인덱스인지 명확히 구분하는 것입니다. 이를 통해 id 값이나 index 번호를 정확히 찾을 수 있습니다.

헷갈렸던 점#

처음에는 화면에 보이는 ‘이름’이나 ‘책’ 같은 문자를 찾으려 했으나, 문제는 실제로는 id 값이나 배열 index 번호를 요구한다는 점을 구분하지 못해 막막했습니다. 특히 9-1과 9-2처럼 숫자 ID와 배열 위치의 차이를 혼동하며, 입력이 무엇을 의미하는지 파악하는 데 어려움을 느꼈습니다. fetch는 단순히 데이터를 가져오는 과정이 아니라, 서버에서 받은 데이터 구조를 정확히 파악해 id나 index 같은 특정 값을 어떻게 추출하고 활용할지가 핵심임을 깨달았습니다.

정리된 이해#

fetch는 단순히 서버와 통신하는 문법이 아니라, 데이터가 도착한 후 어떤 연산을 수행할지가 핵심입니다. 중요한 것은 데이터를 받기 전 구조를 확인하고, 입력값이 ID인지 인덱스인지 정확히 구분하는 것입니다. 전체적인 흐름은 fetch → JSON 변환 → 처리 → DOM 출력으로 일정하며, 실제 데이터 형태만 다를 뿐 과정은 동일합니다.

// 데이터 구조 확인하기
const users = [
  { id: 1, name: "김철수" },
  { id: 2, name: "이영희" },
  { id: 3, name: "박민준" }
];

// ID로 찾기 (문제에서 id를 요구하는 경우)
function findById(users, targetId) {
  return users.find(user => user.id === targetId);
}

// 배열 index로 찾기 (문제에서 위치(index)를 요구하는 경우)
function findByIndex(users, targetIndex) {
  return users[targetIndex];
}

4. 배열 순회와 정렬의 개념 구분하기#

무엇을 배웠나#

순회는 배열을 인덱스 순서대로 읽는 행위이며, 정렬은 값의 크기에 따라 위치를 재배치하는 과정입니다. “순서대로"라는 표현이 자동으로 정렬로 연결되는 습관을 경계해야 합니다. 두 개념을 명확히 구분하면 문제 의도를 정확하게 파악할 수 있습니다.

헷갈렸던 점#

문제의 의도가 ‘배열의 인덱스 순서’를 따른다는 점을 간과하고, 무의식적으로 값의 크기 순서를 떠올려 답이 틀렸습니다.

순회는 배열을 읽어내는 행위이고 정렬은 값의 위치를 재배치하는 행위라는 사실을 구분하지 못해 개념이 혼동되었습니다.

정리된 이해#

순회는 배열을 인덱스 순서대로 읽는 행위이며, 정렬은 값의 크기에 따라 요소 위치를 재배치하는 과정입니다. 두 개념은 목적이 다르고 결과도 달라지므로 혼동해서는 안 됩니다. 따라서 “순서대로 출력"이라는 문제 의도는 배열에 저장된 인덱스 순서를 따른다는 점을 명확히 이해해야 합니다.

// 순회: 현재 배열을 어떤 방향으로 읽는가 (인덱스 유지)
const scores = [50, 100, 30];
for (let i = 0; i < scores.length; i++) {
  console.log(scores[i]); // 출력: 50, 100, 30
}

// 정렬: 값의 크기에 따라 위치를 재배치 (값 순서 변경)
scores.sort((a, b) => a - b); // 오름차순: [30, 50, 100]

총평#

오늘 오전 전체에서 배운 것#

오늘은 DOM 입출력 파이프라인 ‘입력 → 처리 → 출력’ 구조를 명확히 이해하고, input.value 문자열 변환과 타입 처리의 중요성을 학습했습니다. 또한 스타일, 클래스, 속성의 용도별 구분 방법을 통해 DOM 조작의 범위를 정확히 설정하는 법을 익혔습니다. 마지막으로 데이터 구조와 입력 값(ID·인덱스)의 의미를 명확히 구분하여 fetch 연산 로직을 설계하는 안목을 기를 수 있었습니다.

다음에 조심할 것#

입력값 변환 과정을 항상 체크리스트처럼 점검하는 습관을 들이지 않으면, 문자열과 숫자의 타입 불일치로 인한 예상치 못한 연산 오류에 빠지기 쉽습니다.

스타일, 클래스, 속성의 용도를 혼동하여 DOM을 조작하면, 시각적 변화는 커녕 UI 상태가 꼬이거나 버튼이 정상적으로 작동하지 않는 등 의도치 않은 부작용이 발생합니다.

데이터 구조를 파악하기 전에 입력값이 ID인지 인덱스인지 구분하지 못하면, 잘못된 요소를 선택하거나 연산을 수행하여 데이터를 엉뚱한 곳으로 가져오게 되는 치명적인 실수를 범할 수 있습니다.

다음 복습 주제#

다음에 복습할 주제#

DOM 파이프라인에서 가장 중요한 것은 입력값의 유효성 검사다. input.value가 문자열이라는 점을 간과하고 바로 연산을 진행하면 타입 오류가 발생하기 쉽기 때문이다. 따라서 항상 Number()나 parseInt()를 통해 숫자형으로 변환한 뒤 연산을 수행하는 습관을 들여야 한다.

또한 스타일, 클래스, 속성의 용도를 명확히 구분하는 것이 DOM 조작의 핵심이다. 시각적인 디자인 변화는 style, UI 상태 전환은 classList, 고유한 속성 제어는 property를 사용하는 식으로 목적에 맞는 메서드를 선택해야 혼란을 줄일 수 있다.

마지막으로 데이터 구조와 입력값의 의미를 정확히 구분하는 연습이 필요하다. fetch로 데이터를 받았을 때, 그것이 ID 값인지 배열 인덱스인지를 먼저 확인한 뒤 해당 요소를 찾는 과정이 필수적이다. 이를 통해 의도치 않은 데이터 접근 오류를 방지하고 정확한 연산을 수행할 수 있다.
