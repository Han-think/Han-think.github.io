1. 내장 객체 활용: 숫자, 날짜, JSON 완벽 가이드#

무엇을 배웠나#

JavaScript 내장 객체 사용 시 toFixed()가 문자열을 반환한다는 점과 객체와 JSON 문자열의 차이를 명확히 이해하게 되었어. 숫자, 날짜, JSON 객체 활용 방법을 익히면서 각 객체의 역할과 주의해야 할 점을 확인했고, 실습 예제를 통해 좀 더 구체적인 사용법을 파악할 수 있었어. 앞으로는 내장 객체를 사용할 때 각 객체의 반환형과 특성을 고려하여 오류를 줄이도록 노력할게.

헷갈렸던 점#

숫자를 문자열로 변환하는 toFixed()가 실제로 문자열을 반환한다는 점과, 객체와 JSON 문자열을 구분하지 못해 혼동했던 부분이 명확하지 않았다. 특히, 숫자 연산 후 toFixed()를 사용했을 때 예상치 못한 오류가 발생하는 이유를 제대로 이해하지 못했다.

정리된 이해#

숫자 처리, 날짜 관리, 그리고 데이터 교환을 위한 객체 변환 방식에 대한 기본 개념을 확실히 다져야겠다고 느꼈다. toFixed()처럼 문자열을 반환하는 메서드의 특징을 이해하고, 객체와 JSON 문자열의 차이를 명확히 구분하는 것이 중요하며, JSON 직렬화/역직렬화가 데이터 전송 시 필수적이라는 것을 기억해야겠다.

   const value = 31
   const formattedValue = value.toFixed(2) // 문자열 반환
   console.log(formattedValue) // "31.00"
   console.log(typeof formattedValue) // "string"

2. 실행 컨텍스트와 this 완벽하게 이해하기#

무엇을 배웠나#

실행 컨텍스트, 렉시컬 환경, 스코프 체인, 콜 스택 같은 개념들이 서로 얽혀있지만, 각각 현재 실행 환경과 변수 접근 경로를 정의하는 중요한 역할을 한다는 것을 이해하게 되었다. 특히 this가 호출 컨텍스트에 따라 값이 달라지는 점, 그리고 객체 메서드 내에서 this가 호출 객체를 참조한다는 점을 명확히 알게 되었다. 앞으로는 예제를 통해 이러한 개념들의 상호작용을 더 깊이 공부해야겠다.

헷갈렸던 점#

처음에는 실행 컨텍스트, 렉시컬 환경, 스코프 체인 같은 용어들이 너무 비슷해서 뭐가 어떻게 연결되는지 감이 잘 안 잡혔어요. 특히 함수가 여러 개 겹쳐서 호출될 때 콜 스택이 어떻게 동작하는지 시각적으로 이해하기 어려웠고, this가 항상 객체 자신을 가리킨다고 생각해서 전역 컨텍스트에서 window를 가리키는 상황을 설명하기 힘들었습니다.

정리된 이해#

실행 컨텍스트는 코드가 실행될 때 필요한 환경을 정의하고, 콜 스택은 함수 호출 순서를 관리하며, 렉시컬 환경은 변수 접근 경로를 결정한다. this는 함수가 어떻게 호출되었는지에 따라 가리키는 객체가 달라지며, 이는 현재 실행 환경에 따라 결정된다. 이러한 개념들을 이해하면 this가 왜 전역 컨텍스트에서 window를 가리키는지도 설명할 수 있게 되었다.

function outer() {
  function inner() {
    console.log("Inner Function");
  }
  inner();
}

const globalValue = 10;
function outer() {
  const outerValue = 20;
  function inner() {
    console.log(globalValue);
    console.log(outerValue);
  }
  inner();
}

3. 배열 변환, 필터링, 축소: 초보자를 위한 학습 노트#

무엇을 배웠나#

map, filter, reduce 내장 함수를 사용하는 과정에서 콜백 함수의 역할과 배열 요소 간의 상호작용을 이해하는 데 어려움을 겪었지만, 각 함수의 기능을 명확히 정리하고 예시를 통해 이해도를 높였습니다. 특히 map은 변환, filter는 조건 검사라는 키워드를 통해 각 함수의 핵심 기능을 기억하기로 했습니다. 이제 이러한 함수들을 좀 더 자신 있게 활용할 수 있을 것 같습니다.

헷갈렸던 점#

map, filter, reduce 내장 함수를 처음 사용할 때, 콜백 함수가 어떻게 동작하는지, 그리고 각 요소와 어떻게 상호작용하는지 이해하는 데 어려움을 느꼈습니다. 특히 map에서 콜백 함수가 어떤 역할을 하는지, reduce에서 누적값이 어떻게 변경되는지 파악하기 힘들었습니다. 전체적인 흐름을 한눈에 보기 어려워서 디버깅하는 데 시간이 오래 걸렸습니다.

정리된 이해#

map, filter, reduce는 각각 배열의 요소를 변환하고, 조건에 따라 요소를 선택하고, 배열의 모든 요소를 처리하여 단일 값을 만드는 강력한 내장 함수입니다. 콜백 함수는 각 요소에 적용될 동작을 정의하며, map은 요소를 변환하고, filter는 조건을 만족하는 요소를 선택하며, reduce는 누적값을 계산하는 데 사용됩니다. 이 함수들을 이해하면 코드를 간결하고 효율적으로 작성할 수 있습니다.

const doubledArray = arrayFunctions.map([1, 2, 3], (item) => item * 2);
// 결과: [2, 4, 6]

const longStrings = arrayFunctions.filter(["apple", "banana", "cherry", "fig"], (item) => item.length >= 5);
// 결과: ["banana", "cherry"]

const sum = arrayFunctions.reduce([1, 2, 3, 4], (accumulator, currentValue) => accumulator + currentValue, 0);
// 결과: 10

4. 상대 시간 계산의 혼란과 해결: 기준 정립 및 효율적인 코드 작성#

무엇을 배웠나#

상대 시간 계산 문제를 풀 때, 문제에서 제시하는 기준과 일반적인 달력 기준을 명확히 구분해야 한다는 것을 깨달았습니다. 특히 채점 시스템의 요구사항에 맞춰 달을 4주, 년을 12개월로 정의하는 것이 중요했습니다. 복잡한 조건문 사용을 지양하고 기준값 배열과 .find() 메소드를 활용하여 코드의 효율성과 가독성을 높이는 방법을 익혔습니다.

헷갈렸던 점#

처음에는 달과 해의 길이를 임의로 정해서 계산했더니 채점 시스템의 기준과 차이가 많이 나서 어려움을 겪었습니다. 특히 4주, 2개월, 2년 단위의 상대 시간 표현에서 오답이 나왔고, 여러 개의 if 문을 사용해서 코드가 복잡해지는 문제도 있었습니다. 기준을 명확히 하고 효율적인 코드 작성 방법을 찾아야 한다는 것을 깨달았습니다.

정리된 이해#

상대 시간 계산 시, 문제에서 제시하는 기준(4주=1개월, 12개월=1년)과 일반적인 달력 기준을 명확히 구분해야 했고, 복잡한 조건문 대신 기준값 배열과 .find() 메소드를 활용하여 코드의 효율성을 높일 수 있었습니다. 중요한 것은 문제의 조건을 정확히 파악하고, 이에 맞춰 코드를 구현하는 것이었습니다.

const units = [
  { limit: 60 * 24 * 7, value: 60, text: "분" },
  { limit: 24 * 7, value: 24, text: "시간" },
  { limit: 7 * 24 * 30, value: 7 * 24, text: "일" },
  { limit: 30 * 24 * 365, value: 30 * 24, text: "주" }
];

5. JSON 생성 및 폼 입력 처리 연습#

무엇을 배웠나#

HTML 폼 제출 시 페이지 리로드를 막기 위해 event.preventDefault()를 사용해야 한다는 것을 알게 되었고, JSON 문자열을 만들 때 JavaScript 객체를 활용하고 JSON.stringify()를 사용하는 것이 더 안전하고 효율적인 방법임을 이해했습니다. 또한, 폼 요소의 name 속성이 없을 때는 FormData를 직접 활용하기 어렵다는 점도 확인했습니다. 이 내용을 바탕으로 좀 더 안정적인 폼 처리 코드를 작성할 수 있을 것 같습니다.

헷갈렸던 점#

HTML 폼 제출 시 페이지 새로고침이 발생하는 이유와 event.preventDefault()를 사용해야 하는 시점을 파악하는 데 어려움을 겪었습니다. 또한, JSON 문자열을 직접 만들 때 오류 발생 가능성이 높다는 것을 인지하고, JSON.stringify()를 사용하는 것이 더 안전하고 효율적인 방법임을 깨달았습니다. 폼 요소의 name 속성 유무에 따라 데이터 처리 방식이 달라지는 점도 처음에는 명확하게 이해하지 못했습니다.

정리된 이해#

JSON 문자열을 만들 때는 JavaScript 객체를 먼저 만들고 JSON.stringify()를 사용하는 것이 더 안전하고 효율적인 방법임을 알게 되었다. 폼 제출 시 페이지 새로고침을 막기 위해서는 버튼 클릭 이벤트에서 event.preventDefault()를 사용해야 한다. 폼 요소의 name 속성이 없을 때는 FormData를 활용하기 어려우므로, 각 입력 요소의 값을 직접 접근하여 JSON 객체를 만들어야 한다.

const user = {
  email: document.querySelector("#inputEmail").value,
  name: document.querySelector("#inputName").value,
  password: document.querySelector("#inputPassword").value,
};
const userJson = JSON.stringify(user);

button.addEventListener("click", (event) => {
  event.preventDefault();
  alert(userJson);  // 예시 출력
});

const formData = new FormData(form);
const user = Object.fromEntries(formData.entries());
alert(JSON.stringify(user));

6. FormData를 활용한 금융 계산기 구현, 데이터 변환과 수학 공식 적용 이해#

무엇을 배웠나#

FormData 객체를 숫자 객체로 변환하는 과정에서 Number() 함수를 사용하여 문자열 값을 숫자로 바꿔야 한다는 것을 알게 되었고, formDataToObject 함수의 쉼표 연산자 활용법도 이해하게 되었습니다. 또한, 문제에서 요구하는 “반올림"이 Math.floor() 함수를 사용한 내림을 의미한다는 것을 명확히 깨달았습니다. 복리 계산기 및 손익분기점 계산기 구현 시 이러한 부분을 주의하면 원하는 결과를 얻을 수 있을 것 같습니다.

헷갈렸던 점#

FormData 객체를 숫자 객체로 변환하는 과정, 특히 formDataToObject 함수 안의 Number() 변환이 왜 필요한지 처음에는 잘 이해하지 못했습니다. 또한, 코드에서 쉼표 연산자를 사용한 압축 표현을 보면서, 그 의미를 파악하는 데 시간이 걸렸습니다. 반올림이라는 지시사항 때문에 Math.floor()함수가 왜 사용되었는지 혼란스러웠습니다.

정리된 이해#

HTML 폼에서 받은 데이터를 숫자 형태로 변환하는 과정, 특히 formDataToObject 함수에서 Number()를 사용하여 값을 숫자로 바꾸는 점을 명확히 이해하게 되었어요. 또한, Math.floor() 함수가 반올림이 아닌 내림 함수라는 것을 깨달았고, 복리 계산 공식 적용 시 이를 고려해야 함을 알게 되었습니다.

function formDataToObject(formData) {
  return Array.from(formData).reduce((acc, [key, value]) => {
    acc[key] = Number(value); // 숫자 변환 필수
    return acc;
  }, {});
}

7. 주식 수익률 계산기 오류 분석 및 데이터 검증 방법#

무엇을 배웠나#

HTML 폼 데이터를 가져올 때, FormData 객체에서 실제 키를 정확히 파악하는 것이 중요하다는 것을 배웠습니다. 예상 키로 데이터를 가져오려 했기 때문에 오류가 발생했고, 실제 키를 확인하는 방식으로 문제를 해결했습니다. 또한, 폼 데이터의 타입 변환과 계산 로직 검토의 필요성을 인지하게 되었습니다.

헷갈렸던 점#

처음에는 HTML 폼에서 데이터를 가져올 때 FormData.get()에 넣는 키 값을 정확히 몰라서 데이터를 제대로 가져오지 못했고, 그 결과 계산이 제대로 이루어지지 않았던 부분이 컸습니다. 특히 자동 채점 결과가 모두 0점으로 나오는 이유를 파악하는 데 어려움을 겪었으며, 폼 데이터의 실제 키와 예상 키가 일치하지 않는다는 것을 인지하는 데 시간이 오래 걸렸습니다.

정리된 이해#

HTML 폼에서 받아오는 데이터의 정확한 키를 확인하지 않고 FormData.get()을 사용해서 데이터를 가져오려 했더니, 계산에 필요한 값이 누락되어 오류가 발생했습니다. 실제 폼 데이터를 확인하고, 데이터 타입 변환 과정과 각 계산 단계별 결과를 로깅하여 문제점을 파악하는 것이 중요함을 알게 되었습니다.

const formData = Object.fromEntries(new FormData(stockForm).entries());
console.log(formData);

console.log(calculateStockResult({buyPrice: parseFloat(formData.buyPrice), currentPrice: parseFloat(formData.currentPrice), stockAmount: parseFloat(formData.stockAmount)}));
