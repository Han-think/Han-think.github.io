1. 결정계수와 SST·SSR·SSE 그래프, 초보자를 위한 해석#

무엇을 배웠나#

결정계수 (R^2)를 이해하는 데 필요한 SST, SSR, SSE 각각이 의미하는 바를 명확히 알게 되었다. SST는 전체 데이터의 변동성, SSR은 모델이 설명하는 변동성, SSE는 모델이 설명하지 못한 오차를 나타냄을 이해했다. 특히, SSR과 SSE의 혼동을 바로잡고, 이들의 관계를 통해 모델의 설명력을 파악하는 방법을 익혔다.

헷갈렸던 점#

결정계수 R²와 관련된 그래프에서 회귀선, 평균선, 실제값-예측값 거리 요소들의 의미를 명확하게 구분하는 데 어려움을 느꼈다. SSR과 SSE의 정의가 자료마다 다르게 사용되어 혼란스러웠고, R² 값을 모델의 정확도를 나타내는 수치로 단순하게 해석하는 것이 맞는지 확신이 없었다. 전체적인 데이터 변동성과 모델이 설명하는 변동성, 그리고 예측하지 못한 오차를 어떻게 그래프로 표현하는지 파악하는 것이 중요했다.

정리된 이해#

전체 데이터의 변동성(SST)은 실제값과 전체 평균의 차이, 모델이 설명하는 변동성(SSR)은 예측값이 전체 평균과 얼마나 차이가 나는지, 그리고 모델이 설명하지 못한 오차(SSE)는 실제값과 예측값의 차이로 각각 이해하면 된다. 결정계수 R²는 SSR을 SST로 나눈 값으로, 모델이 데이터의 변동성을 얼마나 설명하는지를 나타내는 지표이며, 1에 가까울수록 모델의 설명력이 높다. SSR과 SSE의 정확한 정의는 자료에 따라 달라질 수 있으므로 주의해야 한다.

SST = \sum (y_i - \bar{y})^2

SSR = \sum (\hat{y}_i - \bar{y})^2

2. 다항 회귀 과적합과 손실 지표 이해하기#

무엇을 배웠나#

초보자를 위한 회귀 분석 학습 과정에서 과적합 판단과 손실 지표 해석에 대한 잘못된 이해가 있었음을 깨달았습니다. 훈련 데이터 오차 감소만으로 모델 개선을 판단하는 오류를 범했고, 손실 값의 변화에만 지나치게 집중했습니다. 이제는 훈련/검증 오차의 변화를 종합적으로 고려하고, 다양한 요인을 염두에 둔 손실 지표 해석이 중요하다는 것을 알게 되었습니다.

헷갈렸던 점#

처음에는 훈련 데이터의 오차가 계속 줄어들면 모델이 잘 학습되고 있다고 생각했는데, 테스트 데이터의 오차를 간과하고 과적합을 제대로 판단하지 못했습니다. 손실 값이 감소할 때마다 모델이 항상 좋아지는 것처럼 생각했고, 손실 변화에 너무 의미를 부여하여 다른 요인을 고려하지 못했습니다.

정리된 이해#

초보자도 쉽게 이해할 수 있도록 단순 및 다항 회귀 분석에서 과적합과 손실 지표에 대한 이해를 정리했습니다. 훈련 데이터 오차가 계속 줄어든다고 모델이 좋아지는 것이 아니라, 검증 데이터 오차의 증가를 통해 과적합을 판단해야 하며, 손실 지표(RMSE, MAE)를 통해 모델의 성능을 균형있게 평가해야 합니다. 이 내용을 바탕으로 학습 진행 과정에서 발생할 수 있는 실수를 줄이고 더 나은 모델을 구축할 수 있을 것입니다.

헷갈렸던 점#

정리된 이해#

데이터 탐색 단계에서는 데이터의 전체적인 특징을 파악하고, 전처리 학습 단계에서는 훈련 데이터에만 통계적 기준을 적용하여 데이터 누수를 방지해야 한다는 것을 이해했다. Pipeline을 사용하면 전처리 과정을 체계적으로 관리하고 교차 검증 시에도 데이터 누수를 막을 수 있어 유용하다. 앞으로는 변수명 관리를 철저히 하고 Pipeline을 적극 활용하여 분석의 신뢰도를 높이도록 노력해야겠다.

4. 교차검증과 모델 선택: 성능 평가의 핵심 이해#

무엇을 배웠나#

교차검증이 단순히 데이터를 반복 사용하는 것이 아니라, 모델 성능을 보다 안정적으로 평가하기 위한 중요한 기법임을 깨달았습니다. Train/Test 분할만으로는 모델 성능을 제대로 판단하기 어렵고, 특히 데이터의 편향에 취약하다는 점을 알게 되었습니다. neg_root_mean_squared_error 스코어는 실제 RMSE를 구하기 위해 음수를 취한 값이라는 것을 이해했고, 이를 통해 모델 선택에 더욱 신중해질 수 있을 것 같습니다.

헷갈렸던 점#

처음에는 교차검증이 데이터를 그냥 반복해서 쓰는 것처럼 보여서 데이터 낭비라고 생각했고, neg_root_mean_squared_error가 음수로 나오는 이유가 궁금했습니다. 또한, 단일 Train/Test 분할만으로도 충분할 거라 생각해서 교차검증의 필요성을 명확하게 인지하지 못했습니다.

정리된 이해#

교차검증은 데이터의 특정 부분에 모델 성능이 지나치게 의존하는 것을 방지하기 위해, 데이터를 여러 조각으로 나누어 반복적으로 학습하고 검증하는 방법이다. neg_root_mean_squared_error와 같은 음수 스코어는 실제 RMSE를 나타내므로 음수를 취해 변환해야 한다. 교차검증을 통해 모델 선택 시 더 안정적이고 일반화된 성능을 확보할 수 있다.

5. 하이퍼파라미터 탐색: 시간과 성능의 균형 잡기#

무엇을 배웠나#

하이퍼파라미터 탐색은 단순히 가장 낮은 RMSE를 찾는 것이 아니라, 시간과 성능을 고려한 효율적인 모델 구축 과정이라는 것을 알게 되었습니다. Grid Search, Random Search, Bayesian Optimization 각각의 장단점을 이해하고 상황에 맞게 선택하는 것이 중요하며, CV RMSE와 Test RMSE의 관계를 통해 모델의 일반화 성능을 제대로 평가해야 한다는 점을 깨달았습니다. 그리고 시각화 도구를 활용하여 하이퍼파라미터와 성능 지표 간의 관계를 파악하는 것이 도움이 된다는 것을 확인했습니다.

헷갈렸던 점#

하이퍼파라미터 탐색을 할 때 가장 낮은 RMSE 값을 가진 모델이 항상 최선의 선택일 거라고 생각했는데, 시간과 컴퓨팅 자원을 고려해야 한다는 점이 헷갈렸어요. 교차 검증 결과만으로 모델의 성능을 완벽하게 평가할 수 있을까 의문이었고, 다양한 평가 지표들을 어떻게 조합해야 할지 감을 잡지 못했습니다.

6. SHAP을 활용한 모델 해석 및 시각화 워크노트#

무엇을 배웠나#

SHAP 값이 선형 모델 계수와는 다른, 각 데이터 포인트별 변수의 기여도를 보여주는 개별적인 지표라는 점을 이해하게 되었다. SHAP 값이 높다고 해서 반드시 인과관계를 의미하는 것은 아니며, 모델 해석 시 주의해야 함을 알게 되었다. SHAP Summary Plot을 통해 데이터 포인트와 변수 중요도를 시각적으로 분석하는 방법을 익혔다.

헷갈렸던 점#

선형 모델의 계수와 SHAP 값의 차이를 명확히 이해하지 못해서, 그래프들을 비교하며 어떤 정보를 얻어야 하는지 혼란스러웠습니다. SHAP 값이 높다고 해서 반드시 변수가 예측의 주요 원인이라고 단정할 수 있는지 확신이 없었고, 파생 변수들의 방향성이 직관과 맞지 않을 때 모델이나 데이터의 문제인지 판단하기 어려웠습니다. SHAP 값 해석이 단순한 상관관계 설명에 그치는 건 아닌가 고민했습니다.

정리된 이해#

SHAP 값은 선형 모델 계수와 달리 특정 샘플에 대한 변수의 영향력을 세밀하게 보여주는 도구이며, 모델의 예측 결과를 설명하는 데 유용하지만 인과관계를 증명하지는 않습니다. SHAP Summary Plot을 통해 개별 데이터 샘플의 변수 영향력을 시각적으로 분석할 수 있으며, 이를 통해 모델의 예측 방향성을 파악하고 잠재적인 문제를 발견할 수 있습니다. 예를 들어, 특정 변수의 SHAP 값이 직관과 다를 경우 데이터나 모델 자체를 다시 검토해야 할 수 있습니다.

7. Stacking 모델 학습의 어려움과 올바른 이해#

무엇을 배웠나#

Stacking 모델을 사용할 때, OOF 예측값을 활용하여 누수를 방지하고 모델 성능을 개선해야 한다는 것을 알게 되었다. 또한 Stacking이 무조건적으로 성능 향상을 보장하는 것이 아니며, 시간 효율성과 해석 가능성 등의 요소를 함께 고려해야 함을 깨달았다. 다양한 기반 모델을 선택하여 예측 패턴을 활용하는 실습도 앞으로 진행해봐야겠다.

헷갈렸던 점#

Stacking 모델을 처음 접했을 때, 기반 모델들이 훈련 데이터를 재사용하는 부분이 누수처럼 느껴져서 과적합이 될까 봐 걱정했어요. 또, Stacking이 항상 다른 모델보다 성능이 좋을 것이라는 막연한 기대 때문에, 실제로는 성능 향상이 크지 않더라도 억지로 적용하려는 경향이 있었던 것 같아요.

정리된 이해#

Stacking 모델은 OOF 예측값을 활용하여 누수를 방지해야 하며, 항상 성능이 좋다고 단정 지을 수 없어 시간 효율성과 해석 가능성도 함께 고려해야 합니다. 기반 모델들의 다양한 예측 패턴을 활용하여 메타 모델을 학습시키는 것이 중요하며, 경우에 따라서는 단일 모델이 더 효율적일 수 있습니다. 성능 개선 효과와 시간 증가를 균형 있게 판단하는 것이 핵심입니다.

8. PyCaret AutoML 실습 환경 구축 및 버전 호환성 문제 해결#

무엇을 배웠나#

PyCaret 실습 시 pip 설치 완료 여부가 실행 환경 호환성을 보장하지 않는다는 점을 깨달았습니다. 패키지 버전, 파이썬 버전 등의 호환성 문제를 확인하는 것이 중요하며, pip check 명령어를 통해 의존성 충돌을 진단해야 합니다. 정확한 환경 확인 과정을 거쳐야 강의 내용과 동일한 결과를 얻을 수 있음을 알게 되었습니다.

헷갈렸던 점#

강사님 화면에서는 모델 비교표가 바로 출력되었는데, 제 코드를 실행하니 비교표가 나타나지 않아 코드를 잘못 썼다고 생각했습니다. 설치 로그가 길게 나오길래 필요한 패키지가 모두 설치된 줄 알았고, 실행 환경에 문제는 없을 거라고 생각했습니다. 결국 환경 버전과 의존성 문제를 제대로 확인하지 않았기에 오류가 발생한 것이었습니다.

정리된 이해#

PyCaret 실습 시 패키지 설치가 완료되었다고 해서 곧바로 실행이 가능하다는 착각을 했지만, Python 버전, 패키지 버전, PyCaret 버전 간의 호환성 문제가 발생할 수 있다는 것을 깨달았습니다. 앞으로는 환경 진단 명령어를 활용하여 정확한 환경을 확인하고, pip check 명령어를 통해 의존성 충돌을 해결해야 원활한 PyCaret 사용이 가능할 것 같습니다.

무엇을 배웠나#

헷갈렸던 점#
