React에서 map·Props·State를 분리해 마스터하기 학습 정리

1. map#

왜 이걸 보게 됐나#

React를 처음 접했을 때, 데이터를 화면에 뿌려주는 가장 직관적인 방법이 map 함수임을 깨닫게 되었습니다. 단순히 반복문을 돌리는 것이 아니라, 배열 안에 있는 각각의 아이템을 JSX 형태로 변환해 주는 핵심 도구라는 점이 신선하게 다가왔습니다.

또한 컴포넌트 간의 데이터 흐름을 이해하기 위해 props와 state의 역할을 명확히 구분해야 했습니다. map이 배열 전체를 다루는 반면, props는 부모에서 자식으로 단방향으로 데이터를 전달하고, state는 사용자 상호작용에 따라 화면이 dynamically 변하게 만드는 역할을 한다는 점을 배우며 React의 데이터 흐름 구조가 눈에 들어왔습니다.

내가 헷갈린 지점#

처음에는 map이 단순히 배열을 반복하는 함수라고 생각해서, JSX 안에서 어떻게 화면에 렌더링되는지 감이 안 잡혔습니다. 특히 key prop의 존재 이유와 필수성을 이해하는 데 시간이 걸렸습니다. 또한 map 안에 있는 변수가 부모 컴포넌트의 상태(state)와 연동되는 것인지, 아니면 독립적인 로컬 변수인지 구별하지 못해 혼란스러웠습니다.

시도한 코드 / 예시#

// 10번 화면: map으로 li 리스트 생성
<ul>
  {items.map((item) => (
    <li key={item}>{item}</li>
  ))}
</ul>

결과와 해석#

배열 데이터를 화면에 표시하기 위해 map 함수를 사용하면, 각 아이템을 순회하며 JSX 요소를 반환할 수 있습니다. 이때 key 속성을 지정해주는 것이 리렌더링 성능 최적화와 목록 식별에 필수적입니다. map 내부에서는 인자로 받은 item을 그대로 화면에 출력하거나 가공하여 구조화된 목록 형태로 변환하게 됩니다.

정리된 이해#

map은 배열을 순회하며 각 아이템을 JSX 형태로 변환해 화면에 렌더링하는 반복 처리 도구다. 이때 key 속성을 통해 리액트가 변경된 항목을 효율적으로 식별하고 관리할 수 있다. map의 결과는 반드시 부모 요소 아래에 감싸져야 정상적으로 작동한다.

2. props#

왜 이걸 보게 됐나#

나는 React에서 데이터가 어떻게 흐르는지 이해하기 위해 Props를 배우기 시작했다. 부모 컴포넌트에서 자식에게 데이터를 전달하는 구조를 파악하는 것이 필수적이었기 때문이다. 단순히 값을 넘기는 것을 넘어, 어떻게 하면 자식 컴포넌트에서 그 데이터를 활용할 수 있을지를 고민하며 Props의 역할을 익혔다.

내가 헷갈린 지점#

부모와 자식 컴포넌트 사이에서 데이터가 어떻게 흐르는지 파악하지 못해, prop 이름과 실제 전달되는 값이 일치하는지 확인하는 데 시간을 많이 보냈다. 특히 자식 함수에서 받는 인자 이름이 부모의 prop 이름과 달라 헷갈리거나, 구조 분해 할당을 사용하지 않아 props 객체 전체를 받아와서 접근하는 방식에 익숙해져 있어 코드가 복잡하게 느껴졌던 적이 있었다.

시도한 코드 / 예시#

// props: 부모에서 자식으로 데이터 전달 (자식 함수 인자로 구조 분해)
function Child({ name, age }) {
  return <div>안녕? {name}님은 {age}살이야.</div>;
}

function Parent() {
  const user = { name: "철수", age: 20 };
  // props로 user 객체의 속성값을 전달
  return <Child {...user} />;
}

결과와 해석#

부모 컴포넌트에서 자식에게 데이터를 전달할 때는 JSX 태그의 속성(attribute)으로 값을 지정하고, 자식 컴포넌트에서는 함수 인자로서 구조 분해 할당을 통해 해당 값을 받아와야 한다. 이 과정을 통해 부모의 상태 변화가 자식으로 자연스럽게 흐르며 화면이 업데이트된다. props는 읽기 전용 성격을 띠므로 자식 내부에서 직접 수정하려 하면 에러가 발생하거나 의도치 않은 결과가 나올 수 있다.

정리된 이해#

props는 부모 컴포넌트에서 자식에게 데이터를 전달하는 역할을 하며, 자식은 함수 인자로 구조 분해하여 값을 받아 사용한다. 데이터가 흐르는 방향은 항상 부모 → 자식이며, props는 불변성(immutable)을 가지므로 직접 수정할 수 없다.

3. state#

왜 이걸 보게 됐나#

React 컴포넌트에서 데이터가 화면에 어떻게 반영되는지 이해하기 위해 state 개념을 배우게 되었습니다. 단순히 고정된 데이터를 표시하는 것이 아니라, 사용자의 상호작용에 따라 화면이 실시간으로 변해야 하는 동적인 UI를 구현할 수 있다는 점이 핵심 이유였습니다. 특히 useState 훅을 통해 값의 변화를 감지하고 재렌더링되는 과정을 직접 경험하며, ‘상태’가 컴포넌트의 생명력처럼 작동한다는 사실을 체감하게 되었습니다.

내가 헷갈린 지점#

처음에는 useState가 단순히 값을 저장하는 변수라고 생각해서, 화면이 업데이트될 때마다 값이 초기화되는 줄 알았습니다. 또한 props와 state의 구분이 모호하여, 부모에서 내려주는 데이터와 내부적으로 관리하는 데이터를 구분하지 못해 컴포넌트 간의 데이터 흐름을 잘못 설계한 적이 있습니다.

시도한 코드 / 예시#

// 12번: State - 사용자가 입력한 값을 기억함
const [text, setText] = useState("");

결과와 해석#

useState를 통해 변수를 선언하고 초기값을 설정하면, 해당 값이 변경될 때마다 컴포넌트가 자동으로 다시 그려집니다. 사용자가 버튼을 클릭하거나 입력란에 값을 넣으면 setter 함수를 호출해 상태를 업데이트하면 화면이 즉시 반영됩니다. 이 과정이 반복되어 동적인 UI가 완성된다고 이해했습니다.

정리된 이해#

useState는 컴포넌트 내부에서 값을 기억하고, 값이 변할 때마다 화면을 자동으로 다시 그리는 역할을 한다. setState 함수를 호출하면 데이터가 업데이트되고 React는 변경된 상태를 기반으로 UI를 재렌더링한다.

4. useState#

왜 이걸 보게 됐나#

React 컴포넌트에서 데이터가 시간에 따라 변하거나 사용자의 상호작용에 반응해야 할 때, 정적인 HTML로는 표현할 수 없는 동적 기능을 구현하기 위해 useState를 배우게 되었습니다. 단순히 화면에 텍스트를 출력하는 것을 넘어, 버튼 클릭이나 입력값 변경 같은 이벤트가 발생했을 때 화면을 자동으로 다시 그릴 수 있게 되어 앱의 interactivity가 가능해졌기 때문입니다. 또한, useState를 통해 관리되는 상태가 변하면 React가 자동으로 컴포넌트를 재렌더링해 주므로, 복잡한 DOM 조작 코드 없이도 일관된 UI를 유지할 수 있어 개발 효율이 크게 높아졌습니다.

내가 헷갈린 지점#

useState를 처음 접했을 때, 단순히 값을 저장하는 함수라고 생각하다가도 화면이 업데이트될 때마다 렌더링이 일어난다는 점이 가장 큰 혼란이었습니다. 특히 setText() 같은 setter 함수를 호출해야만 비로소 값이 변하고 화면에 반영된다는 흐름을 이해하는 데 시간이 걸렸습니다. 또한, 초기값으로 빈 문자열을 넣어도 바로 화면에 뜨는 것이 아니라, state가 변경될 때 비로소 DOM이 업데이트된다는 점에서 ‘동기적인 갱신’인지 ‘비동기적인 상태 변화’인지를 구분하기 어려웠습니다.

시도한 코드 / 예시#

// 12번: State - 사용자가 입력한 값을 기억함
const [text, setText] = useState("");

결과와 해석#

useState는 컴포넌트 내부에서 변수를 선언하고 초기값을 설정하는 훅입니다. setText와 같은 반환값을 통해 상태를 업데이트하면, 화면이 자동으로 다시 그려져 최신 값을 보여줍니다. 이는 데이터가 변할 때마다 UI가 실시간으로 반영되게 해주는 핵심적인 역할을 합니다.

정리된 이해#

useState는 화면에서 변하는 값을 기억하고, 값이 바뀌면 자동으로 화면을 다시 그리는 React의 상태 관리 함수입니다. useState로 초기화한 값과 setter 함수를 사용해 데이터를 업데이트하면 컴포넌트가 재렌더링되어 최신 상태로 화면이 갱신됩니다.

총평#

오늘 전체에서 배운 것#

React를 배우며 map, props, state가 각각 배열을 화면에 그리는 역할, 부모에서 자식으로 데이터를 전달하는 역할, 화면의 동적인 값을 관리하는 역할임을 명확히 구분했습니다. 특히 State는 값이 변할 때마다 화면을 다시 그리는 핵심 메커니즘이라는 점을 이해하게 되어 자신감이 생겼습니다.

다음에 조심할 것#

map은 key값을 반드시 지정해야 렌더링 오류를 막을 수 있습니다. props는 부모에서 자식으로 데이터를 내려보낼 때, 자식에서는 구조 분해 할당으로 받아야 합니다. useState는 초기값을 직접 수정하지 않고 setter 함수를 호출하여 상태를 업데이트해야 화면이 다시 그려집니다.

다음 복습 주제#

  • useEffect: 컴포넌트 마운트 시점이나 상태 변화 시 특정 로직(데이터 fetch 등)을 자동 실행하는 훅.
  • Event Handler (onClick 등): 사용자 상호작용을 감지하고 state를 업데이트하거나 함수를 호출하는 역할.
