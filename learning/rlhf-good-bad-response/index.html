1. 강화학습과 LoRA#

왜 이걸 보게 됐나#

RLHF 학습 과정에서 모델의 성능을 향상시키는 여러 기술들이 사용되는데, 초기에 강화학습 자체와 LoRA라는 기술을 혼동하여 전체적인 학습 흐름을 제대로 파악하지 못했습니다. 따라서 RLHF의 역할과 LoRA의 역할을 구분하여 학습해야 더 깊이 있는 이해가 가능하다고 생각하여 이 개념을 배우게 되었습니다. 이 개념을 명확히 이해하면 모델 학습 과정을 더 효율적으로 분석하고 개선할 수 있을 것입니다.

내가 헷갈린 지점#

초기에 강화학습(RLHF)과 LoRA를 마치 같은 의미인 것처럼 착각하여, 강화학습을 모델 최적화 전체 과정을 나타내는 것이고 LoRA는 그 과정을 위한 기술적인 도구라고 생각했습니다. 학습 과정에서 두 개념을 혼동하며, RLHF가 단순히 LoRA를 사용하는 방식으로 이해하고 있었던 점이 오해였습니다. 실제로는 RLHF는 학습 방식과 조련 루프를 지칭하고, LoRA는 기존 모델을 미세 조정하는 기술이라는 것을 명확히 구분해야 했습니다.

시도한 코드 / 예시#

# 코드 없음. 강화학습(RLHF)과 LoRA는 개념적인 차이이며, 코드 예시를 통해 설명할 수 없음.
# RLHF는 학습 방식, LoRA는 미세 조정 기술.

결과와 해석#

RLHF와 LoRA는 혼동했었는데, RLHF는 사용자 선호도를 반영하여 모델을 학습시키는 전체 과정이고, LoRA는 기존 모델을 효율적으로 미세 조정하는 기술이라는 것을 깨달았다. 이를 통해 SFT 이후 LoRA를 사용하여 RLHF 과정을 구현할 수 있다는 것을 이해하게 되었고, 실제 모델 학습 시 연관성을 고려하여 적용할 수 있을 것이다. 처음에는 어렵게 느껴졌지만, 예시를 통해 개념적 차이를 명확히 구분할 수 있었다.

정리된 이해#

RLHF는 LLM을 인간의 선호도에 맞춰 학습시키는 전체적인 방식이고, LoRA는 기존 모델을 효율적으로 미세 조정하는 기술적인 방법이다. 두 개념은 분리해서 이해해야 하며, RLHF 과정에서 LoRA를 활용할 수 있다. 나는 이 둘을 혼동했었지만, 이제는 명확히 구분해서 이해하고 있다.

2. LLM 학습 단계#

왜 이걸 보게 됐나#

LLM 학습 단계를 이해하게 된 건 강화학습(RLHF)과 LoRA를 혼동했던 초기 혼란을 해소하기 위해서였어. RLHF를 단순히 기술적인 방법으로 오해하고 있었던 점을 명확히 하고, LLM이 어떻게 인간의 피드백을 반영하여 발전하는지 전체적인 흐름을 파악하고 싶었지. 이를 통해 더 나은 프롬프트 엔지니어링 및 모델 조련 전략을 수립하는 데 도움이 될 거라고 생각했어.

내가 헷갈린 지점#

처음에는 강화학습(RLHF)이 전체적인 학습 과정이고 LoRA는 그 과정에서 사용되는 기술이라고 생각해서 두 개념이 혼동되었었다. RLHF는 인간 피드백을 활용하여 모델을 조련하는 방식이고, LoRA는 기존 모델을 효율적으로 미세 조정하는 방법이라는 것을 명확히 구분해야 했다. 이 두 가지가 서로 다른 개념이라는 것을 이해하는 데 시간이 좀 걸렸다.

시도한 코드 / 예시#

# 코드 예시: LLM 학습 단계 - SFT (Self-Supervised Fine-Tuning)
# SFT는 인간이 작성한 좋은 응답을 학습하는 단계

결과와 해석#

LLM 학습 단계를 이해하기 위해 간단한 날씨 질문에 대한 모델 응답을 세 개 생성하여 ‘최적’, ‘보통’, ‘불량’으로 분류하는 실습을 해봤어. 모델이 단순히 “오늘 날씨는 맑습니다"라고 답하는 것은 보통으로 평가했고, 날씨 정보와 함께 오늘 활동 추천까지 하는 응답은 최적으로 평가했고, 관련 없는 내용을 섞어 쓰는 응답은 불량으로 분류했어. 이 과정을 통해 LLM이 사용자 의도를 얼마나 잘 파악하고, 어떤 내용이 사용자에게 도움이 되는지 판단하는 기준을 구체적으로 알 수 있었어.

정리된 이해#

LLM 학습은 먼저 토큰 예측 모델을 만들고, 인간이 작성한 좋은 답변을 모방하도록 SFT 과정을 거쳐, 사용자의 선호도를 반영하여 답변을 최적화하는 RLHF 또는 DPO/ORPO 단계를 통해 진행됩니다. 이 과정에서 좋은 응답은 지시사항 준수, 상황 적절성, 실질적인 도움 제공을 포함하며, 나쁜 응답은 이러한 기준을 충족하지 못하는 경우에 해당합니다.

3. 좋은 응답 기준#

왜 이걸 보게 됐나#

RLHF 관점에서 좋은 응답과 나쁜 응답을 이해하기 위해서는, 모델이 사용자 선호도에 맞춰 답변을 최적화하는 과정을 명확히 파악해야 했기 때문입니다. 이를 통해 모델이 어떤 기준으로 답변을 생성해야 하는지, 그리고 어떤 종류의 답변이 사용자에게 만족스러운 경험을 제공하는지 알 수 있었습니다. 궁극적으로는 모델의 성능을 향상시키고 사용자에게 더욱 유용한 답변을 제공하는 데 도움이 될 것이라고 생각합니다.

내가 헷갈린 지점#

처음에는 ‘좋은 응답 기준’이 단순히 문법적으로 완벽하고 형식적인 답변을 의미한다고 생각했어요. 사용자 상황에 맞고 실질적인 도움을 제공하는 것까지 포함해야 한다는 점을 명확히 이해하지 못했고, 위험하거나 부적절한 내용을 피하는 윤리적인 측면까지 고려해야 한다는 점을 간과했습니다.

시도한 코드 / 예시#

"""
좋은 응답 예시:

print(“오늘 서울의 날씨는 맑고, 최고 기온은 28도입니다.”)

print() 함수를 사용해 날씨 정보를 제공#

구체적인 정보 (서울, 28도)를 포함하여 사용자에게 유용함#

"""

결과와 해석#

좋은 응답 기준에 따라 평가한 결과, ‘최적’ 응답은 현재 날짜, 위치 정보를 포함하여 명확하고 사용자 상황에 맞는 정보를 제공하는 것이 중요함을 알 수 있었다. 반면, ‘불량’ 응답은 일반적인 답변만 제공하거나 사실과 다른 정보를 제공하여 사용자에게 실질적인 도움을 주지 못하는 경우임을 확인했다. 이러한 실습을 통해 좋은 응답이 단순히 형식적인 정확성뿐 아니라 내용의 유용성과 관련 있음을 깨달았다.

정리된 이해#

좋은 응답은 사용자의 지시사항을 정확히 따르면서, 상황에 맞는 실질적인 도움을 제공해야 해. 특히 근거 없는 주장은 최소화하고, 위험하거나 부적절한 내용은 피해야 한다는 점을 명심해야 할 것 같아. 형식적인 완성도도 중요하지만, 내용의 의미가 핵심이라는 것을 잊지 말아야지.

4. 프로토콜 기반 평가#

왜 이걸 보게 됐나#

프로토콜 기반 평가는 LLM 응답의 품질을 체계적으로 평가하고 개선하기 위해 도입되었습니다. 단순히 주관적인 판단을 넘어, 명확한 기준에 따라 응답을 분류하고 개선 방향을 제시하여, 모델의 성능을 객관적으로 향상시키고자 했습니다. 또한, 이 과정을 통해 효과적인 프롬프트 엔지니어링 및 규칙 개선 전략을 구축하는 데 도움을 받고자 했습니다.

내가 헷갈린 지점#

프로토콜 기반 평가가 단순히 응답을 ‘좋다/나쁘다’로 나누는 것이 아니라, 왜 그런 판단을 내렸는지 구체적인 이유를 기록하는 과정이라는 점이 처음에는 잘 이해되지 않았다. 단순히 분류하는 것이 아니라, 응답의 어떤 부분이 어떤 기준에 부합하거나 벗어나는지 자세하게 분석해야 한다는 점이 중요했다. 또한, 이 피드백이 프롬프트 개선에 직접적으로 활용될 수 있다는 점도 처음에는 인지하지 못했다.

시도한 코드 / 예시#

결과와 해석#

프로토콜 기반 평가는 동일 질문에 대한 여러 응답을 비교하며 답변의 질을 객관적으로 판단하는 방법론으로, ‘최적’, ‘보통’, ‘불량’ 태그를 부여하여 구체적인 피드백을 기록한다. 이 과정을 통해 프롬프트 및 답변 생성 규칙을 개선하여 모델의 성능을 향상시킬 수 있었다. 예를 들어, 단순히 날씨를 묻는 질문에 ‘최적’ 응답은 현재 온도, 습도, 풍속과 같은 구체적인 정보를 제공해야 한다.

정리된 이해#

프로토콜 기반 평가는 동일한 질문에 대해 생성된 여러 응답을 객관적으로 평가하여, 각 응답의 장단점을 파악하고 개선점을 찾는 방법론이다. 이를 통해 프롬프트와 규칙을 지속적으로 개선하여 모델의 답변 품질을 향상시킬 수 있다. 단순히 ‘좋다’, ‘나쁘다’를 판단하는 것이 아니라, 구체적인 피드백을 통해 모델 학습 방향을 설정하는 것이 중요하다.

총평#

오늘 전체에서 배운 것#

강화학습(RLHF)과 LoRA는 서로 다른 개념이며, RLHF는 답변을 최적화하는 학습 방식이고 LoRA는 모델 미세 조정 기술이다. 좋은 응답은 지시사항 준수, 상황 적합성, 실질적인 도움 제공을 포함하며, 프로토콜 기반 평가를 통해 이러한 기준을 객관적으로 판단할 수 있다.

다음에 조심할 것#

다음에는 RLHF 학습 과정에서 LoRA의 역할과 전체 프로세스의 차이점을 명확히 이해하고, 프로토콜 기반 평가를 더욱 체계적으로 수행하여, 응답의 품질을 높이는 데 집중해야겠다. 특히, ‘왜’ 좋았는지/불만족스러웠는지에 대한 구체적인 피드백을 상세하게 기록하여, 지속적인 개선 방향을 설정하는 데 활용해야겠다.

다음 복습 주제#

LoRA를 활용한 RLHF 구현 과정에서 발생하는 문제점과 디버깅 전략을 좀 더 깊이 파악하고 싶다. 또한, DPO/ORPO와 같은 최신 선호 학습 방식의 장단점을 비교 분석하여 RLHF의 발전 방향을 이해해야겠다.
