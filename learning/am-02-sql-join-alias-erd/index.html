1. ERD 이해#

왜 이걸 보게 됐나#

SQL 쿼리를 작성할 때 여러 테이블의 데이터를 조합해야 했는데, 테이블 간의 관계를 제대로 파악하지 못해서 어떤 컬럼을 기준으로 연결해야 할지 막막했어. ERD를 제대로 이해하면 테이블 간의 관계를 시각적으로 보여주기 때문에, 어떤 데이터를 어떻게 가져와야 할지 판단하는 데 도움이 될 거라고 생각했어. 결국 ERD를 통해 데이터를 연결하는 과정을 명확히 이해하고 싶었어.

내가 헷갈린 지점#

ERD를 보면 테이블들이 연결되어 있지만, 그 연결이 실제로 어떤 데이터가 어떻게 연결되는지를 명확하게 보여주지 못한다고 생각했어요. 테이블 간의 관계가 있다는 것만으로는 데이터가 어떻게 조인되는지, 어떤 컬럼이 연결되어야 하는지 파악하기 어려웠습니다. 테이블 구조를 나열한 단순한 그림이라고만 생각했던 탓인지, 실제 데이터 흐름을 나타내는 지도가 아니라고 생각했습니다.

시도한 코드 / 예시#

SELECT
    t.Name AS TrackName

결과와 해석#

ERD를 통해 tracks 테이블과 genres 테이블 간의 GenreId 연결을 명확히 파악하고, 이를 바탕으로 쿼리를 작성하여 각 트랙의 이름을 장르 이름과 함께 가져올 수 있었다. ERD를 그림으로 떠올리니 테이블 간의 관계를 시각적으로 이해하고 JOIN 조건을 설정하는 데 도움이 되었다. 이 실습을 통해 ERD가 단순히 테이블 구조를 보여주는 것이 아니라, 실제 데이터가 어떻게 연결되는지 보여주는 중요한 도구임을 깨달았다.

정리된 이해#

ERD는 테이블 간의 데이터 연결 경로를 보여주는 회로도와 같아서, 테이블 구조뿐 아니라 실제 데이터가 어떻게 연결되는지 파악하는 데 도움을 줘요. ERD를 보면 기본 키와 외래 키를 통해 어떤 컬럼들이 연결되는지 쉽게 알 수 있어서 JOIN 조건 설정에 필요한 정보를 얻을 수 있습니다.

2. 점 표기#

왜 이걸 보게 됐나#

여러 테이블에 동일한 컬럼명이 존재할 때, 어떤 테이블의 컬럼을 참조해야 하는지 명확하게 하기 위해 점 표기법을 배우게 됐어. 예를 들어 tracks 테이블과 invoice_items 테이블 모두 TrackId라는 컬럼을 가지고 있는데, 쿼리에서 어떤 테이블의 TrackId를 가져와야 하는지 구분하기 위해 tracks.TrackId와 같이 점으로 표기해야 했어. 이렇게 하면 쿼리 엔진이 정확히 어떤 컬럼을 사용해야 하는지 알 수 있어서 오류를 줄일 수 있었어.

내가 헷갈린 지점#

처음에는 invoice_items.TrackId나 tracks.TrackId처럼 점으로 구분된 컬럼명이 어떤 의미인지, 그리고 왜 두 개의 같은 이름 컬럼을 구별해야 하는지 몰랐어. 테이블 이름을 명시해야 한다는 건 알겠는데, 어떤 상황에서 점 표기를 해야 하는지, 또 점 표기 없이 사용하면 어떻게 되는 건지 명확하게 이해하지 못했어. 강의를 듣고 나서야 테이블의 관계를 고려해서 특정 컬럼을 지칭하는 표기법이라는 것을 알게 되었어.

시도한 코드 / 예시#

SELECT
    ins.InvoiceId,
    ins.Total,
    cu.FirstName,
    cu.LastName
FROM invoices ins
INNER JOIN customers cu
    ON ins.CustomerId = cu.CustomerId;

결과와 해석#

invoice_items.TrackId와 tracks.TrackId는 같은 이름의 컬럼이라도 어느 테이블에 속해 있는지 명확히 구분해야 한다는 걸 알게 되었어. 점 표기는 테이블 이름을 명시하여 어떤 테이블의 컬럼인지 혼동을 피하게 해주는 중요한 표기법이야. 예를 들어, invoice_items.TrackId는 송장 항목 테이블의 TrackId를 의미하고, tracks.TrackId는 트랙 테이블의 TrackId를 의미하는 것을 알 수 있어.

정리된 이해#

점 표기법은 테이블이 여러 개일 때 어떤 테이블의 어떤 컬럼을 참조하는지 명확하게 알려주는 방식이야. 테이블명.컬럼명처럼 사용하면, 동일한 컬럼명이라도 어느 테이블에 속한 컬럼인지 구분할 수 있어서 쿼리가 훨씬 명확해지고 오류를 줄일 수 있어. 예를 들어 invoices.InvoiceId와 customers.InvoiceId는 완전히 다른 컬럼을 가리키는 것을 나타내지.

3. Alias 사용#

왜 이걸 보게 됐나#

복잡한 쿼리를 작성할 때 테이블 이름이 너무 길어서 가독성이 떨어지고 쿼리 작성 자체가 불편해졌어. 그래서 테이블 이름을 줄여주는 별칭을 배우게 됐고, 특히 여러 테이블을 연결하는 JOIN 쿼리에서 효율적으로 쿼리를 작성하고 이해하는 데 필요하다는 것을 깨달았어.

내가 헷갈린 지점#

처음에는 Alias가 테이블 이름을 줄여주는 것 이상으로 어떤 특별한 의미나 역할을 하는 건가 싶었는데, JOIN 조건이나 SELECT 절에서 컬럼을 명확하게 지정하기 위해 필수적인 도구라는 걸 이해하지 못했다. 특히 여러 테이블을 JOIN할 때 어떤 컬럼이 어느 테이블에 속하는지 혼동될 때 Alias가 없으면 코드가 너무 길어지고 가독성이 떨어지는 것을 경험했다. Alias를 효과적으로 사용해야 복잡한 쿼리를 깔끔하게 작성할 수 있다는 것을 깨달았다.

시도한 코드 / 예시#

SELECT
    tr.Name AS TrackName

결과와 해석#

별칭을 사용하면 쿼리가 더 읽기 쉽고 간결해져서 복잡한 JOIN 구문에서도 테이블 이름을 줄여가며 가독성을 높일 수 있어 편리하다. 예를 들어, tracks 테이블에 tr이라는 별칭을 부여하여 tr.Name과 같이 짧게 참조할 수 있다. 이렇게 하면 쿼리 전체의 가독성을 향상시키고 오타의 가능성도 줄일 수 있다.

정리된 이해#

별칭은 테이블 이름을 줄여서 쿼리를 더 읽기 쉽게 만들어주는 기능이야. 특히 JOIN을 여러 번 사용할 때나 테이블 이름이 길 경우, 쿼리 가독성을 높여주고 실수할 가능성을 줄여줘. 복잡한 쿼리에서 테이블과 컬럼을 구분하기 어려울 때 alias를 활용하면 훨씬 명확하게 표현할 수 있어.

4. JOIN의 본질#

왜 이걸 보게 됐나#

테이블이 여러 개일 때 어떤 데이터를 가져와야 할지 감이 잘 안 잡혀서, JOIN이 어떻게 데이터를 연결하는지 정확히 알아야 쿼리를 작성할 수 있다는 생각에 JOIN의 본질을 배우게 됐어. ERD를 보고도 테이블 간의 관계를 파악하는 데 어려움을 겪었기에, JOIN의 작동 원리를 이해하면 ERD를 더 효과적으로 활용할 수 있을 거라고 생각했어. 결국은 복잡한 쿼리도 자신감 있게 작성할 수 있도록 돕기 위한 과정이라고 느껴졌어.

내가 헷갈린 지점#

처음에는 JOIN을 테이블을 합치는 단순한 작업 정도로 생각해서, 어떤 기준으로 연결해야 할지 막막했어요. ERD를 보더라도 테이블 간의 관계를 정확히 이해하지 못하고, 어떤 컬럼이 연결되어야 하는지 파악하는 데 어려움이 있었습니다. 테이블명이 똑같은 컬럼이 여러 테이블에 존재할 때 어떻게 구별해야 할지 혼란스러웠습니다.

시도한 코드 / 예시#

SELECT
    ins.InvoiceId,
    ins.Total,
    cu.FirstName,
    cu.LastName
FROM invoices ins
INNER JOIN customers cu
    ON ins.CustomerId = cu.CustomerId;

결과와 해석#

위 쿼리는 트랙 정보와 장르 정보를 연결하여 트랙 이름과 해당 장르 이름을 함께 보여주는 예제입니다. INNER JOIN을 사용하여 두 테이블을 연결하고, 테이블 이름을 tr과 g라는 별칭으로 줄여서 쿼리를 더 읽기 쉽게 만들었습니다. 이를 통해 테이블 간의 관계를 이해하고 데이터를 효율적으로 추출할 수 있습니다.

정리된 이해#

JOIN은 여러 테이블의 데이터를 연결하여 원하는 정보를 얻어내는 문법이고, 특정 컬럼을 기준으로 테이블을 연결한다. 단순히 테이블을 합치는 것이 아니라, 관계를 기반으로 데이터를 가져온다는 점이 중요하다. 이를 통해 필요한 정보만 효율적으로 추출할 수 있다.

총평#

오늘 전체에서 배운 것#

ERD를 통해 테이블 간 데이터 연결 경로를 시각적으로 파악하고, 테이블명.컬럼명 표기법을 이해하여 SQL 쿼리 작성 시 혼동을 줄일 수 있게 되었다. 별칭을 사용하면 쿼리를 간결하게 만들고 가독성을 높일 수 있다는 점도 명확해졌다.

다음에 조심할 것#

ERD를 보면서 데이터가 어떻게 연결되는지 경로를 명확히 따라가도록 연습해야겠다. JOIN 쿼리 작성 시, 별칭의 사용이 필수적임을 잊지 않고, 테이블명.컬럼명 표기법을 꾸준히 숙달해야겠다.

다음 복습 주제#

JOIN 조건 설정 시, 외래 키와 기본 키 간의 관계를 ERD와 함께 명확하게 파악하는 연습을 더 해야겠다. 복잡한 JOIN 쿼리에서 별칭 사용의 우선순위를 정하는 기준을 알아보고 싶다.
