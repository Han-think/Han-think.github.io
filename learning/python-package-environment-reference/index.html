1. GitHub 저장소#

왜 이걸 보게 됐나#

개발한 코드를 다른 사람들과 공유하고, 협업하며 프로젝트를 진행하려면 코드를 안전하게 보관하고 관리할 수 있는 장소가 필요해졌어. GitHub 저장소는 버전 관리 시스템을 통해 코드 변경 사항을 추적하고, 팀원들과 함께 코드를 개발할 수 있게 해주는 핵심적인 도구이기 때문에 배우게 되었어.

내가 헷갈린 지점#

처음에는 GitHub 저장소가 단순히 코드 보관 공간일 뿐이라고 생각했는데, 버전 관리 기능과 원격 협업 기능이 있다는 점을 제대로 이해하지 못했습니다. 코드 변경 이력을 관리하고 다른 사람들과 함께 개발하는 데 중요한 역할을 한다는 것을 알게 되었습니다. 또한, 저장소의 main 브랜치와 연결하는 방식이 처음에는 다소 복잡하게 느껴졌습니다.

시도한 코드 / 예시#

git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/yourusername/your-repo.git
git push -u origin main

결과와 해석#

GitHub 저장소는 내 코드와 프로젝트 문서를 안전하게 보관하고 버전 관리할 수 있는 공간이야. git init, git add, git commit 명령어를 사용하여 로컬 저장소를 만들고, git remote add origin 명령어로 원격 저장소를 연결해서 코드를 업로드했어. 이렇게 하면 협업도 쉽고 이전 버전으로 되돌리기도 간편하게 관리할 수 있겠네.

정리된 이해#

GitHub 저장소는 내가 작성한 코드를 안전하게 보관하고, 다른 사람들과 공유하며, 코드의 변경 이력을 관리할 수 있는 온라인 공간이야. 마치 문서 파일을 클라우드에 저장하는 것과 비슷하다고 생각하면 돼. 특히 협업을 할 때 버전 관리에 매우 중요한 역할을 하더라고.

2. PyPI 패키지#

왜 이걸 보게 됐나#

내가 앞으로 코드를 작성하고 다른 사람들과 공유하거나, 다른 사람의 코드를 재사용하고 싶을 때, 패키지로 만들어 배포하고 설치하는 과정이 필요하다는 것을 알게 되었어. 이를 위해선 PyPI와 같은 패키지 저장소에 등록하고, 관리하는 방법을 익혀야 하는데, 오늘 학습을 통해 그 기본적인 이해를 시작하게 된 거지. 앞으로는 좀 더 복잡한 패키지를 만들고 관리할 수 있도록 꾸준히 학습해야 할 것 같아.

내가 헷갈린 지점#

처음에는 PyPI가 단순히 패키지들을 모아놓는 저장소일 뿐이라고 생각했어요. 하지만 .pypirc 파일을 만들고 API 토큰을 설정하는 과정에서, 패키지 배포에는 보안 인증이라는 복잡한 절차가 필요하다는 것을 깨달았습니다. 그리고 twine을 통해 업로드를 하는 방식이 왜 필요한지 처음에 이해하기 어려웠어요.

시도한 코드 / 예시#

[build-system]
requires = ["setuptools>=61.0"]
build-backend = "setuptools.build_meta"

결과와 해석#

PyPI 패키지는 파이썬 코드를 재사용 가능한 형태로 묶어 배포하는 것을 의미하며, pyproject.toml 파일을 통해 패키지의 메타데이터와 빌드 설정을 정의합니다. twine 도구를 사용하여 빌드된 패키지를 PyPI에 업로드하면 다른 개발자들이 pip 명령어를 통해 쉽게 설치하고 사용할 수 있게 됩니다. 이 과정에서 .pypirc 파일은 PyPI 서버와의 연결을 위한 인증 정보를 담고 있어 안전하게 관리해야 합니다.

정리된 이해#

PyPI 패키지는 파이썬 코드를 재사용 가능한 형태로 묶어서 배포하고 공유하는 시스템이고, 다른 개발자들이 쉽게 내 코드를 가져다 쓸 수 있도록 돕는 중요한 역할을 한다. 패키지를 배포하려면 GitHub에 코드를 저장하고, pyproject.toml 파일로 패키지 정보를 설정한 후, uv로 빌드하고 twine으로 PyPI에 업로드하는 과정을 거쳐야 한다.

3. 빌드 및 업로드 도구#

왜 이걸 보게 됐나#

패키지 배포를 위해 코드를 빌드하고 PyPI에 업로드하는 과정을 자동화하기 위해 이 도구들을 배우게 됐어. uv는 현대적인 빌드 시스템을 제공하고, twine은 안전하게 패키지를 PyPI에 전달해주는 역할을 하기 때문에, 수동으로 업로드하는 번거로움을 줄이고 배포 과정을 효율적으로 관리할 수 있게 됐어. 특히, 보안상의 이유로 직접적으로 인증 정보를 입력하지 않고 안전하게 패키지를 배포할 수 있도록 도와주기 때문에 꼭 필요한 도구라고 생각했어.

내가 헷갈린 지점#

처음에는 uv랑 twine이 하는 일이 명확히 구분되지 않아서, 둘 다 패키지를 PyPI에 올리는 과정의 일부 도구라고 막연하게 생각했어요. 그래서 uv가 코드 빌드하는 역할이고, twine은 빌드된 결과물을 PyPI에 업로드하는 역할이라는 것을 이해하는 데 시간이 걸렸습니다. 또, twine을 사용할 때 PyPI 토큰이 필요한 이유가 단순히 패키지를 업로드하기 위한 ‘키’라고 생각했지만, 보안 인증과 관련된 더 중요한 역할이 있다는 점을 나중에 알게 되었습니다.

시도한 코드 / 예시#

[project]
name = "your-package-name"
version = "0.1.0"
description = "Your package description"
authors = [
    { name = "Your Name", email = "your.email@example.com" }
]
dependencies = [
    # "dependency1 >= 1.0",
    # "dependency2 < 2.0",
]

[build-system]
requires = ["uv"]
build-backend = "uv.core.build.pyproject.main"

uv --help

uv build

twine upload --repository testpypi your-package-name-0.1.0-py3-none-any.whl

twine upload --repository pypi your-package-name-0.1.0-py3-none-any.whl

결과와 해석#

uv는 pyproject.toml 파일에 정의된 빌드 설계를 기반으로 패키지 코드를 실행 가능한 형태로 만드는 도구이고, twine은 빌드된 패키지를 PyPI 서버에 안전하게 업로드하는 역할을 합니다. uv를 사용해서 빌드하면, 프로젝트의 메타데이터와 코드 자체가 패키지 파일로 묶이고, twine은 이 패키지 파일을 PyPI에 전송하여 다른 사람들이 다운로드받아 사용할 수 있게 됩니다.

정리된 이해#

uv는 패키지를 빌드해서 배포 가능한 형태로 만드는 도구이고, twine은 빌드된 패키지를 PyPI 서버에 안전하게 업로드하는 역할을 합니다. 이 두 도구를 함께 사용하면 패키지 빌드부터 배포까지의 과정을 자동화하여 효율적으로 관리할 수 있습니다.

4. 테스트 구조#

왜 이걸 보게 됐나#

코드의 품질을 유지하고 예상치 못한 오류를 방지하기 위해 테스트 구조를 배우게 됐어. 패키지를 배포하기 전에 제대로 작동하는지 확인하는 과정은 매우 중요하고, tests/ 디렉토리에 테스트 케이스를 작성함으로써 다른 사람들이 내 패키지를 사용할 때 안정적으로 사용할 수 있도록 돕고 싶었어. 결국, 테스트를 통해 내가 만든 코드가 제대로 동작하는지 스스로 검증하는 방법이라고 생각했어.

내가 헷갈린 지점#

처음에는 tests/ 디렉토리가 왜 필요한지, 그리고 어떤 방식으로 테스트 케이스를 작성해야 하는지 잘 몰랐습니다. 단순히 코드를 실행하는 것이 아니라, 특정 입력값에 대한 예상 결과를 검증하는 코드를 따로 작성해야 한다는 점이 낯설게 느껴졌습니다. 테스트 케이스를 어떻게 구성해야 하는지, 어떤 종류의 테스트를 작성해야 하는지 막연하게 느껴졌습니다.

시도한 코드 / 예시#

# tests/test_my_module.py

import my_module  # 실제 모듈 이름으로 변경

def test_my_function():
    """
    my_module의 my_function에 대한 테스트 케이스입니다.
    """
    assert my_module.my_function(2) == 6  # 예시: 2를 입력했을 때 6이 반환되는지 확인

결과와 해석#

테스트 구조는 tests/ 디렉토리 안에 테스트 코드를 작성하는 방식으로, pytest를 사용하여 실행합니다. 이 테스트들은 패키지의 기능이 예상대로 작동하는지 검증하는 역할을 하며, 코드 품질을 유지하는데 중요한 역할을 합니다. pytest를 통해 테스트 코드를 실행하면, 패키지의 각 기능에 대한 검증 결과를 빠르게 확인할 수 있습니다.

정리된 이해#

테스트 구조는 코드의 정확성을 검증하기 위한 테스트 케이스들을 담고 있는 디렉토리입니다. 이 디렉토리 내에 작성된 테스트들은 패키지의 각 기능이 예상대로 작동하는지 확인하는 역할을 하며, 코드 변경 시에도 테스트를 통해 안정성을 유지할 수 있습니다. 이렇게 작성된 테스트들은 pytest와 같은 도구를 사용하여 실행하고 결과를 확인할 수 있습니다.

총평#

오늘 전체에서 배운 것#

Python 패키지 배포 과정은 코드 저장소, 빌드 도구, 배포 플랫폼 연동, 테스트 실행 등 다양한 단계를 포함하는 복잡한 작업임을 알게 되었다. 특히 .pypirc 파일과 같은 설정 파일에 민감한 정보가 포함되어 보안에 유의해야 한다는 점을 숙지해야겠다.

다음에 조심할 것#

.pypirc 파일에 저장된 토큰 관리에 특히 주의해야 하고, 버전 관리를 제대로 하지 않으면 나중에 큰 문제가 될 수 있다는 것을 기억해야겠다. 테스트를 꼼꼼하게 작성해서 코드의 안정성을 확보하는 것도 중요하다고 생각한다.

다음 복습 주제#

pyproject.toml 파일 설정에 대한 더 자세한 설명을 찾아보고, twine 업로드 시 발생하는 에러 해결 방법에 대해 알아봐야겠다. .pypirc 파일의 보안 관리 부분도 더 공부할 필요가 있다.
