1. Sprite 애니메이션 프레임 제어와 setInterval 활용법#

무엇을 배웠나#

setInterval 함수가 단순히 속도를 조절하는 것이 아니라, 주어진 시간 간격마다 함수를 반복 실행하는 주기적 타이머라는 것을 이해하게 되었어. 초기에는 프레임 속도와 시간 간격을 혼동했지만, i % pos.length를 사용하여 프레임을 반복하는 방식과 setInterval의 역할을 명확히 구분할 수 있게 되었어. 이제 setInterval을 활용하여 스프라이트 애니메이션을 보다 효과적으로 제어할 수 있을 것 같아.

헷갈렸던 점#

처음에는 setInterval을 프레임 속도를 조절하는 역할로 생각해서, 시간 간격을 좁히면 더 많은 프레임이 보이는 줄 알았습니다. 또한, i % pos.length 부분이 프레임을 무한 반복하는 원리라는 것을 명확히 이해하지 못하고 단순히 배열의 크기를 제한하는 것으로만 생각했습니다. 이 과정을 통해 setInterval의 역할을 정확히 이해하고 프레임 제어 로직이 어떻게 작동하는지 명확히 알게 되었습니다.

정리된 이해#

setInterval은 특정 시간 간격마다 함수를 반복 실행하는 타이머이고, 이 타이머를 사용해서 스프라이트 애니메이션의 프레임을 변경할 수 있다는 것을 알게 되었다. i % pos.length를 통해 프레임 인덱스를 순환시켜 스프라이트 애니메이션을 끊임없이 반복할 수 있으며, setInterval의 간격이 짧을수록 스프라이트가 더 빠르게 움직인다.

const spritePositions = [0, -297, -538, -790, -1065, -1310];
let i = 0;

const animateSprite = setInterval(() => {
    document.getElementById('animationScreen').style.background = `url(sprite.png) ${spritePositions[i % spritePositions.length]}px 0`;
    i++;

    if (i >= spritePositions.length) {
        i = 0;
    }
}, 100);

2. 캐릭터 이동과 배경 스크롤 연출, 변수 스코프 이해#

무엇을 배웠나#

캐릭터 이동 시 stop()과 start() 함수를 사용할 때, 전역 변수로 선언된 변수가 초기화되어 위치 정보가 잃어지는 문제를 해결했습니다. 변수 스코프에 대한 이해를 바탕으로, 함수 내에서 변수를 선언하여 상태를 유지하는 방법을 익혔습니다. 또한, 캐릭터 움직임, 배경 스크롤, 시간 제어 등 핵심 개념들을 명확히 이해하게 되었습니다.

헷갈렸던 점#

캐릭터를 멈췄다가 다시 움직일 때, 캐릭터의 위치가 초기화되는 문제가 발생해서 왜 변수가 초기화되는지 이해하기 어려웠다. stop() 함수를 호출해도 위치 정보가 유지되지 않아서, 캐릭터가 항상 처음 위치로 돌아오는 것 같았다. 변수 선언 위치에 따른 스코프의 차이를 제대로 이해하지 못해서 이러한 문제가 발생한 것을 깨달았다.

정리된 이해#

함수를 호출할 때마다 변수가 초기화되는 문제 때문에 캐릭터 이동이 제대로 작동하지 않았는데, 변수를 함수 내부에 선언하여 이 문제를 해결할 수 있었다. setInterval을 이용하여 캐릭터의 이동과 배경 스크롤을 제어하며, sprite 프레임 변경, left 값 변경, 배경 위치 변경 등의 다양한 기법을 활용할 수 있다는 것을 알게 되었다. 함수 스코프에 대한 이해가 중요하다는 것을 깨달았다.

3. Promise 기반 비동기 처리, async/await 활용 가이드#

무엇을 배웠나#

Promise 기반의 비동기 처리 방식에서 발생하는 코드 가독성 문제를 해결하기 위해 async/await 문법을 사용하는 방법을 익혔습니다. async 함수 내에서 await 키워드를 사용하면 코드를 순차적으로 읽을 수 있으며, Promise의 .then() 체이닝보다 훨씬 명확하게 비동기 흐름을 파악할 수 있게 되었습니다. try…catch 구문을 활용하여 에러 처리까지 포함하는 기본적인 실습 예제를 통해 async/await의 활용법을 이해했습니다.

헷갈렸던 점#

처음에는 async와 await가 Promise를 대체하는 개념인지 알았고, await가 코드 실행을 멈추는 것이라서 성능에 영향을 줄까 봐 걱정했었다. 특히 에러 처리가 .then() 체이닝에서는 직관적이었는데, async/await에서는 어떻게 해야 하는지 몰라서 어려움을 느꼈다. 에러 핸들링 블록(try...catch)이 필요하다는 것을 이해하는 데 시간이 걸렸다.

정리된 이해#

Promise는 비동기 작업의 결과를 다루는 객체이고, async는 Promise를 반환하는 함수를 만들 때 사용하며, await은 async 함수 내에서 비동기 작업이 끝날 때까지 기다려 그 결과를 쉽게 가져올 수 있게 해준다. async/await을 사용하면 코드가 더 읽기 쉽고, .then() 체이닝으로 인한 복잡함을 줄일 수 있다. 이 둘을 이해하고 실습하면서 비동기 프로그래밍이 더 명확해졌다.

// async/await 예시
async function fetchDataAsync() {
    try {
        const data = await fetchData();  // 데이터 받을 때까지 기다림
        console.log(data);              // "데이터 받음" 출력
        const moreData = await fetchData();  // 두 번째 데이터 받기
        console.log(moreData);          // "데이터 받음" 다시 출력
    } catch (error) {
        console.error("오류 발생:", error);
    }
}

4. try-catch-finally와 JSON 파싱 예외 처리 가이드#

무엇을 배웠나#

try catch finally 구조를 정확히 이해하게 되었고, 특히 finally 블록이 항상 실행된다는 점을 확실히 알게 되었다. JSON.parse를 사용할 때 발생할 수 있는 예외를 처리하는 방법을 배우고, 오류 발생 시 대체 값을 설정하는 방법도 익혔다. 이제 이 구조를 활용하여 더욱 안정적인 코드를 작성할 수 있을 것 같다.

헷갈렸던 점#

처음에는 try catch finally 구문이 에러 메시지를 보여주는 역할만 한다고 생각해서, finally 블록의 중요성을 제대로 이해하지 못했다. 또한 try 블록이 단독으로 존재할 수 없다는 점을 인지하지 못해 코드 작성에 어려움을 겪었다. JSON.parse를 사용할 때 에러 처리가 왜 필요한지 명확하게 이해하지 못했다.

정리된 이해#

try...catch...finally 구조는 예외가 발생할 수 있는 코드를 감싸고, 에러 발생 시 적절하게 처리하며, 항상 실행되어야 하는 마무리 작업을 수행하는 데 사용된다. finally 블록은 에러 발생 여부와 상관없이 반드시 실행되어 자원 해제 등에 활용될 수 있다는 점을 명확히 이해했다. JSON.parse()와 함께 사용할 때, 잘못된 형식의 JSON 문자열을 처리하는 예외 처리 로직을 구현할 수 있다.

const faultyJsonStr = '{"name":"Jhone","age":"thirty"}';

try {
    let data = JSON.parse(faultyJsonStr);
    console.log('파싱 성공:', data);
} catch (error) {
    console.error('JSON 파싱 오류:', error);
    console.log('에러 발생 시 대체 값 설정:', { name: 'Default Name', age: 0 });
} finally
