1. 집합 연산자#

왜 이걸 보게 됐나#

데이터 분석 프로젝트를 진행하다가 여러 테이블에서 특정 조건을 만족하는 고객 목록을 추출하고 비교하는 작업이 필요했는데, 단순히 테이블을 합치는 방식으로는 원하는 결과를 얻기 어려웠다. 이때 집합 연산자가 여러 조건에 따라 고객 목록을 나누고 비교하는 데 유용하다는 것을 알게 되어 학습하게 되었다. 이를 통해 데이터 분석 효율성을 높이고 싶었다.

내가 헷갈린 지점#

집합 연산자가 단순히 ID 목록을 반환하는 것 같아서, 실제 데이터 분석에서 어떻게 활용되는지 감이 잘 안 잡혔어요. 특히 UNION, INTERSECT, EXCEPT가 어떤 기준으로 결과를 합치고 빼는지 명확하게 이해되지 않았고, 테이블 이름이 일관되지 않으면 쿼리 자체가 실패할 수 있다는 점도 처음엔 몰랐습니다.

시도한 코드 / 예시#

-- 오늘 헷갈린 주제 목록
SET A = ['SQL Join', 'SubQuery']

결과와 해석#

집합 연산자는 여러 쿼리의 결과를 단순히 합치거나 비교하는 논리적인 연산인데, 결과 자체만으로는 어떤 고객의 이름이나 구매 정보 같은 실제 데이터가 나타나지 않아서 처음에는 활용 방법을 이해하기 어려웠다. 예를 들어, UNION ALL을 사용하면 두 개의 쿼리 결과가 이어지지만, 각 결과에 필요한 추가 정보는 별도로 가져와서 결합해야 한다. 쿼리 결과 테이블 간의 컬럼 구조가 일치해야 한다는 규칙이 매우 중요하며, 이를 지키지 않으면 오류가 발생할 수 있다는 점을 기억해야겠다.

정리된 이해#

집합 연산자는 여러 쿼리 결과를 논리적으로 결합하거나 비교하여 새로운 결과 집합을 만드는 기술이야. 단순히 데이터를 합치는 것이 아니라, 중복 제거, 교집합, 차집합 등의 연산을 통해 원하는 정보를 추출하는 데 활용될 수 있어. 즉, 물리적인 데이터 병합이 아닌, 데이터 간의 관계를 분석하고 새로운 정보를 생성하는 데 중요한 역할을 해.

2. 결과 해석#

왜 이걸 보게 됐나#

쿼리를 돌려보면 CustomerId만 나오는 경우가 많았는데, 실제 분석에서는 고객 이름이나 다른 정보가 필요하므로 결과 해석에 어려움을 느껴서였습니다. 단순히 ID 목록만으로는 분석 목표에 맞는 정보를 얻기 어려웠고, 집합 연산 결과가 어떻게 활용되는지 파악하는 과정에서 어려움을 겪었습니다. 그래서 집합 연산의 결과가 어떻게 다른 테이블과 연결되어 전체적인 데이터 분석에 기여하는지 이해하고 싶어졌습니다.

내가 헷갈린 지점#

집합 연산자가 단순히 ID 목록을 반환하는 것 같아서, 이 결과가 실제 데이터 분석에서 어떻게 활용되는지 감이 잘 안 잡혔습니다. 단순히 ID 목록만으로는 고객의 이름이나 구매 내역과 같은 중요한 정보를 알 수 없어서, 이 결과가 어떻게 다른 데이터와 연결되어 전체적인 그림을 그리는 데 사용되는지 이해하기 어려웠습니다. 또한, 결과 해석과 관련해서, 집합 연산의 결과가 어떤 기준으로 정렬되고, 어떻게 다른 테이블과 연결되는지 명확하게 파악하는 데 어려움을 느꼈습니다.

시도한 코드 / 예시#

-- 오늘 헷갈린 주제 목록
SET A = ['SQL Join', 'SubQuery']

결과와 해석#

UNION ALL을 사용해서 오늘 헷갈린 주제 목록과 어제 헷갈렸던 주제 목록을 합쳐서, 제가 어떤 주제에 대해 계속 어려움을 겪고 있는지 빠르게 파악할 수 있습니다. 예를 들어 ‘SQL Join’이 두 목록에 모두 등장한다면, 이 부분에 대한 집중적인 학습이 필요하다는 것을 알 수 있습니다. 이 쿼리의 결과는 단순히 두 목록을 합친 것이 아니라, 제가 학습해야 할 우선순위를 보여주는 중요한 정보가 됩니다.

정리된 이해#

집합 연산의 결과는 단순히 ID 목록처럼 보이지만, 실제로는 다른 테이블과 조인하여 필요한 정보를 가져오는 과정을 통해 분석에 활용됩니다. 즉, 집합 연산은 데이터의 논리적인 관계를 정의하고, 이를 기반으로 원하는 데이터를 추출하는 데 도움을 줍니다. 예를 들어, 구매 이력 고객 분류 쿼리처럼 집합 연산 결과를 바탕으로 추가적인 정보를 가져와서 최종 분석 결과를 얻을 수 있습니다.

3. 컬럼 일치#

왜 이걸 보게 됐나#

집합 연산자를 사용할 때 여러 SELECT 문의 결과가 합쳐지는 방식 때문에, 컬럼의 개수와 순서가 일치하지 않으면 오류가 발생하기 때문이에요. 만약 컬럼이 다르면 어떤 정보를 어떻게 조합해야 할지 판단하기 어려워지고, 연산 결과가 예상과 다르게 나올 수 있습니다. 그래서 각 쿼리의 컬럼 구조를 맞춰야 올바른 결과를 얻을 수 있음을 알게 됐습니다.

내가 헷갈린 지점#

컬럼 일치 규칙을 처음 봤을 때는 단순히 컬럼의 개수가 같으면 된다고 생각했어요. 그런데 다양한 예제를 풀어보면서 각 컬럼의 데이터 타입까지 일치해야 제대로 된 결과를 얻을 수 있다는 점을 깨달았죠. 컬럼의 순서도 중요하다는 사실을 알고 나서 더 꼼꼼하게 쿼리를 작성하게 됐습니다.

시도한 코드 / 예시#

-- 컬럼 일치 예시: 두 SELECT 문의 컬럼 수가 같아야 함
SELECT CustomerId, Name FROM customers WHERE City = 'London';
UNION
SELECT OrderId, CustomerId FROM orders WHERE CustomerId IN (SELECT CustomerId FROM customers WHERE City = 'London');

결과와 해석#

컬럼 일치 규칙은 두 SELECT 문의 컬럼 개수가 같아야 집합 연산이 가능하다는 뜻이에요. SELECT id FROM table1 UNION SELECT name FROM table2 와 같은 쿼리는 컬럼 개수가 다르므로 에러가 발생하고, SELECT id, name FROM table1 UNION SELECT id, email FROM table2 와 같이 컬럼 개수를 맞추면 쿼리가 실행됩니다. 하지만 이 경우, 결과는 id, name, email 이 섞여서 나타나므로, 원하는 정보 분석을 위한 데이터가 아닐 수 있습니다.

정리된 이해#

집합 연산은 여러 쿼리 결과의 컬럼 구조가 동일하다면, 결과를 논리적으로 합치거나 차집합을 구할 수 있게 해주는 연산입니다. 이 때 중요한 점은 실제 데이터를 물리적으로 결합하는 것이 아니라, 결과 집합을 생성하는 것이며, 각 쿼리의 컬럼 개수와 데이터 타입이 일치해야 제대로 동작합니다. 최종 결과는 첫 번째 SELECT 문의 컬럼 구조를 따르게 됩니다.

4. 프로젝트 연결#

왜 이걸 보게 됐나#

프로젝트 연결은 실제 데이터 분석 상황에서 쿼리를 작성할 때 필요한 실질적인 문제 해결 능력을 키우기 위해 도입되었다. 단순히 쿼리 문법을 익히는 것만으로는 부족하고, 쿼리가 어떤 비즈니스 질문에 답하고 어떤 결과를 도출해야 하는지 이해하는 것이 중요하기 때문이다. 이를 위해 다양한 프로젝트 상황을 제시하고, 각 상황에 맞는 쿼리를 작성하는 연습을 통해 쿼리 작성 능력을 향상시키는 것이 목표다.

내가 헷갈린 지점#

프로젝트 연결이라는 개념이 처음에는 왜 학습 노트에 기록해야 하는지 잘 이해가 안 갔습니다. 단순히 헷갈렸던 주제들을 나열하는 것 이상으로, 왜 그 주제들을 프로젝트와 연결해야 하는지, 그리고 그렇게 연결했을 때 어떤 도움이 되는지 알기가 어려웠습니다. 결국, 이것은 나중에 비슷한 문제에 직면했을 때 빠르게 해결책을 찾도록 돕는 중요한 연결고리라는 것을 깨달았습니다.

시도한 코드 / 예시#

-- 오늘 헷갈린 주제 목록
SET A = ['SQL Join', 'SubQuery']

결과와 해석#

어제와 오늘 헷갈린 주제들을 비교하여 어떤 주제가 중복되었는지, 어떤 새로운 주제가 등장했는지 파악하는 쿼리를 작성하려고 했어. SET을 사용하여 변수에 주제 목록을 저장하고, 이를 활용하여 쿼리를 구성하면 두 날짜의 학습 내용을 비교 분석할 수 있을 것 같아. 아직 완벽하게 구현하지는 않았지만, 이 방법을 통해 학습 과정에서 어려움을 겪는 부분을 더 체계적으로 관리할 수 있을 거야.

정리된 이해#

프로젝트 연결은 내가 학습한 개념들을 실제 프로젝트 상황에 적용해보는 연습을 의미한다. 이를 통해 이론적인 지식을 실질적인 문제 해결에 활용하는 능력을 키울 수 있으며, 학습 내용을 더욱 깊이 이해하고 기억하는 데 도움이 된다. 실제로 적용해보면서 막히는 부분을 발견하고 개선하는 과정을 통해 실력 향상으로 이어질 수 있다.

총평#

오늘 전체에서 배운 것#

집합 연산자가 단순히 ID 목록을 반환하는 것이 아니라, 데이터를 논리적으로 결합하여 분석에 활용될 수 있다는 점을 이해하게 되었다. 쿼리 결과 해석과 테이블 이름 일관성의 중요성을 깨달았고, 프로젝트에 집합 연산자를 연결하는 실습을 통해 응용력을 키웠다.

다음에 조심할 것#

쿼리 결과가 단순히 ID 목록으로 보일 때 실제 데이터 분석에 어떻게 활용되는지, 그리고 테이블 이름의 일관성을 유지하는 것이 얼마나 중요한지 명심해야겠다. 특히 UNION이나 EXCEPT을 사용할 때, 각 SELECT 문의 컬럼들이 실제로 어떤 데이터를 가져오는지 꼼꼼히 확인해서 의도하지 않은 결과를 방지해야겠다.

다음 복습 주제#

SQL 집합 연산자 활용 시 결과 해석과 테이블 이름 일관성 유지에 더 신경 써야겠다. 실제 데이터 분석에서 집합 연산 결과가 어떻게 활용되는지 다양한 예제를 통해 더 깊이 파악해야 할 것 같다.
