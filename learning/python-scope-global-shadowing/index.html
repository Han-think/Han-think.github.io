파이썬 스코프와 shadowing 이해하기: 초보자를 위한 전역과 지역 변수 혼동 해소

파이썬에서 전역 변수와 지역 변수의 차이를 이해하고, 함수 내에서 변수 수정 시 발생하는 'UnboundLocalError'를 어떻게 피할 수 있는지 초보자 관점에서 설명합니다.
2026년 6월 2일 · 5 min

왜 썼나#

초보 학습자로서 파이썬 프로그래밍을 시작하면서 가장 먼저 마주치는 개념 중 하나가 변수의 스코프입니다. 특히 전역 변수와 지역 변수의 차이를 이해하는 것이 중요하지만, 이를 실제 코드로 적용할 때 발생하는 오류는 더욱 혼란스럽게 만듭니다. 이번 포스팅에서는 이러한 경험을 바탕으로, 특히 UnboundLocalError가 발생하는 상황을 분석하고 해결 방법을 공유하고자 합니다.

배운 것#

  • 스코프 이해: 파이썬에서 변수의 스코프는 전역 스코프와 지역 스코프(함수 내)로 나뉩니다. 전역 변수는 프로그램 전체에서 접근 가능하지만, 함수 내에서 선언된 지역 변수는 그 함수 내에서만 접근 가능합니다.
  • Shadowing 개념: 동일한 이름의 변수가 스코프가 다른 경우, 내부 스코프의 변수가 외부 스코프의 변수를 가리게 됩니다. 그러나 이 경우 변수 수정 시 특별한 주의가 필요합니다.

헷갈릴린 것#

  • 주요 혼란: 전역 변수 count = 0이 함수 내에서 자연스럽게 업데이트될 것으로 기대했으나, 실제로는 UnboundLocalError가 발생했습니다. 이는 파이썬이 함수 내에서 변수를 수정하려면 먼저 그 변수에 값을 할당해야 한다는 점을 간과한 결과입니다. 
    count = 0

def increase():
    count += 1  # 에러 발생

increase()
    에러 메시지: UnboundLocalError: cannot access local variable 'count' where it is not associated with a value

정리된 이해#

파이썬은 함수 내에서 변수를 참조하거나 수정할 때, 해당 변수가 로컬 스코프 내에서 초기값이 할당되어야 한다는 규칙

왜 썼나#

프로그래밍을 배우면서 가장 기초적이면서도 중요한 개념 중 하나인 변수의 스코프에 대해 깊이 이해하고자 했습니다. 특히 전역 변수와 지역 변수의 차이와 그 사용 시 주의해야 할 점들을 명확히 하는 것이 코드 작성의 정확성과 가독성을 높이는 데 필수적이라고 느꼈습니다.

배운 것#

  • 전역 변수와 지역 변수의 구분: 함수 외부에서 정의된 변수는 전역 변수로, 함수 내에서도 접근 가능하지만 내부에서 수정하려면 특별한 키워드가 필요합니다. 반면에 함수 내에서 정의된 변수는 지역 변수로, 그 함수 내에서만 유효합니다.
  • global 키워드의 역할: 함수 내에서 전역 변수를 직접 수정하려면 global 키워드를 사용해야 합니다. 이를 통해 함수 내부에서 전역 변수의 값을 변경할 수 있습니다.
  • Shadowing 현상 이해: 함수 내부에서 동일한 이름의 변수를 정의하면, 해당 함수 내에서는 지역 변수가 우선시되어 전역 변수가 가려집니다. 이는 의도치 않은 변수 값 변경을 방지하는 데 중요합니다.

헷갈린 것#

  • 초기 학습 단계에서의 오해: 초기에는 count += 1과 같은 코드가 단순히 전역 변수 count에 값을 더하는 것이라 생각했습니다. 그러나 실제로는 현재 count의 값을 읽어들여 1을 더하고 그 결과를 다시 count에 저장하는 과정임을 이해하는 데 시간이 걸렸습니다.
  • 스코프 관련 오류: 함수 내에서 전역 변수를 참조하지 않고 지역 변수로 간주되어 UnboundLocalError가 발생하는 경우를 겪으면서 스코프의 중요성을 실감했습니다.

정리된 이해#

  • 전역 변수: 함수 외부에서 정의되어 함수 내에서 접근 가능하며,

왜 썼나#

프로그래밍을 배우면서 가장 혼란스러운 부분 중 하나는 변수의 스코프 이해였습니다. 특히 함수 내부와 외부에서 동일한 변수 이름이 사용될 때 어떻게 동작하는지 파악하는 것이 쉽지 않았습니다. 이러한 혼동을 통해 프로그래밍에서의 변수 관리와 스코프의 중요성을 깊이 이해하게 되었습니다.

배운 것#

  • 스코프 이해: 함수 내에서 사용되는 변수는 기본적으로 지역 변수로 취급됩니다. 따라서 함수 외부의 전역 변수에 직접 접근하거나 수정하려면 특별한 방법이 필요합니다.
  • global 키워드의 역할: global 키워드를 사용하면 함수 내에서 전역 변수를 명시적으로 참조하고 수정할 수 있습니다. 이를 통해 함수 내부에서 전역 상태를 변경할 수 있는 방법을 배웠습니다.

헷갈린 것#

  • 전역 변수와 지역 변수의 충돌: 함수 내에서 동일한 이름의 변수가 전역 변수와 지역 변수로 동시에 존재할 때, 파이썬이 어떻게 이를 처리하는지 정확히 이해하는 데 시간이 걸렸습니다. 특히, 의도치 않은 변수 덮어쓰기(shadowing) 현상이 혼란을 초래했습니다.

정리된 이해#

  • 스코프 이해: 함수 내부에서 동일한 이름의 변수가 사용될 때, 파이썬은 먼저 지역 변수를 참조합니다. 전역 변수 count에 직접 접근하거나 수정하려면 global 키워드를 사용해야 합니다.

    # 전역 변수 초기화
count = 0

def increase():
    # 전역 변수로 지정
    global count
    count += 1  # 전역 변수 `count`에 1을 더함

# 함수 호출 및 출력 확인
increase()
print(count)  # 출력:

왜 썼나#

이번 학습 세션에서는 함수 내에서의 변수 처리 방식, 특히 전역 변수와 함수 내 매개변수 간의 차이점에 대해 깊이 이해하고자 했습니다. 실제 코드 작성 중 발생한 예상치 못한 결과를 통해 이러한 개념의 중요성을 실감했습니다.

배운 것#

  • 함수 내 매개변수와 전역 변수의 독립성: 함수 내에서 매개변수를 수정해도 외부의 전역 변수에는 영향을 주지 않는다는 사실을 확실히 배웠습니다. 이는 코드의 가독성과 유지보수 측면에서 매우 중요합니다.
  • Shadowing (변수 숨기기): 함수 내에서 매개변수 이름이 전역 변수와 겹칠 경우, 함수 내부에서는 매개변수가 전역 변수를 숨기는 역할을 한다는 점을 이해했습니다.

헷갈린 것#

  • 결과 예측의 어려움: 함수 내에서 매개변수를 수정해도 외부 변수에 영향을 미치지 않는다는 개념이 처음에는 직관적으로 이해하기 어려웠습니다. 특히, print(count) 함수 호출이 전역 변수의 값을 직접적으로 반영한다고 오해할 수 있었습니다.

정리된 이해#

  • 전역 변수와 지역 변수의 차이:

    • 전역 변수: 프로그램 전체에서 접근 가능하며, 어디서든 값을 변경할 수 있지만, 여러 위치에서 수정될 경우 코드 추적이 복잡해질 수 있습니다.
    • 지역 변수: 특정 함수 내에서만 유효하며, 함수 외부에서는 접근할 수 없습니다. 이는 코드의 명확성과 오류 감소에 도움이 됩니다.

  • Shadowing (변수 숨기기):

    • 함수 내에서 매개변수 이름이 전역 변수와 동일할 경우, 해당 매개변수는 함수 내에서 전역 변수를 가리게 됩니다. 따라서 함수 내에서의 변경 사항은 외부 전역 변수에 영향을 미치지 않습니다.

배운 것#

  • 지역 변수 (Local Variable): 함수 내에서만 유효한 변수로, 함수 외부에서는 접근할 수 없습니다. 이는 데이터의 스코프를 제한하여 코드의 안정성을 높입니다.
  • 전역 변수 (Global Variable): 프로그램 전체에서 접근 가능한 변수로, 함수 내외에서 사용할 수 있지만 과도한 사용은 코드의 유지 보수성을 해칠 수 있습니다.
  • Shadowing (덮어쓰기 효과): 동일한 이름의 변수가 중첩된 스코프 내에서 사용될 때, 내부 스코프의 변수가 외부 스코프의 변수를 덮어씁니다. 이 개념은 변수 관리에 있어 주의가 필요합니다.
  • return 키워드: 함수가 특정 값을 반환할 때 사용됩니다. 이를 통해 함수의 결과를 다른 코드 부분에서 활용할 수 있습니다.
  • UnboundLocalError 예외: 지역 변수를 직접 참조할 때 발생하는 오류로, 변수가 선언되지 않았거나 지역 스코프 밖에서 접근하려고 할 때 나타납니다.

헷갈릴 수 있는 점#

  • Shadowing의 영향: 변수 이름이 중첩된 스코프에서 덮어쓰는 경우, 변수의 사용이 예상과 다르게 동작할 수 있어 주의가 필요합니다.
  • 전역 변수의 부작용: 전역 변수는 쉽게 접근 가능하지만, 여러 부분에서 수정될 경우 버그 발생 가능성이 높아집니다.
