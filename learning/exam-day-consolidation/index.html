1. for 루프 기반 실습 패턴#

왜 이걸 보게 됐나#

시험 직전 막연한 불안감에 빠져 방대한 자료를 이리저리 뒤적거리다가, 정작 중요한 핵심 내용을 놓칠까 봐 조급해했던 경험이 있었습니다. 그러다 완성된 코드를 외우는 것보다, 문제를 구조적으로 파악하고 필요한 패턴만 빠르게 꺼내 쓰는 방식이 훨씬 효율적임을 깨닫고 학습 방법을 전환하게 되었습니다. 특히 반복되는 for 루프 같은 기본기를 직접 작성하며 확인함으로써, 어떤 부분이 약한지 실시간으로 파악하고 자신감을 키울 수 있었습니다.

내가 헷갈린 지점#

처음에는 for 루프가 단순히 숫자를 세는 반복 도구로만 느껴져, 문제의 조건에 맞춰 언제 멈출지(break), 어떻게 건너뛰는지(continue) 제어하는 로직을 잡는 것이 어렵게 느껴졌다. 또한 반복문 안에서 변수의 스코프나 상태가 어떻게 변하는지 추적하다 보면, 기존에 작성하던 코드와 다른 흐름 제어로 인해 예상치 못한 결과가 나와 당황했던 적이 있다. 결국 “반복되는 패턴을 구조화해서 읽고, 필요한 부분만 골라 수정하는 과정” 자체가 낯설어서 처음에는 전체를 파악하려다 세부 로직에 매몰되기 쉬웠다.

시도한 코드 / 예시#

for 정방향 / 역방향
조건문
DOM 선택 / 이벤트
value / checked
style / classList
setTimeout / fetch
React map / Props / State

결과와 해석#

for 루프를 활용한 실습은 문제 유형을 빠르게 파악하고 기본 골격을 잡는 데 매우 효과적이었다. 반복되는 패턴을 직접 코드로 작성하면서, 자주 사용하는 구조와 항상 헷갈리는 부분을 실시간으로 인지할 수 있었다. 이를 통해 완성된 코드를 외우는 것이 아니라, 문제를 구조로 읽고 필요한 패턴을 꺼내 쓰는 습관이 형성되었다.

정리된 이해#

시험 직전에는 정보를 추가하는 것보다 압축→분류→즉시 확인의 과정이 무엇보다 중요하며, 완성된 코드를 외우는 것이 아니라 문제를 구조로 읽고 필요한 패턴을 꺼내 쓰며 실행 상태를 확인하면서 수정한다.

2. 조건문#

왜 이걸 보게 됐나#

시험 직전 막막함을 극복하기 위해, 수많은 자료 속에서 무엇을 먼저 봐야 할지 방향성을 잃지 않기 위해 조건문을 공부하게 되었습니다. 특히 반복되는 패턴을 빠르게 파악하고, 헷갈리는 부분은 즉시 확인하며 수정하는 연습을 통해 개념을 확실히 다질 수 있었습니다.

내가 헷갈린 지점#

조건문의 참과 거짓 판단을 위해 변수의 값이 아니라 논리식 자체에 집중하다 보니, 부수 효과가 있는 코드나 복잡한 연산이 섞여 있어도 결과값만 보고 판단하려다 실제 실행 흐름과는 다른 결과를 낳곤 했습니다. 또한 if문 안에서 else if를 연결할 때 각 분기가 중복되지 않도록 신중히 검토하지 않으면, 앞선 조건이 참일 경우 뒤에 오는 코드가 무시되는지 확인하지 않아 의도치 않은 로직 흐름이 발생하기도 했습니다.

시도한 코드 / 예시#

// 조건문 (if-else) 핵심 예시
const score = 85;

if (score >= 90) {
  console.log("등급: A");
} else if (score >= 80) {
  console.log("등급: B"); // 실제 값 적용
} else {
  console.log("등급: C");
}

결과와 해석#

조건문을 작성할 때는 먼저 변수의 값이 참인지 거짓인지 명확히 판단하고, if와 else를 통해 실행 흐름을 나누는 연습을 했습니다. 작성한 코드를 바로 실행해보며 true일 때와 false일 때의 결과가 어떻게 다른지 즉시 확인함으로써, 논리적인 오류를 빠르게 수정하는 습관을 들였습니다.

정리된 이해#

조건문을 단순한 참/거짓 판단이 아니라, 프로그램 흐름을 결정하는 **‘갈림길’**로 인식하고 핵심 비교 대상을 정확히 파악해 실행 순서를 예측한다.

필요한 경우에만 실행되는 선택적 로직임을 이해하고, else문과 결합했을 때 어떤 경우의 수가 발생하는지 전체적인 흐름도를 머릿속으로 그려가며 디버깅의 효율을 높인다.

3. DOM 선택 / 이벤트#

왜 이걸 보게 됐나#

시험 직전 막연한 불안감에 대처하기 위해, 방대한 자료 중에서 핵심 패턴을 빠르게 식별하고 적용할 수 있는 실전적인 학습 방법이 필요했습니다. 특히 마크다운 파일의 구조적 한계를 극복하고, 문제를 단순한 지식 나열이 아닌 ‘구조’와 ‘패턴’으로 인식하여 효율적으로 복습하고 수정하는 훈련을 하게 되었습니다.

내가 헷갈린 지점#

처음에는 document.getElementById() 같은 특정 메서드에만 집중하다가, 실제로는 이벤트가 발생한 요소 자체(this나 event.target)를 기준으로 움직여야 한다는 사실을 놓쳤습니다. 또한 이벤트 핸들러 등록 시 addEventListener와 onclick 속성 사용의 차이점이나 이벤트 버블링(전파) 동작이 어떻게 DOM 트리를 타고 올라가는지 정확히 이해하지 못해, 의도치 않은 요소까지 반응하거나 반대로 반응하지 않는 경우를 경험했습니다.

시도한 코드 / 예시#

// DOM 선택 및 이벤트 핸들링 예시

const button = document.querySelector('#myButton'); // 버튼 요소 선택
const input = document.getElementById('username');   // 입력란 요소 선택

button.addEventListener('click', () => {             // 클릭 이벤트 리스너 등록
  const value = input.value;                         // 입력값 가져오기
  console.log(`입력된 값: ${value}`);                // 콘솔에 출력
});

결과와 해석#

DOM 선택은 document.querySelector() 같은 메서드를 사용해 특정 요소를 찾고, 이벤트는 .addEventListener()로 해당 요소에 반응을 연결하는 방식입니다.

실제로 버튼 클릭 시 btn.addEventListener('click', () => { ... }) 형태로 리스너를 등록하고, 내부에서 console.log()나 스타일 변경을 실행해보면 화면이 즉시 업데이트되는 것을 확인할 수 있습니다.

정리된 이해#

DOM 선택은 document.querySelector나 getElementById 같은 메서드를 통해 요소에 직접 접근하는 것이고, 이벤트는 사용자의 행동(클릭 등)에 반응해 실행되는 콜백 함수를 등록하는 것이다. 핵심은 요소를 먼저 찾아낸 뒤, 그 위에 특정 동작을 연결한다는 순서다. 이렇게 접근하면 매번 전체 코드를 다시 짜지 않고 필요한 부분만 수정하며 빠르게 확인할 수 있다.

4. value / checked#

왜 이걸 보게 됐나#

시험 직전, 방대한 양의 학습 자료를 앞에 두고 어떤 내용을 우선적으로 봐야 할지 막막함을 느꼈습니다. 특히 Markdown 파일의 경우 내용 보존에는 유리하지만, 빠른 훑어보기와 검색에 있어 HTML보다 불편함을 느껴 효율적인 복습 방법을 고민하게 되었습니다. 이에 완성된 코드를 외우는 것이 아니라, 문제를 구조로 읽고 필요한 패턴을 꺼내 쓰는 방식으로 접근하여 핵심만 빠르게 확인하고 수정하는 연습을 하게 되었습니다.

내가 헷갈린 지점#

value와 checked는 HTML input 요소에서 데이터 전달 방식과 상태 확인 방법이라는 점에서 차이가 있었습니다. value는 주로 텍스트 입력란이나 숫자 입력 시 사용자가 입력한 실제 값을 의미하며, checked는 체크박스나 라디오 버튼처럼 On/Off 상태를 나타내는 불리언 값입니다. 특히 value는 input 태그의 attribute로써 초기값(default value)뿐만 아니라 사용자의 입력값까지 포함하지만, checked는 단순히 선택 여부만을 판단하기 때문에 두 속성 모두 form 데이터를 서버에 전송할 때 각각 name과 함께 묶여 전달된다는 점에서 혼동이 있었습니다.

시도한 코드 / 예시#

# 💻 실습 예시: value / checked

value 속성 (입력값)#

<input type="text" id="username" value="홍길동">
<script>
  const input = document.getElementById('username');
  // 현재 입력된 값 읽기
  console.log(input.value); // "홍길동"

  // 값 변경하기
  input.value = "김철수";
</script>

checked 속성 (체크박스/라디오)#

<input type="checkbox" id="agree" checked>
<script>
  const checkbox = document.getElementById('agree');
  // 체크 여부 확인
  console.log(checkbox.checked); // true

  // 체크 상태 토글
  checkbox.checked = !checkbox.checked;
</script>

결과와 해석#

value는 입력 폼이나 드롭다운 등에서 사용자가 선택한 데이터 자체를 의미하며, checked는 체크박스나 라디오 버튼이 현재 선택된 상태인지 여부를 나타냅니다. 실습을 통해 value는 주로 <input> 태그의 속성으로, 제출되는 데이터를 담아내는 역할을 한다는 것을 확인했습니다. 반면 checked는 boolean 형태의 상태로, 사용자가 항목을 직접 활성화하거나 비활성화하는 인터랙션의 핵심임을 체감했습니다.

정리된 이해#

value는 입력 요소에 담긴 실제 데이터(텍스트, 숫자 등)를 의미하며, checked는 체크박스나 라디오 버튼이 선택된 상태인지 여부를 나타내는 불린 값입니다.

총평#

오늘 전체에서 배운 것#

시험 직전 방대한 자료 앞에서 방향성을 잃지 않기 위해, ‘압축 → 분류 → 즉시 확인’의 과정을 통해 핵심 패턴을 빠르게 파악하고 실행에 옮겼습니다. 특히 for 루프와 같은 기본 구조를 직접 작성하며, 자주 사용하는 패턴과 헷갈리는 부분을 실시간으로 점검하여 효율적인 복습을 마무리했습니다.

다음에 조심할 것#

시험 직전에는 새로운 문제를 풀기보다, 지금까지 푼 문제들에서 자주 틀리거나 헷갈렸던 핵심 패턴을 위주로 빠르게 확인하는 것이 가장 중요했습니다.

특히 for 루프, 조건문, DOM 선택 등 기본 골격은 그대로 두고 필요한 부분만 수정하는 방식으로 접근하니, 막연하게 전체를 다시 공부하는 것보다 훨씬 효율적으로 약점을 파악할 수 있었습니다.

다음에 복습하거나 더 알아볼 주제
