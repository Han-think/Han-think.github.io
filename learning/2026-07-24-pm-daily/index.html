1. uv 프로젝트 초기화 및 의존성 관리 가이드#

무엇을 배웠나#

uv 프로젝트를 초기화하고 의존성을 관리할 때 pip install와 uv add의 차이점을 명확히 이해하게 되었다. pyproject.toml은 프로젝트의 의존성 정보를 정의하고, uv.lock은 실제 설치된 패키지 버전과 해시값을 기록하여 재현성을 보장한다는 것도 알게 되었다. 이제 uv를 사용한 프로젝트를 더 효과적으로 관리할 수 있을 것 같다.

헷갈렸던 점#

처음에는 pip install과 uv add 명령의 차이를 명확하게 이해하지 못했습니다. 패키지를 설치하는 과정이 비슷해 보여서 어떤 명령을 언제 사용해야 하는지 헷갈렸습니다. 또한, pyproject.toml과 uv.lock 파일이 비슷해 보여서 각각의 역할이 무엇인지 파악하는 데 어려움을 겪었습니다.

정리된 이해#

pip install은 전역 환경에 패키지를 설치하는 반면, uv add는 프로젝트의 의존성을 관리하고 추적하는 데 사용된다. pyproject.toml 파일은 프로젝트가 필요로 하는 패키지와 버전을 명시하고, uv.lock 파일은 프로젝트의 의존성 트리를 기록하여 재현 가능한 환경을 구축하도록 돕는다. 즉, uv는 프로젝트 기반 의존성 관리 도구이다.

# pyproject.toml 예시
[project]
name = "uv-project"
version = "0.1.0"
requires-python = ">=3.14"
dependencies = [
    "pandas>=3.0.5",
]

# uv.lock 예시 (간략화)
{
    "dependencies": {
      "pandas": {
        "version": "==3.0.5",
        "hashes": [...]
      }
    }
  }

2. 웹 기초: 웹 표준, 접근성, 크로스 브라우징 이해#

무엇을 배웠나#

웹사이트 제작은 단순히 HTML, CSS, JavaScript를 사용하는 것 외에도 웹 표준, 웹 접근성, 크로스 브라우징을 고려해야 한다는 것을 알게 되었습니다. 특히 웹 접근성 확보를 위해 이미지에 대체 텍스트를 제공하는 등 사용자를 위한 배려가 중요하다는 점을 인지하게 되었습니다. 앞으로 웹 개발을 할 때 이러한 서비스 품질 조건을 항상 염두에 두어야겠습니다.

헷갈렸던 점#

웹사이트를 만들 때는 단순히 예쁜 디자인을 만드는 것만으로는 안 된다는 점이 처음에는 와닿지 않았습니다. 웹 접근성이나 크로스 브라우징과 같은 개념들이 생각보다 복잡하게 느껴졌고, ‘내 눈에 보이는 것’과 ‘모든 사용자에게 사용 가능한 것’ 사이의 차이를 명확히 이해하지 못했습니다.

정리된 이해#

웹사이트는 HTML로 구조를 만들고, CSS로 디자인을 적용하고, JavaScript로 기능을 추가하여 완성됩니다. 웹 표준을 지키고 웹 접근성을 고려하여 모든 사용자가 불편함 없이 사용할 수 있도록 만들고, 다양한 브라우저와 기기에서 정상적으로 작동하도록 하는 것이 중요합니다. 이 모든 과정을 통해 사용자에게 최적의 경험을 제공하는 웹사이트를 만들 수 있습니다.

<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>초보 웹사이트</title>
</head>
<body

3. HTML 문서 구조와 <head> 메타데이터 완벽 이해하기#

무엇을 배웠나#

HTML 문서 구조에서 <head> 영역이 웹 페이지의 실제 보이는 영역이 아닌 메타데이터를 담는 곳이라는 것을 제대로 이해하게 되었습니다. favicon 연결 시 rel 속성을 정확하게 사용하는 방법과 <title> 태그에 텍스트만 삽입할 수 있다는 것도 알게 되었습니다. 앞으로는 <head> 영역을 정확하게 활용하여 웹 페이지의 정보와 설정을 관리해야겠습니다.

헷갈렸던 점#

<head> 영역이 웹 페이지의 보이는 영역이라고 착각했고, favicon을 연결할 때 rel 속성에 파일 형식을 직접 지정하는 실수를 했습니다. 또한 <title> 태그 안에 이미지를 넣어 브라우저 탭에 표시할 수 있다고 생각했습니다.

정리된 이해#

HTML 문서 구조에서 <head>는 화면에 직접 보이는 부분(<body)이 아닌, 문서의 메타데이터와 설정을 담는 중요한 영역이다. <title> 태그는 텍스트만 표시하며, favicon 연결 시 rel 속성은 rel="icon"으로 지정해야 한다. 이처럼 <head> 영역을 정확히 이해하고 활용하는 것이 웹 페이지의 완성도를 높이는 데 필수적이다.

<link rel="icon" type="image/png" href="myIcon.png">

<link rel="icon" type="image/png" href="myIcon.png">

4. HTML 태그 진화와 속성 이해하기#

무엇을 배웠나#

HTML의 역할 분담이 과거에는 구조와 시각적 표현을 동시에 담당했지만, 현재는 HTML은 구조, CSS는 스타일, JavaScript는 동작을 담당하게 되었음을 명확히 알게 되었다. 또한 HTML 요소의 구성 요소(태그명, 속성, 콘텐츠 등)를 이해하고, 예시 코드를 통해 실제 적용하는 연습을 함으로써 HTML의 기본적인 작동 방식을 익혔다. 이제는 과거 HTML 태그와 현재 지원되는 태그의 차이점을 구분하고, 속성들이 어떻게 기능을 담당하는지 파악하는 데 더 자신감을 갖게 되었다.

헷갈렸던 점#

과거에는 HTML 태그 하나로 내용의 의미와 디자인까지 모두 결정했지만, 지금은 역할이 분리되어 HTML은 내용의 구조를 담당하게 되었다는 점이 처음에는 이해가 잘 안 갔었다. <font>나 <center> 같은 태그가 더 이상 사용되지 않는다는 사실도, 왜 그런 변화가 있었는지 궁금했다. 속성들이 각각 무슨 역할을 하는지, 그리고 여러 속성이 함께 사용될 때 어떤 영향을 주는지 파악하는 데 시간이 좀 걸렸다.

정리된 이해#

HTML은 웹 페이지의 구조와 의미를 정의하는 역할만 담당하고, CSS로 디자인을, JavaScript로 동적인 기능을 구현하는 방식으로 분리되어 발전했습니다. HTML 요소는 태그, 속성, 콘텐츠로 구성되며, 속성은 요소에 추가적인 정보를 제공하여 기능과 의미를 확장합니다. 이러한 분리를 통해 웹 개발의 효율성과 유지보수성을 높일 수 있습니다.

<h1 style="color: blue;">HTML 태그 실습</h1>

<p>이 단락은 <strong>중요한</strong> 정보를 담고 있습니다.</p>

<a href="https://example.com" target="_blank">Example 링크</a>

<img src="image.jpg" alt="이미지 설명">

5. HTML 기본 태그 실습: 제목 태그와 하이퍼링크 완벽 이해#

무엇을 배웠나#

HTML 기본 태그 실습을 통해 제목 태그는 단순히 텍스트 크기를 조절하는 것이 아니라 정보 구조를 나타내는 중요한 역할을 한다는 것을 깨달았습니다. 또한 하이퍼링크 태그의 기본 구조와 속성을 이해하고, CSS를 사용하여 링크의 스타일을 변경할 수 있다는 것을 알게 되었습니다. 앞으로는 HTML 코드를 작성할 때 정보의 계층 구조를 고려하고, CSS를 활용하여 디자인을 개선하는 데 더욱 집중해야겠습니다.

헷갈렸던 점#

링크 태그의 기본 구조가 예전 웹사이트 경험과 달라서 혼란스러웠고, 제목 태그가 단순히 텍스트 크기를 조절하는 것 이상이라는 점을 이해하는 데 어려움이 있었습니다. 링크 스타일링과 제목 태그의 구조적인 의미를 명확히 파악하는 과정에서 검색과 실습을 반복해야 했습니다.

정리된 이해#

HTML 제목 태그는 단순히 텍스트 크기를 결정하는 것이 아니라 웹 페이지 정보의 계층 구조를 나타내는 중요한 역할을 합니다. 하이퍼링크 태그는 href 속성을 통해 연결되는 URL을 지정하며, target 속성을 사용해 새 탭에서 링크를 열 수 있고, CSS를 통해 다양한 스타일을 적용할 수 있습니다. 이러한 기본 태그들을 이해하고 활용하면 웹 페이지의 구조를 명확하게 만들고 사용자의 편의성을 높일 수 있습니다.

a {
    color: inherit; /* 기본 텍스트 색상 상속 */
    text-decoration: none; /* 밑줄 제거 */
}

6. HTML 편집기 포맷팅, 빠른 학습 속도, 그리고 효과적인 이해 전략#

무엇을 배웠나#

다양한 편집기 사용법 혼란을 겪었는데, IDE는 단순히 코드 작성 도구일 뿐이고 HTML 문법 자체를 바꾸지 않는다는 점을 깨달았다. 기능 이름을 중심으로 학습하고 편집기 설정의 영향을 고려하면 좀 더 효율적으로 학습할 수 있을 것 같다. 앞으로는 코드 작성 도구에만 집중하기보다는 HTML의 기본 구조와 문법을 함께 익히는 것이 중요하다고 생각한다.

헷갈렸던 점#

처음에는 각 IDE마다 다른 단축키 때문에 코드를 깔끔하게 정리하는 포맷팅 작업을 할 때마다 당황스러웠다. 빠르게 진행되는 강의 내용 때문에 웹 표준이나 크로스 브라우징 같은 중요한 개념들을 제대로 이해하지 못할까 봐 걱정되기도 했다. 편집기 사용법에만 집중하느라 HTML 구조 자체에 대한 이해가 부족했다는 걸 깨달았다.

정리된 이해#

IDE는 코드 작성을 돕는 도구일 뿐, HTML 문법 자체를 바꾸지 않는다는 것을 깨달았고, 특정 단축키보다는 기능 이름을 익혀서 다양한 환경에서도 적용할 수 있도록 해야겠다. 편집기 설정에 따라 포맷팅 스타일이 달라질 수 있다는 점을 기억하고, HTML 문법과 기본 구조에 집중하며 학습 속도를 조절해야겠다.

<body>
    <h1">Hello World</h1>

    <ul>
        <li">메뉴1</li>
    </ul>

오늘 오후 전체에서 배운 것#

uv 프로젝트 초기화 및 의존성 관리, 웹 표준 및 접근성, HTML 문서 구조 및 태그 활용 등 웹 개발 기초를 다지는 시간을 보냈다. 특히 HTML 구조와 역할 분담에 대한 이해를 높이고, 웹 접근성을 고려한 개발의 중요성을 인지하게 되었으며, 앞으로 프로젝트를 진행하면서 학습한 내용을 적용해 나갈 계획이다. 다양한 편집기 사용법에 대한 혼란도 줄이고, HTML 기본 구조와 문법을 함께 익히는 방향으로 학습 접근 방식을 개선할 것이다.

다음에 조심할 것#

앞으로는 웹 표준, 접근성, 크로스 브라우징을 잊지 않고 웹 개발에 적용해야겠다. 특히 이미지 대체 텍스트 제공 등 사용자 배려를 위한 요소들을 항상 염두에 두어야 프로젝트의 완성도를 높일 수 있을 것이다. 편집기 설정에 너무 의존하지 않고, HTML의 기본적인 구조와 문법을 먼저 익히는 것이 학습 속도를 높이는 데 도움이 될 것 같다.

다음 복습 주제#

웹 접근성에 대한 이해를 바탕으로 실제 프로젝트에 적용하는 연습을 더 해야 할 것 같습니다. 특히 다양한 사용자 환경을 고려하여 웹 표준을 준수하고, 이미지 대체 텍스트 제공 등 사용자를 위한 배려를 구체적으로 적용하는 방법을 숙지해야겠습니다. 또 HTML 태그 진화 과정에서 변화된 역할 분담과 속성들을 다시 한번 복습하여 실제 코딩에 자연스럽게 적용되도록 노력해야겠습니다.
