1. React State 기초: 숫자와 객체 상태 다루기#

무엇을 배웠나#

React State의 기초를 배우면서, 상태 변수를 직접 수정하면 화면이 업데이트되지 않는다는 것을 깨달았습니다. 특히 객체 상태를 업데이트할 때는 객체를 직접 변경하는 것이 아니라 새로운 객체를 생성하여 업데이트해야 하는 점이 헷갈렸지만, spread 연산자를 활용하여 객체를 복사하는 방법을 통해 해결했습니다. 이 과정을 통해 React State 업데이트의 핵심 원리를 이해하게 되었습니다.

헷갈렸던 점#

처음에는 React state를 그냥 변수처럼 생각해서 count++ 같은 방식으로 직접 바꿔보려고 했더니 화면이 안 바뀌는 게 너무 당황스러웠어. 객체 state를 업데이트할 때, 기존 객체를 건드리지 않고 새로운 객체를 만들어야 한다는 점도 헷갈렸고, spread 연산자를 사용해야 하는 이유를 명확히 이해하지 못했어.

정리된 이해#

React 상태는 직접 수정하면 화면이 업데이트되지 않기 때문에 setCount나 setPerson과 같은 상태 업데이트 함수를 사용해야 해. 객체 상태를 업데이트할 때는 항상 객체를 복사하고 필요한 부분만 변경하여 새로운 객체를 반환해야 React가 변경 사항을 감지하고 화면을 다시 렌더링할 수 있어. 기존 객체를 직접 변경하면 React는 변경 사항을 알 수 없기 때문이야.

const [person, setPerson] = useState({
  name: "김민수",
  count: 0
});

setPerson((current) => {
  const newPerson = { ...current };  // 객체 복사
  newPerson.count = newPerson.count + 1;
  return newPerson;  // 새 객체 반환
});

2. State와 Props를 활용한 컴포넌트 데이터 전달 이해#

무엇을 배웠나#

React에서 State를 Props로 전달하여 자식 컴포넌트가 실시간으로 업데이트되는 방식을 이해하게 되었어. App 컴포넌트의 state가 변경될 때마다 Greeting 컴포넌트가 다시 렌더링되어 최신 상태를 반영한다는 것을 알게 되었고, 다양한 데이터 타입을 Props로 전달할 수 있다는 것도 배웠어. 이를 통해 React 컴포넌트 간 데이터 전달 및 상호작용에 대한 이해도를 높일 수 있을 것 같아.

헷갈렸던 점#

이전에는 컴포넌트에 전달하는 값이 고정된 문자열이라고 생각했는데, React의 State를 Props로 전달하면서 컴포넌트가 실시간으로 업데이트되는 것에 대해 낯설렀다. 특히, State가 변경될 때마다 자식 컴포넌트가 즉시 렌더링되는 자동 업데이트 과정이 어떻게 작동하는지 이해하는 데 어려움을 느꼈다. State를 Props로 전달하는 것이 단순히 값을 넘겨주는 것 이상의 의미를 갖는다는 점을 깨달았다.

정리된 이해#

React의 State를 Props로 전달하면, State가 변경될 때마다 자식 컴포넌트가 자동으로 업데이트된다는 것을 알게 되었다. useState 훅을 사용하여 State를 관리하고, 이 State 값을 Props로 자식 컴포넌트에 넘겨주면, 부모 컴포넌트의 State 변화가 실시간으로 자식 컴포넌트에 반영된다. 다양한 데이터 타입의 값을 Props로 전달할 수 있다는 것도 중요한 점이다.

import React from 'react';

const Greeting = ({ username }) => {
  return <h1>{username}님 안녕하세요.</h1>;
};

export default Greeting;

import React, { useState } from 'react';
import Greeting from './components/Greeting';

function App() {
  const [username, setUsername] = useState('');

  return (
    <div className="App">
      <input
        value={username}
        onChange={(event) => {
          setUsername(event.target.value);
        }}
      />
      <Greeting username={username} />
    </div>
  );
}

3. Todo 앱 디버깅: id, index, useMemo 개념 정리#

무엇을 배웠나#

Todo 앱 디버깅 과정에서 상태, 속성, 이벤트 핸들러 등의 개념이 복잡하게 얽혀 혼란스러웠지만, id와 index의 차이점과 useMemo의 역할을 명확히 이해하게 되었다. 특히 id는 고유 식별자, index는 배열 위치라는 구분을 확실히 하고, useMemo를 통해 성능 최적화가 가능하다는 점을 알게 되었다. 이러한 이해를 바탕으로 Todo 항목의 체크박스 토글 기능을 구현하는 데 필요한 코드를 작성할 수 있게 되었다.

헷갈렸던 점#

Todo 앱 디버깅 과정에서 상태, 속성, 이벤트 핸들러 같은 개념들이 얽혀서 어디서부터 시작해야 할지 막막했습니다. 기존 코드와 수정된 코드를 비교하면서 어떤 부분이 달라졌는지 파악하는 데 어려움을 겪었고, id가 문자열인데 데이터는 숫자로 되어있어서 예상치 못한 오류가 발생했습니다.

정리된 이해#

Todo 앱 디버깅 과정에서 id와 index의 차이, useMemo의 역할, 그리고 타입 불일치 문제를 명확히 이해하게 되었고, 각 개념이 어떻게 연결되는지 파악했습니다. id는 고유 식별자, index는 위치를 나타내며, useMemo는 성능 최적화를 돕는다는 점을 기억해야 합니다. 이제 코드 전환 및 디버깅 시 혼란을 덜 수 있을 것 같습니다.

4. React Router: 링크, 라우팅, 중첩 경로 이해#

무엇을 배웠나#

React Router를 처음 사용할 때 주소 규칙과 파일 구조의 복잡성에 어려움을 겪었지만, Link, Route, 중첩 라우팅, 그리고 useParams()의 역할을 이해하게 되었습니다. 특히 /topics/*와 같은 패턴이 하위 경로 매칭에 필수적이라는 것을 알게 되었고, 이를 통해 SPA에서 페이지 이동 및 URL 파라미터 접근에 대한 개념을 명확히 했습니다. 이제 기본 라우팅 설정을 통해 React Router의 동작 방식을 더 잘 이해할 수 있게 되었습니다.

헷갈렸던 점#

처음 React Router를 접했을 때, 파일 구조가 복잡하게 얽혀 있어서 전체적인 라우팅 흐름을 파악하기 어려웠다. 특히 /topics/와 /topics/*의 차이를 명확히 이해하지 못해 하위 경로 매칭에 오류가 발생하는 경우가 많았다. 이러한 어려움을 해결하기 위해 기본적인 라우팅 설정부터 시작하여 점진적으로 복잡한 구조를 학습했다.

정리된 이해#

React Router는 Link 컴포넌트를 사용하여 페이지를 이동시키고, Route 컴포넌트를 통해 특정 URL과 컴포넌트를 연결합니다. 중첩 라우팅을 사용하면 복잡한 URL 구조를 만들 수 있으며, useParams 훅을 통해 URL 파라미터에 접근하여 동적인 콘텐츠를 표시할 수 있습니다. /topics/* 와 같은 패턴은 하위 경로를 올바르게 매칭하기 위해 필요합니다.

5. React DOM 조작에서 State 기반 렌더링으로의 전환 학습 노트#

무엇을 배웠나#

React에서 DOM을 직접 조작하는 방식에서 벗어나 State 기반 렌더링으로 전환하는 과정에 대한 이해가 부족했던 점을 파악했습니다. 핵심은 State를 변경하면 React가 자동으로 UI를 다시 렌더링한다는 점을 이해하고, DOM 직접 조작 대신 State 관리에 집중해야 함을 알게 되었습니다. 간단한 예제를 통해 State 변경과 UI 업데이트의 관계를 경험하며 조금 더 명확하게 이해하게 되었습니다.

헷갈렸던 점#

수업 진행 속도가 너무 빨라서 제가 놓치는 부분이 있는 것 같았고, DOM 직접 조작에서 React의 State 기반 렌더링 방식으로 넘어가는 과정이 낯설게 느껴졌습니다. 특히, State 변경이 어떻게 UI 업데이트로 이어지는지 명확하게 이해되지 않아 혼란스러웠습니다.

정리된 이해#

React에서는 DOM을 직접 수정하는 대신 State를 변경하여 컴포넌트가 재렌더링되도록 해야 UI가 업데이트됩니다. State 기반 렌더링은 UI 변경에 필요한 로직을 컴포넌트 내부에 포함시켜 코드의 예측 가능성과 유지보수성을 높입니다. 강의에서 빠르게 진행된 코드 수정 과정은 이러한 State 기반 렌더링의 작동 원리를 이해하는 데 중요했습니다.

import React, { useState } from 'react';

function TextChanger() {
    const [text, setText] = useState("처음");
    const changeText = () => {
        setText("변경됨");
    };
    return <div onClick={changeText}>{text}</div>;
}
