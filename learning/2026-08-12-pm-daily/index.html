1. React SPA 블로그 리스트 UI 구현 실습#

무엇을 배웠나#

SPA 개념을 페이지 이동이 아닌 컴포넌트 단위 업데이트로 이해하게 되었고, props를 통해 데이터를 전달하여 하위 컴포넌트에서 map() 함수를 사용해 리스트 UI를 만들 수 있다는 것을 알게 되었다. 배열 데이터를 기반으로 블로그 리스트 UI를 만드는 실습을 통해 데이터 처리 과정과 JSX 반복 사용법을 익혔다. 이제 SPA 구조에서 데이터 흐름과 컴포넌트 간 상호작용에 대한 이해가 조금 더 명확해졌다.

헷갈렸던 점#

처음에는 SPA가 여러 페이지를 가진 앱이 아니라, 하나의 페이지에서 동적으로 내용을 바꾸는 형태라는 것을 제대로 이해하지 못했습니다. 특히 데이터를 어떻게 부모 컴포넌트에서 자식 컴포넌트로 넘기고, 배열 데이터를 바탕으로 UI를 반복적으로 만들어야 할지 막막했습니다. map() 함수를 어떻게 활용해야 할지 감이 잘 오지 않았습니다.

정리된 이해#

SPA는 페이지 전체를 새로 로딩하지 않고 필요한 부분만 업데이트해서 사용자 경험을 향상시키는 구조이며, 데이터를 props를 통해 컴포넌트 간에 전달하고 map() 함수를 사용하여 배열 데이터를 반복적으로 렌더링하여 리스트 형태의 UI를 만들 수 있다는 것을 알게 되었다. 이번 실습을 통해 SPA의 작동 방식과 데이터 전달 및 UI 생성 과정을 명확하게 이해하게 되었다.

2. React Todo 앱: 컴포넌트 구조와 역할 이해#

무엇을 배웠나#

React Todo 앱을 여러 컴포넌트로 나누는 방식에서 컴포넌트 계층과 상태 관리의 복잡함이 느껴졌다. 각 컴포넌트의 역할과 데이터 흐름을 명확히 이해하는 것이 중요하며, 컴포넌트 분리는 코드의 유지보수성과 확장성을 높이는 데 기여한다는 것을 알게 되었다. 앞으로는 컴포넌트 역할 분담과 상태 관리 기본을 더 깊이 학습해야겠다.

헷갈렸던 점#

이전 블로그 예제에서는 데이터 출력이 직관적이었는데, Todo 앱에서는 상태와 컴포넌트 계층 구조 때문에 데이터 흐름이 복잡하게 느껴져서 명확히 이해하기 어려웠다. 단순히 코드를 나누는 것 이상의 컴포넌트 분리의 목적이 무엇인지도 제대로 파악하지 못했다. 각 컴포넌트의 역할과 책임 분담이 어떻게 코드 유지보수와 확장성에 기여하는지 궁금했다.

정리된 이해#

Todo 앱을 컴포넌트로 나누면 각 컴포넌트가 특정 역할을 담당하여 코드의 유지보수성과 확장성이 높아집니다. 각 컴포넌트는 사용자 입력, 목록 표시, 개별 항목 관리와 같은 기능을 분담하며, 컴포넌트 계층을 통해 앱 전체의 구조를 효율적으로 관리할 수 있습니다.

// TodoInput.js
import React, { useState } from 'react';

function TodoInput({ addTodo }) {
  const [inputValue, setInputValue] = useState('');

  const handleInputChange = (e) => {
    setInputValue(e.target.value);
  };

  const handleAddTodo = () => {
    if (inputValue.trim() !== '') {
      addTodo(inputValue);
      setInputValue('');
    }
  };

  return (
    <div>
      <input type="text" value={inputValue} onChange={handleInputChange} />
      <button onClick={handleAddTodo}>Add</button>
    </div>
  );
}

export default TodoInput;

3. React를 위한 Modern JavaScript 핵심 개념 정리#

무엇을 배웠나#

React 코드를 보면서 Modern JavaScript 문법들이 섞여 혼란스러웠는데, const, let, 배열 메서드(forEach, map, filter), 그리고 Arrow Function의 역할을 명확히 정리하며 이해도를 높였습니다. 특히 map() 함수를 활용하여 배열 데이터를 React 컴포넌트 내에서 효과적으로 활용하는 방법을 실습 예시를 통해 배웠습니다. 이제 좀 더 자신감 있게 React 코드와 Modern JavaScript 문법을 함께 사용할 수 있을 것 같습니다.

헷갈렸던 점#

처음에는 const와 let의 차이점을 명확히 이해하지 못해서, 변수를 선언할 때 어떤 것을 사용해야 할지 혼란스러웠어요. 또한, forEach, map, filter 같은 배열 메서드들이 각각 어떤 상황에 적합한지, 그리고 어떻게 서로 다른 역할을 수행하는지 파악하기 어려웠습니다. Arrow Function의 간결함은 좋지만, 기존 함수 표현식과의 차이점을 명확하게 인지하지 못했습니다.

정리된 이해#

const와 let의 차이, 그리고 forEach, map, filter와 같은 배열 메서드들과 Arrow Function을 제대로 이해했으니 이제 React 코드 속 복잡함에서 벗어날 수 있겠어요. 특히 map 함수를 활용하여 데이터를 변환하고 화면에 표시하는 예제를 통해 Modern JavaScript 문법이 React 컴포넌트 안에서 어떻게 활용되는지 감을 잡았습니다. 이제는 이러한 문법들을 상황에 맞게 적용하여 더 깔끔하고 효율적인 코드를 작성할 수 있을 것 같습니다.

const numbers = [1, 2, 3];
const listItems = numbers.map(number => <li key={number}>{number}</li>);
return (
  <ul>{listItems}</ul>
);

4. Modern JavaScript 핵심 문법: 구조 분해, 단축 속성, Spread, 템플릿 리터럴#

무엇을 배웠나#

Modern JavaScript의 객체 문법, 특히 구조 분해, 단축 속성명, Spread 연산자, 템플릿 리터럴, 옵셔널 체이닝을 실습하며 React 개발에 필수적인 문법들을 익혔습니다. 실제 코드 예제를 통해 각 문법의 사용법을 이해하고, React 상태 관리에 구조 분해가 어떻게 활용되는지 명확하게 알게 되었습니다. 앞으로 React 코드를 작성할 때 더욱 간결하고 효율적인 코드를 작성할 수 있을 것 같습니다.

헷갈렸던 점#

처음 구조 분해 할당을 접했을 때, 변수명과 객체 속성명 매칭이 정확히 안되면 에러가 나는 이유가 잘 이해가 안 갔습니다. 단축 속성명은 변수명과 속성명이 같을 때만 가능한 줄 알았는데, 좀 더 다양한 상황에서 적용될 수 있다는 점이 신기했습니다. Spread 연산자를 사용할 때, 배열이나 객체를 복사하는 개념인지, 단순히 참조를 전달하는 건지 혼란스러웠습니다.

정리된 이해#

Modern JavaScript의 구조 분해, 단축 속성명, Spread 연산자, 템플릿 리터럴, 옵셔널 체이닝 문법을 실습하면서 React 개발에 필수적인 기능들이라는 것을 체감했습니다. 특히 구조 분해는 상태 관리 및 컴포넌트 props 전달에서 매우 유용하며, Spread 연산자는 배열이나 객체를 쉽게 확장할 수 있게 해준다는 것을 알게 되었습니다. 앞으로 이 문법들을 능숙하게 활용하여 더 효율적인 코드를 작성하도록 노력해야겠습니다.

5. React import와 JSX 환경 이해: 초보자를 위한 핵심 정리#

무엇을 배웠나#

이번 실습을 통해 React 프로젝트에서는 import React from 'react';을 반드시 작성해야 한다는 것을 알게 되었다. JSX를 사용하려면 React가 스코프에 있어야 하고, 이는 ESLint 규칙 및 JSX 문법 요구사항에 따른 것이다. 파일이나 패키지를 불러오는 방식도 명확히 이해하게 되어 앞으로 React 코드를 작성할 때 도움이 될 것 같다.

헷갈렸던 점#

최근 React 환경에서 JSX만 사용하는 줄 알고 import React from 'react';가 필요 없을 것이라고 생각했습니다. 하지만 코드를 실행했을 때 발생하는 오류 메시지를 이해하지 못해 어려움을 겪었습니다. 실습을 통해 현재 환경에서는 해당 import가 필수적이라는 것을 알게 되었습니다.

정리된 이해#

현재 React 환경에서는 JSX 문법을 사용하기 위해 import React from 'react';를 반드시 추가해야 하며, 이는 ESLint 규칙과 JSX 문법 요구사항 때문입니다. 파일이나 패키지를 불러오는 방식은 비슷하지만, React 라이브러리 자체를 불러오는 것이 JSX 사용에 필수적임을 이번 실습을 통해 알게 되었습니다.

import React from 'react';  // 필수로 추가
import './App.css';          // CSS 파일 import
import Axios from 'axios';  // 외부 패키지 import

function App() {
  return (
    <div className="App">
      <div>안녕하세요.</div>
    </div>
  );
}

export default App;
