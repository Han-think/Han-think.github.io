1. pip 패키지 설치#

왜 이걸 보게 됐나#

프로젝트를 진행하면서 필요한 라이브러리를 설치하고 관리해야 했는데, 단순히 pip install만으로는 제대로 관리하기 어려웠다. 다른 개발자와 협업하거나 프로젝트를 배포할 때 환경 일관성을 유지하기 위해서는 패키지 의존성을 명확하게 기록하고 관리하는 것이 필수적이라는 것을 깨달았다. 그래서 pip 명령어를 보다 정확하게 이해하고 requirements.txt 파일을 활용하여 환경을 재현하는 방법을 익히게 되었다.

내가 헷갈린 지점#

처음에 pip 명령어를 봤을 때, 단순히 패키지를 설치하는 것 외에 버전 관리나 환경 관리를 어떻게 할 수 있을지 막막했다. 특히 pip freeze 명령어가 왜 필요한지, requirements.txt 파일과 어떻게 연관되는지 정확히 이해하지 못했다. 패키지 설치 명령어들의 차이점을 명확히 파악하지 못해, 어떤 명령어를 써야 원하는 결과를 얻을 수 있을지 혼동되기도 했다.

시도한 코드 / 예시#

pip install pandas

결과와 해석#

pip install pandas 명령어를 실행했을 때, pandas 패키지의 최신 버전이 설치되면서 터미널에 설치 진행 상황이 출력되었다. pip list 명령어를 통해 확인했을 때, pandas가 설치된 것을 확인할 수 있었고, pip freeze > requirements.txt 명령어를 통해 현재 환경의 패키지 목록을 파일로 저장할 수 있었다. 이 파일을 다른 환경에서 pip install -r requirements.txt 명령어로 사용하면 동일한 패키지들을 설치할 수 있다는 것을 알게 되었다.

정리된 이해#

pip install 명령어를 사용하면 원하는 패키지를 쉽게 설치하거나 특정 버전을 지정해서 설치할 수 있어 편리하다. pip freeze 명령어를 활용하면 현재 환경에 설치된 패키지 목록을 파일로 저장하여, 다른 환경에서도 동일한 환경을 구축할 수 있다. requirements.txt 파일과 함께 사용하면 프로젝트에 필요한 모든 패키지를 일괄적으로 관리하고 설치할 수 있다.

2. requirements 파일#

왜 이걸 보게 됐나#

프로젝트를 진행할 때, 다른 환경에서도 똑같은 패키지 버전을 사용해야 원활하게 작동하는 경우가 많아서 requirements 파일을 배우게 됐어. 혼자 개발하는 것도 있지만, 팀 프로젝트에서는 특히 필수적이고, 내가 만든 환경을 다른 사람에게 쉽게 공유하거나, 나중에 다시 프로젝트를 열 때 처음처럼 환경을 구축할 수 있도록 도와주니까. 이 파일을 사용하면 프로젝트의 의존성을 명확하게 관리할 수 있어.

내가 헷갈린 지점#

처음에는 requirements.txt 파일이 단순히 설치할 패키지 이름들의 목록인 줄 알았어. 그런데 왜 pip freeze 명령어를 통해 현재 환경의 패키지 목록을 만들어야 하는지, 그리고 그 파일이 어떤 의미를 가지는지 이해하는 데 시간이 걸렸어. 또, pip install -r requirements.txt 명령어가 어떻게 현재 환경을 복원하는 역할을 하는지 명확하게 파악하지 못했어.

시도한 코드 / 예시#

pip freeze > requirements.txt

결과와 해석#

requirements.txt 파일을 만들어서 프로젝트에 필요한 패키지와 버전을 기록해두면, 다른 환경에서도 동일한 환경을 쉽게 재현할 수 있어 편리하다. 예를 들어, pip freeze > requirements.txt 명령어를 통해 현재 환경의 패키지 목록을 파일로 저장하고, pip install -r requirements.txt 명령어를 통해 해당 패키지들을 한 번에 설치할 수 있다. 이를 통해 팀원들과 환경 설정을 공유하거나, 나중에 프로젝트를 다시 실행할 때 일관성을 유지할 수 있다.

정리된 이해#

requirements 파일은 현재 프로젝트에 필요한 패키지 목록을 담고 있는 텍스트 파일이라고 이해했다. 이 파일을 사용하면 다른 환경에서도 동일한 패키지를 쉽게 설치하여 프로젝트를 실행할 수 있고, 프로젝트의 의존성을 관리하는 데 도움이 된다.

3. 패키지 버전 관리#

왜 이걸 보게 됐나#

프로젝트를 진행하면서 팀원 간 환경 차이로 인한 오류가 자주 발생해서, 일관된 패키지 버전을 유지하는 것이 얼마나 중요한지 깨달았어. 그래서 프로젝트를 재현하거나 공유할 때 발생하는 문제를 해결하기 위해 패키지 버전을 관리하는 방법을 배우게 되었어. 궁극적으로는 프로젝트의 안정성과 협업 효율성을 높이기 위해서야.

내가 헷갈린 지점#

처음에는 특정 버전의 패키지를 설치하는 것과 최신 버전을 설치하는 것의 차이를 명확히 이해하지 못해서, 왜 == 기호를 사용하는지 궁금했다. 또한 pip freeze 명령어가 단순히 설치된 패키지 목록을 보여주는 것인지, 아니면 좀 더 복잡한 역할을 하는지 헷갈렸었다. 패키지 버전을 고정하는 것이 왜 중요한지, 그리고 requirements.txt 파일이 프로젝트의 환경을 어떻게 관리하는지에 대한 그림이 부족했다.

시도한 코드 / 예시#

# 패키지 버전 관리 예시: 특정 버전 설치
pip install pandas==1.5.3

결과와 해석#

pip install pandas==1.5.3 명령어를 실행하니, 기존에 설치되어 있던 pandas 버전이 1.5.3으로 덮어씌워지는 것을 확인했다. 이를 통해 특정 버전의 패키지를 명시적으로 관리하여, 프로젝트의 호환성을 유지하고 예상치 못한 오류를 방지할 수 있다는 것을 알게 되었다. 요약하면, == 연산자를 사용하여 버전 고정은 프로젝트의 안정적인 실행에 필수적인 작업이다.

정리된 이해#

패키지 버전 관리는 프로젝트가 특정 버전의 라이브러리에 의존하도록 보장하여, 다른 환경에서도 일관된 실행을 가능하게 해주는 중요한 작업이야. requirements.txt 파일은 프로젝트에 필요한 패키지와 버전 정보를 기록하며, 이를 통해 다른 사람이 쉽게 동일한 개발 환경을 구축할 수 있어. 패키지 버전을 고정하는 것은 프로젝트의 안정성을 유지하는 데 도움이 돼.

4. 환경 내보내기#

왜 이걸 보게 됐나#

프로젝트를 진행하거나 다른 사람에게 내 환경을 공유할 때, 어떤 패키지를 설치했는지 정확히 전달해야 했기 때문에 환경 내보내기를 배우게 되었다. 단순히 패키지 이름만 알려줘도 버전까지 맞춰서 설치하기 어렵다는 것을 깨달았고, 이를 해결하기 위해 pip freeze 명령어를 사용하게 되었다. 결국, 재현 가능한 환경을 구축하는 데 필수적인 기술이라는 것을 알게 되었다.

내가 헷갈린 지점#

처음에는 pip freeze 명령어가 단순히 설치된 패키지 목록을 보여주는 명령어라고 생각했었어. 그런데 > 기호를 통해 그 목록을 파일로 저장할 수 있다는 점이 신기했고, 그 파일로 다른 환경에서 동일한 패키지를 설치할 수 있다는 개념이 조금 어렵게 느껴졌어. 결국 이걸 통해 환경을 일관되게 유지할 수 있다는 것을 알게 됐어.

시도한 코드 / 예시#

pip freeze > current_env.txt

결과와 해석#

pip freeze > current_env.txt 명령어를 실행하니, 현재 내가 사용하고 있는 파이썬 환경에 설치된 모든 패키지와 버전을 current_env.txt라는 파일에 기록하게 됐어. 이 파일은 다른 환경에서도 동일한 패키지 버전을 설치해야 할 때 매우 유용하게 사용할 수 있을 것 같아. 마치 레시피처럼, 내 환경 설정을 그대로 옮겨갈 수 있게 해주는 거지.

정리된 이해#

현재 파이썬 환경에 설치된 패키지 목록과 버전을 requirements.txt 파일 같은 텍스트 파일로 저장하여, 다른 환경에서도 동일한 패키지 버전을 쉽게 설치할 수 있도록 만드는 과정이야. 마치 레시피처럼, 프로젝트에 필요한 패키지들을 기록해두는 거라고 생각하면 돼.

총평#

오늘 전체에서 배운 것#

pip 명령어를 이용해서 패키지를 설치, 업그레이드, 제거하고, requirements.txt 파일을 통해 여러 패키지를 한 번에 관리할 수 있다는 것을 알게 되었다. pip freeze 명령어를 사용해서 현재 환경을 파일로 내보낼 수 있다는 것도 중요한 내용이었다.

다음에 조심할 것#

패키지 버전을 고정해서 설치할 때는 정확한 버전 번호를 확인해야 오류를 줄일 수 있겠다. requirements.txt 파일 관리를 철저히 해서 프로젝트 이동 시나리오에서 환경 일치를 유지해야겠다.

다음 복습 주제#

requirements.txt 파일을 직접 만들어서 설치해보는 연습을 더 해보고 싶다. 가상 환경을 사용해서 pip를 관리하는 방법도 알아봐야겠다.
