1. JavaScript 반복 방식 비교: for, forEach, for…of#

무엇을 배웠나#

for, forEach, for...of 반복 방식의 차이점을 명확하게 이해하게 되었어. for는 세밀한 제어가 가능하고, forEach는 break로 중단할 수 없으며, for...of는 값 중심으로 순회한다는 점을 기억해야겠다. 이제 상황에 맞는 적절한 반복 방식을 선택하여 코드를 작성할 수 있을 것 같아.

헷갈렸던 점#

어떤 반복 방식을 선택해야 할지 몰라서 여러 가지 방법을 다 써보게 되는데, 왜 이렇게 다양하게 존재하는지 이해하기 어려웠어. forEach랑 for...of의 차이점, 특히 forEach가 break를 사용할 수 없다는 점이 직관적이지 않았고, 인덱스 접근이 필요한 경우 for...of를 어떻게 활용해야 할지 막막했어. forEach가 문자열에 바로 적용되지 않는다는 제한 조건도 처음에는 헷갈렸어.

정리된 이해#

for 반복문은 인덱스 접근과 세밀한 제어가 가능한 반면, forEach()는 모든 요소를 처리하며 중간 중단이 어렵고, for...of는 값 중심 순회를 하며 break를 사용할 수 있다는 차이가 있다. 상황에 따라 적절한 반복 방식을 선택하는 것이 중요하며, 특히 break가 필요한 경우 for 또는 for...of를 사용해야 한다. forEach()는 배열의 모든 요소를 처리해야 할 때 유용하며, for...of는 값만 순회하며 break로 제어해야 할 때 적합하다.

let arr = [10, 20, 30, 40];
for (let i = 0; i < arr.length; i++) {
    if (arr[i] == 30) {
        console.log("30을 찾았습니다:", i);
        break;
    }
}

let arr = [1, 2, 3];
arr.forEach((item) => {
    console.log(item * 2); // 각 요소를 2배로 출력
});

2. while, do…while 반복문과 break 이해하기#

무엇을 배웠나#

while 반복문은 조건이 참일 때 반복하고, do…while은 최소 한 번은 실행한다는 점을 확실히 이해하게 되었어. break 구문은 반복문을 즉시 종료하고 다음 코드를 실행한다는 것도 명확해졌고, 무한 루프의 위험성과 break를 이용한 종료 조건 설정의 중요성을 알게 되었어. do…while 문은 꼭 필요한 상황에서만 사용하는구나.

헷갈렸던 점#

처음에는 while 루프의 while (true) 같은 무한 루프가 어떻게 끝나는지, 그리고 언제 종료되는지 감이 잘 안 잡혔어. break 문을 사용해도 실행 흐름이 어떻게 되는지, 반복문 밖의 코드가 실행될지 계속 의문이었어. do...while 루프는 일반 while 루프랑 뭐가 다르고, 언제 사용하는 건가 싶었어.

정리된 이해#

while 반복문은 조건을 먼저 확인하고, do...while 반복문은 코드를 먼저 실행한 뒤 조건을 확인한다는 차이가 있어, 필요한 상황에 맞춰 선택해야 해. break 문은 현재 반복문을 즉시 종료하고 다음 코드를 실행하므로, 무한 루프를 제어하거나 특정 조건을 만족할 때 반복을 멈추는 데 유용해. 최소 한 번은 실행해야 하는 경우나, 조건 확인 전에 코드가 반드시 필요할 때 do...while이 적합해.

var cnt = 1;
while (cnt <= 10) {  // 조건 검사
    console.log(`${cnt}회 사용`);
    cnt++;            // 값 변경 후 다시 조건 검사
}

var cnt = 11;
do {
    console.log(`do while : ${cnt}회 사용`);  // 본문 실행
    cnt++;
} while (cnt <= 10);  // 조건 검사

while (true) {
    break;  // 반복 종료
}
console.log('도달 가능');  // 반복문 이후 코드 실행 가능

3. 문자열 문제 해결: 초보자를 위한 여정#

무엇을 배웠나#

문자열 문제 해결 과정에서 반복문과 변수 활용, replace() 함수의 전역 검색 기능, 그리고 실습 환경과 채점 코드의 차이에 대한 이해가 부족했던 점을 파악했습니다. 이를 바탕으로 문제 분석, 변수 초기화, 그리고 각 환경에 맞는 코드 작성의 중요성을 깨달았습니다. 앞으로는 좀 더 체계적인 접근 방식을 통해 문자열 조작 문제를 해결해 나가겠습니다.

헷갈렸던 점#

처음에는 반복문과 변수를 조합해서 문자열을 원하는 대로 바꾸는 코드를 짜는 게 너무 어려웠어. replace() 함수가 어떻게 동작하는지, 특히 전체 공백을 제거하는 방법을 이해하는 데 시간이 꽤 걸렸고, 실습 환경과 채점 코드가 달라서 당황스러웠던 기억이 있어.

정리된 이해#

문자열 문제 해결의 핵심은 반복문과 변수를 활용하여 원하는 방식으로 문자들을 이어붙이거나 수정하는 것이고, replace() 함수를 사용할 때는 전역 검색을 위한 옵션을 반드시 확인해야 합니다. 실습 환경과 채점 코드의 차이를 이해하고, 결과 변수를 초기화하는 시점을 정확하게 결정하는 것이 중요합니다.

// 예시: 공백 제거 (replace() 사용)
function removeAllSpaces(str) {
  return str.replace(/\s/g, '');
}

4. 브라우저와 Node 실행 환경, 이해와 활용법#

무엇을 배웠나#

브라우저와 Node.js 실행 환경의 차이점을 명확히 이해하게 되었다. 브라우저에서는 직접 함수를 호출하고 console.log()를 통해 결과를 확인하는 반면, 엘리스 채점 시스템과 같은 Node.js 환경에서는 module.exports를 사용하여 함수와 입력값을 전달해야 한다. 특히 module.exports는 채점기에 필요한 정보 전달을 위한 설정이라는 점을 깨달았다.

헷갈렸던 점#

브라우저 콘솔에서 함수를 실행하는 것과 엘리스 채점 시스템에서 함수를 실행하는 방식이 달라서, 어떤 코드를 어떻게 실행해야 하는지 헷갈렸다. 특히 module.exports의 역할이 무엇인지 명확하게 이해하지 못해서, 코드 통합 과정에서 어려움을 겪었다. 브라우저 환경에서 실행하는 것과 Node 환경에서 실행하는 것의 차이를 명확히 구분해야 했다.

정리된 이해#

브라우저 환경에서는 console.log()를 사용하여 직접 함수를 실행하고 결과를 확인할 수 있으며, 엘리스/Node 환경에서는 module.exports를 통해 함수와 입력 데이터를 채점 시스템에 전달해야 합니다. 핵심은 두 환경의 실행 방식과 데이터 전달 방식이 다르다는 점을 이해하고, 각 환경에 맞는 코드를 작성해야 한다는 것입니다.

module.exports = {
    inputs: ["hello world"],
    func: removeBlank
};

5. 배열 필터링과 동적 객체 키 활용법 익히기#

무엇을 배웠나#

배열 필터링 시 원본 배열을 변경하지 않고 새로운 배열을 만들어 결과를 반환하는 것이 안전하다는 것을 알게 되었다. 또한, 객체의 키를 동적으로 생성하여 접근하는 대괄호 표기법을 이해했고, 특정 조건에서 반복문을 종료하는 방법을 익혔다. 이 과정을 통해 초보자도 배열 필터링과 동적 객체 키 접근을 쉽게 할 수 있다는 자신감을 얻었다.

헷갈렸던 점#

배열 필터링을 할 때, 기존 배열을 변경해야 할지 새로운 배열을 만들어야 할지 몰랐다. 동적 객체 키를 사용할 때는 속성 이름이 문자열로 표현되어야 한다는 점이 낯설었다. 반복문에서 특정 조건이 충족되면 종료해야 하는데, 어떻게 조건을 설정하고 break 문을 사용하는지 명확하지 않았다.

정리된 이해#

배열 필터링은 원본 배열을 수정하는 대신 새로운 배열을 생성하여 값을 추출하는 것이 안전하고 예측 가능한 코드를 만드는 데 도움이 된다. 동적 객체 키를 활용하면 객체의 속성 이름을 런타임에 결정할 수 있어서 유연한 데이터 처리가 가능하다. 반복문에서는 특정 조건이 충족될 때 break 문을 사용하여 불필요한 반복을 피하는 것이 효율적이다.

function getOnlyOddNumbers(arr) {
    let result = [];
    for (const num of arr) {
        if (num % 2 !== 0) {
            result.push(num);
        }
    }
    return result;
}
