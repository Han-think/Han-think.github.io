1. 배열과 객체 순회 및 조건 필터링 학습 노트#

무엇을 배웠나#

배열과 객체를 순회할 때 for...of와 일반 for 문의 차이를 명확히 이해하게 되었고, 함수 내에서 결과를 얻기 위해서는 반드시 return 문을 사용해야 한다는 것을 깨달았습니다. 또한, join() 함수는 배열 요소를 문자열로 연결하는 기능이며, 숫자 배열을 직접 숫자로 변환하는 것이 아니라는 점을 알게 되었습니다. 이 학습을 통해 배열과 객체 순회 및 조건 필터링에 대한 이해도가 높아졌습니다.

헷갈렸던 점#

배열의 각 요소를 직접 접근하는 for...of 방식과 인덱스를 사용하는 일반 for 방식의 차이를 명확히 이해하지 못해서 객체 접근 방식이 다를 거라고 생각했습니다. 함수 내에서 생성한 배열을 외부로 반환하지 않으면 결과가 보이지 않는다는 점을 간과했습니다. join() 함수가 배열의 숫자 요소를 문자열로 변환하는 게 아니라 연결하는 기능이라는 것을 잘못 알고 있었습니다.

정리된 이해#

배열의 요소에 접근할 때 for...of는 각 요소를 직접 가져오고, 일반 for는 인덱스를 통해 접근하는 방식 차이를 명확히 이해하게 되었습니다. 함수에서 결과를 얻기 위해서는 반드시 return 구문을 사용해야 하며, join("")는 배열 요소들을 문자열로 연결하는 기능이라는 것을 알게 되었습니다. 이 내용을 바탕으로 코드를 더 효율적이고 정확하게 작성할 수 있을 것 같습니다.

// for...of 방식
function getAdults(arr) {
    let adults = [];
    for (let person of arr) {
        if (person.age >= 20) {
            adults.push(person.name);
        }
    }
    return adults;
}

// 일반 for 방식
function getAdultsAlt(arr) {
    let adults = [];
    for (let i = 0; i < arr.length; i++) {
        if (arr[i].age >= 20) {
            adults.push(arr[i].name);
        }
    }
    return adults;
}

2. 중첩 반복문으로 소수 찾기, 변수 역할 및 break 이해#

무엇을 배웠나#

중첩 반복문을 사용하여 소수를 찾고 합계를 구하는 과정에서 변수 역할, 불리언 변수 초기화의 필요성, 그리고 break 문의 역할에 대한 이해가 부족했습니다. 하지만 이 노트를 통해 i와 j의 역할을 명확히 이해하고, 각 숫자를 검사할 때마다 isPrime을 초기화해야 하는 이유와 break를 사용하여 효율성을 높이는 방법을 알게 되었습니다. 이제 중첩 반복문을 활용한 알고리즘을 더욱 효과적으로 작성할 수 있게 되었습니다.

헷갈렸던 점#

처음에는 중첩 반복문 안에서 i와 j가 각각 어떤 역할을 하는지, 특히 j가 어떤 숫자를 나누는지 명확히 이해하지 못했습니다. 또한, 각 숫자에 대해 isPrime을 true로 초기화하는 이유가 잘 와닿지 않았고, break를 사용하는 조건이 왜 약수를 발견했는지에 한해야 하는지 확신이 없었습니다.

정리된 이해#

중첩 반복문을 이용해 소수를 찾고 합계를 구할 때, 바깥쪽 반복문은 검사할 숫자를, 안쪽 반복문은 나누어 보는 약수를 담당합니다. 각 숫자를 소수라고 가정하고 검사 시작하며, 약수가 발견되면 break를 통해 불필요한 반복을 줄여 효율성을 높입니다.

let sum = 0;

for (let i = 2; i <= 200; i++) {
    let isPrime = true;

    for (let j = 2; j < i; j++) {
        if (i % j === 0) {
            isPrime = false;
            break;
        }
    }

    if (isPrime) {
        sum += i;
    }
}

3. HTML 문서, DOM 트리, 그리고 자바스크립트#

무엇을 배웠나#

자바스크립트를 사용해 HTML 요소를 다루기 전에 DOM이 어떻게 HTML 코드를 객체 트리로 변환하는지 이해하는 것이 중요하다는 것을 알게 되었다. 브라우저가 HTML을 해석하여 DOM 트리를 만들고, document 객체를 통해 이 트리의 모든 노드에 접근하고 조작할 수 있다는 것도 명확해졌다. 이제 HTML 요소들이 객체로 표현되는 과정과 document 객체의 역할을 확실히 이해하게 되어, DOM 워킹을 진행하는 데 도움이 될 것이다.

헷갈렸던 점#

처음에는 HTML 태그들이 단순히 화면에 보여주는 역할을 한다고 생각했는데, DOM을 배우면서 각 태그가 자바스크립트에서 객체로 다뤄질 수 있다는 점이 생소했습니다. 특히 document 객체가 웹 페이지 전체를 나타낸다는 개념이 추상적으로 느껴져서 어떻게 활용해야 할지 감이 잘 잡히지 않았습니다. 또한, node라는 용어가 계속 등장하면서 기존에 알고 있던 HTML 요소와 어떻게 연결되는지 명확하게 이해하기 어려웠습니다.

정리된 이해#

브라우저는 HTML 코드를 해석하여 웹 페이지의 구조를 객체 기반 트리 구조인 DOM으로 변환합니다. 이 DOM 트리의 최상위 노드 객체는 document이며, 이를 통해 웹 페이지의 모든 요소에 접근하고 수정할 수 있습니다. HTML 요소는 DOM에서 노드(Node)라는 객체로 표현되며, 각 노드는 웹 페이지의 일부분을 나타냅니다.

 const titleNode = document.querySelector('title');
 titleNode.textContent = '새로 바뀐 제목';

4. DOM 요소 선택 방법 및 반환값 구분#

무엇을 배웠나#

DOM 요소 선택 메서드들의 이름이 비슷해서 혼동되었지만, 각 메서드가 단수 또는 복수 요소를 반환하는지, 그리고 반환되는 데이터 타입이 무엇인지 명확히 이해하게 되었습니다. 특히 getElementsByTagName과 getElementsByClassName처럼 복수 요소를 반환하는 경우 배열 형태로 반환된다는 점을 기억해야 합니다. querySelector와 querySelectorAll의 차이점도 파악하여 상황에 맞는 적절한 선택자를 사용할 수 있게 되었습니다.

헷갈렸던 점#

DOM 요소 선택 메서드 이름들이 비슷해서 어떤 메서드를 써야 할지 헷갈렸고, 어떤 메서드는 하나의 요소만, 어떤 메서드는 여러 요소를 반환하는지 파악하는 데 어려움이 있었습니다. 특히, 여러 요소를 반환하는 메서드의 결과에 어떻게 접근해야 할지 처음에는 막막했습니다.

정리된 이해#

DOM 요소 선택 메서드는 id, 태그 이름, 클래스 이름으로 요소를 찾는 전용 메서드와 CSS 선택자를 사용하는 메서드로 나눌 수 있습니다. 전용 메서드는 id를 기준으로 하나를 반환하거나, 태그나 클래스 이름을 기준으로 여러 요소를 배열로 반환하는 반면, querySelector는 CSS 선택자에 따라 첫 번째 매칭 요소를, querySelectorAll은 모든 매칭 요소를 NodeList 형태로 반환합니다. 여러 요소를 선택하는 경우, 배열이나 NodeList의 인덱스를 사용하여 특정 요소를 접근할 수 있습니다.

// getElementById 예시
const myElement = document.getElementById('myId');

// getElementsByTagName 예시
const allParagraphs = document.getElementsByTagName('p');

// getElementsByClassName 예시
const elementsWithClass = document.getElementsByClassName('myClass');

// querySelector 예시
const firstElement = document.querySelector('.myClass');

// querySelectorAll 예시
const allElements = document.querySelectorAll('.myClass');

5. DOM 조작 및 요소 추가 실습 가이드#

무엇을 배웠나#

DOM 요소의 내용, 스타일, 속성을 변경하는 방법과 새로운 요소를 생성하여 DOM에 추가하는 방법을 익혔습니다. innerHTML, style, setAttribute()의 차이점을 이해하고, createElement()로 만든 요소가 화면에 바로 반영되지 않는 이유를 알게 되었습니다. 특히 getElementsByTagName 결과 배열에서 특정 요소를 가져오는 인덱스 사용법도 명확해졌습니다.

헷갈렸던 점#

innerHTML이랑 style을 어떻게 구분해서 써야 할지 몰라서 계속 엉뚱한 값을 넣고 있었고, createElement로 만들었는데 왜 화면에 바로 안 보이는지 궁금했어. 그리고 getElementsByTagName에서 [0]을 쓰는 이유가 정확히 기억이 안 났어.

정리된 이해#

요소의 내용 변경은 innerHTML이나 innerText를 사용하고, 스타일 변경은 element.style을 통해, 속성 변경은 setAttribute()를 활용하는 것을 명확히 이해하게 되었다. createElement()로 만든 요소는 appendChild()를 통해 DOM에 추가해야 화면에 나타나고, getElementsByTagName()으로 선택한 요소는 배열이므로 인덱스를 사용하여 특정 요소를 선택해야 함을 알게 되었다. 이제 이러한 방법들을 활용하여 동적으로 웹 페이지의 내용을 수정하고 새로운 요소를 추가할 수 있을 것 같다.

var paragraph = document.getElementById('p1');
paragraph.innerHTML = '이제 새로운 텍스트입니다';

var img = document.querySelector('img');
img.setAttribute('src', '새이미지.jpg');

var newInput = document.createElement('input');

총평#

오늘 오전 전체에서 배운 것#

배열과 객체 순회, 중첩 반복문, HTML과 DOM 구조, 그리고 DOM 조작 방법까지 광범위하게 학습했습니다. 특히 DOM 트리를 이해하고, 요소 선택 메서드들의 차이점을 파악하여 상황에 맞는 선택을 할 수 있게 되었으며, DOM 조작 실습을 통해 실제 HTML 요소를 제어하는 감각을 익혔습니다. 전반적으로 웹 개발의 기초를 다지는 데 중요한 내용을 배운 하루였습니다.

다음에 조심할 것#

중첩 반복문을 사용할 때는 변수 초기화와 break 문의 역할이 중요하니, 소수 찾기 문제처럼 복잡한 알고리즘을 풀 때 다시 한번 주의해야겠다. DOM 조작 시에는 반환값의 형태를 확실히 구분하고, 생성된 요소가 화면에 바로 표시되지 않는 이유를 잊지 않도록 해야겠다.

다음 복습 주제#

중첩 반복문을 활용한 알고리즘 구현 시 변수 역할과 break 문의 활용법을 좀 더 복습해서 효율적인 코드를 작성할 수 있도록 연습해야겠다. DOM 조작 시 innerHTML, style, setAttribute()의 사용법을 다양한 예제를 통해 숙달하고, 실제 웹 페이지에 적용해보면서 감을 익혀야겠다.
