1. COUNT 함수#

왜 이걸 보게 됐나#

데이터 분석 프로젝트를 진행하면서 데이터의 개수를 정확하게 파악하는 것이 중요해졌고, 특히 특정 조건에 맞는 데이터의 개수를 세는 과정에서 COUNT 함수의 다양한 활용법에 대한 이해가 필요해졌어. COUNT(id)와 COUNT(*)의 차이점을 알아야 데이터의 정확성을 확보할 수 있고, 조건부 개수를 세는 HAVING절을 활용하기 위해서도 기본 개념이 필요했어. 이러한 문제들을 해결하기 위해 COUNT 함수에 대해 더 깊이 공부하게 되었어.

내가 헷갈린 지점#

COUNT 함수를 사용할 때, COUNT() 와 COUNT(id) 의 차이를 명확히 이해하지 못해서 특정 컬럼이 NULL 값인 경우 결과가 어떻게 달라지는지 헷갈렸어요. 모든 컬럼에 값이 있다고 생각하고 무심결에 COUNT() 만 사용했던 기억이 납니다. COUNT(id)는 NULL 값을 제외하고 세는 것이라는 것을 알고 나서 데이터 분석 시 좀 더 정확한 결과를 얻을 수 있게 되었죠.

시도한 코드 / 예시#

-- COUNT 함수 예시: id 컬럼이 NULL인 행을 제외하고 세는 경우
-- user 테이블에 id 컬럼이 NULL인 행이 2개 있고, 전체 행이 5개라면 결과는 3이 된다.
SELECT COUNT(id) FROM user;

결과와 해석#

COUNT(id)는 id 컬럼이 null이 아닌 행의 개수를 세는 반면, COUNT(*)는 전체 행의 개수를 세기 때문에 id 컬럼에 null 값이 존재하면 결과가 달라진다. 예를 들어, 테이블에 100개의 행이 있고, id 컬럼에 null 값이 5개 있다면 COUNT(id)는 95를 반환하지만 COUNT(*)는 100을 반환한다. 데이터의 정확성을 위해 null 값을 고려해야 할 때 COUNT(id)를 사용하는 것이 좋다.

정리된 이해#

COUNT(id)는 id 컬럼이 NULL이 아닌 행만 세는 반면, COUNT(*)는 테이블의 모든 행을 센다. 따라서 id 컬럼에 NULL 값이 있을 수 있는 경우, COUNT(id)는 실제 데이터 개수를 더 정확하게 반영할 수 있다. 두 함수는 데이터의 특성에 따라 적절히 사용해야 한다.

2. LIMIT 절#

왜 이걸 보게 됐나#

데이터를 쿼리할 때 전체 결과가 너무 많아서 일부만 보고 싶을 때가 있었어. 그래서 특정 개수만큼만 결과를 가져오거나, 특정 위치부터 데이터를 확인하는 방법을 배우게 됐지. 마침 딱 필요한 순간에 필요한 기능이라는 걸 깨달았어.

내가 헷갈린 지점#

LIMIT절에서 offset이 0부터 시작한다는 게 헷갈라서, 1을 넣으면 두 번째 행부터 데이터를 가져올 거라고 생각했었어. 그래서 offset을 제대로 활용하지 못하고, 원하는 데이터를 가져오는데 어려움을 겪었지. 처음에는 offset이 페이지네이션과 어떻게 연관되는지 이해하는 데 시간이 좀 걸렸어.

시도한 코드 / 예시#

-- LIMIT 절 예시: 1번째 행부터 5개의 행을 가져옵니다.
-- offset은 1이고, count는 5입니다.
SELECT *
FROM your_table
LIMIT 1, 5;

결과와 해석#

LIMIT 1, 5 쿼리를 실행했을 때, 데이터셋에서 두 번째 행부터 시작해서 총 5개의 행을 가져왔다. 즉, offset이 1이므로 첫 번째 행은 제외되고, 그 다음 5개의 행이 결과로 나타났다. 이 기능을 활용하면 특정 페이지의 데이터를 가져오거나, 결과의 일부만 빠르게 확인하는 데 유용하다.

정리된 이해#

LIMIT 절은 결과를 제한하는 역할을 하는데, LIMIT offset, count 형태로 사용될 때 offset은 결과 집합의 시작 위치를 나타내며, 0부터 시작한다는 점을 기억해야 한다. 즉, LIMIT 1, 5는 두 번째 행부터 다섯 개의 행을 보여주는 것과 동일하다. 이 기능을 활용하여 원하는 특정 범위의 데이터를 추출할 수 있다.

3. HAVING 절#

왜 이걸 보게 됐나#

GROUP BY 절을 사용해서 데이터를 묶어 분석하다 보면, 묶인 그룹별로 특정 조건을 만족하는 것만 보여주고 싶을 때가 있다. 이때 WHERE 절은 그룹을 묶기 전에 적용되어서 원하는 결과를 얻기 어려워서 HAVING 절을 사용하게 되었다. HAVING 절은 GROUP BY 절과 함께 사용되어 묶인 데이터에 대한 필터링을 더 효과적으로 할 수 있도록 해준다.

내가 헷갈린 지점#

처음에는 HAVING절이 WHERE절과 거의 같은 역할을 하는 것처럼 생각해서, 그룹화된 결과에 조건을 걸 때 어디에 조건을 줘야 하는지 헷갈렸었어. 그룹화가 먼저 이루어진 후에 조건을 적용한다는 점을 이해하는 데 시간이 좀 걸렸고, 정확히 어떤 상황에서 HAVING을 사용해야 하는지 파악하는 데 어려움이 있었어.

시도한 코드 / 예시#

-- HAVING 절 예시: 10개 이상 대여한 사용자 검색
SELECT user_id, COUNT(*) AS rental_count
FROM rentals
GROUP BY user_id
HAVING COUNT(*) >= 10;
-- 실행 결과 예시:
-- | user_id | rental_count |
-- |---------|-------------|
-- | 123     | 15          |
-- | 456     | 12          |

결과와 해석#

HAVING 절은 GROUP BY로 묶인 그룹에 조건을 적용할 때 사용하는데, 예를 들어 SELECT department, AVG(salary) FROM employees GROUP BY department HAVING AVG(salary) > 50000는 평균 연봉이 50000 이상인 부서를 선택하는 쿼리가 된다. WHERE 절은 개별 행에 대한 필터링을 하는 반면, HAVING은 그룹화된 결과에 대한 필터링을 수행한다는 차이가 명확하다. 이렇게 그룹화된 결과에 조건을 걸어 원하는 데이터만 추출할 수 있어 유용하다.

정리된 이해#

GROUP BY로 묶인 데이터에 필터링 조건을 적용할 때는 WHERE 대신 HAVING을 사용해야 한다는 걸 알게 되었어. WHERE는 테이블 전체에서 필터링하고, HAVING은 이미 묶인 그룹에 대해서만 필터링한다는 점이 중요해. 이제 그룹화된 데이터에 조건을 적용할 때 HAVING을 활용할 수 있겠어.

4. JOIN 조건#

왜 이걸 보게 됐나#

데이터를 분석하려면 여러 테이블에 흩어져 있는 정보를 합쳐서 봐야 했는데, 단순히 테이블을 나열하는 것만으로는 원하는 결과를 얻을 수 없었어. 그래서 테이블 간의 관계를 정확하게 연결하는 JOIN 구문을 이해하고 활용하는 방법이 중요해졌어. JOIN 조건에 대한 정확한 이해는 효율적인 데이터 추출과 분석에 필수적이라는 것을 깨달았어.

내가 헷갈린 지점#

JOIN을 사용할 때 어떤 컬럼을 기준으로 연결해야 하는지, 그리고 그 기준이 어떻게 작동하는지 잘 이해하지 못해서 여러 번 조건을 바꿔가며 테스트했던 기억이 난다. 특히 테이블 간의 관계가 명확하지 않을 때는 어떤 컬럼을 ON 조건으로 지정해야 하는지 파악하는 데 시간이 오래 걸렸다. 처음에는 단순히 테이블의 모든 컬럼을 비교해 보려고 했던 것도 실수였다.

시도한 코드 / 예시#

-- user 테이블의 id 와 rental 테이블의 user_id 를 연결하는 예시
-- ON 조건은 실제 연결 기준이 된다.
SELECT *
FROM user
INNER JOIN rental ON user.id = rental.user_id;

결과와 해석#

두 테이블을 ON 조건으로 연결할 때, ON 조건은 실제로 어떤 컬럼들을 기준으로 데이터를 연결하는지 명시하는 부분이야. 예를 들어 orders 테이블과 customers 테이블을 customer_id를 기준으로 연결하면, 같은 customer_id를 가진 행들끼리 묶여서 결과가 보여. 이렇게 연결 조건을 제대로 설정해야 원하는 데이터를 효과적으로 가져올 수 있어.

정리된 이해#

JOIN 쿼리에서 ON 절은 두 테이블을 연결할 핵심 기준을 명시하는 부분이야. 특정 컬럼들이 일치하는 행들끼리 연결되어 결과 집합을 형성하는 거지. 예를 들어, 사용자 테이블과 대여 테이블을 연결할 때 ON 절에서 두 테이블의 연결 고리가 되는 사용자 ID 컬럼을 지정하는 방식으로 작동해.

총평#

오늘 전체에서 배운 것#

COUNT 함수에서 NULL 값 처리 차이, LIMIT 절의 offset이 0부터 시작한다는 점, GROUP BY 후 HAVING 절을 사용해야 한다는 것, 그리고 JOIN 조건이 테이블 연결의 기준이 된다는 것을 확실히 이해하게 되었어. 특히 JOIN 조건과 HAVING 절 사용법이 이전에는 헷갈렸는데, 오늘 학습을 통해 명확해졌어.

다음에 조심할 것#

COUNT 함수 사용 시 NULL 값 처리가 중요하고, LIMIT 절의 offset은 0부터 시작한다는 것을 명심해야겠다. GROUP BY와 HAVING 사용 시 조건을 적용하는 시점을 혼동하지 않도록 주의해야 할 것 같다.

다음 복습 주제#

LEFT JOIN과 RIGHT JOIN을 좀 더 다양한 예제를 통해 확실하게 이해하고, 실제 데이터 모델에 적용하는 연습을 해야겠다. 서브쿼리 사용법도 함께 공부해서 쿼리 복잡도를 줄이는 방법을 익혀야 할 것 같다.
