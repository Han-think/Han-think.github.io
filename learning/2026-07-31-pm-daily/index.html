1. DOM 이벤트와 핸들러: 연결 방식 비교 및 기본 이해#

무엇을 배웠나#

DOM 이벤트와 이벤트 핸들러의 작동 원리를 이해하고, HTML 속성 방식, 자바스크립트 프로퍼티 방식, 그리고 addEventListener 방식의 차이점을 명확하게 구분하게 되었습니다. 개발 환경 활용에 대한 불안감도 조금 해소되었고, 이벤트 연결 방식에 대한 혼란을 이해하고 정리할 수 있었습니다. 이제 이벤트 처리 방식을 선택적으로 활용하여 웹 페이지에 상호작용을 구현할 수 있을 것 같습니다.

헷갈렸던 점#

이벤트 연결 방식이 왤케 다양하고, 각각 언제 써야 하는 건지 잘 모르겠어서 헷갈렸어. 그리고 VS Code랑 브라우저 콘솔을 어떻게 활용해야 하는지 감이 안 잡혀서 제대로 하고 있는 건가 막연하게 생각했어.

정리된 이해#

이벤트는 브라우저가 사용자의 동작이나 상태 변화를 감지하여 자바스크립트에게 알려주는 신호이고, 이벤트 핸들러는 그 신호에 반응하여 실행되는 함수입니다. HTML 속성, 자바스크립트 프로퍼티, addEventListener() 방식은 모두 이벤트 핸들러를 연결하는 방법이지만, 각기 다른 특징과 장단점을 가지고 있으며 addEventListener() 방식이 가장 유연하고 권장되는 방식입니다. 개발 환경에서 코드를 작성하고 브라우저 콘솔을 활용하는 과정에 익숙해지면 이벤트와 핸들러를 보다 효과적으로 활용할 수 있습니다.

var button = document.getElementById("btn");
button.addEventListener("click", showText);

window.onload = function() {
    var text = document.getElementById("text");
    text.innerHTML = "페이지가 열렸습니다";
};

<button onclick="getDay()">날짜 추출</button>
<div onmouseover="mouseEvt('over')" onmouseout="mouseEvt('out')">
    내용
</div>

2. 이벤트 객체와 폼 처리: 초보자를 위한 이해 정리#

무엇을 배웠나#

이벤트 객체의 evt.target, this, zone 변수가 각각 어떤 요소를 가리키는지 혼동되었지만, evt.target은 이벤트가 발생한 정확한 요소, this는 이벤트 핸들러가 연결된 요소를 참조한다는 것을 알게 되었습니다. 또한 다양한 이벤트 종류를 언제 사용해야 하는지 고민되었지만, 각 이벤트가 처리하는 사용자 입력의 종류에 따라 선택해야 한다는 점을 명확히 했습니다. 이러한 개념들을 실습 예시를 통해 확인하며 이해도를 높였습니다.

헷갈렸던 점#

이벤트 객체에서 evt.target, this, zone의 역할을 명확하게 구분하지 못해 어떤 변수를 사용해야 할지 헷갈렸고, 다양한 이벤트 종류가 언제 사용되어야 하는지 상황에 맞춰 판단하기 어려웠습니다. 특히 evt.target이 항상 예상대로 작동하는 것은 아닌 것 같아서 혼란스러웠고, this가 맥락에 따라 다른 값을 가지는 부분도 이해하기 힘들었습니다.

정리된 이해#

이벤트 객체에서 evt.target은 이벤트가 발생한 정확한 요소를, this는 이벤트 핸들러가 연결된 요소를 가리키고, zone 변수는 코드의 가독성을 높이기 위해 특정 요소를 미리 참조하는 용도로 사용됩니다. 따라서 상황에 따라 적절한 변수를 선택하여 사용해야 하며, 이벤트 종류에 따라서도 처리 방식이 달라지므로 사용자 입력의 종류를 잘 파악해야 합니다.

document.getElementById('myElement').addEventListener('click', function(evt) {
    console.log("Clicked element ID:", evt.target.id); // 실제 클릭된 요소의 ID 출력
});

document.getElementById('myElement').addEventListener('mouseout', function() {
    console.log("Element id:", this.id); // 이벤트 핸들러가 연결된 요소의 ID 출력
});

3. 이벤트 리스너 등록 및 제거 방법#

무엇을 배웠나#

이벤트 리스너 등록 시 printPos와 printPos()의 차이를 명확히 이해하게 되었고, 함수를 직접 호출하는 것과 참조하는 것의 적절한 사용법을 알게 되었다. 이름 있는 함수를 사용하는 것이 재사용성, 테스트 용이성, 제거 가능성 측면에서 이점을 제공한다는 것을 깨달았고, 이를 통해 더 효율적인 코드를 작성할 수 있을 것 같다. 앞으로는 이름 있는 함수를 활용하여 이벤트 리스너를 관리하는 습관을 들여야겠다.

헷갈렸던 점#

함수 호출 방식을 구분하는 게 너무 헷갈렸고, 함수를 이름으로 정의하는 것 대신 익명 함수를 계속 사용하고 싶었는데 왜 이름 있는 함수를 써야 하는지 이해가 안 됐습니다. 이벤트 리스너 등록과 제거할 때 이름 있는 함수가 필요하다는 점을 명확히 알지 못했습니다.

정리된 이해#

이벤트 리스너를 등록할 때는 함수를 직접 실행하지 않고, 함수 이름만 전달해야 하며, 이름 있는 함수를 사용하면 코드 재사용, 테스트, 제거가 용이하다는 것을 깨달았습니다. printPos와 printPos()의 차이를 이해하는 것이 중요했습니다.

div.addEventListener("mousemove", printPos);

printPos();

4. DOM 트리 생성, 삽입, 삭제: 초보자를 위한 가이드#

무엇을 배웠나#

DOM 트리 조작 과정에서 요소를 생성해도 바로 화면에 나타나지 않는 이유와, 텍스트 노드와 요소를 연결하는 복잡한 과정을 명확하게 이해하게 되었다. createElement(), createTextNode(), appendChild() 메서드의 사용법과 DOM 요소 삽입 순서를 익혔고, 반복문과 함수를 활용하여 동적으로 요소를 추가하는 방법을 알게 되었다. 특히 insertBefore()와 removeChild() 메서드를 통해 요소의 위치를 변경하고 삭제하는 방법을 배울 수 있었다.

헷갈렸던 점#

처음에는 createElement()로 요소를 만들었다고 바로 화면에 나타날 줄 알았는데, 그렇지 않아서 당황했습니다. 텍스트 노드를 따로 만들어서 연결하고, 이걸 다시 부모 요소에 붙이는 과정이 너무 복잡하게 느껴졌습니다. DOM 트리 조작이 생각보다 꼼꼼하게 단계를 거쳐야 한다는 점을 이해하는 데 시간이 걸렸습니다.

정리된 이해#

DOM 조작은 요소를 만들고, 텍스트를 연결한 뒤, 부모 요소에 삽입하는 단계를 거쳐야 화면에 반영됩니다. createElement(), createTextNode(), appendChild() 메서드를 이해하고, insertBefore()와 removeChild()를 활용하면 요소의 위치를 제어하고 삭제할 수 있습니다. 복잡해 보이지만, 단계별로 진행하면 DOM 트리를 원하는 대로 변경할 수 있습니다.

function myFunction() {
    var newP = document.createElement("p");
    var text = document.createTextNode("새로운 단락!");
    newP.appendChild(text);
    document.body.appendChild(newP);
}

5. classList와 이벤트 활용, 화면 상태 전환하기#

무엇을 배웠나#

이벤트 핸들러에서 스타일을 직접 변경하는 방식과 CSS 클래스를 추가하는 방식의 차이를 명확히 이해하게 되었어요. 특정 스타일을 즉시 변경해야 할 때는 style 속성을 쓰고, 여러 상태를 관리하거나 전환할 때는 classList를 사용하는 것이 좋다는 것을 알게 되었습니다. 실습 예제를 통해 실제로 적용해보니 훨씬 이해가 잘 되는 것 같아요.

헷갈렸던 점#

이벤트 핸들러에서 스타일을 직접 수정할까, 아니면 classList를 사용할까가 헷갈렸어요. 두 방식의 차이점을 명확히 인지하지 못해서 어떤 상황에 어떤 방식을 사용해야 할지 판단하기 어려웠습니다. 특히 상태 전환이 필요한 UI 요소에 대해서는 어떻게 적용해야 할지 갈피가 잡히지 않았습니다.

정리된 이해#

스타일을 직접 변경하는 방식은 간단한 즉각적인 수정에 좋지만, 여러 스타일을 묶어서 관리하거나 상태 전환이 필요할 때는 classList를 사용하는 것이 더 효율적입니다. classList를 사용하면 스타일 변경을 더 일관성 있고 관리하기 쉽게 만들 수 있습니다. 상황에 따라 적절한 방법을 선택하는 것이 중요합니다.

function changeButtonOnClick() {
    // 클래스 추가로 스타일 변경
    target.classList.add("changeColor");
    // 텍스트 변경
    target.innerText = "버튼 클릭 성공!";
}

function zoomIn() {
    // 클래스를 통해 스타일 변경
    image.style.transform = "scale(1.2)";
    image.style.transition = "all 0.5s"; // 부드럽게 전환
}
