2. 데이터 분리 및 과적합 완벽 이해하기#

무엇을 배웠나#

데이터를 단순히 나누는 것이 아니라 모델의 일반화 능력을 평가하기 위한 중요한 과정이라는 것을 알게 되었습니다. 학습, 검증, 테스트 데이터의 역할을 명확히 이해하고, 검증 데이터를 통해 과적합 여부를 감지하고 방지하는 방법을 배우었습니다. scikit-learn 라이브러리의 train_test_split 함수를 사용하여 데이터 분리를 쉽게 수행할 수 있다는 것도 알게 되었습니다.

헷갈렸던 점#

데이터 분리는 단순히 파일을 나누는 것이라는 생각을 했었고, 과적합이 무엇인지 이해했지만 어떻게 감지하고 방지해야 할지 막연했습니다. 모델의 일반화 능력과 데이터 분리의 관계, 그리고 검증 데이터의 역할에 대한 정확한 이해가 부족했습니다.

정리된 이해#

데이터 분리는 모델의 일반화 능력을 평가하기 위한 중요한 과정이며, 학습 데이터로 모델을 학습시키고 검증 데이터로 성능을 모니터링하며, 테스트 데이터로 최종 성능을 평가하는 방식으로 진행됩니다. 과적합은 학습 데이터에만 지나치게 맞춰져 새로운 데이터에 대한 성능이 떨어지는 현상이며, 검증 데이터를 통해 이를 감지하고 적절한 조치를 취해야 합니다. 데이터 분리를 통해 모델의 실제 성능을 객관적으로 평가하고 일반화 능력을 높일 수 있다는 점을 명확히 이해했습니다.

3. K-Fold 교차검증과 Epoch, 초보자를 위한 개념 정리#

무엇을 배웠나#

K-Fold 교차검증과 Epoch 개념을 공부하면서 두 용어가 혼동되었지만, Epoch은 학습 데이터 전체를 반복하는 횟수이고, K-Fold 교차검증은 데이터 분할을 통해 모델의 일반화 성능을 평가하는 방법임을 명확히 알게 되었다. 특히, K-Fold 교차검증은 모델이 특정 데이터에 과도하게 의존하지 않고 안정적으로 작동하는지 확인하는 데 중요한 역할을 한다는 것을 깨달았다. 앞으로는 이 두 개념을 정확히 이해하고 모델 학습 과정에 적용하여 성능을 향상시킬 수 있을 것 같다.

헷갈렸던 점#

K-Fold 교차검증과 Epoch 모두 모델 학습을 반복하는 것처럼 보여서, Epoch이 모델 전체 학습을 몇 번 반복하는 것인지, K-Fold가 모델 자체를 여러 개 학습하는 것인지 헷갈렸어요. 특히 K-Fold가 모델을 여러 번 학습시키는 과정이라고 생각해서 더 복잡하게 느껴졌었죠.

정리된 이해#

Epoch은 모델이 전체 학습 데이터를 반복하며 가중치를 업데이트하는 횟수를 의미하며, K-Fold 교차검증은 데이터를 여러 조각으로 나누어 모델의 일반화 성능을 안정적으로 평가하는 방법이에요. 두 개념 모두 모델 학습 과정에서 중요한 역할을 하지만, Epoch은 학습을 위한 반복 횟수를 조절하고, K-Fold 교차검증은 모델의 성능을 객관적으로 측정하는 데 초점을 맞춘다는 차이가 있답니다.

from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense

# 간단한 모델 정의
model = Sequential()
model.add(Dense(32, activation='relu', input_dim=100))
model.add(Dense(1, activation='sigmoid'))

# 컴파일 설정
model.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])

5. 데이터 분할 및 Feature/Label 분리 실습#

무엇을 배웠나#

train_test_split 함수를 사용하여 데이터를 학습 및 테스트 세트로 나누는 방법을 익혔고, 데이터 분할 시 행 기반과 열 기반 선택의 차이를 명확히 이해하게 되었다. 또한, feature(특성)와 label(레이블)을 분리하는 방법을 실제 코드를 통해 확인하며 데이터 전처리 과정에 대한 이해를 높였다. 앞으로 이 지식을 바탕으로 실제 데이터에 적용해 볼 계획이다.

헷갈렸던 점#

데이터셋 슬라이싱할 때 행과 열을 어떻게 선택해야 할지 몰라서 dataset[0:3]와 dataset[:, 0:3]의 차이를 명확히 이해하지 못했습니다. train_test_split 함수를 어떻게 활용해야 할지, 그리고 각 파라미터가 어떤 역할을 하는지 확실히 알지 못했습니다. 특히 test_size와 shuffle 옵션의 의미를 제대로 파악하지 못했습니다.

정리된 이해#

데이터 분할 시 dataset[0:3]은 처음 3행을, dataset[:, 0:3]은 처음 3개의 특성(열)을 선택한다는 것을 명확히 이해했습니다. train_test_split 함수는 데이터를 학습 및 테스트 세트로 나누는 데 사용되며, test_size는 테스트 데이터의 비율을, shuffle=False는 섞지 않고 분할함을 의미합니다. 이제 이 지식을 바탕으로 실제 데이터셋에 적용하여 모델을 학습하고 평가할 수 있을 것 같습니다.

7. 초보자를 위한 EDA 시각화 및 결측치 처리 가이드#

무엇을 배웠나#

결측치 처리할 때 실제 값을 복원하는 것이 아니라 모델 학습을 위한 임시방편이라는 점을 깨달았고, 어떤 방식으로 채웠는지 기록하고 영향도 인지해야 한다는 점을 알게 되었다. isnull().sum()이 반환하는 Series 형태를 이해하는 데 도움이 되었고, 코드 구조가 어떻게 작동하는지 더 명확하게 이해하게 되었다. 원본 데이터를 보존하는 방법도 중요하고, 코드 실행 중간 구조를 확인하는 연습이 필요하다는 것을 알게 되었다.

헷갈렸던 점#

결측치 처리할 때 평균이나 중앙값으로 채우는 게 실제 데이터의 의미를 훼손하는 것 같아서 불안했는데, 그냥 모델 학습을 위한 임시방편이라는 점을 알게 되었다. 그리고 isnull().sum()의 결과가 Series 형태라는 점이 처음에 헷갈렸었다.

정리된 이해#

결측치 처리의 목적은 실제 값을 복원하는 것이 아니라 모델 학습을 위한 임시 조치이며, 어떤 방식으로 채웠는지 기록하고 그 영향을 고려해야 합니다. isnull().sum()은 Series 형태로 반환되며, 이 Series를 pd.DataFrame()으로 변환하는 과정에서 중간 구조를 이해하는 것이 중요합니다. 코드 실행 시 원본 데이터는 df_titanic.copy()를 통해 보존하는 것이 좋습니다.

# 평균으로 결측치 채우기
mean_fill = df_titanic.fillna(df_titanic.mean())

# 중앙값으로 결측치 채우기
