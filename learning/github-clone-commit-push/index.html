1. 저장소 주소#

왜 이걸 보게 됐나#

GitHub를 사용하려면 저장소가 어디 있는지 알아야 하고, 그 주소를 통해 파일을 주고받을 수 있기 때문입니다. 저장소 URL의 구조를 이해해야 어떤 파일이 어디에 저장되는지, 그리고 나중에 해당 파일을 어떻게 찾을 수 있는지 알 수 있습니다. 특히 .git 접미사가 왜 필요한지를 이해하면 GitHub 사용의 기본 원리를 파악하는 데 도움이 됩니다.

내가 헷갈린 지점#

처음에는 https://github.com/USER/class-practice-repo.git처럼 긴 URL이 무엇을 의미하는지, 특히 .git가 왜 붙어있는지 이해하기 어려웠다. URL의 각 부분이 어떤 의미를 가지는지, 그리고 이 주소가 실제 저장소와 어떻게 연결되는지 직관적으로 파악하는 데 시간이 걸렸다. 단순히 파일의 위치를 알려주는 주소인 줄 알았지, 저장소의 전체 구조를 복제하라는 명령이라는 것을 이해하는 데 어려움이 있었다.

시도한 코드 / 예시#

https://github.com/USER/class-practice-repo.git

결과와 해석#

GitHub 저장소 주소 https://github.com/USER/class-practice-repo.git는 온라인 코드 저장소를 가리키는 URL이며, .git 접미사는 해당 저장소의 전체 복사본을 가져오라는 의미를 담고 있습니다. 이 URL을 통해 원격 저장소의 전체 구조와 내용을 로컬 환경으로 다운로드하여 작업할 수 있습니다. 주소의 앞부분은 사용자 계정(USER)과 저장소 이름(class-practice-repo)을 나타냅니다.

정리된 이해#

GitHub 저장소 주소는 원격 저장소의 위치를 나타내는 URL이며, .git 접미사는 해당 저장소의 전체 구조를 복제하라는 명령입니다. 쉽게 말해, 이 주소를 통해 GitHub 상의 특정 프로젝트를 내 로컬 환경으로 가져오거나, 내 변경사항을 그 프로젝트에 반영할 수 있습니다. URL의 구조를 통해 누가 어떤 프로젝트를 만들었는지도 알 수 있습니다.

2. 클론 과정#

왜 이걸 보게 됐나#

원격 저장소의 코드를 내 컴퓨터로 가져와서 직접 수정하고 실험해보고 싶었기 때문에 클론 명령어를 배우게 되었어. 팀원들과 협업할 때도 다른 사람의 코드를 가져와서 함께 작업해야 하는 경우가 많으니, 이 과정을 익혀두는 것이 중요하다고 생각했어. 또, 나중에 내가 만든 프로젝트를 다른 사람들과 공유하거나 백업할 때도 클론 과정은 필수적이 될 거라고 생각해.

내가 헷갈린 지점#

처음에는 git clone 명령어를 실행했을 때, 로컬 폴더에 어떤 파일들이 어떻게 복제되는지 시각적으로 보여주는 듯한 느낌을 받지 못해서, 실제로 어떤 작업이 일어나는 건지 명확히 이해하지 못했다. 특히 경로 설정이 잘못될 경우 예상치 못한 문제가 발생할까 봐 걱정스러웠고, cd 명령어를 통해 폴더를 이동하는 과정이 실제 복제 작업과 어떤 연관이 있는지 파악하기 어려웠다. 결과적으로는 파일을 다운로드하는 것 이상의 작업이 진행되는 것을 인지하지 못했던 것 같다.

시도한 코드 / 예시#

git clone <저장소 URL>
cd <폴더 경로>

결과와 해석#

git clone <저장소 URL> 명령어를 실행하면, 원격 저장소의 모든 파일과 변경 이력이 내 로컬 컴퓨터의 폴더로 복제됩니다. 복제가 완료되면 cd <폴더 경로> 명령을 통해 새로 생성된 폴더로 이동하여, 편집기에서 파일을 수정할 수 있습니다. 이 과정을 통해 원격 저장소의 내용을 내 환경에서 작업할 수 있도록 준비됩니다.

정리된 이해#

git clone 명령어를 실행하면 원격 저장소에 있는 모든 파일과 이력 정보가 로컬 컴퓨터의 지정된 폴더로 복제된다. 이 과정에서 .git 폴더는 원격 저장소의 메타데이터를 포함하여 버전 관리 시스템을 완벽하게 복사하는 역할을 한다. 복제 후에는 복제된 폴더로 이동하여 편집기를 통해 파일 수정 작업을 시작할 수 있다.

3. 커밋 메시지#

왜 이걸 보게 됐나#

처음에는 코드 수정 후 단순히 저장하는 것만으로도 충분하다고 생각했지만, 여러 사람이 함께 작업할 때 어떤 변경이 있었는지, 왜 수정했는지 기록하지 않으면 혼란이 커질 수 있다는 것을 알게 되었습니다. 커밋 메시지를 통해 변경 이력을 명확하게 관리하면 협업 효율성을 높이고, 나중에 코드를 다시 볼 때도 이해하기 쉬워집니다.

내가 헷갈린 지점#

커밋 메시지를 작성해야 한다는 것을 알았지만, 어떤 내용을 어떻게 써야 하는지 막연했습니다. 단순히 수정 내용을 나열하는 것만으로는 부족하다는 것을 인지했지만, 구체적인 작성 가이드라인이 명확하게 떠오르지 않았습니다. 커밋 메시지가 단순히 형식적인 절차일 것이라고 생각했지만, 나중에 변경 이력을 추적하고 이해하는 데 중요한 역할을 한다는 것을 깨달았습니다.

시도한 코드 / 예시#

git commit -m "오늘 학습 내용 업데이트"

결과와 해석#

변경사항을 기록하는 커밋 메시지는 프로젝트의 변경 이력을 관리하는 데 매우 중요한 역할을 한다. 커밋 메시지는 간결하고 명확하게 변경 내용을 요약하며, 다른 개발자 또는 미래의 나에게 어떤 수정이 있었는지 빠르게 이해할 수 있도록 돕는다. 좋은 커밋 메시지는 변경의 의도를 설명하여 코드 유지보수를 용이하게 만든다.

정리된 이해#

git commit 명령어 실행 시, 변경사항에 대한 간략한 설명을 담은 메시지를 함께 작성해야 한다. 이 메시지는 변경 이력을 추적하고 다른 개발자와 협업할 때 중요한 역할을 한다. 명확하고 간결하게 작성하여 변경 내용을 쉽게 이해할 수 있도록 하는 것이 중요하다.

4. git add#

왜 이걸 보게 됐나#

처음에는 파일을 수정했다고 생각하고 바로 커밋했는데, 커밋 메시지를 작성했음에도 불구하고 변경 사항이 적용되지 않았어요. 그 이유는 수정된 내용을 스테이징 영역에 추가하지 않았기 때문이라는 것을 알게 되었습니다. ‘git add’ 명령어를 통해 변경된 파일을 스테이징 영역에 추가해야만 커밋 과정에서 반영될 수 있다는 것을 깨달았죠.

내가 헷갈린 지점#

처음에는 ‘git add’ 명령어를 실행할 때, 파일 내용 수정만으로는 변경 사항이 반영되는 게 아니라, 이 명령어를 통해서 명시적으로 변경 사항을 기록해야 한다는 점을 몰랐다. 단순히 파일 수정 후 바로 커밋하면 되는 줄 알았고, 그래서 ‘Changes not staged for commit’ 메시지가 나왔었다. 또한, 어떤 파일을 추가해야 할지, 혹은 추가하면 안 되는지에 대한 기준도 잘 이해하지 못했다.

시도한 코드 / 예시#

git add README.md

결과와 해석#

git add 명령어는 수정하거나 새로 생성된 파일을 스테이징 영역에 추가하는 역할을 합니다. 스테이징 영역은 다음 커밋에 포함될 변경 사항들을 모아두는 일종의 준비 공간이라고 생각하면 됩니다. git add .과 같이 명령어를 실행하면 현재 디렉토리의 모든 변경 사항이 스테이징 영역에 포함되므로, 원하는 파일만 커밋하려면 파일 이름을 명시해야 합니다.

정리된 이해#

git add는 수정된 파일을 로컬 저장소의 스테이징 영역으로 옮겨 커밋 대상에 포함시키는 중요한 단계야. 이 명령을 실행해야만 내가 수정한 내용이 다음 커밋에 기록될 수 있고, 그렇지 않으면 변경 사항은 저장되지 않아. 간단히 말해, git add는 내가 변경한 내용을 Git이 주목하게 만드는 첫 번째 신호탄과 같아.

총평#

오늘 전체에서 배운 것#

GitHub 저장소를 클론하고, 수정 사항을 스테이징 영역에 추가하고, 커밋 메시지를 작성하여 로컬 저장소에 기록하는 과정을 이해했다. git add 단계를 생략하면 변경 사항이 commit되지 않음을 명확히 알게 되었다. 앞으로는 git status를 통해 작업 상태를 꾸준히 확인하며 작업하겠다.

다음에 조심할 것#

git add 단계를 잊지 않도록 주의해야겠다. git push 후에도 원격 저장소에 반영되었는지 확인하는 습관을 들여야겠다. 커밋 메시지를 작성할 때 변경 사항을 명확하게 설명하도록 노력해야겠다.

다음 복습 주제#

.gitignore 파일의 활용법을 더 깊이 공부해야겠다. 특히 운영체제별, 프로젝트별로 필요한 규칙을 어떻게 설정하는지 알아봐야겠다. 또한, 브랜치 전략과 머지 전략에 대한 이해를 높여서 협업 환경에서 효과적으로 작업하고 싶다.
