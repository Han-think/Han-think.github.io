2026-05-28 학습 노트: Git Bash, Markdown, vi, 그리고 Hugo 활용

오늘의 학습 경험을 바탕으로 Git Bash의 기초, Markdown 문서 작성, vi 편집기 사용법 그리고 이를 활용한 Hugo 블로그 설정에 대한 개인적인 통찰과 고민들을 정리했습니다.
2026년 5월 30일 · 10 min

왜 썼나#

오늘의 학습 목표는 다양한 도구와 플랫폼을 효과적으로 활용하여 개인적인 학습 내용을 체계적으로 기록하고 공유하는 방법을 익히는 것이었습니다. 특히 Git Bash를 통한 Linux CLI 기초, Markdown을 활용한 문서 작성, 텍스트 편집기인 vi의 기초, 그리고 이를 블로그 플랫폼인 Hugo에 적용하는 방법을 학습했습니다. 이러한 기술들은 정보를 효과적으로 관리하고 공유하는 데 필수적이기 때문입니다.

배운 것#

  1. Git Bash와 Linux CLI: 단순히 명령어를 외우는 것이 아니라, 터미널 내에서 문제 해결을 위한 경로 탐색 감각을 키웠습니다. 이를 통해 시스템 관리와 버전 관리에 대한 이해도가 향상되었습니다.
  2. Markdown 문서 작성: Markdown의 기본 문법을 배워 문서를 간결하고 가독성 있게 작성할 수 있게 되었습니다. 특히 #를 이용한 제목 표시와 >/>>를 이용한 파일 내용 추가 방식을 이해했습니다.
  3. vi 편집기: vi 편집기의 기본적인 사용법을 익혔습니다. 특히 파일을 열고 편집하며 내용을 추가하거나 수정하는 방법을 배웠습니다. 하지만 vi의 복잡한 모드 전환은 아직 익숙해지는 과정에 있습니다.
  4. Hugo 블로그 구축: 내가 학습한 내용을 Hugo를 통해 블로그 형태로 기록하고 공개하는 방법을 학습했습니다. LearningLog 구조를 이해하며, 개인적인 학습 일지를 효과적으로 관리하고 공유할 수 있는 플랫폼을 구축하는 데 필요한 기본적인 설정을 수행했습니다.

헷갈리던 점#

  1. >와 >>의 차이: 처음에는 >와 >>의 기능 차이를 정확히 이해하지 못했습니다. >는 첫 줄에 내용을 추가하고, >>는 기존 내용 뒤에 추가한다는 점을 깨달았습니다.
  2. Markdown 내 #의 이중 역할: Markdown에서 #은 제목을 표시하는 데 사용되지만, Git Bash에서는 주석 표시로 사용됩니다. 문맥에 따라 같은 기호가 다른 역할을 한다는 점이 혼란스러웠습니다.
  3. vi 편집기의 모드 전환: vi 편집기에서 i 모드로 들어가 편집을 시작하는 것은 이해했지만, 다시 정규 모드로 돌아가는 방법을 찾는 데 어려움을 겪었습니다. Esc 키를 사용한다는 것을 알게 되었습니다.
  4. 문자열 표기법의 차이: " "와 ' '의 차이를 이해하는 데 시간이 걸렸습니다. 특히 변수 $변수가 포함될 때 두 방식의 차이를 직접 실행해 보며 확인했습니다.

정리된 이해#

  • Git Bash: 터미널에서의 문제 해결 능력 향상이 중요하다.
  • Markdown: 간결하고 읽기 쉬운 문서 작성을 위한 기본 문법 숙지.
  • vi 편집기: 기본적인 편집 기능과 모드 전환을 이해하는 것이 핵심이다.
  • Hugo: 개인 블로그 구축을 위한 구조와 기본 설정 이해.

title: “명령어 사용 경험과 학습 정리: rm 옵션 이해하기” date: 2026-05-30 draft: true categories: [“learning”] tags: [“shell”, “Linux”] description: “Hugo 블로그 초안으로, rm 명령어의 다양한 옵션과 경로 지정에 대한 학습 경험과 이해를 정리합니다.”

왜 썼나#

최근에 파일 관리를 위한 명령어 rm을 사용하면서 다양한 옵션과 경로 지정에 대한 혼란을 겪었습니다. 특히 rm -ri 옵션을 사용할 때 경로와 삭제 대상을 명확히 구분하는 것이 어려웠습니다. 이러한 경험을 바탕으로 더 명확하게 이해하고, 비슷한 문제를 겪는 초보자들에게 도움을 주고자 합니다.

배운 것#

  1. 경로 지정과 삭제 대상 구분:

    • rm -ri a_11/A_11 명령어에서 a_11/은 디렉토리 경로를 지정하고, A_11은 그 안에서 삭제할 특정 파일을 의미합니다. 초보자로서 처음에는 전체 디렉토리가 삭제되는 줄 오해했습니다.

  2. 레드irection 연산자 >와 >> 이해:

    • >는 파일을 새로 쓰면서 기존 내용을 지우고, >>는 파일의 끝에 내용을 추가합니다. 이는 Python에서 파일을 쓰는 모드와 유사한 개념입니다: open("f","w")는 >와 동일하고, open("f","a")는 >>와 유사합니다.

  3. 주석 표기 #의 다양한 해석:

    • Bash 스크립트 내에서 #은 주석을 나타냅니다. 반면, Markdown 문서에서는 #이 제목을 나타냅니다. 파서의 차이로 인해 같은 기호가 다른 의미를 가질 수 있다는 점을 배웠습니다.

  4. vi 편집기 기본 단축키:

    • vi 편집기에서 작업을 마치는 가장 기본적인 방법들을 익혔습니다:
      • ESC → :q!: 저장 없이 종료
      • ESC → :wq: 변경 사항 저장 후 종료
    • vi 편집기를 처음 사용할 때는 이러한 탈출 방법을 먼저 익히는 것이 중요하다는 것을 깨달았습니다.

  5. 따옴표의 차이 " " vs ' ':

    • 큰따옴표(")로 묶으면 변수 확장이 이루어지지만, 작은따옴표(')로 묶으면 그대로 보존됩니다. 이 차이점은 스크립트 작성 시 중요한 포인트였습니다.

헷갈린 것#

  • rm 명령어의 옵션과 경로 지정 혼동: 특히 -i 플래그가 있는 경우, 각 파일에 대해 삭제 여부를 물어보는 과정에서 혼란이 있었습니다. 초보자로서 이런 과정이 다소 복잡하게 느껴졌습니다.
  • #의 맥락에 따른 해석 차이: Markdown과 Bash 스크립트에서 #의 의미가 다르다는 점에서 처음에는 혼란스러웠습니다.

정리된 이해#

  • > vs >>: 파일 입출력 모드의 차이를 명확히 이해했습니다. >는 내용을 덮어쓰고, >>는 내용을 추가합니다.
  • #의 맥락: 파서에 따라 주석 또는 제목으로 해석되므로 사용 환경에 따라 주의해야 합니다.
  • vi 탈출: 편집기 사용 시 필수적인 단축키를 기억하고 활용하는 것이 중요합니다.
  • 따옴표의 역할: 변수 확장과 내용 보존의 차이를 확실히 이해했습니다.
  • rm -ri 옵션: 경로와 삭제 대상을 명확히 구분하고, -i 플래그의 역할을 이해하여 안전하게 파일을 관리할 수 있게 되었습니다.

실습 예시#

# 디렉토리 내 특정 파일 삭제 예시
rm -ri /home/user/project/a_11/A_11

# 파일 덮어쓰기 예시
echo "새 내용" > example.txt  # 기존 내용 삭제
echo "추가 내용" >> example.txt  # 내용 추가

# 변수 확장 예시
echo $HOME  # 환경 변수 확장
echo '오늘 날짜: '$DATE  # 문자열 그대로 출력

title: “Linux 기본 명령어와 텍스트 편집기 활용 가이드” date: 2026-05-30 draft: true categories: [“learning”] tags: [“linux”, “cli”, “vi”] description: “Linux 환경에서 기본적인 명령어 사용법과 vi 텍스트 편집기의 핵심 단축키를 익히는 학습 경험을 공유합니다.”

왜 썼나#

최근 프로젝트를 진행하면서 Linux 서버 관리에 직접 참여하게 되었습니다. 기본적인 터미널 명령어와 텍스트 편집 기법을 익혀야 실제 작업 환경에서 효율적으로 작업할 수 있겠다는 필요성을 느꼈습니다. 특히, 팀원들 간의 코드 공유와 관리가 원활해지기 위해 이러한 기술들이 필수적임을 깨달았습니다.

배운 것#

  • 터미널 명령어: pwd, ls, cd, mkdir, touch, echo, rm 등을 통해 디렉토리 구조를 관리하고 파일을 생성, 수정, 삭제하는 방법을 배웠습니다. 특히 >와 >>의 차이는 중요한 포인트였습니다. >는 파일을 덮어쓰기 위해 사용하고, >>는 기존 내용 뒤에 추가하기 위해 사용된다는 점을 명확히 이해했습니다.
  • 텍스트 편집기 vi: vi 편집기의 기본적인 사용법을 배웠습니다. 삽입 모드(i), 일반 모드(ESC), 그리고 파일 저장 및 종료 방법(:wq) 등이 핵심적이었습니다. 상황에 따라 :q!로 강제 종료하는 방법도 중요했습니다.

헷갈린 것#

  • mkdir -p 명령어를 처음엔 이해하기 어려웠습니다. 중첩 폴더 생성의 편의성을 제공한다는 점은 알았지만, 실제로 어떻게 동작하는지에 대한 구체적인 이해가 필요했습니다.
  • >와 >>의 차이는 처음엔 혼동되었습니다. 파일 내용을 어떻게 처리할지에 따라 선택해야 하는 순간이 많았습니다.

정리된 이해#

Linux 환경에서의 기본적인 파일 시스템 관리와 텍스트 편집은 작업 효율성을 크게 향상시킵니다. 터미널 명령어와 vi 편집기는 단순한 도구 이상으로, 문제 해결과 코드 관리에 필수적인 기술입니다. 특히, vi 편집기의 단축키는 시간을 크게 절약시켜 줍니다. >와 >>의 차이점을 정확히 이해하고 활용하는 것은 파일 관리에서 중요한 능력입니다.

실습 예시#

이번 실습을 통해 다음과 같은 과정을 거쳤습니다:

  1. 폴더 구조 생성: mkdir -p test/docs/linux 명령어로 중첩 폴더를 생성했습니다.
  2. 파일 생성 및 내용 작성: touch memo.md로 파일을 생성한 후, >와 >>를 활용해 내용을 추가했습니다. 
    echo "첫 번째 줄" > memo.md
echo "두 번째 줄" >> memo.md
cat memo.md  # 내용 확인
  3. vi 편집기 활용: vi memo.md로 파일을 열고, 내용을 수정한 후 :wq로 저장하고 종료했습니다. 
    vi memo.md
# 삽입 모드 진입: i
# 수정 후: ESC
# 저장 및 종료: :wq
  4. 안전한 파일 삭제: rm -ri test/docs로 중첩 폴더와 파일을 안전하게 삭제했습니다. 
    rm -ri test/docs
# 삭제 확인 대화상자에서 y 입력

왜 썼나#

최근에 Hugo 블로그를 구축하는 과정에서 Python의 파일 쓰기 모드와 Vim 편집기의 작동 방식에 대한 이해가 중요해졌습니다. 특히, 터미널 환경에서의 작업과 텍스트 편집기 사용법 사이의 연관성을 파악하는 것이 학습의 핵심이 되었습니다. 이를 통해 기술적인 능력뿐 아니라, 학습 내용을 효과적으로 기록하고 정리하는 방법을 개선하고자 했습니다.

배운 것#

  1. Python 파일 모드:

    • >는 파일을 새로 생성하여 내용을 쓰는 모드입니다 (open("file","w")).
    • >>는 기존 파일의 끝에 내용을 추가하는 모드입니다 (open("file","a")).
    • 이는 터미널에서의 리다이렉션과 유사한 개념으로, 작업의 일관성을 유지하는 데 도움이 됩니다.

  2. Vim 편집 모드:

    • Vim은 “모드 기반 편집기"로, INSERT 모드와 NORMAL 모드 등 다양한 모드가 존재합니다.
    • INSERT 모드에서는 타이핑만 가능하고, NORMAL 모드에서는 명령을 입력하여 편집 작업을 수행할 수 있습니다.
    • 초기에는 복잡해 보일 수 있지만, 이러한 모드 이해는 Vim을 효과적으로 활용하는 데 필수적입니다.

헷갈렸던 것#

  • Vim의 다양한 모드 중에서 각각의 역할과 전환 방법이 처음에는 혼란스러웠습니다. 특히, NORMAL 모드에서 명령을 입력하고 다시 INSERT 모드로 돌아가는 과정이 익숙해지는데 시간이 걸렸습니다.

정리된 이해#

  • 파일 쓰기 모드와 Vim 모드는 모두 특정 작업에 최적화된 환경을 제공합니다. Python에서 파일을 다룰 때와 Vim 편집기를 사용할 때, 각각의 모드 선택이 작업 효율성을 크게 향상시킵니다. 이러한 개념을 통해 더 체계적이고 효과적인 코딩 및 편집 경험을 쌓을 수 있음을 깨달았습니다.

실습 예시#

  • Python 파일 모드 실습:

    # 파일 생성 및 내용 쓰기
with open("example.txt", "w") as file:
    file.write("Hello, Hugo!\n")

# 파일 끝에 내용 추가
with open("example.txt", "a") as file:
    file.write("Adding more content.\n")

  • Vim 편집 모드 실습:

    • Vim을 실행하고 :edit example.txt 명령어로 파일을 열어 봅니다.
    • INSERT 모드에서 텍스트를 입력하고, :w로 저장 후 NORMAL 모드로 돌아가 다른 명령을 실행해 보세요 (예: :q로 종료).

왜 썼나#

블로그를 운영하며 독자들과 기술적인 지식을 공유하는 것은 매우 의미 있는 경험이었습니다. 특히 이번 프로젝트는 Git Bash와 Linux 명령어를 활용해 글을 작성하고, 이를 Hugo 프레임워크로 웹사이트로 전환하는 과정을 직접 체험함으로써 실질적인 기술 습득이 목표였습니다. 이러한 경험을 통해 기술적인 능력뿐만 아니라 콘텐츠 제작과 배포의 전반적인 흐름을 이해하고 싶었습니다.

배운 것#

  1. Git Bash와 Linux CLI 활용: 명령어를 통해 파일을 쉽게 관리하고 작업 흐름을 효율화할 수 있었습니다. 특히 cd, ls, mkdir, touch 등의 기본 명령어는 일상적인 작업에서 큰 도움이 되었습니다.
  2. Markdown 문법 이해: #를 사용한 헤딩 표기법부터 간단한 링크 삽입까지, Markdown의 기본적인 작성 방법을 익히며 문서 작성이 훨씬 직관적으로 느껴졌습니다.
  3. 텍스트 편집기 활용: vi와 nano를 사용하면서 기본적인 편집 모드와 명령어를 배웠습니다. 예를 들어 vi에서 INSERT 모드로 전환하기 위해 ESC를 눌러 정상 모드로 이동한 후 :wq로 저장하고 종료하는 방법 등이 있었습니다.
  4. Hugo 워크플로우: 콘텐츠를 Markdown 파일로 작성하고 이를 Hugo 프로젝트로 컴파일하는 과정을 이해했습니다. 이는 단순한 텍스트 작성을 넘어 실제 웹사이트 생성까지 연결되는 중요한 단계였습니다.

헷갈린 것#

  • ** > (overwrite) vs >> (append)**: Bash에서 파일을 처리할 때 >는 기존 내용을 덮어쓰고, >>는 내용을 추가하는 것을 처음에는 혼동했습니다. 실제로 작업해보면서 확실하게 이해할 수 있었습니다.
  • ** #의 역할 혼동**: Markdown에서 #은 헤딩을 나타내지만, Bash에서는 주석으로 사용됩니다. 이 둘의 차이를 명확히 인식하게 되면서 혼동이 줄었습니다.
  • 셸에서의 Quote 사용: 이중 인용(")과 단일 인용(')의 차이점에 대해 처음에는 어려움을 겪었습니다. 특히 환경 변수나 명령어 결과를 포함할 때 올바르게 사용하는 방법을 익혔습니다.

정리된 이해#

Linux CLI와 Git Bash를 활용해 효율적인 파일 관리와 텍스트 편집을 학습하면서 Markdown 문법을 익히는 것은 웹 콘텐츠 작성에 있어 필수적입니다. 특히 Hugo를 통한 웹사이트 생성 과정은 이러한 모든 요소를 하나로 묶어 실제 웹사이트를 구축하는 경험을 제공했습니다. vi와 nano 같은 편집기의 기본적인 사용법도 실제 작업에서 큰 도움이 되었습니다.
