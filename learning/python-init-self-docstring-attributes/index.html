초보자를 위한 `__init__`, `self`, 그리고 Docstring 이해하기

Python 클래스에서 `__init__`, `self`, 그리고 Docstring의 핵심 개념을 이해하고 실습하며 배우는 초보자 가이드.
2026년 6월 2일 · 6 min

왜 이 글을 썼나#

이번 워킹 노트는 Python 프로그래밍에서 클래스를 처음 접하는 초보자들이 흔히 겪는 어려움을 다루고자 작성되었습니다. 특히, 객체 지향 프로그래밍의 기본 요소인 __init__, self, 그리고 문서화를 위한 Docstring에 초점을 맞추었습니다. 이를 통해 학습자들이 코드 작성 시 발생할 수 있는 주요 오류를 피하고, 개념을 명확히 이해하는 데 도움을 주고자 합니다.

이번 학습 세션에서는 Python에서 클래스를 활용하는 방법에 초점을 맞추었습니다. 특히, 객체 지향 프로그래밍의 기초 중 하나인 클래스 내 객체 생성과 속성 관리에 대해 깊이 있게 탐구하였습니다. 이를 통해 실제 프로젝트에서 클래스를 효과적으로 사용할 수 있는 기반을 다지고자 했습니다.

클래스를 활용하여 객체 지향 프로그래밍을 배울 때 가장 기본적이면서도 중요한 부분 중 하나는 각 객체의 속성을 올바르게 초기화하는 것입니다. 이를 통해 프로그램의 안정성과 예측 가능성을 높일 수 있습니다.

  • 코드 가독성 향상: 단순히 코드를 작성하는 것 이상으로, 코드의 목적과 기능을 명확하게 설명하는 것이 중요합니다. Docstring을 통해 다른 개발자들이 코드를 이해하고 유지보수를 쉽게 할 수 있도록 지원합니다.
  • 자동 문서화 도구 활용: Python의 내장 도구들과 연계하여 자동으로 문서를 생성할 수 있어 개발 효율성을 크게 높입니다. 이를 통해 개발 시간을 절약하고 오류를 줄일 수 있습니다.

클래스 개념을 처음 접하는 분들에게 실제 코드 예시를 통해 이해를 돕고자 했습니다. 특히, 클래스를 활용해 객체를 생성하고 관리하는 방법을 구체적으로 설명함으로써 학습의 문턱을 낮추고자 했습니다.

이 글은 프로그래밍의 핵심 개념 중 하나인 **클래스와 객체지향 프로그래밍(Object-Oriented Programming, OOP)**에 대해 더 깊이 이해하기 위한 학습 경험을 공유하고자 작성되었습니다. 특히, Python 언어를 통해 실제 코드 작성과 함께 이론적 배경을 탐구하며 습득한 지식을 정리하는 데 초점을 맞추었습니다.

오늘 배운 핵심#

1. 학습 포인트#

  • __init__ 메서드의 역할: 클래스의 인스턴스를 초기화하는 데 사용되는 특수 메서드입니다. 이 메서드 내에서 정의된 매개변수들은 클래스의 인스턴스 속성으로 할당됩니다.
  • self의 중요성: self는 클래스의 인스턴스를 참조하는 키워드로, 메서드 내에서 클래스의 속성과 메서드에 접근할 수 있게 해줍니다. 이를 통해 각 인스턴스가 독립적인 데이터를 가질 수 있게 됩니다.
  • Docstring 작성: 클래스와 메서드에 대한 설명을 문서화하는 데 사용되며, 코드의 가독성을 높이고 향후 유지보수에 도움을 줍니다.

2. 학습 포인트#

  • __init__ 메서드: 클래스 인스턴스가 생성될 때 자동으로 호출되는 메서드로, 객체의 초기 상태를 설정하는 데 필수적입니다. 이 메서드를 통해 클래스의 속성을 정의하고 초기 값을 할당할 수 있습니다.
  • self 키워드: 클래스 메서드 내에서 현재 객체 인스턴스를 참조하는 데 사용됩니다. 이를 통해 객체의 속성과 메서드에 접근하고 조작할 수 있습니다.
  • 인스턴스 속성: 각 객체 인스턴스가 독립적인 데이터를 가질 수 있도록 하는 속성입니다. 예를 들어, 여러 팀원을 표현할 때 각 팀원의 이름, 역할, 급여가 다르게 설정될 수 있습니다.
  • Docstring: 코드의 가독성을 높이고 문서화를 용이하게 하는 데 중요한 역할을 합니다. 클래스와 함수에 대한 설명을 담아 추후 유지보수나 팀 내 협업에 도움을 줍니다.

3. 학습 포인트#

  • __init__ 메서드의 역할: 클래스 인스턴스를 생성할 때 필요한 속성을 초기화하는 데 사용됩니다. 이 메서드 내에서 self 키워드를 사용하여 인스턴스 변수를 정의해야 합니다.
  • 인스턴스 변수의 중요성: 각 객체마다 독립적인 상태를 유지하기 위해 필요하며, 이를 통해 클래스 내 객체 간의 데이터 일관성을 보장할 수 있습니다.

4. 학습 포인트#

  • 주석과 Docstring의 차이: 초기에는 주석과 Docstring의 구분이 명확하지 않았으나, Docstring이 코드 이해와 자동 문서화 도구에서 중요한 역할을 한다는 것을 깨달았습니다.
  • Docstring 작성 규칙: 공식적인 문서화를 위해 일관된 구조와 스타일을 따르는 것이 중요하다는 것을 배웠습니다. 특히, Google, NumPy, reStructuredText 등의 스타일 가이드를 참고하여 작성하는 것이 좋습니다.

5. 학습 포인트#

  • 클래스 초기화 (__init__ 메서드): 클래스 인스턴스를 생성할 때 필요한 속성을 초기화하는 방법을 배웠습니다. __init__ 메서드는 객체 생성 시 자동으로 호출되어 기본 설정을 제공합니다.
  • self 키워드: self는 클래스 내에서 현재 객체를 참조하는 키워드입니다. 이를 통해 클래스의 속성과 메소드에 접근할 수 있음을 이해했습니다.
  • 인스턴스 속성 정의 및 사용: 클래스 내에서 인스턴스 속성을 정의하고 이를 통해 객체의 상태를 관리하는 방법을 익혔습니다. 예를 들어, TeamMember 클래스에서 이름, 직책, 연봉을 속성으로 설정했습니다.

6. 학습 포인트#

  • 클래스 정의와 생성자: 클래스를 어떻게 정의하고 인스턴스를 생성하는지에 대한 기본적인 이해를 얻었습니다. 특히 __init__ 메서드가 클래스 인스턴스 초기화에 중요한 역할을 한다는 점이 명확해졌습니다.
  • self 키워드의 활용: 클래스 내에서 인스턴스 변수에 접근하거나 메소드를 호출할 때 self 키워드의 필수성을 깨달았습니다. 이를 통해 클래스 인스턴스 간의 상태 공유와 메소드 호출이 가능해진다는 것을 배웠습니다.
  • 인스턴스 속성의 중요성: 각 인스턴스마다 고유한 속성 값을 가질 수 있다는 점이 객체지향 프로그래밍의 유연성과 효율성을 크게 높이는 요소임을 확인했습니다.
  • 코드 문서화: 클래스와 메소드에 대한 설명을 담는 Docstring의 중요성을 인지하게 되었습니다. 이는 코드의 가독성을 향상시키고 유지보수를 용이하게 만드는 데 필수적임을 깨달았습니다.

헷갈렸던 지점#

1. 혼동 포인트#

  • 인스턴스 속성 정의: 지역 변수와 인스턴스 속성의 차이를 명확히 이해하는 데 어려움이 있었습니다. 예를 들어, name만 정의하면 클래스의 인스턴스에 저장되지 않고 지역 변수로만 취급됩니다. 반면 self.name을 사용하면 각 인스턴스에 고유하게 저장됩니다.
    • 실습 예시: 
      class Person:
    def __init__(self, name):
        name  # 지역 변수로 취급되어 인스턴스 속성으로 저장되지 않음
        self.name  # 올바른 정의


### 2. 혼동 포인트

- **오류 메시지 해석**: `AttributeError: 'TeamMember' object has no attribute 'role'` 오류 메시지를 받았을 때, `role` 속성이 정의되지 않았다는 사실을 이해하는 데 어려움을 겪었습니다. 특히, 코드 내에서 `self.role`이 제대로 할당되지 않았음을 알아차리지 못해 혼란스러웠습니다. 이 오류는 클래스 정의 내에서 속성이 올바르게 초기화되었는지 꼼꼼히 확인해야 함을 다시 한번 깨닫게 해주었습니다.

### 3. 혼동 포인트

- **`self`의 사용**: 처음에는 `self`를 어떻게 사용해야 하는지 혼란스러울 수 있습니다. 특히 여러 속성을 초기화할 때 각 변수에 `self`를 올바르게 붙이는 것이 중요합니다.

### 4. 혼동 포인트

- **Docstring의 실제 활용**: 초기에는 Docstring이 단순히 주석 역할만 하는 것으로 오해했습니다. 그러나 실제로는 `help()` 함수를 통해 코드 내에서 직접 접근 가능하고, 다양한 문서화 도구와 연동되어 자동으로 문서를 생성한다는 점이 혼란스러웠습니다.
- **도구 활용 이해 부족**: `sphinx`, `pdoc`, `pydoc` 등 다양한 문서화 도구들이 Docstring을 어떻게 활용하는지 완전히 이해하지 못했습니다. 이 도구들이 어떻게 Docstring을 통해 개발자의 의도를 정확하게 전달하는지에 대한 이해가 부족했습니다.

### 5. 혼동 포인트

- **`__init__` 메서드 이해**: 초기화 메서드가 객체 생성 시 어떤 역할을 하는지 정확히 파악하는 데 어려움이 있었습니다. 이로 인해 객체 생성 시 필요한 매개변수를 놓치는 오류가 발생했습니다.
- **`self` 키워드 활용**: `self`를 올바르게 사용하는 것이 처음에는 어려웠습니다. 특히 메소드 내에서 클래스의 속성에 접근할 때 오류가 발생하곤 했습니다.
- **속성 초기화 오류**: 클래스 속성을 초기화하는 과정에서 잘못된 타입이나 값 설정으로 인해 `AttributeError`가 발생하는 경우를 경험했습니다.

### 6. 혼동 포인트

- **`AttributeError` 처리**: 초기에는 클래스 인스턴스에 존재하지 않는 속성에 접근하려고 할 때 발생하는 `AttributeError`를 자주 마주쳤습니다. 이를 방지하기 위해 속성 존재 여부를 확인하는 로직을 추가하는 것이 중요하다는 것을 학습했습니다.
