1. FastAPI 개념 매핑: Express와 클래스 구분하기#

무엇을 배웠나#

FastAPI는 Express의 const app = express()와 달리 import fastapi만으로는 앱이 생성되지 않는다. 핵심은 fastapi라는 모듈 안에 있는 FastAPI 클래스를 ()로 호출해 인스턴스를 만들어야 한다는 점이다. 또한 자동완성 기능에 속아 app = fastapi처럼 모듈을 변수에 대입하면 오류가 나니, 반드시 클래스 이름을 붙여 인스턴스를 생성해야 한다.

헷갈렸던 점#

fastapi는 import하는 모듈이고 FastAPI는 그 안에 정의된 클래스이며, FastAPI()를 호출해야 실제 app 객체가 생성된다는 점을 명확히 구분하지 못해 자동완성 함정에 빠졌던 것이 가장 큰 혼란이었다. Express의 const app = express() 패턴과 연결해 머릿속에 각인시키려 했으나, import 구문만으로도 app이 완성되는 FastAPI의 특성이 처음에는 이해되지 않았다. 결국 fastapi는 모듈, FastAPI는 클래스, FastAPI()는 인스턴스를 생성하는 객체라는 3단계 구조를 정확히 인식해야 한다는 교훈을 얻었다.

정리된 이해#

Express의 const app = express()와 같이 FastAPI()를 호출해야 실제 앱 객체가 생성된다는 점을 명확히 인지하는 것이 핵심입니다. fastapi는 모듈(import 대상)이며, FastAPI는 그 안에 정의된 클래스이므로 대소문자 구분과 괄호 사용이 필수적입니다. 이 개념을 이해하면 Express와 FastAPI의 라우팅 패턴(app.get vs @app.get) 간의 차이도 자연스럽게 익힐 수 있습니다.

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "Hello World"}

2. Uvicorn과 FastAPI의 역할 구분: 서버와 애플리케이션#

무엇을 배웠나#

Uvicorn은 HTTP 요청을 처리하는 웹 서버 역할을 하고, FastAPI는 실제 비즈니스 로직과 경로 설정을 담당하는 애플리케이션 프레임워크입니다. 두 도구를 분리하여 생각하면, Uvicorn이 ‘통로’이고 FastAPI가 ‘배우’라는 비유가 가장 명확하게 이해됩니다. 따라서 uvicorn main:app 명령어는 Uvicorn이 FastAPI가 만든 앱을 실행시켜주는 신호와 같습니다.

헷갈렸던 점#

FastAPI와 Uvicorn이 모두 ‘서버’로 보여 역할 구분이 안 됐습니다. Uvicorn은 HTTP 요청을 받아들이는 ‘통로’이고, FastAPI는 비즈니스 로직을 담당하는 ‘배우’입니다. 명령어 uvicorn main:app는 Uvicorn이 FastAPI가 만든 앱을 실행해달라는 신호입니다.

정리된 이해#

Uvicorn은 HTTP 요청을 받아들이고 응답하는 웹 서버 역할을 수행하며, FastAPI는 실제 비즈니스 로직과 API 경로를 담당하는 애플리케이션 프레임워크입니다. Uvicorn이 FastAPI가 만든 앱 객체를 실행시켜주는 역할이고, uvicorn main:app 명령어는 이 두 도구가 협업하여 서버를 구동시키는 핵심적인 과정입니다.

# main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "Hello World"}

3. 파이썬 실행 환경과 uv 설치의 차이점#

무엇을 배웠나#

터미널 명령어가 안 될 때 코드부터 의심하기보다 tool 설치와 PATH를 먼저 확인하는 것이 가장 중요합니다. PyCharm Interpreter와 Terminal Shell은 별개의 영역이며, venv activation는 현재 환경을 전환하는 과정입니다. uv는 기본 내장된 도구가 아니므로 시스템에 설치되어 있어야 명령어가 인식됩니다.

헷갈렸던 점#

터미널 명령어가 안 된다는 사실 자체를 간과하고, Python 언어 자체의 문법적 오류로 돌리는 패턴이었습니다.

PyCharm Interpreter와 Terminal Shell는 별개의 영역이며, uv는 기본 내장된 도구가 아니라 별도의 CLI 툴로 시스템에 설치되어 있지 않으면 명령어가 인식되지 않습니다.

정리된 이해#

실행 환경과 언어 코드는 별개의 영역이며, 명령어가 작동하지 않을 때는 코드 자체보다는 도구 설치와 PATH 설정을 먼저 확인해야 한다.

# PyCharm 가상환경 및 uv 설치 문제 해결 순서 (핵심 요약)

# 1. 터미널에서 현재 활성화된 환경 확인
# (venv가 활성화되어야 pip가 해당 환경의 패키지를 관리함)
$ python -m venv .venv
$ .venv\Scripts\activate

# 2. uv CLI 툴이 설치되지 않았을 경우를 대비한 설치 명령어
# (uv는 기본 내장되지 않으므로 first-time setup 필요)
$ pip install uv

# 3. 가상환경 내에서 패키지 설치 (예: FastAPI)
$ uv add fastapi uvicorn

총평#

오늘 오후 전체에서 배운 것#

FastAPI는 Express와 달리 () 호출로 인스턴스를 생성해야 하며, Uvicorn은 서버 역할을 FastAPI는 애플리케이션 프레임워크 역할을 분리하여 생각해야 한다. 또한 파이썬 실행 환경 설정 시 tool 설치와 PATH 확인을 우선시하고, PyCharm Interpreter와 Terminal Shell의 영역 구분을 명확히 해야 한다는 점을 오늘 배웠다.

다음에 조심할 것#

FastAPI 클래스 인스턴스 생성을 위해 () 호출을 반드시 붙여야 한다는 점을 잊지 말아야 한다. Uvicorn과 FastAPI를 ‘통로’와 ‘배우’에 비유하여 역할 분담을 명확히 하여 실행 명령어를 이해하는 것이 중요하다. 파이썬 환경 설정 시 PyCharm Interpreter와 Terminal Shell의 분리 여부를 확인하고, uv 도구가 시스템 PATH에 등록되어 있는지 점검해야 한다.

다음 복습 주제#

FastAPI는 import 문만으로는 앱이 생성되지 않고, 클래스를 호출해 인스턴스를 만들어야 한다는 점을 반드시 기억해야 한다.

Uvicorn과 FastAPI의 역할 분담을 명확히 이해하고 있어야 서버 실행 명령어와 실제 로직 설정의 관계를 오해하지 않을 수 있다.

터미널 환경 설정 시 PyCharm Interpreter와 Shell의 격차를 파악하고, uv 같은 도구가 시스템에 제대로 설치되어 PATH가 잡혀 있는지 확인하는 습관이 필요하다.
