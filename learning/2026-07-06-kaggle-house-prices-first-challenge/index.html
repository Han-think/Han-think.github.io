1. 첫 Kaggle 시도에서 질문이 바뀐 과정

House Prices는 주택의 품질, 면적, 위치, 차고, 지하실, 판매 조건으로 SalePrice를 예측하는 회귀 문제다. 처음에는 여러 회귀 모델을 돌려 가장 낮은 점수를 제출하면 된다고 생각했다. 그러나 실제 문제는 모델 개수가 아니라 데이터 의미와 검증 구조였다.

  • 결측치가 단순 누락이 아니라 시설 없음을 뜻하는 열이 있었다.
  • SalePrice는 오른쪽 꼬리가 길어 log1p 타깃이 안정적이었다.
  • GrLivArea가 매우 크지만 가격은 낮은 특이 사례가 회귀선을 흔들었다.
  • one-hot encoding 뒤 feature 수가 커지자 단순 선형의 계수가 불안정해졌다.
  • local CV가 좋아도 Kaggle public score가 그대로 따라오지 않았다.

어떤 모델이 가장 강한가가 아니라, 어떤 데이터 정책과 검증 구조에서 어떤 선형 모델을 써야 안정적인가?

2. EDA를 모델링 파이프라인으로 연결하기

EDA에서 강하게 나타난 변수는 OverallQual, GrLivArea, GarageCars, GarageArea, TotalBsmtSF, 1stFlrSF, YearBuilt, Neighborhood, ExterQual, KitchenQual, BsmtQual, GarageFinish 등이었다. 핵심은 그래프를 보고 끝내지 않고 전처리와 파생변수로 옮기는 것이었다.

의미 기반 결측치

NONE_COLS = [
    'PoolQC', 'MiscFeature', 'Alley', 'Fence', 'FireplaceQu',
    'GarageType', 'GarageFinish', 'BsmtQual', 'BsmtCond',
    'BsmtExposure', 'BsmtFinType1', 'BsmtFinType2'
]

ZERO_COLS = [
    'GarageArea', 'GarageCars', 'BsmtFinSF1', 'BsmtFinSF2',
    'BsmtUnfSF', 'TotalBsmtSF', 'BsmtFullBath', 'MasVnrArea'
]

범주형 시설이 없으면 None, 면적이나 개수가 없으면 0, 실제 미기록 가능성이 높은 LotFrontage는 Neighborhood별 중앙값으로 대체했다.

EDA 기반 파생변수

df['TotalSF'] = df['TotalBsmtSF'] + df['1stFlrSF'] + df['2ndFlrSF']
df['TotalBath'] = df['FullBath'] + 0.5*df['HalfBath'] \
                  + df['BsmtFullBath'] + 0.5*df['BsmtHalfBath']
df['HouseAge'] = df['YrSold'] - df['YearBuilt']
df['IsRemodeled'] = (df['YearBuilt'] != df['YearRemodAdd']).astype(int)
df['HasGarage'] = (df['GarageArea'] > 0).astype(int)
df['HasBsmt'] = (df['TotalBsmtSF'] > 0).astype(int)
df['OverallQual_TotalSF'] = df['OverallQual'] * df['TotalSF']

파생변수는 많이 만드는 것이 목적이 아니라 EDA에서 발견한 관계를 코드로 표현한 가설이어야 했다.

단순 선형

후속 모델이 무엇을 개선했는지 확인하는 기준선. 규제 없이 고차원 one-hot feature를 넣자 test 최대 예측이 약 1,367만 달러까지 튀었다.

기존 v1 Lasso

alpha=0.0005를 고정하고 같은 5-fold CV에서 비교했다. 이상치 524, 1299 제거 효과를 확인했다.

내 v3 LassoCV

내부 CV로 alpha를 선택하고 RobustScaler를 적용했다. L1 규제와 scaling으로 계수와 예측을 안정화했다.

조합형

Ridge·Lasso·ElasticNet OOF 예측을 섞었지만 오류가 서로 비슷해 best single을 넘지 못했다.

model = Pipeline([
    ('scaler', RobustScaler()),
    ('model', LassoCV(
        alphas=np.logspace(-5, -2, 40),
        cv=5,
        max_iter=20000,
        random_state=42,
    )),
])
정확한 해석

“정규화해서 좋아졌다”보다는 L1 규제와 Robust Scaling이 고차원 one-hot feature 공간의 계수와 예측을 안정화했다고 표현하는 것이 맞다.

4. 첫 Kaggle 제출과 local CV 차이

v3 LassoCV의 local CV는 0.110139였지만 Kaggle public score는 0.12607이었다. 차이는 +0.015931이었다. fold 안에서 전처리를 다시 학습한 CV-safe random 검증에서도 0.110101 ± 0.007142로 거의 같아 단순 전처리 누수만의 문제는 아니었다.

5. 다각적 시각을 실제 모델링에 접목하는 법

다각적 시각은 의견을 많이 모으는 것이 아니라 같은 결과를 다른 질문으로 검사하는 일이었다.

  • 데이터: 결측치는 누락인가 시설 없음인가? 이상치는 오류인가 실제 희귀 주택인가?
  • 모델: 단순 선형의 실패는 비선형 부족인가 계수 불안정인가? 앙상블 구성원이 다른 오류를 내는가?
  • 검증: random KFold만으로 충분한가? 가격대·지역별 성능은 같은가?
  • 사용자: 저가·노후 주택이나 희소 지역에서 오차가 커지면 누구에게 위험한가?

EDA로 가설 생성 → 고정된 CV로 모델 비교 → 그룹별 오류 진단 → 사용자 액션으로 연결 순서로 진행하니 관점이 뒤섞이지 않았다.

6. 수많은 선형 모델은 어떻게 나눠 써야 하나

상황우선 모델이유
가장 빠른 기준선LinearRegression출발점 확인
feature가 많고 계수가 흔들림Ridge모든 계수를 부드럽게 축소
불필요한 변수를 줄이고 싶음Lasso일부 계수를 0으로 만듦
상관된 변수 그룹ElasticNetL1과 L2를 함께 사용
alpha 고정이 어려움RidgeCV/LassoCV/ElasticNetCV내부 CV로 규제 강도 선택
이상치 영향이 큼RobustScaler + 규제 선형median/IQR 기반 scaling
오류가 다른 모델들이 있음OOF 기반 blend단일 모델 분산 완화

실전 순서는 기준선 → 규제 필요성 확인 → CV로 alpha 선택 → OOF 오류 상관 확인 → 필요한 경우 비선형 후보와 조합이었다.

7. GPT-OSS와 Hermes를 비교해 본 이유

대표적으로 GPT-OSS와 Hermes 계열 모델에 같은 실험 자료를 다른 관점으로 검토시켰다.

  • GPT-OSS에는 파이프라인 구조, 검증 누수 가능성, 코드와 실험 로그의 일치 여부를 집중적으로 질문했다.
  • Hermes에는 결과 해석, 발표 흐름, 사용자 액션으로 연결되는 설명을 집중적으로 질문했다.
역할 경계

실제 학습, CV 계산, submission 생성은 scikit-learn 코드가 수행했다. LLM은 코드 검토·설계 보조·해석 초안에 사용했다.

여러 LLM의 결론을 투표로 결정하지 않았다. 코드, OOF 예측, 실험 로그, Kaggle score로 고정된 증거표를 만든 뒤 유용한 설명만 취하고 잘못된 부분은 다시 코드와 숫자로 교정했다.

8. 어려웠던 점과 다음 액션

어려웠던 점

  1. NaN을 모두 같은 결측치로 볼 수 없었다.
  2. 이상치를 제거하면 점수는 좋아질 수 있지만 삭제 근거가 필요했다.
  3. 모델 이름은 많지만 어떤 증상을 해결하는지 구분하기 어려웠다.
  4. local CV와 public score 차이의 원인을 다시 검증해야 했다.
  5. 여러 해석을 모으는 것보다 공정한 비교 규칙을 유지하는 일이 더 어려웠다.
  6. 모델 결과를 중개인·매도자·구매자·가격 추정 플랫폼의 액션으로 바꾸는 과정이 별도 작업이었다.

다음 액션

  1. Neighborhood를 고려한 CV-safe target encoding을 실험한다.
  2. 품질형 범주에 ordinal encoding을 적용한다.
  3. 저가·노후 주택과 취약 Neighborhood의 오류를 별도 분석한다.
  4. LightGBM, XGBoost, CatBoost가 규제 선형과 다른 오류를 내는지 확인한다.
  5. 앙상블 weight를 OOF 성능뿐 아니라 예측 상관과 그룹별 오류로 조정한다.
  6. public leaderboard에 맞춘 과적합은 피한다.

총평

좋은 모델은 점수가 한 번 낮게 나온 모델이 아니라, 어떤 데이터와 검증 조건에서 왜 선택됐는지 설명할 수 있는 모델이다.

단순 선형은 실패 기준을 만들었고, 기존 Lasso는 규제와 이상치 정책의 효과를 보여줬다. v3 LassoCV는 규제 강도 선택과 scaling을 체계화했고, 조합형은 앙상블이 항상 좋아지는 것은 아니라는 사실을 확인시켰다. 비선형 모델과 그룹 검증은 선형 모델이 어디에서 약해지는지를 보여줬다.

결국 수많은 선형 모델을 전부 외우는 것보다, 각 모델이 어떤 증상을 해결하는지 구분하고 동일한 검증 구조에서 비교하는 것이 더 중요했다.
