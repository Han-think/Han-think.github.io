1. 클래스 상속#

왜 이걸 보게 됐나#

클래스 상속을 통해 자식 클래스가 부모 클래스의 메서드를 물려받고 오버라이드할 수 있다는 점을 이해하는 것이 중요합니다. 이를 통해 코드의 재사용성과 유연성을 높일 수 있습니다. 특히 type(), isinstance(), issubclass() 함수를 통해 클래스 관계를 명확히 파악할 수 있습니다.

내가 헷갈린 지점#

상속 관계에서 자식 클래스가 부모 클래스의 메서드를 어떻게 확장하거나 덮어쓰는지, 그리고 이러한 관계가 객체의 타입 확인에 어떻게 영향을 미치는지 이해하는 데 어려움이 있었습니다. 특히 DevTeam이 Department의 하위 클래스임에도 불구하고 특정 메서드 동작이 어떻게 달라지는지 명확히 파악하는 것이 헷갈렸습니다.

시도한 코드 / 예시#

# 부모 클래스 정의
class Department:
    def meeting_summary(self):
        return '일반 회의 요약'

# 자식 클래스 정의
class DevTeam(Department):
    def meeting_summary(self):
        return '개발팀 회의 요약'

class PlanningTeam(Department):
    def meeting_summary(self):
        return '기획팀 회의 요약'

# 객체 생성
dev_team = DevTeam()
planning_team = PlanningTeam()

# 메서드 호출 확인
print(dev_team.meeting_summary())  # 출력: 개발팀 회의 요약
print(planning_team.meeting_summary())  # 출력: 기획팀 회의 요약

# 타입 확인
print(type(dev_team))  # <class '__main__.DevTeam'>
print(isinstance(dev_team, Department))  # True
print(issubclass(DevTeam, Department))  # True

결과와 해석#

출력 예시:

개발팀 회의 요약
기획팀 회의 요약
<class '__main__.DevTeam'>
True
True

정리된 이해#

클래스 상속을 통해 DevTeam과 PlanningTeam은 Department 클래스의 기능을 물려받으면서도 각자의 특성을 반영한 메서드 오버라이드를 수행할 수 있습니다. type(), isinstance(), issubclass() 함수를 사용하면 이러한 상속 관계를 확인하고, 객체의 실제 타입과 클래스 계층 구조를 명확히 이해할 수 있습니다.

2. type() 확인#

왜 이걸 보게 됐나#

이해를 돕기 위해 type(), isinstance(), issubclass() 함수들이 어떻게 객체의 타입과 상속 관계를 확인하는지 구체적인 예시를 통해 설명하고자 합니다. 특히 상속 관계에서 자식 클래스가 부모 클래스의 인스턴스로 어떻게 간주되는지 명확히 파악하고자 합니다.

내가 헷갈린 지점#

상속 관계에서 자식 클래스 객체가 부모 클래스의 인스턴스로도 인식되는 이유를 이해하는 데 어려움이 있었습니다. 특히 DevTeam 객체가 Department 클래스의 인스턴스로도 isinstance() 함수를 통해 True를 반환하는 이유를 명확히 파악하지 못했습니다.

시도한 코드 / 예시#

# 부모 클래스 정의
class Department:
    def meeting_summary(self):
        return '일반 회의 요약'

# 자식 클래스 정의
class DevTeam(Department):
    def meeting_summary(self):
        return '개발팀 회의 요약'

# 객체 생성
dev_team = DevTeam()

# 타입 확인
print(type(dev_team))  # <class '__main__.DevTeam'>

# 부모 클래스 타입 확인
print(isinstance(dev_team, Department))  # True

# 하위 클래스 확인
print(issubclass(DevTeam, Department))  # True

결과와 해석#

<class ‘main.DevTeam’> True True

정리된 이해#

이 코드를 통해 DevTeam 객체가 Department 클래스의 인스턴스로도 인식되는 원리를 확인할 수 있습니다. type() 함수는 DevTeam 클래스의 타입을 명확히 보여주며, isinstance() 함수는 상속 관계 덕분에 DevTeam 객체가 Department 클래스의 인스턴스로도 간주됨을 보여줍니다. 마지막으로 issubclass()는 DevTeam이 Department의 하위 클래스임을 확인합니다.

3. isinstance() 확인#

왜 이걸 보게 됐나#

상속 관계에서 특정 객체가 상위 클래스와 하위 클래스 모두에 어떻게 속하는지 이해하기 위해 isinstance() 함수의 역할을 명확히 파악하고자 합니다. 특히, 하위 클래스가 상위 클래스의 인스턴스로도 올바르게 인식되는지 확인하는 방법을 배우고자 합니다.

내가 헷갈린 지점#

상속 구조에서 하위 클래스 객체가 상위 클래스의 인스턴스로도 확인되는 이유를 완전히 이해하는 데 어려움이 있었습니다. 특히 DevTeam이 Department 클래스의 인스턴스로도 인식되는 이유를 명확히 파악하지 못했습니다.

시도한 코드 / 예시#

dev_team = DevTeam()  # 하위 클래스 객체 생성
print(isinstance(dev_team, Department))  # True - 상속 관계로 인해
print(isinstance(dev_team, DevTeam))  # True - 직접적인 클래스 타입 확인

# 추가 예시
class HR(Department):
    def team_report(self):
        return '인사팀 보고서'

hr_team = HR()
print(isinstance(hr_team, Department))  # True
print(isinstance(hr_team, DevTeam))  # False

결과와 해석#

출력 예시:

True
True
True
False

정리된 이해#

이 섹션을 통해 isinstance() 함수가 객체의 타입을 확인할 때 상속 관계를 고려한다는 것을 이해했습니다. DevTeam 객체는 Department 클래스의 하위 클래스이므로 isinstance()를 사용해 Department 타입으로도 확인 가능하다는 점을 확인했습니다. 반면, 다른 하위 클래스인 HR은 DevTeam 타입으로는 확인되지 않는다는 점도 명확히 알게 되었습니다.

4. issubclass() 확인#

왜 이걸 보게 됐나#

상속 구조에서 특정 클래스가 다른 클래스의 하위 클래스인지 명확히 파악하고 싶었습니다. 특히, DevTeam이 Department 클래스의 하위 클래스임을 issubclass()를 통해 확인하는 방법을 이해하고 싶었습니다.

내가 헷갈린 지점#

DevTeam이 Department 클래스의 하위 클래스임에도 불구하고, 그 관계를 코드로 정확히 어떻게 표현하고 확인하는지 혼란스러웠습니다.

시도한 코드 / 예시#

print(issubclass(DevTeam, Department))  # True
print(issubclass(TeamMember, Department))  # TeamMember 클래스가 정의되지 않았으므로 결과는 None 또는 오류를 줄 수 있습니다.

결과와 해석#

True

TeamMember 클래스가 정의되지 않았으므로 실제 실행 시 오류 또는 None이 출력될 수 있습니다.#

정리된 이해#

이 섹션에서는 issubclass() 함수를 통해 DevTeam 클래스가 Department 클래스의 하위 클래스임을 확인하는 방법을 학습했습니다. 이를 통해 상속 관계를 코드로 어떻게 표현하고 확인할 수 있는지 이해할 수 있었습니다.

총평#

오늘 전체에서 배운 것#

클래스 상속 구조 이해와 type(), isinstance(), issubclass() 함수의 구체적 활용법을 익혔다. 특히 상속 관계에서 하위 클래스의 인스턴스 확인 방법이 명확해졌다.

다음에 조심할 것#

상속 관계에서 하위 클래스의 인스턴스 확인 시 isinstance() 함수의 활용 범위를 정확히 이해하는 것이 중요하다. 특히 상위 클래스와 하위 클래스 간의 관계를 명확히 파악해야 한다.

다음 복습 주제#

다형성을 통해 부모 클래스의 메소드를 자식 클래스에서 오버라이드하여 특화된 동작을 구현하는 방법을 실습을 통해 확인했다. 이를 통해 코드의 유연성과 재사용성을 높일 수 있음을 체감했다.
