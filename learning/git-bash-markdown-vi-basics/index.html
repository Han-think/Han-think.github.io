Git Bash, Markdown, vi 기초 — 내가 헷갈린 것들

CLI 처음 배울 때 헷갈렸던 것들 솔직 정리. > vs >>, # 의 이중 의미, vi 탈출법, 따옴표 차이. 명령어 암기보다 개념 이해에 집중한 기록.
2026년 5월 28일 · 3 min

터미널을 처음 쓸 때 가장 힘든 건 명령어를 모르는 것이 아니었다.
명령어는 검색하면 나온다.

진짜 힘든 건 같은 기호가 환경마다 다르게 작동한다는 것, 그리고
vi를 열었는데 나갈 수가 없다는 것이었다.

오늘은 그 혼란들을 정리해 본다.

> 와 >> — 둘 다 “파일에 쓰기"인데 왜 다른가#

처음에 이 두 기호를 배웠을 때 “파일에 저장한다"는 설명만 들었다.
그래서 둘이 같은 거라고 생각했다.

직접 써보고 나서야 차이를 알았다.

echo "첫 번째 줄" > memo.md
echo "두 번째 줄" > memo.md
cat memo.md

결과:

두 번째 줄

첫 번째 줄이 사라졌다. >는 파일을 새로 쓰기 때문이다. 기존 내용이 지워진다.

echo "첫 번째 줄" > memo.md
echo "두 번째 줄" >> memo.md
cat memo.md

결과:

첫 번째 줄
두 번째 줄

>>는 이어 쓰기다. 기존 내용 아래에 추가된다.

내가 이해한 방식:

>  = 새 종이에 처음부터 씀 (기존 내용 삭제)
>> = 같은 종이 맨 아래에 이어 씀 (기존 내용 보존)

Python을 조금 안다면 이렇게 연결할 수 있다.

open("file", "w")  →  >
open("file", "a")  →  >>

# — 문서에선 제목, 터미널에선 주석#

Markdown 파일을 편집할 때 #는 제목이다.

# 이건 H1 제목
## 이건 H2 제목

그런데 Git Bash 터미널에서 #는 주석이다.

# 이 줄은 실행되지 않음
echo "이건 실행됨"

같은 기호인데 어디서 쓰느냐에 따라 의미가 완전히 다르다.

내가 이해한 방식:

Markdown 안에서 #  →  제목
터미널 명령어 안에서 #  →  주석

한 가지 더. Markdown 파일 안의 코드 블록(```)에서는 bash 문법이 작동한다.
즉, 같은 .md 파일 안에서도 Markdown 영역과 코드 블록 영역이 다르게 해석된다.

vi — 처음엔 탈출 게임이다#

vi를 처음 열면 당황한다.
타이핑을 해도 화면에 아무것도 안 보이거나, 글자 대신 명령이 실행된다.

이유는 vi가 모드 기반 편집기이기 때문이다.
일반 편집기와 달리 “지금 내가 어느 모드에 있는지"에 따라 키보드가 다르게 작동한다.

처음엔 이것만 외우면 된다.

파일 열기      → vi 파일명
입력 시작      → i 누름 (INSERT 모드)
입력 중단      → ESC 누름 (NORMAL 모드로 복귀)
저장하고 나가기 → :wq Enter
그냥 나가기    → :q! Enter

내 표현:

VS Code = 평소 작업실
nano    = 쉬운 터미널 편집기
vi      = 야전 생존 편집기

vi를 쓰는 이유는 간단하다. SSH 서버, Docker 컨테이너, GUI 없는 환경에는
VS Code가 없다. vi는 거의 모든 Linux 환경에 기본으로 설치되어 있다.

즐겨 쓸 필요는 없다. 하지만 열었을 때 나올 수는 있어야 한다.

큰따옴표와 작은따옴표 — 실제로 다르다#

name="Hugo"
echo "Hello $name"

출력: Hello Hugo

name="Hugo"
echo 'Hello $name'

출력: Hello $name

큰따옴표 안에서는 $변수가 실제 값으로 치환된다.
작은따옴표 안에서는 내용이 그대로 보존된다.

내가 이해한 방식:

" "  = 어느 정도 해석하는 보호막
' '  = 거의 그대로 보존하는 강한 보호막

mkdir -p — 폴더 구조를 한 번에#

mkdir docs
mkdir docs/linux
mkdir docs/linux/basic

이렇게 세 번 칠 것을 -p 하나로 줄일 수 있다.

mkdir -p docs/linux/basic

중간에 없는 폴더가 있으면 알아서 만들어 준다.

오늘 개인 학습 관리 폴더 구조를
만들 때도 이 방식이 쓰였다. 명령어를 배우면서 동시에 그 명령어로
배운 것을 담는 구조를 만든다는 게 흥미로웠다.

오늘의 핵심 명령어 정리#

pwd                     # 현재 위치 확인
ls -al                  # 숨김 파일 포함 상세 목록
cd ..                   # 상위 폴더로 이동
mkdir -p 경로/폴더      # 중첩 폴더 한 번에 생성
touch 파일명.md         # 빈 파일 생성
echo "내용" > 파일.md   # 파일 새로 쓰기 (덮어씀)
echo "내용" >> 파일.md  # 파일에 이어 쓰기
rm -ri 폴더/            # 확인하면서 삭제 (초보자 권장)
