1. 사람 감지 흐름과 핵심 설정 정리#

무엇을 배웠나#

처음에는 콘솔 메시지만 출력되는 화면이 헷갈렸으나, result.plot()로 탐지 상자를 그린 이미지를 얻는다는 점을 이해하고 나니 흐름이 명확해졌다. 또한 i % 60 == 0은 프레임 수 기반이므로 영상의 FPS에 따라 실제 시간 간격이 달라질 수 있음을 깨닫고 코드를 수정했다. 마지막으로 conf=0.5가 정확도 50%가 아니라 모델의 신뢰도 임계값임을 정확히 인지하고 적용할 수 있게 되었다.

헷갈렸던 점#

처음에는 모델이 탐지를 수행했는지 확인하는 방법과 실제 영상 창이 뜨지 않을 때의 대처법을 몰랐다. 또한 i % 60 == 0이 프레임 간격인지 시간 간격인지가 명확하지 않아, 영상의 FPS에 따라 실제 초 단위 간격이 어떻게 달라지는지 감 잡기 힘들었다. 마지막으로 웹캠 입력과 영상 파일 입력을 구분하는 설정 부분도 초보자에게는 혼란스러운 요소였다.

정리된 이해#

처음에는 콘솔 메시지만 출력되는 것과 영상 창이 뜨지 않는 것 사이의 차이를 이해하는 데 어려움이 있었다. 핵심은 YOLO 모델에 classes=[0]을 지정해 사람 클래스만 탐지하도록 필터링하고, result.plot()로 시각화된 이미지를 얻더라도 실제 저장은 원본 frame이어야 한다는 점이다. 또한 i % 60 == 0은 반복문 횟수 기반이므로 영상의 FPS에 따라 실제 시간 간격이 달라질 수 있음을 반드시 고려해야 한다.

import cv2
from ultralytics import YOLO

# 모델 로드 (사용 가능한 최적의 weights 사용)
model = YOLO('yolo26n.pt')  # NVIDIA CUDA 환경에 권장되는 경량 모델

# 영상 입력 소스 설정 (0: 웹캠, 파일 경로: 로컬 영상)
source = 0  # 또는 'data/video/sample.mp4'

# 비디오 캡처 객체 초기화
cap = cv2.VideoCapture(source)

if not cap.isOpened():
    print("영상 소스를 열 수 없습니다.")
    exit()

while cap.isOpened():
    success, frame = cap.read()

    if not success:
        break

    # 60프레임마다 탐지 수행 (i % 60 == 0)
    # 실제 초 단위 간격은 영상의 FPS에 따라 달라짐 (FPS가 30이면 2초 간격 등)
    if cap.get(cv2.CAP_PROP_POS_FRAMES) % 60 == 0:
        # 사람 클래스([0])만 탐지하도록 필터링
        results = model(frame, classes=[0], conf=0.5)

        # 탐지 결과가 있을 경우
        if len(results[0].boxes) > 0:
            print(f"사람 탐지됨 (confidence 확인): {len(results[0].boxes)}개")

        # 시각화: result.plot()은 탐지 상자가 그려진 이미지를 반환
        annotated_frame = results[0].plot()

        # [중요] 저장할 때는 원본 frame에 박스를 그리지 않은 상태여야 함
        # 또는 annotated_frame을 사용하려면 저장 로직을 조정해야 함

        # cv2.imshow('YOLO Detection', annotated_frame)
        # if cv2.waitKey(1) & 0xFF == ord('q'):
        #     break
    else:
        # 탐지하지 않는 프레임은 원본 그대로 표시하거나 건너뜀
        annotated_frame = frame

    # 키 입력 대기 (실시간 영상의 경우 필수)
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()

2. 프레임 추출과 저장 간격의 오해 (Frame Extraction and Interval Misunderstanding)#

무엇을 배웠나#

처음에는 폴더 생성까지만 진행된 줄 알고 이미지 저장 기능이 누락된 것으로 생각했지만, 실제로는 cv2.imwrite()가 30프레임마다 실행되어 있었다. 특히 f_cnt % 30 == 0 코드가 원본 영상의 FPS와 연관되어 있다는 점을 명확히 이해하게 되었다. 또한, 이미지 추출과 화면 표시(imshow)는 별개의 기능이며, 임의 리사이즈 시 라벨링 좌표와 실제 위치가 어긋날 수 있음을 깨달았다.

헷갈렸던 점#

처음에는 VideoCapture로 폴더 생성까지만 진행된 줄 알고 캡처 기능이 누락된 줄 알았습니다. 하지만 최신 커밋을 확인해 보니 cv2.imwrite() 함수가 있어 30프레임마다 이미지가 저장되고 있었습니다. 이 ‘시간 차이’가 저를 혼란스럽게 만든 주된 원인이었습니다.

동영상 처리의 기본 원리를 이해할 수 있었습니다. cap.read()를 반복하면 영상의 각 프레임을 개별적인 이미지로 분리할 수 있으며, cv2.imshow()는 화면에 보여주는 기능이고 실제 파일로 저장하는 것은 cv2.imwrite() 함수입니다. 특히 f_cnt % 30 == 0 코드는 원본 영상이 30FPS일 때 1초마다 한 장씩 저장된다는 의미이며, FPS가 다르면 실제 시간 간격과 프레임 간격이 달라져 의도치 않은 결과가 나올 수 있습니다.

정리된 이해#

동영상 처리의 기본 원리는 cap.read()를 통해 영상을 개별 프레임으로 분리하고, cv2.imwrite() 함수를 사용해야 실제 파일에 저장된다는 점입니다. 특히 f_cnt % 30 == 0 코드는 영상의 FPS가 30일 때 1초 간격으로 이미지가 저장된다는 의미이므로, 원본 해상도를 유지하는 것이 라벨링 정확성을 위해 중요합니다.

import cv2

# 영상 파일 열기 (예: 'video.mp4')
cap = cv2.VideoCapture('video.mp4')

# 저장할 폴더 생성 전처리 (주석 처리된 부분)
# import os
# if not os.path.exists('dataset/source'):
#     os.makedirs('dataset/source')

f_cnt = 0

while cap.isOpened():
    ret, frame = cap.read()
    if not ret:
        break

    # 30프레임마다 이미지 저장 (원본 FPS가 30일 경우 1초 간격)
    if f_cnt % 30 == 0:
        cv2.imwrite(f'dataset/source/frame_{f_cnt}.jpg', frame)

    f_cnt += 1

cap.release()
cv2.destroyAllWindows()

3. 라벨링 준비와 데이터 계약의 이해#

무엇을 배웠나#

처음에는 GUI 툴 설치와 실행에 막막함을 느꼈지만, 영상→프레임 추출→라벨링→export→학습이라는 전체적인 흐름을 이해하는 데 집중했습니다. 특히 class ID와 이름의 순서 매핑이 모델 학습에 미치는 영향을 깨닫고, 데이터 계약에서 task·class·label·split 항목의 일치 중요성을 새롭게 인식하게 되었습니다.

헷갈렸던 점#

처음에는 GUI 툴 설치와 실행 자체가 막막해 Python 코드만 보고 감을 잡기 어려웠습니다. 특히 이미지에 그려진 박스가 YOLO 모델에 들어갔을 때 클래스 ID가 어떻게 매핑되는지 확신할 수 없어, 데이터가 다른 모델과 섞였을 때 구분하는 방법이 두려웠습니다. 결국 중요한 건 단순히 프로그램을 쓰는 것이 아니라, task와 class ID, label 포맷 등 데이터 계약이 일치해야 모델 학습이 꼬이지 않는다는 점을 깨닫게 되었습니다.

정리된 이해#

YOLO 모델을 사용하기 위해서는 이미지 라벨링 툴과 데이터 포맷팅이 필수적이며, 클래스 ID와 이름의 순서 매핑은 모델 학습에 결정적인 영향을 미칩니다. 영상 프레임을 단순히 추출하는 것보다 중복 정보를 최소화한 전략적인 데이터 구성이 필요합니다.

# LabelImg를 통한 데이터 라벨링 예시 (YOLO 형식)
# - class ID와 이름은 data.yaml 파일을 통해 매핑됩니다.
# - YOLO format: <class_id> <x_center> <y_center> <width> <height> (정규화된 값)

classes = ['person', 'car', 'bicycle']  # 클래스 이름 목록
class_ids = {name: idx for idx, name in enumerate(classes)}  # 이름 -> ID 매핑

# 예시 라벨 파일 내용 (txt format)
# person: class 0, car: class 1, bicycle: class 2
label_content = f"""0 0.5 0.5 0.2 0.3
1 0.7 0.4 0.15 0.25
2 0.3 0.6 0.25 0.2
"""

print("클래스 ID 매핑:", class_ids)
print("\n생성된 라벨 내용:\n", label_content)

총평#

오늘 오전 전체에서 배운 것#

영상 처리 파이프라인 전체 흐름(추출→표시→라벨링)을 이해하며, 프레임 간격 설정 시 FPS에 따른 시간 보정과 신뢰도 임계값의 의미를 정확히 인지하게 되었다. 특히 라벨링 데이터 계약에서 class ID와 이름의 매핑, task·class·label·split 항목 간의 일치 중요성을 새롭게 인식하여 모델 학습 준비 단계에서의 주의점을 명확히 했다.

다음에 조심할 것#

이번 주에는 영상 처리 파이프라인 전체가 하나의 흐름으로 연결된다는 점을 명확히 이해하게 되었다. 특히 프레임 추출 간격과 모델 신뢰도 임계값 설정은 영상의 FPS와 직접적으로 연관되어 있어, 이를 간과하면 의도치 않은 결과가 발생할 수 있음을 깨달았다. 앞으로는 코드 실행 전 FPS 확인과 conf 파라미터의 의미를 반드시 검증하여 불필요한 오류를 방지하겠다.

다음 복습 주제#

  1. YOLOv8 탐지 모델 파라미터와 영상 처리 로직: conf 임계값이 신뢰도인지 정확도인지, 그리고 프레임 카운트 기반 간격 코드가 원본 FPS에 어떻게 영향을 미치는지(시간 단위 vs 프레임 단위)를 정확히 구분하여 적용하는 연습을 해야 한다.

  2. 라벨링 툴 활용과 데이터 계약 설계: 영상 추출부터 라벨링, 익스포트의 전 과정이 하나의 파이프라인임을 인지하고, class ID와 이름의 매핑 규칙 및 train/valid split 비율 설정이 모델 성능에 미치는 영향을 체계적으로 검토해야 한다.

  3. 시각화와 실제 좌표 보정: result.plot()을 활용한 탐지 상자 그리기와 화면 표시(imshow)의 차이점을 명확히 하고, 임의 리사이즈 시 라벨 좌표가 실제 위치와 어긋나는 문제를 해결하기 위한 보정 로직이나 비율 유지 방법을 고민해봐야 한다.
