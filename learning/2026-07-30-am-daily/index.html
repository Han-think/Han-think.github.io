1. 배열 수정과 활용: splice() 완벽 이해하기#

무엇을 배웠나#

배열을 수정하는 splice() 함수와 복사하는 slice() 함수의 차이점을 명확히 이해하게 되었어요. splice()가 원본 배열을 직접 변경하는 반면, slice()는 새로운 배열을 만드는 것을 기억해야겠네요. 특히 splice()에서 삭제 개수를 0으로 설정하면 추가만 가능하다는 점을 확인했습니다.

헷갈렸던 점#

splice()가 여러 기능을 동시에 수행하는 방식이 복잡하게 느껴졌고, 삭제 개수가 0일 때 추가만 이루어지는 원리가 명확하지 않았습니다. 또한 slice()와 splice()의 이름이 비슷해서 원본 배열의 변경 여부를 구분하는 데 어려움을 겪었습니다.

정리된 이해#

slice()는 원본 배열을 건드리지 않고 필요한 부분만 복사해 새로운 배열을 만들지만, splice()는 원본 배열 자체를 수정하는 함수입니다. splice()는 삭제, 수정, 추가를 한 번에 처리할 수 있으며, 삭제 개수를 0으로 설정하면 추가 기능만 수행합니다. 따라서 splice()를 사용할 때는 원본 배열이 어떻게 변경될지 주의해야 합니다.

let slicedFruits = fruits.slice(2, 4); // ['포도', '배'] 복사

var fruits = ['사과', '바나나', '포도', '배', '오렌지', '복숭아'];
fruits.splice(2, 2); // ['사과', '바나나', '오렌지', '복숭아']

2. JavaScript Math 객체와 숫자 변환 완벽 가이드#

무엇을 배웠나#

JavaScript의 Math 객체에서 난수를 생성하고 범위를 조정하는 방법을 배웠습니다. 특히 Math.random()과 Math.floor() 함수의 역할을 명확히 이해했고, parseInt()와 parseFloat()는 Math 객체가 아닌 전역 함수라는 것을 알게 되었습니다. 이제 주사위와 같은 특정 범위의 난수를 생성하는 코드를 더 잘 이해하고 작성할 수 있게 되었습니다.

헷갈렸던 점#

처음에 Math.floor() 함수가 난수 생성 과정에서 어떤 역할을 하는지 잘 몰라서 0.9 * 6의 결과가 왜 6이 되는지 헷갈렸어요. 그리고 parseInt()나 parseFloat() 같은 함수들이 Math 객체에 속한 메서드라고 생각해서 당황했었네요.

정리된 이해#

Math 객체는 수학적인 상수와 함수들을 제공하며, 난수 생성 시 Math.random()과 Math.floor()를 조합하여 원하는 범위의 정수를 만들 수 있다. parseInt()와 parseFloat()는 Math 객체의 메서드가 아니라, 전역 함수로서 문자열을 숫자로 변환하는 역할을 한다. 주사위처럼 특정 범위의 난수를 생성하려면 Math.random()으로 난수를 만든 후, Math.floor()로 내림하여 원하는 범위의 값으로 조정해야 한다.

let diceRoll = Math.floor(Math.random() * 6) + 1;

3. JavaScript 연산자와 자동 형변환 완벽 해설#

무엇을 배웠나#

JavaScript에서 증감 연산자의 동작 방식과 문자열 연산 시 자동 형변환이 일어나는 점을 확실히 이해하게 되었습니다. 특히 ++num와 num++의 차이와 문자열 연산 시 숫자 계산이 어떻게 이루어지는지 명확해졌습니다. 이를 통해 코드를 더 정확하게 예측하고 디버깅할 수 있을 것 같습니다.

헷갈렸던 점#

문자열 연산에서 +만 결합을 하고 나머지는 숫자 연산으로 해석되는 점이 이해가 안 갔고, 증감 연산자의 전위/후위 연산 시점 차이도 헷갈렸습니다. 특히 삼항 연산자를 복잡하게 중첩해서 사용할 때 가독성이 떨어져서 코드를 이해하기 어려웠습니다.

정리된 이해#

증감 연산자는 전위 연산자는 값을 먼저 증가시키고 후위 연산자는 값을 먼저 사용한 뒤 증가시킨다는 점을 이해했다. 또한, JavaScript에서 문자열과 숫자를 혼합하여 연산할 때, 숫자처럼 해석될 수 있는 문자열은 자동 형변환이 이루어져 계산이 진행된다는 점을 기억해야겠다.

var num = 10;
console.log(++num);
console.log(num++);

4. 비교·논리 연산자와 deprecated 이해#

무엇을 배웠나#

비교 연산자 ==와 ===의 차이, 특히 ==가 자동 타입 변환을 수행한다는 점을 명확히 이해하게 되었고, 이를 통해 예상치 못한 오류를 방지할 수 있음을 알게 되었다. deprecated된 키워드와 권장되지 않는 관행의 차이를 구분하는 것의 중요성을 깨달았으며, 논리 연산자 활용 예시를 통해 조건문 작성 능력을 향상시킬 수 있을 것 같다. 앞으로 코드를 작성할 때 비교 연산자와 논리 연산자를 더욱 신중하게 사용해야겠다.

헷갈렸던 점#

= 와 == 비교 연산자를 쓸 때, 할당 연산자를 사용하는 건지 값 비교를 하는 건지 혼동했어요. 특히 ==가 자동으로 타입을 변환한다는 점이 예상 밖이었고, ==와 ===의 차이를 명확히 이해하지 못했습니다. var 키워드가 완전히 deprecated되었는지, 아니면 그냥 권장되지 않는 건지 구분하는 데 어려움이 있었습니다.

정리된 이해#

비교 연산자에서 =는 할당이고 ==는 타입 변환 후 비교, ===는 값과 자료형 모두 같아야 비교가 되는 것을 명확히 이해하게 되었어. 또한 var 키워드는 현재 사용하지 않는 것은 아니지만, let과 const를 사용하는 것이 더 현대적인 방법이라는 것을 알게 되었어. 이 점들을 기억하고 앞으로 코딩할 때 주의해야겠어.

console.log(2 == '2');
console.log(2 === '2');
console.log(false == 0);
console.log(false === 0);
console.log('' == false);
console.log('' === false);
console.log(null == undefined);
console.log(null === undefined);

let flag = true;
flag = !flag;

5. if 조건문과 검증 실습: 자연어 조건 변환 및 구문 오류 해결#

무엇을 배웠나#

자연어 조건을 JavaScript 조건문으로 정확하게 변환하는 과정에서 어려움을 겪었지만, 비교 연산자, 논리 연산자, 그리고 if문 구조에 대한 이해를 높일 수 있었습니다. 특히 기본적인 구문 오류를 해결하고, 직각삼각형 판별 시 피타고라스 정리를 활용하는 방법을 깨달았습니다. 앞으로는 이 지식을 바탕으로 더 복잡한 조건문과 검증 함수를 작성할 수 있을 것입니다.

헷갈렸던 점#

자연어 조건을 코드로 변환하는 과정에서 어떤 조건을 어떻게 표현해야 할지 감이 잘 잡히지 않았고, JavaScript 구문 오류에 대한 이해가 부족하여 간단한 조건문 작성에도 어려움을 겪었습니다. 특히 비교 연산자와 논리 연산자를 정확하게 사용하는 방법을 명확히 이해하지 못했습니다.

정리된 이해#

자연어 조건을 JavaScript 코드로 변환하는 과정에서 어려움이 있었지만, 비교 연산자와 논리 연산자를 제대로 활용하여 복합적인 조건을 만들 수 있게 되었습니다. 특히, if문 구조를 정확히 이해하고, 피타고라스 정리를 활용한 직각삼각형 판별 문제 해결 방법을 익혔습니다. 앞으로는 이러한 경험을 바탕으로 더욱 정확하고 효율적인 코드를 작성할 수 있을 것입니다.

function isValidEmail(email) {
  if (typeof email !== 'string' || email.length < 5 || email.indexOf('@') === -1 || email.indexOf('.') === -1) {
    return false;
  }
  return true;
}

6. 객체 배열 필터링: 배열 요소 접근 및 조건 이해#

무엇을 배웠나#

객체 배열에서 특정 조건을 만족하는 객체를 골라내는 과정에서 배열과 객체에 대한 이해가 부족해서 오류가 발생했지만, 배열의 각 요소가 객체라는 점과 JavaScript의 대소문자 구분에 주의하며 문제를 해결했습니다. a가 배열 전체를 나타내고 a[i]가 배열의 각 객체를 의미한다는 것을 명확히 이해하게 되었습니다. 앞으로 객체 배열을 다룰 때 a의 의미를 혼동하지 않도록 주의해야겠습니다.

헷갈렸던 점#

처음에는 객체 배열을 다루는 과정에서 a가 하나의 객체라고 착각해서 객체 속성에 접근할 때 a.age처럼 사용하려고 했어요. 또 함수 이름을 정확히 입력하지 않아서 대소문자 구분에 대한 이해가 부족했다는 점도 실수를 유발했습니다. 이 두 가지 오해 때문에 코드가 예상대로 작동하지 않아 어려움을 겪었습니다.

정리된 이해#

객체 배열에서 특정 조건을 만족하는 객체를 찾을 때, 배열 전체를 a가 가리키고 각 객체는 a[i]로 접근해야 한다는 것을 명확히 이해하게 되었습니다. JavaScript는 대소문자를 엄격하게 구분하므로 함수 이름을 정확히 사용하는 것이 중요합니다. 이제 배열 내 객체들의 속성에 접근하는 방식에 대한 혼란은 사라졌습니다.
