1. DSPy 입출력 계약과 모듈의 관계#

무엇을 배웠나#

DSPy는 LLM 프로그램을 설계할 때 입력과 출력을 정의하는 ‘서명’과 실제 논리를 처리하는 ‘모듈’을 분리하여 구성하는 프레임워크입니다. 처음에는 이미지 모델인 줄 알았지만, 기존 프롬프트 엔지니어링과의 연결 고리를 파악하며 그 구조를 이해할 수 있었습니다. 특히 ChainOfThought가 모델의 성능을 높여주는 것이 아니라 문제 해결 방식을 선택하는 모듈이라는 점이 명확해졌습니다. 마지막으로 입력과 출력 계약 사이의 순서를 정하는 것이 DSPy 사용에서 중요한 포인트임을 배웠습니다.

헷갈렸던 점#

DSPy를 처음 접할 때 가장 큰 혼란은 ‘이미지 처리 모델인가?‘라는 오해였습니다. 또한 ChainOfThought가 단순히 모델의 성능을 높여주는 기능인 줄 알았으나, 실제로는 문제 해결 방식을 선택하는 모듈일 뿐임을 깨닫고 이해가 깊어졌습니다. 마지막으로 입력과 출력의 계약(서명)과 실제 실행 코드 사이의 순서를 혼동하기 쉽지만, DSPy에서는 계약을 먼저 정의한 뒤 모듈을 올리는 구조라는 점이 가장 중요했습니다.

정리된 이해#

DSPy는 LLM 기반 프로그램을 설계할 때 ‘입출력 계약(Signature)‘과 ‘실행 전략(Module)‘을 분리하여 정의하는 프레임워크입니다. 먼저 어떤 데이터를 입력받아 무엇을 반환할지 계약을 체결한 뒤, 그 위에 ChainOfThought나 Predict 같은 모듈을 올려 실제 추론 로직을 구성합니다. 이를 통해 프롬프트 작성에 집중하기보다 프로그램의 구조적 설계와 유지보수에 효율성을 높일 수 있습니다.

# DSPy 입출력 계약 정의 예시 (초보자 워킹 노트 기준)

from dspy import Module, Predict, InputField, OutputField

class SimpleQA(Module):
    # 1. Signature (입출력 계약) 정의
    # question: str -> answer: str 형태의 계약을 선언
    question = InputField(desc="사용자가 질문한 내용")
    answer = OutputField(desc="모델이 생성할 답변")

    # 2. Module (실행 전략) 설정
    # ChainOfThought 모듈을 사용하여 계약에 맞는 처리를 수행
    student = Predict(question=question, answer=answer)

2. YOLO 환경 차이와 핵심 파라미터 정리#

무엇을 배웠나#

YOLO 실습을 진행하며, 하드웨어에 따른 PyTorch 백엔드의 차이를 이해하게 되었습니다. NVIDIA GPU용 CUDA 코드를 그대로 실행하면 인텔 XPU 환경에서는 인식되지 않아서, 기기별로 적절한 런타임 설정이 필수적임을 깨달았습니다. 또한 conf 파라미터가 모델의 정확도를 의미하는 것이 아니라, 탐지 결과를 걸러내는 신뢰도 임곗값이라는 점을 명확히 구분할 수 있었습니다. finally, source, save, conf 등 핵심 인자들을 통해 YOLO 예측 과정을 체계적으로 제어할 수 있다는 흐름을 잡았습니다.

헷갈렸던 점#

처음 YOLO 실습을 시작했을 때 가장 큰 혼란은 “내 컴퓨터(인텔 XPU/아크)에서 강사님의 CUDA 예제를 똑같이 따라 할 수 있을까?” 였습니다. torch.cuda.is_available()가 False로 뜨면서 GPU가 없다고 나왔지만, 저는 인텔 아크 카드를 쓰고 있었고 PyTorch도 XPU를 지원하는 버전을 설치해 두었던 터라 당황스러웠습니다.

또 하나의 헷갈린 부분은 conf=0.5 였습니다. 이건 모델의 정확도를 50%로 보장하는 숫자인가 싶었는데, 실제로는 **“얼마나 확신하는지(신뢰도) 기준으로 결과를 걸러내는 임곗값”**이었습니다. 이 부분을 모르고 있으면 점수가 낮은 사물은 안 잡힌다고 생각하다가 실수할 것 같아서 꼭 정리하고 싶었습니다.

정리된 이해#

YOLO 모델을 실행할 때 하드웨어에 맞는 백엔드(CUDA 또는 XPU)를 정확히 설정하는 것이 필수적이며, conf 파라미터는 탐지 결과를 걸러내는 신뢰도 임곗값임을 명확히 이해해야 한다.

# YOLO 모델 로드 (학습된 가중치 파일 불러오기)
model = YOLO('yolo26n.pt')

# 이미지 예측 실행
# source: 이미지 또는 비디오 파일 경로
# conf: 신뢰도 임곗값 (0.5 이상인 경우만 탐지 수행)
# save: 결과 이미지를 저장할지의 여부
results = model.predict(source='test.jpg', conf=0.5, save=True)

# CUDA와 XPU 환경 확인 예시
import torch
if torch.cuda.is_available():
    device = 'cuda'
elif hasattr(torch, 'xpu') and torch.xpu.is_available():
    device = 'xpu'
else:
    device = 'cpu'

print(f"사용 중인 디바이스: {device}")

3. YOLO 상자좌표와 Confidence 해석하기#

무엇을 배웠나#

YOLO 결과 해석 시 좌표 형태(xyxy와 xywh)가 섞여 있어 위치 파악에 혼란이 있었으며, Confidence 점수가 모델 전체 성능 지표가 아니라 개별 예측 신뢰도임을 명확히 이해하게 되었다. 또한 박스 좌표 변환, 클래스 라벨 매핑, confidence 임계값 설정 등 4단계를 통해 원시 데이터를 시각화 가능한 형태로 가공하는 과정을 체계적으로 학습했다.

헷갈렸던 점#

처음 YOLO 결과를 볼 때 x1, y1과 center_x가 동시에 등장해 좌표 체계가 혼동되었습니다. 또한 Confidence 점수가 모델 전체의 정확도를 의미하는 것으로 오해했으나, 실제로는 개별 사각형 내 객체 식별에 대한 신뢰도임을 알게 되었습니다.좌표 변환(Class xyxy/xywh)과 클래스 번호 매핑, 그리고 임계값 기반 Confidence 필터링 과정을 거쳐야만 사람이 해석할 수 있는 결과로 만들 수 있습니다.

정리된 이해#

YOLO 모델은 xyxy 또는 xywh 형태의 좌표와 클래스 ID, 신뢰도 점수를 반환하며, 이를 통해 실제 물체의 위치와 종류를 파악할 수 있다. Confidence 점수는 모델이 특정 사각형 안에 포함된 객체에 대해 얼마나 확신하는지를 나타내는 개별 예측 지표이며, 임계값을 설정해 불필요한 탐지를 걸러내거나 표시 방식을 조정할 수 있다. finally, 좌표를 이미지 크기에 맞게 변환하고 클래스 이름을 매핑하여 Matplotlib나 OpenCV 같은 시각화 도구에 사각형을 그리면 사람이 이해하기 쉬운 결과 이미지를 얻을 수 있다.

# YOLO 탐지 결과 시각화를 위한 핵심 코드

results = model.predict(source="test.jpg", conf=0.25)[0]

for box in results.boxes:
    # 1. 좌표 변환 (xyxy 형태를 사용 assumed)
    x1, y1, x2, y2 = box.xyxy[0].tolist()

    # 2. 클래스 라벨 매핑
    cls_id = int(box.cls[0])
    label = results.names[cls_id]

    # 3. Confidence 필터링 및 표시
    conf = float(box.conf[0])

    # 시각화 (OpenCV 예시)
    color = (0, 255, 0) # 초록색
    cv2.rectangle(img, (int(x1), int(y1)), (int(x2), int(y2)), color, 2)
    cv2.putText(img, f"{label} {conf:.2f}", (int(x1), int(y1)-10),
                cv2.FONT_HERSHEY_SIMPLEX, 0.5, color, 2)

오늘 오전 전체에서 배운 것#

DSPy는 입력과 출력을 정의하는 ‘서명’과 논리를 처리하는 ‘모듈’을 분리하여 LLM 프로그램을 설계하는 프레임워크이며, ChainOfThought 같은 모듈이 모델의 성능 자체를 높이는 것이 아니라 문제 해결 방식을 선택하는 도구임을 이해했습니다. 또한 YOLO 실습을 통해 하드웨어에 따른 PyTorch 백엔드의 차이와 conf 파라미터가 정확도보다는 신뢰도 임곗값임을 구분했으며, 좌표 변환과 confidence 설정을 통해 원시 데이터를 시각화 가능한 형태로 가공하는 4단계 과정을 체계적으로 학습했습니다.

다음에 조심할 것#

DSPy에서는 입력과 출력의 계약 순서를 반드시 확인하여 모듈 연결 오류를 방지해야 하며, YOLO 실습 시 하드웨어에 맞는 백엔드 설정과 conf 파라미터가 신뢰도 임계값임을 정확히 구분하는 것이 중요하다.
