1. 로그인 버튼 활성화 및 JavaScript 문법 오류 해결#

무엇을 배웠나#

로그인 버튼 활성화 기능을 구현하는 과정에서 JavaScript 문법 오류, 특히 alert 함수 사용 시 괄호의 중요성을 깨달았다. 입력 조건 로직과 별개로 코드 전체가 실행되지 않아 오류가 발생할 수 있다는 점을 알게 되었고, keyup 이벤트와 classList 조작을 활용하여 동적인 UI를 구현하는 방법을 익혔다. 앞으로는 코드를 작성할 때 오타나 문법 오류에 더욱 주의하여 디버깅해야겠다는 생각을 했다.

헷갈렸던 점#

버튼이 안 활성화되는 이유를 입력 조건 로직에 문제가 있다고 생각했는데, 알고 보니 스크립트 자체가 실행되지 않았다는 걸 몰랐다. alert 함수를 사용할 때 괄호를 안 써서 에러가 발생했고, 이 때문에 다른 함수들이 실행되지 않았던 것이다. 이 사소한 문법 오류 때문에 문제를 해결하는 데 오래 걸렸다.

정리된 이해#

로그인 버튼 활성화 문제의 원인은 예상과 달리 입력 조건 로직이 아니라 JavaScript 문법 오류, 특히 alert 함수 호출 시 소괄호 누락이었다. 아이디와 비밀번호 입력 시 keyup 이벤트를 활용하여 버튼 색상을 변경하고, 로그인 성공 여부를 별도로 확인하는 방식으로 코드를 수정했다. 이 과정을 통해 JavaScript 문법 오류 추적의 중요성을 깨달았다.

function activateBtn() {
    if (id.value && pw.value) {
        loginButton.classList.add("activatedColor");
        loginButton.classList.remove("deactivatedColor");
    } else {
        loginButton.classList.add("deactivatedColor");
        loginButton.classList.remove("activatedColor");
    }
}

id.addEventListener("keyup", activateBtn);
pw.addEventListener("keyup", activateBtn);

if (id.value === "일반사용자ID" && pw.value === "일반비밀번호") {
    alert("로그인 성공!");
} else {
    alert("아이디 또는 비밀번호를 확인해 주세요.");
}

3. 화살표 함수, this, 호이스팅: 초보자를 위한 핵심 정리#

무엇을 배웠나#

화살표 함수에 대한 기본 개념과 ES6 문법의 축약 표현 방식을 이해하게 되었고, 일반 함수와 화살표 함수 간의 this 키워드 동작 방식 차이를 명확히 인지하게 되었다. 특히 이벤트 핸들러에서 this의 동작을 제대로 파악하고 evt.currentTarget을 사용하는 이유를 알게 되어, 더욱 안전한 코딩을 할 수 있을 것 같다. 앞으로 화살표 함수를 좀 더 자신 있게 활용할 수 있을 것 같다.

헷갈렸던 점#

처음에는 화살표 함수라는 새로운 문법이 기존 함수와 어떻게 다른지, 특히 this 키워드가 어떻게 동작하는지 이해하는 데 어려움을 느꼈습니다. 이벤트 핸들러에서 this가 왜 예상과 다르게 작동하는지, 그리고 evt.currentTarget을 사용해야 하는 이유도 명확하지 않았습니다. 이러한 점들을 명확히 이해하고 정리하여 앞으로 화살표 함수를 활용하는 데 도움이 되도록 학습했습니다.

정리된 이해#

화살표 함수는 ES6에서 도입된 간결한 함수 표현 방식이며, 일반 함수와 달리 자체적인 this 컨텍스트를 가지지 않고 호출되는 위치의 this를 상속받습니다. 따라서 이벤트 핸들러에서 this 대신 evt.currentTarget을 사용해야 하는 이유는 화살표 함수의 this가 예상과 다르게 동작할 수 있기 때문입니다. 이 두 가지 차이점을 이해하는 것이 화살표 함수를 정확하게 활용하는 데 중요합니다.

       });

헷갈렸던 점#

처음에는 세 개의 <i> 요소를 전기 회로처럼 생각해서 하나가 켜지면 나머지가 자동으로 꺼진다고 생각했어요. 또 HTML 라디오 버튼처럼 같은 그룹 내에서 자동으로 하나만 활성화되는 걸 기대했지만, <i> 요소는 그런 기능이 없다는 점이 헷갈렸습니다.

5. setTimeout과 setInterval 활용법: 시간 제어 및 진행 관리#

무엇을 배웠나#

setTimeout과 setInterval 함수의 차이점을 명확하게 이해하게 되었고, setInterval을 사용할 때 반환되는 타이머 식별값을 저장하여 나중에 중지할 수 있다는 점을 알게 되었습니다. 또한, 타이머를 제어하는 변수를 먼저 정의하고 사용하는 것이 중요하다는 것을 깨달았습니다. 실습 예제를 통해 시간 제어 함수의 작동 방식을 더 잘 이해할 수 있었습니다.

헷갈렸던 점#

처음에는 setTimeout과 setInterval의 사용법을 제대로 이해하지 못하고, 특히 setInterval에서 반환되는 타이머 식별값을 저장하고 사용하는 부분에서 어려움을 느꼈습니다. 또한, 타이머를 중지하는 clearInterval 함수를 사용할 때, 타이머 식별값을 저장하는 변수가 정의되지 않아 오류가 발생하는 상황을 해결하지 못했습니다. 복잡한 예제를 풀 때 각 타이머의 역할을 명확하게 구분하지 못해 전체적인 흐름 파악이 어려웠습니다.

정리된 이해#

setTimeout은 함수를 딱 한 번 실행하는 함수이고, setInterval은 특정 간격으로 반복 실행하는 함수라는 것을 명확히 이해했습니다. setInterval을 사용할 때는 반드시 반환되는 타이머 식별값을 변수에 저장하고, clearInterval()을 사용하여 반복을 멈춰야 한다는 점을 깨달았습니다. 이제는 타이머를 제어하는 코드를 작성할 때, 타이머 식별값을 잊지 않고 사용할 수 있을 것 같습니다.

var i = 0;
var time;
var h1 = document.getElementById("cnt");

time = setInterval(function() {
    i++;
    h1.innerHTML = i;
    if (i >= 10) clearInterval(time);
}, 100)

6. 옵셔널 체이닝과 템플릿 리터럴, 초보자를 위한 완벽 이해#

무엇을 배웠나#

옵셔널 체이닝은 객체 속성 접근 시, 값이 undefined나 null일 때 에러를 방지하고 안전하게 undefined를 반환하는 방법이라는 것을 알게 되었습니다. 템플릿 리터럴에서는 변수가 null일 경우에도 에러 없이 처리할 수 있도록 null 체킹이나 기본값 설정을 고려해야 함을 배웠습니다. 이 두 개념을 통해 코드를 더욱 안전하고 간결하게 만들 수 있을 것 같습니다.

헷갈렸던 점#

옵셔널 체이닝을 사용할 때 어떤 값이 undefined인지, 언제 붙여야 하는지 판단하기 어려웠어요. 템플릿 리터럴에서 변수가 null일 경우 어떻게 처리해야 하는지, 에러가 발생하는 조건에 대한 이해가 부족했습니다. 실제 코드 적용 시 어떻게 활용해야 할지 감이 잘 잡히지 않았습니다.

정리된 이해#

옵셔널 체이닝은 객체 속성에 접근할 때, 속성값이 null이나 undefined일 경우 에러를 발생시키지 않고 안전하게 undefined를 반환하도록 해주는 편리한 기능이다. 템플릿 리터럴은 변수나 표현식을 문자열 안에 삽입하여 문자열을 조합하는 데 사용되며, 변수가 null일 경우에도 에러를 방지하기 위해 조건부 렌더링이나 기본값을 제공하는 방식으로 처리할 수 있다. 중요한 점은 옵셔널 체이닝은 체이닝되는 모든 값이 존재할 필요는 없지만, 템플릿 리터럴 안에서는 변수가 존재하지 않으면 에러가 발생할 수 있다는 것이다.

const user = { contact: { email: 'example@example.com' } };
console.log(user.contact?.email);

const emptyUser = {};
console.log(emptyUser.contact?.email);

7. 동적 쇼핑 목록 구현과 자동 채점 문제 해결#

무엇을 배웠나#

동적 쇼핑 목록 실습에서 자동 채점 오류가 발생했을 때, 단순히 코드가 작동하는 것 외에 채점 시스템이 기대하는 DOM 구조와 텍스트 내용의 정확한 일치 여부가 중요하다는 것을 알게 되었습니다. 특히 버튼 텍스트와 함수 정의 방식이 중요하며, 채점 기준에 맞춰 코드를 수정해야 함을 배웠습니다. 이 과정을 통해 자동 채점 시스템의 작동 방식을 조금 더 이해하게 되었습니다.

헷갈렸던 점#

자동 채점 결과가 0점인 이유가 코드 자체의 기능적 오류 때문인지, 아니면 채점 기준과 나의 결과물의 불일치인지 확신이 서지 않았습니다. 특히 버튼 텍스트와 DOM 구조의 미세한 불일치가 채점 시스템에 큰 영향을 미칠 수 있다는 점을 인지하지 못했습니다. 함수 정의 방식에 대한 주의가 필요했고, 기존 함수를 수정하는 것이 아니라 기존 함수를 재정의하면 안 된다는 점을 깨달았습니다.

정리된 이해#

자동 채점 시스템은 코드 실행 결과뿐만 아니라, 기대하는 DOM 구조와 텍스트 내용까지 정확히 일치해야 제대로 작동한다는 점을 알게 되었습니다. 특히, 버튼 텍스트와 함수 정의 방식에 주의해야 했으며, 채점 기준에 명시된 정확한 내용과 형식을 따라야 했습니다. 이번 경험을 통해 자동 채점 시스템의 평가 기준을 더 명확하게 이해하게 되었습니다.

8. Rest Operator 활용법: 함수 인자 처리 및 재귀 함수 응용#
