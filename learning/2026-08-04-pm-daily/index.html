전역 변수와 지역 변수의 관계, 그리고 중첩 함수 내에서 변수가 어떻게 검색되는지 이해하는 데 어려움을 느꼈습니다. 특히 변수가 어떤 스코프에서 찾히는지 시각적으로 따라가기 어려웠고, 여러 스코프가 얽히면 추적하는 과정이 복잡하게 느껴졌습니다.

2. 화살표 함수, this, 호이스팅: 초보자를 위한 핵심 정리#

무엇을 배웠나#

화살표 함수에 대한 기본 개념과 ES6 문법의 축약 표현 방식을 이해하게 되었고, 일반 함수와 화살표 함수 간의 this 키워드 동작 방식 차이를 명확히 인지하게 되었다. 특히 이벤트 핸들러에서 this의 동작을 제대로 파악하고 evt.currentTarget을 사용하는 이유를 알게 되어, 더욱 안전한 코딩을 할 수 있을 것 같다. 앞으로 화살표 함수를 좀 더 자신 있게 활용할 수 있을 것 같다.

헷갈렸던 점#

처음에는 화살표 함수라는 새로운 문법이 기존 함수와 어떻게 다른지, 특히 this 키워드가 어떻게 동작하는지 이해하는 데 어려움을 느꼈습니다. 이벤트 핸들러에서 this가 왜 예상과 다르게 작동하는지, 그리고 evt.currentTarget을 사용해야 하는 이유도 명확하지 않았습니다. 이러한 점들을 명확히 이해하고 정리하여 앞으로 화살표 함수를 활용하는 데 도움이 되도록 학습했습니다.

정리된 이해#

화살표 함수는 ES6에서 도입된 간결한 함수 표현 방식이며, 일반 함수와 달리 자체적인 this 컨텍스트를 가지지 않고 호출되는 위치의 this를 상속받습니다. 따라서 이벤트 핸들러에서 this 대신 evt.currentTarget을 사용해야 하는 이유는 화살표 함수의 this가 예상과 다르게 동작할 수 있기 때문입니다. 이 두 가지 차이점을 이해하는 것이 화살표 함수를 정확하게 활용하는 데 중요합니다.

       });

3. 옵셔널 체이닝과 템플릿 리터럴, 초보자를 위한 완벽 이해#

무엇을 배웠나#

옵셔널 체이닝은 객체 속성 접근 시, 값이 undefined나 null일 때 에러를 방지하고 안전하게 undefined를 반환하는 방법이라는 것을 알게 되었습니다. 템플릿 리터럴에서는 변수가 null일 경우에도 에러 없이 처리할 수 있도록 null 체킹이나 기본값 설정을 고려해야 함을 배웠습니다. 이 두 개념을 통해 코드를 더욱 안전하고 간결하게 만들 수 있을 것 같습니다.

헷갈렸던 점#

옵셔널 체이닝을 사용할 때 어떤 값이 undefined인지, 언제 붙여야 하는지 판단하기 어려웠어요. 템플릿 리터럴에서 변수가 null일 경우 어떻게 처리해야 하는지, 에러가 발생하는 조건에 대한 이해가 부족했습니다. 실제 코드 적용 시 어떻게 활용해야 할지 감이 잘 잡히지 않았습니다.

정리된 이해#

옵셔널 체이닝은 객체 속성에 접근할 때, 속성값이 null이나 undefined일 경우 에러를 발생시키지 않고 안전하게 undefined를 반환하도록 해주는 편리한 기능이다. 템플릿 리터럴은 변수나 표현식을 문자열 안에 삽입하여 문자열을 조합하는 데 사용되며, 변수가 null일 경우에도 에러를 방지하기 위해 조건부 렌더링이나 기본값을 제공하는 방식으로 처리할 수 있다. 중요한 점은 옵셔널 체이닝은 체이닝되는 모든 값이 존재할 필요는 없지만, 템플릿 리터럴 안에서는 변수가 존재하지 않으면 에러가 발생할 수 있다는 것이다.

const user = { contact: { email: 'example@example.com' } };
console.log(user.contact?.email);

const emptyUser = {};
console.log(emptyUser.contact?.email);

4. Rest Operator 활용법: 함수 인자 처리 및 재귀 함수 응용#

무엇을 배웠나#

Rest Operator는 함수의 매개변수들을 하나의 배열로 묶어주는 역할을 하며, Spread Operator와 구분해서 이해해야 한다는 점을 알게 되었다. 특히 Rest Operator의 사용 위치와 재귀 함수에서의 활용 방식이 처음에는 헷갈렸지만, 예시 코드를 통해 조금 더 명확하게 이해할 수 있었다. 앞으로는 이 지식을 바탕으로 다양한 함수를 작성해 보면서 실력을 키워나가야겠다.

헷갈렸던 점#

Rest Operator와 Spread Operator를 구분하는 데 어려움이 있었고, 재귀 함수에서 head와 tail을 분리하여 나머지 인자를 넘기는 부분이 이해가 잘 안 되었습니다. 특히 재귀 호출이 반복되는 과정이 복잡하게 느껴졌습니다.

정리된 이해#

Rest Operator는 함수에서 나머지 인자들을 하나의 배열로 묶어주는 역할을 하며, 매개변수 목록의 마지막에 위치해야 합니다. Spread Operator와 혼동하지 않도록 주의해야 하며, 재귀 함수에서는 배열을 head와 tail로 나누고 tail을 Rest Operator로 처리하는 부분이 핵심입니다. 이러한 이해를 바탕으로 다양한 함수 구현에 활용할 수 있습니다.

5. 배열 메서드 활용법: forEach, map, filter, sort 완벽 가이드#

무엇을 배웠나#

배열 처리 메서드 선택에 어려움을 겪었는데, forEach, map, filter, sort 각각의 역할과 반환값을 명확히 이해하게 되었다. forEach는 작업을 수행, map은 요소 변환, filter는 조건 만족 요소 추출, sort는 정렬임을 기억해야겠다. 중복 선언 실수도 줄이고, 각 메서드의 목적에 맞춰 적절한 코드를 작성할 수 있을 것 같다.

헷갈렸던 점#

배열 메서드들을 보면서 각각의 역할이 비슷해 보여서 언제 어떤 걸 써야 할지 혼란스러웠다. 특히 forEach, map, filter는 기존 for문과 어떻게 연결되는지 파악하는 데 어려움을 느꼈다. 또한, 코드를 작성할 때 배열 선언과 함수 적용 부분을 헷갈려 중복 선언하는 실수를 자주 했다.

정리된 이해#

배열 처리 메서드는 각자 명확한 목적을 가지고 있으며, forEach는 단순히 각 요소를 처리하고, map은 변환된 요소를 담은 새 배열을, filter는 조건을 만족하는 요소만 담은 새 배열을 생성합니다. sort는 배열 자체를 정렬하는 역할을 합니다. 이들을 상황에 맞게 선택하고 사용하는 것이 중요합니다.

const qualifiedBooks = bestsellers.filter(book => book.price > 20);

const sortedCities = cities.sort((a, b) => a.population - b.population);

무엇을 배웠나#

구조 분해 할당 시 변수 이름을 너무 짧게 사용하면 코드를 이해하기 어려워지고, 속성이 없을 때 사용할 기본값을 제대로 이해하지 못했음을 깨달았습니다. 앞으로는 가독성을 위해 의미 있는 변수 이름을 사용하고, 기본값은 속성 자체가 없는 경우에 사용된다는 점을 기억해야겠습니다. 실습 예시를 통해 작업 객체와 이벤트 객체에서 필요한 필드를 효율적으로 추출하는 방법을 익혔습니다.

헷갈렸던 점#

객체 분해 할당 시 짧은 별칭을 사용하면 변수 의미를 파악하기 어려워 코드 가독성이 떨어지고, 기본값을 설정하는 부분에서 객체 속성을 새로 추가하는 것으로 착각했습니다. 별칭 사용과 기본값 설정에 대한 이해가 부족하여 학습 효율이 낮았습니다.

정리된 이해#

구조 분해 할당 시에는 변수 이름이 의미 있도록 길게 쓰는 것이 코드 가독성을 높이는 데 중요하다. 특히 기본값을 설정할 때, 객체에 새로운 속성을 추가하는 것이 아니라 속성이 없을 때 사용할 값을 지정하는 것임을 명확히 이해해야 한다. 이러한 점들을 인지하고 실습을 통해 적용하면 더욱 효율적인 코드를 작성할 수 있을 것이다.

7. 스프레드 연산자와 Rest 문법 완벽하게 이해하기#

무엇을 배웠나#

Spread 연산자와 Rest 문법이 같은 기호를 사용하지만 역할이 다르다는 것을 명확히 이해하게 되었어요. Spread 연산자는 배열을 펼치고, Rest 문법은 함수 매개변수를 처리합니다. 특히 Spread 연산자의 얕은 복사 개념과 중첩 객체 참조 문제는 앞으로 주의해야 할 부분인 것 같습니다.

헷갈렸던 점#

처음에는 Spread 연산자와 Rest 문법이 모두 ... 기호를 사용해서 어떤 차이가 있는지 파악하기 어려웠고, Spread 연산자가 얕은 복사를 한다는 개념과 그로 인해 발생하는 문제점(중첩 객체 참조)을 이해하는 데 시간이 걸렸습니다. 얕은 복사가 실제로 어떻게 동작하는지 시각적으로 확인하고 다양한 예제를 통해 직접 코드를 작성하면서 그 차이를 명확하게 알게 되었습니다.

정리된 이해#

Spread 연산자는 배열이나 문자열을 펼쳐서 개별 요소로 만들고, 얕은 복사를 수행하여 중첩된 객체는 참조를 공유합니다. Rest 문법은 함수에서 여러 인자를 받아들이는 데 사용되며, Spread 연산자와는 역할이 다릅니다. 이 둘의 차이점을 명확히 이해하고, 얕은 복사의 한계점을 인지하는 것이 중요합니다.

오늘 오후 전체에서 배운 것#

스코프 체인과 화살표 함수의 this, 호이스팅을 다시 확인하고 옵셔널 체이닝과 템플릿 리터럴을 정리했다. Rest·Spread, 구조 분해 할당과 forEach·map·filter·sort를 연결해 ES6 문법이 데이터 처리에서 어떻게 쓰이는지 살펴봤다.
