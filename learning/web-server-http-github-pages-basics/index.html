웹 서버와 GitHub Pages — 내 PC를 서버로 켜둬야 하나?

처음 블로그를 만들 때 가장 헷갈렸던 것 — 내 컴퓨터가 꺼지면 블로그도 꺼지나? 로컬 서버와 공개 서버, GitHub Pages의 차이를 솔직하게 정리했다.
2026년 5월 28일 · 2 min

내가 처음 가진 공포#

블로그를 만들겠다고 Hugo를 설치하고, hugo server 를 실행했다.

로컬호스트에서 사이트가 뜨자마자 갑자기 무서운 생각이 들었다.

내가 컴퓨터를 끄면 이 블로그도 꺼지는 건가?

이 질문이 헷갈린 이유는 “서버"라는 단어 하나에 너무 많은 개념이 묶여 있기 때문이다.

로컬 서버 = 임시 미리보기#

hugo server 로 켜는 서버는 내 컴퓨터 안에서만 열린다.

http://localhost:1313

이 주소는 나만 볼 수 있다. 인터넷에 열려있지 않다. 내가 터미널 창을 닫으면 이 서버도 사라진다.

정리: 로컬 서버는 글을 쓰면서 “어떻게 보이는지 확인하는 미리보기"다.

GitHub Pages = 공개 호스팅#

GitHub Pages에 올라간 블로그는 내 PC가 꺼져도 열린다.

왜냐하면 파일이 내 컴퓨터가 아니라 GitHub 서버에 저장되어 있기 때문이다.

내 PC = 글 쓰고, 빌드하고, git push 하는 작업장
GitHub Pages = 그 결과물을 24시간 공개하는 서버

내 PC는 “항상 켜야 하는 서버"가 아니다. 내 PC는 “작업하고 업로드하는 작업장"이다.

Hugo는 서버가 아니다#

혼동하기 쉬운 것:

도구 역할
Hugo Markdown → HTML 파일 생성
hugo server 로컬 미리보기용 (개발 중에만 사용)
GitHub Pages 정적 파일을 인터넷에 공개
GitHub 저장소 파일 저장 및 버전 관리

Hugo는 “변환 도구"다. 직접 인터넷에 파일을 올리지 않는다. 내가 git push를 해야 GitHub Pages가 그 파일을 공개한다.

HTTP는 뭔가#

브라우저가 사이트를 여는 과정은 이렇다.

브라우저: 이 주소의 페이지 주세요.
서버: 여기 HTML 파일입니다.

이게 HTTP request-response 구조다.

정적 사이트에서는 서버가 미리 만들어진 HTML 파일을 그냥 전달하면 된다. 복잡한 계산이나 데이터베이스가 필요 없다.

정적 사이트가 맞는 이유#

로그인, 댓글, 실시간 데이터가 필요한 사이트는 백엔드 서버가 필요하다.

하지만 블로그에 필요한 건:

글 목록
글 내용
태그/카테고리 페이지

이건 정적 파일로 충분하다. GitHub Pages가 이 역할을 무료로 해준다.

정리#

처음 가졌던 공포의 정답:

내 PC가 꺼져도 블로그는 살아있다.
GitHub Pages가 24시간 대신 서비스하기 때문이다.

hugo server 는 글 쓸 때만 켜는 미리보기 도구다. 글을 완성하고 git push 하면 내 PC 없이도 블로그가 공개 상태로 유지된다.

English Technical Summary#

Key Concepts#

  • Local server (hugo server): accessible only at localhost:1313, stops when terminal closes
  • GitHub Pages: static file hosting by GitHub — survives PC shutdown
  • Hugo: static site generator (Markdown → HTML), not a hosting service
  • HTTP: request-response protocol between browser and server
  • Static site: pre-built HTML/CSS/JS files served as-is (no server-side computation)

My Setup Flow#

Write Markdown → hugo build → git push → GitHub Pages serves HTML
