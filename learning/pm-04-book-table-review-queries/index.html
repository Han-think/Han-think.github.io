1. 데이터 변화#

왜 이걸 보게 됐나#

DELETE 명령어를 실행하고 나서 SELECT 결과가 달라지는 것을 보고, 데이터베이스의 상태가 쿼리 실행 결과에 직접적으로 영향을 미친다는 것을 깨달았습니다. 이전에는 데이터가 항상 존재한다고 생각하고 쿼리를 짰었는데, 데이터 변경이 결과에 영향을 주는 것을 알게 되면서 데이터베이스의 상태를 고려하는 쿼리 작성의 중요성을 인지하게 되었습니다.

내가 헷갈린 지점#

DELETE 명령을 실행했는데, 그 뒤에 바로 SELECT 쿼리를 돌려보니 데이터가 사라져서 당황스러웠어요. 마치 데이터베이스의 내용이 갑자기 변하는 마법처럼 느껴졌었죠. 데이터의 일관성을 당연하게 생각해서, 쿼리 실행 순서에 따른 결과 변화를 예상하지 못했습니다.

시도한 코드 / 예시#

-- DELETE 명령을 실행한 후 SELECT 쿼리를 실행했을 때 결과가 달라지는 예시
DELETE FROM book WHERE id = 1;
SELECT * FROM book;

결과와 해석#

DELETE 명령을 실행하여 book 테이블에서 특정 레코드를 삭제한 후 SELECT 쿼리를 실행했을 때, 삭제된 레코드가 결과에 나타나지 않는 것을 확인했습니다. 이는 데이터베이스의 내용은 실시간으로 반영된다는 점을 보여주며, 쿼리 실행 시점의 데이터 상태에 따라 결과가 달라질 수 있다는 것을 알게 되었습니다. 따라서 데이터 변화를 고려하여 쿼리를 다시 실행해야 정확한 결과를 얻을 수 있습니다.

정리된 이해#

데이터베이스의 내용은 변경될 수 있으며, DELETE 명령을 실행하면 데이터가 실제로 삭제됩니다. 따라서 SELECT 쿼리를 다시 실행하면 삭제된 데이터는 결과에 포함되지 않아 이전과는 다른 결과를 보여줄 수 있습니다. 데이터 변경은 쿼리 결과에 직접적인 영향을 미치므로 항상 유념해야 합니다.

2. LIKE 연산자#

왜 이걸 보게 됐나#

제목에 특정 단어가 들어간 책을 검색하는 쿼리를 작성하려고 할 때, 예상했던 결과가 나오지 않아서 원인이 무엇인지 파악하려고 했습니다. 특히 제목에 ‘the’라는 단어가 포함된 책을 찾으려고 했는데, 대소문자 구분을 어떻게 해야 하는지 몰라서 검색이 제대로 되지 않았습니다. 그래서 LIKE 연산자의 활용법과 SQLite의 대소문자 구분 방식을 배우게 되었습니다.

내가 헷갈린 지점#

처음에 LIKE 연산자를 사용할 때, 데이터베이스마다 대소문자 구분이 어떻게 달라지는지 몰라서 조건을 정확하게 설정하는 데 어려움을 겪었습니다. 예상과 달리 검색 결과가 나오지 않아서, WHERE절 전체를 다시 확인하는 번거로움이 있었습니다. 또한, 와일드카드 문자(%)의 위치에 따라 검색 결과가 달라지는 점도 처음에는 직관적으로 이해하지 못했습니다.

시도한 코드 / 예시#

SELECT * FROM book WHERE title LIKE '%the%';

결과와 해석#

LIKE 연산자를 사용하여 제목에 ’the’가 포함된 책을 검색해봤는데, SQLite는 대소문자를 구분하지 않아서 ‘The’나 ’the’ 모두 검색할 수 있었습니다. 쿼리 SELECT * FROM book WHERE title LIKE '%the%'를 실행했을 때, 제목에 ’the’가 들어간 책들이 결과로 나왔고, 이는 LIKE 연산자가 패턴 매칭을 통해 데이터를 찾는데 유용하다는 것을 보여줍니다. 이렇게 패턴 검색을 통해 원하는 데이터를 효율적으로 찾을 수 있다는 점이 인상 깊었습니다.

정리된 이해#

SQLite에서 LIKE 연산자를 사용하면 특정 패턴을 포함하는 데이터를 찾을 수 있는데, 중요한 점은 SQLite가 대소문자를 구분하지 않기 때문에 % 기호를 활용하여 원하는 패턴을 검색할 수 있습니다. 예를 들어, 제목에 “the"가 포함된 책을 찾을 때는 '%' || 'the' || '%'와 같이 문자열 결합을 사용할 필요 없이 바로 '%the%'로 쿼리를 작성할 수 있습니다. 이를 통해 문자열 검색 조건을 유연하게 설정할 수 있습니다.

3. WHERE 절#

왜 이걸 보게 됐나#

데이터를 추출하는 쿼리를 작성하다 보면, 전체 데이터가 아닌 특정 조건에 맞는 데이터만 보고 싶을 때가 많았어요. 그래서 ‘WHERE 절’을 배우게 됐는데, 원하는 조건만 걸러서 필요한 정보만 보여주는 방법을 익히게 되니 데이터 분석의 기본이 되는 중요한 개념이라는 걸 알게 됐습니다. 예를 들어, 특정 가격 이상의 책만 보여주거나, 제목에 특정 단어가 포함된 책만 검색할 수 있게 됐죠.

내가 헷갈린 지점#

처음에 WHERE 절을 사용할 때 어떤 조건을 정확히 어떻게 표현해야 하는지 막연하게 느껴졌어요. 단순한 숫자 비교는 이해했지만, 문자열 패턴 매칭이나 여러 조건을 조합하는 방식은 어떻게 해야 하는지 감이 잘 안 잡혔습니다. 특히, AND와 OR을 어떻게 활용해야 하는지에 대한 이해가 부족해서, 원하는 결과를 얻기 어려웠어요.

시도한 코드 / 예시#

SELECT * FROM book WHERE price >= 40;

결과와 해석#

WHERE 절은 특정 조건을 만족하는 데이터만 선택하는 데 사용돼요. 예를 들어, WHERE price > 100 조건을 사용하면 가격이 100보다 큰 책만 결과로 보여줘서, 원하는 조건에 맞는 데이터만 빠르게 찾을 수 있었어요. 이 기능을 활용하여 특정 가격대 또는 특정 키워드를 포함하는 책을 필터링하는 연습을 했답니다.

정리된 이해#

WHERE 절은 테이블에서 특정 조건을 만족하는 데이터만 선택할 수 있도록 해주는 핵심적인 기능입니다. 조건을 명확히 설정해야 원하는 데이터만 얻을 수 있으며, 조건에는 다양한 비교 연산자와 패턴 매칭을 활용할 수 있습니다. 이를 통해 데이터의 일부분만 조회하여 분석하거나 필요한 정보만 추출할 수 있습니다.

4. ORDER BY#

왜 이걸 보게 됐나#

책 정보 테이블에서 데이터를 나열할 때, 원하는 순서대로 보여줘야 했기 때문에 ORDER BY를 배우게 됐어. 예를 들어, 가격이 높은 책부터 낮은 책 순으로 보여주거나, 출판일이 최근 순으로 정렬해서 보여주는 등 다양한 방식으로 정렬할 필요가 있었거든. 정렬 기능을 사용하면 데이터를 훨씬 효율적으로 분석하고 활용할 수 있다는 것을 깨달았어.

내가 헷갈린 지점#

처음에 ORDER BY를 사용할 때 어떤 컬럼을 기준으로 정렬할지 정확히 이해하지 못해서, 결과가 예상과 다르게 나오곤 했습니다. 특히 ASC와 DESC의 의미를 명확히 몰라서 오름차순, 내림차순 정렬을 제대로 활용하지 못했습니다. 다른 컬럼을 기준으로 정렬하는 방법도 처음에는 어떻게 적용해야 할지 막막했습니다.

시도한 코드 / 예시#

SELECT * FROM book ORDER BY price DESC;

결과와 해석#

ORDER BY price DESC를 사용했을 때, 책 테이블의 모든 책 정보가 가격을 기준으로 내림차순으로 정렬되어 나타났습니다. 즉, 가격이 가장 높은 책부터 낮은 책 순으로 결과가 표시되었고, 이 명령어를 통해 특정 기준에 따라 데이터를 정렬하는 방법을 익힐 수 있었습니다. 이를 통해 원하는 정보의 순서대로 데이터를 확인하고 분석하는 것이 가능하다는 것을 알게 되었습니다.

정리된 이해#

ORDER BY절은 SELECT 결과의 순서를 정렬하는 데 사용되며, ASC는 오름차순, DESC는 내림차순으로 정렬할 수 있습니다. 예를 들어 가격을 기준으로 책 목록을 높은 가격부터 낮은 가격 순서로 보여주고 싶다면 ORDER BY price DESC를 사용합니다. 이를 통해 원하는 기준으로 데이터를 정렬하여 분석하거나 사용자에게 보여줄 수 있습니다.

총평#

오늘 전체에서 배운 것#

DELETE 명령을 사용한 후 SELECT 쿼리의 결과가 달라지는 점을 이해하게 되었고, SQLite의 LIKE 연산자가 대소문자를 구분하지 않는다는 사실을 알게 되어 검색 조건을 더 효과적으로 설정할 수 있게 되었습니다. 또한 WHERE절과 ORDER BY절을 활용하여 데이터를 필터링하고 정렬하는 방법을 다시 한번 복습했습니다.

다음에 조심할 것#

DELETE 문 실행 후 SELECT 쿼리 결과가 달라지는 것을 항상 기억하고, 데이터가 변경될 때마다 다시 확인해야겠다. LIKE 연산자를 사용할 때는 대소문자 구분을 고려하지 않는다는 점을 명심하고, 검색 조건을 설정할 때 주의해야겠다.

다음 복습 주제#

LIKE 연산자의 대소문자 구분 규칙을 좀 더 확실하게 이해하고, 다양한 WHERE 절 조건을 조합하는 연습을 해야겠다. 또한, ORDER BY 절을 활용하여 복합적인 정렬 조건을 만들어보는 것도 필요할 것 같다.
