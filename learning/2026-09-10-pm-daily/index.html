1. LangChain과 Ollama로 구현한 챗 스트리밍 흐름#

무엇을 배웠나#

LangChain은 단순한 CLI 도구가 아니라 LLM을 연결해 실제 애플리케이션을 구성하는 오케스트레이션 프레임워크이며, chain.stream()과 StreamingResponse는 LLM의 chunk 생성 과정과 HTTP 전송 계층으로 구분된다. 또한 ChatPromptTemplate을 사용해 시스템 프롬프트와 대화 이력을 관리하고, LCEL 문법인 prompt | model을 활용하면 체인을 간결하게 구성할 수 있다.

헷갈렸던 점#

LangChain이 단순한 CLI 도구인지 오케스트레이션 레이어인지 구분하지 못해 혼란스러웠습니다. 특히 chain.stream()과 StreamingResponse가 LLM 내부 처리와 HTTP 전송 계층이라는 점에서 개념이 혼동되었습니다.

정리된 이해#

LangChain은 CLI 도구가 아니라 LLM 기반 애플리케이션을 구성하는 오케스트레이션 프레임워크이며, chain.stream()과 StreamingResponse는 LLM의 chunk 생성 과정과 HTTP 전송 계층으로 구분된다.

2. LM Studio 환경에 맞춘 LangChain 적응기#

무엇을 배웠나#

LangChain 코드를 그대로 따라 하면 ChatOllama 같은 특정 라이브러리 함수에 의존하게 되어 환경이 다르면 수업 내용을 놓칠까 봐 걱정했습니다. 하지만 공통 구조인 프롬프트와 체인은 동일하며, 실제 모델 호출 부분만 Provider별로 다를 뿐이라는 점을 명확히 구분할 수 있었습니다. 결국 저는 LangChain의 ChatOpenAI를 사용해 OpenAI 호환 인터페이스를 통해 LM Studio에 접속하는 방식으로 변환했습니다.

헷갈렸던 점#

처음에는 ChatOllama 같은 특정 라이브러리 함수에 의존하는 것처럼 보여서, LM Studio 환경에서 핵심 내용을 놓치지 않을까 걱정했습니다. 하지만 수업을 통해 공통 구조(prompt, history 등)와 Provider별 차이점(실제 모델 호출 부분)을 명확히 구분할 수 있게 되었습니다. 결국 강사님의 흐름보다 제 작업 환경에 더 부합하는 방식으로 재구성하며, Provider layer를 직접 조절할 수 있는 유연함을 얻었습니다.

정리된 이해#

LangChain의 ChatOpenAI 모듈을 사용하면 Ollama 코드와 유사한 흐름을 유지하면서 LM Studio 환경에 맞게 모델을 로딩할 수 있어, Provider layer를 직접 조작하지 않고도 기존 학습 내용을 빠르게 적용할 수 있다. 핵심적인 LLM 상호작용 구조인 프롬프트, 히스토리, 체인, 스트리밍 등은 공급자 변경과 무관하게 동일하게 유지되며, 저는 OpenAI-compatible 어댑터를 통해 LM Studio와 연결하는 방식을 선택해 유연성을 확보했습니다.

from langchain_openai import ChatOpenAI

# LM Studio가 기본적으로 제공하는 로컬 주소와 API 키를 사용합니다.
model = ChatOpenAI(
    base_url="http://localhost:1234/v1",
    model_name="local-model",  # LM Studio에서 사용하는 모델 이름
    temperature=0.7
)

3. tool 함수 로직 수정 및 agent pipeline 완성하기#

무엇을 배웠나#

tool 함수가 단순히 a * b로 구현된 것을 보고 처음에는 오타라고 생각했으나, 실제 코드베이스에 그대로 존재한다는 사실에 당황했다. 이는 tool이 올바르게 작동하지 않으면 agent가 신뢰할 수 있는 결과를 도출할 수 없다는 점을 깨닫게 해주었다. 가장 시급한 과제는 덧셈, 뺄셈, 나눗셈 연산 로직을 수정하여 tool의 기능을 정상화하는 것이다.

헷갈렸던 점#

가장 큰 혼란은 tool 함수들의 구현 오류였습니다.

수업 시간에 multiply 함수가 a * b인 것은 이해가 갔지만, 나머지 세 함수까지 전부 같은 코드를 쓰고 있는 것을 보고 **“이건 분명 오타나 임시 작성일 거야”**라고 생각했습니다. 하지만 실제 Git repository 상태를 확인하니까 실제로 그런 코드가 존재해서 당황했습니다. “강사님이 의도적으로 문제를 남겨둔 건가? 아니면 아직 완성되지 않은 초안인가?“라는 질문이 들었고, source code만으로는 확인이 불가능해서 답답함을 느꼈습니다. tool이 제대로 작동하지 않으면 agent가 올바른 결과를 내놓을 수 없는데, 어떻게 학습해야 할지 막막했죠.

핵심 학습 포인트

가장 중요한 것은 tool 함수 자체의 코드보다, 다음과 같은 agent loop입니다.

LLM이 tool을 선택 → argument 생성 → tool 실행 → result를 다시 LLM이 사용 → final answer

정리된 이해#

tool 함수가 올바르게 구현되지 않으면 agent가 원하는 결과를 도출할 수 없다는 점을 뼈저리게 느꼈습니다. 특히 plus, minus, divide 함수까지 전부 a * b로 작성된 것을 보고 코드 검증의 중요성을 절실히 체감했습니다. 다음 단계에서는 실제 연산 로직을 수정하고, tool이 정상적으로 호출되는지 확인하며 agent loop가 어떻게 동작하는지 직접 검증해보는 것이 시급한 과제입니다.

# tool 함수 수정 전 (오류 포함)
def plus(a, b):
    return a * b  # 오류: 더하기를 곱셈

def minus(a, b):
    return a * b  # 오류: 빼기를 곱셈

def divide(a, b):
    return a * b  # 오류: 나누기를 곱셈

# tool 함수 수정 후 (정상)
def plus(a, b):
    return a + b  # 덧셈 연산으로 수정

def minus(a, b):
    return a - b  # 뺄셈 연산으로 수정

def divide(a, b):
    if b == 0:
        raise ZeroDivisionError("0으로는 나눌 수 없습니다.")
    return a / b  # 나눗셈 연산으로 수정

4. 에이전트 구조와 실행 흐름의 이해#

무엇을 배웠나#

에이전트의 핵심은 특정 LLM 공급자에 국한되지 않고, 모델·도구·에이전트·실행이라는 네 가지 층으로 구성된다는 점을 명확히 했습니다. 강사님의 빠른 피드백 방식과 구조적인 분리를 통해 ‘계약(contract)‘을 이해하는 것이 무엇보다 중요하다는 사실을 깨달았습니다. 이를 기반으로 실제 환경에서 제공자별 세부 설정을 유연하게 적용할 수 있는 설계 역량이 필요하다고 느꼈습니다.

헷갈렸던 점#

에이전트 구현에서 가장 큰 혼란은 **‘도구와 모델의 경계’**와 **‘실행 흐름’**에 있었습니다. 특히 LM Studio나 OpenAI 호환 API를 사용하려 할 때, 기존 강사님 방식과의 연동이 원본을 망가뜨릴까 봐 불안했습니다. 또한 ChatOllama와 @tool 연결 뒤에는 model object, tool 정의, prompt instruction라는 각각의 계약이 있지만, 이들이 메모리 위에서 어떻게 상호작용하는지 감 잡기 어려웠습니다.

두 번째로, create_agent()를 정확히 어떻게 호출해야 하는지와 인자로 무엇을 넘겨줘야 하는지에 대한 버전 의존적인 부분이 있어 실습 중 오류가 날까 봐 긴장되었습니다.

정리된 이해#

에이전트 시스템은 ‘모델’, ‘도구’, ‘실행’이라는 네 가지 핵심 층(layer)으로 구성되며, 각 층 사이의 계약(contract)을 이해하는 것이 가장 중요합니다. 특정 LLM 공급자(Ollama/OpenAI)에 얽매이지 않고 이 구조를 유연하게 분리하면 다양한 환경에 맞춰 에이전트를 완성할 수 있습니다.

# Cleaner Approach: Agent Architecture Structure

from typing import List, Optional
from abc import ABC, abstractmethod

class ModelInterface(ABC):
    """Abstract base for model providers (Ollama, OpenAI, etc.)"""

    @abstractmethod
    def generate(self, prompt: str, tools: Optional[List] = None) -> str:
        pass

class ToolDefinition:
    """Encapsulates tool metadata and execution logic"""

    def __init__(self, name: str, description: str, func):
        self.name = name
        self.description = description
        self.func = func

class AgentService:
    """Core agent orchestration logic"""

    def __init__(self, model: ModelInterface, tools: List[ToolDefinition]):
        self.model = model
        self.tools = {t.name: t for t in tools}

    def execute(self, user_input: str) -> str:
        # 1. Prepare prompt with tool instructions
        tool_instructions = "\n".join(
            f"{t.name}: {t.description}"
            for t in self.tools.values()
        )
        full_prompt = f"{tool_instructions}\nUser: {user_input}"

        # 2. Generate response from model
        response = self.model.generate(full_prompt, list(self.tools.values()))

        # 3. Execute if tool call detected
        if response.startswith("Tool:"):
            tool_name = response.split(":")[1].strip()
            tool = self.tools.get(tool_name)
            if tool:
                result = tool.func()
                return f"Result: {result}"

        return response

# Usage Example
if __name__ == "__main__":
    # Mock model implementation
    class OllamaModel(ModelInterface):
        def generate(self, prompt, tools=None):
            # In real usage: returns LLM output potentially with tool calls
            return "Tool: calculator"  # Simulated tool call

    # Define tools
    def calculate():
        return "42"

    calc_tool = ToolDefinition(
        name="calculator",
        description="Performs mathematical calculations",
        func=calculate
    )

    # Initialize and run
    model = OllamaModel()
    agent = AgentService(model, [calc_tool])
    result = agent.execute("What is 6*7?")
    print(result)  # Output: Result: 42

총평#

오늘 오후 전체에서 배운 것#

LangChain은 LLM 연결 및 애플리케이션 오케스트레이션을 위한 프레임워크이며, ChatPromptTemplate과 StreamingResponse를 활용해 프롬프트 관리와 스트리밍 전송 계층을 분리할 수 있다. 또한 tool의 로직 수정 없이 agent가 신뢰할 수 있는 결과를 도출하지 못한다는 점을 깨닫고, 덧셈·뺄셈·나눗셈 연산 기능을 정상화하여 pipeline을 완성하는 것이 시급한 과제였다.

다음에 조심할 것#

다음에는 tool 함수 로직이 실제 비즈니스 요구사항을 충실히 반영하는지 반드시 검증한 뒤 agent pipeline에 적용해야겠다. 또한 provider별 모델 호출 인터페이스를 추상화해 LangChain 코드를 환경 변경 없이 유연하게 재구성할 수 있도록 설계하는 습관을 들일 것이다. 마지막으로 에이전트 실행 전 각 tool의 연산 로직이 올바르게 동작하는지 단위 테스트를 수행하여 신뢰성을 확보하는 과정을 반드시 거칠 계획이다.
