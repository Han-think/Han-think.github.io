1. Conditional Edge: State와 Router를 거쳐 LLM 출력을 실제 노드로 연결하는 다리#

무엇을 배웠나#

Conditional Edge는 LLM의 출력을 바로 실행하는 것이 아니라, State와 Router를 거쳐 실제 노드를 선택하는 간접적인 파이프라인 구조라는 점을 명확히 이해하게 되었다. 특히 분석 결과를 State에 저장한 뒤, 별도의 라우팅 함수가 키를 반환해야만 해당 노드가 실행된다는 흐름이 핵심이었다. 이를 통해 기존의 게이트나 라우터 개념과 유사하면서도 LangChain 특유의 구조적 장치임을 실감할 수 있었다.

헷갈렸던 점#

LLM의 판단 결과가 곧바로 다음 단계로 연결되는 것이 아니라, State와 Router를 거쳐야 실제 노드가 선택된다는 점이 가장 큰 오해였습니다.

Conditional Edge는 현재 State를 기준으로 routing key를 결정하는 장치이며, LLM의 텍스트 출력을 구조화된 실행 흐름으로 변환하는 다리 역할을 합니다.

정리된 이해#

Conditional Edge는 현재 State를 기준으로 다음 단계의 routing key를 결정하는 장치이며, LLM의 분석 결과를 실제 함수 실행으로 연결하기 위해 State와 Router라는 중간 매개체를 거친다. 즉, LLM의 출력을 구조화된 결정으로 변환하여 State에 반영하고, 이를 기반으로 적절한 Node로 분기시키는 파이프라인 역할을 한다.

# Conditional Edge 파이프라인 구조 (State → Router → Key → Node)

from typing import Literal

# 1. State: LLM 분석 결과를 저장하는 컨텍스트
class AgentState:
    dept: str = ""  # billing 또는 technical

# 2. Analyzer: LLM이 질문을 분석하여 state에 라벨링
def analyzer(question: str) -> AgentState:
    # 실제 구현에서는 LLM 호출 후 응답 파싱
    # 여기서는 예시 로직으로 분류
    if "요금" in question or "결제" in question:
        return AgentState(dept="billing")
    elif "오류" in question or "수리" in question:
        return AgentState(dept="technical")
    else:
        return AgentState(dept="unknown")

# 3. Router 함수: State를 검사하고 routing key 반환
def router(state: AgentState) -> str:
    # state.dept 값을 기준으로 다음 노드 결정
    if state.dept == "billing":
        return "billing"
    elif state.dept == "technical":
        return "tech"
    else:
        return "unknown"

# 4. Mapping: routing key에 해당하는 실제 실행 함수 (Node)
def billing_node():
    print(">>> Billing department node executing...")

def tech_node():
    print(">>> Technical department node executing...")

def unknown_node():
    print(">>> Unknown department node executing...")

# --- 실행 흐름 예시 ---
question = "내 청구서가 안 왔어요."

# Step 1: analyzer가 LLM 분석 결과를 state에 기록
state = analyzer(question)
print(f"[Analyzer] classified dept as: {state.dept}")

# Step 2: router 함수가 State를 확인하여 key 결정
routing_key = router(state)
print(f"[Router] determined key: {routing_key}")

# Step 3: mapping된 Node 실행
if routing_key == "billing":
    billing_node()
elif routing_key == "tech":
    tech_node()
else:
    unknown_node()

2. LangGraph Loop·Tool·Human in the Loop 구조 정리#

무엇을 배웠나#

LangGraph에서 Loop는 단순한 반복이 아니라, 그래프 구조 내에 사이클을 만들어 조건에 따라 노드를 순환시키는 방식이다. Tool은 LLM이 외부 기능을 호출하면 tool node가 실행되고 결과가 ToolMessage를 통해 상태에 누적되어 에이전트로 돌아오는 흐름이며, Human in the Loop는 그래프를 일시 정지시킨 후 사람의 승인이나 수정을 받은 뒤 checkpointer를 통해 상태를 보존한 채 재개하는 과정이다.

헷갈렸던 점#

LangGraph에서 Loop는 단순한 반복문이 아니라, 그래프 구조 자체에 사이클을 만들어 이전 노드로 돌아가는 방식이며, Tool은 LLM이 외부 기능을 호출했을 때 결과가 ToolMessage를 통해 상태에 누적되어 에이전트로 복귀하는 흐름이고, Human in the Loop는 그래프를 일시 정지시킨 후 사람의 승인을 받은 뒤 checkpointer를 통해 상태를 보존한 채 재개한다는 점이었다.

정리된 이해#

LangGraph에서 Loop는 Python의 while문이 아니라, 그래프 구조 자체에 사이클을 만들어 조건에 따라 이전 노드로 돌아가는 방식이다.

Tool은 LLM이 외부 기능을 호출하면 tool node가 실행되고 결과가 ToolMessage를 통해 상태에 누적되어 agent로 복귀하는 흐름이며, 상태를 overwrite 대신 add_messages로 쌓아올리는 것이 핵심이다.

Human in the Loop는 그래프를 일시 정지시킨 후 사람의 승인이나 수정을 받은 뒤 checkpointer를 통해 상태를 보존한 채 재개하는 방식으로, 단순히 입력을 받는 것을 넘어 상태 유지와 재개가 필수적이다.

# LangGraph Loop, Tool, Human in the Loop 핵심 구조 예시

from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.base import CheckpointMetadata
from typing import TypedDict, Annotated
import operator

# 1. Loop (사이클 구조)
# Edge를 타고 이전 노드로 돌아가는 구조.
# 조건에 따라 그래프 내부를 순환함.

def loop_example():
    graph = StateGraph(dict)

    # 간단한 순환 구조: A -> B -> C -> A (조건에 따라)
    graph.add_node("A", lambda state: {"step": "A"})
    graph.add_node("B", lambda state: {"step": "B"})
    graph.add_node("C", lambda state: {"step": "C"})

    # Loop: C에서 A로 다시 연결 (사이클 생성)
    graph.add_edge(START, "A")
    graph.add_edge("A", "B")
    graph.add_edge("B", "C")
    graph.add_edge("C", "A")  # 이 한 줄이 Loop(순환)를 만듦
    graph.add_conditional_edges("C", lambda x: "END" if x.get("count", 0) > 2 else "A")

    return graph

# 2. Tool (도구 호출 및 상태 누적)
# LLM이 도구를 호출하면 tool node가 실행되고,
# 결과는 ToolMessage를 통해 message state에 쌓임.

class State(TypedDict):
    messages: Annotated[list, operator.add]  # add_messages: 상태를 overwrite하지 않고 누적

def tool_example():
    # tool 사용 시 메시지가 stack처럼 쌓림
    pass  # 실제 구현 시 @tool decorator와 tool node가 필요

# 3. Human in the Loop (인간 개입 및 상태 보존)
# interrupt로 그래프 일시정지 후, checkpointer로 state 보존 후 재개.

def human_in_the_loop_example():
    from langgraph.checkpoint.sqlite import SqliteSaver

    memory = SqliteSaver.from_conn_string(":memory:")

    graph = StateGraph(dict)
    graph.add_node("human_approval", lambda s: s)  # 인간 입력 대기 노드

    # interrupt_before: 그래프를 일시정지 시킴
    # interrupt_after: 승인 후 상태를 보존하고 재개
    graph.add_edge(START, "human_approval")
    graph.set_entry_point("human_approval")

    # checkpointer가 있어야 state가 디스크/메모리에 저장되어 재개가 가능함
    app = graph.compile(checkpointer=memory)
    return app

# 실행 예시 (실제 LangGraph 환경에서 사용)
if __name__ == "__main__":
    print("Loop, Tool, Human in the Loop 구조 정의 완료")

3. 인프라 개념 잡기: 온프레미스·가상화·WSL2 이해하기#

무엇을 배웠나#

오늘 수업을 통해 ‘On-premise’가 내 PC에 LM 스튜디오를 설치한 상태와 같다는 점을 명확히 이해했습니다. 또한 가상화 기술이 물리적 자원을 논리적으로 분할하여 여러 환경을 구현하는 핵심 개념임을 깨닫고, WSL2가 단순한 편의 기능이 아니라 인프라 계층의 가상화라는 사실에 놀랐습니다. 특히 하이퍼바이저와 VM이라는 용어가 낯설었지만, 이 모든 것이 내 현재 로컬 환경과 어떻게 연결되는지 감을 잡는 소중한 시간이 되었습니다.

헷갈렸던 점#

WSL2가 단순히 윈도우에서 리눅스 명령어를 쓰는 편의 도구인지, 아니면 실제 인프라 계층의 가상화 기술인지에 대해 큰 혼란을 느꼈습니다. 또한 물리적인 하드웨어 위에서 여러 개의 가상 머신을 실행하게 만드는 ‘하이퍼바이저’와 ‘가상화’ 개념이 낯설어, 현재 제 로컬 환경(윈도우 + LM 스튜디오)이 이러한 인프라 구조와 어떻게 연결되는지 감을 잡기 어려웠습니다.

정리된 이해#

나는 현재 윈도우 PC에 LM 스튜디오를 올려둔 온프레미스 환경에서 작업하고 있으며, 물리적 자원을 논리적으로 분리해주는 가상화 기술과 WSL2의 존재를 통해 인프라 계층이 어떻게 내 코드를 실행하는지 이해하게 되었다.

On-premise (온프레미스): "내 thing이 내 장비에서 돌아간다." 회사나 개인이 직접 하드웨어를 소유하고 서비스를 운영하는 방식입니다.

Virtualization (가상화): "물리적인 자원을 논리적으로 쪼개서 쓰는 것." 물리 하드웨어 위에서 여러 개의 가상 머신(VM)을 만들어 독립된 OS처럼 실행하게 만드는 기술입니다. 여기서 **하이퍼바이저**가 중재자 역할을 합니다.

VM (Virtual Machine): "가상의 컴퓨터." 하이퍼바이저 위에 올려져 Guest OS를 실행합니다.

WSL2 (윈도우 서브시스템 리눅스 2): "윈도우 위에서 가볍게 리눅스를 쓰는 기술." 완전한 가상 머신처럼 무겁지 않고, 실제 리눅스 커널을 경량화하여 윈도우에 심어주는 방식입니다.

총평#

오늘 오후 전체에서 배운 것#

Conditional Edge는 LLM 출력을 바로 실행하는 것이 아니라 State와 Router를 거쳐 실제 노드를 선택하는 LangGraph 특유의 간접 파이프라인 구조임을 명확히 이해했다. 또한 Loop, Tool, Human in the Loop 등 그래프 내의 순환 및 외부 연동 메커니즘이 어떻게 상태를 누적하고 제어하는지 전반적인 흐름을 파악할 수 있었다. 마지막으로 On-premise와 가상화, WSL2가 로컬 환경과 인프라 계층에서 어떻게 연결되는지를 이해하며 시스템 전체의 맥락을 잡는 소중한 시간이 되었다.

다음에 조심할 것#

LangGraph의 구조적 특성을 이해하는 데 있어, State와 Router가 Conditional Edge를 통해 실제 노드를 제어한다는 흐름을 놓치지 않고 메모해두는 것이 중요하다. 또한 Loop·Tool·Human in the Loop 개념은 단순한 기능 나열이 아니라, 그래프 내부의 상태 관리와 외부 상호작용이 어떻게 연계되는지 전체적인 그림을 먼저 파악한 뒤 세부 사항을 채워가는 식으로 접근해야 한다. 마지막으로 인프라 지식은 추상적인 용어보다는 현재 사용 중인 로컬 환경(LM Studio 등)과 직접 연결하여 이해하려 노력하면, 추후 더 복잡한 시스템 구성 시에도 혼란 없이 적용할 수 있을 것이다.

다음 복습 주제#

LangGraph의 핵심 메커니즘인 Conditional Edge와 Tool, 그리고 Human in the Loop가 실제 파이프라인에서 어떻게 상호작용하는지 시뮬레이션 코드나 플로우차트를 그려보며 구체적인 실행 흐름을 재정리해 보는 것이 좋다. 또한, 온프레미스 환경에서의 LLM 스튜디오 설정과 WSL2의 가상화 계층이 실제 AI 개발 및 배포 환경에 어떻게 영향을 미치는지, 로컬 테스트와 클라우드 배포 간의 차이점을 비교해보는 시간을 갖는 것을 추천한다.
