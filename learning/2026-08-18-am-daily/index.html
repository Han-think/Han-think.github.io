1. Next.js 구조와 로컬 서버 연결하기#

무엇을 배웠나#

Next.js와 Java 백엔드는 완전히 분리된 프로세스로 동작하며, 프론트엔드 화면은 Next.js가 담당하고 데이터는 Java 서버가 제공한다는 점이었다. 특히 create-next-app 실행 시 src/ 폴더 선택 여부가 프로젝트 구조에 영향을 미칠 수 있어 강사님 환경과 일치시키는 것이 중요하다고 느꼈다. 또한 WebStorm만으로는 백엔드 서버를 자동으로 띄워주지 않으므로, PowerShell에서 java -jar server.war 명령어를 직접 실행해야 한다는 점을 명확히 했다.

헷갈렸던 점#

프론트엔드와 백엔드가 서로 다른 프로세스로 동작한다는 점이 가장 큰 혼란이었습니다. Next.js가 화면을 그리고 Java 서버가 데이터를 제공하는 구조라 두 가지가 어떻게 연결되는지 막막했습니다. 또한 src/ 폴더 위치 선택에 따라 강사님 환경과 내 환경의 경로가 달라질 수 있다는 점도 초보자로서는 신중하게 결정해야 할 부분이었습니다.

정리된 이해#

Next.js와 Java 백엔드는 각각 독립적인 프로세스로 실행되며, 화면 렌더링은 Next.js가 담당하고 데이터 제공은 Java 서버가 담당하는 분리된 구조이다. src/ 폴더 생성 옵션을 수업 환경에 맞게 설정하고 WebStorm에서 별도로 자바 서버를 구동해야만 두 시스템이 연결된다.

Next.js App Router 구조와 로컬 백엔드 서버 연결 (학습 요약)#

📁 폴더 구조 및 설정#

src/app 디렉토리 선택의 중요성

  • create-next-app 실행 시 src/ directory 옵션을 선택해야 강사님 환경과 폴더 경로가 일치
  • 선택하지 않으면 경로 mismatch로 인해 헤맬 수 있음

🖥️ 서버 실행 방식#

프론트엔드와 백엔드의 분리

  • Next.js: npm run dev 명령어로 실행 (화면 렌더링)
  • Java 서버: PowerShell에서 java -jar server.war 명령어로 별도 구동 필요
  • WebStorm이 자동으로 백엔드를 켜주지 않으므로 수동 실행 필수

2. useEffect와 axios로 게시글 목록 가져오기#

무엇을 배웠나#

axios.get()은 전체 응답 객체를 반환하며, 실제 데이터는 response.data 안에 있다는 점을 명확히 이해했습니다. ({data}) 문법은 response.data를 바로 꺼내는 구조 분해 할당이라는 사실에 익숙해졌습니다. useEffect의 빈 의존성 배열([])이 페이지 고정 시 한 번만 실행된다는 점과, page가 변하면 [page]로 추가해야 한다는 점을 확실히 인지했습니다. 이러한 내용을 바탕으로 실제 데이터 요청 흐름과 상태 업데이트 메커니즘을 정확하게 파악할 수 있게 되었습니다.

헷갈렸던 점#

useEffect 안에서 axios.get()으로 받은 응답 객체 전체가 아니라, 실제 데이터는 response.data 안에 있다는 점이 가장 먼저 헷갈렸습니다.

또 다른 하나는 useEffect의 의존성 배열이 빈 배열([])로 되어 있는데, page props가 바뀌면 데이터 요청이 다시 일어나는지 알 수 없어 흐름을 파악하기 어려웠습니다.

정리된 이해#

axios.get()은 전체 응답 객체를 반환하며, 실제 데이터는 response.data 안에 있습니다. ({data})는 이 response.data를 바로 꺼내는 구조 분해 할당 문법입니다. 현재 코드는 page={1}이 고정되어 있어 useEffect가 한 번만 실행되도록 의존성 배열을 빈 배열로 구성했지만, 페이지 이동 시 데이터를 다시 가져오려면 [page]를 추가해야 합니다.

'use client'
import {useEffect, useState} from "react";
import axios from "axios";

export default function PostList({page}) {
    const [posts, setPosts] = useState([]);

    useEffect(() => {
        // axios로 서버로부터 데이터 요청
        axios.get(`http://localhost/list/${page}`)
            .then((response) => {
                // response.data 안에 실제 게시글 배열이 들어있음
                setPosts(response.data);
            });
    }, [page]);

    return (
        <div>
            {posts.map((post) => (
                <div key={post.id}>
                    <h3>{post.title}</h3>
                    <p>{post.content}</p>
                </div>
            ))}
        </div>
    );
}

3. React controlled form의 핵심 원리 이해하기#

무엇을 배웠나#

React의 controlled component를 다룰 때 value 속성만 연결하면 입력창이 읽기 전용으로 고정되는 문제를 겪었다. 이에 따라 onChange와 name 속성을 반드시 함께 사용해야 입력이 가능하다는 점을 학습했다. 또한, 상태를 직접 갱신하는 setInfo와 이벤트를 처리해 주는 changeInfo 함수의 역할 차이를 명확히 구분할 수 있게 되었다.

헷갈렸던 점#

React에서 controlled component를 다룰 때 value 속성만 연결하면 입력창이 읽기 전용으로 고정되는 것을 경험했습니다. 또한 onChange 이벤트와 함께 name 속성을 지정하지 않으면 어떤 상태 필드를 수정해야 할지 알 수 없어 입력이 되지 않았습니다. 마지막으로 React가 제공하는 setInfo 함수와 내가 만든 changeInfo 함수의 역할 구분이 처음에는 모호하여 혼란을 겪었습니다.

정리된 이해#

React에서 controlled component를 제어하려면 value 속성뿐만 아니라 onChange와 name 속성을 반드시 연결해야 한다. 입력값을 상태에 저장하기 위해 setInfo 함수를 호출하는 역할을 changeInfo 같은 핸들러가 담당하며, 이벤트 객체에서 target.name을 통해 어떤 상태 필드를 업데이트할지 정확히 지정할 수 있다.

const [info, setInfo] = useState({ user_name: '' });

const changeInfo = (e) => {
  const { name, value } = e.target;
  setInfo({
    ...info,
    [name]: value
  });
};

4. axios POST 흐름과 상세 페이지 이동#

무엇을 배웠나#

axios POST 요청 시 async/await, 서버 응답 처리, 페이지 이동이 하나의 파이프라인처럼 순차적으로 연결된다는 점을 이해했습니다. 특히 useState로 데이터를 모으고 axios.post()로 전달한 뒤, 서버가 반환한 idx를 받아 라우팅하는 흐름이 이전보다 명확해졌습니다. 이러한 순서 파악을 통해 상태 관리와 HTTP 요청이 별개가 아니라 하나의 연쇄 과정임을 실감했습니다.

헷갈렸던 점#

axios POST 한 줄 안에 async/await, 서버 응답 처리, 페이지 이동이 섞여 있어 전체적인 흐름을 놓쳤습니다.

핵심은 순차적 파이프라인이었습니다. 상태 관리는 데이터를 모으는 ‘수집 단계’이고, axios는 모은 데이터를 전달하는 ‘전달 단계’이며, 서버 응답과 라우팅은 그다음 이어지는 과정입니다.

정리된 이해#

핵심은 useState로 데이터를 모으고, axios.post()가 그 데이터를 서버에 전달하는 순서대로 흐름이 이어진다는 점입니다. 서버로부터 받은 idx를 기준으로 성공 여부를 판단한 뒤, 상세 페이지로 이동하는 것이 전체적인 파이프라인입니다.

총평#

오늘 오전 전체에서 배운 것#

Next.js와 Java 백엔드의 분리된 구조, useEffect를 활용한 데이터 요청 시점과 axios 응답 처리 방법, 그리고 React controlled form에서 value와 onChange를 함께 사용하여 입력 가능하게 만드는 핵심 원리를 정리했습니다.

다음에 조심할 것#

Next.js와 Java 백엔드 분리 구조를 확실히 이해한 만큼, PowerShell에서 직접 서버 실행 명령어를 입력하는 습관을 들여야겠다. useEffect 의존성 배열을 활용해 불필요한 리렌더링을 방지하고, axios 응답 데이터 처리에 익숙해졌으니 form 제어 시 value와 onChange를 반드시 쌍으로 연결하여 입력이 차단되지 않도록 주의할 것이다.

다음 복습 주제#

Next.js 프로젝트 구조 설정 시 src 폴더 선택 여부가 중요하다는 점을 재확인하고, WebStorm 환경에서 백엔드 서버를 직접 실행하는 방법을 숙지해야겠다.

React 훅과 HTTP 통신 관련하여, useEffect의 의존성 배열([]) 동작 원리와 axios 응답 데이터 구조(response.data)를 정확히 이해하여 불필요한 렌더링이나 데이터 누락 없이 게시글 목록을 가져오는 로직을 완성해야 한다.

React controlled form에서 value 속성만 연결하면 입력창이 고정되는 문제를 해결하기 위해 onChange와 상태 업데이트 함수의 조합이 필수적임을 다시 한번 점검하고, 실제 서비스 구현 시 데이터 흐름을 체계적으로 설계할 수 있도록 연습해야 한다.
