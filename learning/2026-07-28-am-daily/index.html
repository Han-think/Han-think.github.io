1. CSS 주석 작성법 및 VS Code 활용 가이드#

무엇을 배웠나#

CSS 주석을 적용하는 방법과 VS Code 단축키 사용법을 명확히 이해하게 되었다. 특히, 원하는 부분만 주석 처리하는 방법을 알고 나니 이전보다 훨씬 효율적으로 CSS 코드를 관리할 수 있게 되었다. 앞으로는 프로젝트에 참여할 때 이 지식을 활용하여 코드의 가독성과 유지보수성을 높이는 데 기여할 수 있을 것 같다.

헷갈렸던 점#

처음에는 CSS 주석을 줄바꿈 없이 한 줄로 작성할 수 있는지 궁금했고, Ctrl + / 단축키로 주석을 달 때 예상보다 더 많은 코드 영역이 주석 처리되는 부분에서 어려움을 겪었습니다. CSS 주석의 올바른 사용법과 VS Code 단축키 활용법을 익히면서 효율적인 CSS 작성 방법을 배우게 되었습니다.

정리된 이해#

CSS 주석은 /* */ 형식으로 작성하며, VS Code의 Ctrl + /는 줄 전체를 주석 처리하므로 원하는 부분만 주석 처리하려면 직접 /* 설명 */를 입력하거나 Shift + Alt + A 단축키를 사용해야 한다. Pipeline OS 웹 인터페이스 개선 작업 시, 속성 옆에 주석을 달아 코드의 의도를 명확하게 기록할 수 있다.

/* 전체 줄 주석 예시 */
body {
  background-color: #f0f0f0; /* 배경색 설정 */
  /* 위 코드 전체가 주석 처리됨 */
}

/* 선택적 블록 주석 예시 */
margin: 20px; /* 여백 설정 */
/* 위 코드만 주석 처리 */
margin: 20px;

2. 플로팅과 클리어: 웹 레이아웃의 기본 원리#

무엇을 배웠나#

float는 요소를 배치할 때 주변 요소의 흐름을 바꿔서 레이아웃을 만들 수 있지만, 그 영향으로 인해 다른 요소들이 예상치 못한 위치로 이동할 수 있다는 것을 배웠어요. 특히 footer가 제대로 표시되지 않는 문제는 clear: both를 사용하여 해결해야 한다는 것을 알게 되었습니다. 이 학습을 통해 float와 clear를 함께 사용하면 원하는 웹 레이아웃을 만들 수 있다는 것을 이해했습니다.

헷갈렸던 점#

플로팅을 적용하면 요소가 옆으로 밀려나고 그 뒤의 요소들이 위로 올라가는게 왜 그런지 잘 이해가 안 갔어. footer를 아래로 내리기 위해 width를 100% 적용하는 것으로는 해결되지 않고, 뭔가 다른 방법이 필요할 것 같았어. clear 속성이 어떻게 작동하는지, 특히 clear: both가 왜 중요한지 처음에는 명확하게 알지 못했어.

정리된 이해#

float는 요소를 화면의 왼쪽이나 오른쪽에 배치하고, 그 공간을 다른 요소들이 채우도록 만들기 때문에, 주변 요소들의 배치에 영향을 줍니다. clear 속성은 이 float의 영향을 없애, 요소가 문서의 정상적인 흐름을 따르도록 만들어주며, 특히 clear: both는 왼쪽과 오른쪽 모두에 영향을 받은 플로팅 요소를 아래로 내리는 데 사용됩니다. footer가 float된 요소 뒤에 위치할 때 width: 100%만으로는 해결되지 않고, clear: both를 적용해야 제대로 표시됩니다.

#left {
    width: 200px;
    height: 200px;
    background-color: red;
    float: left;
}
main {
    width: 300px;
    height: 200px;
    background-color: green;
    float: left;
}
#right {
    width: 200px;
    height: 200px;
    background-color: pink;
    float: right;
}
footer {
    width: 100%;
    height: 100px;
    background-color: black;
    clear: both;
}
div.first {
    border-color: red;
    clear: left;
}

3. 시맨틱 HTML과 외부 CSS를 활용한 카드 페이지 구축#

무엇을 배웠나#

HTML과 CSS를 분리하여 페이지를 구성할 때, CSS 선택자가 적용되는 HTML 요소를 추적하는 데 어려움이 있었지만, HTML 구조와 CSS 스타일링의 역할 분리를 통해 이를 해결할 수 있었다. 특히 링크 요소에 display: block을 적용하는 이유를 명확히 이해하게 되었고, 분리된 파일에서 스타일을 관리하는 방법론을 익혔다. 이제는 HTML 구조를 명확히 정의하고, 그에 맞는 CSS를 적용하여 카드형 페이지를 더 효율적으로 만들 수 있을 것 같다.

헷갈렸던 점#

HTML과 CSS 파일을 분리해서 작업할 때, CSS 선택자가 어떤 HTML 요소를 스타일링하는지 파악하는 과정이 상당히 복잡하고 시간이 오래 걸렸습니다. 특히, 계층 구조를 따라가면서 적용되는 스타일을 추적하는 데 어려움을 느꼈습니다. 또한, 링크 요소에 display: block을 적용하는 이유를 정확히 이해하지 못해, 단순히 줄바꿈을 위한 것인지 클릭 영역을 넓히기 위한 것인지 혼란스러웠습니다.

정리된 이해#

HTML은 페이지의 구조를 담당하고, CSS는 그 구조에 스타일을 적용하여 코드 유지보수성을 높인다. 링크 요소에 display: block을 적용하면 줄바꿈 기능 외에도 클릭 영역을 확장하여 사용자 경험을 개선할 수 있다. 복잡한 CSS 선택자 추적의 어려움을 해결하기 위해 HTML 구조를 명확히 하고, CSS를 체계적으로 작성해야 한다.

    /* 기본 설정 */
    * {
        margin: 0;
        padding: 0;
    }

4. CSS Transform 속성 활용법: 변환 순서와 비율 이해하기#

무엇을 배웠나#

CSS transform 속성을 사용할 때 변환 적용 순서가 뒤에서부터 적용된다는 것을 알게 되었고, scale 함수의 값이 픽셀이 아닌 비율을 나타낸다는 것을 명확히 이해하게 되었습니다. 여러 변환을 적용할 때는 하나의 transform 속성 안에 모두 넣어줘야 한다는 점을 확인했습니다. 이제 transform 속성을 활용하여 다양한 시각적 효과를 구현할 수 있을 것 같습니다.

헷갈렸던 점#

CSS transform 속성을 사용할 때 변환 적용 순서가 이해가 안 갔고, scale 함수에서 숫자가 픽셀 단위인지 비율 단위인지 헷갈렸습니다. 여러 변환을 따로 작성하면 예상대로 작동하지 않는 이유가 명확하지 않았습니다.

정리된 이해#

CSS transform 속성 내에서 여러 변환을 적용할 때, 변환 기능들은 순서대로 적용되지 않고 마지막에 선언된 변환만 적용된다는 것을 알게 되었다. scale 함수는 픽셀 단위가 아닌 비율을 사용하며, 비율을 조정하여 원하는 크기로 확대 또는 축소할 수 있다는 것을 명확히 이해했다. 이제 transform 속성을 활용하여 더욱 복잡하고 다이나믹한 시각적 효과를 구현할 수 있을 것이다.

.animated-box {
    width: 100px;
    height: 100px;
    background-color: blue;
    margin: 50px;
    transform: rotate(30deg) scale(0.7);
    transition: transform 0.5s ease;
}

5. 브라우저 호환성을 위한 CSS 접두사 완벽 이해#

무엇을 배웠나#

CSS 접두사는 과거 브라우저 호환성 문제를 해결하기 위해 사용되었으며, 현재는 표준 속성을 함께 사용하여 대부분의 브라우저에서 잘 작동합니다. 접두사는 오래된 브라우저 지원을 위해 필요하며, 각 접두사마다 특정 브라우저와 연관되어 있다는 것을 알게 되었습니다. 이는 Pipeline OS처럼 다양한 환경에서의 호환성을 위한 어댑터와 유사한 개념입니다.

헷갈렸던 점#

처음에는 CSS 속성을 여러 버전의 브라우저에 맞춰 따로 작성해야 한다는 점이 비효율적으로 느껴졌고, 어떤 속성은 접두사를 써야 하는지, 어떤 속성은 표준 속성만 써도 되는지 헷갈렸습니다. 또한 접두사가 왜 필요한지, 그리고 현대 브라우저에서는 더 이상 필요 없는 건지 명확하지 않았습니다.

정리된 이해#

과거 브라우저 구현 방식의 차이 때문에 특정 CSS 속성을 적용하기 위해 -webkit-, -moz- 같은 접두사를 사용했는데, 이제는 대부분의 브라우저가 표준 속성을 지원하기 때문에 접두사는 주로 오래된 브라우저 호환성을 위해 사용합니다. 표준 속성을 먼저 사용하고, 필요한 경우 접두사를 추가하는 방식으로 코드를 작성하면 대부분의 환경에서 잘 작동합니다. 이는 마치 여러 런타임 환경에서 동일한 기능을 작동시키기 위한 어댑터와 비슷한 역할을 한다고 생각하면 이해하기 쉽습니다.

  .transition {
      -webkit-transform: translate(100px, 200px); /* Chrome, Safari */
      -moz-transform: translate(100px, 200px);   /* Firefox */
      -ms-transform: translate(100px, 200px);     /* IE */
      -o-transform: translate(100px, 200px);      /* Opera */
      transform: translate(100px, 200px);         /* 표준 속성 */
  }

다음에 조심할 것#
