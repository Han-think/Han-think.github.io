1. 숫자 비교 오류#

왜 이걸 보게 됐나#

SQL 실습을 하면서 숫자를 비교할 때, 실수로 문자열처럼 따옴표를 사용해서 오류가 발생했어. SQL은 숫자 리터럴을 그냥 사용해야 한다는 점을 간과했지. 이 실수를 통해 SQL에서 숫자와 문자열 비교의 차이점을 확실히 이해하게 됐어.

내가 헷갈린 지점#

숫자를 비교할 때 따옴표를 붙여야 한다고 생각했는데, 데이터베이스는 숫자를 문자열로 인식하는지 몰랐어요. 따옴표가 문자열 비교에 쓰이는 건 알았지만, 숫자 비교에도 적용해야 한다는 점이 헷갈렸고, 그 결과 예상치 못한 오류가 발생했습니다. 숫자는 숫자 그대로 비교해야 한다는 걸 깨닫고 코드를 수정했더니 문제가 해결되었습니다.

시도한 코드 / 예시#

SELECT *
FROM tracks
WHERE UnitPrice > '0.99'  -- 오류 예시
LIMIT 10;

결과와 해석#

숫자를 비교할 때 따옴표를 붙여서 ‘0.99’처럼 작성했더니 오류가 발생했고, 나중에 숫자 리터럴은 따옴표 없이 바로 사용해야 한다는 것을 알게 되었어. 그래서 따옴표를 제거하고 UnitPrice > 0.99처럼 수정했더니 제대로 작동하는 것을 확인했고, 숫자 비교에서는 따옴표를 사용하지 않도록 주의해야겠다는 점을 배웠어. 이 실수를 통해 SQL에서 데이터 타입에 따른 올바른 표기법을 사용하는 것이 중요하다는 것을 깨달았어.

정리된 이해#

숫자를 비교할 때는 따옴표를 사용하면 안 되고, 숫자 그대로 비교해야 한다는 것을 알게 되었습니다. 따옴표를 사용하면 텍스트로 인식되어 예상치 못한 결과를 가져올 수 있음을 확인했습니다. 앞으로는 숫자 비교 시에는 숫자 리터럴을 직접 사용하도록 주의해야겠습니다.

2. LIKE 연산자#

왜 이걸 보게 됐나#

앨범이나 트랙 제목을 검색하는 과정에서 특정 패턴을 가진 데이터만 찾고 싶었을 때, 단순한 문자열 비교로는 원하는 결과를 얻기 어려웠다. 그래서 특정 문자열이 포함되었는지, 혹은 특정 문자열로 시작하는 데이터를 찾기 위한 LIKE 연산자를 배우게 되었다. 이 연산자를 통해 데이터 검색 범위를 좁히고 원하는 결과를 더욱 효율적으로 찾을 수 있게 되었다.

내가 헷갈린 지점#

처음에는 LIKE 연산자를 사용할 때, 와일드카드 기호가 위치하는 방식에 대해 명확히 이해하지 못했습니다. % 기호가 앞이나 뒤에 붙는 경우의 의미를 혼동하여, 특정 문자가 앨범 제목 어디에나 포함되는 검색을 의도했던 반면, 앨범 제목의 시작 부분만 검색하고 싶었던 기억이 납니다. 이 때문에 검색 결과가 예상과 달랐고, 정확한 패턴을 사용해야 한다는 것을 깨달았습니다.

시도한 코드 / 예시#

SELECT *
FROM albums
WHERE Title LIKE 'K%';  -- 수정된 코드 (K로 시작하는 앨범)

결과와 해석#

LIKE 연산자는 SQL에서 문자열 패턴을 검색할 때 사용하는데, %와 _ 와 같은 특수문자를 활용하여 ‘K%‘는 ‘K’로 시작하는 문자열을 찾고 ‘%K%‘는 ‘K’를 포함하는 모든 문자열을 찾도록 하는 기능을 합니다. 나는 처음에 ‘%K%‘를 사용하여 모든 앨범을 검색하려고 했지만, ‘K’로 시작하는 앨범만을 찾고 싶었기 때문에 LIKE 'K%'로 수정했습니다. 이 과정을 통해 LIKE 연산자의 패턴 표현에 대한 이해가 높아졌습니다.

정리된 이해#

LIKE 연산자는 문자열 컬럼의 값과 특정 패턴을 비교할 때 사용하는데, LIKE '패턴%'는 지정된 패턴으로 시작하는 문자열을 찾고, LIKE '%패턴%'는 문자열 내 어디든 패턴이 포함되는 문자열을 찾습니다. 이 연산자를 사용할 때는 원하는 검색 결과를 얻기 위해 패턴의 위치와 ‘%’ 기호의 사용법을 정확히 이해해야 합니다.

3. ORDER BY 컬럼#

왜 이걸 보게 됐나#

데이터를 분석하고 결과를 의미 있게 보여주려면, 데이터를 특정 기준에 따라 정렬하는 것이 중요해. 처음에는 단순히 데이터 목록을 보는데 집중했지만, 정렬을 제대로 활용해야 데이터의 흐름을 파악하고 인사이트를 얻을 수 있다는 걸 깨달았어. 그래서 어떤 기준으로 데이터를 정렬해야 하는지, 그리고 ORDER BY를 어떻게 사용하는지 배우게 됐어.

내가 헷갈린 지점#

곡 가격’ FROM tracks ORDER BY UnitPrice DESC; – 수정된 코드

시도한 코드 / 예시#

SELECT
         Name AS "곡 이름",
         UnitPrice AS "단

결과와 해석#

ORDER BY절은 결과 집합을 특정 컬럼을 기준으로 정렬하는 역할을 합니다. 예를 들어 ORDER BY UnitPrice DESC는 UnitPrice 컬럼을 기준으로 내림차순 정렬하여 가장 높은 가격부터 표시합니다. 정렬 기준을 잘못 지정하면 원하는 순서로 결과를 얻을 수 없으므로, 문제에서 요구하는 컬럼을 정확히 선택하는 것이 중요합니다.

정리된 이해#

ORDER BY 절은 결과 집합을 특정 컬럼을 기준으로 정렬하는 명령어입니다. 정렬 기준이 되는 컬럼 이름을 ORDER BY 뒤에 명시하고, DESC를 붙여 내림차순으로 정렬할 수 있습니다. 문제에서 요구하는 정렬 기준에 맞춰 컬럼을 선택하는 것이 중요합니다.

4. 데이터 정렬#

왜 이걸 보게 됐나#

데이터가 쌓이면 원하는 정보를 찾기 어려워지고, 분석하기도 힘들어지거든요. 그래서 데이터를 특정 기준에 맞춰 정리하는 ‘데이터 정렬’ 개념을 배우게 됐어요. 체계적으로 정렬하면 데이터를 더 쉽게 이해하고 활용할 수 있게 되니까요.

내가 헷갈린 지점#

데이터를 정렬해야 할 때 어떤 컬럼을 기준으로 할지, 그리고 내림차순인지 오름차순인지 혼동되는 경우가 많았습니다. 특히 문제에서 요구하는 정렬 기준과 제가 생각하는 기준이 일치하는지 제대로 확인하지 않고 코드를 작성했던 실수를 반복했습니다. 컬럼명만 적는다고 정렬이 되는 게 아니라, 올바른 기준으로 정렬하고 있는지 항상 검증해야 한다는 것을 깨달았습니다.

시도한 코드 / 예시#

SELECT
    Name AS "곡 이름",
    UnitPrice AS "단가"
FROM tracks
ORDER BY UnitPrice DESC;

결과와 해석#

데이터 정렬은 쿼리 결과에서 특정 컬럼을 기준으로 오름차순 또는 내림차순으로 결과를 재배열하는 것을 의미합니다. 처음에는 곡 이름을 기준으로 내림차순 정렬하려 했지만, 실제로는 가격 기준으로 정렬해야 했고, ORDER BY UnitPrice DESC 구문을 사용하여 가격을 기준으로 내림차순 정렬했음을 알게 되었습니다. 이 과정에서 ORDER BY 뒤에 올 컬럼 선택의 중요성을 다시 한번 확인했습니다.

정리된 이해#

데이터 정렬은 결과를 원하는 순서대로 보여주기 위해 사용하며, ORDER BY 절 뒤에 정렬 기준이 되는 컬럼 이름을 명시해야 합니다. 정렬 기준 컬럼을 잘못 지정하면 원하는 결과가 나오지 않으므로, 문제에서 요구하는 컬럼을 정확히 파악하는 것이 중요합니다.

총평#

오늘 전체에서 배운 것#

숫자 비교 시 따옴표를 붙이는 실수를 했고, LIKE 연산자 사용법을 다시 한번 확인해야 했어. 곡 이름 대신 가격으로 정렬해야 한다는 것을 놓쳤던 부분도 수정했어.

다음에 조심할 것#

숫자 비교 시에는 따옴표를 잊고 숫자 그대로 사용해야 하고, LIKE 연산자를 사용할 때 원하는 패턴이 무엇인지 정확히 파악해야 한다. ORDER BY 절에서는 정렬 기준이 되는 컬럼을 다시 한번 확인하고 사용해야 한다.

다음 복습 주제#

숫자 비교 시 따옴표 사용 오류와 LIKE 연산자의 패턴 이해를 더 확실하게 다져야겠다. ORDER BY 컬럼 선택 시 요구사항에 맞춰 정확하게 선택하는 연습이 필요해.
