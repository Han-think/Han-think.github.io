1. SQL 함수#

왜 이걸 보게 됐나#

데이터 분석을 하려면 다양한 정보를 효율적으로 추출하고 분석해야 하는데, SQL 함수는 데이터를 요약하고 계산하는 데 필수적인 도구라서 배우게 되었어. 특히 여러 테이블에 흩어져 있는 정보를 연결하고 활용하려면 JOIN과 함께 SQL 함수를 능숙하게 다룰 줄 알아야 원하는 결과를 얻을 수 있기에 중요하다고 생각해.

내가 헷갈린 지점#

처음에는 함수들의 역할이 단순히 데이터에 적용하는 것이라고 생각해서, 어떤 함수를 사용해야 할지 상황에 맞춰 적용하는 기준이 불명확했어요. 특히, 서브쿼리 안에서 어떻게 함수를 활용해야 하는지, 그리고 어떤 기준으로 어떤 테이블을 JOIN 해야 하는지 이해하는 데 어려움을 겪었습니다. 테이블 간의 관계를 파악하고, 함수의 결과를 어떻게 활용해야 하는지 감을 잡는 것이 가장 헷갈렸던 부분입니다.

시도한 코드 / 예시#

-- 평균 판매 금액 구하기
SELECT AVG(UnitPrice) AS AveragePrice
FROM orders INNER JOIN products ON orders.product_id = products.id;

결과와 해석#

COUNT 함수를 사용해서 테이블 내 특정 컬럼의 데이터 개수를 손쉽게 셀 수 있었는데, 예를 들어 SELECT COUNT(*) FROM customers;를 통해 고객 테이블에 몇 명의 고객이 있는지 확인할 수 있었습니다. SUM 함수를 활용하여 특정 컬럼 값들의 합계를 구하는 실습도 문제 해결에 도움이 되었고, 이를 통해 데이터 분석의 기초를 다질 수 있었습니다. 실제 데이터셋에 적용하면서 함수가 단순히 값을 계산하는 것 이상으로, 다양한 조건과 함께 활용되어 의미 있는 정보를 추출하는 도구임을 깨달았습니다.

정리된 이해#

SQL 함수는 데이터 개수 세기(COUNT), 합계 계산(SUM), 평균 구하기(AVG), 최댓값/최솟값 찾기(MAX/MIN), 그리고 결과 개수 제한(LIMIT) 등 다양한 방식으로 데이터를 분석하고 요약하는 데 사용됩니다. 각 함수는 특정 목적에 맞춰 사용되며, 여러 함수를 조합하여 더욱 복잡한 분석을 수행할 수 있습니다. JOIN과 함께 사용하면 여러 테이블에 흩어진 데이터를 효과적으로 결합하여 원하는 결과를 얻을 수 있습니다.

2. JOIN 종류#

왜 이걸 보게 됐나#

데이터를 분석하다 보면 여러 테이블에 흩어져 있는 정보를 하나로 묶어 분석해야 하는 경우가 많았는데, 이때 테이블을 연결하는 방법을 배우기 위해 JOIN을 익히게 됐어. 단순히 테이블을 합치는 것 이상의 다양한 JOIN 종류를 통해 필요한 데이터만 효율적으로 추출하는 방법을 배우고 싶었어. 특히 LEFT JOIN과 RIGHT JOIN은 어떤 데이터를 가져오는지 정확히 이해하고 활용하는 것이 중요하다고 느껴서 집중적으로 학습하게 됐지.

내가 헷갈린 지점#

LEFT JOIN이랑 RIGHT JOIN이 어떤 차이인지 정확히 이해하지 못해서, 왼쪽 테이블과 오른쪽 테이블 중 어떤 데이터를 기준으로 가져와야 하는지 헷갈렸어요. 특히, 문제에서 어떤 테이블이 주요한 테이블인지 판단하는 데 어려움을 겪었습니다. INNER JOIN과의 차이점도 명확하게 구분하지 못해 상황에 맞는 JOIN을 선택하는 데 어려움이 있었습니다.

시도한 코드 / 예시#

-- INNER JOIN: 두 테이블 간 겹치는 데이터만 반환합니다.
SELECT *
FROM orders INNER JOIN customers ON orders.customer_id = customers.id;
-- 예시: 주문 정보와 고객 정보를 함께 조회 (두 테이블에 모두 존재하는 고객의 주문 정보만 표시)

-- LEFT JOIN: 왼쪽 테이블의 모든 데이터를 유지하고 오른쪽 테이블의 매칭 데이터를 포함합니다.
SELECT *
FROM customers LEFT JOIN orders ON customers.id = orders.customer_id;
-- 예시: 고객 정보 전체 조회, 주문 정보가 있는 경우 주문 정보도 함께 표시 (주문이 없는 고객도 포함)

-- RIGHT JOIN: 오른쪽 테이블의 모든 데이터를 유지하고 왼쪽 테이블의 매칭 데이터를 포함합니다.
SELECT *
FROM orders RIGHT JOIN customers ON orders.customer_id = customers.id;
-- 예시: 주문 정보 전체 조회, 고객 정보가 있는 경우 고객 정보도 함께 표시 (주문이 없는 고객에 대한 주문 정보는 표시되지 않음)

결과와 해석#

INNER JOIN은 두 테이블에 모두 존재하는 레코드만 보여줘서, 두 테이블의 관계가 꼭 맞아야 데이터를 가져올 수 있어 제한적이야. LEFT JOIN은 왼쪽 테이블의 모든 레코드를 유지하고, 오른쪽 테이블에서 매칭되는 데이터가 있으면 함께 보여줘서 더 많은 데이터를 볼 수 있어 편리해. RIGHT JOIN은 LEFT JOIN과 반대로 오른쪽 테이블의 모든 데이터를 보여줘.

정리된 이해#

INNER JOIN은 두 테이블에서 조건에 맞는 행들만 가져오고, LEFT JOIN은 왼쪽 테이블의 모든 데이터를 가져오면서 오른쪽 테이블에서 일치하는 데이터가 있으면 함께 가져와요. RIGHT JOIN은 LEFT JOIN과 반대로, 오른쪽 테이블의 모든 데이터를 유지하면서 왼쪽 테이블에서 일치하는 데이터를 가져오는 역할을 합니다.

3. 서브쿼리 활용#

왜 이걸 보게 됐나#

복잡한 요구사항을 가진 쿼리를 작성하려면 단순히 테이블을 연결하는 것만으로는 부족했고, 이미 계산된 값을 기준으로 결과를 필터링하거나 특정 조건을 만족하는 데이터를 추출해야 하는 상황이 자주 발생했기 때문에 서브쿼리 활용법을 익히게 됐어. 단순히 데이터를 조회하는 것에서 벗어나, 데이터 분석 및 보고서 작성에 필요한 더 깊이 있는 쿼리 작성 능력을 키우기 위해 필요했어.

내가 헷갈린 지점#

서브쿼리가 어떻게 동작하는지 그림을 그려서 이해하려고 했는데, 결국 문제의 조건과 테이블을 연결하는 논리적인 흐름을 잡기가 어려웠다. 서브쿼리 자체가 다른 쿼리의 일부처럼 섞여 있어서 전체적인 그림을 파악하는 데 시간이 오래 걸렸고, 각 단계별로 어떤 역할을 하는지 명확하게 이해하지 못했다. 단순한 문제도 서브쿼리의 역할을 파악하고 적용하는 과정에서 막히곤 했다.

시도한 코드 / 예시#

-- 평균 판매 금액 구하기
SELECT AVG(UnitPrice) AS AveragePrice
FROM orders INNER JOIN products ON orders.product_id = products.id;

-- 최대 주문 수량 확인
SELECT MAX(quantity) AS MaxQuantity
FROM orders LEFT JOIN customers ON orders.customer_id = customers.id;

결과와 해석#

서브쿼리를 활용하여 평균 판매 가격보다 높은 가격의 제품을 찾을 때, 먼저 전체 제품의 평균 판매 가격을 서브쿼리로 계산하고, 메인 쿼리에서는 그 평균값을 기준으로 조건을 걸어 필터링하는 방식으로 문제를 해결했습니다. 이 과정에서 서브쿼리의 결과가 메인 쿼리의 조건으로 어떻게 사용되는지 명확히 이해할 수 있었고, 문제 해결을 위한 기준점 설정의 중요성을 알게 되었습니다. 따라서 서브쿼리는 복잡한 조건을 가진 결과를 도출하는 데 유용하게 활용될 수 있습니다.

정리된 이해#

서브쿼리는 이전 쿼리 결과를 이용해서 또 다른 쿼리를 수행하는 방식으로, 주로 복잡한 조건이나 기준값을 계산해서 최종 결과를 도출할 때 활용됩니다. 예를 들어, 특정 기준값(평균, 최대값 등)을 먼저 계산하는 서브쿼리의 결과를 바탕으로, 메인 쿼리에서 필터링이나 정렬을 수행할 수 있습니다. 이를 통해 테이블 간의 관계를 활용하여 원하는 정보를 효율적으로 추출할 수 있습니다.

4. ERD 해석#

왜 이걸 보게 됐나#

ERD가 없었으면 테이블 간 관계를 정확히 파악하기 어려워서 어떤 컬럼을 어떻게 연결해야 할지 막막했을 거야. 문제에서 요구하는 조건을 만족하는 쿼리를 작성하려면 테이블 구조를 명확하게 이해하는 게 필수적이었거든. 결국 ERD를 통해 테이블과 컬럼을 시각적으로 연결하는 방법을 익히게 된 거지.

내가 헷갈린 지점#

처음에는 ERD 그림의 컬럼 이름이나 관계가 실제 데이터베이스 테이블과 정확히 어떻게 연결되는지 파악하는 데 어려움을 느꼈다. 특히, 그림에서 일부 컬럼이 생략되어 있을 때, 어떤 정보가 빠져있는 건지, 혹은 그 컬럼이 존재하지 않는 건지 혼동되는 경우가 많았다. 테이블 간의 관계가 복잡해질수록 그림만으로는 테이블 구조를 완전히 이해하기 어려웠다.

시도한 코드 / 예시#

-- 최대 주문 수량 확인
SELECT MAX(quantity) AS MaxQuantity
FROM orders LEFT JOIN customers ON orders.customer_id = customers.id;

결과와 해석#

ERD를 보면서 테이블 간의 관계를 파악하는 연습을 했어요. 실제 테이블 구조를 제대로 이해하지 못해서 JOIN 조건 설정에 어려움을 겪었는데, ERD 상의 관계를 바탕으로 테이블 이름과 컬럼명을 연결하는 연습을 통해 조금 더 명확하게 이해할 수 있었습니다. 예를 들어, customers 테이블과 orders 테이블이 customer_id로 연결되어 있다는 것을 ERD에서 확인하고, 이를 JOIN 조건에 반영했습니다.

정리된 이해#

ERD 그림을 통해 테이블 간의 관계와 각 테이블이 가지는 컬럼 정보를 파악해야 실제 쿼리를 작성할 수 있습니다. 컬럼이 생략된 경우, 문제에서 주어진 조건과 테이블 간의 관계를 유추하여 누락된 컬럼의 존재 여부를 판단해야 합니다. ERD를 정확하게 해석하는 것은 데이터베이스의 구조를 이해하고 효율적인 쿼리를 작성하는 데 필수적입니다.

총평#

오늘 전체에서 배운 것#

SQL 함수와 JOIN 종류의 개념을 다시 한번 정리했고, 서브쿼리가 문제 해결에 어떻게 활용될 수 있는지 감을 잡았습니다. ERD 그림을 보면서 테이블 구조를 파악하는 연습을 꾸준히 해야겠습니다.

다음에 조심할 것#

ERD 그림을 볼 때, 컬럼이 생략된 경우 테이블 구조를 꼼꼼히 다시 확인하고, 서브쿼리가 문제 상황에 어떻게 적용되어야 하는지 끊임없이 질문하며 풀어야겠다. 특히 JOIN 조건을 정확히 파악하는 데 더 집중해야 할 것 같다.

다음 복습 주제#

LEFT JOIN과 RIGHT JOIN의 실제 데이터 변화를 시각적으로 비교해보면서 완전히 이해하고 싶다. 서브쿼리를 활용한 복잡한 쿼리 작성 연습을 꾸준히 해야겠다. ERD를 더 빠르게 파악할 수 있도록 다양한 유형의 ERD를 풀어봐야겠다.
