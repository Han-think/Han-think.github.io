1. SQL 윈도우 함수와 인라인 뷰 활용법#

무엇을 배웠나#

SQL 윈도우 함수에서 PARTITION BY는 데이터를 필터링하는 것이 아니라 윈도우 함수가 계산될 영역을 나누는 역할을 한다는 것을 명확히 이해하게 되었습니다. 또한 LAG와 LEAD 함수를 사용할 때 ORDER BY절의 중요성을 인지하고, 인라인 뷰를 활용하여 쿼리를 구조화하는 방법을 익혔습니다. 이제 복잡한 데이터 분석 쿼리를 작성하는 데 도움이 될 것 같습니다.

헷갈렸던 점#

SQL 윈도우 함수에서 PARTITION BY와 NTILE이 ‘나누다’는 의미로 사용되는데, 이 둘의 역할이 달라서 혼동되었고, LAG와 LEAD 함수가 이전/다음 행의 값을 어떻게 가져오는지 파악하기 어려웠다. 인라인 뷰가 무엇이고 어떻게 활용하는지 역시 처음에는 명확하게 이해하지 못했다.

정리된 이해#

SQL 윈도우 함수에서 PARTITION BY는 데이터를 필터링하는 것이 아니라 윈도우 함수의 계산 범위를 나누는 역할을 하며, LAG와 LEAD 함수는 ORDER BY 절과 함께 이전/다음 행의 값을 참조하는 데 사용된다는 것을 명확히 이해하게 되었다. 또한, 인라인 뷰는 임시 결과표를 생성하여 복잡한 쿼리를 단순화하는 데 유용한 도구임을 확인했다. 이제 윈도우 함수와 인라인 뷰를 활용하여 데이터 분석 작업을 더욱 효율적으로 수행할 수 있을 것 같다.

SELECT
    customerName,
    country,
    creditLimit,
    AVG(creditLimit) OVER (PARTITION BY country) AS avgCreditByCountry
FROM customers
WHERE creditLimit IS NOT NULL
ORDER BY country ASC, creditLimit DESC;

SELECT *
FROM (
    SELECT customerNumber, paymentDate, amount
    FROM payments
    WHERE paymentDate BETWEEN '2023-01-01' AND '2023-12-31'
)

2. SQL 도구와 AI 자동화, 데이터 질의의 괴리를 어떻게 좁힐까#

무엇을 배웠나#

SQL 자동화 도구가 생각보다 완벽하게 작동하지 않더라도, 핵심은 문제를 데이터 질의로 변환하는 과정이라는 것을 깨달았습니다. AI 도구는 쿼리 생성 과정을 돕지만, 반드시 검증하고 오류를 수정하는 과정이 필요하며, 이는 데이터 질의 번역 능력을 향상시키는 데 중요한 역할을 합니다. 자주 사용하는 쿼리 패턴을 템플릿화하여 재사용하는 습관을 들여야 효율적으로 작업할 수 있을 것 같습니다.

헷갈렸던 점#

SQL과 AI 자동화 도구를 사용할 때, ERD를 기반으로 간단하게 쿼리가 생성될 것이라고 기대했지만, 실제로는 테이블명이나 컬럼명을 일일이 확인해야 하는 상황에 당황했습니다. AI가 생성한 쿼리는 반드시 검증이 필요하다는 것을 깨달았고, SQL 학습이 단순히 코딩이 아니라 문제 해결 능력과 밀접하게 연결되어 있음을 알게 되었습니다.

정리된 이해#

SQL 학습의 어려움은 단순히 문법 암기가 아닌, 실제 문제를 데이터 질의로 변환하는 과정에 있다는 것을 깨달았습니다. AI 도구는 이 과정을 돕지만, 생성된 쿼리는 반드시 검증해야 하며, 특히 존재하지 않는 컬럼 사용이나 JOIN 조건 오류 같은 부분을 주의해야 합니다. 자주 사용하는 쿼리 패턴을 템플릿화하여 효율성을 높이는 방법도 중요하다고 생각합니다.

SELECT customer_id, SUM(amount) AS total_spent
FROM orders
-- AI 제안: WHERE condition 추가 (예: customer_id = ?)
GROUP BY customer_id;

3. 프로젝트 DB와 클라우드 아키텍처 완벽 가이드#

무엇을 배웠나#

다양한 DB 종류와 각 DB가 적합한 프로젝트 시나리오를 이해하게 되었어. 개인 프로젝트에는 SQLite, 팀 프로젝트에는 MySQL/PostgreSQL, 대용량 분석에는 BigQuery와 같이 상황에 맞는 DB를 선택하는 기준을 세울 수 있게 되었어. 특히 클라우드 서비스 사용 시 비용 관리의 중요성을 깨닫고, 리소스 관리에 신경 써야겠다는 점도 알게 되었어.

헷갈렸던 점#

다양한 종류의 데이터베이스가 존재한다는 건 알고 있었지만, 각각 어떤 상황에 적합한지 명확하게 구분하지 못해서 프로젝트를 시작할 때 어떤 DB를 선택해야 할지 어려움을 겪었습니다. 클라우드 서비스와 관리형 DB 서비스의 차이점도 잘 몰라서 클라우드 비용을 예측하고 관리하는 데 어려움이 있었습니다.

정리된 이해#

프로젝트의 규모와 목적에 따라 적절한 데이터베이스를 선택하는 것이 중요하며, 개인 프로젝트나 간단한 웹 서비스에는 SQLite, MySQL, PostgreSQL이 적합하고, 대용량 데이터 분석에는 BigQuery를 고려해야 한다. 클라우드 서비스를 이용할 때는 비용 관리에 신경 쓰고, 리소스 관리를 통해 예산을 효율적으로 사용해야 한다.

4. 테이블 정의와 데이터 타입, 정합성 이해하기#

무엇을 배웠나#

데이터베이스에서 데이터 타입을 명시적으로 정의하는 것의 중요성을 깨달았습니다. 데이터 타입은 단순히 데이터 형식을 규정하는 것이 아니라 데이터의 의미와 사용 규칙을 고정하여 데이터 일관성을 유지하는 데 필수적이라는 것을 알게 되었습니다. 앞으로는 데이터베이스를 설계할 때 데이터 타입 선택에 더욱 신중을 기해야겠습니다.

헷갈렸던 점#

데이터베이스에서 데이터 타입을 명시적으로 정의해야 하는 이유를 처음에는 잘 몰랐습니다. 특히 날짜 형식이 다양해서 데이터베이스에서 어떻게 관리해야 할지 혼란스러웠습니다.

정리된 이해#

데이터베이스는 파일과 달리 데이터 타입이 단순한 형식 정의를 넘어 데이터의 의미와 사용 규칙을 명확히 규정하며, 이를 통해 데이터 일관성을 확보합니다. DATE 타입과 같이 데이터 타입을 명시적으로 정의하면 데이터의 정확성과 활용도를 높일 수 있습니다. 앞으로는 데이터 타입 선택 시 데이터의 의미와 목적을 고려하여 신중하게 결정해야겠습니다.

CREATE TABLE learning_notes (
    note_id INT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(255) NOT NULL,
    created_at DATE NOT NULL DEFAULT CURRENT_DATE,
    content TEXT,
    last_modified DATE
);

총평#

오늘 오전 전체에서 배운 것#

SQL 윈도우 함수 활용법과 인라인 뷰를 익혀 복잡한 데이터 분석 쿼리 작성에 도움이 될 것 같고, SQL 자동화 도구를 효율적으로 활용하기 위해 데이터 질의 번역 능력을 키워야 함을 알게 되었다. 또한 다양한 DB 종류와 클라우드 아키텍처에 대한 이해를 높여 프로젝트에 적합한 DB를 선택하고 비용 관리에도 신경 쓸 수 있게 되었다.

다음에 조심할 것#

SQL 윈도우 함수와 인라인 뷰를 익혔지만, 실제 데이터 분석 쿼리에 적용하면서 예상치 못한 에러가 발생할 수 있으니 꾸준히 연습해야겠다. AI 자동화 도구를 활용할 때는 맹신하지 않고 결과의 정확성을 항상 검증하는 습관을 들여야 할 것 같고, 클라우드 환경에서 DB를 사용할 때는 비용 관리에도 더욱 신경 써야겠다.

다음 복습 주제#

SQL 윈도우 함수를 활용한 복잡한 분석 쿼리를 실제로 작성하며 응용해보고, AI 자동화 도구를 사용할 때 발생하는 오류를 수정하는 과정을 통해 데이터 질의 번역 능력을 더 향상시켜야겠다. 클라우드 환경에서 DB를 사용할 때 비용 최적화를 위한 전략과 리소스 관리 노하우를 익히는 것도 중요할 것 같다.
