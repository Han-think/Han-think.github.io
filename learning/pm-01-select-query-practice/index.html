1. OR 조건#

왜 이걸 보게 됐나#

처음에는 여러 조건을 연결해서 데이터 필터링하는 방법을 OR을 여러 번 사용해서 표현하려고 했는데, 너무 번거롭고 가독성이 떨어진다는 것을 깨달았어. 그래서 여러 값을 비교할 때 IN을 사용하는 것이 훨씬 효율적이라는 것을 알게 되었지. 좀 더 깔끔하고 간결하게 SQL 쿼리를 작성하고 싶어서 OR 대신 IN을 배우게 됐어.

내가 헷갈린 지점#

처음에는 OR을 여러 번 사용해서 여러 조건을 연결하는 게 맞는 줄 알았어. 예를 들어, 여러 나라를 포함시키려고 OR을 계속 이어썼지. 그런데 나중에 IN 키워드를 알게 되면서 훨씬 간결하게 표현할 수 있다는 것을 깨달았어.

시도한 코드 / 예시#

SELECT *
FROM customers
WHERE Country = 'USA' OR Country = 'Canada';

결과와 해석#

처음에는 OR을 여러 번 사용해서 여러 나라를 선택하는 조건식을 작성했는데, IN 키워드를 사용하면 훨씬 간결하고 가독성이 좋다는 것을 알게 되었다. IN을 사용하면 컬럼 값들이 여러 개의 지정된 값과 비교되는 것을 한 번에 표현할 수 있어서 코드량이 줄어들고 이해하기도 편하다. 예를 들어, ‘USA’ 또는 ‘Canada’ 고객을 선택할 때 OR을 반복하는 것보다 IN을 사용하는 것이 훨씬 효율적이다.

정리된 이해#

처음에 여러 조건을 연결할 때 OR을 반복적으로 사용하면 되는 줄 알았지만, 같은 컬럼에 대해 여러 값을 비교할 때는 IN 키워드를 사용하는 것이 훨씬 간결하고 가독성이 좋다는 것을 알게 되었다. IN을 사용하면 코드를 더 쉽게 이해하고 유지보수할 수 있다. 예를 들어, 여러 국가를 검색할 때 WHERE Country IN ('USA', 'Canada')처럼 표현하는 것이 더 효율적이다.

2. LIKE 와일드카드#

왜 이걸 보게 됐나#

처음에는 OR 조건처럼 여러 값을 비교할 때 LIKE 연산자가 어떻게 활용되는지 감이 잘 안 잡혔어. 패턴 매칭이 제대로 되는지 확신이 안 들어서, 이름 검색할 때 원하는 결과만 나오는지 계속 확인해야 했거든. 그래서 LIKE와 와일드카드의 정확한 사용법을 익히고 싶었어.

내가 헷갈린 지점#

처음에는 LIKE 연산자를 사용할 때 % 와일드카드의 위치가 결과에 어떤 영향을 미치는지 정확하게 파악하지 못해서, 패턴이 예상과 다르게 작동하는 경우가 있었어. 특히, % 가 앞이나 뒤에 붙었을 때 어떤 레코드를 포함하는지 혼동했지. 예를 들어, ‘%Live’ 와 ‘Live%’ 의 차이를 명확히 이해하지 못했던 것 같아.

시도한 코드 / 예시#

-- 이름이 "K"로 시작하는 경우
SELECT *
FROM customers
WHERE CustomerName LIKE 'K%';

-- 이름이 "Live"로 끝나는 경우
SELECT *
FROM customers
WHERE CustomerName LIKE '%Live';

-- 이름에 "Love"가 포함된 경우
SELECT *
FROM customers
WHERE CustomerName LIKE '%Love%';

결과와 해석#

LIKE 연산자를 사용할 때 %는 0개 이상의 문자를 나타내고 _는 정확히 1개의 문자를 나타낸다는 것을 실습을 통해 확실히 알게 되었다. 예를 들어, WHERE City LIKE 'A%'는 ‘A’로 시작하는 모든 도시를 찾았고, WHERE City LIKE '_ondon'은 두 글자로 끝나는 도시를 찾았는데, 좀 더 복잡한 패턴을 검색할 때 유용하다는 것을 깨달았다. 이러한 와일드카드를 활용하면 다양한 방식으로 데이터 검색 범위를 조정할 수 있었다.

정리된 이해#

LIKE 연산자는 문자열 패턴 매칭을 할 때 사용하며, %는 0개 이상의 문자를 나타내고 _는 정확히 1개의 문자를 나타낸다. 예를 들어 이름이 “K"로 시작하는 고객을 찾을 때는 ‘K%‘를 사용하고, 이름이 “Live"로 끝나는 고객을 찾을 때는 ‘%Live’를 사용하며, 이름에 “Love"가 포함된 고객을 찾을 때는 ‘%Love%‘를 사용한다. 와일드카드의 위치에 따라 패턴 매칭의 범위가 달라진다.

3. SQL 기본 문법#

왜 이걸 보게 됐나#

데이터베이스를 다루는 기본적인 방법부터 익혀야 앞으로 더 복잡한 쿼리를 작성하고 데이터를 효율적으로 관리할 수 있을 것 같아서 SQL 기본 문법을 배우게 되었다. 특히, 데이터를 검색하고 필터링하는 SELECT 문의 기본을 이해하는 것이 데이터 분석의 첫걸음이라고 생각했기 때문이다. 앞으로 다양한 데이터베이스 시스템을 사용해야 할 일이 있을 것을 대비해서, 기초를 확실히 다져두는 것이 중요하다고 판단했다.

내가 헷갈린 지점#

처음에는 여러 조건을 연결할 때 OR을 반복해서 사용하는 게 맞다고 생각했는데, IN을 사용하면 훨씬 간결하고 읽기 편하다는 것을 깨달았다. 그리고 LIKE 연산자의 와일드카드 %가 어디에 위치하느냐에 따라 매칭되는 범위가 달라지는 점을 정확히 이해하지 못해, 패턴 매칭에서 엉뚱한 결과를 얻기도 했다.

시도한 코드 / 예시#

SELECT 컬럼명
FROM 테이블명
WHERE 조건
ORDER BY 정렬기준
LIMIT 개수;

결과와 해석#

SQL 기본 문법은 테이블에서 원하는 데이터를 선택하고 필터링하는 데 필요한 핵심 틀을 제공해줘서 이해하기 중요했어. SELECT, FROM, WHERE 키워드들을 조합하여 원하는 컬럼을 선택하고 특정 조건을 만족하는 레코드만 추출할 수 있다는 것을 알게 되었어. 특히, WHERE 절에서 IN 연산자를 사용하면 여러 값을 비교할 때 코드를 더 간결하게 만들 수 있다는 점이 인상 깊었어.

정리된 이해#

SQL SELECT 문은 테이블에서 원하는 데이터를 가져오는 기본적인 방법이며, WHERE 절을 사용해 조건을 설정하여 특정 데이터만 선택할 수 있다. 여러 조건을 조합할 때는 IN 키워드를 활용하여 가독성을 높일 수 있고, LIKE 연산자를 사용하면 패턴 매칭을 통해 원하는 데이터를 추출할 수 있다.

4. 범위 조건#

왜 이걸 보게 됐나#

데이터 분석을 하려니 특정 금액대 사이의 거래 건수를 확인해야 하는 경우가 발생했고, 그냥 ‘5보다 크고 10보다 작은 값’이라고 조건을 따로 적으면 코드가 복잡해질 것 같았어. BETWEEN을 사용하면 조건식을 더 간결하고 명확하게 표현할 수 있다는 것을 알게 됐지.

내가 헷갈린 지점#

Total 컬럼이 5에서 10 사이의 값을 갖는 인보이스를 찾는다는 ‘범위 조건’을 처음에는 5보다 크고 10보다 작은 값만 포함한다고 생각했었다. 즉, 5나 10은 포함되지 않는다고 오해했고, WHERE절에 조건을 입력할 때 어려움을 느껴서 꼼꼼히 확인해야 했다. BETWEEN 연산자가 포함되는 범위에 경계값도 포함한다는 것을 명확히 이해하고 나니, 조건문을 작성하는 것이 훨씬 쉬워졌다.

시도한 코드 / 예시#

SELECT *
FROM invoices
WHERE Total BETWEEN 5 AND 10;

결과와 해석#

Total 컬럼의 값이 5에서 10 사이인 모든 청구서를 가져오는 조건을 사용해봤어. BETWEEN 키워드를 이용하면 특정 범위 내의 값들을 쉽게 검색할 수 있다는 것을 알게 되었고, 실제 데이터 테이블에서 조건을 만족하는 레코드들을 확인하는 실습을 통해 이해도를 높일 수 있었어. 예를 들어, 총액이 7.5달러인 청구서도 범위 조건에 포함되는 것을 확인했지.

정리된 이해#

BETWEEN 연산자를 사용하면 특정 컬럼의 값이 지정된 범위 내에 속하는 레코드를 쉽게 찾을 수 있어 데이터 분석 시 유용하다. 예를 들어, 청구서의 총액이 5에서 10 사이의 값들을 한 번에 검색할 수 있으며, 이는 여러 개의 OR 조건 사용보다 훨씬 간결하고 가독성이 좋다. 범위 조건을 사용할 때는 시작 값과 끝 값을 정확히 이해하고 데이터 타입에 맞게 지정해야 한다.

총평#

오늘 전체에서 배운 것#

OR 조건을 여러 번 사용하는 것보다 IN 키워드를 사용하면 더 간결하게 여러 조건을 표현할 수 있다는 것을 알게 되었다. 또한 LIKE 연산자의 와일드카드 위치에 따라 검색 범위가 달라지는 점을 명확히 이해하게 되었다. SQL 기본 문법과 범위 조건을 복습하고 응용할 수 있는 실습을 진행했다.

다음에 조심할 것#

OR 조건을 사용할 때 IN 키워드를 활용하는 것을 명심하고, LIKE 연산자의 와일드카드 위치에 따라 패턴이 어떻게 달라지는지 다시 한번 확인해야겠다. 특히 LIKE 문의 다양한 패턴 조합을 좀 더 연습해서 실제 데이터 검색에 익숙해져야 할 것 같다.

다음 복습 주제#

ORDER BY 절을 활용한 정렬 및 집계 함수(COUNT, SUM, AVG 등) 사용법을 좀 더 깊이 파악하고 싶다. 특히 복잡한 조건과 함께 정렬 및 집계 함수를 사용하는 경우를 연습해봐야겠다.
