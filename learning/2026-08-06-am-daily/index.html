1. JavaScript this와 바인딩: 초보자를 위한 완벽 이해#

무엇을 배웠나#

템플릿 리터럴은 문자열 내에 JavaScript 표현식을 삽입하여 값을 쉽게 넣을 수 있다는 것을 이해하게 되었고, this가 함수 호출 방식에 따라 동적으로 결정된다는 점을 명확히 알게 되었다. 특히 apply, call, bind의 차이점을 이해하고 콜백 함수에서 bind가 왜 유용한지 알 수 있었으며, 화살표 함수가 this 바인딩에 미치는 영향에 대해서도 학습했다. 앞으로는 이러한 점들을 염두에 두고 JavaScript 코딩을 진행해야겠다.

헷갈렸던 점#

this가 어디를 가리키는지에 따라 결과가 달라져서 예측하기 어려웠고, apply, call, bind의 차이점을 명확하게 이해하지 못해서 어떤 상황에 어떤 함수를 써야 할지 헷갈렸습니다. 화살표 함수를 사용하면 this 바인딩이 달라진다는 것도 인지했지만, 객체 메서드 안에서 사용할 때 예상치 못한 동작이 발생할 수 있다는 점이 명확하게 이해되지 않았습니다.

정리된 이해#

JavaScript에서 this는 함수가 호출되는 방식에 따라 결정되는 동적인 값이며, apply, call, bind는 이 this 값을 명시적으로 변경하는 데 사용된다. 템플릿 리터럴은 문자열 내에 JavaScript 표현식을 삽입하여 문자열을 만들 때 매우 유용하며, 화살표 함수는 특정 상황에서 this 바인딩 문제를 해결하는 데 도움을 준다.

const obj = {
  name: "Elice",
  introduce: function() {
    console.log(`이름은 ${this.name}입니다.`); // obj 객체를 가리킴
  }
};
obj.introduce();

2. 실행 컨텍스트, 스코프, 호이스팅 완벽 이해#

무엇을 배웠나#

변수와 함수 선언이 코드 실행 전에 메모리에 등록되는 호이스팅 현상을, 코드 줄 이동이 아닌 등록 과정으로 이해하게 되었어. 또한, var, let, const의 동작 방식 차이와 함수 선언문과 표현식의 차이점을 명확히 구분하고, 실행 컨텍스트, 스코프 체인, 콜 스택의 역할을 구분하는 데 도움이 되었어. 이제는 이 개념들을 활용하여 코드의 실행 과정을 더 정확하게 예측할 수 있을 것 같아.

헷갈렸던 점#

호이스팅은 코드 줄이 실제로 이동하는 것처럼 생각했고, 함수 선언문과 표현식의 차이를 명확히 이해하지 못했습니다. var, let, const의 동작 방식 차이도 헷갈렸고, 실행 컨텍스트, 스코프 체인, 콜 스택의 관계가 복잡하게 느껴졌습니다.

정리된 이해#

코드 실행 전 변수와 함수 선언이 메모리에 등록되는 호이스팅 현상은 코드 자체의 이동이 아닌 등록 과정이고, 함수 선언문과 표현식, 그리고 var, let, const의 동작 방식 차이를 명확히 이해해야 한다. 실행 컨텍스트는 코드가 실행되는 환경을 정의하며, 스코프 체인은 변수 검색 시 적용되는 규칙을 나타내는 중요한 개념이다. 이러한 개념들을 통해 코드의 실행 과정을 더 깊이 이해할 수 있다.

// 호이스팅 예시 - 함수 선언문
console.log(myFunction); // undefined (함수 선언문이라 호이스팅되어 undefined로 출력)
myFunction(); // 함수 실행

function myFunction() {
  console.log("Hello from myFunction!");
}

// 호이스팅 예시 - 함수 표현식
// console.log(myFunctionExpression); // ReferenceError: Cannot access 'myFunctionExpression' before initialization
// myFunctionExpression();

const myFunctionExpression = function() {
  console.log("Hello from myFunctionExpression!");
};

myFunctionExpression();

// var, let, const 호이스팅 예시
// var: undefined로 초기화
console.log(x); // undefined
var x = 10;

// let, const: TDZ (Temporal Dead Zone)
// console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 10;

// const도 마찬가지
// console.log(z); // ReferenceError: Cannot access 'z' before initialization
const z = 10;

3. 비동기 처리, 타이머 함수, 이벤트 루프 완벽 이해#

무엇을 배웠나#

setTimeout 함수가 지정된 시간 이후 바로 실행되지 않고, 콜 스택이 비어있는 시점에 실행된다는 점을 명확히 이해하게 되었다. 싱글 스레드 환경에서도 비동기 처리가 가능한 이유가 콜 스택, 태스크 큐, 그리고 이벤트 루프의 상호작용을 통해 설명된다는 것을 알게 되었고, this 키워드와 실행 컨텍스트가 비동기 작업의 실행 시점과 연결되어 있다는 점도 새롭게 깨달았다. 이 내용을 바탕으로 좀 더 복잡한 비동기 코드를 이해하고 작성할 수 있을 것 같다.

헷갈렸던 점#

setTimeout이 정확히 지정된 시간 후에 실행될 거라고 생각했고, 싱글 스레드인데 어떻게 여러 작업을 동시에 처리하는지, 그리고 콜 스택과 태스크 큐가 어떤 차이가 있는지 감이 잘 안 잡혔다. this 키워드를 공부하다가 바로 비동기 처리에 넘어간 게 주제 전환에 어려움을 더했다.

정리된 이해#

JavaScript는 싱글 스레드이지만, 콜 스택과 태스크 큐, 이벤트 루프의 조합으로 비동기 처리를 구현하여 동시에 여러 작업을 처리할 수 있다는 점을 명확히 이해하게 되었다. setTimeout의 지연 시간은 최소 대기 시간이며, 콜 스택이 비어있는지 확인하는 이벤트 루프의 역할이 중요하며, this 키워드와 실행 컨텍스트 이해는 비동기 작업의 실행 시점을 파악하는 데 필수적임을 알게 되었다.

// 콜 스택과 태스크 큐 이해를 위한 예시
console.log("Start"); // 콜 스택에 추가

setTimeout(() => {
  console.log("Async Task"); // 태스크 큐에 추가
}, 1000);

console.log("Continue"); // 콜 스택에서 실행

// 이벤트 루프 이해를 위한 예시
console.log("A");
setTimeout(() => console.log("B"), 0);

4. 비동기 결과 처리와 콜백 지옥 해소#

무엇을 배웠나#

setTimeout 내에서 변수를 변경해도 즉시 바깥에서 반영되지 않고, 콜백 내 return은 콜백 함수 자체에만 영향을 준다는 것을 알게 되었다. 비동기 결과를 처리하기 위해 콜백을 전달하는 방식이 복잡하게 느껴졌지만, 이제는 결과 전달의 역할을 좀 더 명확하게 이해하게 되었다. 여러 콜백이 중첩되는 콜백 지옥의 문제점도 인지하게 되었다.

헷갈렸던 점#

setTimeout 안에서 변수를 변경해도 바깥에서 바로 값이 바뀌지 않는 점이 처음에는 헷갈렸고, 콜백 함수 내의 return이 바깥 함수에 영향을 줄 거라고 생각했습니다. 비동기 작업 결과를 받기 위해 콜백 함수를 전달하는 방식이 함수 경계를 흐릿하게 만들어 이해하기 어려웠습니다. 여러 비동기 작업이 겹쳐서 발생하는 콜백 지옥의 복잡성이 가독성을 떨어뜨리는 이유가 명확하지 않았습니다.

정리된 이해#

setTimeout과 같은 비동기 함수 내에서 변수를 변경해도 즉시 바깥에서의 변화를 반영하지 않으며, 콜백 함수 내의 return은 콜백 자체만 종료할 뿐 바깥으로 값을 전달하지 못합니다. 비동기 결과 처리를 위해 콜백을 전달하는 방식은 함수 간의 관계를 복잡하게 만들 수 있으며, 여러 콜백이 중첩되면 코드의 가독성이 떨어지는 콜백 지옥 현상이 발생할 수 있습니다. 이러한 문제들을 해결하기 위해 Promise나 async/await와 같은 대체 방법을 사용하는 것이 중요합니다.

function plus(a) {
  let result = 0;
  setTimeout(() => {
    result = a + 10;  // 안쪽에서 변경되었지만 바깥에서 즉시 반영되지 않음
  }, 100);
  console.log("비동기 방식:", result);  // 초기값 0 출력
}

function plus(a) {
  setTimeout(() => {
    return a + 10;  // 이 반환은 콜백 내에서만 유효
  }, 100);
}

function plusCall(a, onResult) {
  setTimeout(() => {
    onResult(a + 10);  // 결과 전달을 위한 콜백 호출
  }, 100);
}

5. 객체 메서드 실습: 초보자의 흔한 오류와 핵심 이해#

무엇을 배웠나#

객체 메서드를 사용할 때 값 반환과 상태 변경의 차이, 그리고 return this의 역할에 대해 헷갈렸던 점을 명확히 이해하게 되었습니다. getter와 setter의 차이를 통해 상태 변경이 필요한 경우를 구분할 수 있게 되었고, 메서드 체이닝의 필요성을 이해하며 코드 구조에 대한 고민도 덜게 되었습니다. 앞으로는 철자 및 문법 오류에 더욱 주의하며 코드를 작성할 것입니다.

헷갈렸던 점#

객체 메서드를 만들 때 메서드 내에서 값을 반환해야 하는지, 아니면 객체의 상태를 직접 변경해야 하는지, 그리고 return this의 역할이 무엇인지 명확히 이해하지 못했습니다. 또한, 파일 구조와 모듈화 방식, 그리고 객체 기반 코드에서 함수 호출 방식이 어떻게 달라지는지에 대해서도 혼란스러웠던 부분이 있었습니다.

정리된 이해#

객체 메서드에서는 값을 반환하는 것과 객체 상태를 직접 변경하는 것의 차이를 명확히 이해하고, setter 메서드에서는 항상 객체의 프로퍼티를 직접 수정해야 합니다. return this는 메서드 체이닝을 위한 선택적인 기능이며, 사용하지 않더라도 메서드는 정상적으로 동작합니다.

setAge: function(newAge) {
  this.age = newAge;  // 상태 변경 필수
}

오늘 오전에는 JavaScript의 핵심 개념들을 깊이 있게 학습했습니다. 특히 this 바인딩, 실행 컨텍스트, 비동기 처리, 그리고 객체 메서드에 대한 이해를 높였고, 이를 통해 코드의 실행 과정과 동작 방식을 더 정확하게 예측할 수 있게 되었습니다. 앞으로는 오늘 배운 내용을 바탕으로 더욱 효율적이고 안정적인 JavaScript 코드를 작성할 수 있을 것 같습니다.

다음에 조심할 것#

this 바인딩, 실행 컨텍스트, 비동기 처리 개념이 서로 얽혀있어서, 코드를 작성할 때 각 상황에 맞는 this가 어떻게 결정되는지, 스코프가 어떻게 작동하는지, 그리고 비동기 작업이 언제 실행되는지를 항상 염두에 두어야겠어. 특히 bind 사용과 화살표 함수의 this 바인딩에 대한 이해를 더욱 심화시켜야 실수를 줄일 수 있을 것 같아.
