1. 파일 업로드의 두 얼굴: 미리보기와 전송#

무엇을 배웠나#

File 객체는 단순히 ‘파일 자체’가 아니라, 상황에 따라 Data URL로 변환되거나 FormData에 담겨 서버로 전송된다는 점이 핵심입니다. FileReader는 화면용 미리보기를 위해 파일을 문자열로 변환하는 반면, FormData는 실제 HTTP 요청을 통해 데이터를 전달할 때 파일과 텍스트 필드를 묶어주는 역할을 합니다. 이러한 구분만 명확히 하면 파일 업로드 로직이 하나의 블랙박스가 아니라 명확한 파이프라인으로 보이기 시작합니다.

헷갈렸던 점#

가장 큰 혼란은 File 객체가 단순히 ‘파일 자체’인 줄 알았는데, 상황에 따라 Data URL로 변환되거나 FormData에 담겨 서버로 간다는 점이었습니다.

또 다른 오해는 FileReader로 만든 데이터가 자동으로 서버에 전달된다고 생각했으나, 실제로는 화면용 미리보기용일 뿐 HTTP 요청에는 포함되지 않는다는 점을 나중에야 명확히 이해할 수 있었습니다.

정리된 이해#

FileReader는 선택된 파일을 브라우저 화면에 표시하기 위해 Data URL로 변환하는 반면, FormData는 텍스트와 파일을 서버가 인식할 수 있는 multipart 형식으로 묶어 네트워크를 통해 전송하는 객체라는 점이 핵심입니다. File 객체는 사용자가 직접 선택한 원본 데이터이며, Upload State는 React 등에서 파일 전송 전 임시로 보관해두는 공간 역할을 합니다. 따라서 미리보기와 실제 서버 전송은 각각 다른 도구를 거쳐야 하며, 이 두 단계의 구분만 명확히 하면 로직이 하나의 흐름으로 자연스럽게 연결됩니다.

// 1. File 객체 (선택된 파일 자체)
const file = e.target.files[0]; // input[type="file"]에서 선택됨

// 2. 미리보기용: FileReader로 Data URL 변환
const reader = new FileReader();
reader.onload = (e) => {
  const previewUrl = e.target.result; // 화면에 표시할 데이터
  setPreviewImage(previewUrl); // UI 업데이트
};
reader.readAsDataURL(file); // 파일 -> Data URL 변환

// 3. 서버 전송용: FormData에 파일 포함
const formData = new FormData();
formData.append('profileImage', file); // 필드명과 파일 객체 매핑
formData.append('username', nameInput.value); // 텍스트 필드도 함께 추가

// 4. fetch 등으로 서버 전송
await fetch('/upload-endpoint', {
  method: 'POST',
  body: formData // FormData 객체를 직접 바디에 전달
});

2. 이미지 경로와 데이터 흐름의 차이#

무엇을 배웠나#

업로드된 이미지가 화면에 표시되는 방식은 ‘정적 파일’과 ‘동적 엔드포인트’라는 두 가지 완전히 다른 경로를 따른다는 점을 명확히 구분하는 것이 핵심입니다. 단순히 “이미지가 안 보인다"는 현상만으로는 어디서 데이터가 오는지 알 수 없으며, files, ori_filename, file_idx 등 다양한 네이밍이 뒤섞여 있어 데이터 흐름을 추적하는 데 큰 혼란을 겪습니다. 결국 화면상의 이미지 출처를 파악하려면 파일이 public 폴더에 있는지, 아니면 서버 API 엔드포인트를 통해 file_idx로 조회되는지에 따라 접근 방법이 달라진다는 사실을 이해해야 합니다.

헷갈렸던 점#

가장 큰 혼란은 ‘이미지’라는 단어 하나로 다양한 데이터 경로가 뒤섞여 있다는 점이었습니다. 화면상에서는 모두 이미지로 보이지만, 실제로는 정적 파일과 동적 엔드포인트를 구분하는 개념이 필요했습니다. 특히 file_idx와 같은 서버 관리자식 식별자와 사용자가 업로드한 원래 이름의 차이를 명확히 이해하지 못했을 때 디버깅에 큰 어려움을 겪었습니다.

정리된 이해#

핵심은 **“화면상의 이미지 = 다양한 경로를 가진 데이터”**라는 점이다. 목록 아이콘은 정적 파일 경로이고, 상세 업로드 이미지는 file_idx를 통해 서버 엔드포인트에서 동적으로 조회되는 파일이다. 즉, “어디서 왔냐"에 따라 경로와 접근 방법이 완전히 달라지므로 이 구분이 안 되면 디버깅할 수밖에 없다.

// 1. 목록 화면: public 폴더 이미지 (정적)
<img src="/icons/user.png" alt="유저 아이콘" />

// 2. 상세 화면: 서버 엔드포인트 이미지 (동적)
// /photo/5 와 같은 경로로 file_idx를 통해 조회된 동적 파일
<img src={`/photo/${fileIdx}`} alt="상세 이미지" />

3. 카카오맵 적용, ‘키’와 ‘어디서’의 필수 계약#

무엇을 배웠나#

API 키를 단순히 코드에 입력하는 것만으로는 지도가 표시되지 않으며, SDK 도메인과 실제 실행 주소 등 환경 설정이 반드시 맞물려야 한다는 점을 깨달았다. 특히 Live Server 사용 시 포트 번호나 localhost와 127.0.0.1의 차이로 인해 SDK가 키를 인식하지 못해 지도가 안 뜨는 경험을 통해, ‘키 입력’과 ‘환경 설정’이 하나의 계약처럼 작동해야 한다는 것을 체감했다.

헷갈렸던 점#

API 키를 입력했는데도 지도가 표시되지 않는 이유는, 키 그 자체뿐만 아니라 트래픽을 허용하는 도메인과 실제 실행되는 브라우저 주소가 정확히 일치해야 하기 때문입니다.

특히 Live Server 사용 시 포트 번호나 localhost와 127.0.0.1의 차이 때문에 SDK가 키를 인증하지 못해 지도가 뜨지 않는 경우가 많았습니다.

정리된 이해#

API 키는 단순히 코드에 입력하는 값이 아니라, SDK 도메인과 실제 실행 주소가 일치할 때만 유효해지는 ‘서비스 계약’과 같다. 따라서 지도 표시를 위해서는 키 설정뿐만 아니라 트래픽을 허용한 도메인 목록과 브라우저 주소창에 보이는 실제 실행 주소가 정확히 맞물려야 한다.

<!-- HTML 구조 -->
<div id="map"></div>

<script>
  // 1. 카카오 SDK 스크립트 로딩 (domain이 중요!)
  const script = document.createElement('script');
  script.src = 'https://dapi.kakao.com/v2/maps/sdk.js?appkey=YOUR_JAVASCRIPT_KEY&services=map,coord';

  // 2. 스크립트 로드 후 지도 초기화
  script.onload = () => {
    const mapContainer = document.getElementById('map'); // 지도를 표시할 div
    const mapOption = {
      center: new kakao.maps.LatLng(33.450701, 126.570667), // 지도 중심좌표
      level: 3 // 지도 레벨
    };

    const map = new kakao.maps.Map(mapContainer, mapOption); // 지도를 생성합니다
  };

  document.head.appendChild(script);
</script>

총평#

오늘 오후 전체에서 배운 것#

파일 업로드는 Data URL과 FormData라는 두 가지 명확한 파이프라인 구조를 가지고 있으며, 이미지 표시 여부는 정적 파일 경로와 동적 API 엔드포인트 중 어디에 있는지 확인하는 것이 핵심입니다. 또한 카카오맵 SDK는 키 입력만으로는 해결되지 않고 도메인과 포트 설정 등 환경 구성과의 ‘계약’이 필수적임을 깨닫게 되었습니다.

다음에 조심할 것#

  • File 객체가 단순히 ‘파일 자체’가 아니라 Data URL이나 FormData로 변환되어 다른 목적을 수행한다는 점을 명확히 구분하여, 업로드 로직을 하나의 파이프라인으로 설계하는 습관을 들인다.
  • 화면상의 이미지 출처를 파악할 때는 public 폴더에 저장된 정적 파일인지, 아니면 서버 API 엔드포인트를 통해 file_idx로 조회되는 동적 데이터인지 정확히 확인하여 경로를 추적한다.
  • 카카오맵 SDK 적용 시, 단순히 키를 입력하는 것을 넘어 도메인과 포트 번호(localhost vs 127.0.0.1) 등 환경 설정이 정확하게 일치하는지 반드시 검증한다.

다음 복습 주제#

  1. 파일 업로드 시 Data URL과 FormData의 역할 차이를 명확히 이해하여, 파이프라인 구조를 머릿속에 그릴 수 있도록 만든다.
  2. 이미지 경로가 ‘정적 파일’인지 ‘동적 API 엔드포인트’인지 구분하는 습관을 들여, 화면 표시 여부를 진단할 때 출처를 빠르게 파악한다.
  3. API 키 입력과 함께 SDK 도메인, 포트 번호 등 환경 설정이 정확히 일치하는지 검증하여, 지도 표시 실패의 원인을 체계적으로 Elimination해 나간다.
