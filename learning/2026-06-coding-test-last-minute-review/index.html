시험 직전 요약강의#

운영체제, 리눅스, 파이썬 기초#

CPU = 계산 / 명령 처리
Memory = 실행 중인 데이터 임시 저장
Disk = 파일과 프로그램 영구 저장

Program = 디스크에 저장된 실행 파일
Process = 실행되어 메모리에 올라온 프로그램
Thread = 프로세스 안의 실행 흐름

FCFS = 먼저 온 순서대로 처리
SJF = 짧은 작업 먼저 처리
Deadlock = 서로 자원을 기다리며 아무도 진행하지 못하는 상태

교착상태 4조건은 이렇게 외우면 된다.

상호 배제 = 같이 못 씀
점유 대기 = 가진 채 기다림
비선점 = 강제로 못 뺏음
순환 대기 = 서로 물고 물림

리눅스 명령어는 “명령어가 무엇을 움직이는지”를 먼저 보면 덜 헷갈린다.

pwd = 현재 위치
ls = 목록 보기
cd = 이동
mkdir = 폴더 생성
cp = 복사
mv = 이동 / 이름 변경
rm = 삭제
cat = 파일 내용 보기

echo = 문자열 출력
grep = 문자열 검색
> = 덮어쓰기
>> = 추가
| = 앞 명령의 출력 결과를 뒤 명령 입력으로 전달

파이썬은 자료형이 핵심이다.

input()은 기본 str
숫자 계산하려면 int(), float() 필요
list = [] / 인덱스 접근 / 수정 가능
tuple = () / 수정 불가
dict = {} / key:value / key로 접근

DB와 SQL 핵심#

관계형 DB = 행(row)과 열(column)을 가진 테이블 구조
PK = 한 행을 고유하게 식별
FK = 다른 테이블의 PK를 참조
JOIN = 테이블을 연결해서 조회

정규화는 “중복을 줄이고 이상 현상을 막기 위해 테이블을 나누는 것”이다.

1NF = 한 칸에 값 하나
2NF = 복합키 일부에만 의존하는 부분 종속 제거
3NF = 일반 컬럼이 다른 일반 컬럼에 의존하는 이행 종속 제거

SQL 순서는 아래 틀을 먼저 외우면 된다.

SELECT 컬럼
FROM 테이블
WHERE 행 조건
GROUP BY 그룹 기준
HAVING 그룹 조건
ORDER BY 정렬 기준
LIMIT 개수;

JOIN은 결과에 어떤 행이 남는지를 생각하면 된다.

CROSS JOIN = 모든 조합
INNER JOIN = 양쪽에서 조건이 맞는 행만
LEFT JOIN = 왼쪽 테이블은 모두 살리고 없으면 NULL

서브쿼리와 다중행 연산자는 말뜻 그대로 연결한다.

IN = 목록 안에 있냐
ANY = 하나라도 만족하냐
ALL = 전부 만족하냐
EXISTS = 결과 행이 존재하냐

윈도우 함수는 원래 행을 줄이지 않고 옆에 계산 결과를 붙인다.

RANK() OVER (
    PARTITION BY 그룹컬럼
    ORDER BY 정렬컬럼 DESC
) AS rank_col

GROUP BY = 행이 그룹 단위로 줄어듦
윈도우 함수 = 원래 행 유지 + 계산 결과를 옆에 붙임

pandas, 시각화, 통계#

import pandas as pd
import numpy as np
from scipy import stats

pandas에서 자주 쓰는 함수는 아래 정도다.

하고 싶은 일 함수
CSV 읽기 pd.read_csv()
앞부분 보기 head()
컬럼/결측치/타입 확인 info()
값별 개수 세기 value_counts()
숫자 변환 pd.to_numeric()
날짜 변환 pd.to_datetime()
그룹별 계산 groupby()
범주형 교차표 pd.crosstab()

시각화는 데이터 형태에 맞춰 고르면 된다.

데이터 형태 먼저 떠올릴 그래프
범주형 1개 value_counts().plot(kind="bar"), plt.bar()
수치형 1개 plt.hist(), sns.histplot(), sns.boxplot()
수치형 2개 plt.scatter(), sns.scatterplot()
범주형 2개 pd.crosstab() 후 막대그래프
상관계수 표 sns.heatmap()

통계는 판단 문장을 외우는 게 중요하다.

평균 = 전체 합 / 개수, 극단값 영향 큼
중앙값 = 가운데 값, 극단값 영향 적음
최빈값 = 가장 자주 나온 값
분산/표준편차 = 퍼진 정도
IQR = Q3 - Q1
상관계수 = 두 변수가 같이 움직이는 정도, 인과관계 아님

가설검정은 아래 한 줄이 핵심이다.

H0 = 귀무가설 = 차이 없음 / 효과 없음 / 기본 주장
H1 = 대립가설 = 차이 있음 / 효과 있음 / 확인하고 싶은 주장
p-value < 0.05 → H0 기각
p-value >= 0.05 → H0 기각하지 못함

1종 오류 = H0가 참인데 기각
2종 오류 = H0가 거짓인데 기각하지 못함

z검정에서 자주 나오는 값도 같이 잡아둔다.

SE = σ / √n
z = (x̄ - μ0) / SE
오른쪽 단측 α=0.05 기준값 = 1.645
양측 α=0.05 기준값 = ±1.96

코딩형 예상문제 20개#

코딩형은 “완벽한 암기”보다 패턴 인식이 중요하다. 시험에서 테이블명과 컬럼명이 바뀌어도 구조를 그대로 적용하면 된다.

C01. SQL: 제품 라인별 제품 수 구하기#

products 테이블에서 productLine별 제품 수를 구하고, 제품 수가 많은 순서로 정렬하시오.

SELECT
    productLine,
    COUNT(*) AS product_count
FROM products
GROUP BY productLine
ORDER BY product_count DESC;

핵심은 ~별 = GROUP BY, 개수 = COUNT(*), 많은 순 = ORDER BY ... DESC다.

C02. SQL: 국가별 고객 수 구하기#

customers 테이블에서 country별 고객 수를 구하시오.

SELECT
    country,
    COUNT(*) AS customer_count
FROM customers
GROUP BY country
ORDER BY customer_count DESC;

C03. SQL: 2004년 주문 건수 구하기#

orders 테이블에서 2004년에 발생한 주문 건수를 구하시오.

SELECT
    COUNT(*) AS order_count_2004
FROM orders
WHERE strftime('%Y', orderDate) = '2004';

SQLite에서 날짜의 연도만 뽑을 때는 strftime('%Y', 날짜컬럼)을 쓸 수 있다.

C04. SQL: 제품 라인별 평균 MSRP 구하기#

products 테이블에서 productLine별 평균 MSRP를 구하고, 소수 둘째 자리까지 반올림하시오.

SELECT
    productLine,
    ROUND(AVG(MSRP), 2) AS avg_msrp
FROM products
GROUP BY productLine
ORDER BY avg_msrp DESC;

C05. SQL: INNER JOIN으로 국가별 총 주문 금액 구하기#

customers, orders, orderdetails를 연결하여 국가별 총 주문 금액을 구하시오. 금액은 quantityOrdered * priceEach로 계산한다.

SELECT
    c.country,
    ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS total_sales
FROM customers AS c
INNER JOIN orders AS o
    ON c.customerNumber = o.customerNumber
INNER JOIN orderdetails AS od
    ON o.orderNumber = od.orderNumber
GROUP BY c.country
ORDER BY total_sales DESC;

고객, 주문, 주문상세 순서로 연결한다. 매출은 수량 * 단가다.

C06. SQL: 제품 라인별 매출과 판매수량 구하기#

products와 orderdetails를 연결하여 productLine별 총 판매 수량과 총 매출을 구하시오.

SELECT
    p.productLine,
    SUM(od.quantityOrdered) AS total_quantity,
    ROUND(SUM(od.quantityOrdered * od.priceEach), 2) AS total_sales
FROM products AS p
INNER JOIN orderdetails AS od
    ON p.productCode = od.productCode
GROUP BY p.productLine
ORDER BY total_sales DESC;

C07. SQL: HAVING으로 3회 이상 구매 고객 찾기#

Classic Cars 제품 라인을 3회 이상 구매한 고객을 찾으시오.

SELECT
    c.customerNumber,
    c.customerName,
    COUNT(DISTINCT o.orderNumber) AS order_count
FROM customers AS c
INNER JOIN orders AS o
    ON c.customerNumber = o.customerNumber
INNER JOIN orderdetails AS od
    ON o.orderNumber = od.orderNumber
INNER JOIN products AS p
    ON od.productCode = p.productCode
WHERE p.productLine = 'Classic Cars'
GROUP BY c.customerNumber, c.customerName
HAVING COUNT(DISTINCT o.orderNumber) >= 3
ORDER BY order_count DESC;

WHERE는 그룹 전 행 조건이고, HAVING은 GROUP BY 이후 집계 조건이다.

C08. SQL: 평균보다 신용한도가 높은 고객#

전체 고객 평균 creditLimit보다 높은 고객을 조회하시오.

SELECT
    customerNumber,
    customerName,
    creditLimit
FROM customers
WHERE creditLimit > (
    SELECT AVG(creditLimit)
    FROM customers
)
ORDER BY creditLimit DESC;

비교 기준이 한 값이면 WHERE 안에 서브쿼리를 넣을 수 있다.

C09. SQL: 2003년과 2004년 모두 주문한 고객#

2003년에도 주문하고 2004년에도 주문한 고객을 찾으시오.

SELECT
    c.customerNumber,
    c.customerName
FROM customers AS c
WHERE c.customerNumber IN (
    SELECT customerNumber
    FROM orders
    WHERE strftime('%Y', orderDate) = '2003'
)
AND c.customerNumber IN (
    SELECT customerNumber
    FROM orders
    WHERE strftime('%Y', orderDate) = '2004'
);

둘 다 만족해야 하면 AND, 목록 안에 있어야 하면 IN을 쓴다.

C10. SQL: 한 번도 주문하지 않은 고객#

orders에 한 번도 등장하지 않은 고객을 찾으시오.

SELECT
    c.customerNumber,
    c.customerName
FROM customers AS c
WHERE c.customerNumber NOT IN (
    SELECT customerNumber
    FROM orders
);

같은 문제는 LEFT JOIN으로도 풀 수 있다.

SELECT
    c.customerNumber,
    c.customerName
FROM customers AS c
LEFT JOIN orders AS o
    ON c.customerNumber = o.customerNumber
WHERE o.orderNumber IS NULL;

C11. SQL: 고객별 결제액 순위 TOP 10#

payments에서 고객별 총 결제액을 구하고, 결제액 기준 순위를 매긴 뒤 TOP 10을 출력하시오.

SELECT
    customerNumber,
    total_amount,
    RANK() OVER (ORDER BY total_amount DESC) AS pay_rank
FROM (
    SELECT
        customerNumber,
        SUM(amount) AS total_amount
    FROM payments
    GROUP BY customerNumber
) AS t
ORDER BY pay_rank
LIMIT 10;

먼저 고객별 합계를 만든 뒤, 바깥 SELECT에서 RANK()를 붙인다.

C12. SQL: 국가 내 신용한도 순위#

고객의 국가별로 creditLimit이 높은 순위를 구하시오.

SELECT
    country,
    customerName,
    creditLimit,
    RANK() OVER (
        PARTITION BY country
        ORDER BY creditLimit DESC
    ) AS country_credit_rank
FROM customers
ORDER BY country, country_credit_rank;

PARTITION BY country는 국가별로 따로 순위를 계산한다는 뜻이다.

C13. SQL: 월별 매출과 전월 대비 증감#

월별 매출을 구한 뒤, LAG로 전월 매출과 전월 대비 증감을 구하시오.

WITH monthly_sales AS (
    SELECT
        strftime('%Y-%m', o.orderDate) AS order_month,
        SUM(od.quantityOrdered * od.priceEach) AS sales
    FROM orders AS o
    INNER JOIN orderdetails AS od
        ON o.orderNumber = od.orderNumber
    GROUP BY strftime('%Y-%m', o.orderDate)
)
SELECT
    order_month,
    ROUND(sales, 2) AS sales,
    ROUND(LAG(sales) OVER (ORDER BY order_month), 2) AS prev_sales,
    ROUND(sales - LAG(sales) OVER (ORDER BY order_month), 2) AS diff_sales
FROM monthly_sales
ORDER BY order_month;

C14. SQL: 한 번도 판매되지 않은 제품 찾기#

orderdetails에 한 번도 등장하지 않은 제품을 찾으시오.

SELECT
    p.productCode,
    p.productName
FROM products AS p
WHERE NOT EXISTS (
    SELECT 1
    FROM orderdetails AS od
    WHERE od.productCode = p.productCode
);

NOT EXISTS는 해당 조건을 만족하는 행이 존재하지 않는다는 뜻이다.

C19. Python: 독립표본 t-검정#

channel이 온라인, 오프라인인 두 집단의 monthly_sales 평균 차이를 독립표본 t-검정으로 확인하시오.

from scipy import stats

online = df.loc[df["channel"] == "온라인", "monthly_sales"]
offline = df.loc[df["channel"] == "오프라인", "monthly_sales"]

levene_stat, levene_p = stats.levene(online, offline)
equal_var = True if levene_p >= 0.05 else False

t_stat, p_value = stats.ttest_ind(online, offline, equal_var=equal_var)

print(round(t_stat, 3), round(p_value, 3))

판단문은 아래처럼 쓴다.

if p_value < 0.05:
    print("H0 기각: 두 집단 평균 차이가 유의함")
else:
    print("H0 기각하지 못함: 유의한 평균 차이를 확인하지 못함")

C20. Python: 카이제곱 독립성 검정#

hire_type과 final_pass 사이에 연관성이 있는지 카이제곱 검정하시오.

import pandas as pd
from scipy.stats import chi2_contingency

ct = pd.crosstab(df["hire_type"], df["final_pass"])
chi2, p_value, dof, expected = chi2_contingency(ct)

print(ct)
print(round(chi2, 3), round(p_value, 3))

if p_value < 0.05:
    print("H0 기각: 두 범주형 변수는 독립이 아님, 연관성이 있음")
else:
    print("H0 기각하지 못함: 연관성이 있다고 보기 어려움")

마지막 10분 벼락치기#

SQL은 이 틀부터 확인한다.

SELECT 컬럼
FROM 테이블
WHERE 조건
GROUP BY 그룹
HAVING 집계조건
ORDER BY 정렬 DESC
LIMIT 개수;

JOIN은 항상 ON 조건을 같이 확인한다.

SELECT *
FROM A
JOIN B
ON A.id = B.id;

윈도우 함수는 OVER()가 있어야 한다.

RANK() OVER (
    PARTITION BY 그룹
    ORDER BY 값 DESC
) AS 순위

pandas는 아래 패턴을 먼저 외운다.

pd.read_csv("file.csv")
df.head()
df.info()
df["col"].value_counts()
df.groupby("group")["value"].mean()
pd.crosstab(df["a"], df["b"])

통계 판단은 아래 문장으로 정리한다.

p < 0.05 → H0 기각
p >= 0.05 → H0 기각하지 못함
상관관계 ≠ 인과관계
독립표본 t-test = 서로 다른 두 집단 평균 비교
대응표본 t-test = 같은 대상의 전/후 비교
ANOVA = 3개 이상 집단 평균 비교
카이제곱 = 범주형 변수끼리 독립성/연관성 확인

운영체제와 리눅스는 이 정도를 바로 말할 수 있으면 된다.

Process = 실행 중인 프로그램
Thread = 프로세스 안 실행 흐름
Deadlock 4조건 = 상호배제, 점유대기, 비선점, 순환대기
SaaS = 인터넷으로 쓰는 완성형 소프트웨어
| = 앞 출력 → 뒤 입력
> = 덮어쓰기
>> = 추가

시험장에서 실수 줄이는 체크리스트#

[ ] SQL에서 SELECT 다음 콤마 빠뜨리지 않았나?
[ ] FROM 테이블명을 맞게 썼나?
[ ] JOIN에는 ON 조건이 있는가?
[ ] GROUP BY가 필요한 문제인가?
[ ] 집계 조건이면 WHERE가 아니라 HAVING인가?
[ ] ORDER BY DESC/ASC 방향이 맞나?
[ ] LIMIT 개수를 넣었나?
[ ] 서브쿼리 괄호를 닫았나?
[ ] 윈도우 함수에 OVER()를 썼나?
[ ] PARTITION BY와 ORDER BY의 역할을 헷갈리지 않았나?
[ ] pandas 컬럼명에 따옴표를 썼나?
[ ] p-value 판단을 반대로 하지 않았나?

출제 가능성 우선순위#

1순위는 직접 손으로 풀 수 있어야 한다.

SQL GROUP BY / HAVING
JOIN + GROUP BY
서브쿼리 IN / NOT IN / EXISTS
윈도우 함수 RANK / PARTITION BY / LAG
pandas groupby / value_counts / crosstab
p-value 해석

2순위는 객관식에서 자주 헷갈리는 영역이다.

정규화 1NF / 2NF / 3NF
ON / USING / NATURAL JOIN
상관관계 vs 인과관계
조건부 확률 / 독립성
Linux redirection / pipe / grep

3순위는 정의를 짧게 말할 수 있으면 충분하다.

CPU / Memory / Disk
Process / Thread
FCFS / SJF
Deadlock 4조건
SaaS / IaaS / PaaS

모르면 문제 문장을 먼저 쪼개면 된다. “~별”은 GROUP BY, “개수”는 COUNT, “평균 차이”는 t-test, “범주형끼리 관계”는 카이제곱, “순위”는 RANK() OVER()처럼 키워드를 코드 패턴으로 바로 연결하는 것이 마지막 복습의 목표다.
