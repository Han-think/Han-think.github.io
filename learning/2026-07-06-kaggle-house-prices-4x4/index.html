첫 Kaggle House Prices 도전: 4개의 선형 분석과 4개의 LLM 관점

기존 단순 선형, 오늘 강의형, 내 고급 선형, 조합형과 네 개 LLM 해석을 비교한 첫 Kaggle 학습 기록
2026년 7월 6일 · 10 min · AI 보조: GPT-OSS · Gemma · Magistral · Hermes

1. 첫 Kaggle 시도에서 질문이 바뀐 과정

House Prices는 주택 품질, 면적, 위치, 차고, 지하실, 판매 조건으로 SalePrice를 예측하는 회귀 문제다. 처음에는 여러 모델을 돌려 가장 낮은 점수를 제출하면 된다고 생각했지만, 실제 어려움은 모델 개수보다 데이터 의미와 검증 구조였다.

  • 결측치가 단순 누락이 아니라 시설 없음을 뜻하는 경우가 있었다.
  • SalePrice는 오른쪽 꼬리가 길어 log1p 타깃이 안정적이었다.
  • GrLivArea 고면적·저가격 사례가 회귀선을 흔들었다.
  • one-hot encoding 뒤 feature 수가 늘면서 단순 선형의 계수가 불안정해졌다.
  • local CV와 Kaggle public score가 달랐다.

어떤 모델이 가장 강한가가 아니라, 어떤 데이터 정책과 검증 구조에서 어떤 선형 모델을 써야 안정적인가?

2. EDA를 파이프라인으로 연결하기

EDA에서 OverallQual, GrLivArea, GarageCars, GarageArea, TotalBsmtSF, Neighborhood, ExterQual, KitchenQual, BsmtQual 등이 강하게 나타났다. 이를 의미 기반 결측치 처리와 파생변수로 연결했다.

NONE_COLS = ['PoolQC', 'MiscFeature', 'Alley', 'Fence', 'FireplaceQu',
             'GarageType', 'GarageFinish', 'BsmtQual', 'BsmtCond']
ZERO_COLS = ['GarageArea', 'GarageCars', 'BsmtFinSF1',
             'TotalBsmtSF', 'BsmtFullBath', 'MasVnrArea']

df['TotalSF'] = df['TotalBsmtSF'] + df['1stFlrSF'] + df['2ndFlrSF']
df['HouseAge'] = df['YrSold'] - df['YearBuilt']
df['HasGarage'] = (df['GarageArea'] > 0).astype(int)
df['OverallQual_TotalSF'] = df['OverallQual'] * df['TotalSF']

기존 단순 선형

LinearRegression은 개선 폭을 확인하는 기준선이다. 규제가 없어 test 최대 예측이 약 13,676,626까지 튀었고 fold 편차도 컸다.

오늘 강의형

Ridge, Lasso, ElasticNet과 tree 모델을 같은 5-fold CV, 같은 전처리, 같은 이상치 정책에서 비교했다. Id 524와 1299를 제거했을 때 fixed-alpha Lasso가 가장 안정적이었다.

정확한 해석

L1 규제와 Robust Scaling이 고차원 one-hot feature 공간의 계수와 예측을 안정화했다.

조합형

RidgeCV, LassoCV, ElasticNetCV의 OOF 예측을 가중 평균했지만 best single보다 조금 나빴다. 비슷한 선형 가정을 공유해 오류 상관이 높았기 때문이다.

앙상블은 모델 수가 아니라 서로 다른 오류가 있어야 이득이 생긴다.

4. 비선형 비교와 Kaggle 제출

HistGradientBoostingRegressor는 이상치 제거 시 0.125700 ± 0.008490이었다. 현재 데이터 크기와 feature 설계에서는 규제 선형이 더 안정적이었다.

실제 학습, CV, OOF, submission 생성은 scikit-learn 코드가 수행했다. LLM은 코드 검토, 설계 보조, 결과 해석 초안에 사용했다. 네 LLM의 결론을 투표로 결정하지 않고 코드와 숫자를 고정된 증거표로 삼았다.

6. 다각적 시각을 접목하는 법

  • 데이터: 결측치는 누락인가 시설 없음인가?
  • 모델: 계수 불안정인가 비선형 부족인가?
  • 검증: random KFold만으로 충분한가?
  • 사용자: 저가·노후·희소 지역의 큰 오차를 어떻게 표시할 것인가?

8. 다음 액션

  1. Neighborhood를 고려한 CV-safe encoding을 실험한다.
  2. 품질형 범주에 ordinal encoding을 적용한다.
  3. 저가·노후 주택과 취약 Neighborhood의 오류를 따로 분석한다.
  4. tree 모델이 규제 선형과 다른 오류를 내는지 확인한다.
  5. 앙상블은 OOF 상관과 그룹별 오류를 보고 조정한다.
  6. public leaderboard에 맞춘 과적합은 피한다.

총평

  • 기존 단순 선형은 실패 기준을 만들었다.
  • 오늘 강의형은 공정한 비교 규칙을 만들었다.
  • 내 고급 선형은 규제 강도 선택과 scaling을 체계화했다.
  • 조합형은 앙상블이 항상 좋아지는 것은 아님을 보여줬다.
  • 4개 LLM은 같은 증거를 다른 관점으로 읽었지만 최종 판단은 코드와 숫자로 고정했다.

좋은 모델은 점수가 한 번 낮게 나온 모델이 아니라, 어떤 데이터와 검증 조건에서 왜 선택됐는지 설명할 수 있는 모델이다.
