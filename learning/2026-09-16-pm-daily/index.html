1. 인터럽트와 메모리: 사람과 AI가 이어주는 흐름#

무엇을 배웠나#

interrupt_after, MemorySaver, thread_id, get_state()가 하나의 흐름 속에서 어떻게 상호작용하는지 이해하게 되었다. 핵심은 상태를 보존하며 멈췄다가 사람 확인 후 다시 실행하는 ‘일시정지 및 재개’ 패턴이다. 이를 통해 그래프 실행 중간에 사람의 개입을 자연스럽게 유도할 수 있게 되었다.

헷갈렸던 점#

가장 큰 혼란은 interrupt_after, MemorySaver, thread_id, get_state() 같은 용어가 각각 독립적인 개념처럼 보여서 전체 흐름을 잡기 어려웠습니다. ‘멈춤(interrupt)‘이라는 행위와 ‘상태 저장(MemorySaver)’, ‘세션 구분(thread_id)’, ‘확인(get_state)‘가 어떻게 맞물려 도는지 감이 안 잡혔습니다.

핵심은 “State를 잃지 않고 멈췄다가 사람 확인 후 이어가는 것"입니다. MemorySaver는 실행 중인 상태를 메모리에 보관하는 ‘책갈피’ 역할을 하고, thread_id는 같은 흐름을 유지하기 위한 세션 구분자입니다. interrupt_after=["writer"]는 writer 노드 실행 직후 그래프를 일시정지시켜 사람이 개입할 지점을 미리 지정하는 것이고, get_state()는 그래프가 멈춰있는 시점의 상태를 확인하여 다음 단계를 결정하는 역할을 합니다.

정리된 이해#

MemorySaver는 그래프 실행 중 상태를 보존하는 ‘책갈피’ 역할을 하며, thread_id는 연속적인 세션을 식별하는 고유값입니다. interrupt_after=[“writer”]는 writer 노드 실행 직후 자동으로 실행을 멈추고, get_state()로 현재 위치를 확인한 뒤 사용자 승인을 받아 resume()하면 그래프가 이어지는 흐름입니다.

# Human in the Loop 패턴 핵심 코드 예시

from langgraph.graph import StateGraph, START
from langgraph.checkpoint.memory import MemorySaver
from typing import TypedDict

class AgentState(TypedDict):
    content: str
    approved: bool  # 사람 승인 여부 플래그

# 그래프 정의 (간소화된 예시)
writer = lambda state: {"content": "초안 작성 완료"}
checker = lambda state: {"approved": True}  # 사람이 확인 후 True로 변경

graph = StateGraph(AgentState)
graph.add_node("writer", writer)
graph.add_node("checker", checker)
graph.add_edge(START, "writer")
graph.add_edge("writer", "checker")

# MemorySaver: 상태를 메모리에 유지 (책갈피 역할)
memory = MemorySaver()

# thread_id로 세션 구분
config = {"configurable": {"thread_id": "session_001"}}

# interrupt_after: writer 노드 실행 후 일시정지 설정
# person_in_the_loop가 개입할 지점을 미리 지정
app = graph.compile(checkpointer=memory, interrupt_after=["writer"])

# 상태 확인 (get_state): 현재 그래프 위치 snapshot
state_snapshot = app.get_state(config)
print(f"현재 노드 위치: {state_snapshot.values}")
# 출력 예시: 현재 노드 위치: {'content': '초안 작성 완료'}

# 사람 승인 후 resume (실제로는 사용자 입력 대기 후 실행)
# app.resume() 또는 app.stream()을 통해 다음 단계로 진행

2. 사람이 승인하고 router가 길을 여는 ‘human loop#

무엇을 배웠나#

Router는 판단자가 아니라 State를 읽고 길을 여는 교통정리 역할입니다. 사람은 승인 여부를 결정하고, router는 그 결정을 읽어 다음 단계로 넘어가는 ‘길’을 정합니다. 특히 update_state 함수를 통해 사람의 입력을 State에 기록한 뒤, router가 이를 바탕으로 경로를 선택한다는 점이 핵심입니다. 이러한 흐름을 이해하면 AI와 인간의 협업 구조를 명확히 구분할 수 있습니다.

헷갈렸던 점#

router가 단순히 사람의 결정을 전달받아 경로를 선택하는 역할인지, 아니면 스스로 승인 여부를 판단하는지 구분이 가지 않았습니다.

가장 중요한 깨달음은 Router는 판단자가 아니라 State를 읽고 길을 여는 교통정리 역할이라는 점입니다. 사람은 승인 여부를 결정하고, router는 그 결정을 읽어 다음 단계로 넘어가는 ‘길’을 정합니다.

정리된 이해#

Router는 판단자가 아니라 State를 읽고 길을 여는 교통정리원 역할을 수행합니다. 사람은 승인 여부를 최종적으로 결정하고, router는 그 결정을 바탕으로 다음 단계로 넘어갈 경로를 선택합니다. 즉, 사람은 ‘판단’하고 router는 ‘길 안내’하는 것이 핵심적인 구분입니다.

# Router 함수: approval 값에 따라 경로 선택
def router(state: TaskState) -> str:
    if state.approval:      # 사람이 'yes'라고 입력한 경우
        return "go_send"   # send 노드로 이동
    else:                   # 사람이 'no'라고 입력한 경우
        return "go_write"  # writer 노드로 복귀하여 재작성

# 전체 흐름 요약
# writer → (일시정지) → 사람 확인(input) → update_state(기록) → router(경로 선택) → send/writer

3. 그래프 재개: update_state와 invoke(None)의 조합#

무엇을 배웠나#

invoke(None, config)는 새로운 입력이 아니라 저장된 상태를 재개하는 역할을 한다는 점을 깨달았습니다. thread_id와 config를 통해 그래프가 멈췄던 지점의 이력을 찾아올 수 있다는 사실도 중요했습니다. 무엇보다 MemorySaver가 있어 중단된 흐름을 논리적으로 복구할 수 있다는 점이 핵심적이었습니다.

헷갈렸던 점#

invoke(None, config)에서 None은 새로운 입력이 아니라 “이미 저장된 상태를 재개한다"는 뜻이라는 점이 가장 헷갈렸습니다. update_state로 상태를 수정했으니 다음 단계가 정상 실행인 줄 알았는데, 실제로는 checkpoint된 이력을 타고 다시 뛰는 시스템이었습니다.

정리된 이해#

invoke(None, config)는 새로운 입력이 아니라, MemorySaver에 의해 저장된 이전 상태를 불러와 그래프 실행을 재개하는 역할을 합니다. update_state로 상태를 갱신한 뒤 같은 config를 사용하면, 중단 전의 흐름을 자연스럽게 이어받아 다음 단계로 넘어갈 수 있습니다.

# 1. 승인(True) 또는 거부(False)의 결과를 상태에 기록
app.update_state(
    config,               # 현재 실행 세션의 식별자 (thread_id 등)
    {"approval": True},   # 실제 업데이트할 값
)

# 2. 중단된 그래프를 재개하여 다음 단계로 진행
# invoke(None)은 "새로운 입력 없음"을 의미하며,
# checkpoint된 상태를 바탕으로 graph를 이어서 실행합니다.
app.invoke(None, config)

오늘 오후 전체에서 배운 것#

인터럽트와 메모리 기능을 통해 그래프 실행 중간에 사람과 AI가 자연스럽게 협업할 수 있는 ‘일시정지 및 재개’ 패턴을 이해하게 되었다. 특히 Router가 판단자가 아니라 State를 읽어 다음 경로를 결정하고, update_state를 통해 사람의 입력을 기록한 뒤 invoke(None)로 그래프를 재개하는 흐름이 핵심이었다. 이를 통해 AI와 인간의 협업 구조를 명확히 구분하며, 중단된 흐름을 논리적으로 복구할 수 있게 되었다.

다음에 조심할 것#

오늘은 인터럽트와 메모리 관리 기능을 통해 AI가 사람과 자연스럽게 협업할 수 있는 ‘일시정지 및 재개’ 패턴을 학습했습니다. 특히 update_state를 활용해 사람의 입력을 상태에 기록하고, router가 이를 바탕으로 다음 경로를 결정하는 흐름이 핵심적이었습니다. 앞으로는 invoke(None)로 저장된 이력을 정확히 복구하여 중단 지점을 놓치지 않도록 주의해야겠습니다.
