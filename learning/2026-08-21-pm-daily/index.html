1. React 배열 map을 통한 JSX 생성하기#

무엇을 배웠나#

React에서 map()을 사용해 JSX를 렌더링할 때는 ‘배열 → map 함수 → JSX 반환’이라는 3단계 흐름만 기억하면 된다. 핵심은 각 요소에 고유한 key prop을 부여해야 React가 변경된 항목을 효율적으로 업데이트할 수 있다는 점이다. 가장 큰 장벽이었던 blank state에서 코드를 작성할 때도, 중괄호와 소괄호의 위치만 정확히 하면 items.map((item) => (<div>...</div>)) 구조를 자연스럽게 잡을 수 있다.

헷갈렸던 점#

처음에는 map() 안에 JSX를 어떻게 감싸야 할지 괄호와 중괄호의 위치가 막막했다. 특히 빈 에디터에서 시작할 때, map이 단순히 반복하는 함수인지, JSX를 반환하는 변환기인지 구분이 안 되어 코드 작성에 큰 장벽이 있었다. 결국 핵심은 map이 배열의 각 아이템을 받아 JSX 형태로 변환해주는 장치이며, 이때 반드시 고유한 key prop을 부여해야 한다는 점을 이해하는 것이 가장 중요했다.

정리된 이해#

React에서 배열을 화면에 그리려면 map() 함수를 사용해 각 아이템을 JSX로 변환하는 과정이 필수적이다. 가장 중요한 핵심은 반환값 전체를 소괄호로 감싸야 한다는 점이며, 각각의 요소에는 고유한 key prop을 반드시 부여해야 효율적인 업데이트가 가능하다.

const fruits = ['사과', '바나나', '딸기'];

function FruitList() {
  return (
    <div>
      {fruits.map((fruit) => (
        <li key={fruit}>{fruit}</li>
      ))}
    </div>
  );
}

2. React Props를 읽고 컴포넌트로 옮기기#

무엇을 배웠나#

function Book({ title }) 형태가 낯설었지만, prop 이름을 함수 인자로 받는다는 규칙을 이해하고 나니 코드 작성이 수월해졌습니다. 부모 JSX에서 보낸 데이터를 자식 컴포넌트에서 바로 받아 화면에 표시하는 흐름을 파악할 수 있었습니다. 특히 prop 이름이 하나뿐일 경우 { title } 구문만으로도 값이 전달되는 것을 확인하며 직관적으로 익힐 수 있었습니다.

헷갈렸던 점#

함수 파라미터로 prop 이름을 직접 받는 { title } 구문이 낯설게 느껴져서, 함수 인자로 전달되는 개념과 JSX 속성 이름이 어떻게 연결되는지 감을 잡기 어려웠습니다.

핵심은 부모가 넘긴 prop 이름 그대로 자식 함수의 변수가 된다는 점이며, function Book({ title }) 형태를 통해 prop의 이름을 바로 지역 변수로 사용할 수 있다는 사실을 이해하는 데 집중했습니다.

정리된 이해#

부모 컴포넌트가 자식에게 전달한 prop 이름은, 자식 함수에서 바로 파라미터로 받아 쓸 수 있다. 이를 통해 부모는 JSX에 title="값"과 같이 작성하고, 자식은 { title } 구문을 사용해 값을 꺼내 화면에 표시할 수 있다. 이처럼 ‘prop 이름 = 함수 인자’라는 규칙을 기억하면 컴포넌트 간 데이터 전달이 자연스럽게 이루어진다.

// 부모 컴포넌트
function App() {
  return <Book title="해리포터" />;
}

// 자식 컴포넌트 (prop 이름 = 함수 인자)
function Book({ title }) {
  return <h2>도서명: {title}</h2>;
}

3. React State Hooks 실전 가이드#

무엇을 배웠나#

React State는 화면에서 계속 기억해야 하는 내부 값이며, useState를 통해 변수와 setter를 동시에 선언하면 된다. 상태 변화는 이벤트 핸들러를 통해 setState 함수에 값을 전달함으로써 업데이트된다. 특히 input의 onChange에서는 e.target.value를 직접 인자로 넘겨주어야 화면이 실시간으로 반영된다.

헷갈렸던 점#

useState 안에 숫자나 문자열을 직접 넣는 것이 아니라, 그 값을 관리하는 ‘함수(setter)‘를 함께 받아야 한다는 점이 가장 어려웠습니다. 또한 이벤트 핸들러 안에서 발생한 값(e.target.value)을 setState 함수에 어떻게 인자로 넘겨주어야 화면이 업데이트되는지 연결하는 과정이 직관적이지 않았습니다.

정리된 이해#

React State는 화면에서 계속 기억해야 하는 컴포넌트 내부의 값이며, useState를 통해 초기값을 선언하고 이벤트를 연결해 setter 함수를 호출하면 자동으로 화면이 업데이트된다. 핵심은 상태가 필요한 값을 찾고, 그에 맞는 이벤트와 setter를 연결하는 패턴을 익히는 것이다.

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>카운트: {count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
    </div>
  );
}

4. DevTools는 ‘코드 검증’을 위한 도구입니다.#

무엇을 배웠나#

DevTools는 코드를 짜주는 에디터가 아니라, 이미 작성된 코드가 실제 화면에 어떻게 반영되었는지 확인하는 검증 도구입니다. 주요 기능은 요소 이름과 props, state의 실시간 확인이며, $0 같은 특수 변수를 활용해 선택된 요소의 값이나 스타일을 바로 조회할 수 있습니다. 결국 DevTools는 내가 짠 코드가 브라우저 환경에서 의도한 대로 작동하는지 디버깅하고 검증하는 창구 역할을 합니다.

헷갈렸던 점#

DevTools는 코드를 자동으로 작성해주는 에디터가 아니라, 이미 실행된 코드가 화면에 어떻게 반영되었는지 확인하는 검증 도구라는 점이 가장 큰 혼란 포인트였습니다.

주요 역할은 요소의 이름과 상태를 파악하고, 변수의 실시간 값을 확인하며, 내가 작성한 로직이 브라우저 환경에서 실제로 어떻게 해석되는지 디버깅하는 것입니다.

정리된 이해#

DevTools는 코드를 직접 작성하는 에디터가 아니라, 이미 실행된 코드가 실제 화면에 어떻게 반영되었는지 확인하고 디버깅하는 검증 도구입니다. 주요 기능은 요소의 이름과 상태를 파악하고, 변수의 값을 실시간으로 확인하며, 내가 짠 로직이 브라우저 환경에서 올바르게 동작하는지 검증하는 것입니다.

LearningLog: Chrome·React DevTools를 검증 도구로 사용하는 법 (초보자 워킹 노트)#

🔍 무엇이 헷갈렸나#

처음 DevTools를 켰을 때, 화면에 떠있는 방대한 정보들에 압도되었습니다. 특히 **“이걸로 코드를 자동으로 짤 수 있지 않을까?”**라는 기대감이 들었습니다. ‘Elements’ 패널에서 $0, $r 같은 특수 변수들이나 ‘Console’의 자동완성 기능이 마치 마법처럼 느껴졌죠. 하지만 막상 사용해보니, DevTools는 이미 작성된 코드가 실제 화면에 어떻게 반영되었는지 확인하는 창구일 뿐, 새로운 로직을 설계해주는 에디터는 아니었습니다. “상태 이름이나 문제 구조까지 대신 설계해주진 않는다"는 점이 가장 큰 혼란 포인트였습니다.

📌 정리된 이해#

DevTools의 핵심 역할은 **“내 코드가 실제 런타임 상태와 맞는지 검증하는 것”**입니다.

  • 이름 확인: 어떤 요소가 선택되었는지, props나 state의 이름은 무엇인지 파악.
  • 값 확인: 현재 변수의 값이 의도한 대로 동작하고 있는지 실시간 확인.
  • 현재 상태 확인: 화면상의 DOM 구조나 React 컴포넌트의 Hooks/State 변화를 눈으로 직접 확인.
  • 내 코드 결과 검증: 내가 작성한 로직이 브라우저나 리액트 환경에서 실제로 어떻게 해석되는지 디버깅.

결론적으로, DevTools는 **“코드를 대신 짜주는 도구"가 아니라 “내가 짠 코드가 제대로 작동하는지 확인하는 검증 도구”**로 이해해야 합니다.

🛠️ 실습 예시#

간단한 콘솔 자동완성 연습부터 시작했습니다.

// Console에서 입력 시 자동완성 제안
document.    // document.querySelector 등 제안
[1, 2, 3].   // 배열 메서드 제안
Math.        // 수학 함수 제안

그리고 Elements 패널에서의 $0 활용 예시입니다.

// 요소를 선택한 후 Console에서
$0.value     // 선택된 input 요소의 값 확인
$0.checked   // 체크박스 상태 확인
$0.style     // inline 스타일 확인
$0

5. 시험 대비 핵심 패턴 인식법#

무엇을 배웠나#

처음에는 문제 전체를 외워야 한다고 생각했지만, 메서드 이름이 안 보여도 뼈대 구조가 머릿속에 있다면 힌트로 바로 복구할 수 있다는 점을 깨달았다. 핵심은 문제를 개별 답안이 아니라 표준 구조로 분류하고 인식해내는 ‘패턴 인식’ 능력이다. 그래서 DOM, Fetch, React 등 각 상황에 맞는 기본 패턴을 익혀두면 새로운 문제에도 유연하게 대처할 수 있게 된다.

헷갈렸던 점#

처음에는 문제 풀이의 정답을 외우는 것이 목표라고 생각했지만, 막상 시험에 들어가니 이름 하나 기억나지 않아 전체가 무너지는 경험을 했다. 그러다 ‘이름은 까먹어도 구조는 안다’는 사실을 깨닫고, 각 문제를 DOM 선택이나 상태 업데이트 같은 표준 패턴으로 분류해두면 힌트만으로도 바로 복구할 수 있다는 것을 알게 되었다.

정리된 이해#

시험 대비의 핵심은 개별 답안 암기가 아니라, 문제를 표준 구조로 분류하고 인식해내는 능력이다. 메서드 이름이 기억나지 않더라도 DOM 선택 → 이벤트 → 값 처리 → 출력 같은 뼈대 구조가 머릿속에 있다면 자동완성이나 힌트로 바로 복구할 수 있다. 따라서 헷갈릴 때마다 해당 패턴을 카테고리별로 묶어두는 것이 중요하다.

[DOM 패턴]
1. 버튼 클릭 → input 값 읽기 → 유효성 검사 → 결과 출력
2. li 요소 찾기 → 텍스트 변경 → 클래스 추가/제거

[Fetch 패턴]
입력값 준비 → fetch() 호출 → json() 변환 → 배열 필터링 → 화면 업데이트

[React 패턴]
부모 컴포넌트 → props 전달 → 자식에서 onClick 사용 → setState로 rerender

총평#

오늘 오후 전체에서 배운 것#

React 개발자로서 오늘 오후 핵심 내용을 정리하자면, map을 통한 JSX 생성 시 고유 key 부여와 blank state 코드 작성법, 그리고 prop과 state를 활용해 컴포넌트 간 데이터를 흐르게 하는 패턴을 확실히 익힌 점이 가장 크다. 또한 DevTools가 코드의 실제 동작 여부를 검증하는 도구임을 깨닫고, 문제 풀이 시 전체 암기보다는 구조적인 패턴 인식 능력을 키우는 것이 효율적이라는 전략적 사고도 함께 습득했다.

다음에 조심할 것#

오늘 React 핵심 내용을 정리하며 느낀 점은, 코드를 짜는 ‘방법’보다 ‘구조’를 이해하는 것이 훨씬 중요하다는 것입니다.

첫째, map 함수와 key prop의 조합은 반복되는 UI를 만들 때 필수적인 패턴이지만, blank state 같은 예외 상황에서도 당황하지 않고 중괄호와 소괄호 위치를 잡는 것만으로도 자연스럽게 해결된다는 점이 인상 깊었습니다. 둘째, Props와 State의 흐름을 이해하는 과정이 처음에는 낯설었지만, 데이터가 부모에서 자식으로 어떻게 전달되고 화면에 반영되는지 파악하니 컴포넌트 분리가 훨씬 수월해졌습니다. 앞으로는 이러한 ‘데이터 흐름’과 ‘패턴 인식’을 중심으로 복습하며, DevTools를 단순히 디버깅하는 도구가 아니라 내가 짠 코드가 브라우저에서 어떻게 동작하는지 검증하는 거울로 활용해야겠습니다.

다음 복습 주제#

오늘 배운 React 핵심 내용을 바탕으로, 다음에 복습할 주제는 다음과 같다.

React에서 데이터를 화면에 표시하는 가장 기본적인 흐름은 ‘props 전달 → state 관리 → UI 업데이트’이다. props는 부모로부터 자식으로 일방향으로 흐르며, 사용자 입력이나 변하는 데이터는 state를 통해 관리해야만 화면이 실시간으로 반영된다. 따라서 컴포넌트를 설계할 때는 데이터가 어디서 오는지, 그리고 상태 변화가 UI에 어떻게 영향을 미치는지 전체적인 파이프라인을 파악하는 것이 무엇보다 중요하다.

다음 단계에서는 useEffect Hook을 활용해 비동기 통신이나 라이프사이클 이벤트를 처리하는 방법을 학습해야 한다. 컴포넌트가 마운트될 때나 업데이트 될 시점에 특정 로직을 실행하고, 정리 함수(cleanup)를 통해 메모리 누수를 방지하는 패턴을 익히면 실제 서비스 개발에서 필수적인 데이터 fetching과 이벤트 바인딩 능력을 기를 수 있을 것이다.
