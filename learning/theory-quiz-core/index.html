1. f-string 포매팅#

왜 이걸 보게 됐나#

파이썬을 배우면서 문자열을 동적으로 생성해야 할 일이 잦아졌습니다. 기존에 사용하던 % 연산자나 .format() 메서드는 문법이 복잡하고 가독성이 떨어지는 경우가 많아 불편함을 느꼈습니다. 그래서 파이썬 3.6 이상에서 도입된 **f-string(Formatted String Literal)**을 배우게 되었고, 변수 직접 삽입과 표현식 사용이 간편하다는 장점을 깨닫고 적극적으로 적용하게 되었습니다.

내가 헷갈린 지점#

처음에는 f 접두사가 붙은 문자열을 일반 문자열과 동일하게 취급하다가, 중괄호 {} 안에 있는 변수나 식이 실제 값으로 치환된다는 사실을 깨닫고 놀랐습니다. 특히 줄 바꿈(\n)이나 탭(\t) 같은 이스케이프 시퀀스가 자동으로 처리되어 코드가 훨씬 깔끔해진 점은 파이썬의 강점을 실감하게 만든 대목이었습니다.

시도한 코드 / 예시#

# f-string 포매팅 핵심 예시
name = "홍길동"
age = 25

# 기본 변수 삽입
print(f"내 이름은 {name}입니다.")
# 출력: 내 이름은 홍길동입니다.

# 연산 및 표현식 사용
print(f"{name}은(는) {age}살입니다.")
# 출력: 홍길동은(는) 25살입니다.

# 조건부 표현식 (삼항 연산자)
status = "성인" if age >= 20 else "미성년자"
print(f"나이 상태: {status}")
# 출력: 나이 상태: 성인

# 포맷 지정자 (소수점 자리 수 조절)
price = 1234.5678
print(f"가격: {price:.2f}원")
# 출력: 가격: 1234.57원

결과와 해석#

f-string은 파이썬에서 문자열 안에 변수나 식을 직접 삽입할 수 있게 해주는 포매팅 방법입니다. 중괄호 {} 안에 원하는 표현식을 넣으면 자동으로 해당 값이 문자열에 대치되어 반환됩니다. 이를 사용하면 별도의 메서드 호출 없이도 변수의 값을 쉽게 문자열에 포함시킬 수 있어 코드가 간결해집니다.

정리된 이해#

f-string은 파이썬 문자열 내부에 중괄호 {}를 사용하여 변수나 식을 직접 삽입할 수 있게 해주는 포매팅 방식입니다. 기존의 .format() 메서드보다 문법이 간결하고 가독성이 높아, 복잡한 문자열 구성 없이도 손쉽게 동적 내용을 포함할 수 있습니다. 특히 중괄호 안에서 다양한 연산이나 메서드 호출이 가능하여 표현의 유연성을 크게 높여줍니다.

2. 클래스와 인스턴스#

왜 이걸 보게 됐나#

객체지향 프로그래밍을 배우기 전에는 변수와 함수의 조합으로만 프로그램을 구성하다 보니, 복잡한 데이터 구조를 관리하는 데 한계가 있었습니다. ‘클래스’를 통해 객체를 생성하고 재사용할 수 있다는 개념을 알게 되면서, 코드의 구조화와 유지보수가 훨씬 효율적이라는 것을 깨닫게 되었습니다. 특히 인스턴스를 통해 개별적인 상태를 가질 수 있다는 점은 실무에서 다양한 상황을 모델링하는 데 필수적이었습니다.

내가 헷갈린 지점#

클래스는 객체를 생성하기 위한 청사진(설계도)이며, 인스턴스는 이 설계도에 따라 실제로 만들어져 메모리에 할당된 구체적인 객체입니다. 클래스를 통해 공통된 속성과 기능을 정의할 수 있고, 각 인스턴스는 고유한 상태를 유지하면서 동일한 행동을 수행할 수 있습니다.

시도한 코드 / 예시#

# 클래스와 인스턴스의 핵심 예시

class Car:
    def __init__(self, color):
        self.color = color  # 인스턴스 변수 (각 객체마다 고유)

my_car = Car("red")
print(my_car.color)  # red

결과와 해석#

클래스는 객체를 생성하기 위한 청사진(설계도)이며, 인스턴스는 이 설계도에 따라 메모리에 실제로 할당된 구체적인 객체입니다. new 키워드를 사용하여 클래스를 호출하면 해당 클래스의 프로퍼티와 메서드를 가진 새로운 인스턴스가 생성됩니다.

정리된 이해#

클래스는 객체를 생성하기 위한 청사진(설계도)이며, 인스턴스는 이 청사대로 실제로 만들어낸 구체적인 객체입니다. 클래스를 통해 공통된 속성과 메서드를 정의하고, 각 인스턴스는 자신만의 고유한 상태를 가집니다.

3. 블록 스코프#

왜 이걸 보게 됐나#

블록 스코프 개념을 배우게 된 것은 변수의 유효 범위를 정확히 파악하여 예기치 않은 버그를 방지하기 위해서입니다. let과 const는 블록 { } 내에서만 유효한 지역 변수로 선언되며, var처럼 전역이나 함수 전체에 영향을 주지 않아 코드의 안전성을 높일 수 있습니다. 이러한 스코프 규칙을 이해하면 변수의 생명 주기를 명확히 하여 유지보수성이 높은 코드를 작성할 수 있습니다.

내가 헷갈린 지점#

let과 const가 var와 다른 점은 변수의 유효 범위(scope)가 함수 전체가 아니라 코드 블록({}) 단위로 구분된다는 것입니다. 특히 const는 선언과 동시에 값을 할당받아야 하며, 이후 재할당이 불가능하여 변하지 않는 상수 역할을 한다는 점이 가장 큰 차이점이었습니다. 또한 var는 함수 스코프라 중괄호 안에서 선언해도 외부까지 영향을 미칠 수 있지만, let과 const는 블록 스코프를 따르므로 중괄호 밖에서는 접근할 수 없다는 점을 명확히 구분해야 했습니다.

시도한 코드 / 예시#

// let/const는 블록 스코프를 가집니다.
{
  const x = 1;
  console.log(x); // 1
}
// console.log(x); // ReferenceError: x is not defined (블록 밖에서는 접근 불가)

// var는 함수 스코프를 가집니다.
function test() {
  var y = 2;
  console.log(y); // 2
}
console.log(y); // 2 (함수 밖에서도 전역 변수로 인식됨)

결과와 해석#

let 키워드로 선언한 변수는 블록 { } 내에서만 유효하며, 중괄호 밖에서는 접근할 수 없습니다. 반면 var 키워드는 함수 전체 또는 전역 스코프를 따르기 때문에, 블록 내부에서 선언해도 외부에서 여전히 참조가 가능합니다. 이러한 차이로 인해 let은 의도치 않은 변수 오염을 막고 지역적 유효 범위를 명확히 할 수 있어 현대 자바스크립트 개발에 권장됩니다.

정리된 이해#

let은 변수 재할당과 블록 범위(Block Scope)를 허용하며, const는 선언과 동시에 값을 고정하고 블록 내 유효범위를 가집니다. this는 함수가 호출된 방식에 따라 전역 객체, undefined, 또는 특정 객체를 가리키게 되며, 화살표 함수에서는 상위 스코프의 this를 그대로 사용합니다.

4. this 바인딩#

왜 이걸 보게 됐나#

이번 학습은 JavaScript의 핵심 개념 중 하나인 this 바인딩에 대한 내용이었습니다. 초보자 입장에서 가장 막막했던 부분이었는데, 강의를 통해 호출 방식별로 this가 어떻게 달라지는지 명확히 이해할 수 있었습니다.

가장 인상 깊었던 점은 this가 고정되어 있는 것이 아니라, 함수가 어디서 불려졌는지(호출 위치)에 따라 동적으로 결정된다는 것이었습니다. 특히 new 키워드를 사용한 생성자 함수 호출 방식이나, .call(), .apply(), .bind() 메서드를 통한 명시적인 바인딩 방법이 처음에는 추상적으로 느껴졌지만, 실제 코드 예제를 보며 ‘아, 이렇게 유연하게 제어할 수 있구나’라고 느꼈습니다. 이제 this가 어디서든 window나 undefined로 바뀌는 실수를 줄이기 위해 함수 호출 전 항상 문맥을 확인하는 습관을 들이고 있습니다.

내가 헷갈린 지점#

this가 함수 호출 방식에 따라 달라진다는 점이 가장 헷갈렸습니다. 일반 함수로 호출하면 전역 객체에 바인딩되지만, 메서드 내부의 this는 소유한 객체를 가리키므로 함수를 따로 떼어내면 undefined나 다른 대상이 됩니다. 화살표 함수는 자체적인 this를 가지지 않고 상위 스코프의 this를 그대로 사용하기 때문에, 콜백 함수에서 this를 보존할 때 유용하게 사용할 수 있습니다.

시도한 코드 / 예시#

// this 바인딩: 일반 함수 호출 시 전역 객체 바인딩
function showThis() {
  console.log(this); // [Window Object] (브라우저 환경)
}
showThis();

// 화살표 함수는 자체 this를 바인딩하지 않고 상위 스코프의 this를 사용함
const obj = {
  name: 'Nemotron',
  getName: () => { console.log(this); } // undefined 또는 외부 컨텍스트의 this
};
obj.getName();

결과와 해석#

this는 함수가 호출된 방식에 따라 달라집니다.

일반적으로 단독으로 호출된 함수에서는 this가 전역 객체를 가리키지만, 메서드로서 호출되면 해당 객체가 됩니다. 화살표 함수는 자체적인 this를 바인딩하지 않고 상위 스코프의 this를 그대로 사용합니다.

정리된 이해#

this는 함수가 호출된 방식에 따라 자동으로 결정되는 바인딩 규칙입니다. 화살표 함수에서는 this가 상위 스코프(전역 또는 가장 바깥쪽 함수)를 그대로 따르므로 별도의 바인딩이 필요 없습니다. 반면 일반 함수에서 this를 사용하면 호출 주체에 따라 전역 객체, null, 혹은 특정 객체가 자동으로 할당됩니다.

📌 오늘 복습한 핵심 개념#

  • f-string 포매팅: 파이썬에서 변수나 식을 문자열 안에 직접 삽입할 수 있는 문법입니다. {변수명} 구문을 사용하며, 표현식 계산 결과가 바로 문자열에 반영됩니다.
  • 클래스와 인스턴스: 클래스는 객체를 생성하기 위한 ‘도면(설계도)‘이고, 인스턴스는 그 도면에 따라 실제 메모리상에 생성된 ‘실체’입니다. 클래스를 정의하면 해당 타입의 객체를 만들 수 있습니다.
  • 블록 스코프: if, for, function 등 특정 영역({}) 안에서 선언된 변수는 그 영역 밖으로는 접근할 수 없습니다. let과 const는 블록 레벨 스코프를 가지며, var는 함수 레벨 스코프입니다.
  • this 바인딩: 자바스크립트에서 this의 값은 함수가 호출된 방식에 따라 달라집니다. 일반 함수 호출 시 undefined, 메서드 호출 시 해당 객체, 화살표 함수는 lexical scoping(렉시컬 스코핑)에 의해 상위 스코프의 this를 따릅니다.
