1. Promise 체인과 async/await 완벽 이해하기#

무엇을 배웠나#

Promise 체인 방식과 async/await 방식을 통해 비동기 코드의 흐름을 이해하게 되었고, .then() 안의 return이 어떻게 다음 Promise로 이어지는지 명확해졌습니다. async/await은 Promise를 대체하는 것이 아니라, Promise 기반 코드를 더 읽기 쉽게 만들고 순차적인 흐름을 파악하도록 도와주는 문법이라는 것을 알게 되었습니다. 이제 비동기 코드 작성 시 두 방식 중 상황에 맞게 선택하여 활용할 수 있을 것 같습니다.

헷갈렸던 점#

처음에는 Promise 체인 방식과 async/await 방식의 관계가 명확하게 이해되지 않았고, .then() 안에서 return이 없어도 어떻게 다음 단계로 넘어가는지 궁금했습니다. 또한, async/await가 Promise를 완전히 대체하는 것인지 아니면 코드 스타일을 개선하는 기능인지 혼동되었습니다.

정리된 이해#

Promise 체인은 .then()을 통해 이전 Promise의 결과를 다음 단계로 전달하며, return이 생략될 경우에도 자동 연결됩니다. async/await은 Promise 기반 코드를 더 읽기 쉽고 순차적으로 보이도록 해주는 문법이며, Promise를 완전히 대체하는 것이 아니라 코드의 가독성을 높이는 역할을 합니다. 결국 async/await은 Promise를 사용하면서 콜백 지옥을 피하고 깔끔한 코드를 작성하는 데 도움을 줍니다.

async function getResult(a, b) {
  try {
    let r1 = await plus(a, b);
    let r2 = await multi(r1, 4);
    let r3 = await divide(r2, 2);
    console.log('결과:', r3);
  } catch (error) {
    console.error('에러 발생:', error);
  }
}

2. 타이머와 콜백 이해: setTimeout과 setInterval 완벽 가이드#

무엇을 배웠나#

setTimeout은 한 번만 실행되는 타이머이고, setInterval은 특정 간격으로 반복 실행되는 타이머라는 것을 알게 되었다. setInterval을 멈추는 방법과 동기/비동기 코드의 차이점을 이해하고, while 루프가 UI를 멈추게 하는 이유도 명확해졌다. 이제 타이머를 활용한 코드를 좀 더 효율적으로 작성할 수 있을 것 같다.

헷갈렸던 점#

처음에는 setTimeout과 setInterval이 어떻게 실행되는지, 각각이 독립적으로 작동하는지 순차적으로 기다리는 건지 감이 잘 안 잡혔습니다. 특히 setInterval을 어떻게 멈추고, 특정 조건을 만족했을 때 자동으로 종료되게 할 수 있을지 몰랐고, 동기 코드와 비동기 코드의 차이 때문에 왜 while 루프가 화면을 멈추는지 이해하기 어려웠습니다.

정리된 이해#

setTimeout은 한 번만 실행되는 타이머이고, setInterval은 주기적으로 반복 실행되는 타이머인데, 반복 타이머는 명시적으로 종료해야 합니다. 동기 코드는 실행을 멈추므로 UI가 멈춰 보일 수 있지만, 비동기 코드는 실행을 기다려 다른 작업을 처리할 수 있습니다. 이 둘의 차이를 이해하면 JavaScript에서 타이머를 효과적으로 사용하는 데 도움이 됩니다.

let count = 0;
const intervalId = setInterval(() => {
  console.log(`간격 타이머 실행: ${count++}`);
  if (count >= 5) clearInterval(intervalId); // 종료 조건
}, 1000);

3. Promise 기본: 생성, resolve, reject 완벽 이해#

무엇을 배웠나#

Promise 객체를 생성할 때 resolve와 reject 함수의 역할이 무엇인지 명확히 이해하게 되었고, resolve를 즉시 호출하면 어떻게 Promise가 성공 상태로 바뀌는지 알게 되었다. 또한, Promise의 실패 처리를 위해 reject를 사용하는 것이 왜 중요한지, 그리고 어떻게 활용해야 하는지도 학습했다. 이제 Promise를 좀 더 자신 있게 사용할 수 있을 것 같다.

헷갈렸던 점#

Promise 생성자와 resolve, reject 함수의 역할이 비슷해서 언제 뭘 써야 할지 혼란스러웠다. resolve()를 즉시 호출하는 부분이 왜 결과가 바로 반환되는지 이해가 잘 안 갔고, 오류 상황이 없을 때 reject를 어떻게 활용해야 할지 궁금했다.

정리된 이해#

Promise는 new Promise()를 통해 생성되며, resolve는 성공적인 결과를, reject는 실패 이유를 전달하여 Promise의 상태를 변경합니다. resolve를 즉시 호출하면 Promise가 즉시 성공 상태로 바뀌고, reject는 실패 조건을 처리하지 않을 때도 Promise의 실패 상태를 나타낼 수 있습니다. 이들을 올바르게 사용하면 비동기 작업을 효율적으로 관리할 수 있습니다.

function getData() {
  return new Promise((resolve, reject) => {
    const data = '데이터 가져오기 완료';
    setTimeout(() => resolve(data), 1000);
  });
}

function checkPositiveNumber(n) {
  return new Promise((resolve, reject) => {
    if (n > 0) {
      resolve(`${n}은 양수입니다!`);
    } else {
      reject(`${n}은 음수입니다...`);
    }
  });
}

무엇을 배웠나#

DOM 요소의 속성 변경과 이벤트 리스너를 활용하여 링크의 주소를 동적으로 변경하는 방법을 익혔습니다. 특히 target="_blank" 속성과 href 속성의 역할을 명확히 이해했으며, 명확하지 않은 지시사항에 대해서는 무조건적으로 코드를 완성하는 것을 지양해야 함을 깨달았습니다. 또한, 실습 과정을 통해 이벤트 기반으로 링크 변경 동작이 실행됨을 확인했습니다.

헷갈렸던 점#

테스트 시작 전에 지시사항을 제대로 이해하지 못해 코드를 작성하는 방향이 틀어졌고, 링크 클릭 시 페이지 이동 방식과 href 속성 변경의 차이점을 명확히 파악하지 못했다. 특히 테스트 2의 요구사항이 불명확하여 어떤 코드를 작성해야 할지 감을 잡기 어려웠다. 강의 진행 중 이미지 파일 관련 문제로 테스트 3, 4 진행이 잠시 중단되었다.

정리된 이해#

링크 변경 시 href 속성만 변경되고 실제 페이지 이동은 사용자 클릭 동작에 의해 발생하며, target="_blank"는 링크를 새 탭에서 열도록 하는 역할을 한다. 지시사항이 불명확한 경우 코드를 임의로 완성하지 않고, 정확한 요구 사항 확인 후 진행하는 것이 중요하다.

오늘 오후 전체에서 배운 것#

비동기 코드 작성 시 Promise 체인과 async/await를 상황에 맞게 활용할 수 있게 되었고, 타이머 함수(setTimeout, setInterval)의 동작 원리와 활용법도 익혔습니다. 또한, Promise 객체의 생성 및 실패 처리 방법을 명확히 이해하고, DOM 조작 실습을 통해 이벤트 기반 동작의 중요성을 깨달았습니다.
