1. 상속#

왜 이걸 보게 됐나#

객체 지향 프로그래밍에서 코드 재사용성과 계층 구조를 효율적으로 관리하기 위해 상속 개념을 배우게 되었어. 기존 코드를 수정 없이 확장하고, 클래스 간의 관계를 명확히 정의하여 유지보수를 용이하게 하고 싶었기 때문이야. 상속을 통해 복잡한 시스템을 더 단순하고 이해하기 쉽게 만들 수 있다는 점이 매력적이었어.

내가 헷갈린 지점#

처음 상속 구조를 볼 때, 부모 클래스와 자식 클래스 간의 역할 분담이 명확하지 않아, 자식 클래스가 부모 클래스의 기능을 단순히 복사하는 것인지, 아니면 다른 의미가 있는지 헷갈렸어요. 또한, 어떤 기능을 부모 클래스에 두고 어떤 기능을 자식 클래스에 둘 것인지에 대한 기준점이 보이지 않았습니다. 전체적인 구조가 복잡해 보여서 어디서부터 시작해야 할지 막막했습니다.

상속은 부모 클래스의 기능을 그대로 물려받아 자식 클래스에서 확장하거나 특화할 수 있게 해주는 방식이야. 이를 통해 코드 중복을 줄이고, 각 클래스만의 고유한 특징을 추가하면서도 기본적인 틀은 공유할 수 있어. 결국 상속은 코드 재사용성과 계층적인 관계를 표현하는 강력한 도구라고 이해했어.

2. 부모 클래스#

왜 이걸 보게 됐나#

이전에는 코드를 복사해서 붙여넣고 수정하는 방식으로만 개발했는데, 코드의 중복이 많아지고 유지보수가 어려웠어요. 상속 개념을 배우게 된 건, 코드 재사용성을 높이고 객체 지향 프로그래밍의 장점을 활용하여 더 효율적으로 코드를 작성하기 위해서였어요.

내가 헷갈린 지점#

처음에는 부모 클래스가 어떤 역할을 하는지, 자식 클래스와 어떻게 연결되는지 감이 잘 안 잡혔어요. 마치 큰 나무에서 가지가 뻗어나가는 과정이, 코드 상에서는 어떻게 구현되는지, 그리고 각 클래스가 서로 어떻게 상호작용하는지 이해하기 어려웠습니다. 부모 클래스가 단순한 기본 틀일 뿐인지, 아니면 더 중요한 역할을 하는 건지 헷갈렸어요.

시도한 코드 / 예시#

class Department:
    def __init__(self, team_name, budget):
        self.team_name = team_name  # 팀 이름
        self.budget = budget  # 예산
        self.members = []  # 팀 멤버 목록

결과와 해석#

부모 클래스인 Department는 모든 팀들이 공유하는 기본적인 속성과 기능들을 묶어놓는 역할을 합니다. __init__ 메서드를 통해 팀 이름, 예산, 멤버 목록을 초기화하고, 멤버를 추가/삭제/출력하는 메서드를 정의하여, 자식 클래스들이 이를 상속받아 활용할 수 있도록 해줍니다. 이는 코드 재사용성을 높이고, 각 팀의 특성을 살린 기능을 추가하는 기반이 됩니다.

정리된 이해#

부모 클래스는 모든 자식 클래스가 공유하는 기본적인 속성과 기능을 정의하는 역할을 합니다. 즉, 부모 클래스는 공통적인 부분을 추상화하여 코드 중복을 줄이고, 상속을 통해 자식 클래스들이 이를 활용할 수 있도록 해줍니다. 마치 나무의 뿌리처럼, 모든 팀은 부모 클래스인 Department에서 기본적인 구조를 물려받는다고 이해하면 됩니다.

3. 자식 클래스#

왜 이걸 보게 됐나#

처음에는 코드를 이해하고 수정하는 데 필요한 기본적인 클래스 구조를 만드는 법을 배우기 위해 자식 클래스 개념을 접하게 됐어. 상속을 통해 코드 중복을 줄이고, 기존 코드를 재활용하며 확장할 수 있다는 점이 중요하다고 생각했거든. 복잡한 프로젝트에서 효율적으로 코드를 관리하려면 이 개념이 필수적이라는 것을 깨달았어.

내가 헷갈린 지점#

처음에는 자식 클래스가 부모 클래스의 모든 기능을 단순히 복사하는 건가 싶었어요. 자식 클래스만의 고유한 기능과 함께 부모 클래스의 기능을 어떻게 활용해야 하는지, 그리고 그 역할 분담이 어떻게 이루어지는지가 잘 이해가 안 되었습니다. 부모 클래스는 정말 추상적인 역할을 하는 건가, 구체적인 코드가 아니라 개념적인 역할만 하는 건가 궁금했습니다.

시도한 코드 / 예시#

class DevTeam(Department):
    def __init__(self, team_name, budget, tech_stack):
        super().__init__(team_name, budget)
        self.tech_stack = tech_stack

    def show_tech_stack(self):
        print(f"{self.team_name} 팀의 기술 스택: {self.tech_stack}")

결과와 해석#

자식 클래스인 DevTeam은 Department 클래스의 속성과 메서드를 그대로 물려받아, 개발팀에 특화된 tech_stack 속성과 code_review() 메서드를 추가함으로써 더 구체적인 기능을 수행하도록 확장했습니다. 이를 통해 부모 클래스의 기능을 재사용하면서도, 자식 클래스만의 고유한 특성을 표현할 수 있다는 것을 확인했습니다. 이 과정에서 상속이 코드 중복을 줄이고, 클래스 간의 관계를 효율적으로 관리하는 데 도움이 되는 것을 알 수 있었습니다.

정리된 이해#

자식 클래스는 부모 클래스의 기본적인 기능과 속성을 그대로 물려받아 사용하면서, 각자 특화된 기능이나 속성을 추가하여 더욱 구체적인 역할을 수행하게 됩니다. 이를 통해 코드 재사용성을 높이고, 클래스 간의 관계를 명확하게 정의할 수 있습니다. 결국, 자식 클래스는 부모 클래스를 확장하여 더 전문적인 역할을 담당하게 되는 관계라고 이해했습니다.

4. 팀 특성#

왜 이걸 보게 됐나#

팀 특성을 배우게 된 건 부서 트리 구조에서 부모 클래스의 공통 기능을 자식 클래스가 어떻게 확장하고 구체화하는지 이해하기 위해서였어. 단순히 상속의 개념을 넘어, 각 팀이 가진 고유한 기능과 역할을 부모 클래스 내에서 어떻게 표현하고 관리할 수 있는지 파악하는 과정에서 필요했어. 이를 통해 실제 업무 환경에서 다양한 팀들을 유연하게 모델링할 수 있는 기반을 마련하려고 해.

내가 헷갈린 지점#

처음에는 부모 클래스인 Department가 가진 속성들이 자식 클래스에게 그대로 적용되는 것인지, 아니면 단순히 이름을 공유하는 것인지 명확하지 않았어요. 특히, 각 팀의 특성이 부모 클래스의 속성을 덮어쓰거나 확장하는 방식이 어떻게 결정되는지 이해하는 데 어려움을 겪었습니다. 자식 클래스에서 새로운 속성을 추가하는 것 외에 기존 속성을 수정하거나 확장할 수 있는지에 대한 부분이 특히 궁금했습니다.

시도한 코드 / 예시#

class DevTeam(Department):
    def __init__(self, team_name, budget, tech_stack):
        super().__init__(team_name, budget)
        self.tech_stack = tech_stack

    def show_tech_stack(self):
        print(f"{self.team_name} 팀의 기술 스택: {self.tech_stack}")

결과와 해석#

DevTeam 클래스에서는 부모 클래스인 Department의 속성과 메서드를 그대로 활용하면서, 개발팀에 특화된 tech_stack 속성과 code_review() 메서드를 추가하여 개발팀의 고유한 특징을 잘 반영했습니다. 이를 통해 부모 클래스의 공통 기능과 자식 클래스의 특화된 기능을 분리하여 코드를 더 체계적으로 관리할 수 있다는 것을 알게 되었습니다. 특히, tech_stack은 개발팀의 기술 스택을 나타내는 속성이며, code_review()는 코드 검토 작업을 수행하는 메서드입니다.

정리된 이해#

각 팀(DevTeam, PlanningTeam 등)은 부서(Department)에서 공통적으로 가지는 속성과 기능을 그대로 이어받으면서, 그 위에 자신들만의 고유한 특성과 기능을 추가하여 더욱 전문적인 역할을 수행하게 됩니다. 이를 통해 부서 전체의 틀을 유지하면서도 각 팀의 개성을 살릴 수 있습니다. 결국 상속은 코드 재사용성과 구조적인 확장을 가능하게 하는 효과적인 방법입니다.

총평#

오늘 전체에서 배운 것#

상속을 통해 부모 클래스의 공통 속성을 재사용하면서, 자식 클래스에서 팀별 고유한 기능도 추가할 수 있다는 것을 알게 되었어. 부모 클래스와 자식 클래스의 역할 분담을 명확히 이해하는 것이 상속 구조를 효과적으로 설계하는 핵심인 것 같아.

다음에 조심할 것#

자식 클래스에서 부모 클래스의 속성이나 메서드를 제대로 활용하고 있는지, 그리고 자식 클래스만의 고유한 기능을 추가할 때 부모 클래스와 충돌하지 않는지 항상 확인해야겠다. 부모 클래스의 로직 변경이 자식 클래스에 예상치 못한 영향을 미치지 않도록 주의해야 해.

다음 복습 주제#

상속 구조를 활용하여 더 복잡한 관계를 표현하는 방법을 찾아보고 싶어. 특히, 다중 상속이나 다형성을 활용한 예제를 학습해봐야겠어. 그리고 상속 대신 구성을 사용할 때의 장단점을 비교해 보는 것도 도움이 될 것 같아.
