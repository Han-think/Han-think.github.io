1. JSX 문법: Fragment, {} 사용법, 조건 표현 이해하기#

무엇을 배웠나#

JSX 기본 문법을 공부하면서 Fragment, JavaScript 값 삽입, 조건 표현 방식에서 어려움을 겪었지만, Fragment는 여러 요소를 묶는 방법, {}는 JavaScript 값을 삽입하는 방법, 그리고 삼항 연산자와 익명 함수를 활용하여 조건을 처리하는 방법을 익혔습니다. 이를 통해 JSX를 좀 더 효과적으로 사용할 수 있게 되었고, 리액트 컴포넌트 개발에 필요한 기본적인 이해를 쌓았습니다. 앞으로는 다양한 실습을 통해 이 지식을 더욱 숙달해나가겠습니다.

헷갈렸던 점#

처음에는 <>...</> 형태의 Fragment가 마치 잘못된 태그처럼 보였고, JSX 안에 {} 를 사용해야 하는 문법이 JavaScript에서의 문자열 표현과 달라서 낯설었습니다. 특히 조건문 표현이 if 문을 직접 사용할 수 없어 삼항 연산자나 익명 함수를 활용해야 한다는 점이 이해하기 어려웠습니다.

정리된 이해#

JSX는 HTML과 JavaScript를 혼합하여 사용할 수 있게 해주는 문법이며, Fragment는 불필요한 DOM 요소를 추가하지 않고 여러 요소를 묶어주는 역할을 합니다. JSX 내에서 JavaScript 표현식을 사용하려면 중괄호 {}를 사용해야 하며, 조건부 렌더링은 삼항 연산자나 익명 함수를 활용하여 구현할 수 있습니다.

       <>
         <h3>안녕하세요 리액트</h3>
       </>

2. React 스타일 컴포넌트: 초보자를 위한 이해 정리#

무엇을 배웠나#

React 스타일 적용 방식과 컴포넌트 분리에 대한 이해를 높일 수 있었다. 특히, JSX 내에서 JavaScript 스타일 객체를 사용할 때 중괄호의 역할과 스타일 표기법의 차이(camelCase)를 명확하게 이해하게 되었다. 이를 바탕으로 인라인 스타일, 스타일 객체, 클래스 이름 방식의 스타일 적용 방법을 구분하고 활용할 수 있게 되었다.

헷갈렸던 점#

처음에는 CSS 스타일 속성 이름을 JavaScript 스타일 객체로 변환하는 camelCase 표기법을 헷갈려서 속성값을 제대로 적용하지 못했었어. JSX에서 중괄호가 여러 겹으로 겹쳐서 사용되는 방식 때문에 어떤 게 외부 중괄호이고 어떤 게 내부 중괄호인지 구분하는 데 어려움을 느꼈지. 인라인 스타일, 스타일 객체, 클래스 이름 방식의 차이점도 명확히 이해하지 못해서 적용 방법을 혼동했어.

정리된 이해#

JSX에서 스타일을 적용할 때 CSS 속성 표기법과 JavaScript camelCase 표기법의 차이를 이해하는 것이 중요합니다. 중괄호를 사용한 인라인 스타일 방식은 외부 중괄호가 JavaScript 객체를 감싸고, 내부 중괄호가 스타일 속성을 정의하는 방식으로 처음에는 복잡해 보이지만 익숙해지면 스타일을 동적으로 변경하는 데 유용합니다. 스타일 객체나 CSS 클래스 이름을 사용하는 방법도 있으며, 상황에 맞춰 적절한 방식을 선택할 수 있습니다.

<h1 style={{color: 'red'}}>Hello Inline Style</h1>

const styles = {
  fontSize: 26,
  fontWeight: 700,
  color: 'blue',
  backgroundColor: 'yellowgreen'
};
<p style={styles}>JavaScript Object Style</p>

3. React 컴포넌트: Props와 State 완벽 이해#

무엇을 배웠나#

Props는 부모 컴포넌트에서 자식 컴포넌트로 데이터를 전달하는 방식이고, State는 컴포넌트 내부에서 관리되는 데이터로 UI 렌더링에 영향을 줍니다. useState를 사용하여 State를 정의하고, State 변경 함수(예: setCnt)를 사용하여 UI를 업데이트 할 수 있습니다. 일반 변수와 State 변경 함수의 차이점을 이해하고 언제 무엇을 사용해야 하는지 명확하게 알게 되었습니다.

헷갈렸던 점#

Props와 State 예제가 함께 보일 때 코드가 복잡하게 느껴졌고, 일반 변수와 상태 변경 함수의 차이점을 명확하게 이해하지 못해 언제 어떤 것을 사용해야 할지 혼동되었다. 특히 useState 훅에서 변수 초기화와 상태 업데이트 함수가 함께 등장하는 부분이 처음엔 어렵게 느껴졌다.

정리된 이해#

Props는 부모 컴포넌트에서 자식 컴포넌트로 데이터를 전달하는 역할이고, State는 컴포넌트 내부에서 관리하며 UI 갱신에 영향을 주는 값이야. useState 훅을 사용하면 State를 쉽게 만들 수 있는데, 초기값 설정과 state를 변경하는 함수를 함께 제공해. 일반 변수와 달리 State를 변경하면 컴포넌트가 다시 렌더링되면서 UI가 업데이트돼.

import { useState } from 'react';

const [cnt, setCnt] = useState(100);
const updateCnt = () => setCnt(cnt - 1);

4. React 입력 이벤트 처리: onChange와 이벤트 객체 활용하기#

무엇을 배웠나#

React에서 입력값을 다룰 때 onChange 이벤트와 이벤트 객체 e를 활용해야 하며, e.target.value를 통해 입력값을 가져올 수 있다는 것을 알게 되었다. 초기 상태 설정과 연결이 제대로 되지 않으면 사용자 입력이 반영되지 않는 문제도 인지하고, useState를 활용하여 입력값을 상태에 저장하고 화면에 반영하는 방법을 적용해야 함을 배웠다. 이벤트 기반 입력 처리의 복잡성을 이해하고, 상태 관리와 연결하는 방법을 익혔다.

헷갈렸던 점#

React에서 HTML input 태그를 다루는 방식이 HTML과는 다르게 느껴져서, onChange 이벤트 핸들러와 이벤트 객체 e를 사용하는 부분이 어렵게 느껴졌어요. 특히 초기 value가 비어있는 상태에서는 입력 값이 제대로 반영되지 않는 것 같아 상태 관리와 연결하는 방법을 파악하는 데 어려움을 겪었습니다. 이벤트 객체 e.target.value를 통해 입력 값을 가져오는 과정이 낯설었습니다.

정리된 이해#

React에서 입력 필드의 값을 다루려면 onChange 이벤트 핸들러를 통해 이벤트 객체를 받아 e.target.value로 입력값을 얻어야 합니다. useState 훅을 사용하면 입력값을 상태로 관리하여 화면에 실시간으로 반영할 수 있습니다. 초기 value가 비어 있으면 사용자 입력이 반영되지 않으므로, 상태를 통해 연결하는 것이 중요합니다.

5. WebStorm 로컬 AI 플러그인 설치 및 환경 설정 가이드#

무엇을 배웠나#

WebStorm에 로컬 AI 기능을 추가하는 과정에서 라이선스와 인증 조건이 헷갈렸지만, DevoxxGenie 플러그인 설치를 통해 명확히 구분할 수 있게 되었다. 특히, MCP가 단순히 모델을 연결하는 중간 플랫폼이라는 점을 이해하게 되었고, 이를 바탕으로 로컬 LLM 모델을 활용하여 코드 분석 및 자동화 기능을 적용할 수 있는 기반을 마련했다. 앞으로는 플러그인 설정, 모델 연결, 그리고 MCP 활용 단계를 거쳐 프로젝트 개발 환경을 최적화해야겠다.

헷갈렸던 점#

WebStorm의 무료 라이선스와 AI 플러그인 사용에 필요한 인증 조건이 겹쳐서 어떤 것을 먼저 해결해야 할지 몰랐고, MCP가 단순 연결 도구인 줄 알았습니다. 특히 MCP가 어떤 역할을 하는지 명확하게 이해하지 못해 플러그인 연결 과정에서 어려움을 겪었습니다.

정리된 이해#

WebStorm 자체는 코드 편집 환경을 제공하고, DevoxxGenie 같은 서드파티 플러그인을 통해 로컬 AI 기능을 추가할 수 있습니다. MCP는 LM Studio나 Ollama 같은 도구와 WebStorm을 연결하여 로컬 LLM 모델을 활용할 수 있도록 돕는 중요한 역할을 합니다. 앞으로는 플러그인 설정 및 로컬 모델 연결을 통해 코드 분석 및 자동화 기능을 프로젝트에 적용해 볼 계획입니다.
