1. 클래스 이름 짓기: 대상 중심의 추상화 가이드#

무엇을 배웠나#

클래스 이름은 특정 행동이 아닌, 그 행동들을 수행하는 대상 자체를 대표해야 한다는 것을 알게 되었습니다. 클래스 이름을 짓을 때 너무 구체적인 단어보다는 더 일반적인 개념을 사용하는 것이 좋고, MovingObject와 같이 광범위한 의미를 담는 이름이 적절할 수 있다는 것을 깨달았습니다. 이러한 이해를 바탕으로 앞으로 클래스 이름을 짓는 과정에서 대상 중심적인 관점을 가지도록 노력해야겠습니다.

헷갈렸던 점#

처음에는 acceleration, break, drift 같은 함수들이 특정 객체에만 적용된다고 생각해서 클래스 이름을 정하기가 어려웠습니다. Vehicle이나 Car처럼 구체적인 이름을 붙여야 할지, 아니면 더 일반적인 이름을 사용해야 할지 고민했습니다. 클래스 이름이 특정 행동을 나타내는 것이 아니라, 해당 행동을 수행하는 대상 자체를 대표해야 한다는 점을 깨닫지 못했습니다.

정리된 이해#

클래스 이름을 짓는 건, 그 클래스 안의 함수들이 자연스럽게 연결될 수 있는 대상이나 개념을 대표하는 것이 중요하다는 것을 깨달았습니다. 너무 구체적인 이름보다는 더 일반적인, 추상화된 이름을 선택하는 것이 클래스 설계에 더 도움이 될 수 있습니다. 예를 들어, acceleration, break, drift와 같은 함수들은 MovingObject라는 이름으로 묶이는 것이 더 적절합니다.

class Character {
    run() {
        console.log("달리고 있어요!");
    }
    jump() {
        console.log("뛰어오르고 있어요!");
    }
    walk() {
        console.log("천천히 걷고 있어요!");
    }
    swim() {
        console.log("물속을 헤엄치고 있어요!");
    }
}
const hero = new Character();
hero.run();

class MovingObject {
    acceleration() {
        console.log("가속 중입니다.");
    }
    break() {
        console.log("정지 중입니다.");
    }
    drift() {
        console.log("천천히 움직이고 있어요.");
    }
}

2. 객체지향 프로그래밍, 클래스 정의 및 분류 기준#

무엇을 배웠나#

클래스 이름을 너무 구체적인 동작 위주로 짓지 말고, 해당 클래스가 담당하는 역할과 상태를 명확히 나타내는 이름으로 지어야 한다는 것을 알게 되었다. 또한, 클래스 설계 시 다양한 동작을 가진 객체들의 공통적인 특징을 파악하여 적절한 범위를 설정하는 것이 중요하다는 것을 배웠다. 마지막으로, 자바스크립트에서 추상화와 다형성이 명시적으로 존재하지 않더라도, 그 개념을 이해하고 적용할 수 있다는 점을 인지하게 되었다.

헷갈렸던 점#

클래스 이름을 너무 구체적인 동작 위주로 지으면 클래스의 범위가 좁아져서 적용 가능성이 줄어드는 것 같아서 고민했다. 강사님이 제시하신 예제들이 너무 엉뚱해서 처음에는 이게 뭘 하려는 건지 이해하는 데 어려움을 느꼈다. 추상화와 다형성이 자바스크립트에서 명시적으로 존재하지 않는다는 설명이 조금 헷갈렸다.

정리된 이해#

클래스 이름을 짓을 때는 메서드들의 구체적인 동작만 보고 좁은 범위로 정의하지 말고, 해당 클래스가 책임지는 역할과 상태를 명확하게 나타내야 한다. 추상화나 다형성과 같은 개념은 JavaScript에서 명시적으로 드러나지 않더라도, 동적 타이핑의 유연성을 고려하여 이해하는 것이 중요하다. 결국 클래스 설계는 적절한 범위를 설정하여 재사용성과 확장성을 높이는 과정이다.

// 예시 (상상): MovableObject 클래스
class MovableObject {
  constructor(name) {
    this.name = name;
  }

  accelerate() {
    console.log(`${this.name} is accelerating.`);
  }

  stop() {
    console.log(`${this.name} is stopping.`);
  }

  drift() {
    console.log(`${this.name} is drifting.`);
  }
}

3. 객체 생성 및 속성 접근: this, getter, setter, private#

무엇을 배웠나#

this 키워드가 현재 객체의 멤버에 접근하는 핵심적인 역할을 한다는 것을 깨달았고, 메서드 이름 중복이 발생하는 이유와 parseInt()를 사용하는 이유에 대한 이해가 부족했던 부분을 명확히 했습니다. 특히 setter 작성 시 발생할 수 있는 오류에 대한 주의점을 익혔으며, 이를 통해 객체 지향 프로그래밍의 기본 개념에 대한 이해도를 높일 수 있었습니다.

헷갈렸던 점#

처음에는 this가 무엇인지, 그리고 모든 곳에 굳이 써야 하는 이유를 잘 몰랐다. 또한 동일한 이름의 메서드를 정의했을 때 어떤 기준으로 동작하는지, 그리고 왜 그렇게 동작하는지를 이해하는 데 어려움을 겪었다. parseInt()를 사용해야 하는 상황을 명확히 파악하지 못해 오류가 발생하기도 했다.

정리된 이해#

this는 현재 객체의 프로퍼티를 가리키는 키워드이고, 메서드 정의 시에는 현재 객체의 프로퍼티에 접근해야 한다는 점을 확실히 이해하게 되었으며, getter와 setter를 사용할 때 데이터 타입 변환의 필요성과 프로퍼티 할당 시 검증의 중요성을 깨달았습니다. 동일 이름의 메서드가 덮어써지는 원리도 이제는 설명할 수 있을 것 같습니다.

class Car {
  constructor(name, speed) {
    this.name = name; // 현재 객체의 이름 프로퍼티에 할당
  }
  printDetails() {
    console.log(`Name: ${this.name}, Speed: ${this.speed}`);
  }
}

4. 상속과 직업 클래스: Character 이해하기#

무엇을 배웠나#

Character 클래스의 private 필드에 직접 접근할 수 없고, Getter와 Setter 메서드를 사용해야 한다는 것을 깨달았습니다. 또한 객체의 클래스 확인에는 instanceof 연산자를 사용해야 한다는 점도 명확히 알게 되었습니다. 이제 상속 관계에서 부모 클래스의 private 필드를 안전하게 다루고 객체의 유형을 검증할 수 있을 것 같습니다.

헷갈렸던 점#

Character 클래스의 Private 필드에 자식 클래스에서 직접 접근하는 것이 불가능하다는 점이 처음에는 이해가 안 갔습니다. 특히 Getter와 Setter 메서드를 사용해야 한다는 점이 헷갈렸고, instanceof 연산자를 어떻게 활용해야 하는지 명확하지 않았습니다.

정리된 이해#

부모 클래스의 Private 필드는 직접 접근할 수 없고, Getter와 Setter 메서드를 통해 접근해야 한다는 것을 깨달았습니다. instanceof 연산자를 사용하면 객체가 특정 클래스의 인스턴스인지 여부를 확인할 수 있습니다. 이를 통해 상속 관계에서 데이터 접근과 객체 유형 확인에 대한 이해를 높일 수 있었습니다.

5. 자식 클래스 메서드 오버라이딩과 super 활용하기#

무엇을 배웠나#

메서드 오버라이딩은 부모 메서드를 완전히 새롭게 만드는 것이 아니라, 기능을 확장하는 것이라는 점을 명확히 알게 되었습니다. super를 사용하면 부모 메서드의 기본 동작을 유지하면서 자식 클래스만의 로직을 추가할 수 있다는 것을 깨달았습니다. 이를 통해 부모와 자식 클래스 간의 관계를 더 잘 이해하고 활용할 수 있게 되었습니다.

헷갈렸던 점#

자식 클래스에서 부모 클래스의 메서드를 단순히 수정하는 건지, 완전히 새로운 메서드를 정의하는 건지 구분하는 데 어려움을 느꼈다. super를 언제 어떻게 써야 부모 클래스의 기능을 유지하면서 자식 클래스만의 특징을 더할 수 있을지 명확히 이해하지 못했다. 오버라이딩과 확장의 개념이 뒤섞여 혼란스러웠다.

정리된 이해#

오버라이딩은 자식 클래스에서 부모의 메서드를 재정의하여 기본 동작을 유지하거나 확장하는 것이고, super를 사용하면 부모 메서드를 직접 호출하여 기능을 활용할 수 있습니다. 즉, super는 부모의 기능을 가져오면서 자식 클래스만의 특징을 더하는 역할을 합니다. 이러한 이해를 바탕으로 부모 메서드를 덮어쓰거나 확장하는 상황에 맞는 적절한 방법을 선택할 수 있게 되었습니다.

오늘 오후 전체에서 배운 것#

오늘 강의를 통해 클래스 이름은 대상 자체를 대표해야 하며, 객체 지향 프로그래밍의 핵심 개념인 상속과 오버라이딩을 이해하고 활용하는 것이 중요하다는 것을 알게 되었습니다. 특히 this, getter, setter, super 키워드 사용법을 익히고, private 필드 접근 제어 및 객체 유형 검증에 대한 이해도를 높일 수 있었습니다. 앞으로 클래스 설계 및 코딩 과정에서 오늘 배운 내용들을 적용하여 더욱 효율적이고 유지보수하기 좋은 코드를 작성하도록 노력하겠습니다.

다음에 조심할 것#

클래스 이름을 짓거나 클래스를 설계할 때, 너무 복잡하거나 구체적인 단어에 매몰되지 않도록 대상 중심적인 관점을 유지해야겠다고 생각합니다. 또한 setter를 작성할 때 발생할 수 있는 오류에 대해 더욱 주의 깊게 확인하고, super를 사용할 때 부모 메서드의 동작을 제대로 이해하는 것이 중요할 것 같습니다.

다음 복습 주제#

this 키워드 사용법과 parseInt()가 필요한 이유에 대한 더 깊이있는 이해가 필요합니다. 또한, setter 작성 시 발생할 수 있는 오류와 예외 상황에 대한 추가적인 학습을 통해 객체 지향 프로그래밍의 안정성을 높이고 싶습니다.
