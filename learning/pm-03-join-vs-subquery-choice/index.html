1. 서브쿼리#

왜 이걸 보게 됐나#

데이터를 분석하려면 여러 테이블에 흩어져 있는 정보를 합쳐서 봐야 했는데, 서브쿼리를 배우기 전에는 어떻게 해야 할지 감이 잘 안 잡혔어. 특히 복잡한 조건을 만족하는 데이터를 찾는 과정이 너무 비효율적으로 느껴졌고, 코드가 길어져서 가독성도 떨어졌어. 그래서 좀 더 효율적이고 깔끔하게 데이터를 추출할 수 있는 방법이 서브쿼리라는 것을 알게 됐어.

내가 헷갈린 지점#

처음에 서브쿼리가 왜 복잡한 쿼리를 풀어야 하는지 이해하기 어려웠다. 여러 테이블을 거쳐 값을 찾아오는 과정이 JOIN과 비교했을 때 효율성이 떨어지는 것 같았고, 어떤 상황에서 서브쿼리를 사용하는 것이 가장 적절한지 감이 잘 잡히지 않았다. 결과적으로 서브쿼리는 필요한 값을 먼저 구해내는 과정이라는 것을 이해했지만, 처음에는 그 이유와 장점을 파악하기 힘들었다.

시도한 코드 / 예시#

-- 개념 '서브쿼리' 의 핵심을 보여주는 코드 예시
SELECT ProductName
FROM Products
WHERE Price > (SELECT AVG(Price) FROM Products);
--  ProductName: 제품 이름
--  Products: 제품 테이블
--  AVG(Price): Products 테이블의 평균 가격

결과와 해석#

products 테이블에서 average_price가 10000 이상인 제품을 찾기 위해 서브쿼리를 사용해 average_price가 높은 제품의 ID를 먼저 조회한 후, products 테이블에서 그 ID를 가진 제품을 선택했습니다. 이 과정을 통해 서브쿼리가 복잡한 조건을 만족하는 데이터를 효율적으로 찾는 데 유용함을 확인했습니다. 결과적으로 평균 판매 금액이 높은 제품 목록을 얻을 수 있었습니다.

정리된 이해#

서브쿼리는 필요한 값을 먼저 찾아내서, 그걸 바탕으로 최종 결과를 얻는 방식이야. 마치 최종 목표를 세우고, 그 목표를 달성하기 위한 단계를 거쳐 중간 결과를 활용하는 것과 같아. 주로 특정 조건을 만족하는 값이나 목록을 빠르게 추출할 때 사용해.

2. JOIN#

왜 이걸 보게 됐나#

데이터베이스에서 정보를 더 깊이 분석하고 활용하기 위해서는 여러 테이블에 흩어져 있는 데이터를 결합해야 했기 때문에 JOIN을 배우게 됐어. 단순 SELECT로는 필요한 정보를 얻기 어려울 때, JOIN을 사용하면 여러 테이블을 연결하여 원하는 결과를 효과적으로 얻을 수 있다는 걸 알게 됐지. 서브쿼리도 비슷하게 활용할 수 있지만, JOIN이 더 직관적이고 성능 면에서도 유리한 경우가 많다는 걸 배우면서 JOIN의 필요성을 느끼게 됐어.

내가 헷갈린 지점#

JOIN을 처음 배울 때, 여러 테이블을 연결한다는 개념이 너무 복잡하게 느껴졌어. 마치 퍼즐 조각들을 맞추듯이, 어떤 기준으로 테이블을 연결해야 하는지, 그리고 연결 순서가 결과에 어떤 영향을 미치는지 파악하는 데 어려움을 겪었어. 특히 여러 JOIN을 연달아 사용할 때 전체적인 흐름을 이해하기가 더 힘들었어.

시도한 코드 / 예시#

SELECT t.Name
FROM artists ar
INNER JOIN albums al ON ar.ArtistId = al.ArtistId
INNER JOIN tracks t ON al.AlbumId = t.AlbumId
WHERE ar.Name = 'AC/DC';

결과와 해석#

INNER JOIN을 사용하면 여러 테이블의 정보를 한 번에 가져와서 원하는 결과를 얻을 수 있어 편리하다. 예를 들어, artists, albums, tracks 테이블을 연결하여 특정 아티스트의 곡 목록을 보여줄 때, 각 테이블의 필요한 열을 직접적으로 가져올 수 있다. 이는 서브쿼리처럼 각 테이블을 순차적으로 탐색하는 것보다 직관적이고, 데이터 양이 많을 때 성능상 이점을 줄 수 있다.

정리된 이해#

JOIN은 여러 테이블을 직접 연결해서 필요한 데이터를 한 번에 가져오는 방식이야. 여러 테이블의 데이터를 함께 보여주거나 복잡한 관계를 표현할 때 유용하고, 테이블 간의 관계를 명확하게 보여주는 장점이 있어. 여러 테이블을 조인하면 필요한 정보가 한 번에 나타나기 때문에 편리해.

3. 조건 조달#

왜 이걸 보게 됐나#

데이터를 가져오는 과정에서 특정 테이블의 정보를 얻기 위해 다른 테이블에서 필요한 조건을 찾아야 할 때가 많았어. 처음에는 테이블 간의 관계를 파악하고 필요한 값을 추출하는 방식이 너무 복잡하게 느껴졌는데, 서브쿼리를 배우면서 필요한 값들을 먼저 찾아내는 방법이 익숙해지면서 데이터 추출 과정이 훨씬 명확해졌어. 결국 여러 테이블에서 데이터를 가져오는 작업을 효율적으로 처리하기 위해 필요한 개념이었던 것 같아.

내가 헷갈린 지점#

처음에는 서브쿼리가 마치 최종 결과를 얻기 위한 준비 단계처럼 느껴져서, 굳이 중간 테이블을 거쳐야 하는 이유를 잘 이해하지 못했습니다. 결과적으로 같은 데이터를 얻을 수 있음에도 불구하고, 복잡하게 느껴졌고 왜 이렇게 복잡한 방식을 써야 하는지 의문이었어요. 서브쿼리가 결과 테이블에서 출발한다는 점이 직관적으로 와닿지 않았습니다.

시도한 코드 / 예시#

SELECT ProductName
FROM Products
WHERE Price > (SELECT AVG(Price) FROM Products);

결과와 해석#

서브쿼리를 활용하여 평균 판매 금액을 구한 다음, 이 평균값을 기준으로 판매 금액이 높은 제품을 찾는 코드를 작성했다. 쿼리를 실행했을 때, 평균 판매 금액을 기반으로 필터링된 제품 목록이 제대로 출력되는 것을 확인하여 ‘조건 조달’ 개념이 실질적으로 동작함을 알 수 있었다. 이 예제를 통해 평균값을 먼저 계산하여 조건으로 활용하는 서브쿼리의 역할을 명확하게 이해하게 되었다.

정리된 이해#

서브쿼리는 외부 쿼리에서 필요로 하는 값을 하위 쿼리를 통해 먼저 찾아내서 조건을 만족하는 데이터를 추출하는 방식이야. 마치 최종 목적지를 향해 가기 위해 필요한 정보 조각들을 먼저 수집하는 것과 같다고 생각하면 이해하기 쉬워. 이 방식은 특정 조건을 만족하는 값이나 목록을 빠르게 얻어낼 때 유용해.

4. 데이터 통합#

왜 이걸 보게 됐나#

여러 테이블에 흩어져 있는 정보를 한 번에 가져와서 분석하고 싶을 때, 데이터 통합이 필요하게 됐어. 예를 들어, 어떤 고객이 어떤 제품을 구매했는지, 혹은 어떤 지역에서 특정 제품의 판매량이 높은지 등을 파악하려면 여러 테이블을 연결해서 데이터를 봐야 하니까. 결국 더 유용한 정보를 얻기 위해 데이터 통합, 즉 데이터 테이블을 하나로 합치는 방법을 익히게 된 거야.

내가 헷갈린 지점#

처음에는 JOIN과 서브쿼리가 결국 같은 정보를 가져다주는데, 왜 두 가지 방식으로 쿼리를 작성해야 하는지 이해하기 어려웠어. 특히 서브쿼리가 마치 거꾸로 검색하는 것처럼 느껴져서, 왜 이렇게 복잡한 방식을 사용해야 하는지 궁금했지. 데이터 통합이라는 키워드를 처음 접했을 때는, 단순히 데이터를 합치는 것 이상의 의미가 있을 것 같다고 생각했지만, 정확히 어떤 차이가 있는지 파악하기 어려웠어.

시도한 코드 / 예시#

SELECT t.Name
FROM artists ar
INNER JOIN albums al ON ar.ArtistId = al.ArtistId
INNER JOIN tracks t ON al.AlbumId = t.AlbumId
WHERE ar.Name = 'AC/DC';

결과와 해석#

특정 평균 판매 금액 이상의 제품을 찾기 위해, 먼저 전체 제품의 평균 판매 금액을 서브쿼리를 통해 계산하고, 이를 외부 쿼리의 WHERE절에 넣어서 조건을 만족하는 제품을 찾아보았습니다. 이렇게 서브쿼리를 사용하면 평균 판매 금액을 한 번만 계산하고 재사용할 수 있어서 효율적이라는 것을 알았습니다. 테이블 간의 조인보다는 간단한 조건값을 추출하는 데 더 적합하다는 생각을 했습니다.

정리된 이해#

데이터 통합은 여러 테이블에 흩어진 정보를 하나의 결과 집합으로 묶어 보여주는 것을 의미합니다. 이는 JOIN을 통해 직접 테이블을 연결하거나, 서브쿼리를 활용하여 필요한 값을 먼저 찾아 조건을 적용하는 방식으로 이루어질 수 있습니다. 다양한 테이블의 관계를 파악하고 원하는 결과를 얻기 위해 필수적인 개념입니다.

총평#

오늘 전체에서 배운 것#

서브쿼리와 JOIN은 비슷한 결과를 얻을 수 있지만, 접근 방식이 완전히 다른 SQL 기법이라는 것을 깨달았습니다. 서브쿼리는 중간 결과를 먼저 구하고, JOIN은 테이블을 직접 연결하는 방식으로 데이터 추출 방식을 결정짓습니다. 앞으로는 상황에 따라 적절한 방법을 선택해서 사용해야겠습니다.

다음에 조심할 것#

서브쿼리와 JOIN의 장단점을 명확히 구분하고, 어떤 상황에서 어떤 방식을 사용하는 것이 더 효율적인지 판단하는 연습을 꾸준히 해야겠다. 특히 JOIN은 테이블 간의 관계를 정확히 이해해야 제대로 활용할 수 있다는 점을 기억해야겠다.

다음 복습 주제#

LEFT JOIN과 FULL OUTER JOIN을 좀 더 자세히 알아보고, 서브쿼리에서 JOIN을 사용하는 조합도 연습해봐야겠다. 실제 데이터 분석에서 어떤 상황에서 어떤 방식을 선택하는지에 대한 감을 익히는 게 중요할 것 같아.
