조건문과 논리 연산자 이해하기: 초보자를 위한 가이드

초보 개발자를 위한 조건문과 논리 연산자의 이해와 실제 적용 방법에 대한 안내.
2026년 5월 30일 · 12 min

왜 썼나#

프로그래밍을 배우면서 가장 기초적이면서도 혼란스러운 부분 중 하나가 조건문과 논리 연산자였습니다. 특히 실제 코드로 구현하는 과정에서 이론적 이해와 실제 적용 사이의 간극을 좁히는 것이 중요하다고 느꼈습니다. 이를 통해 초보자들이 쉽게 접근하고 이해할 수 있는 가이드를 만들고자 했습니다.

배운 것#

  • 조건문의 본질: 조건문은 단순히 if를 사용하는 것이 아니라, 특정 조건이 참(True)인지 거짓(False)인지 판단하고 그에 따라 프로그램의 흐름을 조정하는 핵심 도구임을 깨달았습니다.
  • 비교 연산자의 활용: ==, >, <, >=, <= 등의 연산자를 통해 변수 간의 관계를 명확히 파악하고 조건을 설정하는 방법을 배웠습니다.
  • 논리 연산자의 조합: and, or, not 연산자를 적절히 조합하여 복잡한 조건을 처리하는 방법을 이해했습니다. 이를 통해 다양한 시나리오에 맞는 조건을 세밀하게 제어할 수 있게 되었습니다.

헷갈릴린 것#

  • 조건 판단의 복잡성: 단순히 if age >= 18: 조건만 보면 이해하기 쉬운데, 여러 조건을 결합하거나 중첩된 조건문을 작성할 때 혼란이 따랐습니다.
  • 논리 연산자의 적용: and, or, not 연산자를 어떻게 함께 사용하여 복잡한 조건을 처리할지 구체적인 예시와 실제 적용 방법이 명확하지 않았습니다. 예를 들어, age >= 18 and student == True와 같은 조합이 어떻게 동작하는지 이해하는 데 시간이 걸렸습니다.
  • 코드 구현의 어려움: 이론적인 이해를 실제 코드로 구현하는 과정에서 변수의 역할과 조건들이 어떻게 결합되는지 명확히 파악하는 데 어려움이 있었습니다.

정리된 이해#

  • 조건문 (if, elif, else):

    • 목적: 프로그램이 특정 조건이 참(True)인지 거짓(False)인지 판단하고 그에 따라 다른 동작을 수행합니다.
    • 예시: 
      age = 20
if age >= 18:
    print("성인입니다.")
else:
    print("미성년자입니다.")
    • 핵심: 조건이 참(True)일 때 실행되는 코드 블록을 명확히 정의하는 것이 중요합니다.

  • 비교 연산자:

    • 목적: 두 값 사이의 관계를 비교하여 True 또는 False를 반환합니다.
    • 예시: 
      result = 3 < 5  # True
result = 7 == 5  # False

  • 논리 연산자:

    • and: 모든 조건이 참(True)일 때만 결과가 참(True)입니다. 
      age >= 18 and student == True  # 두 조건 모두 참일 때만 True
    • or: 적어도 하나의 조건이 참(True)이면 결과가 참(True)입니다. 
      is_adult = age >= 18 or has_license == True  # 하나라도 참이면 True
    • not: 조건의 반대 값을 반환합니다. 
      not(age < 18)  # age < 18이 거짓이면 True를 반환

간단한 코드 예시를 통해 이해를 돕겠습니다:

    print("회원가입 성공!")
else:
    print("입력이 올바르지 않습니다. 다시 확인해 주세요.")

왜 썼나#

조건문은 프로그래밍에서 매우 중요한 요소로, 특정 조건에 따라 프로그램의 실행 경로를 변경하는 데 사용됩니다. 이를 통해 사용자의 입력에 따라 다르게 동작하는 로직을 구현할 수 있습니다. 이번 학습에서는 Python을 사용하여 조건문을 어떻게 설계하고 적용하는지에 초점을 맞추었습니다.

배운 것#

  • 조건 결합: 여러 조건을 결합하여 복잡한 판단 로직을 구현할 수 있음을 배웠습니다. 예를 들어, 나이, 키, 티켓 소지 여부 등을 모두 고려한 탑승 가능 여부를 판단하는 코드를 작성하였습니다. 
    age = 25
height = 170
has_ticket = True

# 조건 결합 예시
can_ride = age >= 18 and height >= 150 and has_ticket
  • if-elif-else 구조 이해: 여러 조건을 순차적으로 평가하는 방법을 이해했습니다. 각 조건이 이전 조건을 기반으로 평가되므로, 중첩 조건을 효율적으로 처리할 수 있는 방법을 배웠습니다.

헷갈렸던 점#

  • 조건 구분의 복잡성: 여러 조건이 중첩될 때 (예: elif score >= 90), 이전 조건들이 이미 처리되었는지 판단하는 것이 처음에는 혼란스러웠습니다. 특히, 각 조건이 언제 실행되는지 명확히 이해하는 데 시간이 걸렸습니다.
  • 데이터 타입의 중요성: 입력 데이터의 타입이 프로그램 동작에 큰 영향을 미친다는 점을 인지하지 못했습니다. 예를 들어, 성적 점수를 처리할 때 float()를 사용해야 하는 이유를 명확히 이해하지 못했습니다.

정리된 이해#

  • 조건 구분의 핵심: 조건문을 설계할 때, 어떤 상황을 구분하고자 하는지 명확히 파악하는 것이 중요합니다. 예를 들어:

    • True 조건: 특정 조건이 만족될 때 실행되는 코드 블록 (예: if score >= 60: → 합격).
    • False 조건: 조건이 만족되지 않을 때 실행되는 코드 블록 (예: else: → 불합격).

  • 중첩 조건 처리: if-elif-else 구조에서는 각 조건이 순차적으로 평가됩니다:

    • if score >= 80: → 등급 A
    • elif score >= 90: → 등급 B (이전 조건인 score >= 80을 이미 만족했으므로 이 조건만 검사하면 됨)
    • else: → 등급 C 이하

    age = int(input("나이를 입력하세요: "))

정리된 이해#

  • 조건문 활용: 조건문은 특정 조건이 참인지 거짓인지를 검사하여 코드의 흐름을 제어하는 도구입니다. BMI 계산에서는 점수 범위에 따라 다른 등급을 반환하는 로직을 구현할 수 있습니다. 
    score = float(input("체중(kg)와 키(m)의 비율을 입력하세요 (예: 60.0 1.7): "))  # 예시 입력 형식

  • 데이터 흐름:
    1. 입력: 사용자로부터 체중(kg)과 키(cm)를 입력받습니다.
    2. 변환: 입력된 데이터를 적절한 타입으로 변환합니다 (예: 문자열을 실수로).
    3. 단위 조정: 키 값을 미터 단위로 변환합니다 (예: cm를 m로).
    4. 계산: BMI를 계산합니다 (BMI = 체중(kg) / (키(m) * 키(m))).
    5. 조건 판정: 계산된 BMI 값을 기준 범위와 비교하여 판정합니다.
    6. 출력: 결과를 사용자에게 명확하게 보여줍니다.

실습 예시#

아래 코드는 초보자도 쉽게 따라 할 수 있도록 BMI 계산 과정을 단계별로 설명하고 있습니다:

# 1. 사용자로부터 입력 받기
input_weight = input("몸무게를 kg 단위로 입력하세요: ")
input_height_cm = input("키를 cm 단위로 입력하세요: ")

# 2. 입력값 변환 및 단위 조정
try:
    weight = float(input_weight)  # 문자열을 실수로 변환
    height_cm = float(input_height_cm)  # 키 입력도 실수로 변환
    height_m = height_cm / 100  # cm를 m로 변환

    # 3. BMI 계산
    bmi = weight / (height_m ** 2)

    # 4. 조건 판정 및 결과 출력
    if bmi < 18.5:
        result = "저체중"
    elif 18.5 <= bmi < 25:
        result = "정상 체중"
    elif 25 <= bmi < 30:
        result = "과체중"
    else:
        result = "비만"

    print(f"계산된 BMI: {bmi:.2f} ({result})")

except ValueError:
    print("잘못된 입력입니다. 숫자를 입력해 주세요.")

왜 썼나#

이번 학습 세션에서는 Hugo 블로그의 초안 생성 과정 중 특히 파이프라인의 핵심 기능들에 집중했습니다. 특히 파일 관리, 공개 정책 적용, 그리고 에러 처리 메커니즘에 대해 깊이 이해하고자 했습니다. 이러한 지식은 블로그 콘텐츠 관리와 유지보수를 효과적으로 수행하는 데 필수적이라 생각했습니다.

배운 것#

  • 파일 등록 메커니즘: 새로운 파일이 블로그 시스템에 어떻게 등록되는지에 대한 구체적인 과정을 이해했습니다. 파일의 생성 여부와 그에 따른 등록 여부 결정이 핵심임을 깨달았습니다.
  • 공개 정책의 역할: public_policy 설정이 콘텐츠의 공유 범위와 관리 방식에 어떻게 영향을 미치는지 알게 되었습니다. partial-public 설정이 draft 상태와 어떻게 연관되는지 이해했습니다.
  • 에러 관리 전략: 개발 과정에서 발생할 수 있는 다양한 에러 유형과 그에 대한 효과적인 대응 방법을 배웠습니다. 특히 에러 발생 시 문제 해결 절차가 중요함을 인지했습니다.

헷갈릴린 것#

  • 파일 등록 여부 확인: “새 파일"이라는 표현이 명확하지 않아 어떤 파일이 실제로 새로 생성되었는지 판단하는 기준이 모호했습니다. 생성 시점이나 상태 확인 방법에 대한 구체적인 가이드라인이 필요했습니다.
  • 공개 정책과 draft 상태의 연결: public_policy가 partial-public일 때 왜 해당 파일이 draft 상태로 분류되는지의 논리적 연결이 명확하지 않았습니다. 이 연결 고리를 명확히 이해하는 데 시간이 걸렸습니다.
  • 에러 처리의 직관성 부족: 에러 발생 시 어떤 종류의 에러를 어떻게 확인하고 해결해야 하는지에 대한 구체적인 예시가 부족했습니다. 실제 적용 사례를 통해 더 명확한 이해가 필요했습니다.

정리된 이해#

  • 파일 등록:

    • 새 파일 확인: 시스템은 파일 생성 시점이나 고유 식별자 등을 통해 파일의 최초 생성 여부를 판단합니다. 만약 해당 파일이 처음 생성된 경우 (True), registry에 등록됩니다.
    • 등록 프로세스: 기존 파일 (False)은 등록 과정을 생략하고 다음 단계로 진행합니다.

  • 공개 정책:

    • partial-public: 이 설정은 콘텐츠가 부분적으로 공개될 수 있음을 의미합니다. 따라서 이러한 파일들은 검토 단계로 분류되어 draft 상태로 관리됩니다. 이는 외부 공유 전 내부 검토를 위한 것입니다.
    • 내부 전용: public_policy가 False인 경우, 해당 파일은 내부에서만 접근 가능한 상태로 관리됩니다.

  • 에러 처리:

    • 에러 확인: 에러 발생 여부를 판단하기 위해 로그 파일이나 코드 내 에러 핸들러를 통해 확인합니다.
    • 대응 방법: 에러가 발생하면 (True) 원인을 찾아 수정해야 합니다 (repair). 에러가 없다면 (False) 프로세스는 다음 단계로 진행됩니다. 예를 들어, 데이터베이스 연결 오류는 연결 설정을 재검토하고 수정하는 것이 필요합니다.
