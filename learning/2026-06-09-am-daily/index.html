1. am-01-sql-groupby-having#

무엇을 배웠나#

SQL의 GROUP BY와 HAVING을 이해하는 데 어려움을 겪었는데, 문제를 세 단계로 나누어 생각하는 방법을 통해 해결할 수 있었다. GROUP BY는 데이터를 묶는 기준을 명확히 설정하는 것이 중요하며, HAVING은 그룹화된 결과에 조건을 추가하여 원하는 결과를 얻는 데 활용된다는 것을 알게 되었다. 이제 SQL 쿼리를 작성할 때 어떤 테이블에서 데이터를 가져오고, 어떤 기준으로 묶고, 어떤 값을 계산할지 질문하며 접근하면 더욱 효과적일 것 같다.

헷갈렸던 점#

테이블이 복잡해 보일 때 어떤 컬럼을 기준으로 묶어야 할지, 그리고 COUNT(*)가 정확히 무엇을 세야 하는지 헷갈렸었다. HAVING이 왜 필요한지, 그리고 어떻게 활용해야 하는지 감이 잘 안 잡혔던 것 같다. 전체적인 SQL 쿼리의 흐름을 파악하는 데 어려움을 겪었다.

정리된 이해#

SQL GROUP BY는 특정 컬럼을 기준으로 행들을 묶어 그룹화하는 역할을 하며, HAVING은 GROUP BY로 만들어진 그룹에 대한 조건을 추가적으로 적용합니다. 쿼리를 작성할 때는 어떤 테이블에서 데이터를 가져올지, 어떻게 그룹화할지, 그리고 어떤 값을 계산할지를 명확히 정의하는 것이 중요합니다. 이러한 과정을 통해 복잡한 데이터에서도 원하는 정보를 효율적으로 추출할 수 있습니다.

2. am-02-sql-join-alias-erd#

무엇을 배웠나#

SQL JOIN을 통해 여러 테이블의 데이터를 연결하는 방법을 이해했고, ERD를 통해 테이블 간의 데이터 연결 경로를 시각적으로 파악하는 것이 중요함을 알게 되었다. 테이블 이름과 컬럼명에 별칭을 사용하면 쿼리를 간결하게 만들 수 있으며, JOIN 조건을 설정할 때 ERD를 참고하여 어떤 컬럼을 연결해야 하는지 명확히 판단할 수 있게 되었다. 앞으로는 ERD를 활용하여 JOIN 쿼리를 작성하는 연습을 꾸준히 해야겠다.

헷갈렸던 점#

처음에는 ERD를 테이블 간의 연결 관계만 보여주는 그림이라고 생각해서 실제 데이터가 어떻게 연결되는지 이해하기 어려웠다. invoice_items.TrackId와 tracks.TrackId 같이 같은 이름의 컬럼이 다른 테이블에 존재할 때 어떻게 구분해야 할지 헷갈렸고, 별칭을 왜 써야 하는지, 어떻게 활용해야 할지 명확하게 알지 못했다. ON 조건 설정 시 어떤 컬럼을 연결해야 하는지 파악하는 데 어려움을 느꼈다.

정리된 이해#

SQL JOIN은 테이블 간의 관계를 활용하여 데이터를 연결하는 문법이며, ERD는 테이블 간의 데이터 연결 경로를 시각적으로 보여주는 지도와 같습니다. 별칭을 사용하면 쿼리를 간결하게 만들 수 있으며, ON 절은 데이터 연결을 위한 핵심적인 조건입니다. ERD를 통해 데이터 흐름을 파악하고, 별칭과 ON 절을 적절히 활용하면 복잡한 쿼리도 쉽게 작성할 수 있습니다.

SELECT
        ins.InvoiceId,
        ins.Total,
        cu.FirstName,
        cu.LastName
    FROM invoices ins
    INNER JOIN customers cu
        ON ins.CustomerId = cu.CustomerId;

SELECT
        t.Name AS TrackName,
        g.Name AS GenreName
    FROM tracks t
    INNER JOIN genres g ON t.GenreId = g.GenreId;

3. am-03-sql-join-problem-solving#

무엇을 배웠나#

SQL JOIN 문제를 풀 때 ERD만으로는 테이블 간 연결 기준을 명확히 파악하기 어려웠는데, 데이터베이스는 직관적인 구조가 아닌 구조화된 방식으로 데이터를 저장한다는 것을 깨달았다. 특히, 문제 해결을 위해 테이블 별칭을 활용하고, 연결 기준이 되는 컬럼을 명확히 이해하는 것이 중요하다는 것을 실습을 통해 알게 되었다. 앞으로는 ERD를 보면서 테이블 간의 관계를 연결하는 컬럼을 중심으로 분석해야 할 것이다.

헷갈렸던 점#

처음에는 ERD만 보고 테이블 간의 연결 기준을 명확하게 파악하는 데 어려움을 느꼈습니다. 특히 고객 테이블과 직원 테이블의 연결 고리가 직접적인 이름 정보가 아닌 ID로 이루어져 있어 혼란스러웠던 점이 기억에 남습니다. 데이터 구조가 직관적인 이해와는 다를 수 있다는 것을 깨닫고, 공통 컬럼을 통해 테이블을 연결하는 방식을 집중적으로 공부했습니다.

정리된 이해#

데이터베이스에서 테이블 간의 관계는 ERD만으로 완벽하게 파악하기 어려울 수 있으며, 고객과 직원의 정보처럼 서로 다른 테이블에 분산되어 저장되는 경우가 많다. 이럴 땐 공통의 컬럼을 활용하여 테이블을 연결하고 필요한 정보를 조합해야 하며, 데이터 구조가 직관적인 언어와 다를 수 있다는 점을 인지하는 것이 중요합니다.

총평#

오늘 오전 전체에서 배운 것#

SQL의 GROUP BY와 HAVING 사용법을 문제 해결 단계를 나눠서 이해했고, 여러 테이블을 연결하는 JOIN 쿼리를 작성할 때 ERD를 활용하는 것이 중요함을 알게 되었다. 특히 JOIN 조건을 설정할 때는 테이블 별칭을 사용하고, 데이터베이스 구조를 직관적으로 이해하기보다는 연결 기준 컬럼을 중심으로 분석하는 것이 필요하다는 점을 배웠다.

다음에 조심할 것#

ERD를 활용하는 것은 중요하지만, 실제 데이터베이스 구조가 직관적이지 않을 수 있다는 점을 항상 염두에 두어야겠어. 테이블 별칭을 적극적으로 사용하고, 각 테이블의 컬럼을 명확히 이해하며 JOIN 조건을 설정하는 연습을 꾸준히 해야 실수를 줄일 수 있을 것 같아.

다음 복습 주제#

SQL JOIN 문제 해결 시 테이블 별칭 활용법과 데이터베이스 구조화 방식에 대한 이해를 더욱 깊이 있게 복습해야겠다. ERD를 보고 테이블 간 연결 컬럼을 분석하는 연습을 꾸준히 해야 JOIN 쿼리 작성에 자신감을 가질 수 있을 것 같다.
