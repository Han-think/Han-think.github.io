1. 중심 테이블 혼동#

왜 이걸 보게 됐나#

처음에는 테이블 간의 관계가 명확하지 않아 특정 문제를 풀 때 어떤 테이블을 중심으로 데이터를 가져와야 할지 헷갈렸어요. 강사님이 문제 유형을 바꿔가며 제시하셨을 때, 중심 테이블이 바뀌면서 데이터 연결 경로를 다시 생각해야 해서 어려움을 겪었습니다. 이 과정을 통해 문제 해결의 첫걸음은 어떤 데이터를 기준으로 할 것인지를 파악하는 것임을 깨달았습니다.

내가 헷갈린 지점#

처음에는 문제를 풀 때 어떤 테이블이 기준이 되는지 파악하는 데 어려움을 느꼈습니다. 특히 장르별 트랙 수와 매출 통계를 구할 때 중심 테이블이 달라지면서 어디서부터 시작해야 할지 헷갈렸습니다. 테이블 간의 관계를 시각화해서 연결 경로를 이해하는 연습이 필요했습니다.

시도한 코드 / 예시#

-- 장르별 매출 통계 계산
SELECT
    g.Name AS 장르,  -- 장르 이름
    COUNT(DISTINCT ii.InvoiceId

결과와 해석#

초기에 tracks 테이블이 중심이 아닌 invoice_items 테이블을 중심으로 매출 데이터를 분석하는 부분에서 혼란스러웠습니다. invoice_items 테이블을 중심으로 tracks 테이블, 그리고 genres 테이블로 연결하여 장르별 매출을 계산하는 SQL 쿼리를 작성하는 과정에서 테이블 간의 관계를 명확히 이해하는 것이 중요했습니다. 예를 들어, invoice_items에서 TrackId를 통해 tracks 테이블에 연결하고, tracks 테이블에서 GenreId를 통해 genres 테이블에 연결하는 방식으로 데이터 흐름을 파악했습니다.

정리된 이해#

문제를 풀 때 어떤 데이터를 중심으로 분석해야 하는지 파악하는 게 중요했어요. 처음에는 장르별 트랙 수를 구할 때 tracks 테이블이 중심이었지만, 매출 통계를 구하려면 invoice_items 테이블을 중심으로 데이터를 연결해야 한다는 점을 깨달았습니다.

2. 테이블 연결 경로#

왜 이걸 보게 됐나#

처음에는 테이블 간의 관계를 떠올리는 것 자체가 어려웠는데, 문제를 풀어나가면서 어떤 테이블이 중심이 되는지, 그리고 그 테이블과 연결된 다른 테이블들이 어떻게 데이터를 연결해주는지 이해해야 장르별 매출 통계를 낼 수 있다는 것을 알게 되었어. 이 과정에서 각 테이블 간의 연결 경로를 파악하는 것이 얼마나 중요한지, 그리고 문제 해결에 결정적인 역할을 하는지 깨닫게 되었지.

내가 헷갈린 지점#

처음에는 매출 데이터를 어떻게 장르 정보와 연결해야 할지 몰랐습니다. tracks 테이블이 항상 중심이라고 생각해서 invoice_items 테이블을 중심으로 생각하는 데 어려움을 겪었습니다. 테이블 간의 관계를 명확히 이해하지 못해서 어떤 테이블을 기준으로 데이터를 가져와야 할지 혼동스러웠습니다.

시도한 코드 / 예시#

-- 장르별 매출 통계 계산
SELECT
    g.Name AS 장르,  -- 장르 이름
    COUNT(DISTINCT ii.InvoiceId

결과와 해석#

테이블 연결 경로는 문제를 풀 때 어떤 테이블이 중심이 되는지, 그리고 그 테이블과 관련된 다른 테이블들을 어떻게 연결해야 하는지를 파악하는 데 도움을 줍니다. 예를 들어, 장르별 매출을 구하려면 invoice_items 테이블에서 시작하여 tracks 테이블, 그리고 genres 테이블로 연결하여 필요한 데이터를 가져올 수 있습니다. 이를 통해 데이터가 어떻게 연결되어 있는지 시각적으로 이해하고, 원하는 결과를 얻기 위한 쿼리를 효과적으로 작성할 수 있었습니다.

정리된 이해#

문제 해결의 핵심은 어떤 테이블이 중심 데이터인지 파악하는 것입니다. 중심 테이블을 기준으로 필요한 다른 테이블들과의 연결 경로를 명확히 이해해야 원하는 데이터를 추출할 수 있습니다. 이를 통해 다양한 관점에서 데이터를 분석하고 종합적인 리포트를 생성할 수 있습니다.

3. UNION ALL 활용#

왜 이걸 보게 됐나#

여러 테이블에 흩어져 있는 데이터를 하나의 리포트로 보여주고 싶을 때, 각 테이블에서 얻은 결과를 단순히 합쳐서 보여주는 방법이 필요했어. 특히 장르별 트랙 수와 매출 통계를 함께 보여주기 위해, 각 쿼리 결과를 UNION ALL을 통해 합쳐서 하나의 테이블로 만들면서 이 개념을 배우게 됐지. 이를 통해 다양한 데이터를 결합하여 더 풍부한 정보가 담긴 리포트를 만들 수 있다는 점을 알게 되었어.

내가 헷갈린 지점#

UNION ALL을 사용할 때, 단순히 두 쿼리의 결과를 합치는 것이 아니라, 각 쿼리가 어떤 기준으로 데이터를 필터링하고 집계하는지 명확히 이해해야 한다는 점이 처음에는 잘 몰랐습니다. 특히, ‘전체 합계’ 행을 추가할 때는 전체 트랙 수를 계산하는 쿼리와 장르별 트랙 수를 계산하는 쿼리 사이의 데이터 유형과 집계 방식이 일치해야 해서 쿼리 작성에 어려움이 있었습니다. 각 쿼리의 결과를 일관성 있게 보여주기 위해 필요한 필드와 집계 함수를 정확하게 지정하는 데 집중해야 한다는 것을 깨달았습니다.

시도한 코드 / 예시#

UNION ALL
SELECT
    '전체 합계' AS 장르,  -- 전체 합계 레이블
    COUNT(*) AS 트랙_수  -- 전체 트랙 수 계산
FROM tracks;

결과와 해석#

UNION ALL을 사용하면 여러 쿼리의 결과를 하나로 합칠 수 있어서, 장르별 매출 통계와 전체 합계를 같은 형식으로 보여주는 리포트를 만들 수 있었습니다. 처음에는 장르별 트랙 수 쿼리와 매출 통계 쿼리가 비슷해서 혼란스러웠는데, UNION ALL을 통해 두 결과를 합치면서 각 쿼리의 목적과 중심 테이블이 다르다는 것을 명확히 이해하게 되었습니다. 이렇게 하면 리포트를 더 쉽게 읽고 분석할 수 있고, 전체적인 그림을 파악하는 데 도움이 됩니다.

정리된 이해#

UNION ALL은 서로 다른 SELECT 쿼리 결과를 하나로 합쳐서 보여주는 강력한 도구인데, 특히 서로 다른 종류의 데이터를 같은 형태로 표현해야 할 때 유용하다. 장르별 트랙 수와 전체 합계, 장르별 매출 통계와 전체 합계를 같은 형태의 결과로 보여주기 위해 UNION ALL을 사용했는데, 이렇게 하면 결과 집합의 구조를 일관성 있게 유지하면서 필요한 모든 정보를 한눈에 파악할 수 있다.

4. 장르별 매출 통계#

왜 이걸 보게 됐나#

이전에는 장르별 트랙 수를 세는 문제만 풀었었는데, 이번에는 실제 매출 데이터를 기반으로 분석해야 해서 새로운 테이블을 다뤄야 했어. 매출 분석은 단순히 음악 데이터뿐만 아니라 판매량까지 고려해야 하는 중요한 분석 기법이라 배우게 됐어. 이를 통해 음악 데이터와 판매 데이터를 결합하여 더 의미있는 인사이트를 얻을 수 있게 될 거야.

내가 헷갈린 지점#

처음에는 장르별 매출 통계를 구할 때 tracks 테이블을 중심으로 생각해서 혼란스러웠다. 어떤 테이블이 중심이 되는지, 그리고 어떤 테이블 간의 연결 경로를 따라야 하는지 파악하는 데 시간이 걸렸다. 결국 invoice_items 테이블이 중심이 되어야 하고, tracks와 genres 테이블을 거쳐야 한다는 것을 깨달았다.

시도한 코드 / 예시#

-- 장르별 매출 통계 계산
SELECT
    g.Name AS 장르,  -- 장르 이름
    COUNT(DISTINCT ii.InvoiceId) AS 청구_수
FROM genres AS g
LEFT JOIN tracks AS t ON g.GenreId = t.GenreId
LEFT JOIN invoice_items AS ii ON t.TrackId = ii.TrackId
GROUP BY g.GenreId, g.Name;

결과와 해석#

장르별 매출 통계 리포트는 invoice_items 테이블을 중심으로 시작하여 tracks와 genres 테이블을 연결하여 각 장르별 판매 건수를 계산하는 방식으로 구현했습니다. UNION ALL을 사용하여 각 장르별 판매 건수와 함께 전체 합계 행을 하나의 리포트로 통합하여 가독성을 높였습니다. 이 과정을 통해 중심 테이블을 명확히 파악하고 테이블 간 연결 경로를 이해하는 것이 중요함을 알게 되었습니다.

정리된 이해#

장르별 매출 통계를 위해서는 판매 데이터가 있는 invoice_items 테이블을 중심으로 시작해서 tracks 테이블을 거쳐 genres 테이블에 연결해야 한다는 것을 알게 되었습니다. 중심 테이블이 문제의 핵심 데이터에 따라 달라지고, 테이블 간의 연결 경로를 정확히 파악하는 것이 중요하다고 느꼈습니다.

총평#

오늘 전체에서 배운 것#

문제 해결의 핵심은 어떤 테이블이 중심인지 파악하는 것이었고, UNION ALL을 사용하여 장르별 상세 결과와 전체 합계를 한 번에 보여주는 방법을 익혔습니다. 특히, 테이블 간의 연결 경로를 명확히 이해하는 것이 중요함을 알게 되었습니다.

다음에 조심할 것#

문제 해결 시 중심 테이블을 먼저 파악하고, 필요한 테이블 간의 연결 경로를 명확히 그려야겠다. 특히, 문제의 요구사항에 따라 중심 테이블이 바뀌는 경우에 혼동하지 않도록 주의해야 해.

다음 복습 주제#

invoice_items 테이블을 이용해서 더 복잡한 매출 분석을 어떻게 할 수 있을지 알아봐야겠다. 특히 UNION ALL을 활용해서 다양한 통계 지표를 한 번에 보여주는 방법을 더 숙달해야 할 것 같다.
