1. 함수 구조화#

왜 이걸 보게 됐나#

함수 구조화는 코드의 가독성과 유지보수성을 향상시키며, 각 기능을 독립적인 단위로 분리하여 테스트를 용이하게 만듭니다. 이를 통해 복잡한 프로그램도 관리하기 쉬워집니다.

내가 헷갈린 지점#

초보자로서 다양한 코드 요소들이 혼재되어 있어 함수의 핵심 역할과 테스트 방법에 집중하기 어려웠습니다. 특히 클래스와 함수의 경계가 모호해 혼란이 있었습니다.

시도한 코드 / 예시#

def calculate_area(radius): # 원의 넓이 계산 함수
    pi = 3.14159
    return pi * radius ** 2

def calculate_circumference(radius): # 원의 둘레 계산 함수
    pi = 3.14159
    return 2 * pi * radius

# 테스트 코드 예시
def test_circle_functions():
    assert calculate_area(5) == 78.53975
    assert calculate_circumference(5) == 31.4159

# 실행
if __name__ == '__main__':
    test_circle_functions()
    print('테스트 통과')

결과와 해석#

테스트 통과

  • calculate_area(5)는 예상대로 78.53975를 반환합니다.
  • calculate_circumference(5)는 예상대로 31.4159를 반환합니다.

정리된 이해#

함수를 이용해 원의 넓이와 둘레를 계산하는 간단한 예제를 통해 코드의 구조화와 단위 테스트 방법을 이해할 수 있습니다. 각 함수가 독립적으로 동작하며, 테스트를 통해 정확성을 검증할 수 있음을 보여줍니다.

2. 테스트 가능한 코드#

왜 이걸 보게 됐나#

테스트 가능한 코드는 소프트웨어의 신뢰성을 높이고 버그를 조기에 발견하는 데 필수적입니다. 이를 통해 개발자는 코드의 각 부분이 예상대로 동작하는지 확인할 수 있습니다.

내가 헷갈린 지점#

초보자들은 함수를 단순히 코드 조각으로만 이해하기 쉽지만, 실제 테스트를 통해 어떻게 효과적으로 검증할 수 있는지에 대한 구체적인 방법을 모르는 경우가 많습니다.

시도한 코드 / 예시#

def calculate_area(radius):
    if radius < 0:
        raise ValueError("반지름은 음수일 수 없습니다.")
    return 3.14159 * radius * radius

# 테스트 코드 예시
import unittest

class TestCalculateArea(unittest.TestCase):
    def test_positive_radius(self):
        self.assertAlmostEqual(calculate_area(5), 78.53975)
    def test_zero_radius(self):
        self.assertEqual(calculate_area(0), 0)
    def test_negative_radius(self):
        with self.assertRaises(ValueError) as context:
            calculate_area(-1)
        self.assertEqual(str(context.exception), "반지름은 음수일 수 없습니다.")

if __name__ == '__main__':
    unittest.main()

결과와 해석#

테스트 코드 실행 결과:

  • test_positive_radius: 반지름이 5일 때 면적이 78.53975로 올바르게 계산됨.
  • test_zero_radius: 반지름이 0일 때 면적이 0으로 올바르게 계산됨.
  • test_negative_radius: 반지름이 음수일 때 ValueError 예외가 올바르게 발생함.

정리된 이해#

테스트 가능한 코드 작성은 함수의 정확성과 안정성을 검증하는 핵심 방법입니다. 위 예제에서는 calculate_area 함수를 다양한 입력 조건 하에 테스트하여 예상대로 동작하는지 확인합니다. 이를 통해 함수의 경계 조건과 예외 처리가 올바르게 구현되었는지 쉽게 파악할 수 있습니다.

3. 함수 분할 이점#

왜 이걸 보게 됐나#

함수 분할은 코드의 가독성과 유지보수성을 향상시키며, 각 기능을 독립적으로 테스트할 수 있게 해주어 개발 효율성을 높입니다. 이를 통해 복잡한 문제를 단순한 부분 문제로 나누어 해결할 수 있습니다.

내가 헷갈린 지점#

초보자로서 다양한 함수와 클래스의 역할이 혼재되어 있어 핵심 개념인 함수 분할의 이점을 명확히 파악하는 데 어려움이 있었습니다. 특히 실제 코드 예시와 테스트 방법을 어떻게 적용할지 구체적으로 이해하는 데 시간이 필요했습니다.

시도한 코드 / 예시#

def calculate_area(radius): # 원의 넓이 계산 함수
    return 3.14159 * radius * radius

def calculate_circumference(radius): # 원의 둘레 계산 함수
    return 2 * 3.14159 * radius

위 코드는 원의 넓이와 둘레를 계산하는 두 개의 함수를 정의하고, 이를 테스트하는 간단한 함수를 포함하고 있습니다. pytest.approx를 사용하여 부동소수점 계산의 오차를 허용 범위 내에서 검증합니다.

정리된 이해#

함수 분할은 코드를 모듈화하여 각 부분을 독립적으로 테스트하고 유지보수할 수 있게 합니다. 이를 통해 개발 과정이 효율적이며, 오류 수정과 확장성이 향상됩니다.

4. 메서드 활용#

왜 이걸 보게 됐나#

함수를 효과적으로 활용하면 코드의 가독성과 유지보수성이 향상되며, 각 기능을 독립적으로 테스트할 수 있어 개발 효율성이 높아집니다. 이를 통해 복잡한 문제를 단순한 부분 문제로 나누어 해결할 수 있습니다.

내가 헷갈린 지점#

초기에는 함수와 클래스, 그리고 테스트 프레임워크의 통합 방법에 대해 혼란스러웠습니다. 특히 실제 코드 예시와 테스트 코드를 어떻게 작성해야 하는지 구체적으로 이해하는 데 시간이 걸렸습니다.

시도한 코드 / 예시#

def calculate_area(length, width):
    if width < 0:
        raise ValueError('너비는 음수일 수 없습니다.')
    return length * width

# 테스트 코드 예시
import unittest

class TestCalculateArea(unittest.TestCase):
    def test_positive_area(self):
        self.assertEqual(calculate_area(5, 10), 50)
    def test_negative_width(self):
        with self.assertRaises(ValueError) as context:
            calculate_area(-5, 10)
        self.assertTrue('너비는 음수일 수 없습니다.' in str(context.exception))

결과와 해석#

위 코드는 calculate_area 함수를 정의하고, 이 함수가 길이와 너비를 받아 면적을 계산합니다. 테스트 코드는 unittest 모듈을 사용하여 양수 면적과 음수 너비에 대한 예외 처리를 검증합니다. test_positive_area는 정상적인 면적 계산을 확인하고, test_negative_width는 예외 상황을 테스트합니다.

정리된 이해#

함수를 활용해 코드를 모듈화하고, 각 함수에 대한 독립적인 테스트를 작성함으로써 코드의 안정성과 가독성을 높일 수 있습니다. 이 방법은 복잡한 시스템을 관리하기 쉽게 만들며, 버그 수정과 확장성을 향상시킵니다.
