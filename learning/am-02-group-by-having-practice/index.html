1. GROUP BY와 HAVING#

왜 이걸 보게 됐나#

데이터 분석 프로젝트에서 데이터의 특성을 파악하고 의미 있는 정보를 추출하기 위해 데이터 집계를 요약하고 필터링하는 방법이 필요했어. 단순히 개별 데이터를 보는 것만으로는 전체적인 트렌드를 파악하기 어려워서, 그룹화와 조건을 활용하여 데이터를 효과적으로 분석하는 방법을 익히게 됐어. 특히 HAVING 절을 통해 집계된 데이터에 대한 조건을 설정하는 방법을 알게 되니, 더욱 다양한 분석을 할 수 있을 것 같아.

내가 헷갈린 지점#

처음에 GROUP BY 문 뒤에 DESC와 같은 정렬 지시어를 써서 오류가 발생했고, WHERE절과 HAVING절의 차이점을 명확히 이해하지 못해서 어떤 조건식을 어디에 넣어야 하는지 헷갈렸었어. 특히 문제에서 요구하는 조건이 어떤 데이터인지 정확히 파악하는 데 어려움이 있었어.

시도한 코드 / 예시#

SELECT MediaTypeId, COUNT(*) AS track_count
FROM tracks
GROUP BY MediaTypeId
ORDER BY track_count DESC;

결과와 해석#

GROUP BY는 특정 컬럼을 기준으로 데이터를 묶어주는 기능이고, HAVING은 GROUP BY로 묶인 그룹에 대해 조건을 걸 때 사용한다. 문제에서 ORDER BY의 위치를 잘못 이해했던 오류를 수정하고, WHERE와 HAVING의 차이점을 명확히 이해하여 집계된 데이터에 조건을 적용하는 방법을 익혔다. 실습을 통해 GROUP BY와 ORDER BY를 함께 사용하여 원하는 결과를 얻을 수 있음을 확인했다.

정리된 이해#

GROUP BY는 특정 컬럼을 기준으로 데이터를 묶어주는 역할을 하고, HAVING은 이렇게 묶인 그룹에 대한 조건을 설정할 때 사용한다. WHERE절은 개별 데이터 행에 대한 조건을 설정하는 반면, HAVING은 그룹화된 결과에 대한 조건을 설정한다는 점이 핵심이다.

2. WHERE와 HAVING 비교#

왜 이걸 보게 됐나#

쿼리에서 원하는 결과를 얻기 위해 데이터를 그룹화하고, 그 그룹화된 결과에 조건을 걸고 싶었지만, 어떤 조건을 WHERE 절에 넣어야 하고 HAVING 절에 넣어야 하는지 헷갈렸어요. 문제 풀이 과정에서 WHERE 절과 HAVING 절의 차이를 명확히 이해하고 적용해야 데이터 필터링 및 정렬이 정확하게 이루어지는 것을 깨달았습니다.

내가 헷갈린 지점#

처음에 WHERE는 개별 레코드를 걸러내는 조건이라고 생각했는데, GROUP BY 전에 적용된다는 점이 헷갈렸어. HAVING은 집계된 결과에 조건을 걸어주는 건 알았지만, 왜 WHERE와 다르게 GROUP BY 뒤에 와야 하는지 이해가 안 됐었지. 결국 집계 함수를 사용한 결과를 필터링해야 해서 위치가 달라지는구나.

시도한 코드 / 예시#

-- WHERE: 모든 고객에서 총 구매액이 100달러 이상인 고객 필터링
SELECT *
FROM customers
WHERE total_purchases >= 100;

-- HAVING: 총 구매액이 100달러 이상인 고객 그룹에 대한 평균 주문량 계산
SELECT AVG(order_quantity)
FROM (SELECT customer_id, SUM(order_quantity) AS total_quantity FROM orders GROUP BY customer_id) AS customer_totals
HAVING total_quantity >= 100;

결과와 해석#

WHERE 절은 테이블에서 특정 조건을 만족하는 행을 먼저 선택하고, HAVING 절은 GROUP BY를 통해 생성된 그룹에 대한 조건(예: 그룹의 합계, 평균 등)을 필터링합니다. 예를 들어, 특정 지역의 고객 수가 50명 이상인 담당자를 찾을 때 WHERE 절로 기본적인 담당자 정보를 선택하고 HAVING 절로 고객 수 조건을 추가할 수 있습니다. HAVING은 GROUP BY 후에만 사용 가능하며, 집계 함수(COUNT, SUM, AVG 등)와 함께 사용되어 그룹의 특성을 기준으로 필터링합니다.

정리된 이해#

WHERE 절은 GROUP BY를 수행하기 전에 개별 행을 필터링하는 데 사용되는 반면, HAVING 절은 GROUP BY를 통해 그룹화된 결과에 대한 조건을 설정하는 데 사용돼요. 즉, WHERE는 행을 필터링하고, HAVING은 그룹화된 결과를 필터링하는 역할을 한다는 점이 중요한 차이점이에요.

3. SQL 기본 구조#

왜 이걸 보게 됐나#

GROUP BY와 HAVING을 사용하면서 쿼리가 제대로 실행되지 않아 문제 해결에 어려움을 겪었기 때문에 SQL의 기본적인 구조를 다시 한번 확인하게 됐어. 특히 ORDER BY와 WHERE, HAVING 문의 정확한 사용 위치를 이해해야 효율적인 쿼리를 작성할 수 있다는 점을 깨달았지. 앞으로는 쿼리를 작성할 때 전체적인 구조를 염두에 두고, 각 문의 역할을 명확히 파악해야겠어.

내가 헷갈린 지점#

처음에는 GROUP BY 문 뒤에 DESC를 바로 써도 될 거라고 생각했는데, 정렬은 ORDER BY 문을 통해서만 가능하다는 점을 몰랐습니다. 또한, WHERE 절과 HAVING 절의 차이점을 명확하게 이해하지 못해 어떤 조건에 어떤 절을 사용해야 하는지 헷갈렸습니다.

시도한 코드 / 예시#

SELECT MediaTypeId, COUNT(*) AS track_count
FROM tracks
GROUP BY MediaTypeId
ORDER BY track_count DESC;

결과와 해석#

SQL 쿼리의 기본적인 틀은 데이터를 선택(SELECT), 가져올 테이블 지정(FROM), 그룹화(GROUP BY), 조건 필터링(HAVING), 정렬(ORDER BY) 순으로 구성됩니다. GROUP BY는 특정 컬럼을 기준으로 데이터를 묶어주는 역할을 하며, ORDER BY는 결과를 원하는 순서대로 정렬하는 데 사용됩니다. 위의 예제는 미디어 타입별 트랙 수를 계산하고, 트랙 수가 많은 순서대로 정렬하여 보여주는 쿼리입니다.

정리된 이해#

SQL 쿼리는 데이터를 가져올 테이블과 보여줄 컬럼을 정하고, GROUP BY를 통해 데이터를 묶어 통계 값을 계산할 수 있다. HAVING 절은 GROUP BY로 묶인 데이터에 대한 조건을 설정하며, ORDER BY는 최종 결과의 정렬 순서를 지정한다.

4. 데이터 정렬#

왜 이걸 보게 됐나#

데이터를 단순히 나열하는 것만으로는 필요한 정보를 얻기 어려워서, 특정 기준에 따라 데이터를 정렬하는 방법을 배우게 되었어. 문제 해결 과정에서, 단순히 숫자나 알파벳 순서로 정렬하는 것 이상의 복잡한 조건에 맞춰 결과를 보여줘야 할 필요성을 느꼈거든. 효율적인 데이터 분석을 위해 데이터 정렬이 필수적인 도구라는 것을 깨달았어.

내가 헷갈린 지점#

처음에는 GROUP BY 문 뒤에 DESC와 같은 정렬 지시어를 붙일 수 있다고 생각했어요. GROUP BY가 데이터 묶음을 만드는 과정이라고 생각했는데, 그 묶음 자체를 바로 정렬할 수 있다고 오해했죠. 결국 ORDER BY 문이 정렬을 담당한다는 것을 명확히 이해하게 되었습니다.

시도한 코드 / 예시#

SELECT MediaTypeId, COUNT(*) AS track_count
FROM tracks
GROUP BY MediaTypeId
ORDER BY track_count DESC;  -- ORDER BY 적용

결과와 해석#

ORDER BY를 GROUP BY 뒤에 위치시키는 오류를 통해 데이터 정렬은 GROUP BY가 끝난 후, 즉 그룹화된 결과에 대해 적용되어야 함을 알게 되었다. 미디어 타입별 트랙 수를 확인할 때 ORDER BY track_count DESC를 사용하면 각 미디어 타입의 트랙 수를 내림차순으로 정렬하여, 가장 많은 트랙 수를 가진 미디어 타입부터 확인할 수 있다. 이렇게 정렬을 통해 데이터의 흐름을 파악하고 중요한 정보에 집중하는 데 도움이 된다.

정리된 이해#

데이터 정렬은 ORDER BY 절을 사용하여 결과를 특정 컬럼 기준으로 오름차순 또는 내림차순으로 배열하는 것을 의미한다. DESC 키워드를 사용하여 내림차순 정렬을 할 수 있으며, ORDER BY는 일반적으로 쿼리의 마지막 부분에 위치한다. 정렬은 분석 결과나 보고서를 만들 때 중요한 역할을 한다.

총평#

오늘 전체에서 배운 것#

GROUP BY는 데이터를 묶어주는 역할이고, HAVING은 묶인 데이터에 대한 조건을 설정하는 역할을 한다는 것을 알게 되었다. WHERE는 원본 데이터를 필터링하고, HAVING은 GROUP BY로 묶인 결과에 대한 필터링을 수행한다는 점을 명확히 이해했다.

다음에 조심할 것#

ORDER BY 위치를 헷갈리지 않도록 ORDER BY는 항상 GROUP BY 뒤에 위치해야 한다는 점을 기억해야겠다. 쿼리 문제를 풀 때 요구하는 조건을 명확히 이해하고, WHERE와 HAVING의 차이를 확실히 구분해서 사용해야 한다.

다음 복습 주제#

HAVING절을 사용하여 그룹별 조건 필터링하는 다양한 예제를 더 풀어보고, 서브쿼리와 함께 GROUP BY와 HAVING을 활용하는 복잡한 쿼리에 대한 이해도를 높여야겠다. 또한, 성능 최적화 관점에서 GROUP BY 절 사용 시 주의사항을 찾아봐야겠다.
