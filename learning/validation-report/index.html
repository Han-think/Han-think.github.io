1. 라이브러리 생태계#

왜 이걸 보게 됐나#

프로젝트를 진행하면서 필요한 기능들을 직접 구현하기보다는 이미 만들어진 도구를 활용하는 게 효율적이라는 것을 깨달았기 때문입니다. 하지만 다양한 라이브러리가 존재하고 각자의 특징이 달라, 어떤 것을 선택해야 할지 혼란스러웠고, 결국 프로젝트의 성공을 위해 적절한 생태계를 선택하는 기준을 익혀야 했습니다.

내가 헷갈린 지점#

라이브러리 생태계가 너무 광범위해서, 어떤 기준으로 프레임워크를 골라야 할지 감이 잡히지 않았어. 특히 비슷한 기능을 하는 라이브러리들의 차이점을 명확하게 구분하기 어려웠고, 어떤 상황에 어떤 도구를 써야 할지 기준이 불분명했어. 단순히 설치법이나 사용법을 배우는 것보다, 프로젝트의 목적에 맞춰 적절한 도구를 선택하는 기준을 이해하는 것이 중요했던 것 같아.

시도한 코드 / 예시#

# 목표: 간단한 데이터 시각화 웹 애플리케이션 개발
# 선택: Streamlit (PN_2026-06-04_11_streamlit_to

결과와 해석#

간단한 데이터 시각화 웹 애플리케이션을 만들기 위해 Streamlit을 선택했는데, import streamlit as st 구문을 사용해 스트림릿 API를 활용하는 방법을 익혔습니다. 스트림릿을 사용하면 코딩 지식이 부족한 사람도 쉽게 웹 앱을 만들 수 있다는 것을 알게 되었고, 이를 통해 데이터 분석 결과를 빠르게 공유하는 데 도움이 될 것 같습니다. 실제로 몇 가지 간단한 차트와 테이블을 만들어서 웹 페이지에 표시하는 실습을 진행하며 스트림릿의 사용법을 익혔습니다.

정리된 이해#

프로젝트의 목표와 요구사항에 따라 적절한 라이브러리 생태계를 선택하는 것이 가장 중요하며, 이는 데이터 분석, 웹 애플리케이션 개발 등 프로젝트의 성격에 따라 달라집니다. 프로젝트별 의존성 관리를 위해 가상 환경을 사용하고, requirements.txt 파일을 통해 의존성을 기록하여 코드 공유 및 재현성을 확보해야 합니다. 효율적인 코드 작성을 위해서는 라이브러리의 API를 이해하고 import 구문을 적절하게 활용하는 것이 필요합니다.

2. 가상 환경#

왜 이걸 보게 됐나#

프로젝트를 진행하면서 여러 라이브러리를 사용하게 되는데, 각 라이브러리의 버전이 서로 충돌할 수 있다는 사실을 알게 되면서 가상 환경의 필요성을 느꼈어. 가상 환경을 사용하면 프로젝트별로 독립된 환경을 만들 수 있어서, 라이브러리 버전 충돌 문제를 해결하고 프로젝트의 안정성을 높일 수 있다는 것을 알게 되었지. 덕분에 이제는 프로젝트마다 깔끔하게 의존성을 관리할 수 있게 됐어.

내가 헷갈린 지점#

처음에는 가상 환경이 단순히 패키지 버전을 관리하는 공간이라고 생각했어요. 그래서 왜 프로젝트마다 환경을 따로 만들어야 하는지, 그냥 전역적으로 설치하면 안 되는 걸까 하는 의문이 들었죠. 또한, 가상 환경을 만들고 활성화하는 과정이 복잡하게 느껴졌습니다.

시도한 코드 / 예시#

# 실제 값: python3 -m venv .venv

결과와 해석#

가상 환경을 만들고 활성화하는 과정은 프로젝트마다 다른 버전의 라이브러리를 사용해야 할 때, 시스템 환경에 영향을 주지 않고 독립적으로 관리할 수 있게 해 줍니다. venv 모듈을 사용해 프로젝트 폴더 내에 격리된 환경을 만들고, pip install 명령어로 필요한 패키지를 설치하여 환경을 구성했습니다. 이 과정을 통해 프로젝트별로 필요한 특정 버전의 라이브러리를 자유롭게 사용할 수 있으며, 다른 프로젝트에 영향을 주지 않고 안전하게 작업할 수 있습니다.

정리된 이해#

가상 환경은 프로젝트마다 필요한 라이브러리 버전을 독립적으로 관리할 수 있도록 해주는 필수적인 도구입니다. 이를 통해 각 프로젝트의 의존성 충돌을 방지하고, 환경 설정을 쉽게 할 수 있으며, 다른 환경에서도 동일한 결과를 얻을 수 있도록 보장합니다. 간단히 말해, 프로젝트별로 샌드박스 환경을 제공하는 것이라고 이해하면 됩니다.

3. 의존성 관리#

왜 이걸 보게 됐나#

프로젝트를 진행하다 보면 필요한 라이브러리가 정말 많다는 걸 깨달았어. 각자 버전 요구사항도 다르고, 여러 프로젝트를 병행하면 라이브러리 버전 충돌이 일어날 수 있다는 사실에 당황했지. 그래서 프로젝트마다 깔끔하게 라이브러리 환경을 분리하고 관리하는 ‘의존성 관리’ 개념을 배우게 됐어.

내가 헷갈린 지점#

처음에는 프로젝트마다 필요한 라이브러리를 개별적으로 설치하면 되는 줄 알았어요. 그래서 라이브러리 버전 충돌이나 다른 프로젝트에 미치는 영향 같은 부분을 고려하지 못했고, ‘의존성 관리’라는 개념이 왜 필요했는지 제대로 이해하지 못했습니다. virtual environment를 사용하는 이유를 단순히 ‘환경을 분리하는 것’ 정도로만 생각했어요.

시도한 코드 / 예시#

# 예시: virtual environment 생성 및 활성화 (PN_2026-06-04_08_virtual_environment_dependency_survival.md 참고)
# python3 -m venv .venv
# source .venv/bin/activate  # Linux/macOS
# .venv\Scripts\activate  # Windows

결과와 해석#

가상 환경을 만들고 pip install streamlit 명령으로 스트림릿을 설치하는 과정을 통해 프로젝트별 독립적인 환경에서 필요한 라이브러리를 관리하는 것이 중요하다는 것을 체감했습니다. requirements.txt 파일에 스트림릿을 기록하여 다른 환경에서도 동일한 의존성을 쉽게 재현할 수 있게 되었고, 이는 협업 과정에서 큰 도움이 될 것 같습니다. 이후 간단한 스트림릿 코드를 실행하며 라이브러리 API를 활용하는 방법을 익혔습니다.

정리된 이해#

프로젝트별로 독립적인 환경을 virtual environment를 통해 설정하고, 필요한 라이브러리들을 requirements.txt 파일에 기록하여 의존성을 관리하는 것이 중요합니다. 이렇게 하면 팀원 간 코드 공유 및 배포가 용이해지고, 프로젝트 환경의 일관성을 유지할 수 있습니다.

4. 라이브러리 API#

왜 이걸 보게 됐나#

프로젝트를 진행하면서 필요한 기능을 직접 구현하는 것보다 이미 검증된 라이브러리를 사용하는 것이 효율적이라는 것을 깨달았어요. 하지만 라이브러리를 제대로 활용하려면 단순히 설치하는 것 이상으로, 그 안의 API들이 어떻게 작동하는지, 어떤 방식으로 기능을 제공하는지를 이해해야 프로젝트에 자연스럽게 적용할 수 있었습니다.

내가 헷갈린 지점#

처음에는 라이브러리 API가 단순히 함수 목록이라고 생각했는데, 실제로는 클래스, 메서드, 속성 등 다양한 요소들이 상호 작용하며 특정 기능을 수행하는 전체 시스템이라는 것을 알게 되었다. API 레퍼런스를 보면서 기능들을 연결하여 사용해야 한다는 것을 깨달았고, 단순히 함수를 호출하는 것 이상으로 라이브러리의 내부 동작을 이해하는 것도 중요하다는 것을 느꼈다.

시도한 코드 / 예시#

# 예시: Streamlit을 사용하여 간단한 차트 표시
# import streamlit as st
#
# st.title("My First Streamlit App")
#
# data = [1, 3, 2, 1, 2]
# st.line_chart(data)

결과와 해석#

라이브러리 API를 활용하는 실습에서, 특정 함수를 as 키워드로 별칭을 부여하여 사용할 수 있다는 것을 알게 되었다. 예를 들어 pandas.DataFrame을 pd.DataFrame으로 줄여서 사용할 수 있는데, 코드의 가독성을 높이고 반복되는 코드를 줄이는 데 도움이 된다. 또한, API 레퍼런스를 통해 제공되는 다양한 파라미터와 반환 값을 이해하고 활용하여, 원하는 결과를 얻을 수 있었다.

정리된 이해#

라이브러리 API는 특정 라이브러리가 제공하는 함수, 클래스, 변수 등을 활용하여 코드를 작성하는 방법을 의미합니다. 이를 통해 복잡한 기능을 간단하게 구현하고, 코드의 재사용성을 높일 수 있습니다. 효율적인 코드 작성을 위해서는 라이브러리 API를 잘 이해하고, 프로젝트 목표에 맞게 적절히 활용하는 것이 중요합니다.

총평#

오늘 전체에서 배운 것#

프로젝트 목표에 따라 적합한 라이브러리 생태계를 선택하는 것이 중요하며, 가상 환경을 활용해 의존성을 관리하고 requirements.txt 파일로 명확하게 기록해야 한다. 또한, import 구문과 라이브러리 API를 효과적으로 활용하여 코드 구현의 효율성을 높일 수 있다.

다음에 조심할 것#

다음 번에는 라이브러리 선택 시 단순히 기능 비교뿐 아니라, 커뮤니티 지원, 문서화 수준, 유지보수 현황 등을 함께 고려해야겠다. requirements.txt 파일 생성 및 관리 자동화 방법을 찾아 효율성을 높여야겠다. 아직 프로젝트 연동 과정에서 발생할 수 있는 에러에 대한 문제 해결 능력이 부족하다고 느껴서, 예외 처리 및 디버깅에 더 집중해야겠다.

다음 복습 주제#

Streamlit의 좀 더 고급 기능과 다양한 시각화 라이브러리 연동 방법을 익혀야겠다. Flask나 Django와 같은 풀 스택 프레임워크를 사용한 웹 애플리케이션 개발 경험도 쌓아야 프로젝트 적용 범위를 넓힐 수 있을 것 같다.
