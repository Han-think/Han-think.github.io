1. DOM 이벤트 전파 완벽 해설: 캡처링, 타겟, 버블링 완벽 이해#

무엇을 배웠나#

DOM 이벤트 전파 과정에서 여러 로그가 출력되는 이유가 클릭 이벤트 자체가 단일하며, 이벤트가 DOM 트리를 따라 버블링되면서 각 요소의 이벤트 리스너가 실행되기 때문이라는 것을 알게 되었다. 특히 캡처링, 타겟, 버블링 단계를 이해하면서 이벤트 전파의 전체적인 흐름을 파악할 수 있었고, 단순히 역류처럼 느껴졌던 버블링 또한 정상적인 이벤트 처리 과정임을 이해하게 되었다. 이제는 여러 요소에 이벤트 리스너를 등록하더라도 이벤트가 중복 실행되는 문제를 해결할 수 있을 것 같다.

헷갈렸던 점#

버튼 클릭 시 여러 로그가 찍히는 걸 보고 하나의 클릭으로 여러 이벤트가 발생하는 줄 알았습니다. 특히 이벤트가 상위 요소로 올라가는 버블링 과정이 마치 오류처럼 느껴졌습니다. 이벤트 전파가 복잡하고 이해하기 어려워서 이벤트가 어떻게 동작하는지 명확히 파악하지 못하고 있었습니다.

정리된 이해#

버튼 클릭 같은 이벤트는 실제로 한 번 발생하지만, DOM 트리를 따라 여러 요소의 이벤트 리스너가 동작하면서 여러 로그가 출력되는 것처럼 보이는 거야. 이벤트는 캡처링, 타겟, 버블링 단계를 거치며 전파되는데, 버블링은 이벤트가 상위 요소로 다시 올라가는 정상적인 과정이고, 각 요소는 자신에게 할당된 이벤트 리스너를 실행하는 거야.

      console.log('버튼 클릭', event.target); // 버튼 클릭 시 이벤트 로그
  });

  // 부모 요소에도 이벤트 리스너 등록

      console.log('parent_1 로그', event.target); // 버블링 단계에서 로그 출력
  });

2. 이벤트 제어: 전파 중단과 기본 동작 방지#

무엇을 배웠나#

이벤트 제어에서 stopPropagation()은 이벤트 전파를 막고, preventDefault()는 브라우저의 기본 동작을 막는다는 것을 명확히 알게 되었다. 두 메서드의 “멈춤"이라는 표현 때문에 혼동했던 부분이 정리되었고, 각각의 역할과 사용 시나리오를 이해하게 되었다. 이제 event.defaultPrevented 속성과 메서드 혼동 없이 정확히 구분하여 사용할 수 있을 것 같다.

헷갈렸던 점#

이벤트 제어에서 stopPropagation와 preventDefault의 역할이 비슷해 보여 혼동되었고, 특히 event.defaultPrevented 속성을 메서드로 착각하여 이해하는데 어려움이 있었습니다. 두 메서드 모두 “멈춤"이라는 의미를 가지고 있어 더욱 헷갈렸습니다. 기본적인 작동 방식에 대한 이해가 부족하여, 실제 코드 작성 시 어떤 상황에 어떤 메서드를 사용해야 할지 막막했습니다.

정리된 이해#

stopPropagation()은 이벤트가 부모 요소로 전파되는 것을 막아, 이벤트 핸들러 체인을 끊는 역할을 합니다. 반면 preventDefault()는 브라우저의 기본 동작, 예를 들어 폼 제출 시 페이지 리프레시를 막는 역할을 합니다. event.defaultPrevented는 preventDefault()가 호출되었는지 여부를 확인하는 속성이지 메서드가 아닙니다.

function handleClick(event) {
    event.stopPropagation(); // 클릭 이벤트가 상위 요소로 전파되지 않음
    alert('클릭 이벤트 처리 중입니다.');
}

3. DOM 스크롤 제어: scrollTo와 scrollIntoView 활용#

무엇을 배웠나#

DOM 스크롤 제어에서 scrollTo 함수는 window.scrollTo()를 통해 부드럽게 스크롤 위치를 변경한다는 것을 알게 되었습니다. 또한, scrollIntoView()는 특정 요소를 화면에 보이도록 이동시키는 데 사용된다는 것을 이해했습니다. 함수 호출 시점 오해와 코드 목적과의 연결 부족이 있었지만, 정리된 설명을 통해 명확하게 이해할 수 있었습니다.

헷갈렸던 점#

scrollUp 함수 호출이 즉시 화면 이동으로 이어질 것이라고 생각했고, 강사의 시연 코드에서 보여지는 동작의 의도를 파악하기 어려웠습니다. 버튼 클릭 이벤트를 통해 window.scrollTo가 실행되어 화면이 이동하는 원리를 정확히 이해하지 못했습니다.

정리된 이해#

scrollUp 함수는 버튼 클릭 시 window.scrollTo를 통해 부드럽게 화면을 최상단으로 이동시키는 역할을 하며, 함수 호출은 초기화 단계일 뿐 실제 스크롤은 클릭 시에 발생합니다. scrollIntoView는 특정 DOM 요소를 화면에 보이도록 이동시키는 데 사용되는 함수입니다. 강의 시연 코드는 함수 작동 방식을 보여주기 위한 예시이며, 코드의 목적과 실제 동작 시점 사이의 혼동을 최소화해야 합니다.

function scrollUp(id) {
    var target = document.getElementById(id);

    target.addEventListener("click", function () {
        window.scrollTo({
            top: 0,
            left: 0,
            behavior: "smooth"
        });
    });
}

4. 폼 제출과 입력값 검증: 초보자를 위한 워킹 노트#

무엇을 배웠나#

폼 제출 처리와 입력값 검증 과정에서 요소의 반복 참조를 피하고, textContent를 사용하는 것이 innerHTML보다 안전하다는 점을 알게 되었습니다. 코드를 변수에 저장하여 가독성을 높이고, textContent를 사용해 안전하게 텍스트를 출력하는 방법을 익혔습니다. 앞으로는 코드의 효율성과 보안을 고려하여 폼 제출 처리 코드를 작성할 수 있을 것 같습니다.

헷갈렸던 점#

원래 코드는 같은 요소를 계속 찾아서 불편했고, innerHTML과 textContent가 언제 어떻게 써야 할지 명확하지 않았습니다. 요소 변수에 저장하는 방법을 알게 되어서 코드가 훨씬 깔끔해졌고, textContent가 더 안전하다는 점도 기억해두겠습니다.

정리된 이해#

폼 제출 시 요소 ID를 반복적으로 찾는 대신, 요소를 변수에 저장하여 코드를 간결하게 만들 수 있습니다. 또한 보안을 위해 단순 텍스트를 화면에 표시할 때는 innerHTML 대신 textContent를 사용하는 것이 좋습니다. 이 두 가지 방법을 통해 코드의 가독성을 높이고 잠재적인 보안 문제를 예방할 수 있습니다.

5. 출석부 실습: 초보자를 위한 코드 위치 및 요소 역할 정리#

무엇을 배웠나#

자바스크립트 코드를 HTML 파일 내 <script> 태그 안에 직접 넣는 방법과 별도의 .js 파일을 연결하는 방법의 차이점을 이해하게 되었습니다. 또한, 트리거 요소, 입력 요소, 출력 영역의 역할 분담을 명확히 하고, 코드와의 연결 고리를 빠르게 파악하는 연습이 필요하다는 것을 알게 되었습니다. 앞으로는 코드를 좀 더 체계적으로 관리하고 유지보수하는 방향으로 학습해야겠습니다.

헷갈렸던 점#

코드를 HTML 파일 내에 직접 넣을지, 아니면 별도의 파일로 분리해서 연결할지에 대한 선택 기준이 명확하지 않았습니다. 또한, HTML 구조 안에서 특정 버튼이나 입력창과 같은 요소들을 찾아서 코드로 연결하는 과정이 어렵게 느껴졌습니다. 어떤 요소가 어떤 역할을 하는지 빠르게 파악하는 데 어려움을 겪었습니다.

정리된 이해#

자바스크립트 코드를 HTML에 직접 넣든, 별도의 .js 파일로 관리하든 기능은 동일하지만, 코드가 복잡해질수록 파일 분리가 유지보수에 더 유리하다는 것을 알게 되었다. 버튼, 입력창, 출력 영역과 같은 HTML 요소들의 역할을 명확히 구분하고, 이들이 어떻게 상호작용하는지 이해하는 것이 실습의 핵심이라는 것도 깨달았다.

  <!-- HTML 파일 내에 직접 삽입 -->
  <script>
    const target = document.querySelector(".attend");
    const inputName = document.querySelector("input[name='name']");
    const attendee = document.getElementById("attendee");

    function attend() {
        const name = inputName.value;
        if (name) {
            attendee.innerHTML += name + "<br>";
            inputName.value = "";
        } else {
            alert("이름을 입력해 주세요!");
        }
    }

    target.addEventListener("click", attend);
  </script>

  <!-- 또는 별도의 JavaScript 파일 연결 -->
  <script src="index.js"></script>
