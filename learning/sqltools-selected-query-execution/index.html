1. SQL 기본 명령어#

왜 이걸 보게 됐나#

개인 학습 기록을 효율적으로 관리하고 싶어서, 데이터베이스를 활용하는 방법을 익히기로 했어. 간단한 SQL 명령어를 통해 노트를 저장하고 조회하는 기능을 구현하면, 훨씬 체계적으로 학습 내용을 정리하고 복습할 수 있을 것 같아. 앞으로 LearningLog 시스템 구축에 이 기본 명령어들이 필수적으로 사용될 예정이라, 지금부터 확실히 다져놓아야 해.

내가 헷갈린 지점#

처음에는 SQL 문법 오류가 나서 실행이 안 될 때마다 문법에 문제가 있다고 생각했는데, 테이블이 생성되지 않은 상태에서 바로 조회하려고 해서 오류가 났던 것 같아. 그리고 전체 파일을 다 실행해야 한다고 생각해서, 필요한 부분만 선택해서 실행할 수 있다는 점이 신기했다. 명령어를 순서대로 실행해야 한다는 점을 명확하게 인지하지 못해서 삽질을 했던 것 같아.

시도한 코드 / 예시#

-- 테이블 생성
CREATE TABLE IF NOT EXISTS study_notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    category TEXT NOT NULL
);

-- 데이터 삽입
INSERT INTO study_notes (title, category) VALUES ('SQL Basics', 'database');

-- 선택 영역 실행: 특정 쿼리만 실행
SELECT * FROM study_notes WHERE title = 'SQL Basics';

결과와 해석#

CREATE TABLE 명령어로 study_notes 테이블을 만들고, INSERT 명령어로 학습 관련 데이터를 삽입했습니다. SELECT 문을 사용해 테이블에 삽입한 데이터를 조회하면서, 명령어가 순서대로 실행되어야 원하는 결과를 얻을 수 있다는 것을 확인했습니다. 이처럼 테이블 생성, 데이터 삽입, 조회 과정을 거치면서 SQL 기본 명령어의 작동 방식을 좀 더 명확하게 이해하게 되었습니다.

정리된 이해#

SQL 기본 명령어는 순서대로 실행해야 하며, 테이블 생성 후 데이터 삽입, 그리고 조회를 하는 것이 일반적인 흐름입니다. SQLTools의 선택 영역 실행 기능을 활용하면 전체 코드를 실행하지 않고 필요한 부분만 빠르게 테스트할 수 있어서 편리합니다. SELECT, INSERT, CREATE TABLE 등의 명령어의 역할을 이해하는 것이 중요합니다.

2. 선택 영역 실행#

왜 이걸 보게 됐나#

처음에는 SQL 코드를 실행할 때 전체 파일을 한 번에 돌려야 해서, 작은 실수 하나에도 전체 코드가 멈추는 경우가 많았어. 그래서 특정 부분만 빠르게 테스트하고 싶어서 ‘선택 영역 실행’ 기능을 배우게 됐고, 이제는 오류가 발생해도 전체 코드를 다시 실행하지 않고 문제 부분을 집중적으로 수정할 수 있게 됐어.

내가 헷갈린 지점#

처음에는 SQL 문장이 오류 없이 실행될 때만 원하는 결과를 얻는다고 생각해서, 특정 쿼리만 실행했을 때 제대로 작동하지 않으면 항상 문법 오류를 범하는 줄 알았습니다. 전체 코드를 다 실행해야만 원하는 결과가 나올 거라고 생각하니, 부분적으로 실행하는 기능이 있다는 것을 이해하는 데 시간이 걸렸습니다. SQLTools의 선택 영역 실행 기능이 있다는 것을 알게 된 후에는 이제 더 효율적으로 작업할 수 있게 되었습니다.

시도한 코드 / 예시#

  -- 테이블 생성
  CREATE TABLE IF NOT EXISTS study_notes (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      title TEXT NOT NULL,
      category TEXT NOT NULL
  );

  -- 데이터 삽입
  INSERT INTO study_notes (title, category) VALUES ('SQL Basics', 'database');

  -- 선택 영역 실행: 특정 쿼리만 실행
  SELECT * FROM study_notes WHERE title = 'SQL Basics';

결과와 해석#

SQLTools에서 코드 전체가 아닌 내가 선택한 부분만 실행할 수 있다는 것을 알게 되었는데, 특히 테이블 생성 후 데이터를 삽입하고 그 다음에 조회하는 과정을 짧게 테스트할 때 매우 유용했어요. 특정 쿼리가 제대로 작동하는지 빠르게 확인하고, 잘못된 부분을 바로 수정할 수 있어서 전체 코드를 다시 실행하는 것보다 훨씬 효율적입니다.

정리된 이해#

VS Code의 SQLTools에서 필요한 쿼리만 선택해서 실행할 수 있다는 것을 알게 되었고, 전체 코드가 아니라 원하는 부분만 테스트할 수 있어서 편리하다. 이 기능을 활용하면 오류 발생 시 특정 영역만 집중적으로 확인하여 디버깅 시간을 줄일 수 있을 것 같다.

3. 실행 순서#

왜 이걸 보게 됐나#

처음에 SQL 문장이 제대로 작동하지 않아서 뭐가 문제인지 몰랐는데, CREATE TABLE부터 차례대로 실행해야 데이터가 정상적으로 생성되고 삽입되어 조회할 수 있다는 걸 알게 됐어. 테이블을 만들고 데이터를 넣은 후에나 제대로 결과를 확인할 수 있다는 걸 배우게 되면서 SQL 문장의 실행 순서가 중요하다는 걸 깨달았어.

내가 헷갈린 지점#

처음에는 SQL 문장들이 그냥 실행되는 줄 알았어요. 테이블을 만들지 않고 바로 데이터를 조회하거나, 데이터 삽입 전에 테이블이 있어야 하는지조차 몰랐습니다. 그래서 문법 오류인 줄 알고 계속 쿼리를 수정했지만, 실제로는 실행 순서가 잘못된 문제였어요.

시도한 코드 / 예시#

-- 테이블 생성
CREATE TABLE IF NOT EXISTS study_notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    category TEXT NOT NULL
);

-- 데이터 삽입
INSERT INTO study_notes (title, category) VALUES ('SQL Basics', 'database');

-- 선택 영역 실행: 특정 쿼리만 실행
SELECT * FROM study_notes WHERE title = 'SQL Basics';

결과와 해석#

테이블을 먼저 만들고 데이터를 넣어야 SELECT 명령어로 데이터를 가져올 수 있었어. CREATE TABLE로 테이블을 만들고 INSERT로 데이터를 넣은 다음에 SELECT를 실행했더니 데이터가 제대로 나왔고, 순서대로 실행해야 결과가 나오는구나를 깨달았어. 특히 SQLTools의 선택 영역 실행 기능과 함께 명령 순서가 중요함을 알게 되었어.

정리된 이해#

SQL 문장은 순서대로 실행되어야 하는데, 테이블을 먼저 만들고 데이터를 삽입한 후에 조회하는 과정을 거쳐야 원하는 결과를 얻을 수 있다는 것을 알게 되었습니다. 이전에는 명령들의 연결 순서를 고려하지 않고 바로 조회하려고 해서 오류가 자주 발생했던 점이 아쉬웠습니다. 이제는 필요한 부분만 선택해서 실행하는 기능과 함께 명령 순서를 잘 지켜서 코드를 작성해야겠다는 생각을 했습니다.

4. 데이터베이스 활용#

왜 이걸 보게 됐나#

학습 로그를 체계적으로 관리하고, 학습 내용을 효율적으로 추적하기 위해 데이터베이스를 활용하게 되었어. 단순히 텍스트 파일에 내용을 적는 것보다 구조화된 형태로 저장하고 검색할 수 있도록 만들고 싶었지. 앞으로는 프로젝트 기반으로 학습 내용을 저장하고 연결하여 학습 효과를 극대화할 수 있을 것 같아.

내가 헷갈린 지점#

처음에는 SQL 쿼리를 작성했는데도 결과가 바로 나오지 않거나 에러가 발생하는 상황을 이해하지 못해서, 뭔가 복잡한 연결고리가 필요한 줄 알았습니다. 테이블을 만들고 데이터를 넣었는데 바로 조회하는 과정이 제대로 작동하지 않아서, 데이터베이스가 뭔가 특별한 단계를 거쳐야 하는 건가 싶었습니다. 그리고 특정 영역만 실행하는 기능이 있다는 걸 몰라서 전체 파일을 항상 실행해야 하는 줄 생각했습니다.

시도한 코드 / 예시#

-- 테이블 생성
CREATE TABLE IF NOT EXISTS study_notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    category TEXT NOT NULL
);

-- 데이터 삽입
INSERT INTO study_notes (title, category) VALUES ('SQL Basics', 'database');

-- 선택 영역 실행: 특정 쿼리만 실행
SELECT * FROM study_notes WHERE title = 'SQL Basics';

결과와 해석#

LearningLog 시스템에서 학습 노트를 관리하기 위해 SQLite 데이터베이스를 사용해서 테이블을 만들고 데이터를 삽입하여 조회하는 실습을 해봤다. CREATE TABLE, INSERT, SELECT 명령어를 순서대로 실행해야 원하는 결과를 얻을 수 있다는 것을 깨달았고, VS Code의 SQLTools에서 선택 영역 실행 기능을 활용하면 효율적으로 코드를 테스트할 수 있었다. 이를 통해 LearningLog 시스템의 데이터 저장 및 관리에 대한 기초적인 코드를 구현할 수 있을 것 같다.

정리된 이해#

데이터베이스를 활용하면 학습 로그 시스템처럼 사용자 데이터를 체계적으로 관리할 수 있다는 것을 알게 되었다. 테이블 생성, 데이터 삽입, 조회 순서대로 명령어를 실행해야 하며, VS Code의 SQLTools에서 선택 영역 실행 기능을 활용하면 효율적으로 작업할 수 있다.

총평#

오늘 전체에서 배운 것#

SQL 기본 명령어와 SQLite 연결 감각을 익히면서 SQLTools의 선택 영역 실행 기능이 얼마나 효율적인지 알게 되었어요. 테이블 생성, 데이터 삽입, 조회 순서대로 실행해야 한다는 점을 명확히 이해했습니다.

다음에 조심할 것#

SELECT, INSERT, CREATE TABLE 명령어 실행 순서를 항상 지켜야 오류 없이 결과값을 확인할 수 있겠다. SQLTools에서 선택 영역 실행 기능을 더 적극적으로 활용해서, 코드 전체를 실행하지 않고 필요한 부분만 테스트해야겠다.

다음 복습 주제#

SQLite에서 좀 더 복잡한 쿼리(JOIN, GROUP BY 등)를 활용하여 데이터를 분석하는 방법을 익혀야겠다. 에러 메시지를 좀 더 정확하게 해석하고 디버깅하는 능력을 키우고 싶다.
