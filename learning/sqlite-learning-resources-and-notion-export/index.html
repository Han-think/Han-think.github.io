1. SQLite 샘플 DB#

왜 이걸 보게 됐나#

SQLite는 데이터베이스 기초를 다지는 데 유용하고, 샘플 데이터베이스는 실제 환경에서의 복잡성을 줄여 학습 진도를 높이는 데 도움을 줘요. 특히 Chinook 샘플 데이터베이스는 다양한 테이블과 관계를 포함하고 있어, 실제 데이터베이스 설계 및 쿼리 작성 연습에 적합합니다. 이를 통해 SQLite를 활용한 데이터베이스 작업의 기본 원리를 익히고, 실무 적용 가능성을 높일 수 있습니다.

내가 헷갈린 지점#

처음에는 샘플 데이터베이스가 실제 데이터베이스 서버를 설치해야 하는 것 아닌가 생각했어요. Chinook 데이터베이스를 예시로 제시할 때, 그냥 단순한 데이터 파일이라고 생각했지, 어떤 목적으로 어떻게 활용해야 할지 감이 잘 안 잡혔습니다. 데이터베이스의 구성 요소와 테이블 간의 관계를 파악하는 데 시간이 좀 걸렸어요.

시도한 코드 / 예시#

-- 예시: Chinook 데이터베이스에서 모든 앨범 조회
SELECT * FROM albums;

결과와 해석#

Chinook 샘플 데이터베이스는 SQLite를 배우기 위한 훌륭한 자료로, 음반 가게의 판매 데이터를 담고 있어 쿼리 연습에 적합합니다. ERD를 통해 테이블 간의 관계를 파악하고, 이를 기반으로 다양한 SQL 쿼리를 작성해 데이터 분석 실력을 키울 수 있었습니다. 실제 데이터베이스처럼 테이블이 구성되어 있어, 실무적인 쿼리 작성 능력 향상에 도움이 됩니다.

정리된 이해#

SQLite 샘플 DB는 Chinook이라는 실제 데이터베이스를 모방하여 만든 예시 데이터베이스로, 데이터베이스 학습 및 실습에 유용하다. 이 샘플 DB를 통해 테이블 구조, 관계, SQL 쿼리 등을 익힐 수 있으며, ERD와 Crow’s Foot 표기법을 활용하여 시각적으로 데이터 구조를 파악하는 데 도움이 된다. 실습을 통해 SQLite를 익히고 활용하는 데 훌륭한 출발점이 될 것이다.

2. ERD (엔티티-관계 다이어그램)#

왜 이걸 보게 됐나#

데이터베이스 구조를 시각적으로 표현하는 ERD는 데이터 모델링의 핵심 도구이며, 실제 데이터베이스 설계 및 관리 과정에서 필수적인 이해를 돕습니다. 특히 SQLite를 배우면서 데이터베이스 테이블 간의 관계를 명확하게 파악하고, 쿼리 작성 시 효율적인 접근 방식을 결정하는데 도움이 됩니다. 이를 통해 복잡한 데이터 구조를 더욱 직관적으로 이해하고 활용할 수 있게 됩니다.

내가 헷갈린 지점#

처음 ERD를 봤을 때는 그림만 잔뜩 그려져 있어서 이게 뭘 의미하는지, 데이터베이스 구조와 어떤 관련이 있는지 전혀 감이 잡히지 않았어요. 테이블 간의 관계가 어떻게 표현되는 건지, 화살표는 무엇을 나타내는 건지 알 수 없어 당황스러웠습니다. 관계의 종류(1:1, 1:N, N:M)에 대한 설명이 부족해서 ERD가 단순한 그림이 아닌 데이터베이스 설계도를 나타내는 중요한 도구라는 것을 이해하는 데 시간이 좀 걸렸습니다.

시도한 코드 / 예시#

-- ERD (엔티티-관계 다이어그램) 예시 (가상)
-- 실제 데이터베이스 스키마는 Chinook 데이터베이스를 참고하십시오.
-- 이 예시는 설명을 위한 가상의 스키마입니다.

-- 테이블: Customers
-- Columns: CustomerID (PK), FirstName, LastName, City, Country

-- 테이블: Employees
-- Columns: EmployeeID (PK), FirstName, LastName, Title

-- 테이블: Albums
-- Columns: AlbumID (PK), Title, ArtistID

-- 테이블: Artists
-- Columns: ArtistID (PK), Name

-- 관계: Artists 1:N Albums (Artists.ArtistID -> Albums.ArtistID)
-- 관계: Albums 1:N Employees (Albums.ArtistID -> Employees.ArtistID)

결과와 해석#

엔티티-관계 다이어그램은 데이터베이스의 구조를 시각적으로 표현하는 그림인데, 테이블 간의 관계를 화살표로 연결해서 보여줘서 데이터 모델을 이해하는 데 도움을 줘. 강의에서는 Chinook 데이터베이스의 ERD를 통해 테이블 간의 연결 관계를 파악했고, 이를 통해 데이터베이스의 전체적인 구조를 좀 더 직관적으로 이해할 수 있었다. Crow’s Foot 표기법을 통해 관계의 종류(1:1, 1:N, M:N)를 구분할 수 있게 되었다.

정리된 이해#

ERD는 데이터베이스를 시각적으로 표현하는 다이어그램인데, 테이블 간의 관계를 파악하고 데이터 모델을 설계하는 데 도움을 줘요. 엔티티, 속성, 관계를 통해 데이터베이스 구조를 한눈에 보여주므로, 복잡한 데이터베이스를 이해하고 수정할 때 매우 유용하다고 생각해요. Crow’s Foot 표기법을 통해 관계의 종류를 명확히 나타내는 방식이 특히 인상 깊네요.

3. Notion 링크 접근#

왜 이걸 보게 됐나#

Notion 페이지를 자동화 도구로 가져오려고 할 때, 페이지가 제대로 열리지 않는 문제를 겪으면서 이 문제가 발생하게 되었습니다. 자동화된 워크플로우 구축을 위해 Notion 자료를 활용하려 했지만, JavaScript 기반의 페이지 로딩이나 워크스페이스 권한 등의 문제로 인해 직접적인 접근이 어려웠습니다. 이 문제를 해결하기 위해 다양한 접근 방식을 고려하며 ‘Notion 링크 접근’이라는 개념을 배우게 되었습니다.

내가 헷갈린 지점#

처음에는 Notion 페이지가 자동화 도구에서 열리지 않는 이유가 워크스페이스 권한 문제인 줄 알았는데, JavaScript 기반 페이지라서 렌더링이 제대로 안 되는 상황이었던 것 같다. 페이지 자체의 수출 기능도 불안정해서, 웹페이지를 제대로 가져오는 데 어려움을 겪었었어. 결국 PDF로 저장하는 수밖에 없었지만, 이 과정에서 자동화 도구의 한계와 Notion 페이지 구조에 대한 이해가 부족했다는 걸 깨달았어.

시도한 코드 / 예시#

# JavaScript 렌더링 기반 페이지로 자동화 도구 접근 제한
# Notion 워크스페이스 권한 설정 문제
# 자료 수출 제한
# 페이지 자체의 수출 불안정성

결과와 해석#

Notion 페이지를 자동화 도구로 불러오려 할 때 JavaScript 기반 렌더링 때문에 접근이 막히는 경우가 많았어. 워크스페이스 권한이나 페이지 자체의 불안정성도 영향을 미치는 것 같고, 이 때문에 PDF로 저장하거나 텍스트를 복사하는 방식으로 자료를 확보해야 했어. 앞으로는 자동화 전에 수동으로 자료를 PDF로 저장하거나 텍스트를 복사하는 것을 우선적으로 고려해야겠다.

정리된 이해#

Notion 페이지를 자동화 도구로 직접 접근하는 데 어려움이 있어, 콘텐츠를 텍스트로 복사하거나 PDF로 저장하는 방식으로 자료를 확보해야 할 것 같다. JavaScript 기반 페이지 구조나 워크스페이스 권한 설정 등으로 인해 자동화 도구는 페이지를 제대로 렌더링하지 못하는 경우가 많아 보인다.

4. PDF 저장#

왜 이걸 보게 됐나#

Notion 페이지를 자동화 도구로 가져오려 할 때 자꾸 문제가 생겨서, 자료를 효율적으로 확보할 수 있는 다른 방법을 찾아야 했어. 특히 Notion 페이지가 JavaScript로 렌더링되는 방식과 워크스페이스 권한 설정 때문에 자동화가 잘 안 되는 걸 확인하고, PDF로 저장하는 것이 가장 확실한 방법임을 알게 되었지. 이 방법 덕분에 중요한 자료들을 놓치지 않고 학습에 활용할 수 있게 됐어.

내가 헷갈린 지점#

처음에는 PDF로 저장하는 게 좀 번거롭고, 온라인 자료를 바로 활용할 수 없어서 비효율적이라고 생각했어요. 왜냐하면 웹 페이지를 다시 불러와서 내용을 확인해야 하는 과정이 필요할 것 같았거든요. 하지만 자동화 도구 접근 문제를 해결할 수 있는 현실적인 해결책이 필요해서, PDF로 저장하는 게 나름 괜찮은 선택일 수 있다는 생각이 들었어요.

시도한 코드 / 예시#

# PDF 저장: 웹 페이지 인쇄 후 PDF로 저장
# 예시: Chrome 브라우저에서 Ctrl + P (인쇄) 후 "대상으로 저장" 선택하여 PDF 파일 생성
# 파일 경로: C:\Ollama-IPEX\LearningLog\00_inbox\personal_notes\PN_2026-06-08_05_sqlite_learning_resources_and_notion_export.pdf

결과와 해석#

웹 페이지를 PDF로 저장하는 것은 자동화 도구 접근 문제 해결에 유용했다. 특히 JavaScript 기반의 Notion 페이지를 안정적으로 확보할 수 있어서, 이후 텍스트 추출 및 분석 과정에서 데이터 손실을 최소화할 수 있었다. 이 방법은 간단하지만, 이미지나 복잡한 레이아웃은 그대로 유지하면서 텍스트 정보를 보존하는데 효과적이었다.

정리된 이해#

자동화 도구를 통해 Notion 페이지에 직접 접근하는 데 제약이 있어, 웹 페이지를 PDF로 저장하는 것이 현재 가장 안정적인 자료 회수 방법임을 알게 되었다. 이렇게 저장된 PDF는 필요한 정보를 쉽게 추출하고 관리할 수 있도록 해준다. 앞으로는 PDF 저장 방식을 우선적으로 활용하여 Notion 자료를 확보할 계획이다.

총평#

오늘 전체에서 배운 것#

SQLite 샘플 데이터베이스와 ERD 개념을 공부하면서 Notion 페이지 접근에 어려움을 겪었지만, PDF 저장 방식을 통해 자료를 확보했습니다. 자동화 도구로 Notion 페이지를 직접 가져오는 데는 한계가 있어, 텍스트 복사나 PDF 저장 등의 우회적인 방법을 활용해야 할 것 같습니다.

다음에 조심할 것#

Notion 페이지를 자동화 도구로 가져올 때 JavaScript 렌더링, 워크스페이스 권한, 수출 제한 등의 문제가 발생할 수 있으므로, PDF 저장이나 텍스트 복사 등의 우회 방법을 미리 고려해야겠다. 특히 자동화 스크립트 작성 시 Notion 페이지 접근 방식에 대한 예외 처리를 추가하는 것을 잊지 말아야겠다.

다음 복습 주제#

Notion 페이지의 자동화 도구 접근 문제를 해결하기 위한 좀 더 근본적인 원인 파악과 해결 방안을 찾아봐야겠다. 특히 JavaScript 렌더링 기반 페이지에 대한 접근 전략을 고민하고, Notion API 활용 가능성도 검토해봐야 할 것 같다.
