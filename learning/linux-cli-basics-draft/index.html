리눅스 CLI 기초 — 내가 헷갈린 것들 정리

리눅스 터미널 기초 명령어를 배우며 헷갈렸던 부분과 교정된 이해를 기록합니다. > vs >>, ~ 의 정체, rm -r 위험성, 파이프 직관적 이해.
2026년 5월 28일 · 2 min

리눅스 터미널을 처음 배울 때 명령어 자체보다 왜 그렇게 작동하는지를 이해하는 게 더 어려웠다. 여기서는 내가 실제로 헷갈렸던 것들과 어떻게 이해하게 됐는지를 기록한다.

기본 명령어 — 외우는 게 아니라 이해하기#

처음에는 명령어 리스트를 무작정 외우려 했다. 그런데 ls, cd, pwd 정도는 자연스럽게 손에 익었고, 정작 헷갈렸던 건 리다이렉션과 파이프였다.

헷갈렸던 점 1 — > 와 >> 차이#

강의에서 둘 다 “파일에 저장"이라고 설명했는데, 처음엔 같은 기능이라고 생각했다.

교정된 이해:

기호 동작 비유
> 파일을 새로 만들거나 덮어씀 새 종이에 처음부터 씀
>> 기존 파일 뒤에 이어서 추가 같은 종이 아래쪽에 이어 씀 
echo "첫 번째" > memo.txt    # memo.txt 생성 (있으면 덮어씀)
echo "두 번째" >> memo.txt   # memo.txt 뒤에 이어 씀
cat memo.txt
# 출력:
# 첫 번째
# 두 번째

Python 으로 연결하면: open("file", "w") = >, open("file", "a") = >>

헷갈렸던 점 2 — ~ 는 변수인가 약칭인가#

cd ~ 를 쓸 때 ~ 가 정확히 무엇인지 몰랐다.

교정된 이해:

~ 는 틸다 확장(tilde expansion) 이라는 쉘 기능으로, $HOME 환경변수가 가리키는 경로로 자동 변환된다.

echo ~        # /home/username 또는 /c/Users/username (Git Bash)
echo $HOME    # 동일한 결과
cd ~          # 홈 디렉토리로 이동

헷갈렸던 점 3 — rm -r 은 얼마나 위험한가#

강의에서 위험하다고 했는데 처음엔 “그냥 삭제 아닌가?” 싶었다.

교정된 이해:

  • 리눅스 터미널에서 rm 은 휴지통 없이 즉시 영구 삭제
  • rm -r 폴더/ 는 폴더 안 모든 파일과 하위 폴더까지 전부 삭제
  • -rf 플래그는 경고조차 없이 강제 실행
  • 내 규칙: rm 전에는 항상 ls 로 대상 확인하기
# 삭제 전 반드시 확인
ls test_dir/

# 그 다음 삭제
rm -r test_dir/

헷갈렸던 점 4 — 파이프(|) 직관적으로 이해하기#

“앞 명령어의 출력이 뒤 명령어의 입력이 된다"는 설명이 처음엔 추상적이었다.

교정된 이해:

공장 컨베이어벨트 비유: 앞 공정의 결과물이 자동으로 다음 공정의 원료가 된다.

# ls 결과 중 .md 파일만 보기
ls -l | grep ".md"

# 파이프 없이 같은 작업 (번거로움)
ls -l > temp.txt
grep ".md" temp.txt
rm temp.txt

파이프를 쓰면 중간 파일 없이 한 줄에 연결 처리가 가능하다.

핵심 명령어 요약#

ls -la                    # 숨김 파일 포함 상세 목록
pwd                       # 현재 경로 확인
cd ~/Documents            # 홈 디렉토리 하위 이동
mkdir -p a/b/c            # 중간 폴더 포함 생성
cp -r 원본/ 목적지/       # 폴더째 복사
ls | grep ".py"           # py 파일만 필터
