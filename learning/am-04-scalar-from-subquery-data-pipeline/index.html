1. 스칼라 서브쿼리#

왜 이걸 보게 됐나#

데이터 분석 프로젝트에서 고객별 구매 패턴을 분석하는 과정에서, 고객별 총 결제 금액을 계산해야 했는데, 이를 위해 스칼라 서브쿼리가 필요했습니다. 복잡한 쿼리를 작성하다 보니, SQL에서 스칼라 서브쿼리가 어떻게 활용되는지 정확히 이해하고 싶어졌습니다. 또한, FROM 절 서브쿼리를 통해 데이터를 가공하여 임시 테이블처럼 활용하는 방법을 익히면 쿼리 효율성을 높일 수 있을 것 같았습니다.

내가 헷갈린 지점#

SQL에서 “스칼라"가 별도의 구문이 아니라 단일 값을 반환하는 서브쿼리를 지칭한다는 개념이 처음에는 헷갈렸다. 단순히 서브쿼리 결과가 한 셀에 표시되는 것을 스칼라 서브쿼리라고 생각하지 못했고, 각 행에 단일 값을 추가하는 역할을 한다는 점을 명확히 이해하는 데 시간이 걸렸다. 또한, 서브쿼리가 SELECT 절 뿐만 아니라 FROM 절에도 사용될 수 있다는 사실 자체가 예상 밖이었다.

시도한 코드 / 예시#

SELECT
    c.FirstName,
    c.LastName,
    (
        SELECT SUM(i.Total)
        FROM invoices i
        WHERE i.CustomerId = c.CustomerId
    ) AS total_spent
FROM customers c;

결과와 해석#

스칼라 서브쿼리는 각 고객의 총 결제 금액을 total_spent라는 새로운 열로 고객 목록에 추가해주는 역할을 합니다. 이 서브쿼리는 invoices 테이블에서 각 고객의 총 결제액을 계산하고, 이를 customers 테이블의 각 행에 결합하여 보여줍니다. 결과적으로 각 고객별로 이름과 총 결제 금액을 확인할 수 있습니다.

정리된 이해#

스칼라 서브쿼리는 각 행마다 단일 값을 반환하는 서브쿼리로서, 주로 SELECT 절에서 각 레코드를 보강하는 용도로 사용된다. 이것은 마치 쿼리 결과에 추가적인 계산이나 정보를 붙이는 것과 같다고 이해할 수 있다. 중요한 점은 이 서브쿼리의 결과가 하나의 값으로 표현된다는 것이다.

2. FROM 절 서브쿼리#

왜 이걸 보게 됐나#

데이터 분석 프로젝트에서 국가별 매출 분석을 위해 필요한 데이터를 추출하는 과정에서, 중첩된 쿼리를 사용해야 했는데, 이 때 FROM 절에 서브쿼리를 사용하면 임시 테이블을 활용하여 쿼리를 더 효율적으로 작성할 수 있다는 것을 알게 되었다. 기존 테이블에 필터링 및 집계 로직을 적용한 후, 그 결과를 다른 쿼리의 데이터 소스로 활용하는 패턴이 유용하다는 것을 깨달았다. 더 복잡한 데이터 분석 작업을 수행하기 위해 FROM 절 서브쿼리를 이해하고 활용하는 것이 필수적이라고 판단했다.

내가 헷갈린 지점#

처음에는 FROM 절 서브쿼리가 단순한 임시 테이블 생성이 아니라, 바깥쪽 쿼리가 그 테이블을 마치 진짜 테이블처럼 다루는 점이 이해가 잘 안 됐어. 기존 테이블과 임시 테이블의 관계가 어떻게 설정되는지, 그리고 그 임시 테이블이 쿼리 성능에 어떤 영향을 주는지에 대해서도 궁금했어. 특히 복잡한 쿼리에서 FROM 절 서브쿼리가 어떻게 활용되는지 상상하기 어려웠어.

시도한 코드 / 예시#

SELECT
    country_sales.BillingCountry,
    country_sales.total_sales
FROM (
    SELECT
        BillingCountry,
        SUM(Total) AS total_sales
    FROM invoices
    GROUP BY
        BillingCountry
) AS country_sales;

결과와 해석#

FROM 절 서브쿼리를 사용해서 국가별 총 매출을 계산하는 임시 테이블을 만들었더니, 바깥쪽 쿼리에서 마치 진짜 테이블처럼 country_sales라는 이름으로 접근하며 데이터를 가져올 수 있었다. 이를 통해 복잡한 집계 결과를 기준으로 다른 필드를 선택하는 것이 가능해졌고, 임시 테이블을 이름으로 지정하여 활용할 수 있다는 점이 유용했다. 이 방식은 중간 결과를 저장하고 재사용하여 쿼리를 간결하게 만드는 데 도움이 된다.

정리된 이해#

FROM invoices GROUP BY BillingCountry ) AS country_sales ORDER BY country_sales.total_sales DESC LIMIT 5;

  • 핵심: 데이터 가공 및 집계를 수행하고, 그 결과를 마치 실제 테이블처럼 활용하여 더 복잡한 쿼리를 구성할 수 있게 해준다. 즉, 서브쿼리의 결과가 테이블처럼 사용되어 데이터 소스로 활용되는 방식이다.

3. 임시 테이블#

왜 이걸 보게 됐나#

복잡한 데이터 분석을 할 때, 여러 테이블을 조인하거나 집계하는 과정에서 중간 결과를 저장하고 활용해야 할 때가 있었는데, 그때 임시 테이블이 필요하게 됐어. 특히 FROM 절 서브쿼리는 복잡한 집계와 조인을 한 번에 처리하고 싶을 때, 일시적으로 데이터를 정리하고 사용하기 위한 효율적인 방법이라는 걸 알게 됐어. 이를 통해 쿼리 복잡도를 줄이고 가독성을 높일 수 있다는 점이 중요하게 다가왔어.

내가 헷갈린 지점#

처음에 임시 테이블이라는 개념 때문에, 단순히 쿼리 실행 순서가 바뀌는 거라고 생각했었다. 안쪽 쿼리의 결과가 바깥쪽 쿼리에 바로 영향을 주는 게 아니라, 마치 실제 테이블처럼 존재하고 사용된다는 점이 생소했다. 또한, 이 임시 테이블의 스키마(열 이름과 데이터 타입)는 어떻게 정의되고 관리되는지에 대한 구체적인 과정이 궁금했다.

시도한 코드 / 예시#

SELECT
    BillingCountry,
    SUM(Total) AS total_sales
FROM invoices
GROUP BY BillingCountry

결과와 해석#

임시 테이블은 FROM 절 서브쿼리가 실행될 때 데이터베이스 시스템이 내부적으로 생성하는 가상의 테이블인데, country_sales라는 이름을 부여하여 바깥쪽 쿼리에서 마치 진짜 테이블인 것처럼 사용할 수 있었다. 이 임시 테이블은 국가별 총 매출을 담고 있어서, 바깥쪽 쿼리에서 BillingCountry와 total_sales를 간단하게 선택하여 결과를 얻을 수 있었다. WITH 절을 사용하여 같은 기능을 수행할 수도 있지만, FROM 절 서브쿼리는 특정 상황에서 유용하게 사용될 수 있다.

정리된 이해#

FROM invoices GROUP BY BillingCountry ) AS country_sales ORDER BY country_sales.total_sales DESC LIMIT 5;

  • 핵심: 테이블처럼 사용할 수 있는 임시 결과 집합을 생성하여 메인 쿼리에 데이터를 제공한다. 임시 테이블은 메인 쿼리에서 참조할 수 있는 가상의 테이블로 기능하며, 데이터 조작 및 필터링을 위한 기반을 제공한다.

4. 쿼리 결과#

왜 이걸 보게 됐나#

SQL 쿼리를 작성하다 보면 특정 데이터를 활용하기 위해 일시적으로 테이블과 유사한 결과 집합을 만들어야 할 때가 많았는데, 이렇게 서브쿼리를 FROM 절에 넣어 사용하는 방법을 익히면 데이터 분석의 유연성이 크게 향상된다는 것을 알게 되었다. 특히 복잡한 분석이나 집계 연산 시 임시 테이블을 활용하는 것이 효율적이라는 것을 배우면서, FROM 절 서브쿼리의 중요성을 체감하게 되었다.

내가 헷갈린 지점#

처음에는 서브쿼리가 항상 복잡한 결과를 반환하는 것으로 생각해서, 단일 값을 반환하는 서브쿼리를 ‘스칼라’라고 부르는 개념이 낯설었다. FROM 절 서브쿼리가 어떻게 임시 테이블을 만들고, 그 테이블이 외부 쿼리에 사용되는지 이해하는 데 어려움을 느꼈다. 결국 임시 테이블이라는 개념과 외부 쿼리가 그 임시 테이블을 마치 일반 테이블처럼 참조한다는 점을 깨닫고 이해하게 되었다.

시도한 코드 / 예시#

SELECT
    country_sales.BillingCountry,
    country_sales.total_sales
FROM (
    SELECT
        BillingCountry,
        SUM(Total) AS total_sales
    FROM invoices
    GROUP BY
        BillingCountry
) AS country_sales;

결과와 해석#

국가별 총 매출을 계산하는 FROM 절 서브쿼리 예제는 내부 쿼리가 먼저 실행되어 국가별 총 매출을 계산한 임시 테이블을 만들고, 바깥쪽 쿼리가 이 임시 테이블을 마치 실제 테이블처럼 사용하여 결과를 선택한다는 것을 보여준다. 이렇게 하면 복잡한 집계 결과를 바탕으로 추가적인 필터링이나 정렬을 수행하기 용이하다. 결과적으로 임시 테이블을 사용하면 데이터 접근 방식이 유연해지고, 복잡한 쿼리를 더 쉽게 구성할 수 있다.

정리된 이해#

스칼라 서브쿼리는 각 행에 대해 단일 값을 제공하여 SELECT 절을 확장하는 역할을 하며, FROM 절 서브쿼리는 쿼리 결과를 임시 테이블로 만들어 마치 실제 테이블처럼 사용할 수 있게 해준다. 즉, 복잡한 데이터 가공 과정을 중간 임시 테이블을 통해 간결하게 표현할 수 있도록 도와준다. 이 두 가지 서브쿼리 기법을 이해하면 SQL 쿼리의 유연성과 가독성을 높일 수 있다.

총평#

오늘 전체에서 배운 것#

스칼라 서브쿼리는 SELECT 절에서 단일 값을 반환하는 쿼리이고, FROM 절 서브쿼리는 쿼리 결과를 임시 테이블로 만들어 바깥쪽 쿼리에서 활용한다는 것을 이해했다. 이 임시 테이블 개념을 확실히 하면 FROM 절 서브쿼리의 작동 방식을 더 명확하게 파악할 수 있을 것 같다.

다음에 조심할 것#

스칼라 서브쿼리는 각 행에 대한 단일 값을 반환한다는 점을 항상 기억해야 해. FROM 절 서브쿼리는 임시 테이블로 생각하고, 바깥쪽 쿼리는 이 임시 테이블을 실제 테이블처럼 활용한다는 것을 잊지 말아야겠어. 특히, FROM 절 서브쿼리는 alias를 꼭 사용해서 가독성을 확보하고 오류를 줄여야 해.

다음 복습 주제#

FROM invoices GROUP BY BillingCountry ) AS country_sales ORDER BY total_sales DESC LIMIT 5;

  - **핵심**:  임시 테이블을 만들어 바깥쪽 쿼리에서 테이블처럼 사용할 수 있게 함. `AS` 키워드를 사용하여 임시 테이블에 별칭을 부여하는 것이 중요.

핵심 정리#

스칼라 서브쿼리는 각 행에 단일 값만 반환하는 서브쿼리이고, FROM 절 서브쿼리는 임시 테이블을 생성하여 바깥쪽 쿼리에서 활용하는 방식이다. FROM 절 서브쿼리에서 임시 테이블의 이름과 열 이름을 명확하게 설정하는 것이 중요하며, 안쪽 쿼리의 결과가 바깥쪽 쿼리에서 어떻게 활용되는지 파악하는 것이 핵심이다.

오늘 다룬 개념들: 스칼라 서브쿼리, FROM 절 서브쿼리, 임시 테이블, 쿼리 결과

FROM 절 서브쿼리에서 JOIN 연산을 사용하는 경우는 어떻게 되는지 자세히 알아보고, 스칼라 서브쿼리가 성능에 미치는 영향에 대해 좀 더 깊이 파악해보고 싶다. 그리고 서브쿼리 사용 외에 비슷한 결과를 얻을 수 있는 다른 방법이 있는지 찾아보고 싶다.
