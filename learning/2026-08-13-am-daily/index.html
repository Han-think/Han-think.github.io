1. React 배열 데이터 화면 출력 및 map() 활용법#

무엇을 배웠나#

React 배열 데이터를 화면에 출력하는 방법을 익혔다. map() 함수를 사용하여 배열의 각 요소를 JSX 요소로 변환하고, key 속성을 사용하여 각 요소에 고유한 식별자를 부여하는 방법을 알게 되었다. 또한, 코드 복사/붙여넣기 시 발생할 수 있는 문자열 따옴표 오류에 주의해야 한다는 점도 깨달았다.

헷갈렸던 점#

코드를 복사해서 붙여넣을 때 작은따옴표가 깨져서 문법 오류가 발생하는 바람에, 파일 형식 문제인 줄 알았다가 직접 입력하면서 해결했다. 강의 내용을 빠르게 따라 적기가 어려워서 놓치는 부분이 있었고, key 속성이 왜 필요한지 정확하게 이해하지 못하고 단순히 따라 적었던 것 같다. 배열 데이터를 화면에 출력하는 기본적인 방법은 익혔지만, 좀 더 응용해서 다양한 방식으로 표현하는 방법은 추가적으로 학습해야겠다.

정리된 이해#

React 배열 데이터를 화면에 출력하기 위해 map() 함수를 활용하여 배열의 각 요소를 JSX 요소로 변환하고, 각 요소에 key 속성을 부여하여 React가 효율적으로 업데이트할 수 있도록 했습니다. key 속성은 부모 컴포넌트가 자식 요소를 식별하는 데 필수적이며, 일반적으로 데이터 자체의 고유 ID를 사용합니다. 복사/붙여넣기 과정에서 문자열 따옴표 오류가 발생할 수 있으므로 주의해야 합니다.

const posts = [
    {id:1, title:'게시글 제목 1', category:'카테고리'},
    // ... 나머지 게시물
];

export default function Blog({posts}) {
    const list = posts.map(post => (
        <div key={post.id}>
            <h3>{post.id}: {post.title}</h3>
            <p>Category: {post.category}</p>
        </div>
    ));
    return <>{list}</>;
}

2. React Todo 앱: State, Props, 컴포넌트 연결 흐름#

무엇을 배웠나#

React Todo 앱을 만들면서 부모 컴포넌트에서 상태를 관리하고 자식 컴포넌트에 props를 통해 전달하는 구조의 필요성을 알게 되었다. 자식 컴포넌트 내에서 useState를 사용하는 대신 부모 컴포넌트의 상태를 활용하고, props를 통해 함수를 전달하여 자식 컴포넌트가 부모의 상태를 조작하도록 하는 것이 코드 유지보수성에 더 유리하다는 것을 배웠다. 또한, 부모 컴포넌트에서 정의한 함수를 자식 컴포넌트에서 올바르게 사용하기 위해 props를 통해 전달하고, 자식 컴포넌트에서 해당 함수를 호출해야 함을 확인했다.

헷갈렸던 점#

처음에는 Input 컴포넌트 자체에서 상태를 관리하려고 했는데, 부모 컴포넌트에서 상태를 관리하고 props로 전달하는 방식이 왜 필요한지 이해하기 어려웠다. 또한, 부모 컴포넌트에서 정의한 함수를 자식 컴포넌트에서 어떻게 올바르게 사용할 수 있는지 몰라 오류가 발생했다.

3. React Todo 앱 실습: useRef 활용 및 초보자 난관 해결#

무엇을 배웠나#

React Todo 앱 실습에서 useRef의 사용법을 잘못 이해하고 있었는데, useRef는 .current를 통해 값을 가져와야 한다는 것을 알게 되었습니다. useRef는 컴포넌트 리렌더링 시에도 값을 유지하는 중요한 역할을 한다는 것을 명확히 이해하게 되었습니다. 여러 개념이 복합적으로 사용될 때, 각 개념의 역할을 구분하고 어떻게 상호작용하는지 파악하는 것이 중요하다고 깨달았습니다.

헷갈렸던 점#

useRef를 처음 사용할 때, 그냥 변수처럼 값을 꺼내 쓰려고 해서 오류가 났어요. 여러 개념들이 섞여서 한꺼번에 이해하기가 쉽지 않았고, 특히 useEffect, useRef, 상태 관리 등을 연결해서 생각하는 데 어려움을 느꼈습니다.

정리된 이해#

useRef는 컴포넌트 리렌더링을 거쳐도 값이 유지되는 특별한 변수라고 이해했다. 일반 변수처럼 직접 값을 사용할 수 없고, 항상 .current를 통해 접근해야 하며, 주로 값이 계속 유지되어야 할 때 활용된다. Todo 앱에서 ID를 관리하는 용도로 사용해봤는데, useRef 덕분에 ID가 꼬이지 않고 잘 관리되는 것을 확인했다.

4. WebStorm CSS 실습: 초보자의 오류 해결 및 스타일 연결 가이드#

무엇을 배웠나#

React 컴포넌트와 CSS 스타일을 연결하는 방법을 익혔고, className을 사용하여 CSS를 적용하는 방법을 이해했습니다. 또한 강의 속도가 빠를 때 오류를 파악하기 어려울 수 있다는 점을 인지하고, ESLint 메시지와 실제 렌더링 오류를 구분하며 해결하는 연습이 필요하다는 것을 알았습니다. 특히 복사/붙여넣기 과정에서 발생하는 작은따옴표 오류에 주의해야 합니다.

헷갈렸던 점#

강사님께서 코드를 너무 빠르게 입력하고 수정하셔서, 실시간으로 발생하는 오류를 따라가기 어려웠다. 특히 미완성 코드와 오류 코드를 구분하는 데 어려움이 있었고, 복사 붙여넣기 과정에서 작은따옴표 오류가 발생했을 때 해결하는 방법을 바로 알 수 없었다. IDE 경고 메시지와 실제 런타임 에러를 구분하는 것 또한 쉽지 않았다.

정리된 이해#

React 컴포넌트와 CSS를 연결하는 방법을 익혔고, className을 통해 스타일을 적용할 수 있게 되었다. 강의 진행 속도가 빨라 오류를 실시간으로 파악하기 어려웠지만, ESLint 메시지와 className을 확인하며 문제 해결 과정을 거치면서 실력 향상을 위한 발판을 마련했다. 앞으로는 복사/붙여넣기보다는 직접 코드를 입력하며 특수문자 오류를 예방하는 습관을 들여야겠다.

// App.jsx
import './App.css';

function App() {
  return (
    <div className="app">
      <input type="text" placeholder="입력란" />
      <div className="true">중지 표시 텍스트</div>
    </div>
  );
}

.app {
  margin: 20px;
  border: 1px solid lightgray;
  padding: 10px;
}

input[type="text"] {
  height: 40px;
  width: 85%;
  font-size: 20px;
  border-bottom: 1px solid green;
}

.true {
  text-decoration: line-through;
  color: gray;
}
