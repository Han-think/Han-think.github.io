1. am-01-sql-day03-quiz-review#

무엇을 배웠나#

SQL 쿼리 작성 시 WHERE절과 HAVING절의 차이점을 명확히 이해하게 되었고, COUNT(*) 함수를 사용하여 별칭을 부여하는 방식도 제대로 익혔습니다. LEFT JOIN과 IS NULL을 활용하여 특정 테이블에 데이터가 없는 경우를 찾는 방법도 습득했습니다. 복잡한 요구사항을 분석하고 쿼리로 변환하는 연습이 필요하다는 것을 깨달았습니다.

헷갈렸던 점#

처음에는 COUNT(*) 함수가 테이블에 새로운 컬럼을 만드는 줄 알았고, HAVING이 WHERE랑 비슷한 역할을 하는 건 줄 착각했어요. 또한 LEFT JOIN을 사용할 때 NULL 값을 찾는 과정이 어떻게 가능한지 잘 이해가 안 되었습니다.

정리된 이해#

WHERE절은 테이블의 원본 행을 필터링하는 데 사용하고, HAVING절은 GROUP BY로 묶인 결과에 대한 조건을 설정하는 데 사용한다는 것을 명확히 이해하게 되었습니다. COUNT(*)는 단순히 계산된 값을 새로운 컬럼처럼 이름을 붙여 사용할 수 있다는 점도 제대로 알게 되었습니다. 그리고 LEFT JOIN과 IS NULL을 활용하여 관련 정보가 없는 레코드를 찾는 방식도 자연스럽게 사용할 수 있게 되었습니다.

-- HAVING: 그룹화 후 적용
SELECT productLine, COUNT(*) AS 제품수
FROM products
GROUP BY productLine
HAVING COUNT(*) >= 10;

2. am-02-classicmodels-erd-reading#

무엇을 배웠나#

ERD를 처음 볼 때 전체적인 구조가 헷갈렸지만, 회로도나 관계도처럼 생각하고 테이블과 컬럼의 역할을 이해하려 노력했어. 문제 해결 시 필요한 컬럼과 조건을 먼저 파악하는 접근법을 익혔고, INNER JOIN과 LEFT JOIN의 차이를 명확히 이해하게 되었어. 이제 ERD를 보고 SQL 쿼리를 작성하는 데 조금 더 자신감이 생겼어.

헷갈렸던 점#

ERD를 처음 봤을 때 테이블 간의 관계를 파악하는 게 너무 어려웠다. 특히 INNER JOIN과 LEFT JOIN의 차이를 제대로 이해하지 못해서, 어떤 테이블을 기준으로 어떻게 조인해야 할지 막막했다. 문제 해결을 위해 필요한 컬럼과 조건 단어를 먼저 파악하는 방식으로 접근하는 것이 도움이 되었다.

정리된 이해#

ERD는 복잡한 테이블 간의 관계를 시각적으로 보여주는 회로도와 같아서, 전체 구조를 한 번에 파악하기보다는 테이블과 컬럼, 그리고 그 연결 관계를 하나씩 이해하는 것이 중요합니다. 문제를 풀 때는 먼저 필요한 출력 컬럼과 조건을 명확히 파악하고, 이를 바탕으로 어떤 테이블을 JOIN해야 하는지, 그리고 어떤 조건을 WHERE절에 적용해야 하는지를 단계적으로 생각하면 좀 더 쉽게 접근할 수 있습니다.

SELECT c.customerNumber, c.customerName, c.country, c.city, COUNT(o.orderNumber)
      FROM customers c
      INNER JOIN orders o ON c.customerNumber = o.customerNumber
      WHERE c.country IN ('USA', 'France') AND YEAR(o.orderDate) = 2004
      GROUP BY c.customerNumber, c.customerName

3. am-03-jupyterlab-python-sqlite-connection#

무엇을 배웠나#

JupyterLab에서 SQLite를 Python으로 실행할 때 변수명 오류가 발생했던 경험을 통해 정확한 변수명을 사용하는 것의 중요성을 깨달았습니다. 또한 Python 코드와 SQL 쿼리가 어떻게 연결되는지 이해하는 것이 중요하며, 연결 및 쿼리 실행 과정을 명확히 정리하여 실습을 진행했습니다. 이제는 JupyterLab 구조와 SQLite 연결 과정을 더욱 자신 있게 다룰 수 있을 것 같습니다.

헷갈렸던 점#

변수명을 잘못 사용해서 에러가 발생하고, Python 코드와 SQL 쿼리가 JupyterLab 환경에서 어떻게 연결되는지 이해하는 데 어려움을 겪었다. 특히 SQL 문자열을 Python 코드 내에서 어떻게 사용하는지 명확히 파악하지 못해 혼란스러웠다.

정리된 이해#

JupyterLab에서 Python을 사용해 SQLite를 실행할 때 변수명 오류로 인해 어려움을 겪었지만, 올바른 변수명을 사용하고 Notebook 구조와 SQL 쿼리 실행 과정을 이해함으로써 문제를 해결할 수 있었다. 앞으로는 변수명 오류에 주의하고, SQL 쿼리 문자열을 효율적으로 사용하는 방법을 기억해야겠다.

import sqlite3

DB_PATH = 'path_to_your_database.db' # 실제 DB 경로로 변경
conn = sqlite3.connect(DB_PATH)
cur = conn.cursor()
cur.execute("SELECT * FROM your_table")
rows = cur.fetchall()
for row in rows:
    print(row)
conn.close()

4. am-04-python-sqlite-new-db-crud#

무엇을 배웠나#

파이썬으로 SQLite 데이터베이스를 만들고 CRUD 작업을 수행하는 과정에 대한 이해가 부족했던 점을 파악했습니다. 특히 데이터베이스 연결, SQL 실행 객체 생성, 쿼리 실행, 변경 사항 저장, 연결 종료와 같은 핵심 단계들을 명확히 정리하고, UPDATE 및 DELETE 문에서 WHERE 절의 중요성을 깨달았습니다. 앞으로는 더 주의하며 실습해야겠습니다.

헷갈렸던 점#

새 데이터베이스 생성부터 테이블 생성, 데이터 입력, 조회, 수정, 삭제까지의 전체 과정이 한 번에 진행되면서 흐름을 이해하는 데 어려움을 겪었습니다. 특히 테이블 생성과 데이터 입력 사이의 단계를 명확히 구분하지 못했고, UPDATE와 DELETE 문에서 WHERE 절의 중요성을 제대로 인지하지 못해 실수를 할 뻔했습니다.

정리된 이해#

Python으로 SQLite 데이터베이스를 다루는 과정은 DB 연결, SQL 실행 객체 생성, 쿼리 실행, 변경 사항 저장, 연결 종료의 순서로 진행된다. 특히 UPDATE와 DELETE 문에서는 WHERE 절을 명확히 사용하여 의도하지 않은 데이터 변경을 방지해야 하며, 연결 종료를 잊지 않도록 주의해야 한다. 파일 삭제 기능은 데이터베이스를 생성하는 과정에서 활용되지만, 실수로 데이터가 삭제되지 않도록 주의해야 한다.

import sqlite3

5. am-05-join-groupby-subquery-in-practice#

무엇을 배웠나#

이번 실습을 통해 JOIN을 활용하여 여러 테이블의 데이터를 연결하는 방법을 익혔습니다. 특히, 특정 조건을 만족하는 데이터를 찾을 때 어떤 테이블을 어떻게 연결해야 하는지 고민하는 과정에서 데이터베이스 설계에 대한 이해도가 높아졌습니다. 또한 서브쿼리와 IN 연산자를 활용하여 복잡한 쿼리를 작성하는 데 필요한 기본적인 개념을 숙지하게 되었습니다.

헷갈렸던 점#

처음에는 JOIN을 사용할 때 어떤 테이블을 연결해야 하는지, 그리고 어떤 ON 조건을 사용해야 하는지 막막했습니다. 특히 서브쿼리를 사용할 때, 전체적인 데이터 흐름을 놓치고 서브쿼리 자체에만 집중해서 문제를 해결하는 데 어려움을 겪었습니다. 테이블 간의 관계를 명확히 이해하고, 전체적인 관점에서 문제를 해결하는 것이 중요함을 깨달았습니다.

정리된 이해#

JOIN을 활용하여 여러 테이블 간의 관계를 파악하고 필요한 데이터를 조합하는 방법을 익혔습니다. 특히, 문제 해결 과정에서 어떤 테이블을 사용해야 할지 막히는 부분이 있었지만, 테이블 간의 연결 경로를 시각화하고 연습하면서 점차 해결해 나갔습니다. 주요 SQL 함수와 서브쿼리의 활용법을 이해하여 데이터 분석 능력을 향상시켰습니다.

SELECT c.customer_name,
          o.order_id,
          p.product_name,
          oi.quantity,
          p.price,
          (oi.quantity * p.price) AS line_total
   FROM customers c
   INNER JOIN orders o ON c.customer_id = o.customer_id
