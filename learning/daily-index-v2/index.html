1. GROUP BY와 HAVING#

왜 이걸 보게 됐나#

데이터 분석 프로젝트를 진행하다 보면, 특정 기준에 따라 데이터를 묶어서 통계를 내고, 그 결과에 대한 추가적인 필터링이 필요할 때가 많았어. 예를 들어, 지역별 매출액을 분석하거나, 특정 조건을 만족하는 그룹만 추출해야 하는 상황이었지. 그래서 GROUP BY와 HAVING 구문을 통해 데이터 그룹화 및 조건 필터링 방법을 배우게 되었어.

내가 헷갈린 지점#

처음에는 GROUP BY 뒤에 바로 집계 함수를 사용하는 것이 가능한가에 대한 명확한 그림이 잡히지 않았고, HAVING절이 어떤 기준으로 집계된 결과에 조건을 걸어주는 것인지 감이 잘 안왔다. HAVING 절이 WHERE 절과 어떻게 다른지, 언제 어떤 상황에서 사용해야 하는지 혼동스러웠다. 그룹화된 데이터에 대한 필터링이 HAVING 절에서 이루어지는구나를 깨달으면서 좀 더 이해가 되기 시작했다.

시도한 코드 / 예시#

SELECT 상품 카테고리, SUM(매출) as total_sales
FROM 판매테이블
GROUP BY 상품 카테고리
HAVING SUM(매출) > 1000;

결과와 해석#

GROUP BY를 사용해서 상품 카테고리별 총 매출을 계산하고, HAVING 절을 이용해서 총 매출이 1000을 넘는 카테고리만 필터링하는 예제를 실행했습니다. 이렇게 하면 특정 기준 이상의 성과를 보이는 카테고리를 빠르게 파악할 수 있고, 매출 부진 카테고리에 대한 추가 분석을 위한 힌트를 얻을 수 있습니다. 결과적으로 그룹화된 데이터에 대한 조건을 설정하는 HAVING 절의 역할이 명확해졌습니다.

정리된 이해#

GROUP BY는 데이터를 묶어 집계 함수를 적용할 때 사용하고, HAVING은 이처럼 묶인 그룹에 대한 조건을 걸 때 활용해. 즉, HAVING은 집계된 결과값에 대해 필터링하는 역할을 수행하며, SELECT 절에 포함될 수 없는 집계 함수 결과에 대한 조건을 정의하는 데 유용해.

2. JOIN과 서브쿼리#

왜 이걸 보게 됐나#

여러 테이블에 흩어져 있는 데이터를 한눈에 보고 싶을 때 JOIN을 사용해야 했는데, 특정 조건을 만족하는 데이터만 가져오려면 서브쿼리를 활용해야 했습니다. 이를 통해 복잡한 비즈니스 요구사항에 맞는 맞춤형 리포트를 작성할 수 있게 되었습니다. 단순히 데이터를 보는 것을 넘어, 데이터 분석의 깊이를 더하기 위해 이 개념들을 공부하게 됐습니다.

내가 헷갈린 지점#

처음에 JOIN과 서브쿼리를 함께 사용할 때, 어떤 테이블이 먼저 조인되어야 하고 서브쿼리가 정확히 어떤 역할을 하는지 파악하는 게 어려웠다. 서브쿼리가 주 쿼리의 어디에 위치해야 하는지, 그리고 어떤 상황에서 스칼라 서브쿼리와 FROM 절 서브쿼리를 선택해야 할지 판단하기 힘들었음. JOIN이 먼저 실행되는 건지, 서브쿼리가 먼저 실행되는 건지 혼동되기도 했음.

시도한 코드 / 예시#

-- 예제: 고객 정보 테이블(Customers)와 주문 정보 테이블(Orders)을 JOIN하고, 주문 금액이 100달러 이상인 고객의 정보를 조회합니다.

SELECT
    C.CustomerID,
    C.CustomerName,
    O.OrderID,
    O.OrderDate
FROM
    Customers C
JOIN
    Orders O ON C.CustomerID = O.CustomerID
WHERE
    O.OrderAmount > 100;

결과와 해석#

테이블 A의 고객 ID와 테이블 B의 주문 정보를 JOIN하여 특정 고객이 주문한 총 금액을 계산하는 코드를 작성해봤습니다. 스칼라 서브쿼리를 사용해서 각 고객별 주문 금액의 합을 미리 계산하고, 이를 바탕으로 특정 금액 이상 주문한 고객을 필터링 할 수 있었습니다. FROM 절 서브쿼리는 가상 테이블을 만들어 쿼리를 더 간결하게 만들 수 있음을 확인했습니다.

정리된 이해#

JOIN은 여러 테이블의 데이터를 연결해서 필요한 정보를 얻을 수 있게 해주고, 서브쿼리는 쿼리 내부에 또 다른 쿼리를 넣어 더 복잡한 조건을 설정하거나 중간 결과를 활용할 때 유용하다. 스칼라 서브쿼리는 각 행에 대한 계산 결과를 반환하고, FROM 절 서브쿼리는 테이블처럼 사용할 수 있다는 점이 중요하게 다르게 작용한다.

3. 집합 연산자#

왜 이걸 보게 됐나#

데이터 분석 보고서를 작성하다 보면 여러 테이블의 데이터를 결합하거나, 특정 조건을 만족하는 데이터 집합을 비교해야 하는 경우가 많았어요. 그래서 단순히 테이블에서 데이터를 가져오는 것 이상으로, 데이터를 조합하고 분석하는 능력이 필요하다고 생각해서 집합 연산자를 배우게 됐습니다. 복잡한 데이터 세트를 다루는 데 필수적인 도구라고 들었기 때문입니다.

내가 헷갈린 지점#

처음에는 UNION과 UNION ALL이 단순히 중복을 제거하는 정도의 차이만 있을 거라고 생각했는데, UNION은 중복을 제거하고 UNION ALL은 모든 결과를 그대로 합친다는 것을 알게 되었습니다. 또한 INTERSECT는 두 쿼리의 교집합을 찾는 연산이고, EXCEPT는 차집합을 구하는 연산이라는 것을 명확히 이해하지 못해서 어떤 상황에 어떤 연산자를 사용해야 할지 막막했습니다. 결국 다양한 예제를 통해 각 연산자가 어떻게 작동하는지 직접 확인하면서 이해하게 되었습니다.

시도한 코드 / 예시#

-- UNION ALL: 두 테이블의 모든 데이터를 합집합합니다. 중복 데이터도 포함됩니다.
SELECT 상품명 FROM 베스트셀러테이블
UNION ALL
SELECT 상품명 FROM 인기상품테이블;
-- 결과: '우유', '빵', '커피', '과자' 와 같은 상품명 목록이 출력됩니다. 중복 상품명이 있다면, 각 테이블에서 중복된 상품명만큼 나타납니다.

-- INTERSECT: 두 테이블에서 공통으로 존재하는 데이터를 추출합니다.
SELECT 고객ID FROM 주문테이블
INTERSECT
SELECT 고객ID FROM 멤버십테이블;
-- 결과: 주문테이블과 멤버십테이블 모두에 존재하는 고객ID 목록이 출력됩니다.

-- EXCEPT (MINUS): 한 테이블에는 있지만 다른 테이블에는 없는 데이터를 추출합니다.
SELECT 고객ID FROM 주문테이블
EXCEPT
SELECT 고객ID FROM 환불테이블;
-- 결과: 주문테이블에는 있지만 환불테이블에는 없는 고객ID 목록이 출력됩니다.

결과와 해석#

UNION은 두 쿼리의 결과를 합치는 연산자로, 중복된 행을 제거하여 결과 집합을 만듭니다. UNION ALL은 중복 제거 없이 단순히 두 쿼리의 결과를 이어붙이기 때문에 UNION보다 성능이 좋습니다. INTERSECT는 두 쿼리의 결과에서 공통된 행만 추출하는 역할을 하며, EXCEPT는 첫 번째 쿼리에는 있지만 두 번째 쿼리에는 없는 행을 보여줍니다.

정리된 이해#

집합 연산자는 여러 쿼리의 결과를 하나로 합치거나 교집합/차집합을 구할 때 사용하는데, UNION ALL은 중복을 허용하고 UNION은 중복을 제거한다는 점이 핵심이야. 실제로는 여러 테이블에서 필요한 정보를 모아 리포트를 작성할 때 매우 유용하게 활용할 수 있어. 예를 들어 특정 조건을 만족하는 고객 정보를 두 테이블에서 가져와 합치는 데 사용할 수 있지.

4. 데이터 병합#

왜 이걸 보게 됐나#

데이터가 여러 테이블에 분산되어 있을 때, 필요한 정보를 얻기 위해서는 여러 테이블에 있는 데이터를 하나로 합쳐서 분석해야 했어. 단순히 한 테이블만으로는 답변을 얻을 수 없는 복잡한 질문에 답하려면 테이블 간의 관계를 활용해서 데이터를 결합하는 방법이 필요했지. 결국 더 유용한 인사이트를 얻기 위해서는 다양한 테이블을 연결하고 활용하는 능력이 필수적이라는 것을 깨달았어.

내가 헷갈린 지점#

처음에는 JOIN이 단순히 두 테이블의 내용을 나열하는 것처럼 생각했어요. 하지만 실제로는 특정 조건을 기반으로 행을 연결해야 한다는 점이 어렵게 느껴졌고, 서브쿼리와 함께 사용될 때는 더욱 복잡해 보여서 어떻게 동작하는지 파악하기 힘들었습니다. 여러 테이블을 연결할 때 어떤 기준으로 조인해야 하는지, 그리고 서브쿼리가 어떻게 활용되는지 한 번에 이해하기 어려웠어요.

시도한 코드 / 예시#

SELECT
    t1.order_id,
    t1.customer_id,
    t2.product_name
FROM
    orders AS t1
JOIN
    products AS t2
ON
    t1.product_id = t2.product_id;

결과와 해석#

두 테이블을 JOIN하면 관련 있는 행들을 하나의 결과 집합으로 합칠 수 있어, 예를 들어 고객 정보 테이블과 주문 정보 테이블을 연결해서 각 주문에 대한 고객 정보를 함께 볼 수 있습니다. 예를 들어, 고객 ID를 기준으로 두 테이블을 조인하면 각 주문에 누가 주문했는지 쉽게 파악할 수 있습니다. 이렇게 병합된 데이터는 더 복잡한 분석이나 보고서 작성을 용이하게 해줍니다.

정리된 이해#

JOIN은 관련 데이터를 가진 여러 테이블을 하나로 묶어 필요한 정보를 추출할 수 있게 해주는 방법입니다. 서브쿼리는 복잡한 조건이나 계산 결과를 활용하여 주 쿼리의 결과를 더욱 구체화하는 데 활용될 수 있으며, FROM절 서브쿼리를 사용하면 마치 테이블인 것처럼 활용할 수도 있습니다.

총평#

오늘 전체에서 배운 것#

오늘은 GROUP BY와 HAVING 구문으로 그룹화된 데이터에 조건을 걸고, JOIN과 서브쿼리를 활용하여 여러 테이블의 데이터를 효과적으로 결합하는 방법을 익혔습니다. 또한, UNION, INTERSECT, EXCEPT 등 집합 연산자의 활용법을 배우면서 데이터 분석의 폭을 넓힐 수 있었습니다.

다음에 조심할 것#

HAVING절을 GROUP BY 뒤에 바로 적용하는 습관을 들여서, 집계된 결과에 대한 조건을 명확히 해야겠다. FROM절 서브쿼리의 활용은 아직 미흡하니, 다양한 예제를 통해 활용도를 높여야겠다. UNION ALL과 INTERSECT의 차이를 더 깊이 이해하고, 실제 상황에 맞게 사용할 수 있도록 연습해야겠다.

다음 복습 주제#

FROM 절 서브쿼리의 활용법을 더 깊이 파악하고, 다양한 JOIN 유형(LEFT, RIGHT, FULL)을 활용한 복잡한 쿼리 작성 연습이 필요해. 또한, 윈도우 함수(Window Functions)를 학습하여 GROUP BY를 대체할 수 있는 방법도 알아봐야겠다.
