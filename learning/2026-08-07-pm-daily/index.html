1. HTTP 요청 및 응답 구조와 상태 코드 완벽 이해#

무엇을 배웠나#

HTTP 요청과 응답 메시지의 구조, 특히 시작 줄, 헤더, 바디의 역할과 GET과 POST 메서드의 차이점을 이해하게 되었다. 400 Bad Request 상태 코드가 단순히 파라미터 개수 오류가 아니라 클라이언트 측의 다양한 잘못된 요청을 의미한다는 것을 알게 되었고, 다양한 상태 코드의 의미와 범위를 좀 더 명확히 파악했다. 이를 통해 HTTP 통신 과정을 더 깊이 이해하고, 문제 발생 시 디버깅에 도움이 될 것으로 생각한다.

헷갈렸던 점#

400 Bad Request 상태 코드를 단순히 파라미터 개수 오류로만 생각해서 다른 클라이언트 오류 상황을 제대로 이해하지 못했고, 다양한 HTTP 상태 코드들이 어떤 상황에서 사용되는지 전체적인 맥락을 파악하는 데 어려움을 느꼈다. 또한 GET과 POST 요청의 차이점과 각 방식이 적절한 사용 상황에 대한 이해가 부족했다.

정리된 이해#

HTTP 요청은 시작 줄, 헤더, 바디로 구성되며, GET은 URL에 데이터를 노출하고 POST는 본문에 데이터를 포함합니다. 상태 코드는 요청 성공 여부 및 오류 종류를 나타내며, 400 Bad Request는 파라미터 문제 외에도 클라이언트 측의 다양한 잘못된 요청을 의미합니다. 각 상태 코드의 구체적인 상황을 이해하는 것이 중요합니다.

[GET /path?param1=value1&param2=value2 HTTP/1.1

POST /path HTTP/1.1
Content-Type: application/json

{
  "key": "value"
}

2. API, REST, AJAX: 초보자를 위한 핵심 개념 정리#

무엇을 배웠나#

HTTP, API, REST, AJAX의 개념과 역할을 명확하게 정리했으며, 각각의 역할과 구분이 모호했던 부분이 해결되었습니다. 특히 RESTful API 설계 방식과 AJAX를 활용한 비동기 통신이 어떻게 동작하는지 이해하게 되었고, 실습 예시를 통해 실제 코드 구현에 대한 감을 잡았습니다. 앞으로는 이 지식을 바탕으로 API를 활용한 웹 서비스 개발에 활용할 수 있을 것 같습니다.

헷갈렸던 점#

처음에는 HTTP, API, REST, AJAX가 모두 웹 통신과 관련된 용어라는 사실만으로는 이들의 차이점을 파악하기 어려웠다. 특히 API와 REST가 어떻게 연결되는지, 그리고 AJAX가 이들과 어떤 관계를 가지는지 이해하는 데 시간이 걸렸다. 이 개념들을 하나의 그림으로 정리하는 것이 중요하다고 생각했다.

정리된 이해#

HTTP는 웹 서버와 클라이언트 간의 통신 규칙을 정의하고, API는 프로그램 간 상호작용을 위한 인터페이스 역할을 합니다. REST는 API 설계 방식 중 하나로 HTTP를 활용하여 데이터를 표현하고, AJAX는 웹 페이지 리로드 없이 서버와 비동기적으로 데이터를 주고받는 기술입니다. 이 개념들을 명확히 구분하고 실습을 통해 연결하면 서버와의 통신 과정을 더 잘 이해할 수 있습니다.

// fetch를 이용한 HTTP GET 요청 예시
fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));

3. Axios로 API 데이터 요청하기: 초보자를 위한 가이드#

무엇을 배웠나#

Axios를 사용하여 REST API 데이터를 요청할 때 Promise 문법과 async/await 문법을 혼동하고 있었는데, Axios 자체가 Promise 기반이고 둘 다 사용할 수 있다는 것을 알게 되었다. 또한, Axios 응답 객체에서 데이터를 안전하게 접근하기 위해 구조분해 할당을 사용하는 방법을 익혔다. 이 노트를 통해 기본 Axios GET 요청을 수행하고 응답 데이터를 처리하는 방법을 실습해보았다.

헷갈렸던 점#

Axios를 처음 사용할 때 Promise와 async/await 문법이 어떻게 사용되는지, 그리고 어떤 상황에 어떤 방식을 선택해야 할지 명확하게 이해하지 못했습니다. 또한, 응답 객체에서 필요한 데이터를 추출하는 과정, 특히 구조분해 할당을 사용하는 부분이 익숙하지 않았습니다.

정리된 이해#

Axios는 Promise 기반으로 작동하며, .then() 메서드 또는 async/await을 사용하여 API 요청 결과를 처리할 수 있습니다. Axios 응답 객체에서 데이터를 추출할 때는 구조분해 할당을 통해 data 속성을 간결하게 접근할 수 있습니다. async/await을 사용하면 에러 핸들링이 더 직관적이고 가독성이 좋습니다.

axios.get(url)
    .then(({data}) => {
        console.log('API 데이터:', data);
    });

4. 포켓몬 API 활용, 초보자를 위한 이미지 처리 및 요청 구조 이해#

무엇을 배웠나#

PokeAPI를 통해 포켓몬 정보를 가져오는 과정에서 이미지 처리 오류를 겪었는데, 여러 이미지 URL을 처리할 때 변수를 덮어쓰는 방식 대신 배열에 저장하고 반복하여 사용하는 방식으로 수정했다. API 요청 구조를 이해하고, 첫 번째 요청으로 목록을 가져온 후, 각 포켓몬의 상세 정보를 가져오는 두 번째 요청을 하는 방식으로 전체적인 흐름을 파악했다. 이렇게 개선된 코드를 통해 포켓몬의 다양한 이미지를 정상적으로 표시할 수 있게 되었다.

헷갈렸던 점#

포켓몬 이미지를 가져오는 과정에서 여러 이미지 URL을 처리할 때 content 변수를 덮어쓰는 방식 때문에 어떤 이미지만 표시되는 문제가 있었고, #overlay CSS는 준비되었지만 실제 이미지 표시 로직이 연결되지 않아 전체적인 흐름을 파악하기 어려웠다. API 요청 구조가 두 단계로 나뉘어 있다는 점도 처음에는 명확하게 이해하지 못했다.

정리된 이해#

포켓몬 API를 호출할 때, 첫 번째 요청으로 포켓몬 목록을 가져오고, 각 포켓몬의 상세 정보는 별도의 요청으로 가져와야 한다는 것을 깨달았습니다. 이미지 URL을 처리할 때는 여러 이미지를 덮어쓰는 방식 대신, 배열에 담아 관리하고, 비어있는 값은 필터링해야 합니다.

 const sprites = [
     data.sprites.front_default,
     data.sprites.back_default,
     data.sprites.front_shiny,
     data.sprites.back_shiny
 ].filter(Boolean); // 비어 있는 값 제거
