1. YOLO 분류와 탐지의 차이점 정리#

무엇을 배웠나#

처음에는 YOLO가 주로 물체 탐지 도구라고 생각했지만, yolo26n-cls.pt와 같은 파일명과 result.probs 구조를 통해 이미지 전체 분류(Classification) 작업도 수행할 수 있음을 알게 되었다. 특히 result.probs와 result.boxes의 형태가 다르다는 점과 top1, top5 키워드를 사용한 평가 지표가 classification task임을 확인하는 데 큰 도움이 되었다. 또한, epochs나 imgsz 같은 하이퍼파라미터가 훈련에 미치는 영향과 사전 학습 모델을 활용한 파인튜닝(Fine-tuning) 가능성을 통해 YOLO가 다양한 태스크를 수행할 수 있는 유연한 프레임워크임을 이해했다.

헷갈렸던 점#

처음 YOLO 수업을 접했을 때, 모든 과제가 ‘물체 탐지(Object Detection)‘인 줄 알았다. 특히 yolo26n-cls.pt라는 파일명에 -cls가 붙어 있어도, YOLO 프레임워크 자체가 주로 익숙한 ‘박스와 라벨’ 형태의 탐지 결과를 내놓기 때문에, 이것이 이미지 전체를 분류하는(Classification) 작업인지 구분하기 힘들었다.

가장 큰 혼란은 result.probs(분류 확률)와 result.boxes(탐지 박스)의 구조가 완전히 다르다는 점이었다. “모델을 학습시켰다"는 사실만으로도 끝나는 줄 알았는데, 테스트 코드에서 top1, top5 같은 키워드를 찾으려 하니 당황스러웠다. 또한, 학습이 완료된 후 생성되는 best.pt 체크포인트가 어디에 저장되는지, 그리고 시험 코드가 그 위치를 정확히 읽어오는지에 대한 불안감도 있었다.

이번 수업을 통해 YOLO가 단순히 ‘무엇을 찾는 도구’가 아니라, 목적에 따라 다른 태스크(task)를 수행할 수 있는 프레임워크라는 점을 깨달았다.

  • 분류(Classification): 이미지 전체가 어떤 카테고리에 속하는지를 판단하는 것. (yolo26n-cls.pt, result.probs)
  • 탐지(Detection): 이미지 내에서 ‘무엇이’ 어디에 위치하고 있는지를 찾는 것. (yolo26n.pt, result.boxes)

특히 epochs(학습 횟수), imgsz(이미지 크기), batch(배치 크기) 같은 하이퍼파라미터가 훈련에 어떻게 영향을 미치는지 감을 잡을 수 있었다. 그리고 사전 학습된 모델에 새로운 데이터를 추가로 학습시키는 ‘추가 학습(Fine-tuning)‘이 가능하다는 점은 매우 실용적이었다.

정리된 이해#

YOLO는 탐지뿐만 아니라 이미지 전체를 분류하는 작업도 수행할 수 있는 범용 프레임워크다. result.probs와 result.boxes 같은 결과 객체의 구조가 태스크에 따라 다르다는 점을 명확히 구분하는 것이 중요하다. 특히 사전 학습된 모델을 활용한 파인튜닝은 새로운 데이터 상황에 빠르게 적응할 수 있는 실용적인 방법이다.

# 1. YOLO Classification 모델 로드 (이미지 전체 분류용)
from ultralytics import YOLO

model = YOLO('yolo26n-cls.pt')  # classification 전용 가중치 파일

# 2. 학습 실행
results = model.train(
    data='fashion-mnist-data.yaml',  # 데이터셋 설정 파일 경로
    epochs=10,                       # 학습 반복 횟수
    imgsz=224,                       # 입력 이미지 크기 (가로/세로 pixel)
    batch=16                         # 한 번에 처리할 샘플 수
)

# 3. 훈련 완료 후 최고 성능 모델 저장 경로 확인
print(f"Best model saved at: {results.save_dir}/weights/best.pt")

# 4. 테스트 및 예측 (분류 확률 출력)
test_results = model.val(data='fashion-mnist-data.yaml', split='test')
probs = test_results.probs  # 클래스별 확률 분포 (top1, top5 등 포함)
print(f"Top-1 Accuracy: {profs.top1}")

2. 영상 추론·클래스 필터링·OpenCV 추적 (초보자 워킹 노트)#

무엇을 배웠나#

YOLO의 predict()와 track()는 박스 그리기라는 결과물은 비슷하지만, 전자는 프레임마다 독립적으로 물체를 탐지하는 반면 후자는 객체에게 ID를 부여해 연속성을 유지한다는 점이 핵심입니다. 또한 cv2.resize()의 인자 순서가 ‘(너비, 높이)‘임을 이해하고 적용해야 화면이 찌그러지는 문제를 예방할 수 있습니다. 마지막으로 result.plot(), cv2.imshow(), waitKey()는 각각 이미지 생성, 표시, 대기라는 명확한 역할을 수행하므로 이들을 분리해서 생각하면 코드의 의도가 명확해집니다.

헷갈렸던 점#

처음에는 YOLO의 predict()와 track()가 화면에 비슷한 박스를 그려주니 역할이 무엇인지 구분하기 어려웠습니다. 특히 show=True와 track()를 사용하면 창이 즉시 뜨고 박스가 그려져 있어, 두 함수의 차이를 혼동하기 쉽습니다. 또한 cv2.resize()의 인자 순서를 (너비, 높이)로 착각하다가 화면이 찌그러져 당황한 경험이 있습니다.

정리된 이해#

YOLO의 predict()는 매 프레임마다 객체를 새로 탐지하는 것이고, track()는 기존에 인식한 객체에게 ID를 부여해 연속성을 유지하며 추적하는 역할입니다. 영상 처리의 핵심은 탐지와 추적을 분리하여 생각하고, 표시 관련 함수인 plot(), imshow(), waitKey()가 각각 이미지 생성, 화면 출력, 대기 기능을 수행한다는 점을 명확히 구분해야 합니다.

# 카메라 또는 영상 파일 열기
cap = cv2.VideoCapture('sample.mp4')

while cap.isOpened():
    success, frame = cap.read()
    if not success:
        break

    # YOLO 탐지 수행 (박스 그리기 포함)
    results = model.predict(frame)

    # 결과 이미지 추출 (plot 메서드 사용)
    annotated_frame = results[0].plot()

    # 화면에 표시
    cv2.imshow('YOLO Tracking', annotated_frame)

    # 1ms 대기, 'q' 키를 누르면 종료
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()

3. Intel Arc XPU 기반 사람 탐지 구현기: 입력·추론·표시 분리#

무엇을 배웠나#

YOLO 모델은 탐지 결과(박스 정보)를 반환할 뿐, 화면 표시나 콘솔 출력은 별도의 단계임을 명확히 이해하게 되었다. show=False 옵션이 영상 출력을 차단하는 것이 아니라 라이브러리 창을 숨기는 역할이라는 점도 중요한 학습 포인트였다. 또한 하드웨어 사양에 맞는 장치 지정과 fail-fast 정책 적용의 필요성을 통해 안정적인 실행 환경을 구성할 수 있게 되었다.

헷갈렸던 점#

처음에는 ‘사람 탐지’ 결과가 콘솔에 출력되는 것과 영상이 화면에 뜨는 것이 같은 과정인 줄 알았지만, show=False 옵션은 모델의 탐지 자체를 멈추는 것이 아니라 라이브러리 창을 끄는 역할뿐이라는 점을 깨닫고 큰 혼란이 있었습니다. 또한 Intel Arc XPU 환경에서 코드가 의도한 대로 실행되지 않을까 걱정하며 하드웨어 호환성 검증에 시간을 할애해야 했습니다.

정리된 이해#

YOLO 모델은 탐지 결과(박스 정보)를 반환할 뿐, 화면 표시나 콘솔 출력은 별도의 단계에서 이루어져야 한다. show=False 옵션은 라이브러리 내부 창을 끄는 것이지 탐지를 멈추는 것이 아니며, 하드웨어 사양에 따라 실행 백엔드를 선택하고 실패 시 빠르게 중단하는 정책이 필요하다.

# YOLO 모델 로드 (Intel Arc XPU 지원 확인)
model = YOLO('yolov8n.pt')

# 입력 소스 설정 (웹캠 또는 영상 파일)
USE_WEBCAM = True  # True: 웹캠, False: 영상 파일 경로 지정

# 장치 및 실패 정책 설정
device = 'xpu:0' if torch.cuda.is_available() else 'cpu'  # Intel Arc XPU 지정 (fallback 방지)
confidence_threshold = 0.25

# 사람 클래스 탐지만 수행 (COCO 데이터셋 기준 class ID 0)
classes_to_detect = [0]

# 비디오 캡처 초기화
if USE_WEBCAM:
    cap = cv2.VideoCapture(0)  # 기본 웹캠 인덱스
else:
    cap = cv2.VideoCapture('sample_video.mp4')  # 영상 파일 경로

while cap.isOpened():
    success, frame = cap.read()

    if not success:
        print("영상 종료 또는 캡처 실패")
        break

    # YOLO 모델 추론 (사람 클래스만 필터링, 화면 표시 비활성화)
    results = model(frame, conf=confidence_threshold, classes=classes_to_detect, verbose=False)

    # 탐지 결과 박스 그리기 (표시 책임 분리)
    annotated_frame = results[0].plot()  # 박스가 그려진 프레임 반환

    # 콘솔에 탐지 정보 출력 (알림 책임 분리)
    for box in results[0].boxes:
        class_id = int(box.cls[0])
        confidence = float(box.conf[0])
        print(f"탐지: 사람 (신뢰도: {confidence:.2f})")

    # 화면 표시 (렌더링 책임 분리)
    cv2.imshow('Person Detection', annotated_frame)

    # 'q' 키를 누르면 종료
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

# 리소스 해제
cap.release()
cv2.destroyAllWindows()

4. 화면 투명 오버레이 실험: 영역 감지 실패와 저부하 설계#

무엇을 배웠나#

화면 특정 영역을 감지하려면 캡처, 추론, 오버레이라는 세 단계가 각각 독립적으로 작동해야 한다는 점을 깨달았습니다. 특히 투명도 설정은 코드 문법과 상관없이 운영체제나 그래픽 드라이버의 영향을 많이 받아 실제 화면에 반영되지 않을 수 있다는 사실을 이해하게 되었습니다.

헷갈렸던 점#

처음에는 ‘화면 특정 영역 감지’라는 목표가 너무 추상적이어서 좌표와 캡처 범위를 잡는 것이 막막했습니다. 특히 ‘투명 오버레이’ 부분이 헷갈려서, 코드가 에러 없이 돌아간다고 해서 실제 모니터 위에 얹힌 창이 투명하게 보이는 것은 아니라는 점을 혼동했던 것이 가장 큰 실수였습니다. 핵심은 캡처, 추론, 오버레이 세 단계가 따로 노는 것을 막는 것이었고, Tkinter의 -transparentcolor 설정은 운영체제나 그래픽 드라이버 환경에 따라 기대한 대로 작동하지 않을 수 있음을 깨닫고부터는 “코드가 맞더라도 화면이 안 변하면 실패"로 받아들이게 되었습니다.

정리된 이해#

화면 특정 영역을 감지해 결과를 표시하는 작업은 크게 캡처, 추론, 오버레이 세 단계로 나뉘며, 각 단계가 독립적으로 작동하도록 설계해야 한다. 특히 투명 오버레이 기능은 코드 문법이 맞더라도 운영체제나 그래픽 드라이버 환경에 따라 실제 화면이 변하지 않을 수 있으므로, 시각적 결과와 코드 동작을 별개로 판단하는 것이 중요하다.

import cv2
import numpy as np
from mss import mss

# 1. Capture: 화면 영역 캡처 (mss 사용)
with mss() as sct:
    # 모니터 전체가 아닌 특정 영역만 지정 (예: 좌상단 400x300 픽셀)
    monitor = {"top": 100, "left": 200, "width": 400, "height": 300}

    # 화면 캡처 (BGRA 형식)
    img = np.array(sct.grab(monitor))

    # RGB로 변환 (모델 입력에 맞춤)
    frame = cv2.cvtColor(img, cv2.COLOR_BGRA2RGB)

# 2. Inference: 모델에 넣어 탐지 (가상의 함수)
# results = detector.detect(frame)
# detections = results.xyxy[0].tolist() # [x1, y1, x2, y2, conf, class]

# 예시 탐지 결과 (사용자 정의)
detections = [[150, 100, 300, 250, 0.9, 0]]

# 3. Overlay: 탐지 결과를 원본 화면 위에 표시
# mss로 캡처한 img는 BGRA이므로 투명 처리가 용이함
overlay = img.copy()

for *box, conf, cls in detections:
    x1, y1, x2, y2 = map(int, box)

    # 탐지된 사각형 영역에 초록색 박스 그리기 (투명도 50%)
    cv2.rectangle(overlay, (x1, y1), (x2, y2), (0, 255, 0, 128), 2)

# 원본 화면과 오버레이 합성 (알파 블렌딩)
# alpha=0.5: 투명도 50%로 혼합
output = cv2.addWeighted(overlay, 0.5, img, 0.5, 0)

# 표시 (cv2.imshow는 BGRA를 지원하므로 직접 사용 가능)
cv2.imshow("Screen Overlay", output)
cv2.waitKey(1)

5. 강의 화면 OCR 실험: 캡처부터 인식까지#

무엇을 배웠나#

OCR과 YOLO가 같은 도구가 아니라는 점, 그리고 화면 전체 분석이 아니라 특정 영역 글자 인식에 집중해야 한다는 점을 명확히 이해할 수 있었다. 특히 캡처된 이미지가 올바른 입력인지 확인하는 과정이 무엇보다 중요하다는 사실을 실감했다. 앞으로는 OCR 실행 전 화면 구성을 꼼꼼히 점검하며 신뢰도 값을 해석하는 연습을 해야겠다.

헷갈렸던 점#

처음에는 YOLO와 OCR이 같은 도구인지 구분하기 어려웠습니다. 화면 전체를 분석한다는 점에서 두 기능이 섞여 있다고 느껴서, 모델이 ‘무엇을’ 찾는지를 먼저 파악하지 않으면 엉뚱한 결과를 얻을까 봐 두려웠습니다. 또한 OCR의 신뢰도 값이 무조건 정확한 정답인 줄 알았는데, 글씨 크기나 화질에 따라 오류가 날 수 있다는 점이 초보자로서는 감 잡기 힘들었습니다.

정리된 이해#

YOLO와 OCR은 화면 분석에서 서로 다른 역할을 수행한다. YOLO는 이미지 내 객체를 탐지하고 박스를 그리는 역할을 맡으며, OCR은 탐지된 영역 내에서 글자를 인식해 텍스트를 추출하는 전담 도구이다. 따라서 화면 캡처 전 올바른 입력 여부를 확인하는 과정이 무엇보다 중요하다.

# OCR 인식 수행 및 결과 시각화 예시 (노트 기반)

import cv2
from PIL import ImageGrab
import pyocr
import pyocr.builders

# 1. 화면 캡처 (강의 브라우저 영역)
# bbox = (left, top, right, bottom) 형태로 조정 필요
img = ImageGrab.grab(bbox=(0, 0, 1920, 1080))

# 2. OCR 도구 초기화 (한국어 지원 PP-OCRv5 가정)
tools = pyocr.get_available_tools()
if len(tools) == 0:
    print("OCR 툴을 찾을 수 없습니다.")
else:
    tool = tools[0]

    # 3. 글자 인식 수행
    # lang='kor'는 한국어 지원을 의미하며, builder에 confidence 포함 요청
    text = tool.image_to_string(
        img,
        lang="kor",
        builder=pyocr.builders.TextBuilder(tesseract_layout=6)
    )

    # 4. 신뢰도 점수 및 인식된 텍스트 출력
    print("=== 인식 결과 ===")
    print(f"인식된 문장: {text}")

설명: 위 코드는 노트에 기술된 흐름(캡처 → OCR 실행 → 결과 출력)을 파이썬으로 구현한 예시입니다. ImageGrab로 화면을 캡처하고, pyocr 라이브러리를 통해 한국어(OCR) 인식을 수행한 뒤, 인식된 문장과 신뢰도 정보를 콘솔에 출력하는 구조입니다.

강사님의 Git 원본과 제 로컬 기록이 뒤섞여 있어, 08, 08-1, 08-2가 연속된 버전인 줄 알았으나 실제로는 각기 다른 검증 단계와 목적을 가진 독립적인 실험들이었다. 특히 OCR과 투명 화면 관련해 실행 전부터 결과가 확인이 안 되는 상태였으며, XPU 설정 역시 장비 환경에 따라 실제 성능이 달라질 수 있다는 점을 확인했다. 무엇보다도 “문법 검사 성공"만으로는 실제 모델 동작이나 원하는 기능 구현이 이루어졌는지 판단할 수 없다는 점이 가장 중요한 교훈이 되었다.

헷갈렸던 점#

정리된 이해#

08, 08-1, 08-2는 연속된 버전이 아니라, 사람 탐지, 투명 오버레이, OCR 실험 등 각기 다른 목적을 가진 독립적인 작업들이었다. 코드가 에러 없이 실행되었다고 해서 화면이 제대로 나오거나 기능이 작동하는 것은 아니므로, “문법 검사 성공"은 실제 모델 동작의 증거가 되지 않는다. 마지막으로 OCR과 투명 UI 관련해 파일 설치부터 인식까지 전 과정이 미확인 상태였고, XPU 설정 역시 실제 장비 환경에 따라 성능 차이가 발생할 수 있는 변수였다.

오늘 오후 전체에서 배운 것#

YOLO는 탐지뿐만 아니라 분류와 파인튜닝이 가능한 유연한 프레임워크이며, predict와 track의 ID 부여 여부나 인자 순서 등 세부적인 구현 차이가 결과에 큰 영향을 미친다. 또한 모델 실행 전후로 화면 표시와 데이터 처리를 분리하고, 하드웨어 환경과 실제 출력(오버레이/OCR) 사이의 격차를 이해하는 것이 안정적인 개발을 위한 필수 조건임을 깨달았다.

다음에 조심할 것#

다음에 조심할 것은 다음과 같다.

  1. YOLO 모델이 반환하는 탐지 결과와 화면 표시 또는 OCR 처리는 별도의 단계로 분리하여 설계해야 하며, show=False 옵션이 창 생성을 차단한다는 사실을 전제로 코드를 작성해야 한다.
  2. 하드웨어 사양(예: Intel Arc XPU)에 맞는 장치 지정과 fail-fast 정책 적용은 안정적인 실행 환경을 구성하는 필수 조건이며, 운영체제나 드라이버 환경에 따라 화면 오버레이나 투명도 설정이 실제와 다르게 나타날 수 있음을 인지해야 한다.
