1. 집합 연산자: SELECT 결과표끼리 계산하기#

무엇을 배웠나#

오후 수업은 SQL 집합 연산자에서 시작했다. 집합 연산자는 원본 테이블을 물리적으로 합치는 것이 아니라, 각각의 SELECT가 만든 결과표끼리 계산하는 방식이다.

UNION     = 두 결과표를 합치고 중복 제거
UNION ALL = 두 결과표를 중복 제거 없이 아래로 붙임
INTERSECT = 두 결과표에 모두 있는 행만 남김
EXCEPT    = 첫 번째 결과표에서 두 번째 결과표를 뺌

공통 규칙은 다음과 같다.

1. SELECT 컬럼 수가 동일해야 한다.
2. 대응 컬럼의 데이터 타입이 호환되어야 한다.
3. 최종 결과 컬럼명은 첫 번째 SELECT의 컬럼명을 따른다.
4. ORDER BY는 최종 결합 결과에 한 번만 적용한다.

JOIN과 집합 연산은 방향이 다르다.

JOIN = 관계를 따라 옆으로 붙이기
UNION / UNION ALL = 같은 모양의 결과표를 아래로 붙이기

구매 이력 유무별 고객 분류는 “구매 이력 있음” 명단과 “구매 이력 없음” 명단을 만든 뒤 아래로 붙이는 구조다.

SELECT
    c.CustomerId,
    c.LastName || ' ' || c.FirstName AS customer_name,
    '구매 이력 있음' AS purchase_status
FROM customers AS c
WHERE c.CustomerId IN (
    SELECT DISTINCT CustomerId
    FROM invoices
)

UNION

SELECT
    c.CustomerId,
    c.LastName || ' ' || c.FirstName AS customer_name,
    '구매 이력 없음' AS purchase_status
FROM customers AS c
WHERE c.CustomerId NOT IN (
    SELECT DISTINCT CustomerId
    FROM invoices
)
ORDER BY CustomerId;

헷갈렸던 점#

목적은 고객인데 쿼리에서는 CustomerId 숫자만 먼저 뽑는 것이 헷갈렸다. 하지만 CustomerId 결과는 최종 보고서가 아니라 다음 단계에서 고객 이름과 이메일을 붙이기 위한 대상자 ID 목록이다.

이름까지 필요하면 집합 연산 결과를 다시 customers와 연결해야 한다.

SELECT
    c.CustomerId,
    c.FirstName,
    c.LastName,
    c.Email
FROM customers AS c
INNER JOIN (
    SELECT CustomerId
    FROM invoices
    WHERE strftime('%Y', InvoiceDate) = '2009'

    EXCEPT

    SELECT CustomerId
    FROM invoices
    WHERE strftime('%Y', InvoiceDate) = '2010'
) AS target_customers
    ON c.CustomerId = target_customers.CustomerId
ORDER BY c.CustomerId;

정리된 이해#

집합 연산은 ERD 연결보다 결과표 모양이 먼저다.

JOIN은 관계가 맞아야 한다.
UNION/INTERSECT/EXCEPT는 결과표 컬럼 모양이 맞아야 한다.

2. 문제본 기준 집합 연산 복습: UNION부터 EXCEPT까지#

무엇을 배웠나#

문제본 기준 복습에서는 집합 연산자를 더 일반적인 예제로 다시 정리했다.

UNION은 합치고 중복을 제거한다.

SELECT student_number, student_name
FROM lecture_basic

UNION

SELECT student_number, student_name
FROM lecture_special
ORDER BY student_number ASC;

UNION ALL은 중복을 제거하지 않고 모두 붙인다. 중복 자체가 횟수 정보라면 UNION ALL이 맞다.

SELECT lecture_name
FROM lecture_basic

UNION ALL

SELECT lecture_name
FROM lecture_special
ORDER BY lecture_name ASC;

INTERSECT는 양쪽에 모두 있는 것만 남긴다.

SELECT student_number, student_name
FROM lecture_basic

INTERSECT

SELECT student_number, student_name
FROM lecture_special
ORDER BY student_number ASC;

EXCEPT는 앞 SELECT 결과에서 뒤 SELECT 결과를 뺀다.

SELECT student_number, student_name
FROM lecture_special

EXCEPT

SELECT student_number, student_name
FROM lecture_basic
ORDER BY student_number ASC;

헷갈렸던 점#

EXCEPT는 방향이 핵심이다.

A EXCEPT B = A에는 있고 B에는 없는 것
B EXCEPT A = B에는 있고 A에는 없는 것

즉 EXCEPT는 SQL판 뺄셈이라서 방향을 틀리면 결과가 완전히 바뀐다.

정리된 이해#

집합 연산 문제를 읽을 때는 먼저 어떤 목록 A와 목록 B를 만들 것인지 정해야 한다.

둘 중 하나라도 포함되면? UNION
중복까지 전부 보고 싶으면? UNION ALL
양쪽 모두에 있으면? INTERSECT
A에는 있는데 B에는 없으면? EXCEPT

3. UNION ALL 리포트: 장르별 통계와 전체합계 붙이기#

무엇을 배웠나#

UNION ALL은 리포트에서 “상세 행들 + 전체합계 행”을 붙일 때 유용하다.

처음에는 장르별 트랙 수와 전체 트랙 수를 합치는 구조로 이해했다.

SELECT
    g.Name AS genre_name,
    COUNT(t.TrackId) AS track_count
FROM genres AS g
LEFT JOIN tracks AS t
    ON g.GenreId = t.GenreId
GROUP BY
    g.GenreId,
    g.Name

UNION ALL

SELECT
    '전체 합계' AS genre_name,
    COUNT(*) AS track_count
FROM tracks;

이후 수업에서는 장르별 매출 통계 리포트로 확장됐다. 이때 중심 테이블은 tracks가 아니라 실제 판매 내역이 있는 invoice_items다.

invoice_items = 판매 상세
tracks        = 트랙 정보
genres        = 장르 정보

연결 경로는 다음과 같다.

invoice_items.TrackId = tracks.TrackId
tracks.GenreId = genres.GenreId

장르별 청구서 수, 판매수량, 총매출은 다음처럼 구한다.

SELECT
    g.Name AS 장르,
    COUNT(DISTINCT ii.InvoiceId) AS 청구서수,
    SUM(ii.Quantity) AS 판매수량,
    ROUND(SUM(ii.UnitPrice * ii.Quantity), 2) AS 총매출
FROM invoice_items AS ii
INNER JOIN tracks AS t
    ON ii.TrackId = t.TrackId
INNER JOIN genres AS g
    ON t.GenreId = g.GenreId
GROUP BY
    g.GenreId,
    g.Name;

전체합계 행까지 붙이면 다음과 같다.

SELECT
    g.Name AS 장르,
    COUNT(DISTINCT ii.InvoiceId) AS 청구서수,
    SUM(ii.Quantity) AS 판매수량,
    ROUND(SUM(ii.UnitPrice * ii.Quantity), 2) AS 총매출
FROM invoice_items AS ii
INNER JOIN tracks AS t
    ON ii.TrackId = t.TrackId
INNER JOIN genres AS g
    ON t.GenreId = g.GenreId
GROUP BY
    g.GenreId,
    g.Name

UNION ALL

SELECT
    '— 전체합계' AS 장르,
    COUNT(DISTINCT ii.InvoiceId) AS 청구서수,
    SUM(ii.Quantity) AS 판매수량,
    ROUND(SUM(ii.UnitPrice * ii.Quantity), 2) AS 총매출
FROM invoice_items AS ii
INNER JOIN tracks AS t
    ON ii.TrackId = t.TrackId
INNER JOIN genres AS g
    ON t.GenreId = g.GenreId;

헷갈렸던 점#

장르별 트랙 수와 장르별 매출 통계는 비슷해 보이지만 중심 테이블이 다르다.

장르별 트랙 수 = tracks 중심
장르별 매출 통계 = invoice_items 중심

정리된 이해#

문제를 볼 때는 먼저 중심 사건을 찾아야 한다.

음악 정보 문제 = tracks 중심
판매/매출 문제 = invoice_items 중심
고객 청구 문제 = invoices 또는 customers 중심

4. WITH RECURSIVE: 직원 조직도 펼치기#

무엇을 배웠나#

SQLite에서는 계층형 질의를 WITH RECURSIVE CTE로 작성한다. 계층형 질의는 부모-자식 관계를 여러 단계 반복해서 따라가는 방식이다.

EmployeeId = 직원 자신의 ID
ReportsTo  = 이 직원의 관리자 EmployeeId

기본 구조는 Anchor와 Recursive로 나뉜다.

WITH RECURSIVE emp_hierarchy(
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo,
           0 AS lvl
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    SELECT e.EmployeeId, e.FirstName, e.LastName,
           e.Title, e.ReportsTo, h.lvl + 1
    FROM employees AS e
    JOIN emp_hierarchy AS h
        ON e.ReportsTo = h.EmployeeId
)
SELECT
       lvl AS 계층레벨,
       EmployeeId AS 직원ID,
       SUBSTR('                ', 1, lvl * 4)
           || FirstName || ' ' || LastName AS 직원명,
       Title AS 직책,
       ReportsTo AS 관리자ID
FROM emp_hierarchy
ORDER BY lvl, EmployeeId;

헷갈렸던 점#

e와 h가 어디서 나온 것인지가 헷갈렸다. 둘은 FROM/JOIN에서 생긴 별칭이다.

h = 이미 계층표에 들어간 상위 직원
e = 이번에 새로 찾을 부하 직원

핵심 연결은 다음이다.

ON e.ReportsTo = h.EmployeeId

즉 새 직원 e의 관리자 ID가 이미 찾은 직원 h의 직원 ID와 같으면, e는 h의 부하다.

정리된 이해#

재귀 CTE는 다음 반복으로 이해한다.

Root 직원 찾기
→ 그 직원의 부하 찾기
→ 그 부하의 부하 찾기
→ 더 이상 없을 때까지 반복

Anchor와 Recursive의 컬럼 개수와 순서가 같아야 한다는 점도 중요하다.

5. 테이블 역할표와 별칭: FROM/JOIN부터 읽기#

무엇을 배웠나#

SQL에서 가장 큰 장벽 중 하나는 별칭이다. 별칭은 작성자가 FROM 또는 JOIN에서 만든 임시 이름표다.

FROM invoice_items AS ii
INNER JOIN tracks AS t
    ON ii.TrackId = t.TrackId
INNER JOIN genres AS g
    ON t.GenreId = g.GenreId

별칭표는 다음과 같다.

ii = invoice_items
t  = tracks
g  = genres

쿼리는 SELECT부터 쓰여 있지만, 읽을 때는 FROM/JOIN부터 보는 편이 안전하다.

1. FROM/JOIN에서 별칭표 만들기
2. 중심 테이블 확인
3. 연결 경로 확인
4. SELECT에서 보여줄 컬럼 확인
5. GROUP BY와 집계 함수 확인
6. UNION/INTERSECT/EXCEPT가 있으면 결과표 모양 확인

헷갈렸던 점#

별칭은 SELECT에 먼저 보이지만 실제로는 아래쪽 FROM/JOIN에서 정의된다. 그래서 위에서부터 읽으면 h, ii, g 같은 이름이 갑자기 튀어나온 것처럼 보인다.

정리된 이해#

테이블을 이름이 아니라 역할로 본다.

tracks = 실제 곡 하나하나가 들어 있는 중심 테이블
albums = 곡이 들어 있는 앨범 설명 테이블
artists = 앨범을 만든 아티스트 설명 테이블
genres = 곡의 장르 설명 테이블
invoice_items = 실제 판매된 항목
invoices = 청구서/결제 머리 정보
customers = 고객 정보
employees = 조직도와 담당자 정보

총평#

오늘 오후 전체에서 배운 것#

오후 수업은 집합 연산자에서 시작해 UNION ALL 리포트, 장르별 매출 통계, WITH RECURSIVE 계층형 질의까지 이어졌다. 핵심은 SQL이 단순 조회가 아니라 여러 결과표를 만들고, 붙이고, 빼고, 반복해서 펼치는 조립 도구라는 점이었다.

UNION, INTERSECT, EXCEPT는 SELECT 결과표끼리 계산하는 방식이고, UNION ALL은 상세 행과 합계 행을 붙이는 보고서 작성에도 쓰인다. WITH RECURSIVE는 부모-자식 관계를 반복해서 펼쳐 조직도 같은 계층 구조를 만들 수 있다.

다음에 조심할 것#

집합 연산에서는 위쪽 SELECT와 아래쪽 SELECT의 컬럼 개수와 의미가 맞아야 한다. EXCEPT는 방향이 바뀌면 결과가 완전히 달라진다. UNION ALL 리포트에서는 현재 문제의 중심 테이블이 tracks인지 invoice_items인지 먼저 확인해야 한다.

재귀 CTE에서는 Anchor와 Recursive의 컬럼 개수와 순서가 같아야 한다. 별칭은 FROM/JOIN에서 정의되므로 쿼리를 해석할 때는 SELECT보다 FROM/JOIN을 먼저 읽어야 한다.
