1. JOIN, GROUP BY, HAVING으로 이탈 고객 찾기#

무엇을 배웠나#

날짜 집계 함수인 MAX()가 날짜 컬럼에서도 가장 최근 날짜를 찾는다는 것을 이해하게 되었고, HAVING 절이 GROUP BY 이후 집계된 결과에 조건을 걸어주는 역할을 한다는 것을 알게 되었다. 이를 통해 고객의 최근 주문 날짜를 기준으로 잠재 이탈 고객을 찾는 SQL 쿼리를 작성할 수 있게 되었고, WHERE와 HAVING 절의 차이점을 명확히 구분할 수 있게 되었다. 이제 날짜 관련 SQL 쿼리를 더 자신 있게 작성할 수 있을 것 같다.

헷갈렸던 점#

처음에는 MAX(orderDate)가 왜 가장 최근 날짜를 나타내는지, 그리고 HAVING 절이 왜 필요한지 잘 이해하지 못했습니다. MAX() 함수가 숫자 컬럼에서만 적용될 것이라고 생각했고, WHERE절로도 충분할 것이라고 생각했습니다. 날짜 컬럼에서의 MAX()의 의미와 HAVING 절의 역할에 대한 이해가 부족했습니다.

정리된 이해#

날짜 컬럼에서도 MAX() 함수는 가장 최근 날짜를 찾기 위해 사용되며, WHERE 절은 개별 행에 대한 조건을, HAVING 절은 그룹화된 결과에 대한 조건을 걸 때 사용합니다. 특히 고객별 마지막 주문 날짜를 기준으로 잠재적 이탈 고객을 찾을 때는 HAVING 절이 필수적입니다. 이 과정을 통해 고객 데이터 분석 및 관리 능력을 향상시킬 수 있습니다.

2. PARTITION BY와 RANK로 그룹별 순위 이해하기#

무엇을 배웠나#

윈도우 함수에서 PARTITION BY는 실제 테이블을 나누는 것이 아니라, 그룹별로 순위를 계산하는 기준을 설정하는 역할이라는 것을 알게 되었다. 또한, 윈도우 함수 내 ORDER BY와 최종 결과 출력 시의 ORDER BY는 서로 다른 역할을 한다는 것을 이해하고, 구체적인 예시를 통해 그 차이를 명확히 했다. 이제 윈도우 함수를 사용할 때 PARTITION BY의 역할과 ORDER BY의 다양한 용도를 더 명확하게 활용할 수 있을 것 같다.

헷갈렸던 점#

윈도우 함수에서 PARTITION BY를 처음 접했을 때, 테이블이 실제로 분할되는 것처럼 느껴져서 혼란스러웠고, ORDER BY가 쿼리 내에서 여러 역할을 하는 것 같아서 어떤 기준으로 해석해야 할지 몰랐습니다. 특히 국가별 순위 계산을 위한 ORDER BY와 최종 결과 정렬을 위한 ORDER BY의 차이점이 명확하게 이해되지 않았습니다.

정리된 이해#

윈도우 함수에서 PARTITION BY는 실제 테이블을 나누는 것이 아니라, 계산 범위를 그룹화하는 역할이고, ORDER BY는 윈도우 함수 내부에서는 정렬 기준, 최종 결과에서는 출력 순서를 결정합니다. 따라서 각 PARTITION BY 절은 개별적인 순위 계산 공간을 만들고, ORDER BY는 그 순위를 어떻게 보여줄지를 정하는 것이라고 이해했습니다. 이제 PARTITION BY가 어떻게 작동하는지 좀 더 명확하게 파악할 수 있을 것 같습니다.

3. OVER와 누적 합계로 집계 범위 이해하기#

무엇을 배웠나#

OVER() 함수가 집계 함수에 적용될 데이터 범위를 정의하는 역할을 한다는 것을 이해하게 되었고, ROUND 함수를 사용하여 소수점 자릿수를 지정할 수 있다는 점을 알게 되었다. 특히 OVER()가 비어있을 때 전체 행을 기준으로 계산한다는 점을 명확히 파악하게 되었으며, SUM 함수와 OVER() 함수의 차이를 통해 전체 합계와 누적 합계를 구분할 수 있게 되었다. 앞으로 다양한 상황에서 OVER()를 활용하여 데이터 분석을 수행할 수 있을 것 같다.

헷갈렸던 점#

처음에는 OVER()가 값을 올리는 함수인 줄 알았고, ROUND 함수 안의 숫자 2가 어떤 의미인지도 정확히 몰랐다. 특히 OVER()가 비어 있을 때 전체 행을 기준으로 계산된다는 점이 이해하기 어려웠다.

정리된 이해#

OVER()는 집계 함수가 적용될 데이터 범위를 설정하는 구문이고, ROUND 함수는 소수점 자릿수를 반올림하는 역할을 합니다. OVER()가 비어있으면 전체 행을 기준으로 계산하며, SUM 함수와 OVER()를 함께 사용하면 전체 합계 또는 누적 합계를 각 행에 적용할 수 있습니다.

SELECT
    InvoiceId,
    InvoiceDate,
    Total,
    ROUND(SUM(Total) OVER (), 2) AS GrandTotal,
    ROUND(SUM(Total) OVER (
        ORDER BY InvoiceDate
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ), 2) AS RunningTotal
FROM invoices
ORDER BY InvoiceDate
LIMIT 20;

4. 윈도우 프레임과 FIRST/LAST/LAG/LEAD 이해하기#

무엇을 배웠나#

윈도우 함수, 특히 ROWS BETWEEN 구문을 사용하는 부분을 이해하는 데 어려움을 겪었지만, UNBOUNDED PRECEDING과 UNBOUNDED FOLLOWING를 ‘무제한 첫 번째 행’과 ‘무제한 마지막 행’으로 단순화하여 개념을 파악할 수 있었다. FIRST_VALUE와 LAST_VALUE를 활용하여 각 국가별 최소/최대 청구 금액을 찾는 실습을 통해 윈도우 함수가 파티션 내의 행 범위를 어떻게 참조하는지 이해했다. Total 컬럼의 실제 의미를 파악하는 과정에서 혼란이 있었지만, 실습을 통해 윈도우 함수를 활용하는 방법을 익힐 수 있었다.

헷갈렸던 점#

윈도우 함수에서 UNBOUNDED PRECEDING이나 UNBOUNDED FOLLOWING 같은 표현이 영어 때문에 처음에는 무슨 의미인지 파악하기 어려웠어요. 특히 Total 컬럼이 실제로는 청구 금액을 나타내는 것인지, 아니면 다른 의미인지 헷갈렸습니다. 처음에는 윈도우 함수 내의 ROWS BETWEEN 구문이 어떻게 동작하는지 이해하는 데 시간이 좀 걸렸어요.

정리된 이해#

윈도우 함수에서 ROWS BETWEEN 구문은 파티션 내에서 특정 행들의 범위를 지정하는 역할을 하며, UNBOUNDED PRECEDING과 UNBOUNDED FOLLOWING는 각각 파티션의 시작과 끝을 의미합니다. FIRST_VALUE와 LAST_VALUE 함수를 사용하여 파티션 내에서 각 행의 최소값과 최대값을 쉽게 찾을 수 있습니다. Total 컬럼의 실제 의미를 파악하는 데 시간을 낭비했음을 기억해야겠습니다.

SELECT
    InvoiceId,
    BillingCountry,
    Total,
    FIRST_VALUE(Total) OVER (
        PARTITION BY BillingCountry
        ORDER BY Total ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS CountryMinTotal,
    LAST_VALUE(Total) OVER (
        PARTITION BY BillingCountry
        ORDER BY Total ASC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS CountryMaxTotal
FROM invoices
ORDER BY BillingCountry, Total;

5. PERCENT_RANK와 NTILE로 분포 읽기#

무엇을 배웠나#

PERCENT_RANK, CUME_DIST, NTILE 함수가 무엇을 의미하는지, 그리고 각각 어떤 방식으로 데이터를 분석하는 데 활용될 수 있는지 이해하게 되었습니다. 특히 PERCENT_RANK는 순위 위치를 비율로 나타내는 방식, CUME_DIST는 누적된 비율을 보여주는 방식이 처음에는 헷갈렸지만, 예시를 통해 개념을 명확히 할 수 있었습니다. 이 함수들을 활용하여 데이터 그룹화 및 분석을 수행할 수 있을 것 같습니다.

헷갈렸던 점#

PERCENT_RANK, CUME_DIST 함수가 이름만 보고는 어떤 값을 계산하는지 감이 잘 오지 않았습니다. 특히 PERCENT_RANK의 0~1 사이의 비율로 순위를 표현하는 방식과 CUME_DIST가 단순한 순위가 아닌 누적 비율을 보여주는 점이 처음에는 직관적으로 이해하기 어려웠습니다.

정리된 이해#

PERCENT_RANK는 데이터 내 순위를 0과 1 사이의 비율로 표현하며, CUME_DIST는 현재 행까지의 누적된 비율을 보여주는 함수입니다. NTILE은 데이터를 특정 개수의 그룹으로 나누어 분석을 용이하게 해주는 기능입니다. 이 세 함수는 데이터 분석 시 순위, 분포, 그룹화 등 다양한 방식으로 활용될 수 있습니다.

   ROUND(SUM(o.TotalAmount), 1) AS TotalSpent,
   PERCENT_RANK() OVER (ORDER BY SUM(o.TotalAmount) DESC) AS PercentileRank
FROM
   Orders o
JOIN
   Customers c ON o.CustomerId = c.CustomerId
GROUP BY
   c.CustomerId
ORDER BY
   PercentileRank DESC
LIMIT 10;
