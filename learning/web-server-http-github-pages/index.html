1. 로컬 서버#

왜 이걸 보게 됐나#

로컬 서버 개념을 배우게 된 건 웹 사이트 개발 과정을 이해하고 싶었기 때문이야. 내 컴퓨터에서 만든 웹 페이지를 어떻게 다른 사람에게 보여주는지, 그리고 그 과정에서 ‘서버’라는 것이 어떤 역할을 하는지 궁금했어. 특히 GitHub Pages를 사용하면서, 내 컴퓨터가 꺼져도 사이트가 유지되는 원리가 궁금해서 로컬 서버와 공개 서버의 차이를 명확히 하고 싶었어.

내가 헷갈린 지점#

처음에는 ‘서버’라는 단어가 내 컴퓨터에서 켜놓은 상태로 유지해야만 사이트가 보이는 공간이라고 생각했었다. 그래서 로컬 서버를 끄면 사이트가 사라지는 게 당연하게 느껴졌고, 항상 켜놓아야 한다는 부담감이 있었다. 하지만 ‘서버’의 의미가 훨씬 다양하고, GitHub Pages는 내 PC의 상태와 상관없이 작동하는 공개 호스팅 서비스라는 것을 알게 되었다.

시도한 코드 / 예시#

hugo server

결과와 해석#

hugo server 명령어를 실행하면 내 컴퓨터에서만 접근 가능한 임시 서버가 실행된다. 이 서버는 내가 끄면 즉시 사라지며, 인터넷 상의 다른 사람은 볼 수 없는 내 컴퓨터 안의 간단한 미리보기 환경이다. 로컬 서버는 실제 웹 서비스를 제공하는 서버가 아니라, 개발 과정에서 내용을 확인하기 위한 도구일 뿐이다.

정리된 이해#

로컬 서버는 내가 컴퓨터에서 작업하는 동안만 접속할 수 있는 임시 미리보기 환경이다. 즉, 컴퓨터를 끄면 사라지는, 인터넷에 공개되지 않는 서버이다. 로컬 서버는 실제 서비스가 아니라, 개발 및 확인을 위한 도구로 이해해야 한다.

2. GitHub Pages#

왜 이걸 보게 됐나#

블로그를 배포하고 싶어서 웹 서버와 관련된 개념들을 공부하게 되었고, 특히 무료로 간단하게 배포할 수 있는 GitHub Pages가 있어 이것부터 시작하게 되었다. 기존에는 웹 서버를 항상 켜두어야 한다는 부담감 때문에 배포를 망설였었는데, GitHub Pages는 이러한 부담감을 덜어주면서 시작점을 제공한다. 지금은 GitHub Pages를 통해 기본적인 블로그 배포를 이해하고, 더 나아가 다양한 웹 기술들을 탐구할 수 있는 발판을 마련했다.

내가 헷갈린 지점#

처음에는 ‘서버’라는 단어가 너무 포괄적이어서, 내 로컬 서버와 GitHub Pages를 어떻게 구분해야 할지 막막했다. 특히 GitHub Pages가 어떻게 24시간 사이트를 유지할 수 있는지 이해하는 데 어려움을 겪었고, 내 PC가 항상 켜져 있어야 한다는 압박감에 휩싸였었다. 로컬 서버는 임시 미리보기일 뿐이고, 실제 공개는 GitHub 서버에서 이뤄진다는 것을 깨닫고 마음이 놓였다.

시도한 코드 / 예시#

Markdown → hugo build → HTML 파일 → git push → GitHub Pages 공개

결과와 해석#

GitHub Pages는 내 PC를 끄더라도 웹사이트를 인터넷에 계속 보여주는 서비스야. Hugo로 만든 정적 웹사이트를 GitHub 저장소에 올리면 자동으로 GitHub 서버에서 공개해 줘서, 별도의 서버를 켜두는 번거로움 없이 웹사이트를 배포할 수 있어. 간단하게 말하면, 내 웹사이트를 24시간 온라인 상태로 유지해 주는 무료 호스팅 서비스라고 이해하면 돼.

정리된 이해#

GitHub Pages는 내가 만든 정적 웹사이트 파일을 GitHub 서버에 올려 24시간 공개하는 서비스다. 내 PC가 꺼져도 사이트가 계속 보이고, 나는 PC를 항상 켜두고 서버 관리할 필요가 없다. GitHub Pages는 단순히 파일을 저장하는 공간이 아니라, 웹사이트를 세상에 보여주는 공개 호스팅 역할을 한다.

3. 정적 사이트#

왜 이걸 보게 됐나#

원래는 복잡한 동적 웹 사이트를 만들고 싶었지만, 유지보수의 어려움과 비용 때문에 쉽게 접근할 수 있는 정적 사이트에 관심을 갖게 되었다. 특히 GitHub Pages를 활용하면 무료로 웹 사이트를 호스팅할 수 있다는 점이 매력적이었다. 정적 사이트 생성 도구인 Hugo를 배우면서 웹 서버와 HTTP에 대한 기본적인 이해가 필요하다는 것을 깨달았고, 이를 통해 웹 개발의 기초를 다지기로 결심했다.

내가 헷갈린 지점#

처음에는 정적 사이트가 ‘무조건 웹 서버를 켜놓고 유지해야 하는 것’이라고 생각했어요. 정적 파일만 제공하면 되는 게 아니라, 뭔가 지속적인 관리가 필요하다고 착각했죠. 결국 Hugo로 빌드해서 GitHub Pages에 올리면 서버 관리가 필요 없다는 걸 이해하고 나니 마음이 놓였습니다.

시도한 코드 / 예시#

Markdown → hugo build → HTML 파일 → git push → GitHub Pages 공개

결과와 해석#

정적 사이트는 HTML 파일이 미리 만들어져서 웹 서버가 요청을 받으면 그 파일을 그대로 전달하는 방식이야. 내 블로그처럼 동적인 기능이 필요 없는 사이트에 적합하고, GitHub Pages 같은 곳에 쉽게 배포할 수 있다는 장점이 있어. Hugo로 마크다운 파일을 HTML로 변환하고, 그걸 GitHub Pages에 올리는 과정을 통해 정적 사이트를 직접 만들 수 있었어.

정리된 이해#

정적 사이트는 미리 만들어진 HTML 파일을 그대로 제공하는 방식으로, GitHub Pages와 같이 파일을 호스팅하는 서버를 통해 24시간 공개할 수 있습니다. 내 컴퓨터가 꺼져 있어도 사이트가 계속 보인다는 것은, 내 컴퓨터가 항상 켜져 있는 서버가 아니라는 것을 의미합니다. 정적 사이트는 로그인이나 댓글과 같은 동적인 기능이 필요 없을 때 적합합니다.

4. HTTP request#

왜 이걸 보게 됐나#

HTTP request/response 구조를 배우게 된 건, 내 블로그를 GitHub Pages로 공개하면서 ‘어떻게 내 컴퓨터가 꺼져도 웹 페이지가 보여질까?‘라는 궁금증에서 비롯됐어. 단순히 파일을 업로드하는 것만으로는 설명이 안 되고, 웹 브라우저와 서버 간에 어떤 주고받음이 일어나는지를 알아야 전체적인 흐름을 이해할 수 있을 것 같거든. 특히 GitHub Pages가 어떻게 작동하는지 더 깊이 파악하려면 HTTP 통신 과정을 알아야 할 것 같아.

내가 헷갈린 지점#

처음에는 HTTP 요청이 단순한 파일 요청인 줄 알았다. 예를 들어, 웹 브라우저가 서버에 특정 HTML 파일을 달라고 보내는 요청인 줄 알았다. 하지만 HTTP는 단순히 파일을 주고받는 것 이상으로, 헤더 정보, 상태 코드, 다양한 메서드(GET, POST 등)를 포함하는 복잡한 통신 방식인 것을 알게 되었다. 이 모든 정보가 요청과 응답 과정에서 중요한 역할을 한다는 것을 이해하는 데 시간이 걸렸다.

시도한 코드 / 예시#

이 워킹 노트에는 HTTP request/response 구조에 대한 코드 예시가 없습니다. 따라서 아무것도 출력하지 않습니다.

결과와 해석#

HTTP 요청/응답 구조는 웹 브라우저가 서버에 정보를 요청하는 과정과 서버가 그 요청에 대한 응답을 보내는 과정을 말한다. 예를 들어, 브라우저에서 특정 웹페이지 주소를 입력하면 브라우저는 해당 주소의 서버에 요청을 보내고, 서버는 요청받은 웹페이지의 HTML 파일을 브라우저에 응답으로 보내준다. 이 과정에서 HTTP 헤더를 통해 요청과 응답에 대한 추가 정보(예: 콘텐츠 유형, 쿠키)가 함께 전달된다.

정리된 이해#

HTTP request는 클라이언트(예: 웹 브라우저)가 서버에 특정 리소스를 요청할 때 보내는 메시지이고, response는 서버가 그 요청에 대한 응답으로 보내는 메시지입니다. 이 과정은 클라이언트가 웹 페이지를 로드하거나 데이터를 가져오는 등의 동작을 가능하게 하는 기본적인 통신 방식입니다. 요청과 응답은 HTTP라는 약속된 규약에 따라 이루어집니다.

총평#

오늘 전체에서 배운 것#

로컬 서버는 내가 끄면 사라지는 임시 작업 공간이고, GitHub Pages는 내 PC가 꺼져 있어도 사이트를 계속 보여주는 공개 호스팅 공간이라는 것을 명확히 알게 되었다. Hugo는 사이트를 만드는 도구일 뿐, 서버가 아니라는 것도 이해했다.

다음에 조심할 것#

서버의 종류와 역할에 대해 혼동하지 않도록 계속해서 명확히 구분해야겠다. 특히 로컬 개발 환경과 실제 배포 환경의 차이점을 항상 염두에 두어야 할 것 같다.

다음 복습 주제#

HTTP request/response 구조와 URL 구조를 좀 더 자세히 알아봐야겠다. DNS가 어떻게 동작하는지 궁금하고, 실제 서버에 접속하는 SSH 과정도 익혀보고 싶다.
