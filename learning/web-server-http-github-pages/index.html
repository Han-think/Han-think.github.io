시도한 코드 / 예시#

# 로컬 서버 예시 코드
from http.server import HTTPServer, SimpleHTTPRequestHandler

def run_local_server(port=8000):
    server_address = ('', port)
    http_server = HTTPServer(server_address, SimpleHTTPRequestHandler)
    print(f'로컬 서버 시작, 포트 {port}')
    try:
        http_server.serve_forever()
    except KeyboardInterrupt:
        print('로컬 서버 종료')
        http_server.server_close()

# 실행 예시
# run_local_server()

출력 주석: 로컬 컴퓨터에서 특정 포트(기본값: 8000)를 통해 웹 서버가 시작되며, Ctrl+C로 종료 가능 result: 위 코드를 실행하면 로컬 컴퓨터에서 지정된 포트를 통해 웹 서버가 작동하며, 해당 컴퓨터에서만 접속 가능 summary: 로컬 서버는 개발자가 임시로 웹 콘텐츠를 테스트하거나 미리보기 위해 사용하며, 컴퓨터가 켜져 있는 동안만 접근 가능하다.

2. GitHub Pages#

왜 이걸 보게 됐나#

GitHub Pages가 로컬 서버와 어떻게 다른지 이해하고자 함으로써 웹 호스팅의 본질을 명확히 하려고 함.

내가 헷갈린 지점#

로컬 서버와 GitHub Pages의 작동 방식 차이와 각각의 역할에 대한 혼동이 있음. 특히 서버의 지속적인 작동 필요성에 대한 오해 해소 필요.

시도한 코드 / 예시#

# 로컬 서버 예시 (Hugo 사용)
command + enter
# 터미널 명령어 예시
hugo server
# 출력 예시
[ 성공 메시지 ]
http://localhost:1313

GitHub Pages 예시#

GitHub 저장소 설정#

파일 커밋 및 푸시#

출력 예시#

[ 사이트 공개 URL ] 예: https://username.github.io/repo-name/

결과와 해석#

로컬 환경에서는 hugo server 명령어로 임시 웹사이트를 로컬에서 확인 가능하지만, 이는 컴퓨터가 켜져 있는 동안만 접근 가능하다. 반면 GitHub Pages는 코드를 GitHub 저장소에 푸시하면 자동으로 웹사이트를 공개 호스팅하여 컴퓨터 상태와 무관하게 항상 접근 가능하다.

정리된 이해#

GitHub Pages는 로컬 개발 환경에서 작성 및 테스트된 정적 웹사이트를 지속적으로 공개 호스팅하는 플랫폼으로, 개발자가 항상 서버를 관리할 필요 없이 웹 콘텐츠를 공유할 수 있게 해준다. 로컬 서버는 개발 및 테스트 목적으로 사용되며, GitHub Pages는 배포 및 공개를 위한 안정적이고 지속적인 호스팅 솔루션을 제공한다.

3. 정적 사이트#

왜 이걸 보게 됐나#

정적 사이트는 사용자가 직접 서버를 항상 가동시키지 않아도 인터넷에 공개될 수 있다는 개념을 이해하기 위함이다. 이를 통해 웹 호스팅에 대한 부담을 줄이고, 웹 개발의 접근성을 높일 수 있다.

내가 헷갈린 지점#

로컬 환경에서 웹사이트를 테스트하는 것과 실제 인터넷에 공개되는 것 사이의 차이점과 GitHub Pages가 어떻게 중간 역할을 하는지 명확히 이해하는 것이 어렵다.

시도한 코드 / 예시#

# 로컬 서버 실행 예시
# hugo server 명령어를 통해 로컬에서 웹사이트를 테스트
# 출력 예시:
# Starting server: http://localhost:1313

결과와 해석#

로컬 서버 실행 시 http://localhost:1313 주소에서만 웹사이트를 확인할 수 있으며, 서버를 끄면 접근 불가능하다. 반면 GitHub Pages는 설정 후에는 서버가 항상 작동하여 인터넷에서 접근 가능하다.

GitHub Pages 배포 예시#

출력 예시:#

…#

Building succeeded.#

Deployment succeeded.#

https://username.github.io/repositoryname/ deployed#

정리된 이해#

정적 사이트는 로컬 환경에서 hugo server를 통해 테스트할 수 있지만, 실제 공개는 GitHub Pages와 같은 호스팅 서비스에 의존한다. 이 구조는 개발자가 서버 관리 부담 없이 웹사이트를 쉽게 배포하고 유지할 수 있게 해준다. 정적 사이트는 동적 기능 없이 미리 만들어진 콘텐츠를 제공하므로, GitHub Pages와 같은 서비스가 이상적인 호스팅 솔루션이 된다.

로컬 서버는 PC에서만 접근 가능한 임시 미리보기 역할을 하며, GitHub Pages는 파일을 GitHub 서버에 호스팅하여 지속적으로 공개 사이트를 제공한다. 정적 사이트는 미리 생성된 콘텐츠를 제공하는 반면, 동적 사이트는 사용자 요청에 따라 동적으로 콘텐츠를 생성한다.
