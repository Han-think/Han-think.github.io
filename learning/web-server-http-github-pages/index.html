웹 서버, HTTP, GitHub Pages 이해하기: 기초 개념 정리

웹 서버, HTTP 프로토콜, 그리고 GitHub Pages와 Hugo 블로그 설정의 기초 개념을 이해하고 실습 예시를 통해 초보자도 쉽게 접근할 수 있도록 정리.
2026년 5월 30일 · 4 min

왜 썼나?#

최근 웹 개발의 기본 요소인 웹 서버, HTTP 프로토콜, 그리고 GitHub Pages를 활용한 블로그 구축에 대해 깊이 이해하고 싶어졌습니다. 특히, 로컬 환경에서의 실습과 클라우드 기반 호스팅 간의 차이점을 명확히 파악하고자 이 글을 작성하게 되었습니다. 이를 통해 웹 개발의 핵심 개념을 초보자도 쉽게 이해할 수 있도록 돕고자 합니다.

배운 것#

로컬 서버 이해#

  • 로컬 서버는 주로 개발 과정에서 사용됩니다. hugo server 명령을 통해 로컬 컴퓨터에서만 접근 가능한 임시 웹사이트를 생성합니다.
    • 예시: http://localhost:1313에서 Hugo가 생성한 사이트를 확인할 수 있습니다.
    • 핵심 포인트: 이 서버는 사용자가 직접 끄기 전까지는 지속적으로 작동합니다. 하지만 인터넷 외부에서는 접근할 수 없습니다.

GitHub Pages의 역할#

  • GitHub Pages는 정적 웹사이트를 공개적으로 호스팅하는 플랫폼입니다. 사용자의 컴퓨터가 꺼져 있어도 웹사이트는 계속 운영됩니다.
    • 작동 원리: HTML 파일들이 GitHub 저장소에 업로드되면 GitHub Pages가 이를 처리하여 웹사이트를 공개합니다.
    • 역할: 개발자의 로컬 작업 환경과 무관하게 웹사이트를 지속적으로 유지하고 서비스합니다.

Hugo의 기능#

  • Hugo는 Markdown 파일을 HTML로 변환하는 정적 사이트 제너레이터입니다.
    • 주요 역할: Markdown 파일을 읽어들여 정적 웹사이트의 HTML 파일을 생성하지만, 직접 웹 호스팅은 수행하지 않습니다.
    • 실습 예시: 
      # Hugo 프로젝트 초기화
hugo new site myblog
# Markdown 파일 생성 및 HTML로 변환
hugo server

헷갈린 것#

서버 개념의 혼동#

  • 혼동 포인트: 로컬 서버, 공개 서버, 정적 사이트, 동적 사이트, GitHub Pages, 그리고 Hugo 간의 구분이 어려웠습니다.
    • 질문: “내 컴퓨터 서버 기반이면 내가 켜놓을 때만 되는 건가?”
    • 해석: 로컬 서버는 개발자의 컴퓨터에서만 작동하며, GitHub Pages는 파일이 GitHub에 업로드되면 지속적으로 호스팅됩니다. 따라서 각각의 역할과 범위를 명확히 이해하는 것이 중요합니다.

정리된 이해#

로컬 vs 공개 호스팅#

  • 로컬 서버: 개발 중에만 사용되며, 로컬 네트워크 내에서만 접근 가능합니다.
    • 예시: http://localhost:1313에서 확인 가능.
  • GitHub Pages: 파일을 GitHub 저장소에 업로드하면 공개적으로 접근 가능한 웹사이트를 제공합니다.
    • 핵심: 로컬 작업은 “업로드 작업장"으로, GitHub Pages가 실제 호스팅을 담당합니다.

Hugo의 역할 재정의#

  • Hugo는 Markdown 파일을 HTML로 변환하는 도구일 뿐, 직접 웹 호스팅은 수행하지 않습니다. GitHub Pages가 실제 호스팅을 담당합니다.

실습 예시#

로컬 환경에서 Hugo 사용하기#

  1. Hugo 프로젝트 초기화: 
    hugo new site myblog
  2. Markdown 파일 생성: 
    hugo new posts/my-first-post.md
  3. 로컬 서버 실행: 
    hugo server
    • 확인: 브라우저에서 http://localhost:1313로 접근 가능.

GitHub Pages와 통합하기#

  1. GitHub 저장소 생성: username.github.io 형식의 저장소 생성.
  2. Hugo 프로젝트를 GitHub에 업로드:
    • main 브랜치에 public 폴더 내의 HTML 파일들을 업로드.
  3. GitHub Pages 설정: 저장소 설정에서 GitHub Pages를 활성화.

왜 썼나?#

블로그를 만드는 과정에서 개인적인 학습 경험을 기록하고, 이를 통해 기술적 이해를 깊게 하며, 향후 비슷한 프로젝트를 진행할 때 참고 자료로 활용하고자 합니다. 또한, 기술에 대한 내 해석을 공유함으로써 초보자들에게도 도움이 되길 바랍니다.

배운 것#

  • Hugo 프레임워크: 빠른 빌드 속도와 유연한 템플릿 시스템을 통해 효율적인 블로그 관리가 가능하다는 것을 배웠습니다.
  • GitHub Pages 연동: 정적 웹사이트를 쉽게 공개할 수 있는 방법을 알게 되었습니다. 특히, 도메인 관리와 호스팅이 간편하다는 점이 큰 장점입니다.
  • 웹 기술 기초: 정적 웹사이트의 작동 원리를 이해하면서 HTTP 요청/응답, URL 구조, DNS, TCP/IP 등 기초적인 웹 기술에 대한 이해를 넓혔습니다.

헷갈리는 것#

정적 사이트의 한계에 대해 잠시 고민했습니다. 예를 들어, 실시간 상호작용 기능 (댓글, 로그인 등)을 어떻게 구현할지에 대한 의문이 있었습니다. 하지만 Hugo는 이러한 기능을 필요로 하지 않는 정적 콘텐츠 중심의 플랫폼이라는 점을 명확히 이해하게 되었습니다.

정리된 이해#

  • 정적 사이트의 장점: 유지보수와 성능 측면에서 뛰어나며, GitHub Pages와 같은 플랫폼을 통해 쉽게 배포 가능하다.
  • 구축 프로세스: 로컬에서 Markdown 파일 작성 → Hugo로 빌드 → Git을 통한 버전 관리 → GitHub Pages로 공개. 이 과정이 효율적이고 직관적임을 확인했습니다.

실습 예시#

  1. Markdown 파일 작성: Hugo 테마를 선택하고, 기본 구조를 따라 포스트 파일을 작성합니다. 예를 들어, 아래와 같이 간단한 포스팅을 시작할 수 있습니다: 
    ---
title: "내 첫 포스팅"
date: 2023-05-29

# 안녕하세요!

이 블로그를 시작하게 되어 기쁩니다. Hugo와 GitHub Pages를 활용한 구축 과정에 대해 계속 공유할 예정입니다.
  2. Hugo 빌드: 터미널에서 hugo version 확인 후 hugo gopher-posts 명령어를 사용해 콘텐츠를 빌드합니다.
  3. Git으로 버전 관리: 생성된 HTML 파일을 Git에 푸시하여 변경사항을 관리합니다.
  4. GitHub Pages에 공개: Settings에서 GitHub Pages를 활성화하여 블로그를 공개합니다.

초보자 키워드#

  • Hugo: 정적 사이트 생성기
  • GitHub Pages: 무료 웹 호스팅 서비스
  • Markdown: 간결한 마크업 언어
  • 버전 관리: Git을 활용한 파일 관리

다음 복습 포인트#

  • HTTP 요청/응답 메커니즘: 정적 사이트의 데이터 전송 방식 이해
  • URL 구조 분석: 웹 주소 체계 이해
  • DNS 기초: 도메인 이름 시스템에 대한 심화 학습
  • TCP/IP 프로토콜: 네트워크 통신 기초
  • CORS (Cross-Origin Resource Sharing): 보안 정책 이해 (주로 동적 사이트에서 중요)
  • SSH 원격 접속: 서버 관리 기술 습득

이러한 주제들을 통해 웹 개발의 기초를 더욱 탄탄히 다질 수 있을 것입니다. 다음 복습에서는 실제 실습 사례를 통해 더 깊이 있는 이해를 추구해 보겠습니다.
