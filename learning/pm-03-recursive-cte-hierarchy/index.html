1. 계층형 질의#

왜 이걸 보게 됐나#

팀에서 데이터 분석을 하다 보니 조직 구조에 따른 직원들의 위치를 파악하고, 각 레벨별 인원수를 계산하는 업무가 필요하게 되었습니다. 이러한 분석을 위해 SQLite에서 계층형 질의를 배우게 되었고, WITH RECURSIVE CTE를 활용하여 복잡한 관계를 효과적으로 처리할 수 있게 되었습니다. 이를 통해 데이터 기반 의사 결정에 필요한 인사이트를 더 정확하게 도출할 수 있을 것으로 기대합니다.

내가 헷갈린 지점#

계층형 질의를 처음 접했을 때, 복잡해 보이는 부모-자식 관계를 SQL 쿼리 하나로 표현할 수 있다는 점이 이해하기 어려웠다. 특히, WITH RECURSIVE 구문이 어떻게 반복적인 관계를 처리하는지, 그리고 쿼리 내에서 별칭이 정의되고 활용되는 과정이 혼란스러웠다. 쿼리의 각 부분이 어떻게 연결되는지 파악하는 데 시간이 걸렸다.

시도한 코드 / 예시#

WITH RECURSIVE emp_hierarchy (
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo, 0 AS lvl
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    SELECT e.EmployeeId, e.FirstName, e.LastName, e.Title, e.ReportsTo, h.lvl + 1
    FROM employees AS e
    JOIN emp_hierarchy AS h ON e.ReportsTo = h.EmployeeId
)

결과와 해석#

계층형 질의는 WITH RECURSIVE를 사용하여 부하 직원 관계를 재귀적으로 탐색하는 방식으로, 조직 구조를 시각화하거나 특정 직원의 모든 하위 직원을 찾는 데 유용합니다. emp_hierarchy CTE는 최상위 직원부터 시작하여 각 단계별로 하위 직원들을 찾아 계층 레벨을 증가시키며, 최종적으로 전체 조직 구조를 파악할 수 있게 해줍니다. 이 쿼리를 통해 직원의 계층 레벨과 ID를 함께 확인할 수 있습니다.

정리된 이해#

계층형 질의는 부모-자식 관계를 반복적으로 탐색하여 계층 구조를 표현하는 SQL 질의 방식이야. SQLite에서는 WITH RECURSIVE 절을 사용하며, 기초 단계(Anchor)에서 시작하여 반복 단계(Recursive)를 통해 하위 관계를 계속 따라가며 계층 구조를 완성해. 이를 통해 조직도처럼 상하 위계를 가진 데이터에서 특정 레벨의 정보를 추출하거나 전체 구조를 파악할 수 있어.

2. WITH RECURSIVE CTE#

왜 이걸 보게 됐나#

데이터베이스에서 조직 구조나 트리 형태의 데이터를 다루는 경우가 많아졌는데, 일반적인 SQL 쿼리만으로는 깊이 있는 관계를 파악하기 어려웠다. 특히 부하급 관계가 여러 단계로 얽혀 있을 때, 수동으로 쿼리를 작성하기가 복잡하고 비효율적이라는 것을 깨달았다. 그래서 재귀적인 방식으로 계층 구조를 탐색하는 WITH RECURSIVE CTE를 배우게 되었다.

내가 헷갈린 지점#

처음에는 WITH RECURSIVE 구문 전체가 너무 복잡하게 느껴졌고, 특히 UNION ALL 앞에 오는 초기 쿼리(Anchor)와 반복적인 쿼리(Recursive)를 구분하는 것이 어려웠다. 별칭이 쿼리 내에서 언제, 어떻게 생성되는지 파악하는 데에도 시간이 걸렸고, GROUP BY 절에서 갑자기 나타나는 별칭 때문에 더욱 혼란스러웠다.

시도한 코드 / 예시#

WITH RECURSIVE emp_hierarchy (
    EmployeeId, FirstName, LastName, Title, ReportsTo, lvl
) AS (
    SELECT EmployeeId, FirstName, LastName, Title, ReportsTo, 0 AS lvl
    FROM employees
    WHERE ReportsTo IS NULL

    UNION ALL

    SELECT e.EmployeeId, e.FirstName, e.LastName, e.Title, e.ReportsTo, h.lvl + 1
    FROM employees AS e
    JOIN emp_hierarchy AS h ON e.ReportsTo = h.EmployeeId
)

결과와 해석#

WITH RECURSIVE CTE는 계층 구조 데이터를 조회할 때 매우 유용하며, 재귀적인 방식으로 데이터를 탐색하여 상위 레벨부터 하위 레벨까지 순차적으로 추출할 수 있습니다. 예를 들어, emp_hierarchy CTE는 employees 테이블에서 보고 체계를 따라 상위 직원부터 하위 직원까지 모든 직원을 계층 레벨과 함께 조회하는 데 사용됩니다. UNION ALL을 통해 anchor 쿼리의 결과와 recursive 쿼리의 결과를 합쳐 최종 결과 집합을 생성합니다.

정리된 이해#

WITH RECURSIVE CTE는 SQLite에서 계층 구조 데이터를 조회할 때 사용하는 핵심 기능으로, 재귀적인 방식으로 부모-자식 관계를 탐색하여 원하는 정보를 추출합니다. 이 CTE는 anchor 쿼리를 통해 시작점을 정의하고, recursive 쿼리를 통해 상위 레코드의 하위 레코드를 반복적으로 탐색하며 계층 구조를 구성합니다.

3. Anchor 단계#

왜 이걸 보게 됐나#

계층 구조를 가진 데이터를 다룰 때, 최상위 레벨의 데이터를 먼저 파악하는 것이 분석의 시작점이라는 것을 깨달았습니다. WITH RECURSIVE를 사용하면서, 이 기초 단계를 정의하는 Anchor가 전체 계층 구조를 탐색하기 위한 출발점이 된다는 것을 알게 되었습니다. Anchor를 이해함으로써 복잡한 계층형 쿼리를 더 효과적으로 구성하고 디버깅할 수 있게 되었습니다.

내가 헷갈린 지점#

처음에는 Anchor 단계가 단순히 최상위 직원을 선택하는 것 이상으로 어떤 의미를 가지는지 파악하기 어려웠다. Recursive 단계와의 연결고리가 명확하게 보여주지 않아서, Anchor 단계가 전체 계층 구조를 결정하는 중요한 시작점이라는 것을 깨닫는 데 시간이 걸렸다. 단순히 시작점을 찾는 것 이상으로, Recursive 단계에서 탐색의 기준이 된다는 점을 이해하는 데 어려움을 겪었다.

시도한 코드 / 예시#

SELECT EmployeeId, FirstName, LastName, Title, ReportsTo, 0 AS lvl
       FROM employees
       WHERE ReportsTo IS NULL

결과와 해석#

Anchor 단계는 계층 구조의 최상위 레벨을 찾는데 사용됩니다. WHERE ReportsTo IS NULL 조건을 통해 누가 누구에게 보고하는 관계가 없는 최상위 관리자를 선택하고, 이들의 정보와 함께 레벨(lvl)을 0으로 설정하여 결과에 포함시킵니다. 이를 통해 재귀적인 검색의 시작점을 정의하고, 이후 하위 직원들을 탐색할 수 있는 기반을 마련합니다.

정리된 이해#

Anchor 단계는 계층형 질의에서 가장 먼저 실행되는 부분으로, 보통 최상위 레벨의 데이터, 즉 부모가 없는 데이터를 찾습니다. 이 단계의 결과는 Recursive 단계에서 시작점으로 사용되어 하위 레벨 데이터 탐색을 이어가게 됩니다. 쉽게 말해, 계층 구조의 ‘뿌리’를 찾는 역할을 합니다.

4. Recursive 단계#

왜 이걸 보게 됐나#

계층 구조가 있는 데이터를 조회하는 과정에서, 데이터 간의 관계를 파악하고 이를 효과적으로 표현해야 했는데, 단순히 테이블을 조인하는 것만으로는 복잡한 계층 구조를 탐색하기 어려웠다. 그래서 여러 단계의 부모-자식 관계를 반복적으로 탐색할 수 있는 Recursive 단계를 이해하고 활용하게 되었다. 이를 통해 좀 더 효율적으로 계층형 데이터를 분석하고 시각화할 수 있게 되었다.

내가 헷갈린 지점#

처음에는 반복 단계에서 어떤 기준으로 직원을 연결하는지, 그리고 h라는 별칭이 어떻게 사용되는지 잘 이해가 안 갔습니다. 특히 이전 단계의 결과를 어떻게 기반으로 다음 단계의 직원을 찾는지 파악하는 데 시간이 걸렸고, emp_hierarchy라는 CTE 안에서 h 별칭이 나타나는 방식이 직관적이지 않았습니다. UNION ALL 구문과 JOIN 조건을 통해 어떤 관계를 나타내는 것인지 명확히 이해하는 데 어려움이 있었습니다.

시도한 코드 / 예시#

       SELECT e.EmployeeId, e.FirstName, e.LastName, e.Title, e.ReportsTo, h.lvl + 1
       FROM employees AS e
       JOIN emp_hierarchy AS h ON e.ReportsTo = h.EmployeeId

결과와 해석#

Recursive 단계는 이전 계층의 직원이 가리키는 직원을 찾아 다음 단계의 직원을 결정합니다. JOIN emp_hierarchy AS h ON e.ReportsTo = h.EmployeeId 부분을 통해 이전 단계(h)의 EmployeeId가 현재 직원(e)의 ReportsTo와 일치하는 직원을 연결하고, h.lvl + 1로 계층 레벨을 증가시켜 하위 직원 정보를 탐색합니다. 이를 반복하며 전체 조직 구조를 계층적으로 파악합니다.

정리된 이해#

Recursive 단계는 이전 단계에서 발견된 직원들의 직속 하위 직원들을 계속해서 찾아 연결하는 과정이야. 마치 나무의 가지를 따라 더 작은 가지들을 찾아가는 것과 같다고 생각하면 돼. 이 과정을 통해 전체 계층 구조를 파악할 수 있어.

총평#

오늘 전체에서 배운 것#

SQLite에서 계층 구조를 쿼리하는 WITH RECURSIVE CTE를 사용하여 데이터 관계를 탐색하는 방법을 익혔습니다. Anchor 단계는 시작점을 정의하고, Recursive 단계는 하위 레벨 데이터를 반복적으로 가져오는 방식으로, 계층 구조를 효과적으로 탐색할 수 있습니다.

다음에 조심할 것#

별칭 생성 시점이 헷갈리지 않도록 FROM 절과 JOIN 절에서 정의되는 별칭을 잘 확인해야겠다. WITH RECURSIVE CTE의 Anchor와 Recursive 단계의 역할과 조건을 정확히 이해하고, 종료 조건을 설정하는 것을 잊지 말아야 한다.

다음 복습 주제#

emp_hierarchy CTE 내에서 h 별칭이 어떻게 사용되는지 좀 더 자세한 예제를 풀어보면서 완전하게 이해하고 싶다. 특히 JOIN 조건과 h.lvl + 1 부분이 직관적으로 연결되도록 만들어보고 싶다.
