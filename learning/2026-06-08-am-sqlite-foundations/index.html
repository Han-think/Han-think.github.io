1. SQLTools에서 SQL 선택 실행하기#

무엇을 배웠나#

오전 실습은 VS Code의 SQLTools로 SQLite DB에 연결하고, SQL 문장을 선택해서 실행하는 감각을 잡는 것부터 시작했다. 핵심은 “전체 실행"과 “선택 실행"의 차이였다.

전체 파일 실행 = 위에서 아래로 모든 SQL 문장을 실행
선택 영역 실행 = 드래그한 SQL 문장만 실행

CREATE TABLE, INSERT, SELECT가 한 파일에 같이 있을 때 SELECT * FROM study_notes;만 드래그해서 실행하면 조회만 수행된다.

헷갈렸던 점#

결과가 안 나오거나 빨간 표시가 뜨면 처음엔 문법이 틀린 줄 알았다. 하지만 실제로는 실행 순서와 연결 상태가 더 중요했다. 테이블을 만들기 전에 조회하면 당연히 결과가 없다.

CREATE TABLE 실행 → INSERT 실행 → SELECT 실행

정리된 이해#

SQLTools에서는 SQL을 한 덩어리씩 나눠 실행하는 습관이 안전하다. 처음 한 번은 전체 실행으로 테이블과 데이터를 만들고, 이후에는 조회문만 선택 실행한다.

CREATE TABLE IF NOT EXISTS study_notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    category TEXT NOT NULL
);

INSERT INTO study_notes (title, category) VALUES
    ('SELECT 기본', 'database');

SELECT * FROM study_notes;

2. SELECT와 CRUD 기본 문법#

무엇을 배웠나#

SQL은 Structured Query Language, 즉 구조화된 데이터에게 질문하는 언어다. 가장 기본이 되는 조회문은 다음 형태다.

SELECT *
FROM study_notes;

여기서 *는 “모든 컬럼"을 뜻하고, 위 문장은 “study_notes 테이블의 모든 컬럼과 모든 행을 보여줘"라는 의미다.

헷갈렸던 점#

SQL이 단순 명령어처럼 보였지만, 강의에서는 핵심을 “질의(質疑)“라고 짚었다. 즉 데이터베이스에게 질문을 던지고 표 형태의 답을 받는 것이 SELECT의 본질이다.

정리된 이해#

데이터를 다루는 네 가지 동작(CRUD)은 SQL 명령과 다음처럼 대응된다.

CRUD 의미 SQL
Create 데이터 추가 INSERT
Read 데이터 조회 SELECT
Update 데이터 수정 UPDATE
Delete 데이터 삭제 DELETE

테이블 자체를 만드는 일은 CREATE TABLE로 처리한다. 조회의 기본 공식은 다음과 같다.

SELECT 컬럼명
FROM 테이블명
WHERE 조건
ORDER BY 정렬기준
LIMIT 개수;

3. ERD와 Crow’s Foot 표기법 읽기#

무엇을 배웠나#

ERD는 Entity-Relationship Diagram의 약자로, 테이블들이 서로 어떻게 연결되는지 보여주는 그림이다. 나는 ERD를 회로도/관계망으로 비유해서 이해했다. 테이블은 부품, Primary Key와 Foreign Key는 부품을 잇는 연결선이다.

헷갈렸던 점#

처음에는 ERD가 위에서 아래로 갈라지는 트리 구조처럼 보였다. 하지만 관계형 데이터베이스는 한 방향으로만 내려가지 않는다. 특히 playlists와 tracks는 직접 연결되지 않고 playlist_track이라는 중간 테이블을 통해 이어진다.

artists → albums → tracks
customers → invoices → invoice_items → tracks
playlists ↔ playlist_track ↔ tracks

정리된 이해#

ERD의 기본 요소와 Crow’s Foot 표기의 감각을 정리하면 다음과 같다.

개념 의미
Entity 테이블
Attribute 컬럼
Primary Key 각 행을 구분하는 고유값
Foreign Key 다른 테이블의 PK를 참조하는 값
Relationship 테이블 간 연결
Cardinality 1:1, 1:N, N:M 같은 관계 수

ERD를 보고 두 테이블을 연결하면 곧 JOIN이 된다.

SELECT
    artists.Name AS artist_name,
    albums.Title AS album_title
FROM artists
JOIN albums
    ON artists.ArtistId = albums.ArtistId;

4. Chinook과 ClassicModels 샘플 DB 살펴보기#

무엇을 배웠나#

강의 자료로 SQLite 샘플 DB 두 개가 제공되었다. chinook.db는 음악/음원 판매 예제 DB, classicmodels.db는 상품·주문·고객·결제 구조를 가진 영업 관리 예제 DB다.

헷갈렸던 점#

DB 파일이 두 개라 무엇을 기준으로 봐야 할지 헷갈렸다. 정리하면 역할이 다르다.

chinook.db      = 음악 가게 DB, ERD/JOIN 감 잡기 좋음
classicmodels.db = 주문 관리 DB, 실무형 SQL 구조 배우기 좋음

정리된 이해#

샘플 DB는 단순 쿼리 연습용이 아니라 관계형 구조를 읽기 위한 지도다. 먼저 각 테이블을 SELECT *로 훑고, 이후 ERD를 보며 관계를 따라가면 된다.

SELECT * FROM artists;
SELECT * FROM albums;
SELECT * FROM tracks;
SELECT * FROM customers;

Chinook의 음악 카탈로그는 artists → albums → tracks로, 판매 구조는 customers → invoices → invoice_items → tracks로 이어진다.

5. 학습 자료를 source로 보존하기#

무엇을 배웠나#

강의에서 기준 참고 자료로 SQLite 튜토리얼의 공개 샘플 DB 페이지가 언급되었다. 이 페이지에서 Chinook 샘플 DB, ERD, SQLite 학습 흐름을 한눈에 볼 수 있다. 노션 공개 페이지는 사람이 브라우저로 볼 때는 잘 보였지만, 자동화 도구로 직접 가져오기는 어려웠다.

헷갈렸던 점#

공개 링크인데도 자동 fetch가 막히는 이유가 처음엔 의아했다. 가능한 원인은 JS 렌더링 페이지, 봇 접근 제한, 워크스페이스 권한 정책, export 제한 등이었다.

정리된 이해#

공개 페이지 자료는 자동으로 긁기보다 PDF로 인쇄 저장하거나 텍스트로 복사해 raw source로 보존하는 편이 현실적이었다. 수업 자료가 외부에 있어도, 내 LearningLog에서는 원본을 따로 보존하고 학습 내용은 주제별 노트로 분리한다는 원칙을 다시 확인했다.

source는 보존하고,
note는 내 것으로 만들고,
draft는 검토 후 공개한다.

총평#

오늘 오전 전체에서 배운 것#

SQLTools로 SQL을 선택 실행하는 감각을 잡고, SELECT와 CRUD의 대응 관계, ERD/Crow’s Foot로 테이블 관계를 읽는 법, 그리고 Chinook·ClassicModels 샘플 DB의 구조까지 한 흐름으로 연결했다. SQL은 결국 “데이터베이스에게 질문하는 언어"라는 점이 핵심이었다.

다음에 조심할 것#

조회 결과가 비어 보일 때는 문법보다 실행 순서와 연결 상태를 먼저 의심하자. 또 ERD를 트리로 착각하지 말고, 중간 테이블(N:M)을 항상 염두에 둔다.

다음 복습 주제#
