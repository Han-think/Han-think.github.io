1. ERD 이해#

왜 이걸 보게 됐나#

SQL JOIN 문제를 풀 때 ERD만으로는 테이블 간의 관계를 명확하게 파악하기 어려웠어서, 데이터베이스의 구조를 더 깊이 이해해야겠다고 생각하게 됐어. 특히 테이블이 분리되어 저장되고, 연결 기준이 되는 컬럼을 정확히 알아야 하는 상황에서 어려움을 느껴서 ERD를 제대로 활용하는 방법을 익히기로 했어. 이 개념을 통해 JOIN 문제를 풀 때 데이터 구조에 대한 이해를 바탕으로 보다 효율적으로 접근할 수 있게 될 거야.

내가 헷갈린 지점#

처음에는 ERD만 보고 테이블 간의 관계가 명확하게 파악될 줄 알았는데, 실제 문제에서 테이블이 예상과 다르게 연결되어 있어서 당황스러웠다. 특히 고객 테이블에 직원 이름 대신 직원 번호만 저장되어 있다는 점이 ERD만으로는 알 수 없어서, 어떤 기준으로 연결해야 할지 혼란스러웠다. ERD는 참고 자료일 뿐, 실제 데이터베이스 구조는 ERD와 완전히 일치하지 않을 수 있다는 점을 인지해야겠다.

시도한 코드 / 예시#

-- 문제 15. 고객과 담당 직원 연결하기
-- 고객 이름과 담당 직원 이름을 보여주는 쿼리 작성

-- 1. 기준 테이블: 고객 정보
--    - FirstName, LastName
--    테이블 별칭: cu
--    ```sql
--    customers -> cu
--    ```

-- 2. 연결할 테이블: 직원 정보
--    - FirstName, LastName
--    테이블 별칭: emp
--    ```sql
--    employees -> emp
--    ```

-- 3. 연결 기준:
--    - 고객 테이블의 `SupportRepId`와 직원 테이블의 `EmployeeId`를 연결
--    ```sql
--    cu.SupportRepId = emp.EmployeeId
--    ```

결과와 해석#

ERD를 제대로 이해하지 못해 고객과 직원의 이름 연결이 어려웠는데, SupportRepId와 EmployeeId라는 공통 컬럼을 통해 두 테이블을 JOIN하는 방법을 실습으로 익혔다. 이 과정을 통해 데이터베이스는 직관적인 연결보다는 명확한 식별자를 기반으로 관계를 정의한다는 점을 깨달았고, ERD와 실제 쿼리 간의 연결고리를 이해하는 데 도움이 되었다. 테이블 별칭을 활용하여 쿼리를 간결하게 작성하는 방법도 습득했다.

정리된 이해#

ERD는 데이터베이스의 구조를 시각적으로 보여주지만, 실제 데이터는 테이블 간의 분리된 저장 방식을 따르기 때문에 ERD만으로는 연결 기준을 명확히 파악하기 어려울 수 있다. 테이블 간의 관계는 공통 컬럼을 통해 연결되며, ERD를 이해하는 것만큼 중요한 것은 각 테이블이 어떤 방식으로 분리되어 저장되는지 파악하는 것이다.

2. 데이터 구조#

왜 이걸 보게 됐나#

SQL JOIN 문제를 풀 때 ERD만으로는 테이블 간의 관계를 제대로 파악하지 못해서 어려움을 겪었고, 이 때문에 데이터가 어떻게 구조화되어 저장되는지 이해하는 것이 얼마나 중요한지 깨달았어. 데이터베이스는 인간이 생각하는 직관적인 방식과 다르기 때문에, 데이터를 효율적으로 관리하고 쿼리하려면 데이터 구조에 대한 이해가 필수적이라는 것을 알게 됐어.

내가 헷갈린 지점#

처음에는 테이블 간의 관계가 ERD에 명확하게 드러날 거라고 생각했는데, 실제로는 테이블이 분리되어 저장되고 공통 컬럼을 통해서 연결된다는 점이 헷갈렸다. ERD는 큰 그림을 보여주지만, 데이터가 어떻게 연결되는지 세부적인 부분을 완벽하게 보여주지는 않는 것 같다. 테이블 관계를 이해하는 데는 ERD 외에 실제 데이터와 컬럼을 파악하는 과정이 필요하다는 것을 깨달았다.

시도한 코드 / 예시#

-- 4. 보여줄 컬럼:
--    - 고객 이름과 직원 이름
--    ```sql
--    cu.FirstName AS customer_first_name,
--    cu.LastName AS customer_last_name,
--    emp.FirstName AS employee_first_name,
--    emp.LastName AS employee_last_name

결과와 해석#

데이터 구조는 테이블을 분리해서 관리하는 방식으로, customers 테이블의 SupportRepId와 employees 테이블의 EmployeeId가 같은 직원과 고객을 연결해주는 중요한 역할을 한다는 것을 알게 되었다. 이 예시 코드를 통해 JOIN 구문이 어떻게 테이블 간의 연결 고리를 만들어 원하는 데이터를 조합하는지 명확히 이해할 수 있었다. 특히 테이블 별칭을 활용하여 쿼리를 간결하게 만드는 방법도 익혔다.

정리된 이해#

데이터베이스는 우리의 직관과는 달리, 데이터가 분리되어 저장되고 공통 컬럼을 통해 연결되는 구조적인 방식으로 관리된다는 점을 이해하게 되었다. 각 테이블 간의 관계를 명확히 파악하고, 어떤 컬럼을 기준으로 연결해야 하는지를 파악하는 것이 중요하다는 것을 알게 되었다.

3. 테이블 연결#

왜 이걸 보게 됐나#

데이터가 분리되어 저장되는 경우가 많고, 여러 테이블 간의 관계를 파악해서 필요한 정보를 조합해야 하기 때문이에요. 단순히 한 테이블의 정보를 보는 것만으로는 충분하지 않고, 데이터베이스를 효율적으로 활용하려면 테이블을 연결하는 방법을 알아야 해요. 이걸 배우면 더 복잡한 데이터 분석이나 보고서 작성도 가능해질 것 같아요.

내가 헷갈린 지점#

처음에는 ERD만 보고 테이블 간의 관계가 명확하게 보이는 게 어려웠어. 특히 어떤 컬럼을 기준으로 연결해야 하는지, 그리고 테이블 이름만 보고 어떤 정보가 저장되어 있는지 파악하는 데 시간이 오래 걸렸어. 테이블 간의 연결 기준을 찾고, 어떤 정보를 보여줘야 하는지 이해하는 과정에서 혼란스러웠던 것 같아.

시도한 코드 / 예시#

SELECT
    cu.FirstName AS customer_first_name,
    cu.LastName AS customer_last_name,
    emp.FirstName AS employee_first_name,
    emp.LastName AS employee_last_name

결과와 해석#

두 테이블을 연결하는 핵심은 공통으로 사용되는 컬럼(SupportRepId와 EmployeeId)을 활용하는 거구나. 이 컬럼들을 기반으로 JOIN 구문을 작성하면, 고객 정보와 담당 직원의 정보를 함께 볼 수 있어서 ERD만으로는 파악하기 어려웠던 연결 관계를 명확하게 이해할 수 있었다. 실습을 통해 데이터베이스 구조가 직관적인 언어와 다를 수 있지만, 관계를 명확히 연결하는 방법을 익힐 수 있었다.

정리된 이해#

데이터베이스에서 테이블은 종종 분리되어 저장되며, 서로 관련 있는 정보는 공통 컬럼을 통해 연결됩니다. 즉, 직관적으로 생각하는 것과는 달리, 테이블 간의 관계는 ERD만으로는 명확하게 보이지 않고, 연결을 위한 공통 컬럼을 이해하는 것이 중요합니다. 이 공통 컬럼을 바탕으로 JOIN 구문을 사용하여 필요한 정보를 조합할 수 있습니다.

4. SQL JOIN#

왜 이걸 보게 됐나#

데이터를 효과적으로 활용하려면 여러 테이블에 흩어져 있는 정보를 연결해서 분석해야 하는데, SQL JOIN은 바로 이 연결을 해주는 핵심적인 기능이거든요. 특히 실제 데이터베이스는 정보가 테이블로 분리되어 저장되는 경우가 많아서 JOIN을 제대로 이해하지 못하면 원하는 정보를 얻어낼 수 없어요. 그래서 JOIN을 배우게 되었습니다.

내가 헷갈린 지점#

처음에는 ERD만 보고 테이블 간의 관계를 명확하게 파악하는 게 어려웠어. 특히 고객 테이블과 직원 테이블의 연결 고리가 직접적인 이름이 아니라 번호로 되어 있다는 점이 혼란스러웠지. 테이블 간의 관계가 ERD에서 보이는 것만큼 직관적이지 않고, 데이터베이스는 분리된 테이블과 연결 컬럼을 통해 관계를 정의한다는 점을 이해하는 데 시간이 걸렸어.

시도한 코드 / 예시#

SELECT
    cu.FirstName AS customer_first_name,
    cu.LastName AS customer_last_name,
    emp.FirstName AS employee_first_name,
    emp.LastName AS employee_last_name

결과와 해석#

SQL JOIN은 서로 다른 테이블의 데이터를 연결하여 보여주는 중요한 기능인데, 문제에서 ERD만으로는 연결 기준을 파악하기 어려워 데이터 구조에 대한 이해가 부족했음을 알게 되었다. 문제 15번 실습을 통해 고객 테이블의 SupportRepId와 직원 테이블의 EmployeeId를 JOIN하여 고객과 담당 직원의 이름을 함께 출력하는 방법을 익혔다. JOIN 연산 시 테이블 별칭을 사용하고, 연결 기준을 명확히 작성하는 것이 중요하다는 점을 체감했다.

정리된 이해#

SQL JOIN은 데이터베이스의 여러 테이블에서 필요한 정보를 가져와 연결하는 방법인데, 테이블 간의 연결 기준이 되는 컬럼을 정확히 파악하는 것이 중요하다. ERD만으로는 연결 기준을 알기 어려울 수 있으므로, 각 테이블의 역할과 어떤 컬럼이 연결되는지 주의 깊게 살펴봐야 한다.

총평#

오늘 전체에서 배운 것#

ERD만 보고 테이블 관계를 명확히 파악하는 게 어려웠는데, 데이터가 분리되어 저장되고 공통 컬럼을 통해 연결된다는 점을 이해하게 됐어. 문제를 풀 때 테이블 별칭을 활용하고, 연결 기준을 명확히 하는 연습이 필요하다는 걸 깨달았어.

다음에 조심할 것#

ERD만 보고 바로 테이블 관계를 파악하는 연습을 꾸준히 해야겠다. 테이블 별칭을 명확하게 쓰고, JOIN 조건이 왜 필요한지 다시 한번 생각하며 코드를 작성해야 실수를 줄일 수 있겠다.

다음 복습 주제#

ERD를 빠르게 파악할 수 있는 노하우가 필요하고, 실제 데이터베이스 설계 원칙과 분리 저장의 이유를 더 자세히 알아봐야겠다. 다양한 예제를 통해 테이블 관계를 손에 익히는 연습을 꾸준히 해야겠다.
