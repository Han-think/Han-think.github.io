1. JavaScript 상속과 오버라이드 완벽하게 이해하기#

무엇을 배웠나#

상속에서 super()는 부모 클래스의 생성자를 호출하고, super.printSpec()는 부모 클래스의 메서드를 직접 호출하는 차이가 있다는 것을 알게 되었습니다. 특히 오버라이드 시 ...super_spec을 통해 부모 객체의 속성을 펼쳐서 활용하는 방법을 이해하게 되었습니다. 이제 자식 클래스에서 부모 클래스의 기능을 확장하고 수정하는 오버라이드 개념을 더 명확하게 이해할 수 있을 것 같습니다.

헷갈렸던 점#

부모 생성자를 호출하는 super(name, speed)와 부모 메서드를 직접 호출하는 super.printSpec()의 역할이 비슷해 보여서 처음에는 혼동되었고, 오버라이드된 메서드 내에서 ...super_spec을 보는 순간 스프레드 문법을 알고 있지만 왜 여기서 사용되었는지 바로 떠오르지 않았습니다. 자식 클래스가 부모 클래스의 기능을 어떻게 확장하는지, 그리고 super를 어떻게 활용해야 하는지가 명확하지 않았습니다.

정리된 이해#

상속을 할 때 super()는 부모 클래스의 생성자를 호출하여 초기화를 담당하고, super.printSpec()은 부모 클래스의 메서드를 직접 호출하여 정보를 가져옵니다. 오버라이드는 자식 클래스에서 부모 클래스의 메서드를 재정의하여 기능을 확장하거나 수정하는 것을 의미하며, 이 때 ...super_spec은 부모 객체의 속성을 펼쳐서 자식 객체에 추가하는 역할을 합니다. 이 개념들을 이해하면 객체 지향 프로그래밍에서 상속을 활용하여 코드를 효율적으로 관리할 수 있습니다.

class SportsCar extends Car {
    constructor(name, speed, isTurbo, horsePower) {
        super(name, speed);  // 부모 클래스의 생성자 호출
        this.#isTurbo = isTurbo;
        this.#horsePower = horsePower;
    }
}

printSpec() {
    let super_spec = super.printSpec();  // 부모의 printSpec() 호출
    console.log(super_spec);
    // 부모 객체의 정보를 기반으로 자식 클래스의 추가 정보를 더함
    return {
        ...super_spec,  // 부모 객체 속성 펼치기
        isTurbo: this.#isTurbo,
        horsePower: this.#horsePower
    };
}

2. React 입문: Virtual DOM, SPA, Component 기초#

무엇을 배웠나#

React 입문 과정에서 Virtual DOM을 통한 효율적인 UI 업데이트와 SPA의 개념, 그리고 Component 구조의 중요성을 배웠습니다. 특히 props, state, ref, useEffect 등의 개념을 이해하고, App.jsx, main.jsx, index.html 파일들의 역할을 명확히 파악하여 React 프로젝트 구조를 이해하는 데 도움이 되었습니다. 앞으로 이러한 이해를 바탕으로 좀 더 복잡한 React 애플리케이션 개발에 도전해볼 수 있을 것 같습니다.

헷갈렸던 점#

처음에는 props, state, ref, useEffect 개념들이 JavaScript 지식과 어떻게 연결되는지 파악하기 어려웠다. Component들을 어떻게 조립해서 전체 애플리케이션을 만들지, 그리고 각 파일들의 역할이 무엇인지 구체적으로 감이 잘 오지 않았던 것도 혼란스러웠다. 프로젝트 구조가 복잡해 보이면서 어디서부터 시작해야 할지 막막했다.

정리된 이해#

React는 Virtual DOM을 사용하여 효율적인 SPA 개발을 가능하게 하는 라이브러리이며, 큰 UI를 작은 Component 단위로 나누어 전체 애플리케이션을 구성할 수 있다. App.jsx, main.jsx, index.html은 각각 Component 조합, App 호출, 실제 DOM의 root 역할을 수행하며, 이들의 연결을 이해하는 것이 중요했다. 앞으로는 props, state, ref, useEffect의 활용법을 익히고 Component 구조를 더욱 명확하게 이해해야겠다.

// 예시: App.jsx (Component 조합)
function App() {
  return (
    <div>
      <h1>Welcome to my App!</h1>
      <MyComponent />
    </div>
  );
}

// 예시: main.jsx (App 호출)
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(<App />);

<!-- 예시: index.html (#root) -->
<!DOCTYPE html>
<html>
<head>
  <title>My React App</title>
</head>
<body>
  <div id="root"></div>
</body>
</html>

3. React 개발 환경, 초보자를 위한 완벽 가이드#

무엇을 배웠나#

React 개발 환경 설정 시 헷갈렸던 Node.js, npm, Vite, WebStorm의 역할을 명확히 이해하게 되었고, 각 도구의 역할과 실제 사용법을 정리할 수 있었습니다. 특히, Node.js는 JavaScript 실행 환경, npm은 패키지 관리 도구, Vite는 빠른 개발 환경 구축, WebStorm은 개발 환경을 제공한다는 것을 알게 되었습니다. 실습을 통해 각 도구를 실제로 사용해보며 이해도를 높일 수 있었습니다.

헷갈렸던 점#

처음에는 Node.js, npm, Vite, WebStorm이 각각 어떤 역할을 하는지, 그리고 이들이 서로 어떻게 연관되는지 파악하는 데 어려움이 있었습니다. 특히 WebStorm 설정 방법이 키맵 예시만 있어서 어떻게 설정해야 하는지 감을 잡기 어려웠고, Node.js와 npm의 역할 차이도 명확하게 이해되지 않았습니다.

정리된 이해#

React 개발 환경 설정 시 Node.js는 JavaScript 실행 환경, npm은 패키지 관리 도구, Vite는 빠른 개발 환경 구축을 돕는 도구, WebStorm은 효율적인 개발을 위한 통합 개발 환경이라는 역할을 각각 수행한다는 것을 알게 되었다. 실습을 통해 각 도구의 역할을 직접 확인하고 간단한 React 프로젝트를 생성하며 기본적인 사용법을 익혔다. 앞으로는 이 도구들을 효과적으로 활용하여 React 개발 역량을 향상시킬 것이다.

node -v

npm -v

npm install -g vite

npm create vite react@latest my-react-app

cd my-react-app

npm install

npm run dev

4. 로컬 AI와 JetBrains IDE 연결, 핵심 개념과 설정 이해#

무엇을 배웠나#

JetBrains IDE는 단순히 코드를 편집하는 도구가 아니라, 로컬 AI 모델과 외부 도구를 연결하는 통합 플랫폼이라는 것을 알게 되었습니다. MCP는 AI 모델이 외부 데이터나 도구에 접근할 수 있도록 돕는 통로 역할을 한다는 것도 명확해졌습니다. 이 노트는 로컬 AI 모델, MCP, 그리고 IDE의 역할을 분리하여 이해하는 데 큰 도움이 되었습니다.

헷갈렸던 점#

MCP가 로컬 모델을 직접 연결하는 것인지, 아니면 다른 도구와 데이터 연결의 역할을 하는지 이해가 안 됐어요. 그리고 WebStorm 같은 IDE가 단순히 코드 편집기인지, 아니면 AI 모델과의 통합 플랫폼인지도 헷갈렸습니다. 이 두 가지를 명확히 구분하고 각각의 역할과 기능을 이해하는 것이 중요했습니다.

정리된 이해#

로컬 AI 모델은 Local Model Provider를 통해 IDE에 연결되고, MCP는 모델이 외부 도구나 데이터에 접근할 수 있도록 지원하는 통로 역할을 합니다. JetBrains IDE는 단순히 코드 편집기를 넘어, 로컬 AI 모델과 외부 도구를 통합하는 플랫폼으로 활용될 수 있습니다. 즉, IDE는 개발 환경과 AI 모델을 연결하는 핵심적인 역할을 수행합니다.

// 예시: WebStorm 설정 파일 (settings.json) - 로컬 모델 연결 옵션

{
  "exaone_ai": {
    "local_model_path": "/path/to/your/exaone3.5/model",
    "api_key": "YOUR_API_KEY" // 예시: API 키 필요할 수 있음
  }
}

오늘 오전에는 JavaScript 상속과 오버라이드 개념을 명확히 이해하고, React의 기본 원리와 개발 환경 구축 방법을 익혔습니다. 또한 JetBrains IDE와 로컬 AI 모델을 연결하여 활용하는 방법에 대한 핵심 개념도 파악하여 앞으로 개발 효율성을 높일 수 있을 것 같습니다.

다음 복습 주제#

JavaScript 상속과 오버라이드 부분에서 super()와 super.method()의 미묘한 차이를 좀 더 다양한 예제를 통해 복습해 봐야 할 것 같아요. React에서는 props와 state의 변화에 따른 컴포넌트 리렌더링 최적화 방안을 좀 더 깊이 있게 공부하고, 실제 코딩을 통해 숙달하고 싶습니다.
