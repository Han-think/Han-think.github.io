1. Jest 설정과 testable code의 경계에서#

무엇을 배웠나#

Jest 설정 단계에서 발생하는 import 오류는 테스트 로직보다 앞단의 실행 환경 문제였으며, 설정이 올바르면 테스트가 정상적으로 실행되는 것을 확인할 수 있었다. 테스트 실패는 한 번에 해결되지 않고 설정 → import → render → assertion 순서로 단계를 나누어 점검해야 한다. UI 내부의 계산 로직을 별도 module로 분리하면 테스트 작성은 물론 코드 재사용성도 크게 높아진다.

헷갈렸던 점#

import 문법이 실행 환경과 맞지 않아 발생하는 SyntaxError는, 테스트 로직 자체보다 앞서 실행 환경을 구성하는 단계에서 발생한다는 점을 명확히 인지하게 되었다. 또한, UI 내부에 복잡한 계산 로직을 포함하기보다는 별도 모듈로 분리하여 관리하는 것이 테스트 작성뿐만 아니라 코드 재사용성 측면에서도 훨씬 효율적이라는 사실을 깨달았다.

정리된 이해#

Jest 설정 단계에서 발생하는 import 문법 오류는 테스트 로직보다 앞단의 실행 환경 및 모듈 처리 단계에서 비롯된다는 점을 이해했다. UI 내부의 계산 로직을 별도 module로 분리하여 작성하면, 테스트 붙이기와 코드 재사용이 훨씬 용이해진다는 원칙을 체득했다.

// utils/calculator.js (분리된 계산 로직)
export const plus = (a, b) => a + b;
export const minus = (a, b) => a - b;
export const multiply = (a, b) => a * b;
export const divide = (a, b) => {
  if (b === 0) throw new Error('Division by zero');
  return a / b;
};

2. RTL UI 테스트 파라미터화 실험: 행동과 데이터의 분리#

무엇을 배웠나#

RTL로 UI 테스트를 처음 작성하면서 ‘반복되는 코드’에 대한 의문이 들었다. 같은 동작을 네 번씩 수행해야 하는 구조에서, 변하는 것은 데이터뿐이라는 사실을 깨닫고 test.each()를 사용해 공통된 행동과 다양한 데이터 세트를 효율적으로 압축하여 테스트할 수 있다는 점을 배웠다.

헷갈렸던 점#

강사님의 방식은 코드 양이 많았지만, 각 테스트 케이스가 독립적이어서 순서를 따라가기 쉽다는 점이 좋았습니다. 반면 저는 test.each()를 사용해 “공통된 행동 하나 + 다양한 데이터 세트"로 압축하면 훨씬 효율적이라고 생각했습니다.

정리된 이해#

반복되는 코드는 ‘행동’이고, 달라지는 부분은 ‘데이터’라는 사실을 깨닫고 나니 테스트 구조가 명확해졌습니다. test.each()를 사용하면 공통된 흐름 하나에 다양한 데이터 세트를 대입해 효율적으로 검증할 수 있어, 개별 테스트 케이스보다 코드 관리가 훨씬 용이하다고 생각했습니다.

1. 무엇이 헷갈렸나 (Confusion)#

가장 먼저 든 질문은 **“왜 같은 동작을 네 번이나 써야 하는가?”**였습니다.

강사님 방식대로 더하기, 빼기, 곱하기, 나누기를 각각 test()로 작성하니, 코드의 구조는 거의 identical했습니다. 실제로 변하는 것은 연산자와 피연산자, 그리고 기대 결과값뿐이었는데, 전체적인 흐름(렌더링 → 입력 → 클릭 → 확인)이 똑같으니 “복사해서 숫자만 바꾼 테스트 4개"라는 인상이 강하게 들었습니다.

2. 정리된 이해 (Organized Understanding)#

반복되는 부분은 **‘행동’**이고, 달라지는 부분은 **‘데이터’**라는 사실을 깨닫고 나니 코드 구조가 명확해졌습니다.

  • 공통 동작: 사용자가 버튼을 누르고 값을 입력하는 전체 흐름
  • 변하는 데이터: 첫 번째 숫자, 두 번째 숫자, 연산자, 기대 결과값

강사님의 방식은 각 테스트 케이스 전체를 독립적으로 보여주어 초보자가 순서를 따라가기 쉽지만, 저는 test.each()를 사용해 “공통된 행동 하나 + 다양한 데이터 세트"로 압축하여 보는 것이 더 효율적이라고 생각했습니다.

총평#

오늘 오후 전체에서 배운 것#

Jest 설정 단계에서의 import 오류는 테스트 로직보다 앞선 실행 환경 문제였으며, 설정이 올바르면 테스트가 정상적으로 실행된다는 점을 확인할 수 있었다. UI 내부의 계산 로직을 별도 모듈로 분리하면 테스트 작성뿐만 아니라 코드 재사용성도 크게 높아진다는 사실을 배웠다. RTL UI 테스트에서 반복되는 동작에 대한 의문을 해결하기 위해 test.each()를 활용해 행동과 데이터를 분리하면, 다양한 데이터 세트를 효율적으로 압축하여 테스트할 수 있다는 점을 실험을 통해 체득했다.

  • UI 내부의 계산 로직을 별도 모듈로 분리하면 테스트 작성뿐만 아니라 코드 재사용성까지 크게 높아진다.
  • 같은 동작을 반복 수행할 때 변하는 데이터만 효율적으로 관리하기 위해 test.each()를 활용해 행동과 데이터를 분리하는 방법을 적용해야 한다.
