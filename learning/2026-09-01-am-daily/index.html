1. 프론트엔드·백엔드·데이터베이스의 실제 역할 이해하기#

무엇을 배웠나#

프론트엔드와 백엔드가 물리적으로 분리된 프로그램이라는 점을 실감했다. Next.js 폴더 안에 파일이 있어도 서버가 실행되지 않으면 화면이 뜨지 않는다는 사실을 확인했다. MongoDB, Express, Next.js가 모두 독립적으로 실행되어야만 데이터 흐름이 완성된다는 구조를 이해했다.

헷갈렸던 점#

강의에서는 ‘역할 분담’이 명확히 설명되었지만, 실제 실행 환경에서는 각 프로그램이 독립된 프로그램이라는 사실을 직관적으로 느끼기 어려웠다. 특히 Next.js 폴더에 파일이 존재함에도 화면이 바로 뜨지 않아 “파일인데 왜 안 뜨지?“라는 의문이 들었다. 또한, 같은 프로젝트 내에 있어도 백엔드와 프론트엔드가 물리적으로 분리되어 있다는 점을 실감하기가 어려웠다.

정리된 이해#

프로젝트 구동을 위해서는 MongoDB, Express, Next.js가 모두 실행되어야 하며, 사용자의 요청은 Next.js → Express → MongoDB 순으로 흐르며 데이터가 반환된다. 각 프로그램은 독립된 포트에서 실행되며, 화면 문제는 Next.js, API 오류는 Express, 데이터 처리 오류는 MongoDB를 확인하면 해결할 수 있다.

# 1. MongoDB 먼저 실행 (저장소 준비)
mongod

# 2. Express API 서버 실행
npm run dev

# 3. Next.js 프론트엔드 실행
npm run dev

2. 프론트와 백엔드의 명확한 역할 구분#

무엇을 배웠나#

폴더 분리라는 물리적인 변화가 단순히 코드 실행 위치의 문제인지, 프로젝트의 역할과 포트 매핑을 명확히 하는 개념적 변화인지 깨닫게 되었다. 특히 project_front와 project_web가 각각 프론트엔드와 백엔드로 역할을 분담하며 :3000과 :80 포트로 통신한다는 구조를 이해하니 이전의 막막함이 해소되었다.

헷갈렸던 점#

기존에는 project_web/client 안에 백엔드와 프론트엔드가 섞여 있어도 애플리케이션이 실행돼서, 굳이 폴더를 분리해야 하는지 의문이 들었다.

또한 각 폴더에서 어떤 명령어를 실행하고 포트는 어디로 연결되는지 감이 안 잡혀 있었으며, 단순히 파일 구조만 바뀌었을 뿐 어디서 무엇을 시작해야 할지 막막했다.

정리된 이해#

폴더 구조 분리 자체가 목적이 아니라, 백엔드와 프론트엔드의 역할과 포트를 명확히 구분하여 개발 효율을 높이는 것이 핵심이다. 각 프로젝트가 독립적인 역할을 수행하며, 브라우저에서 요청을 보내면 프론트엔드가 백엔드로 HTTP 통신을 통해 데이터를 처리하게 된다.

# 백엔드 실행 (project_web)
project_web → node app.js

# 프론트엔드 실행 (project_front)
project_front → npm run dev

Browser
  ↓
project_front :3000  (Next.js)
  ↓ HTTP 요청
project_web :80    (Express + MongoDB)

3. localhost와 포트의 관계#

무엇을 배웠나#

localhost는 내 컴퓨터라는 장소를 의미하고, port 번호는 그 안에서 구분되는 특정 프로그램(방)을 나타냅니다. 같은 localhost라도 포트 번호가 다르면 서로 다른 서버에 접속하는 것이며, 번호가 같으면 충돌이 발생합니다. 따라서 Express를 실행할 때는 80번, Next.js를 실행할 때는 3000번 포트를 명시적으로 지정해 주어야 각각의 프로그램이 정상적으로 동작합니다.

헷갈렸던 점#

localhost는 ‘내 컴퓨터’라는 장소를 의미하고, port 번호는 그 안에서 구분되는 프로그램을 나타냅니다. 같은 건물(컴퓨터) 안에 있지만 포트 번호가 다르면 서로 다른 프로그램에 접속하는 것이지, 다른 서버를 의미하지 않습니다. 따라서 http://localhost만 치면 기본 80번 포트가 연결되어 Express와 동일하게 동작하지만, Next.js는 자동으로 3000번 포트를 할당받아 :3000을 붙여야 화면을 볼 수 있습니다.

정리된 이해#

localhost는 내 컴퓨터라는 장소를 의미하고, port 번호는 그 건물 안에 있는 서로 다른 프로그램(방)을 구분하는 역할을 합니다. 같은 localhost라도 포트 번호가 다르면 충돌 없이 각자의 역할을 수행하며, 기본적으로 80번 포트는 Express 서버로 동작합니다.

# localhost와 port의 관계

📌 핵심 개념: “장소 vs 방”#

  • localhost (내 컴퓨터): 접속 대상이 내 컴퓨터임을 의미하는 주소입니다.
  • port (번호): 같은 컴퓨터(건물) 안에 있지만, 목적하는 프로그램이 다를 때 구분되는 ‘방 번호’입니다.

💡 비유#

localhost = 건물 주소, port = 호수 같은 건물(localhost)이라도 101호(Express)와 201호(Next.js)는 다른 프로그램입니다.

🛠️ 실습 예시#

프로그램 주소 역할
MongoDB localhost:27017 데이터 저장소
Express (API) localhost:80 또는 http://localhost API 서버
Next.js localhost:3000 화면(클라이언트)
  • http://localhost는 기본적으로 80번 포트를 의미하므로 Express와 동일하게 동작합니다.
  • Next.js를 실행하면 자동으로 3000번 포트가 할당되어 http://localhost:3000으로 접속해야 화면이 보입니다.

총평#

오늘 오전 전체에서 배운 것#

프론트엔드와 백엔드가 물리적으로 분리된 프로그램임을 깨닫고, 폴더 구조와 포트 번호가 데이터 흐름과 서버 역할에 미치는 영향을 명확히 이해했다. 특히 localhost와 포트 번호의 관계, 그리고 각 프레임워크가 사용하는 고유한 포트 지정의 필요성을 통해 개발 환경 구축의 필수적인 개념을 학습했다.

다음에 조심할 것#

다음에는 포트 번호가 겹치지 않도록 미리 확인하고, 서버 실행 순서를 체계적으로 관리하여 충돌을 방지해야겠다.

또한 localhost라는 개념이 단순히 ‘내 컴퓨터’를 넘어 각 프로그램이 구분되는 ‘방’이라는 점을 명확히 인지하고, 폴더 구조가 프로젝트의 역할 분담을 의미한다는 점을 잊지 않도록 하겠다.

다음 복습 주제#

다음에 복습할 주제는 다음과 같다.

먼저, 각 프로그램(Next.js, Express 등)이 기본적으로 사용하는 포트 번호와, 프로젝트별로 포트를 재지정해야 하는 이유를 명확히 이해하는 것이다. 또한, 단순히 파일이 존재하는 것이 아니라 서버가 실행되어야만 클라이언트에게 화면이 전달된다는 ‘실행 상태’의 개념을 다시 한번 점검할 계획이다. 마지막으로, localhost를 기준으로 서로 다른 포트에서 동작하는 서버들이 어떻게 통신하고 데이터를 주고받는지에 대한 전체적인 흐름을 복습하여 시스템 통합에 대한 이해도를 높일 것이다.
