1. f-string 포매팅#

왜 이걸 보게 됐나#

시험 직전 패턴을 완성하기 위해, 그동안 막연하게 느껴졌던 반복문의 방향성과 DOM 선택자의 차이를 명확히 구분해야 했습니다. 특히 for문의 조건식과 checked 속성 같은 세부 사항은 ‘값을 가져온다’는 기존 상식과 달라서 헷갈리기 쉬웠습니다. 이러한 혼란을 해소하고 React의 map, Props, useState가 어떻게 연결되는지 공식처럼 정리함으로써, 시험장에서 순간적으로 머리가 하얘지는 상황을 막고자 했습니다.

내가 헷갈린 지점#

f-string에서 변수명과 중괄호가 섞여 있어, 파이썬 코드 내부의 {} 문법이 문자열 안에 포함되는 것인지 실제 값 치환인지 처음에 구분하기 어려웠습니다. 특히 기존의 %나 .format() 방식과는 달리 f 접두사만 붙이면 자동으로 처리된다는 점이 신기하면서도, 중괄호가 코드 블록처럼 보여서 실수로 연산자나 다른 문법을 안에 적다가 오류를 내기도 했습니다. 하지만 {변수명} 형식 자체가 파이썬 식을 그대로 실행해 값을 넣어주는 것이므로, 변수의 타입에 따라 자동으로 문자열로 변환된다는 점만 확실히 기억하면 나머지 복잡한 포맷팅 옵션은 크게 필요 없다는 확신이 들었습니다.

시도한 코드 / 예시#

# f-string formatting example
name = "Alice"
age = 25

print(f"Name: {name}, Age: {age}")
# Output: Name: Alice, Age: 25

결과와 해석#

f-string 안에서 중괄호를 사용해 변수를 직접 삽입하면, 문자열 내부에 있는 변수값이 실시간으로 치환되어 표현됩니다. 이를 통해 별도의 연결 연산자나 복잡한 포맷팅 함수 없이도 가독성 높은 문장을 만들 수 있습니다. 특히 반복문이나 조건문 안에서 동적으로 변하는 값을 출력할 때 매우 유용하게 활용할 수 있습니다.

정리된 이해#

f-string은 변수나 식을 중괄호 안에 직접 삽입하여 문자열을 쉽게 꾸밀 수 있는 파이썬의 강력한 문법입니다. 특히 들여쓰기나 조건부 표현식을 한 줄에 간결하게 작성할 수 있어 코드의 가독성을 크게 높여줍니다. 복잡한 포맷팅 메서드 없이도 직관적으로 원하는 형태의 문자열을 생성할 수 있다는 점이 가장 큰 장점입니다.

2. 반복문 방향성#

왜 이걸 보게 됐나#

반복문을 처음 접했을 때, i < length와 i >= 0 같은 조건식 사이에서 앞으로 나아가는지와 뒤로 나아가는지 판단하는 감이 잡히지 않아 매번 실수할 것 같아서 공부하게 되었습니다. index를 기준으로 방향성을 명확히 구분하지 않으면 코드의 흐름을 예측하기 어렵고, 실제 프로젝트에서 배열을 처리할 때 오류의 원인이 되어 시간을 낭비하게 되기 때문입니다. 결국 반복문의 방향성을 이해하는 것은 논리적인 코드 작성 능력을 키우고, 디버깅 시간을 줄이기 위한 필수적인 기초 지식이라고 판단했습니다.

내가 헷갈린 지점#

처음에는 i < length와 i >= 0이라는 조건식만 보고 앞으로 가는 것과 뒤로 간다는 개념이 추상적으로 느껴졌습니다. 특히 index가 0부터 시작한다는 점과 배열의 길이가 마지막 인덱스보다 1 크기라는 사실을 연결하지 못해, 반복문이 어디서 멈추고 시작하는지 감을 잡기 어려웠습니다. reverse loop를 칠 때 i--와 조건식의 방향이 반대로 작용한다는 논리를 머릿속에 그리기보다는 공식처럼 외우려다 보니, 실제 코드를 작성할 때 방향이 섞여 버리는 경우가 많았습니다.

시도한 코드 / 예시#

// 반복문 방향성: 앞에서부터(i < length)
for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]); // 예시: arr[0], arr[1], arr[2] ...
}

// 반복문 방향성: 뒤에서부터(i >= 0)
for (let i = arr.length - 1; i >= 0; i--) {
    console.log(arr[i]); // 예시: arr[last], ..., arr[0]
}

결과와 해석#

for (let i = 0; i < arr.length; i++)는 배열의 처음부터 끝까지 순차적으로 접근하는 방식이며, i >= 0 조건을 사용하여 역순으로 반복할 때는 인덱스가 0보다 작아지지 않도록 주의해야 한다.

정리된 이해#

반복문의 방향성은 인덱스 변수 i가 증가하는지 감소하는지에 따라 결정된다. 앞으로 이동할 때는 i < length 조건을, 뒤로 이동할 때는 i >= 0 조건을 사용하여 반복의 시작점과 끝점을 명확히 설정해야 한다.

3. DOM 선택자 구분#

왜 이걸 보게 됐나#

시험 직전에 닥친 막막함 속에서, DOM 선택자와 React 개념이 섞여 나오는 문제를 마주하고 “이게 JS야? React야?” 하며 혼란을 느꼈기 때문에 명확한 구분 방법을 배울 필요가 있었습니다. 특히 체크박스의 value와 checked 속성名单子는 직관적이지 않아 헷갈릴 수밖에 없었기에, 반복문과 선택자의 방향성과 목적을 정확히 짚어내는 것이 중요하다고 판단했습니다.

내가 헷갈린 지점#

DOM 선택자의 차이를 구분할 때 가장 헷갈렸던 점은, getElementById가 ID를 기준으로 단 하나의 요소를 찾는 반면 querySelector는 CSS 문법 그대로 사용해 클래스나 태그 등 여러 요소를 골라낼 수 있다는 점이었습니다. 또한 getElementsByClassName은 live 컬렉션이라는 특성상 DOM이 변할 때마다 자동으로 업데이트된다는 점과, querySelectorAll은 정적인 NodeList를 반환한다는 점을 혼동하여 실제 코드 작성 시 의도치 않은 요소를 선택하거나 length 프로퍼티 사용에 오류가 생기곤 했습니다.

시도한 코드 / 예시#

// DOM 선택자 구분 예시

// ID 선택자 (하나만 찾음)
document.getElementById('my-id');

// 클래스 선택자 (여러 개를 찾을 때, NodeList 반환)
document.getElementsByClassName('my-class');

// CSS 선택자 (가장 강력하고 유연함)
document.querySelector('.my-class'); // 첫 번째 요소만 반환
document.querySelectorAll('.my-class'); // 모든 요소를 NodeList로 반환

// 체크박스 예시 (value가 아닌 checked 속성 사용)
const checkbox = document.getElementById('terms');
console.log(checkbox.checked); // true/false

결과와 해석#

ID 선택자는 #으로 시작해 고유한 하나의 요소를 정확히 찾아내지만, 클래스 선택자는 .으로 시작해 여러 요소 중 조건에 맞는 것만 골라낸다. DOM 조작 시 getElementById는 단일 요소 제어용이며, 반복문이나 리스트 렌더링에는 querySelectorAll 등을 활용해 다수의 요소를 한 번에 처리하는 것이 효율적이다.

정리된 이해#

DOM 선택자는 ‘무엇을’ 찾느냐에 따라 getElementById는 고유 ID, querySelector는 CSS 선택자, getElementsByClassName은 클래스명이라는 구분 기준을 명확히 하여 혼동을 방지한다. 특히 체크박스의 경우 value 속성 대신 checked 속성을 사용하여 상태를 확인하는 것이 핵심이다. React에서는 map, Props, useState가 각각 렌더링, 데이터 전달, 상태 관리를 담당한다는 삼각관계 구조를 이해하면 개념이 분리된다.

4. React 삼각관계#

왜 이걸 보게 됐나#

시험 직전에야 React의 핵심 개념들이 왜 중요한지 실감하게 되었습니다. map, Props, useState가 어떻게 연결되는지를 이해하지 못하면 화면이 제대로 그려지지 않기 때문입니다. 특히 상태 관리와 렌더링 흐름을 파악해야만 컴포넌트 간의 데이터 전달이 자연스럽게 이루어지는 것을 알 수 있었습니다.

내가 헷갈린 지점#

React에서 map, Props, useState가 어떻게 연결되는지 감이 안 잡혔습니다. 특히 map 안에서 Props를 어떻게 전달받고, 상태 관리는 useState로 해야 하는지 전체적인 흐름이 복잡하게 느껴졌습니다. map은 배열을 돌고, 그 안에 Props가 들어오며, 결국 화면을 업데이트하려면 useState로 상태를 관리해야 한다는 연결 고리를 이해하는 데 시간이 걸렸습니다.

시도한 코드 / 예시#

// React 삼각관계 핵심 예시

const items = ['사과', '바나나', '체리'];

// 1. map (반복)
const listItems = items.map((item) => {
  // 2. Props (데이터 전달)
  return <li key={item}>{item}</li>;
});

// 3. useState (상태 관리)
const [count, setCount] = useState(0);

결과와 해석#

map() 메서드를 사용해 배열을 순회하며 각 요소에 Props를 전달하고, 그 결과를 화면에 렌더링하는 구조입니다. 이때 상태 변화는 useState 훅을 통해 관리되어 UI가 동적으로 업데이트됩니다.

정리된 이해#

React에서 map은 배열을 순회해 UI를 렌더링하고, 그 안에는 Props가 데이터로 흐르며, 상태 관리는 useState를 통해 이루어지는 공식적인 구조입니다.

다음에 조심할 것#

반복문 방향성을 index(i) 기준으로 반드시 확인한다. DOM 선택자는 id는 하나, class·CSS 선택자는 여러 개라는 규칙을 구분한다. React에서는 map, Props, useState가 어떤 역할을 하는지 명확히 분리해서 생각한다.

다음 복습 주제#

f-string 포매팅 변수 삽입을 {}로 바로 표현할 수 있어 가독성이 높아졌습니다. 기존 문자열 연결(+)이나 % 방식보다 직관적이고 오류가 적어 일상 코드 작성에 즉시 적용할 수 있습니다.

반복문 방향성 i < length는 앞으로, i >= 0은 뒤로 이동한다는 규칙을 index 위치에 고정했습니다. 앞으로는 인덱스 증가, 뒤로는 감소하는 흐름을 시각화해 실수를 방지합니다.

DOM 선택자 구분 ID는 유일하므로 getElementById, 클래스는 다수이므로 getElementsByClassName 또는 CSS 선택자를 상황에 맞게 사용하는 것이 핵심입니다. ‘무엇을 찾느냐’에 따라 메서드를 명확히 분리했습니다.

React 삼각관계 map으로 데이터를 돌고, 안에는 Props가 들어오며, 상태 관리는 useState로 한다는 공식이 잡혔습니다. 이 3가지가 어떻게 연결되는지 구조를 파악하니 개념 정리가 확실히 되었습니다.
